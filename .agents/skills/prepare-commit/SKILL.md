# Prepare Commit

現在の会話全体と実際の Git 差分を照合し、コミットメッセージ案と対象ファイルを整理する。

## 禁止事項

- staging、commit、push を実行しない。
- Git index、working tree、履歴を変更しない。読み取り専用の Git コマンドだけを使う。
- コミットメッセージ規約をこのスキル内へ複製しない。

## 手順

1. `git rev-parse --show-toplevel` でリポジトリルートを特定し、実行時点の `AGENTS.md` を読む。コミットメッセージは、そこに記載された現在の Git・コミットメッセージ規約に従う。
2. 現在の会話全体から、今回コミットしようとしている目的と作業内容を整理する。直近のメッセージだけに限定しない。
3. ユーザーが追加対象、除外対象、分割方法を指定している場合は、その指定を会話からの推定より優先する。指定が矛盾している場合だけ確認する。
4. staged、unstaged、untracked の全変更を調査する。`git status` だけで判断せず、`git diff --cached`、`git diff`、必要な未追跡ファイルの内容を確認する。
5. 各差分が `コミット対象`、`コミット対象(一部)`、`コミット候補`、対象外のどれに当たるか判断する。同じファイル内に複数作業の hunk があるかも確認する。
6. `コミット対象` と `コミット対象(一部)` の全体を表すコミットメッセージ案を、原則として1件作る。`コミット候補` は既定のコミットへ含めない。
7. 複数の意味的な作業単位へ分割できる場合も確認質問は行わず、基本案は1コミットのままとする。分割案が有用なら概要だけを付記する。
8. ユーザーが分割方法を指定している場合は、その単位ごとにコミットメッセージ案と対象ファイルを作る。

## 分類

### コミット対象

会話全体の作業内容へ直接対応する変更、またはユーザーが明示的に追加した変更を置く。対象ファイルはリポジトリルートからの相対パスで列挙する。

### コミット対象(一部)

同じファイル内に対象作業と対象外作業の hunk が混在する変更を置く。ファイルパスに加えて、含める hunk を識別できる短い要約と、部分 stage が必要な旨を書く。ファイル全体を対象として扱わない。

### コミット候補

内容から現在の作業との関連を推定できるが、対象と断定できない変更を置く。ファイルパスごとに、推定した関連性と根拠を書く。ユーザーが追加を指示しない限り、コミットメッセージ案の対象には含めない。

## 出力

Git 状態は併記しない。対象外と判断した変更は出力しない。項目が1件もない分類は、`なし` と書かず見出しごと省略する。

`コミット対象` または `コミット対象(一部)` がある場合は、最初に次を出力する。

```markdown
## コミットメッセージ案

<AGENTS.md に従った案>
```

続けて、項目がある分類だけを次の順序で出力する。

```markdown
## コミット対象

- <repo-relative path>

## コミット対象(一部)

- <repo-relative path> — 対象: <hunk の要約>。部分 stage が必要

## コミット候補

- <repo-relative path> — 推定: <関連性と根拠>
```

分割案がある場合だけ、末尾へ次を追加する。個別のコミットメッセージは作らない。

```markdown
## 分割案

- <作業テーマ>: <大まかなファイル群>
```

ユーザーが分割を指示した場合は、各コミット単位について `コミットメッセージ案` と、項目がある対象分類だけを提示する。`コミット候補` がある場合は最後にまとめて提示する。対象外の変更は提示しない。

## 失敗時

- Git リポジトリでない場合は、コミット案を作れない理由を返す。
- 対象となる実差分がない場合は、メッセージやファイルを捏造せず、見出しを使わずに `コミット対象はありません。` とだけ返す。
- 明示されたファイルに差分がない場合は対象へ追加せず、その事実を短く知らせる。
