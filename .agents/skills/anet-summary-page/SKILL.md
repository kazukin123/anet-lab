# 会話のまとめページ

同じ面（Claude Code または Codex）で同じ仕事を続ける会話を、チャット枠を移っても同じ枠として扱い、会話の枠ごとに 1 枚を持つ。[共通の型と場面の一覧](../../../docs/process/summary-page/README.md) を読み、当てはまる場面の指針だけを読む。

## 作るか続けるか

上から最初に当たる行に従う。

| 行 | 条件 | 扱い |
|---|---|---|
| 1 | ユーザーと話さない会話（レビュー役などのサブエージェント） | 作らず、更新もしない |
| 2 | Plan Mode | 作らず、更新もしない。行 3〜7 に当たるときは書けないことを会話で 1 度だけ知らせ、Plan Mode を抜けた最初の応答で該当する扱いを行う |
| 3 | この会話でページを作った、同じ面からの handoff にページがある、または handoff なしで続ける際に下の手順で同じ枠とみなせるページが見つかった | 続行中のページを更新する。行 6 の始める時機にも当たれば、その場面の節を同じページに足す。ページ全体を終えた後は、後続の応答でそのページを出し直さない |
| 4 | 面をまたいで同じ仕事を続け、handoff に前の面で発行したページの URL がある | 前のページと同じ場面で別の名前のページを作り、冒頭と目印に前の URL を載せる |
| 5 | ユーザーが skill を呼んだ、または言葉で作成を頼んだ | 場面の一覧の始める時機に当たる場面で作る。当たらなければ一般で作る |
| 6 | [場面の一覧](../../../docs/process/summary-page/README.md#場面の一覧)の始める時機に当たった | その場面で作る |
| 7 | 前の応答で振った案・選択肢・論点の記号を、あとの往復で引いた。ただし、選択肢を出した問いへの答え（番号や記号で選ぶこと）とその直後の復唱は数えない | 一般で作る |
| 8 | どれにも当たらない | 作らない |

作る行に当たったら、確認を挟まずその応答で作る。問いかけと決定は会話で行い、記号を出すたびに短い名前を添える。ページへは会話で分かった内容を写す。

### handoff なしで続けるページを探す

ユーザーが前の会話の仕事を続けるよう頼んだら、まとめページに言及していなくても、表の行 3 を確かめるために探す。

1. ユーザーが続けると言った主題を、同じ面で状態が「続行中」の目印ファイルの名前と「元の会話」の主題に照らす。
2. 0 件なら、その面の道具のページ一覧を題で照らす。一覧の URL と目印の「出した先」を照合し、目印があるページは候補から外す。「終わった」ページはこの探索でも続けない。
3. 1 件なら同じ枠として続ける。2 件以上なら候補の名前を示し、選択を受けてから続ける。題で見つけたページを続けるときは目印を作り直す。候補がないか、ユーザーが候補を選ばないと答えたら、表の行 4 以降に従う。

## 手元のファイル

- `.scratch/summary/<ページの名前>.html` に [ひな形](../../../docs/process/summary-page/template.html) を写し、共通の型と該当する場面の指針に従って埋める。題は短い表示名にし、ひな形の `<title>` と `<h1>` の両方に同じものを書く。後ろにコロンなどで説明を付けない。見た目はひな形の CSS だけを土台にし、ほかのまとめページの CSS を写さない。場面の節に要る見た目は、ひな形の色のトークンを使って足し、いまの位置の 4 欄は同じ形のまま使う。
- 名前は、枠の主な主題を英小文字・数字・ハイフンで表し、最初の場面に対応する印を先頭に付ける。例は `grill-prd197`、`exp-atari`。一般には印を付けない。
- 別の枠に同名の `.html` または `.md` があるときは、両方とも空いている最初の番号を `-2`、`-3` の順で付ける。面をまたいだ先では、手元に前のファイルがなくても前の名前を使わない。新規作成時は目印を上書きせずに確保し、並行する会話と名前が競合したら次の番号を使う。冒頭と目印の「前後のページ」に前の URL を載せ、前のファイルはそのまま残す。
- `.scratch/summary/<ページの名前>.md` の目印には次の欄を置く。同じ名前の HTML と並べ、欄の値が変わったときに更新する。

| 欄 | 値 |
|---|---|
| 題 | ページの表示名 |
| 面 | Claude Code または Codex |
| 出した先 | URL と、Codex の場合は Site ID。URL がまだなければ未発行と書き、取得済みの Site ID は保持する |
| 状態 | 続行中 または 終わった |
| 元の会話 | 日付と主題 |
| 前後のページ | 面をまたいだ前のページや、同じ主題で別の枠を始める前のページなど、分かっている関連 URL |

目印には最終更新の時刻を書かない。非公開ページの URL は手元の目印・HTML、会話、引継ぎ文で使い、Git が追跡するファイルには書かない。

## 非公開で出す

- **Claude Code** は作成前に `artifact-design` を読み、Artifact で非公開ページとして出す。ひな形はそのページの決まり（題、色のトークン、明暗、余白）に合わせてあるので、見た目はひな形に従う。更新は同じ HTML のパスと出し先を使う。
- **Codex** は Sites の skill を読む。手元の HTML に `<!doctype html>`、`<html lang="ja">`、文字コードと viewport を含む外枠を付ける。外枠の `<head>` には手元の HTML の先頭の `<title>`・`<meta>`・`<style>` を入れ、`<body>` には `<article>` を入れる。ホスティングの設定とともに Sites 専用の Git へ送る。所有者だけが見られる版として出し、更新は目印の Site ID を使って同じ URL に出す。外枠と設定は出すときだけ組み立て、`.scratch/summary/` には置かない。
- 最初に URL が得られた応答で「まとめページを生成しました: <URL>」を 1 行で知らせる。以降の更新では知らせない。
- 出せなければ HTML と目印を残し、会話で手元の HTML のパスを知らせる。会話は続け、次に中身が変わった応答で再試行する。出す先を作成済みなら、その識別子を引き継ぐ。

## 更新・引き継ぎ・終了

- いまの位置、記号の状態、場面の節の内容が変わった応答で、直した箇所と最終更新の時刻を反映して最終応答の前に 1 回だけ出し直す。複数箇所の変更も 1 回にまとめる。内容が同じなら出し直さない。ユーザーの発言ではなく、バックグラウンドの作業の知らせ（レビューの結果など）で始まった応答も、この応答に含む。
- 工程がユーザーへ返さずに進める往復（レビューの差し戻し対応など）の中では、前の項目の「最終応答の前に 1 回だけ」に代えて、ページに載せる中身が変わるたびに、次の結果を待つ前に 1 回出し直す。次の依頼が結果を返すまで止まる呼び方なら、その依頼を出す前に出し直す。工程の最終応答まで後回しにしない。写すのは、何往復目か、直したこと、待っているもの（いまの位置）と、往復で足した・改めた決定（ページでそれを書く節）である。中身が同じなら出し直さない。ユーザーへ返さない往復のあいだも、ユーザーはこのページで進みを見るためである。
- 出し直すたびに、いまの位置の 4 欄をすべて見直す。済んだ項目を TODO に残さず、DONE は直前に済んだことに書き換える。前の版の文の一部だけを置き換えると、済んだ項目が残るためである。
- チャット枠を移るときは handoff の引継ぎ文に、URL（まだなければ未発行と明記）、HTML と目印のパス、次に使う skill として `anet-summary-page` を入れる。面をまたぎ、引き継いだのが未発行の HTML と目印だけなら、手元の内容を参照し、ページを作るかは表の行 5 以降で判断する。前のページへのリンクは発行済みの URL があるときに載せる。
- 同じ面の新しい会話で続行中のページを更新するときは、handoff の有無にかかわらず、URL の現在の版を読み直し、手元に出せていない変更があれば合わせてから同じ URL へ出す。初回発行に失敗して URL がまだなければ、手元の HTML と目印から続け、次に中身が変わった応答で発行を再試行する。目印に Site ID があれば再利用する。
- 枠の中の主題が済んだら、その主題の塊を「終わった」として畳む。ページ全体を終えるのは、グリルの枠でグリルの完了を報告するときか、ユーザーが終えると言ったとき。いまの位置に「終わった」と書いて最後に 1 回出し、目印の状態も「終わった」にする。ページとファイルは残す。
