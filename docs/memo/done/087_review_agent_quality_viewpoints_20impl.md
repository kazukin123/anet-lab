### `docs/process/registry.md`

PRD §6.1 の 7 節を、この順の `##` 見出しで持つ。見出しは、共有コアが参照する字面に合わせる。

1. **成果物レジストリ** — PRD §6.1 の 5 行（`prd` `impl-plan` `impl` `worklog` `issue-record`）。列は「成果物キー / 成果物名 / 成果物種別 / 入力元 / 出力先 / テンプレート / 品質確認観点 / 担当」。表の下に次を注記する。
   - 「入力元」の値は成果物キーで、`input` は「入力資料」のキーである。
   - `—` は持たないこと、`未整備` は用意していないことを表す。
   - `impl` は固定の出力先を持たないので、パスからは逆引きできない。依頼で成果物キーを渡す。
   - `worklog` と `issue-record` は品質確認観点を持たず、レビューの対象にしない。
   - `impl-plan` は作業記録を兼ねるので、テンプレートの節のあとに、経過と結果の節を足してよい。
   - `anet-create-prd` はまだ無く、それまでの PRD づくりは起票する枠が行う。
2. **成果物以外のレビュー対象** — なし。
3. **サーフェスごとの所在** — レビューエージェントの定義。Claude Code は `.claude/agents/an-review.md`、Codex は `.codex/agents/an-review.toml`（本文を持たず、前者を読んで従う）。観点は対象を実パスで書く、と添える。
4. **入力資料** — `input`: 会話での要求、`reports/` のサーベイ、`docs/experiments/` の実験記録。読み取り元で、工程の中で書き換えない。レビューで入力元にするのは、PRD が本文で名指ししたファイルだけにする。
5. **工程 Agent の切り替え先**、6. **成果物種別とアダプタの対応**、7. **読み替え表** — いずれも「なし」。

### 観点ファイルの共通の形

- 冒頭に位置づけの表（対象の成果物、参照するエージェント、対象外）を置く。
- 「機械検査」と「読解観点」に分ける。
  - 検索による検査: 項番 / 確認観点 / 検索対象 / パターン / 期待値 / 規約の所在。
  - スクリプトによる検査: 項番 / 確認観点 / 実行するもの / 期待値 / 規約の所在。
  - 読解観点: 項番 / 確認観点 / 確認内容 / 規約の所在。
- 項番はファイル内で通しの整数にし、機械検査と読解観点をまたいで一意にする。
- 読解観点は節に分け、節ごとに適用範囲を 1 行で書く。
- 確認内容は規約を書き写さず、成果物が所在の規約を満たすかを、判定できる文で問う。所在は「文書へのリンクと節の名前」で書く。
- 検索対象は実パスかグロブで書く。論理名を使わない。

## 前提

- 受入の対象は、PRD のレビューが PRD 087、実装のレビューが段階 1 の成果物自身とする（2026-10-04 のユーザー回答）。実装はこのセッションで行う（同）。
- レジストリの列名は「成果物種別」にする。PRD の表は「種別」だが、共有コアの 8 節がこの名前で列を参照する。「担当」は PRD のとおりにする。
- レジストリの 7 節はすべて見出しを置き、段階 2 で書く 3 節は「なし」とする。
- コードに対する機械検査（`impl.md` の項番 1〜3）は、変更ファイルを検索対象にする。既存の違反は直さない。着手時点で、production の `dynamic_cast` が 4 件（`gui.cpp` 3、`observers.cpp` 1）、状態行のある PRD が 19 本、skill の実体コピーの不一致が 3 ファイルある。レビューでは、範囲外の検出として扱われる。
- レビューエージェントの Bash は、観点に書かれた検査スクリプトの実行に限られる。実装のレビューで差分を見られるように、`impl.md` のスクリプトによる検査に `git diff` を載せる。
- コード・テスト・設定ファイルの読む範囲を差分中心にすることは、`impl.md` の位置づけに書く。共有コアは書き換えない。1 ファイルで数百 KB のコードがあり、全文を読むレビューは成り立たないためである。
- 観点の項目は、PRD §6.1 の出どころの表にある文書から起こす（NG6）。表の括弧書きは例示と読み、同じ文書のほかの節からも起こす。表の文書が従うよう指す資料（`docs/ownership_guideline.md`）と、同じ skill のファイル（`ADR-FORMAT.md`、`CONTEXT-FORMAT.md`）は、表の文書とあわせて所在に挙げる。表の文書を所在に持たない項目は、次の 2 つだけである。
  - `impl.md` の項番 4（共有コアの語）。PRD §6.1 が、表のあとの文で入れるよう定めている。所在は ADR 0049 である。
  - `impl.md` の項番 6（変更箇所の特定）。所在はプロセス契約の 2 節である。上の箇条書きのとおり、レビューエージェントが差分を見るために要る。
- `grill-with-docs` の 2 つのコピーは中身が違う。所在は、その規約がある側のコピーを指す。段階 2 で `grill-with-docs` を消すとき、`prd.md` の所在を付け替える。
