## 1. 問題・ゴール・非ゴール

### 1.1 問題

1. 9xx の番号を持つ RFD（直下 49 本、保管場所 8 本）が、連番（今の最大は 130）から離れている。新しい RFD は 900 未満の最大の番号の次を取るので、新しい RFD はいつも 9xx の手前に積まれ、番号の並びの最後が最新の RFD にならない（§2 の 1・2）。
2. 9xx の RFD をグリル・実装するたびに、9xx の番号を持つコミットの件名が増える。件名は書き換えられないので、振り直しが遅れるほど、旧い番号のまま残る記録が増える（§2 の 5）。

### 1.2 ゴール

- G1: `docs/memo/` の下に 9xx の番号の RFD が無くなり、57 本が、実装を始めた時点の最大の番号の次からの連番になる。並びは起票の日の順にする。
- G2: この振り直しを「一度使った番号は再利用しない」の例外とし、振り直したあとは 900〜999 も普通の番号として使える。規約に予約の帯を残さない。
- G3: 今使っている文書・道具・課題・コードが、新しい名前と番号を指す。
- G4: コミットの件名と過去の記録に残る旧い番号から、今の RFD を引ける（人は各 RFD の冒頭の行で、道具も同じ行で）。
- G5: 採番の規約、観点、skill、wiki の規約が新しい形に合う。
- G6: 題材の課題 5adbf9 が片付く。

### 1.3 非ゴール

## 4. 確定事項

| # | 決定 | 理由 |
|---|---|---|

### 5.3 冒頭の振り直しの行と、道具の引き方（D7〜D9）

**振り直しの行の形**

```text
> YYYY-MM-DD 番号を <旧> から <新> へ振り直した（PRD<nnn>）。
```

- `<旧>`・`<新>`・`<nnn>` は 3 桁の数字。RFD0114 の既にある行（`（PRD114）`）も、この形に当たる。
- 置き場所は、題の直下にある引用行の先頭とする。

**道具が読む行と検査**（`wiki_support.py` の `maps` が使う）

- `docs/memo/**/*_10rfd.md` の、題のあと最初の見出しまでの行のうち、行頭が `> YYYY-MM-DD 番号を` で始まる行を振り直しの行として読む。本文やコードの枠に日付の例を書いても読まないためである。
- 次のどれかに当たれば、ファイルと行番号を示して止める（課題の欄の検査が止めるのと同じ扱い）。
  - 読んだ行が上の形と完全には一致しない。
  - 1 つの RFD の中で、同じ日付の振り直しの行が 2 つ以上ある。
  - 1 つの RFD の振り直しの行を日付の順に並べたとき、前の行の `<新>` が次の行の `<旧>` と一致しないか、最後の行の `<新>` がそのファイルの番号と一致しない。

**コミットの件名の番号 N を RFD に当てる**（コミットの日付は `git log --format=%ad --date=short` の日付。これから作るコミット（`--pending-subject`）は、道具を回した日をコミットの日付とする）

上の行から順に当て、最初に条件を満たした行で扱う。

| 行 | 条件 | 扱い |
|---|---|---|
| 1 | `<旧>` が N で、日付がコミットの日付以後の振り直しの行を持つ RFD が 1 本 | その RFD |
| 2 | 同じ条件の RFD が 2 本以上（RFD0114 の `999` など） | 一意に決められない |
| 3 | `docs/memo/**/N_*_10rfd.md` が 1 本 | その RFD |
| 4 | 上のどれにも当たらない（ファイルが 0 本か 2 本以上） | 一意に決められない |

**表示**

- 当てた RFD は、今と同じ行の形（文字が `RFD<今の番号>` で今のパスへのリンク、続けて ` — <今の題>`）の 1 行で載せる。同じ RFD に当たった番号が複数あっても 1 行にまとめ、今の番号の順に並べる。
- 一意に決められない番号は、今と同じく `- RFD<N> — （RFD を一意に決められない）` の行にし、`unresolved_rfds` に入れる。

**wiki の点検（D9）**

実装済みの RFD のコミットを探すとき、その RFD の今の番号と、その RFD の振り直しの行にある `<旧>` を、スコープか件名末尾に持つコミットを探す。`<旧>` で探すのは、その行の日付以前のコミットに限る。
