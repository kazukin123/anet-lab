# RFD0199: AGENTS.md を状況別のファイルに分け、毎回読む量を減らす RFD

> 2026-11-24 起票（暫定）。質疑を省いた。確定した決定は持たず、AI が置いた既定と決めきれない点を §6 の未決表に置いた。§7〜§9 は §6 の暫定の既定を前提に書き、前提にした行の番号を名指す。
> 起点: 2026-11-24 の会話。開発者が、AGENTS.md を整理し、最終的には状況別にファイルを分けて必要な内容だけを見るようにしたい、最低限は記載の順序を整理したい、と述べた（§11）。順序の整理（段階 1）は同じ会話で済ませ、ファイルの分割（段階 2）をこの RFD にした。
> 課題: [issue-20261124-707776](../management/issues/issue-20261124-707776.md)（この RFD の仕事）。

## 1. 目的と問題

### 1.1 問題

AGENTS.md は 28 節・770 行・75,769 バイトある（P1）。Claude Code は CLAUDE.md の指示で毎回読み、Codex も毎回読む（P2）。どの作業でも要る決まりは一部で、ビルドと検証、Run と実験、コミットメッセージの書き方のように、その状況に入ったときだけ要る決まりも、毎回の読み込みに入っている（§5.1）。

段階 1 で、節を「いつ要るか」の 4 群の順に並べ替え、群の見出しを置いた（§5.1）。読み込む量は変わっていない。

### 1.2 ゴール

- 毎回読む AGENTS.md を、どの作業でも要る決まりと、状況ごとに読む先の案内にする。
- 状況ごとの決まりは、その状況に入るときに読まれる。移したことで、読まれずに作業が進む場面を増やさない。
- Claude Code と Codex のどちらでも同じに効く。
- 題材の課題 issue-20261124-707776 が片付く。

### 1.3 非ゴール（退けた案と、本当の制約か）

- 決まりの中身を変えること — 移すだけにし、中身の見直しは別の課題にする。本当の制約ではなく、範囲の線引きである。
- 段階 1 の並べ替えを戻すこと — 段階 1 は済んでいる。本当の制約ではない。分けたあとに残る節の並びは、この RFD で直してよい（U9）。

### 1.4 機構とゴールの対応

| 機構 | ゴールへの寄与 |
|---|---|
| 群ごとの移し先（U1・U2・U4） | 状況ごとの決まりを AGENTS.md から出し、毎回読む量を減らす |
| 原則の群の扱い（U3） | 毎回読む量と、読まれずに進む危険の釣り合いを決める |
| 読む表の行（U5）と入口での読み込み（U6） | 状況に入るときに、移した決まりが読まれる |
| 読み込みの仕組みの選び方（U7） | Claude Code と Codex のどちらでも同じに効く |
| 節を名前で引く箇所の付け替え（U8） | 移したあとも、skill・レビュー観点・検証資材から決まりへたどれる |

### 1.5 成功の測り方

- AGENTS.md のバイト数。今は 75,769 バイト。暫定の既定（U1〜U4）どおりなら約 49,000 バイト（65%）、原則の群（②）も移すなら約 27,000 バイト（35%）になる見込み（§5.1 の群ごとのバイト数から）。
- 移したあとの最初のビルド・Run の分析・コミットの準備のそれぞれで、移し先の節を読んだ 1 行が応答にあること（受入 A7）。

## 3. 背景

ADR 0061（RFD0087）で、C++ のコード、コメント、ログ、設定ファイルなどの細則は、AGENTS.md からレビュー観点へ移した。AGENTS.md には「作業ごとに読むもの」の表を置き、書く前に読む先を引かせている（P3・P5）。今回は、レビュー観点に当たらない状況ごとの決まり（ビルドと検証、Run と実験、コミットメッセージ）と、原則の群を、どこへ移すかを決める。

## 4. 用語

- **群**: AGENTS.md の節を、いつ要るかで分けたまとまり。① 毎回守ること、② 設計・契約を変えるとき、③ ビルドと検証、④ Run と実験 の 4 つ。段階 1 で AGENTS.md の見出し（`#` の行）にした。今ある語の「節」は 1 つの見出しの中身を指し、節のまとまりを言えないので、この呼び名を使う。この RFD の中だけで使う呼び名で、`CONTEXT.md` には足さない。

## 7. 仕様

暫定の既定（U1〜U9）を前提に書く。

- AGENTS.md には、冒頭、① 毎回守ること（コミットメッセージの書き方と Topic の表を除く）、② 設計・契約を変えるとき を残す（U3・U4・U9）。
- `docs/rules/` を新しく作り、次の 3 ファイルを置く（U1・U2・U4）。
  - `build.md`: ③ の 4 節（ビルド、検証、Python 補助ツールの実行、AI エージェントでのビルド注意事項（Windows/MSVC））。
  - `run.md`: ④ の 3 節（Run 命名・後片付けルール、実験記録と実効 config の保存ルール、AI エージェントのRun結果分析ルール）。
  - `commit-message.md`: コミットメッセージの書き方と Topic の表。
- 各ファイルの冒頭に、何の決まりか、いつ読むかを 1〜2 文で書く。節の本文は変えない（非ゴール）。
- 「作業ごとに読むもの」の表に U5 の 3 行を足す。
- 移した節を名前で引く現用の箇所を、移し先のファイルの節へ付け替える（U8）。
