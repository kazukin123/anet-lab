## Context / Problem Statement

現状、Run の**計画・順序・実行**を `.bat` が 1 枚で持っている。無人で長時間回す用途では、これが 4 つの形で破綻する。以下はすべて 2026-08-31 に実測した事象である。

### 1. 計画変更がバッチ全体の中断になる

本命の Run が別要因で死に、キューへ戻す必要が出た。しかし **走行中の `.bat` は編集できない** — cmd.exe はバッチファイルを行ごとにバイトオフセットで読み直すため、実行中の編集は次の行の読み出し位置を壊す。結果、`13_batch_run_ln512.bat` という別ファイルを作って退避した。「1 本の bat を放置で回す」という当初の目的と正面から衝突する。

### 2. 設定ファイルを触ると未実行ブロックが道連れになる

**走行中プロセスは起動時に config を読み終えているので安全**である。危険なのは **同じ bat のまだ起動していないブロック**で、こちらは編集後の `Atari.txt` を読む。この日 `Atari.txt` を 1 行修正したが、それが後続 7 ブロックへ及ぼす影響は人間が頭の中で追うしかなかった。

### 3. exe 差し替えの粒度がバッチ単位しかない

現行の唯一の exe スナップショット機構は bat 先頭の 1 行である。

```bat
copy /Y "bin\%BUILD%\AnetRLRunner.exe" "bin\%BUILD%\AnetRLRunner_ab.exe" >nul
```

バッチ開始時に 1 回コピーするだけなので、**エントリごとに exe を指定できない**。「この腕だけ旧ビルドで回す」「実装中の機能を含むビルドを後ろのエントリにだけ当てる」ができない。

### 4. キューの状態が見えない

何が終わり何が残っているかは、`echo` の出力を目で追うしかない。残り時間も、ブロック構成を人間が読んで足すしかない。

**したがって欲しいのは**: 投入した時点で計画が凍結され、キューはファイル操作で編集でき、走行中の変更が未実行分へ波及しない仕組み。

## 効く事実（既存機構の調査結果 2026-08-31）

**この 5 点により、必要な新規実装は「解決だけして学習を始めないモード」と「キューの監督」の 2 つに縮む。**

1. **`--config <path>` が完全自己記述モード**で、workspace 解決を丸ごとバイパスする（[RunnerApp.cpp:235-244](../../apps/runner/src/RunnerApp.cpp)、[CONTEXT.md:257](../../CONTEXT.md)）。スナップショットを食わせる口が既にある。
2. **`config/config_data.txt` は解決後の実効設定**で、`$include` も `.$` 選択もプロファイルも含まない（実測 843 行、選択キー 0 件）。値参照 `${}` も展開済み。**そのまま `--config` へ渡せば冪等になるはず**（未検証。受入条件 1 へ）。
3. **`app.run_name` の `{t}` は config 解決では展開されず literal のまま残る**（実測 `run_{t}_i_rr4_ln512_breakout`）。同じスナップショットを再投入しても Run フォルダは衝突しない。
4. **batchrun モードは `app.exp_exit_step` で自己終了する**。監督側はプロセス終了を待つだけでよく、進捗を解釈する必要がない。
5. **CLI 位置引数 `key=value` は解決の最優先層**（[config_impl.cpp:60-65](../../core/anet-core/src/config_impl.cpp)）。スナップショットに対する最終上書きとして安全に使える。

## 提案

### 形: キューもフォルダが真実

`workspaces/<ws>/queue/` 直下に連番エントリフォルダを置く。

```
workspaces/atari-2nd/
  config/
  runs/
  queue/
    0010_rr4_ln512/
      config_data.txt     投入時に凍結した完全自己記述 config
      entry.txt           exe 指定 / 追加 CLI 上書き / ラベル / メモ
    0020_rr4_tau/
    0030_rr4_hard/
    done/
      0005_wiring/
    frozen/
    failed/
```

| 操作 | 手段 |
|---|---|
| 順序変更 | 連番のリネーム |
| 取り消し | フォルダ削除 |
| 保留 | `frozen/` へ移動（`docs/memo` と同じ規約） |
| 内容変更 | 未実行エントリの `config_data.txt` を直接編集 |
| 追加 | `--enqueue` で投入、または既存エントリのコピー |

**走行中に上流の `Atari.txt` を書き換えても、キュー内は一切影響を受けない。** 凍結済みだからである。これは「Run フォルダ = 真実 / 分類はフォルダ操作で完結」という既存方針の素直な延長にあたる。

### 投入

```
AnetRLRunner.exe --workspace atari-2nd --enqueue "run.$=...>run.@rr4_ln" E1.game=breakout
```

現行の起動コマンドの `--enqueue` 違いにする。処理は、

1. 通常どおり config を解決する
2. 学習を開始せず、実効設定を `queue/<次番号>_<label>/config_data.txt` へ書く
3. exe 指定・追加上書き・ラベルを `entry.txt` へ書く
4. 終了する

**既存の解決経路をそのまま通すので、「投入したもの」と「走るもの」が同一であることが構造的に保証される。** 別実装のパーサを持たない点が重要。

### 実行

キュー先頭のエントリについて

```
<pinned exe> --config queue/<entry>/config_data.txt <entry.txt の追加上書き>
```

を起動し、終了を待ち、`done/` へ移す。次のエントリへ進む。

### exe スナップショット

`entry.txt` の `exe = ` で指定する。

| 書き方 | 意味 |
|---|---|
| 省略 | 実行時点の既定ビルド（現状と同じ挙動） |
| `@snapshot:<name>` | `bin/snapshots/<name>/` に固定したもの |
| 絶対パス | そのまま |

`--enqueue --pin-exe <name>` で投入時にコピーを取る。**既定は pin しない** — 全エントリで無条件にコピーするとディスクを食うため、必要な時だけ指定する（「適宜指定」の要求どおり）。

pin してあれば、**キューが走っている最中にビルドし直しても未実行エントリは影響を受けない**。

## 受入条件（暫定）

1. **冪等性**: 既存 Run の `config_data.txt` を `--config` で再投入し、生成される `config_data.txt` が入力と一致する。**これが破れると提案の前提が崩れる**ので最初に確認する。
2. **凍結**: エントリ投入後に上流 config を書き換えても、そのエントリの実行結果が変わらない。
3. **編集の安全性**: キュー実行中に未実行エントリを追加・削除・並べ替えでき、走行中エントリに影響しない。
4. **exe 固定**: pin したエントリが、その後の再ビルドの影響を受けない。
5. **bat 置換**: 現行の 7 ブロックバッチ（[apps/11_batch_run.bat](../../apps/11_batch_run.bat)）を、投入 7 回 + キュー実行 1 回で等価に再現できる。
6. **run_name 衝突なし**: 同一エントリを 2 回実行しても Run フォルダが衝突しない。
