# GridMaze の迷路を必ず解ける形にする — 解けない seed は派生 seed で決定的に引き直す PRD

> 2026-10-24 起票（`/anet-create-prd`、Claude Code）。グリルで決めたこと: 解けない迷路は派生 seed で引き直す（D1）、解ける seed の迷路は 1 セルも変えない（D2）、env が外に出す seed は実際に迷路を作った seed（D3）、解けない設定と不正な座標は fail-fast（D4）、切替キーは足さない（D5）。細部 7 件は推奨の既定で埋めた（§6）。
> 起点: [PRD098](098_temporl_skip_policy_10prd.md) の段 1 で、`GridMazeEnv.seed = 2` の 5×5 が解けない迷路になり、skip 有効・無効とも不達で比較に使えなかったこと（098 の §7「段 1 の途中経過」）。
> 番号は正式採番の次（最大 099 の次）。[memo README](README.md) §採番の「常に最大値の次を使う」に従う。表の `0xx` は 3 桁の時系列 ID の意味で読む。

> 2026-10-24 実装前監査で改訂（Codex、ユーザー合意）。固定開始とランダムゴールの偶然一致は派生seedで引き直す。初回とは別に最大1000回引き直す。ログ抑制に必要なプロセス共有状態はGridMaze内だけの例外として許容する。正の盤面寸法を検証する。

> 2026-10-24 実装照合でD3を補足。既存のseed表示は上位bitが立つ値を負数で表示し、設定へ戻せない。盤面描画は維持し、表示seedを設定可能な範囲の正しい十進表記にそろえる。

## 1. 目的と問題

GridMazeEnv は seed から各セルを壁 20%・穴 10% で独立に引くだけで、開始からゴールへ到達できるかを確かめない。固定 seed（`randomize_seed = false`）では Run 全体が解けない迷路になり、`randomize_seed = true` では解けないエピソードが混ざって評価値に意味の無い値が入る。5×5・密度 0.2/0.1・ゴール (4,4) では seed 1〜60 のうち解けるのは 35 個で、解けない seed を引く確率は約 4 割ある（§2）。

本 PRD は、GridMazeEnv が出す迷路を「開始から壁と穴を避けてゴールへ到達できる」ものに限る。既に解ける seed の迷路は変えない。

## 2. 現状（2026-10-24 にコードで確認したこと）

- 生成（[GridMazeEnv.cpp:125-178](../../core/envs/gridmaze1/src/GridMazeEnv.cpp)）: `rnd_->SetSeed(current_seed_)` で mt19937_64 を初期化し、y 行 x 列の順に `Uniform01()` を引いて、`p < wall_density` なら壁、`p < wall_density + hole_density` なら穴にする。ゴールの座標（−1 なら乱数で選ぶ）にゴールを置き、開始の座標（−1 なら候補から乱数で選ぶ）のセルをゴールでなければ空ける。到達可能性は見ない。開始・ゴールの座標が盤の中かも見ない（盤の外なら範囲外アクセス）。
- `Reset`（同 180-208）: `randomize_seed` なら `MakeAutoSeed()`、そうでなければ設定の `seed` を `current_seed_` にして生成する。コンストラクタ（同 60）も `Reset()` を呼ぶので、最初の迷路は env の構築時に生成される。
- 外に出す値（`MakeAuxData`、同 105-123）: aux の `seed`（`current_seed_`）・`width`・`height`・`pos_x`・`pos_y`・`ep_reward_sum`・`map`。GridMazeView は aux の `map` を盤面に、`seed` を「Seed:」の文字に描く（[GridMazeView.cpp:119](../../core/envs/gridmaze1/src/GridMazeView.cpp)・152-160）。
- `Step`（同 210-258）: 行動は上・左・下・右の 4 つ。盤の外と壁は衝突（`reward_wall`、位置は変わらない）。穴は `reward_hole` で終端、ゴールは `reward_goal` で終端。
- 乱数（[random.cpp:48-78](../../core/anet-core/src/random.cpp)）: `SetSeed` は `std::mt19937_64::seed`、`Uniform01` は `engine_()` を 2^64−1 で割って float にする。派生 seed の既存の作り方は `splitmix64(base_seed_ + index)`（同 197）。
- 解ける seed の割合: 上の手順を Python で再現し（seed 2 の迷路が 10/24 の画面と全セル一致）、5×5・密度 0.2/0.1・ゴール (4,4) で seed 1〜60 を数えると解けるのは 35 個。seed 2 は開始行の下が壁 3 つと穴、右端が穴で囲まれている。既定 seed（[GridMaze.txt](../../apps/runner/config/GridMaze.txt) の `GridMazeEnv.seed`）は最短 8 で解ける。
- 10/24 の実測（PRD098 §7「段 1 の途中経過」）: `GridMazeEnv.seed = 2` の 400k Run は skip 無効が −1.00（100 step うろつく）、有効が −1.03（穴へ落ちる）で、どちらも学習の成功率 0。
- テスト（[GridMazeEnv_test.cpp](../../core/envs/gridmaze1/src/GridMazeEnv_test.cpp)）: 密度 0 か 1 の 2×2・3×2 で終端の読み取りを確かめる 1 件。穴のケース（3×2・穴密度 1.0・開始 (0,0)・ゴール (2,0)）は全セルが穴の解けない迷路で、「右へ 1 歩で穴」を前提にしている。到達可能性のテストは無い。

## 3. ゴール・非ゴール・成功の測り方

ゴール:

- GridMazeEnv が出す迷路は、開始から壁と穴を避けて（4 近傍で）ゴールへ到達できる。
- 既に解ける seed の迷路は 1 セルも変えない（既定 seed の迷路と、10/22〜10/24 の Run との比較可能性を保つ）。
- 解けない seed は、同じ seed なら同じ迷路に、決定的に置き換わる。

非ゴール:

- 迷路の難しさ（最短路の長さ、穴の近さ）の制御。別の関心なので別 PRD（§8）。
- 生成アルゴリズムの変更（DFS 迷路など）。解ける seed の迷路が変わるので採らない（§8）。
- 観測・報酬・盤面描画の変更。採用seedの表示書式だけはD3の再現経路に必要な範囲で直す。
- skip 有効の学習が既定 seed の 5×5 で崩壊する機構の解明（PRD098 §9 の 2）。

機構とゴールへの寄与:

- 到達可能性の判定（§5.1）: ゴール 1（必ず解ける）の保証そのもの。
- 派生 seed での引き直し（§5.2）: ゴール 3（解けない seed を決定的に置き換える）の実現。解ける seed では 1 回目で終わるので、ゴール 2（解ける seed の迷路を変えない）を壊さない。
- 座標の検証と上限での停止（§5.4・§5.2）: 解けない設定を黙って通さない（D4）。

成功の測り方: §7 の受入がすべて通り、既定 seed の GridMaze の短い Run の metrics checksum が変更前と一致する。

## 4. 確定事項

| # | 決定 | 理由（依存するもの） |
|---|---|---|
| D1 | 生成した迷路が解けなければ、派生 seed で生成し直す。上限回数に達したら止める | 解ける seed の迷路を変えず（D2）、固定 seed でも自動 seed でも同じ規則で済み、解けない設定は止まる（D4）。退けた案は §8 |
| D2 | 解ける seed の迷路は変えない。セルを引く手順と乱数の消費順は今のまま（§2 の生成）に保つ | 既定 seed の迷路と 10/22〜10/24 の Run の比較可能性（ゴール） |
| D3 | env が外に出す seed（aux の `seed`、画面の「Seed:」）は、実際に迷路を作った seed にする | 画面の値を設定に書けば 1 回目で同じ迷路が出て、再現に 1 値で足りる。盤面描画の変更が要らない。seed表示は設定可能な全範囲を負数にせず十進表記する（D1 に依存） |
| D4 | 上限回数で解けなければ `ANET_SYSTEM_ERROR`。開始・ゴールの座標が盤の外、開始とゴールが同じ座標、ランダム開始で開始の候補が無い設定は構築時に `ANET_SYSTEM_ERROR` | [AGENTS.md](../../AGENTS.md) §Fail-Fast 原則（互換性のない組み合わせ）と §設定値の扱い（動作不能な設定を暗黙に既定値へフォールバックしない） |
| D5 | 到達可能性の保証を切る設定キーは足さない | 解けない迷路を意図して使う場面が無い。[AGENTS.md](../../AGENTS.md) §クリーンブレーク方針（念のための互換を足さない） |
| D7 | 固定開始とランダムゴールが偶然重なった候補は、派生seedで引き直す | 有効な設定を抽選結果だけで失敗させず、開始とゴールを異なる位置にする（D1・D4） |
| D8 | D3のログをプロセス全体で抑制するための共有状態は、GridMaze内に限る例外として許容する | 個体ごとの出力では同じ行がenv数だけ並ぶため。生成の状態は共有しない（D3、ユーザー合意） |
| D6 | 引き直しは「設定値の黙った置き換え」には当たらない | 設定の `seed` は生成の入力であり、要求された迷路そのものではない。設定の seed は書き換えず、実際の seed を aux と INFO ログで公開する（D3、§6 の 4）。§設定値の扱いの「sentinel・magic 値による黙った再解釈」にも当たらない |

担当: 起票・レビューは Claude Code の枠。実装は別の枠。

## 5. 実装契約

### 5.1 到達可能性の判定

- 解ける迷路とは、開始のセルから 4 近傍の移動を繰り返し、壁と穴のセルを通らずにゴールのセルへ着ける経路がある迷路。開始とゴールが同じ座標の設定は、判定の前に D4 で止める。
- 判定は、ゴールを置き、開始のセルが決まったあと（`init_pos` が −1 のときは候補から選んだあと）に行う。開始の位置も迷路の一部で、ランダム開始のときは開始ごとに解けるかが変わるため。
- 判定は Reset ごとに行う。盤は最大でも数十セルで、step のループには入らない（§5.5）。

### 5.2 引き直し

- 1 回目は今の手順どおり、設定の `seed`（`randomize_seed` のときは自動 seed）で生成する。これを seed₀ と書く。
- 解けなければ k 回目（k = 1, 2, …）は seed_k = `splitmix64(seed₀ + k)` で乱数を初期化し、同じ手順で生成し直す（§6 の 1）。seed₀ から決定的に決まるので、同じ設定なら同じ迷路になる。
- 固定開始とランダムゴールが偶然一致した候補も採用せず、同じ派生seedの系列で引き直す（D7）。
- 上限は初回生成とは別に引き直し 1000 回（§6 の 2）。上限に達したら `ANET_SYSTEM_ERROR` で止める。メッセージは §6 の 3。
- `randomize_seed = true` でも同じ規則で、エピソードごとに解ける迷路になる。

### 5.3 外に出す値

- 画面の「Seed:」は設定可能な全範囲の値を負数にせず十進表記する。表示を設定へ戻す再現経路を守り、盤面描画の方法は変更しない。

- env が持つ現在の seed は実際に迷路を作った seed_k にし、aux の `seed` にそのまま出す（D3）。引き直しが無ければ seed₀ と同じ。
- 設定の `seed` は変えない。設定の seed と実際の seed が違う Run は、設定 dump（`config/config_data.txt`）と aux の `seed` を見れば分かる。
- `randomize_seed = false` で引き直しが起きたときは、設定の seed ごとにプロセスで 1 回だけ INFO を出す（§6 の 4）。Run は同じ設定で env を複数作る（既定の GridMaze は学習 256 個と評価用）ので、個体ごとに出すと同じ行が個数分並ぶため。`randomize_seed = true` では出さない。

### 5.4 設定の検証（構築時）

- `width`・`height` は正の整数。それ以外はキー・指定値・期待値を含む `ANET_SYSTEM_ERROR`。座標の選択や盤面の確保より前に止める。

- `init_pos_x`・`init_pos_y`・`goal_pos_x`・`goal_pos_y` は、−1（乱数で選ぶ）か、盤の中の座標（0 以上、幅または高さ未満）。それ以外は `ANET_SYSTEM_ERROR`（キー・指定値・期待の範囲を含める）。
- 開始とゴールの両方が固定で同じ座標なら `ANET_SYSTEM_ERROR`。
- ランダム開始（`init_pos` のどちらかが −1）で、選んだゴールに対して開始の候補が無いとき（1 列や 1 行の盤でゴール以外のセルが無いなど）も `ANET_SYSTEM_ERROR`。今は (0,0) か固定側の値へ黙って落ちる（[GridMazeEnv.cpp:169-172](../../core/envs/gridmaze1/src/GridMazeEnv.cpp)）が、同じ検証の経路なので一緒に止める。候補はゴールを決めたあとに検証し、構築中の初回生成だけでなく後続の Reset でも空なら止める。
- `wall_density + hole_density` が 1 を超える設定は、今と同じく止めない（穴の判定が残りの確率を全部取るだけで、動作不能ではない）。解ける迷路が出ないときは §5.2 の上限で止まる。

### 5.5 性能

- 判定は Reset ごとに最大でも幅 × 高さ のセルを 1 回ずつ見る探索で、引き直しは稀。step のループに入らないので、性能の受入は持たない。

### 5.6 移行対象（クリーンブレーク）

- 設定キーの追加・改名は無い。現用の設定（GridMaze.txt、GridMaze_muzero.txt、各 Workspace、`testdata/prd072/baseline/gridmaze*.json`）は既定 seed・5×5・密度 0.2/0.1・(0,0)→(4,4) の解ける迷路なのでそのまま。
- 現用のテストで新しい契約に合わないものは [GridMazeEnv_test.cpp](../../core/envs/gridmaze1/src/GridMazeEnv_test.cpp) の穴のケース（§2）だけで、同じ変更内で移す。意図（右へ 1 歩で穴に落ちる終端の読み取り）は保ち、解ける迷路で開始の右隣が穴になる設定にする。例: 3×2・穴密度 0.5 で、aux の `map` を見て開始の右隣が穴かつ解ける seed を小さい順に探して使う。壊れる現用物はこのテストだけ（ほかの GridMaze の現用物は上の行のとおり解ける）。
- 過去の Run artifact・実験記録は触らない。解けない seed で取った 10/24 の `run_20261024-065353_t98_b3_m2_*` は記録として残す。

## 6. 細部（推奨の既定）

1. 派生 seed の作り方: k 回目の引き直しは `splitmix64(seed₀ + k)`。[random.cpp:197](../../core/anet-core/src/random.cpp) の `splitmix64(base_seed_ + index)` と同じ作りで、決定的かつ連続する seed でも無相関。
2. 引き直しの上限: 初回生成とは別に 1000 回（試す迷路は最大 1001 個）。5×5・密度 0.2/0.1 で解ける確率は約 0.58 なので、1000 回で解けないのは設定の問題と見てよい。探索 1 回は数十マイクロ秒で、上限まで回っても起動時に収まる。
3. 上限で止めるときのメッセージ: 設定の seed、幅と高さ、壁と穴の密度、開始とゴールの座標、上限回数を含める（Fail-Fast 原則のメッセージの規約）。
4. ログ: `randomize_seed = false` で引き直しが起きたら、設定の seed ごとにプロセスで 1 回だけ INFO（設定の seed、引き直した回数、実際の seed）。単位を seed にするのは AGENTS.md §Fail-Fast 原則の「WARN は対象ごと 1 回だけ出し、ログを spam しない」と同じ考えで、Run が同じ設定で作る env の個数によらず 1 回になるため。`randomize_seed = true` では出さない（エピソードごとの spam を避ける。実際の seed は aux で見える）。
5. 設定の検証の場所: コンストラクタ（§5.4）。ランダム開始（`init_pos` が −1）のときは、開始を決めたあとに判定し、解けなければ同じ引き直しに乗せる。
6. 受入テスト: §7 の 1〜5。既定 seed の golden は 25 セルの文字列（`.` 空き、`#` 壁、`O` 穴、`G` ゴール）: `...#.` / `#..#.` / `....#` / `.#O..` / `.O..G`。
7. 設計文書: [120_environments.jp.md](../design/120_environments.jp.md) の GridMaze の行に「到達可能性を保証し、解けない seed は派生 seed で引き直す」を足す。wiki の 322 には起票時に書き戻した（成立の経緯・選ばなかった形・変えるときの条件）。

## 7. 検証と受入

受入（外から観測できるもの。テストは [GridMazeEnv_test.cpp](../../core/envs/gridmaze1/src/GridMazeEnv_test.cpp) に `[gridmaze]` で足す）:

1. 5×5・密度 0.2/0.1・開始 (0,0)・ゴール (4,4)・`seed = 2` で、Reset 後の aux の `map` が解ける迷路（開始からゴールへの経路がある）で、aux の `seed` が 2 ではない。
2. 同じ設定で既定 seed（`6545537233705677626`）のとき、aux の `map` の 25 セルが §6 の 6 の golden と一致し、aux の `seed` が設定の値と同じ。
3. 壁密度 0.9・穴密度 0.1 で構築すると `ANET_SYSTEM_ERROR`（上限 1000 回で解けない）。
4. `randomize_seed = true` で 50 回 Reset して、毎回 aux の `map` が解ける迷路で、aux の `seed` が毎回異なる。
5. 開始 (0,0)・ゴール (0,0)、ゴール (9,9)（5×5 の外）、および 1×1 でゴール (0,0)・開始をランダム（`init_pos_x = -1`）にした設定（開始の候補が無い）で構築すると `ANET_SYSTEM_ERROR`。
6. 既定 seed の GridMaze の短い Run（PRD098 の段 0 と同じ手順、skip 無効）の metrics checksum が今と一致する。
7. 既定 seed で引き直しが起きない Run のログに、引き直しの INFO が出ない。`seed = 2` の Run（既定どおり学習 env 256 個と評価用 env を作る）のログに INFO がちょうど 1 回出て、設定の seed・回数・実際の seed が読める。

8. 同じseedの反復Reset・別個体で同じ迷路になり、auxのseedを設定に戻すと同じ盤面を再現する。固定開始とランダムゴールの偶然一致を引き直す。ランダム開始・部分的なランダム座標も到達可能性を満たす。
9. 非正の幅・高さ、各座標の −2・軸の上限以上を構築時にエラーにする。

## 8. 作らないもの・先送り

| 事項 | 扱い | 理由と再開条件 |
|---|---|---|
| 解けなければ止めるだけ（人が解ける seed を選ぶ） | 不採用 | `randomize_seed = true` の Run が途中のエピソードで止まる。固定 seed でも seed を選ぶ道具が運用に残る。制約ではなく選択で、後から D1 と入れ替えられる |
| 通路を掘る（最短路のセルを空ける） | 不採用 | 迷路の分布が「掘った迷路」に偏り、掘り方の規則が増える。解ける seed を変えない点は同じだが、D1 で足りる。制約ではなく選択で、クリーンブレークで移せる |
| 生成アルゴリズムの変更（DFS 迷路など） | 不採用 | 解ける seed の迷路も変わり、既定 seed の迷路と過去の Run の比較可能性を失う。本当の制約ではなくクリーンブレークで移せるが、本 PRD のゴール（比較可能性を保つ）に反する |
| 到達可能性の保証を切る設定キー | 不採用 | 解けない迷路を意図して使う場面が無い（D5）。制約ではなく選択で、場面が出たらキーを足せる |
| 迷路の難しさ（最短路の長さ、穴の近さ）の制御 | 範囲外 | 別の関心。再開条件: 難しさの違いで学習の差を見たくなったとき |
| seed から迷路を復元して解ける seed を列挙する道具をリポジトリに置くこと | 範囲外 | 本 PRD の後は解けない seed が出ないので要らない。難しさの制御（上の行）を作るときに一緒に検討する |
| ADR | 起こさない | 戻しにくさが無い（引き直した迷路に依存する記録はまだ無く、規則を変えても §7 の 2 で解ける seed の不変は守れる）。判断の理由は D1〜D6 にある |

## 9. 未決

なし。

## 10. 依存と順序

- 単独で作れる。ほかの PRD に依存しない。
- PRD098 の段 1 で迷路 seed を変えて比べる Run は、本 PRD の後に取ると解けない seed を避けられる。
