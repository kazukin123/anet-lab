# NoisyNet のノイズ込み重みに対する Spectral Normalization

2026-10-02、[PRD 084: NoisyNet](084_noisynet_10prd.md) のレビュー指摘 A.1 から切り出した暫定 PRD。番号は 999 とし、方式・公開設定・数値的な受け入れ条件は未裁定とする。084 の実装・完了の前提条件にはしない。

## 1. 問題と目的

NoisyNet のノイズ込み重み \(W_\varepsilon=\mu^w+\sigma^w\odot\varepsilon^w\) を正規化する場合、正規化対象がノイズの再抽選ごとに変わる。既存 SN の永続 u/v と学習 forward ごとの 1 回の power iteration を流用するだけでは、この重みに対する推定精度と、Actor・target・診断を含めた動作を定義しきれない。

さらに、μ-only で ε を 0 にすると、摂動だけでなく正規化分母も変わる。これは推定を十分正確にした後にも残る性質である。評価・追加診断を μ-only にする 084 の契約とどう組み合わせるかを含め、アルゴリズムとして別途裁定する必要がある。

本 PRD は、ノイズ込み重みを正規化する具体的な必要性と、そのための推定・状態・評価・検証契約を検討する。SN の演算自体が原理的に不可能だと判断した記録ではない。084 は μ 正規化 \(\mathcal{S}(\mu^w)+\sigma^w\odot\varepsilon^w\) までで独立して完了できる。

## 2. 現行契約とレビューの根拠

### 2.1 現行 SN で確認したこと

[NN 設計](../design/130_neural_networks.jp.md) と [ADR 0032](../adr/0032-spectral-norm-self-impl-buffer-semantics.md) は、学習可能な重みを追う u/v を named buffer として保持する。初期化で 15 回の power iteration を行い、以後は train mode かつ GradMode 有効の forward だけで 1 回更新する。

Actor・target・追加診断は u/v を更新しない。ただし、正規化分母を保存して読む方式ではなく、どの forward でもその時点の重みと保存された u/v から推定値を再計算する。既存契約自体も、学習と eval の 1 回の更新差を許容した近似であり、厳密な最大特異値との一致は保証していない。

この仕組みが追う対象を、抽選ごとに方向の変わる \(W_\varepsilon\) へ差し替えても同じ精度が得られるとは限らない。学習だけで ε に追従させると、それ以外の forward は別の ε に対応する u/v を使う可能性もある。

2026-10-02 に確認した Atari カタログでは、SN 付き Linear は trunk の `AtariLinear512SN` / `AtariLinear512CAP` にあり、value / advantage 用の `AtariHeadFC512` 定義には SN 指定がない。現在の適用箇所からも、ノイズ込み SN の裁定を NoisyNet 導入全体の必須条件にする必要はない。

### 2.2 初期摂動の構造と報告値

084 の factorised Gaussian と一定値の σ 初期化では、初期摂動は次の外積になる。

\[
\Delta W=\sigma^w\odot\varepsilon^w
=\frac{\sigma_0}{\sqrt{p}}e^{out}(e^{in})^\top,\qquad
\|\Delta W\|_2=\frac{\sigma_0}{\sqrt{p}}\|e^{out}\|_2\|e^{in}\|_2
\]

非ゼロならランク 1 であり、その方向が μ の主要な特異方向と一致する保証はない。学習後は σ の要素ごとの値が変わるため、摂動が常にランク 1 であるとは扱わない。

以下は、レビュー指摘 A.1 で提供された測定例である。本起票では再計測していない。条件は \(\sigma_0=0.5\)、`init.mode=default`、入力 2304・出力 512 の Linear。

| 量 | レビュー提供値 |
|---|---:|
| μ の最大特異値 | 0.84 |
| ノイズ込み重みの最大特異値 | 8.7〜9.2 |
| μ を追う u/v をそのまま使ったノイズ込み重みの推定 | 0.79〜0.83 |
| そこから 1 回 power iteration した推定 | 0.83〜2.9 |
| 3 回 power iteration | この例では真値へ収束したとの報告 |

この例は、μ 用 u/v の再利用や 1 回の追加反復だけでは大きく過小推定し得る根拠として扱う。「3 回ならすべての層・重み・ε で十分」という受け入れ条件にはしない。seed、ε、反復の初期状態、device・dtype、比較基準と許容誤差を保存した再現資材は正式化時に用意する。

なお、現行の `AtariLinear512SN` / `AtariLinear512CAP` の定義は `init.mode=xavier` である。上の default 初期化の例を、そのカタログ設定で実行した Run の測定値とはみなさない。

### 2.3 μ-only と noisy の意味

厳密な正規化を仮定しても、\(\mathcal{S}(\mu^w)\) と \(\mathcal{S}(\mu^w+\Delta W)\) では分母が異なる。上の例では μ 成分に掛かる係数にも約 10 倍の差が生じ得るが、noisy 出力には摂動項もあるため、層出力や最終 Q が一律に 10 倍違うとは言えない。

μ-only がノイズ期待値と一致しないことは NoisyNet 一般の注意点でもある。本件では、ε の除去に伴って分母も変わることが追加の論点になる。推定誤差を解消する問題と、評価・診断でどの関数を測るかという問題を分けて扱う。

## 3. User Stories

1. 実験者として、μ 正規化では満たせない比較目的があるとき、ノイズ込み重みの正規化を独立した実験条件として評価したい。
2. 実験者として、Actor・Learner・target・診断で、推定方法や状態更新の差が結果へどう影響するかを理解したい。
3. 実装者として、batch 共有・遷移別独立と IQN の τ 間共有を維持しながら、ε に対応する推定を正しく行いたい。
4. 実験者として、μ-only と noisy の評価・診断が表す意味、および追加計算・メモリの費用を確認したい。

## 5. 別途裁定する事項

| 論点 | 決める内容 |
|---|---|
| 適用目的・対象層 | μ 正規化と比較したい具体的な構成と検証目的。必要性がなければ μ 正規化にとどめる選択肢も残す |
| ε ごとの推定 | 新しい ε ごとに使う初期 u/v、反復回数または停止条件。報告例の 3 回を普遍的な既定値にしない |
| 永続 u/v の対象 | μ、直近のノイズ込み重み、その他のどれを追うか。永続化せず一時状態で推定する案とも比較する |
| forward ごとの状態更新 | Actor・Learner・target・診断での計算と更新の有無。同じ重み・ε・推定初期状態に対する計算差の許容範囲 |
| 保持・共有との対応 | batch 共有 / 独立、episode / N 回保持、IQN の τ 間共有。ε を保持中に μ・σ が更新・同期された場合の再推定 |
| 参照計算 | 厳密な最大特異値を求める SVD を正規化結果の正本にするのか、定義した近似アルゴリズムを正本にするのか |
| 精度基準 | 同じ近似手順との出力・勾配一致と、SVD に対する推定誤差を区別する。後者の許容誤差・対象ケース・失敗時の扱いを決める |
| μ-only | ε=0 の重みをそれ自身の分母で正規化する意味を採用するか。他案を採る場合は名称・評価・`policy_churn`・`replay_fit` 等の契約まで定義する |
| SN mode・勾配 | `spectral` / `spectral_cap` の扱い、分母を経由する μ・σ の勾配、退化・非有限な推定の扱い |
| 所有権・費用 | 推定状態の所有者、同期・保存対象、一時状態のサイズ、独立ノイズ時の計算・メモリ量 |

精度を揃えるために Actor や診断が学習用の永続 u/v を書き換える案を、未裁定のまま既存機構へ混ぜない。必要なら副作用のない一時推定を比較するが、本起票では方式も反復回数も確定しない。

## 6. 検証候補と昇格条件

採用案を決める前に、少なくとも次を比較できる状態にする。

- seed・重み・ε・初期 u/v を固定し、レビュー例と、形状・初期化・学習後の σ が異なるケースで推定誤差を調べる。
- 厳密な特異値への誤差と、採用した推定手順による forward / 勾配の一致を別の検証項目として記録する。
- shared / independent、同じ状態の τ 間共有、ノイズ保持中の parameter 更新で、対応する重みが正規化対象になることを確認する。
- Actor・Learner・target・診断の更新契約と、診断が学習 RNG・ε 保持・永続状態へ干渉しないことを確認する。
- μ-only と noisy の正規化分母、Q、行動不一致を観測し、診断値の解釈を定める。
- μ 正規化と比較した速度・CPU/GPU メモリ、および必要な実験での効果を記録する。

正式化には、具体的な比較目的・対象範囲、ε ごとの推定方法、永続 u/v の対象、参照計算と数値的受け入れ条件、μ-only の意味、公開設定・所有権を裁定する。実験結果が採用を支持しなければ構造や設定を追加しない判断も残す。
