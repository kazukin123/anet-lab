## 1. 目的と問題

Montezuma's Revenge の n-step 10 の構成では、学習側にまれに出る高い報酬のエピソード（部屋 23 で 1,000 点を取ったゲーム）が、定着する Run としない Run に分かれる。9 本中 8 本の学習側に 1 本以上出たが、定着したのは数千本出た 2 本だけで、ほかの 6 本は 12M 以降に 1〜8 本しか出なかった（§2.2）。数本しか出ないエピソードは、Replay の lane 窓を過ぎると上書きされ（§2.3）、学習に使われる回数が限られる。

この RFD は、まれに出た上位のエピソードを Replay とは別に持ち続け、その遷移の外的の Q を、実際に得た割引収益で下から引き上げる仕組みを DQN 系の Learner に足す。見つける数を増やす仕組み（NGU）とは別に、見つけたものを手放さない側を受け持つ。

## 2. 現状

### 2.1 学習の報酬と点

- 学習の外的報酬は `AtariEnv.reward_clip = true` で、点が入るたびに +1 になる。1 ゲームの報酬は 2500 点 4、2600 点 5、2700 点 6、3500 点 4、3600 点 5、3700 点 6、5600 点 8、6600 点 8 である（出典: [実験記録](../experiments/default-dqn/atari/2026-11-08_montezuma-rnd-taiga-aligned.md)、目的と比較条件の「報酬」の行）。
- 学習率 3e-4 の Run で部屋 23 に入った 12 本の点は、2500・2600 点に 1,000 点ずつ 1〜3 回足した数と合い、3500 点は報酬 5、4500 点は報酬 6、5500 点は報酬 7、5600 点は報酬 8 だった（出典: 同、探索ブロック25）。部屋 23 では 1,000 点を取るたびに報酬が 1 増える。

### 2.3 Replay の保持

- この群の Replay の容量は 2,097,152 で、128 lane なので lane 1 本あたりの窓は 16,384 である。容量を 2 倍（lane 1 本あたり 32,768）にした Run は 1 本だけで、Greedy の平均は下がった（出典: [実験記録](../experiments/default-dqn/atari/2026-11-08_montezuma-rnd-taiga-aligned.md)、現時点のまとめ33。lane 窓の語は [Replay ratio と lane 窓](../wiki/concepts/methods/replay_ratio_lane_window.md)）。
- 44・45 の学習側のゲームは、24〜30M にゲームオーバーで終わった割合が 98%・100% で、1 ゲームの長さの平均は 2,229・1,077 step だった（出典: 同、現時点のまとめ40）。平均の長さは lane 窓の 1/7 以下で、その長さのゲームは、終わった時点では遷移が全部 Replay に残っている。

### 2.4 触る既存部品

- Replay の口は `Push(batch_exp, gammas)` と `Sample(out_samples, minibatch_size, beta, gammas)` で、prefetch を受け持つ包みが同じ口を持つ（[replay_buffer.hpp](../../src/core/base/include/anet/replay_buffer.hpp) の 127〜128 行）。
- 価値の分解が有効のとき、Learner は外的と内的の Head ごとに誤差を作る（[dqn_learner.cpp](../../src/algo/dqn/src/dqn_learner.cpp) の 521〜532 行）。損失の重みと優先度の重みは `learner.intrinsic.loss_weight`・`learner.intrinsic.priority_lambda` で持つ（[dqn_config.hpp](../../src/algo/dqn/src/dqn_config.hpp) の 242〜252 行）。
- IQN の分位点の損失は `QuantileLearnerBase::ComputeQuantileHuberLoss` が作る（[dqn_learner.cpp](../../src/algo/dqn/src/dqn_learner.cpp) の 2218〜2262 行）。
- Actor の行動は、既定（`intrinsic.action_beta_mode = learner`）で外的の Q と内的の Q を Learner の β で合わせた値から選ぶ（[dqn_config.hpp](../../src/algo/dqn/src/dqn_config.hpp) の 150〜164 行）。

### 2.5 文献の事例

- **SIL**（Oh ら 2018）: エピソードが終わったあとに計算した割引収益が価値の推定を上回る組だけに損失を掛け、上回った分を Replay の優先度にする。A2C に足して、難探索 7 ゲーム中 6 で最良（Montezuma's Revenge 2,500）だった。Venture では正の報酬を一度も得ず、序盤に活用しすぎて準最適に留まるゲームもあった。SIL と同じ優先度の PER を ACER に付けた版は A2C より悪く、著者は IS の項が原因と推測した（出典: [PER の弱点のサーベイ](../../reports/survey/per_priority_weaknesses_survey_2026-11-18.md)、§5.2）。
- **EMDQN**（Lin ら 2018）: エピソード記憶を学習の監督に使い、DQN の 1/5 の相互作用で高い性能に達したと要旨で主張する。本文は未読（出典: 同、§5.2）。
- **PSER・EBU**: 収益を手前の遷移へ流す手法で、PSER は Montezuma's Revenge でほぼ 0%、EBU も DQN 比でほぼ 0 だった（出典: 同、§5.1）。どちらも、まれなエピソードを持ち続ける仕組みではない。
- **DTSIL**（Guo ら 2020）: 記憶した軌跡をなぞる方策を学ぶ。Atari の結果は状態の表し方に RAM の位置を使う（出典: [内的報酬の手法の全体像のサーベイ](../../reports/survey/intrinsic_reward_landscape_survey_2026-11-18.md)、§5.3 の表の DTSIL の行）。
- SIL を Q 学習へ広げた手法（Tang 2020 の下限 Q 学習、He ら 2017 の Optimality Tightening）は、手元のサーベイに無い。記憶による。

## 3. ゴールと非ゴール

**ゴール**: まれに出た上位のエピソードを、Replay の上書きで失わずに学習に使い続け、その遷移の外的の Q を実際の収益まで引き上げる仕組みを、設定で有効にできる形で DQN 系の Learner に足す。Montezuma's Revenge の n-step 10 の構成で、部屋 23 まで行くエピソードが数本出た Run が、Greedy で部屋 23 まで行く道に定着する割合を上げられるかを確かめる。

**非ゴール**:

| 退ける案 | 理由（本当の制約か） |
|---|---|
| 部屋 23 のエピソードを見つける数を増やすこと | NGU（RFD0173）の役目で、別の関心である。制約ではなく分担 |
| 3500・3600 点の道を得にすること（報酬の切り詰め方を変える） | 報酬の物差しの話で、この RFD の物差し（U2）と別の関心である。wiki のまとめでは、切り詰めの代わりの h 変換などは全体の集計でほぼ同等かやや劣った（P12）。制約ではない |
| 途中の状態からゲームを始める形（Go-Explore 型の戻る操作） | RFD0173 §2.4 の裁定で、ゲーム仕様を別にする形は採らない（P9）。本当の制約である |
| RAM の値を状態の表し方や報酬に使う形（DTSIL） | 同じ裁定の線（P9）。本当の制約である |
| 価値の分解が無効の構成で使うこと | 収益の物差しが内的報酬を含んでしまう（U6）。分解を前提にするのは暫定の既定で、クリーンブレークで広げられる。制約ではない |

## 6. 仕様（暫定の既定による）

この節は §9 の暫定の既定を前提に書いた。括弧の中は前提にした未決表の番号である。

### 6.1 流れ

1. Learner は lane ごとに、今のエピソードの外的報酬の和（切り詰め後）と、エピソードの始まりの位置を持つ（U2・U5）。
2. エピソードが終わったら、次の条件をすべて満たすときだけ、記憶に入れる候補にする（U3・U4・U5）。
   - ゲームオーバーなどの終端で終わった（打ち切りではない）。
   - 外的報酬の和が 0 より大きい。
   - 長さが lane 窓以下で、遷移が全部 Replay に残っている。
3. 記憶の本数が上限に満たなければ入れる。満ちていれば、和が記憶の最小以上のときだけ入れ、最小のもの（同点なら古いもの）を外す（U3）。
4. 入れるときに、その lane のエピソードの遷移を Replay から写し、遷移ごとに割引収益 G を付ける（U5・U6）。
5. 1 回の更新のバッチの一部を記憶から一様に引き、残りを Replay から今のとおり引く（U9・U10）。
6. 記憶から引いた遷移には、通常の損失に加えて下限の損失を外的の Head だけに掛ける。Replay から引いた遷移には掛けない（U7・U8・U11）。

### 6.2 割引収益と下限の損失

エピソードの長さを T、外的報酬（切り詰め後）を r_t、外的の割引率を γ（この群では 0.997）とすると、時刻 t の割引収益は次のとおりである（U6）。

```text
G_t = Σ_{k=0}^{T-1-t} γ^k · r_{t+k}
```

G_t は、用語集の target return（Replay が持つ N-step の割引和）をエピソードの終わりまで延ばした値で、次の値を足さない。用語集の episode return（割り引かない和）とも違う。この RFD では「割引収益」と呼ぶ（U21）。

下限の損失は、IQN では online の外的の分位点を、その更新で引いた τ について平均した値 Q̄_ext(s_t, a_t) に掛ける（U7）。

```text
L_lb = λ · ½ · max(0, G_t − Q̄_ext(s_t, a_t))²
```

TBO が有効なら、G_t を Q と同じ変換で写してから比べる（U6）。境界の挙動は次のとおりである。

| 場面 | 挙動 |
|---|---|
| Q̄_ext ≥ G_t | 損失も勾配も 0。Q を下げない |
| Q̄_ext < G_t | 差の 2 乗に比例して引き上げる |
| 記憶が空 | バッチを全部 Replay から引き、下限の損失は 0 |
| 価値の分解が無効 | 構築時に止める（U6） |

| 設定キー | 値 | 今あるか | 使うモード |
|---|---|---|---|
| `learner.self_imitation.mode` | `off`（既定）／`lower_bound` | 新しく足す | すべて |
| `learner.self_imitation.lower_bound.episodes` | 記憶するエピソードの本数。整数 1 以上。既定 16 | 新しく足す | `lower_bound` |
| `learner.self_imitation.lower_bound.batch_fraction` | バッチのうち記憶から引く割合。0 より大きく 1 より小さい。既定 0.125 | 新しく足す | `lower_bound` |
| `learner.self_imitation.lower_bound.loss_weight` | 下限の損失に掛ける係数 λ。0 より大きい有限の値。既定 1 | 新しく足す | `lower_bound` |
| `learner.intrinsic.loss_weight` | 内的の損失に掛ける係数 | 今ある | 価値の分解 |

設定例（コロン記法）:

```text
run.@sil : DefaultDQNAgent.learner.self_imitation.mode = lower_bound
run.@sil : DefaultDQNAgent.learner.self_imitation.lower_bound.episodes = 16
```

不正な値の扱い（AGENTS.md の Fail-Fast 原則の、設定の誤りの区分）。行は上から順に当て、最初に当たった行で止める。どの行にも当たらなければ、構築を続ける。

| 場面 | 挙動 |
|---|---|
| `mode` が `off`・`lower_bound` のどちらでもない | 構築時に止め、設定キーの全名と受け付ける値を示す |
| `mode = off` で `lower_bound.*` を書いた | 構築時に止める（使わない設定を黙って読み流さない） |
| `mode = lower_bound` で、価値の分解が無効 | 構築時に止め、`intrinsic.value_mode` の全名を示す |
| `episodes` が 1 未満、`batch_fraction` が 0 以下か 1 以上、`loss_weight` が 0 以下か有限でない | 構築時に止め、値と範囲を示す |
| バッチの大きさ × `batch_fraction` が整数でない | 構築時に止め、バッチの大きさの設定キーの全名と、整数になる割合の例を示す（引く数を丸めない） |

記憶からは、記憶の全遷移から一様に、復元ありで引く（U9）。

## 7. 機構ごとのゴールへの寄与と、仮説・比べ方・終わり方

| 機構 | ゴールへの寄与 |
|---|---|
| 上位エピソードの記憶 | まれに出た上位のエピソードを、lane 窓を過ぎても学習に使い続ける |
| 下限の損失 | 記憶したエピソードの遷移の外的の Q を、実際に得た収益まで引き上げる |
| メトリクス | 記憶に部屋 23 のエピソードが入ったか（最大の和が 7 以上か）と、引き上げが働いているか（G が Q を上回る割合と損失）を見る |

- **仮説**: 部屋 23 のエピソードが数本出た Run でも、記憶と下限の損失があれば、Greedy で部屋 23 まで行く道に定着する。
- **比べ方**: U18 による。暫定の既定では、44・45 と同じ構成に `mode = lower_bound` を足して 4 seed を流し、Greedy が部屋 23 まで行く Run の割合を、n-step 10 の 9 本の 2/9 と比べる。
- **終わり方**: 4 seed の 30M を流し終えたところで判定する。4 本すべてが定着すれば、9 本中 2 本と比べた Fisher の正確検定（片側）でおよそ 0.02（15/715）で、効いたとみなす。2 本以下なら効かなかったとし、記憶の中身と損失のメトリクスで、記憶に部屋 23 のエピソードが入らなかったのか、入っても引き上げが効かなかったのかを分ける。3 本なら seed を足すかを開発者が決める。

## 8. 成功の測り方

- 主な指標: Greedy（`53_evalg`・`54_evalgs`）の 20〜30M に 5500 点以上のゲームが半数を超えた Run の割合。比べる相手は §2.2 の 9 本（45・48 の 2/9）。
- 補う指標: 学習側の 12M 以降の 5500 点以上のゲームの数（§2.2 と同じ数え方）、`38_agent_loss/15_sil_memory_return_max` が 7 以上になった exp step と、Greedy で 5500 点以上が初めて出た exp step の間。
- 部屋 23 のエピソードが 1 本も出ない Run（44 型）は、この仕組みでは変わらない見込みで、割合の分母からは除かない（seed ごとの探索の当たり外れを含めて比べる）。

### 2026-11-28 の会話（SIL の解説）

開発者の発言:

- Montezuma's Revenge では膠着して打ち切りで終わるエピソードも多いので、終端で終わったものだけを入れる形ではあまり効かないかもしれない。ε のある lane なら大丈夫かもしれない。エピソードの長さも Replay の容量に対してきついので、調整が要るかもしれない（U4・U5）。
- エピソード記憶は、既存の Replay を土台にせず新しく作ることになるのか。抽選など似た要素があるので、できるだけ共通にしたい（U26）。
- 上位 16 本は独自の案かと尋ねた（U3）。
- 「記憶」は一般の語すぎて混乱するので、「エピソード記憶」などと言い換えてほしい（U21）。

AI の案と調べたこと:

- U4（打ち切りで終わったエピソード）: 報酬が負にならない構成（Montezuma の切り詰め後の報酬は 0 か +1）では、打ち切りまでの G は、続けていた場合の収益以下で、下限として正しい。原典の SIL の公式実装も、打ち切りを終端として扱い、先を足さない（[サーベイ](../../reports/survey/sil_value_based_lower_bound_survey_2026-11-24.md)、§4.1）。P13 の根拠は Run 44・45 だけで、学習側で打ち切りで終わる割合は構成によって 4〜11%（b001）から 74〜89%（rnd_b001）まで違う（[実験記録](../experiments/default-dqn/atari/2026-11-08_montezuma-rnd-taiga-aligned.md)、現時点のまとめ 4・8）。
- U5（写し方）: lane 窓より長いエピソードも、Replay に残っている後ろの部分だけを写せば、その部分の G は正しい（G_t は t より後の報酬だけで決まる）。写した部分の先頭の数 step は、フレームスタックの履歴が欠ける。
- U24（prefetch の包みの Push との順序）: 写す口は、積まれた Push の完了を待つ必要がある。
- U26（`TopEpisodeStore` の作り）: Replay の内部は、遷移の器、抽選できる範囲の管理、n-step の目標の組み立て、抽選、束の組み立てに分かれている（`src/core/base/src/replay_buffer_impl.hpp`）。共有すれば、束の組み立て（[ADR 0063](../adr/0063-replay-slot-keeps-per-step-reward-and-end-and-samples-variable-windows.md)・[ADR 0065](../adr/0065-scheduled-gamma-recomputes-return-at-sample.md)・[ADR 0073](../adr/0073-replay-keeps-reward-components-and-builds-returns-per-component-discount.md)・[ADR 0095](../adr/0095-frame-stack-setting-is-agent-wide-and-replay-buffer-answers-sample-spec.md) が決めた形）を二重に持たずに済む。一様の抽選と束の組み立ての実装は今 `replay_buffer_impl.cpp` の中だけにあり、内部ヘッダへ出す手直しが要る。1 本を 1 区画にすると、16 本 × 16,384 遷移で観測が約 1.7 GiB（84×84 の 1 フレーム 1 バイトとした目安）になる。もう 1 つの代わりの案は、公開の `CreateReplayBuffer` で 2 つ目の Replay を作る形で、外すエピソードが「和が最小の 1 本」から「古い順」に変わり、G の欄と lane 1 本だけに Push する口を公開の口に足すことになる。
- U3（エピソード記憶の単位・本数・入れ替え）: 上位の軌跡だけを持つ記憶は、方策ベースの自己模倣に先行例がある。GASIL は割引収益で上位 K 本（大きさは step 数で 1,000・10,000）、SIDP は割り引かない和の優先度つきキューで 10 本を持つ。価値の下限の損失と組み合わせた事例は見つかっていない。GASIL は、記憶を大きくすると記憶の軌跡の収益の平均が下がったと述べる（[作業ノート](../../reports/notes/self_imitation_memory.md)、項目 1〜3）。通算の上位なので、16 本がほぼ同じ道で埋まりうる。
- U12（sticky actions の運のよい収益）: 上位を選ぶと、同じ道の中でも運のよかった回を選ぶので、U12 の理由（上位の数本だけを持つので運だけの収益の割合は下がる）と逆の向きに働きうる。SIDP も、確率的な環境では過去の上位の軌跡を真似るだけでは最適方策に戻りにくいと述べる（[作業ノート](../../reports/notes/self_imitation_memory.md)、項目 2）。対策の候補は、n 歩の下限（Tang）、λ を下げる、本数を増やす。
- U11（損失の重み λ）: 価値ベースの例は 0.1 が多い（Tang、EMDQN。EMDQN は大きくすると悪化した）（[サーベイ](../../reports/survey/sil_value_based_lower_bound_survey_2026-11-24.md)、§4.2）。IQN の分位点 Huber は差が 1 を超えると線形で、½·x² と大きさの増え方が違う。
- U22（外的の bootstrap が `combined` のときの下限と TD）: `learner.intrinsic.extrinsic_bootstrap_mode` の既定は `combined` で、外的の Q は新しさも追う方策の外的の価値を学ぶ（[価値の分解の設計文書](../design/214_value_decomposition.jp.md)、§3.1・§4.1）。
- U23（外的の γ を予定で変える構成）: G は入れたときの γ のまま残る。外的の γ の設定（`learner.gamma`）は時間で変わる値を書ける。
- 受入 4 は「§6.3 の不正な値の表の 4 行」と書くが、§6.3 の表は 5 行ある。グリルでそろえる。
- U10（優先度と IS）: 本体の PER の IS 重みはバッチの最大で割って 1 以下にそろえるので、エピソード記憶の分を 1 にすると、本体でいちばん重い遷移と同じ重みになる。
- U25（PPO 系から使うか）: 原典の PPO+SIL は、PPO の 1 回の更新ごとに SIL の更新を 10 回（バッチ 512）足し、SIL の損失に新旧の方策の比を使わない（[作業ノート](../../reports/notes/self_imitation_memory.md)、項目 4）。PPO 系では lane ごとに今のエピソードを貯める入れ方が避けられないので、共通の部品にするなら、Replay から写す入れ方と両方を持つかが論点になる。
- U21（用語）: 文献で「エピソード記憶（episodic memory）」は、EMDQN や NEC の (s, a) ごとの収益の表を指すことが多く、紛れうる。
- §4 の P10・P11: 2026-11-24 のサーベイが扱っている。グリルで §2.5 と §4 の出典を書き直す。
