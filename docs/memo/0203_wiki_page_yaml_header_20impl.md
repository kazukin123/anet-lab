# wiki の YAML ヘッダと Obsidian 一覧 実装メモ

## 概要

[RFD0203](0203_wiki_page_yaml_header_10rfd.md) のステージ 1（道具の実装と 2 枚での試用）の計画。基準コミットは `1f5c8c40`。対象は [issue-20261126-4c7b4e](../management/issues/issue-20261126-4c7b4e.md)。

## 主な変更

- `reports/tools/wiki_support.py` の `headers` で、本文・目録・フォルダ・作業の記録から RFD §8.1 の値を作る。既存の材料とサマリの対応、Markdown リンクの走査、PyYAML を使う。全ページの出力を検証してから、バイト列に差があるページだけを書き込む。ヘッダの外にある本文と、管理対象外のキーに属する記述をバイト単位で保持する。
- `scan` は同じ生成処理を使い、ヘッダの欠落・差分・ページ固有の入力エラーと、主要な概念のリンクの不備を警告に加える。サマリの長さと概念のページの書式・出典の検査は本文で行う。既存の警告の行番号は本文内の位置を基準とする。
- 作業ツリーの wiki ページ・材料・目録・作業の記録を一時フォルダに写して `headers` を回す。その結果から、元から存在するサマリ 1 本と、そのサマリが指す概念のページ 1 枚だけにヘッダを反映し、2 枚の本文と他ページの内容が同じであることを確認する。
- 手元の `docs/wiki/wiki.base` に 2 枚の確認用の表を用意する。既存の Summary の表を保持し、試用の列を持つ表でリンクのクリックと表示名を確認できるようにする。全ページ用の表は試用結果が出たあとのステージ 2 で反映する。

## テスト

公開 CLI の `headers` と `scan` を、一時作業ツリーから検証する。各項目でテスト 1 件を追加し、RED を確認して最小限の実装で GREEN に戻し、必要な整理を行う。

1. 材料と概念を参照するサマリと、目録に載る概念のページを置き、`headers` が両方に規定のキーと値を順に書くことを確かめる。
2. 管理対象の値を戻し、追加されたキーの並び・表記と本文を保持する。書き直した状態での再実行は同じバイト列になる。
3. RFD の D16（入力不備で書き込まない）の各条件で、終了コードと理由を返し、全ファイルをそのまま保つ。空に読めるヘッダは書き直せる。
4. `scan` はヘッダの欠落、差分、個別ページの入力不備を警告し、点検の起動条件を保つ。目録と作業の記録が無い場合は従来どおり終了する。
5. 作業の記録の末尾側の一致行から日付を取る。日本語の読点で区切ったパスとパスの後ろの注記を扱う。
6. サマリの blob、8,000 文字の境界、概念ページの書式と出典の警告、目録に無い概念ページの空欄、実在しない概念へのリンクを個別に検証する。手書きの YAML に Markdown と似た文字列や改行があっても、本文の検査は本文の結果を返す。

## 前提

- RFD0202 のステージ 3（RFD・設計文書・ADR の取り込み）は [完了記録](0202_wiki_accumulate_and_lookup_21impl.md#ステージ-3-の取り込みと検証)で確認した。
- `headers` は全ページを対象とする。試用時の絞り込みは作業コピーから反映するファイルを 2 枚選んで行う。対象ページは、本物の材料と概念への両リンクを持ち、既存の作業ツリー差分に含まれないものを選ぶ。
- 保管庫の根はリポジトリの根とする。`updated` は作業の記録から取り、Git の履歴は使わない。ページの種類の正本がフォルダであるため ADR 0098 と整合する。課題の `rfd` 欄での表示先の重複は別課題で扱う。
- Obsidian の試用結果はステージ 2 の着手条件。運用手順の改訂と全ページの移行はその後に行う。

## ステージ 1 の実装と検証

- `headers` と `scan` の実装、公開 CLI からの検証を追加した。初回はコマンド未登録で失敗し、実装後に書き込みを確認した。続けて、独自欄と本文の保持、入力エラーでの書き込み前の停止、警告と点検の起動条件、更新日、本文の書式と出典、主要な概念のリンクを検証した。
- 2026-11-27、`.scratch/rfd0203/pilot_headers.py` で作業ツリーの隔離コピー 475 枚を処理し、全ページの本文が同じバイト列であることと、2 回目の出力が 0 件であることを確認した。`--apply` で [ADR 0098 のサマリ](../wiki/summary/adr/0098-concept-pages-are-split-by-the-question-they-answer-and-kinds-live-in-folders_summary.md) と [開発プロセス・開発ツール・テスト基盤（311）](../wiki/concepts/framework/311_dev_tools.md) の 2 枚へ反映した。実データの `scan` では YAML ヘッダ未導入の 473 枚だけが警告に挙がった。
- 初回レビュー前の検証は `rfd0114/issues_test.py` が 34 件、`rfd0202/wiki_test.py` が 20 件成功。RFD0095 の標準起動は、Windows 上でテストが環境を復元した際に空の `GIT_CONFIG_VALUE_0` が消え、後続の `git read-tree` が終了値 128 になった。テストのプロセスだけ `GIT_CONFIG_COUNT=0` を指定した再実行は 20 件成功した。
