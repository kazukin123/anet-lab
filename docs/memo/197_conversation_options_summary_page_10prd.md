# PRD197: 記号付きの案が増えた会話で、案・決定・未決のまとめページを作って随時更新する 暫定 PRD

> 2026-11-22 起票（暫定）。質疑を省いた。確定した決定は持たず、AI が置いた既定と決めきれない点を §6 の未決表に置いた。§7〜§9 は §6 の暫定の既定を前提に書き、前提にした行の番号を名指す。
> 起点: 2026-11-22 の会話。ユーザーが、Atari の枠の会話で対策案に記号を振ったあと、記号だけで話が進んで中身を見返すのがしんどいと述べた（§10）。記号を出すたびに短い名前を添える決まりはその場で直し（[AGENTS.md](../../AGENTS.md) の「AI エージェントの概念説明ルール」）、まとめページはこの暫定 PRD で起票した。
> 課題: [issue-20261122-717309](../management/issues/issue-20261122-717309.md)（この PRD の仕事）。

## 1. 目的と問題

### 1.1 問題

会話で案・選択肢・論点に記号（A〜G、1〜5、P3、U1 など）を振ると、そのあとの会話は記号で進む。ユーザーは、記号が何を指すか、どの案を試してどうなったか、何が決まったかを確かめるために、元の応答までスクロールして戻る必要がある。スマホでは、長い会話の中から元の応答を探すのがとくにしんどい（P1）。

記号を出すたびに短い名前を添える決まり（P3）で、1 つの記号の中身はその場で分かるようになった。しかし、案の全体（いくつあり、どれを試し、どうなったか）と、決まったこと・未決は、会話を読み返さないと一覧できない。

### 1.2 ゴール

- 記号付きの案が増えた会話で、ユーザーが、案の一覧と状態、決まったこと、未決を、会話を遡らずに 1 か所で見返せる。
- その場所を、スマホからも開ける（Claude Code の会話）。
- AI が、言われなくても、条件に当たったら作り、会話の進みに合わせて更新する。簡単な題材では作らない。

### 1.3 非ゴール（退けた案と、本当の制約か）

- まとめページを正本にすること — 決定の正本は PRD・実験記録・課題に置く（P10）。ページは見返し用の写しで、決定を書く先を増やさない。本当の制約（正本を 1 つにする方針）。
- 会話の本文での記号の扱いを変えること — 記号に名前を添える決まり（P3）はそのまま続ける。ページを作っても、問いと決定は会話で行う。本当の制約ではなく、役割を分けるための線引きである。
- Codex の会話でスマホから見られるようにすること — Codex に同じ道具があるかを確かめていない（P8、欠け）。本当の制約かは分からず、道具を確かめれば範囲に入れられる。範囲外にするかは §6 の 6 で決める。

### 1.4 機構とゴールの対応

| 機構 | ゴールへの寄与 |
|---|---|
| 始める条件（§6 の 1） | 簡単な題材では作らず、案が増えた会話でだけ作る |
| ページの中身（§6 の 3） | 案の一覧と状態・決定・未決を 1 か所で見返せる |
| 更新の時機（§6 の 4） | 会話の進みとページが食い違わない |
| 置き場（§6 の 5・6） | スマホから開ける |
| 会話をまたぐ引き継ぎ（§6 の 13） | 新しい会話へ移っても、同じページで見返せる |

### 1.5 成功の測り方

- 記号付きの案が 3 つ以上出た会話で、AI が、言われずにページを作り、案の状態や決定が変わった応答で更新している（会話の記録で数える）。
- ユーザーが、案の中身を確かめるために会話を遡る、または「C は何だっけ」と聞き返すことが、ページのある会話で起きない（ユーザーの報告と会話の記録で確かめる）。
- 測る期間と本数は §6 の 12 で決める。

## 3. 背景

PRD161 のグリルは論点と方針が多く、AI がまとめの HTML を作ってユーザーが見返した（P2）。この形は、その会話の中での工夫で、決まりには書かれていない。Atari の枠の会話では作られず、ユーザーは記号の中身を探して会話を遡った（P1）。

## 4. 用語

- **まとめページ**: 会話の中で振った記号付きの案・選択肢・論点と、その状態、決まったこと、未決を並べた HTML のページ。本 PRD での呼び名で、用語集には足さない（§6 の 11）。既存の語のうち、PRD の前提の表・未決表は PRD の中の記録、wiki のトピック別まとめは機能ごとの知見の置き場で、どちらも会話の進みに合わせて更新する見返し用のページを指さないので、言い換えられない。

## 5. 現状（2026-11-22 に文書と道具で確認）

- 記号に名前を添える決まりはある（P3）。まとめページを作る決まりは、AGENTS.md・skill・プロセスの文書のどこにも無い。確かめ: `AGENTS.md`・`.agents/skills/`・`docs/process/`・`docs/quality/` を、`git grep -E` で `まとめ.{0,30}(HTML|ページ)` と `(HTML|ページ).{0,30}まとめ` を引いた（件数を切らずに引いた）。当たった 4 件（`AGENTS.md` 136 行、`anet-create-prd/SKILL.md` 18・194・220 行）は、どれも wiki のトピック別まとめを読む・書く決まりで、会話のまとめページを定めるものは無かった。
- Claude Code では、ページを出す道具（P4）と、ファイルを別の端末へ送る道具（P5）が使える。スマホから開けるか（P6）と費用（P7）は確かめていない。
- Codex に同じ道具があるかは確かめていない（P8）。

## 7. 仕様（暫定の既定を前提）

- AI は、会話で記号を振った案・選択肢・論点が 3 つ以上になったら、聞かずにまとめページを作り、開く先を 1 行で知らせる（§6 の 1・2）。ユーザーが頼んだときも作る。
- ページの節は、いまの位置、案の一覧、決まったこと、未決、更新の日時で、冒頭に見返し用の写しである旨を書く（§6 の 3）。
- 案・状態・決定・未決のどれかが変わった応答の中で、同じページを更新する（§6 の 4）。Claude Code では同じ URL を保ち（§6 の 5）、Codex では `.scratch/summary/` のファイルを更新する（§6 の 6）。
- 会話の本文では、記号に名前を添える決まりを続け、問いと決定は会話で行う（§6 の 7）。
- 題材が終わったら、いまの位置に「終わった」と書いて更新をやめる（§6 の 8）。
- Claude Code で、同じ題材の続きを新しい会話で行うときは、AI が一覧から題でページを探して読み直し、同じ URL のまま更新を続ける（§6 の 13）。

## 10. グリルの材料
