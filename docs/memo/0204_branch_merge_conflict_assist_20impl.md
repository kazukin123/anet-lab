# ブランチを取り込むときの衝突解消支援 実装メモ

## 概要

[RFD0204](0204_branch_merge_conflict_assist_10rfd.md) と [issue-20261126-56483f](../management/issues/issue-20261126-56483f.md) に従い、main を取り込み元としてブランチのワークツリーで衝突を解く手順と、マージのコミット前に wiki の RFD 一覧を確かめるための変更を実装する。

## 主な変更

- `wiki_support.py maps` で、振り直しの行のコミットの名指しを検査する。コミットと旧い番号を組にして当て先を決め、名指しのある行はほかのコミットに適用しない。誤りは RFD のファイルと行を示して、生成物を書き込む前に停止する。マージ中は `HEAD` と `MERGE_HEAD` 側の履歴を読み、通常時の `HEAD` だけの履歴と同じ処理で一覧を作る。
- `anet-merge-branch` の SKILL.md と agents/openai.yaml を 2 か所に置き、AGENTS.md の参照先と Git 操作の例外、両方の skills README、memo の採番と wiki の規約をそろえる。試しのマージと差分の読み方、区画ごとの解き方、開発者の承認、つどステージする範囲、検証と再適用を skill に記す。検出コマンドは skill に記し、検出スクリプトの作成は初回適用の観測を待つ。採番の予防は別課題で扱う。
- 日本語の設計文書「アプリケーションとツール」に、`maps` がマージ中に読む履歴と、旧い番号の照合を追記する。
- 題材の課題を対応中にし、実装と検証の結果を追記する。機械で作る区画は既存の `maps` を使う。

## テスト

対象は rfd0095 の `wiki_test.py` が入口を通して検証する `maps` の生成結果・停止結果。各項目を RED → GREEN の順に進める。

1. 同じ日付・同じ旧番号を件名に持つ 2 コミットを、名指しの有無によって、振り直した RFD と旧い番号を使い続ける RFD に分けて載せる。
2. 空欄、不正な形、同じ行の重複、複数のコミットに一致する接頭辞、対象履歴に無い名指し、振り直しの日付より後のコミット、旧い番号を持たない件名、別 RFD からの二重名指しを検証する。生成物に書き込む前に止まることも確かめる。
3. 一時リポジトリの通常のブランチでは片側、マージ中は両側の RFD が載り、マージのコミット前後で一覧が一致することを確かめる。

## 前提

- 実装を変えるユーザー判断は残っていない。RFD はグリルとレビューを経て暫定の印が外れている。CONTEXT.md の「マージ」を避ける規約は設定の選択チェーンに当たり、Git のマージでは RFD の用語を使う。
- ADR 0077 の日付制約は維持する。コミットの名指しがある振り直しの行は、その日付以前かつ旧い番号が件名にあるコミットに限って当てる。名指しが無い過去の行と、件名を先に渡す `maps` の使い方を保つ。名指しは `maps` が読むコミット履歴の完全ハッシュで照合する。
- ADR 0056・0097・0098 に従い、wiki の派生本文を扱うときは出典を引き直し、wiki だけが持つ記述を移した先へ残す。用語集や ADR の追加は要らない。
- 監査時の main は `a60bae83` で origin/main より 5 コミット先。wiki の Python 実装・テスト・規約と AGENTS.md に並行差分は無かった。課題一覧などは並行作業の生成差分があるため、既存の課題単票と作業ツリーの差分を確認してから再生成する。
- PPO の初回適用は実装後に専用の入口で行う。main に実装が載った時点の両ブランチを引き、承認を受けてから振り直し・マージへ進む。振り直しとマージのコミット、push、PR の取り込みは開発者が行う。実装の検証と続けて進められるところまで確認し、最初の適用が完了していない受入はその結果を課題に記録する。
