# wiki の構造移行と既存資料の取り込み 実装メモ

## 概要

[RFD0202](0202_wiki_accumulate_and_lookup_10rfd.md) §9.10 の Codex 担当、ステージ 1〜3 を記録する。[課題 822a3e](../management/issues/issue-20261125-822a3e.md)。成功の測り方とステージ 4 は [Claude Code の実装メモ](0202_wiki_accumulate_and_lookup_20impl.md) が持つ。着手時点の基準コミットは d39d2f07。

## 主な変更

1. ステージ 1 で wiki の規約、取り込み・点検の skill と参照元、設計文書 160、実験記録の規約、レビュー観点、報告の目録を更新する。知見の 30 ページを題材・手法・測り方・現象に振り分け、7 節と小見出しを置く。トピック別まとめ 16 ページに「外の事例」を足す。旧 subjects・mechanisms・apps・categories はそれぞれ concepts/subjects・本文の問いに応じた concepts/{methods,measurement,phenomena}・concepts/apps・concepts/framework に移す。過去の記録はリンク先だけ直し、作業の記録は追記だけとする。
2. wiki_support.py の scan と maps を移行する。材料とサマリをパスと blob で照合し、点検対象と書式上の警告を区別する。警告の種類と対象は RFD §8.10 に従う。サマリは正本の出典に使わない。
3. ステージ 2 で実験記録 49 本・報告 45 本を原本から取り込む。材料ごとに、サマリ、主張の主な掲載先と要旨、横断的知見、既存の見立て、目録、取り込みの記録を順に点検する。最初の 5 本は使用量を実測して 408 本分に換算し、開発者の明示的な返答を待つ。半ばでも測る。終わりに Claude Code の独立した出典照合の結果を開発者に示してから次へ進む。
4. ステージ 3 で RFD・日本語の設計文書・ADR を取り込み、最初の 5 本の使用量を測る。最後に会話から引く・書く skill、共通の開始条件 2 行、wiki の手順と記録種別 query を導入する。各ステージ末に対応した課題・検証を記録し独立レビューを受ける。

## テスト

- 公開される面は wiki_support.py の scan の JSON と maps 実行後の文書。実ファイルを持つ一時 Git リポジトリから CLI を通す。
- 最初のテストは現行 blob の取り込み記録があってもサマリが無ければ pending となり、同じ blob のサマリがあれば消える経路。他の挙動は一つずつテストを足し、失敗を見てから実装し再実行する。
- 次に古い・欠けた・不正な blob、移動した材料、材料が消えたサマリ、書式と長さ、外からのリンク切れと修復を検証する。警告だけでは eligible が変わらず、query の行は起点と取り込み状況に影響しない。maps の再生成で人の書く節が保たれることも確かめる。
- 既存の rfd0095・rfd0114 の期待値を保って新しいパスとサマリの fixture に移す。rfd0101 の走査先も移す。
