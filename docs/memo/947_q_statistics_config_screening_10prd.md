## Context / Problem Statement

ハイパラの最適値は環境の関数だが、多環境へ展開すると人手探索が `O(env × 腕)` で破綻する。Atari-5 なら 5 ゲーム × 4 点 = 20 Run、フル 57 ゲームなら論外である。

一方で成績（壁突破率）による判定は高コストである。Breakout の実測で、6.16% 対 5.19% の 0.97pt 差を 2σ で分けるのに片側 **約 4,600 エピソード = 6.5M env step** を要した。逆 U 字の頂点近傍はさらに悪く、0.3pt を分けるには差の 2 乗に反比例して片側 68M env step になる。

**しかし多環境展開で必要なのは頂点を当てることではなく、「その env で設定が大きく外れていないか」を知ることである。** こちらは要求される分解能が 1 桁以上ゆるい。

## 実測

### A. τ の最適点と、そのとき Q 統計がどう動いたか

Breakout / RR1 / 50M / V/A ReLU ベース。壁突破率は `42_env/10_game_score_mean` の 25-50M プールで `>= 432` の割合、Q 統計は 45-50M 窓。

| τ | 壁突破率 | `37_agent_qtd/11_q_max_mean` | `35_agent_churn/03_q_delta_abs` |
|---|---|---|---|
| 0.001 | 3.48% | **9.44** | 0.0174 |
| **0.008** | **6.16%** | 11.46 | 0.0183 |
| 0.020 | 5.19% | 11.39 | 0.0198 |
| 0.050 | 4.64% | 11.67 | **0.0251** |
| hard C=125 (a) | 6.29% | 11.22 | 0.0212 |
| hard C=125 (b) | 6.13% | 11.01 | 0.0205 |

成績は逆 U 字（頂点 0.008）。`11_q_max_mean` は τ=0.001 だけが高原（11.0〜11.7、幅 ±3%）から 17% 低く、0.008 以降は飽和する。`03_q_delta_abs` は τ とともに単調増加する。**遅すぎ側と速すぎ側で別の指標が反応し、最適点は「`q_max` が飽和し、`q_delta` がまだ立ち上がっていない膝」にある。**

### B. 伸び率なら既知の良/悪が同一 step で分離する

`37_agent_qtd/11_q_max_mean` の 7-8M 窓平均 → 9-10M 窓平均の伸び率。

| Breakout の腕 | 伸び | 成績（既知） |
|---|---|---|
| τ=0.001 | **+40.2%** | 3.48%（悪） |
| τ=0.008 | +15.8% | 6.16%（最良） |
| τ=0.020 | +11.5% | 5.19% |
| τ=0.050 | +8.6% | 4.64% |

成績での判定は 25M 窓を要したが、この統計は 10M 時点で既知-良/既知-悪を分離している。**遅すぎる τ は「価値がまだ伝播中」として伸び率に残る。**

### C. Atari-5 の既存 Run へ当てた結果（追加計算なし）

`apps/runner/workspaces/atari-5/runs` の 5 本（2026-08-27、[2026-08-27_atari5.md](../experiments/default-dqn/atari/2026-08-27_atari5.md)）は config dump 上 **全て `A1.model.soft_update_tau = 0.001`**。Breakout で 8 倍遅すぎと判明した値である。同一 step で B と同じ統計を取る。

| env | 7-8M | 9-10M | 伸び | 予算 | 判定 |
|---|---|---|---|---|---|
| battle_zone | 0.74 | 1.09 | **+47.9%** | 20M | 既知-悪の帯 |
| qbert | 2.96 | 4.28 | **+44.8%** | 20M | 既知-悪の帯 |
| name_this_game | 5.44 | 7.44 | **+36.7%** | 20M | 既知-悪の帯 |
| double_dunk | −0.63 | −0.72 | −15.3% | 20M | **判定不能** |
| phoenix | 2.03 | 1.52 | −25.1% | 12M | **判定不能** |

**3/5 が既知-悪の帯に入る。** 副次的に、Atari-5 ベースライン 5 本は誤設定の τ で走っており、かつ 20M 予算で `q_max` が収束していない。

### D. 壊れる 2 ケース

- **double_dunk**: Q が負（−0.63）。相対伸び率は符号とゼロ近傍で意味を失う。
- **phoenix**: Q が下降。τ とは別の病理であり、この統計では区別できない。予算も 12M で打ち切られている。

### E. 却下した案

- **`35_agent_churn/13_target_q_delta_abs ÷ 37_agent_qtd/17_q_gap`**: soft 系で τ に対し単調（2.00 → 1.58 → 1.43 → 1.13）だが成績は逆 U 字。**片側指標**であり「速すぎ」を検出できない。さらに hard は 2.01/1.89 で最悪 soft と同値なのに最高成績で、更新方式をまたぐと破綻する。制御の観測量にすると τ を上げ続ける。
- **`q_max` と `q_delta` を正規化した比**: τ=0.001 基準で 1.000 / 1.152 / 1.060 / 0.856 となり、順位が `0.008 > 0.020 > 0.001 > 0.050`。最下位のはずの 0.001 が 3 位に来る。4 点から指標を合成するのは過学習である。

## 案

### 案 1: 進捗率統計（D への対処）

開始点でアンカーして符号と env スケールから独立させる。

```
progress = (v_half − v_start) / (v_final − v_start)
```

Breakout での値は τ=0.001 が **68%**、0.008 / 0.020 / 0.050 が **98〜99%**。走り切った Run に対する事後統計なのでオンラインで出す必要がなく、[054_inspect_run_10prd.md](done/054_inspect_run_10prd.md) 側に `--stat progress` 相当を足すのが素直。env スカラーではなくメトリクス時系列への後処理である点が実装先の判断材料になる。

### 案 2: スクリーニング運用

全 env をスイープせず、**事前分布で 1 本走らせ、ガードが鳴った env だけスイープする。**

事前分布は env-time で持ち込む。τ の最適点は grad step でも wall clock でもなく **env step で決まった**: τ=0.008 @ RR1（125 grad × 256）、hard C=125 @ RR1、BTR C=500 @ 1grad/64env のいずれも **32,000 env step**。独立な 3 設定が同じ env-time に落ちている。

これは [940_target_update_step_axis_10prd.md](940_target_update_step_axis_10prd.md) が RR ラダーから提起した仮説（`soft_update_tau` は「更新あたり」なので RR を変えると target の遅れが exp 軸で変わってしまう）に対する、**独立な実測の裏付け**である。940 は「RR を変えると意図せず 2 変数動く」という A/B の健全性の話だったが、本 PRD の実測は**最適点そのものが env 軸で決まる**ことを示しており、単なる正規化ではなく事前分布として使える。RR4 移行時の env-time 等価は τ=0.002（= hard C=500）。

Atari-5 なら 5 本 → 鳴った 3 本 × 追加 2 点 = 11 本で、全スイープ 20 本より安い。env 数が増えるほど効く。

## 限界（案の前提として明記する）

1. **予算不足と交絡する。** 「まだ伸びている」は「τ が遅すぎ」でも「予算が短い」でも起きる。走り切ってからの事後監査であり、早期検出ではない。
2. **題材固有の学習速度と交絡する。** qbert は Q レンジが大きく（3.6 → 14.4）そもそも収束が遅い。10M で伸びているのが τ のせいか題材のせいかは、この指標だけでは切れない。
3. **判定ではなくフラグである。** スイープが要る env を絞るのが役割で、τ の値そのものは決められない。
4. **閾値は n=1 × Breakout 1 env の校正。** 「+40% は悪、+15% は良」の境界に根拠は薄い。

## 未決 Q

- **Q1**: 進捗率のアンカー `v_start` を何にするか。Run 冒頭の `q_max` はほぼ 0 で不安定（2-3M で 0.19〜5.05 とばらつく）。予算の一定割合（例 5%）時点にするか、`q_start = 0` 固定にするか。
- **Q2**: `v_final` を使うと事後統計にしかならない。予算内の 2 点（例 50% と 100%）だけで書ける形にできるか。
- **Q3**: 速すぎ側のガードを作れるか。実測 A では `03_q_delta_abs` が単調増だが、無次元化の方法が未定（`03/17` 比は E のとおり hard で破綻する）。実務上は遅すぎ側の損失（−43%）が速すぎ側（−25%）より大きいので、片側ガードでも価値の大半は取れる。
- **Q4**: 対象は `soft_update_tau` だけか。同じ「価値伝播が律速されているか」の枠は gamma・n_step・replay_ratio にも当たるはずだが、未検証。
- **Q5**: 負値 Q / 下降 Q の env（double_dunk・phoenix）を、案 1 で本当に救えるか。実データでの確認が要る。
- **Q6**: [927_metric_targeted_hyperparam_control_10prd.md](927_metric_targeted_hyperparam_control_10prd.md) との境界。あちらは Run 中の閉ループ、本 PRD は Run 後の開ループ監査。τ は閉ループの標的として不適（目的関数が高コスト・むだ時間 25M・観測量に絶対基準なし）という結論は本 PRD 側の実測から出ており、あちらの標的選定にも反映が要る。

## 着手条件

**現時点では着手しない。** 理由は 2 つ。

1. **Munchausen（[067](done/067_MunchausenRL_10prd.md)）が TD target に `α·τ·log π` を加算するため、Q のスケールが変わる。** 本 PRD の閾値は全て Munchausen 前の Q 統計で校正しており、実装後に校正し直しになる。
2. **RR4 移行で env-step ↔ grad-step の対応が 4 倍変わる。** 事前分布（32,000 env step）は保たれる想定だが、RR1 で校正した伸び率の閾値がそのまま使えるかは未確認。

着手するなら Munchausen 実装 + RR4 移行の後。最小の検証は、Atari-5 の 3 ゲーム（battle_zone / qbert / name_this_game）で τ を env-time 32,000 相当へ上げて 1 本ずつ引くこと。ガードが「遅すぎ」と言った env で実際に成績が上がるかの直接検証になる。3 本 × 20M ≈ 3.5h。
