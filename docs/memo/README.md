# docs/memo — PRD と実装計画の置き場

PRD (`NNN_<slug>_10prd.md`) と実装計画 (`NNN_<slug>_2ximpl.md`) を置く。

**状態はフォルダで表す。** ファイル内に `Status:` 行は持たない
(`docs/agents/issue-tracker.md` の規約どおり、`Status:` は `.scratch/` の実装 issue 側の概念)。

| 場所 | 意味 | 移動時に足す行 |
|---|---|---|
| 直下 | 未対応 / 対応中。新規 PRD は常にここへ起票する | なし |
| `done/` | 完了。実装が main にコミット済み | なし |
| `frozen/` | 凍結。再開条件が満たされるまで着手しない | `> 凍結中(再開条件: ○○)` |
| `dropped/` | 中止。やらない判断、または後継 PRD へ昇格した | `> 中止(理由: ○○)` |

## 運用

- 移動単位は番号セット一式。`NNN_*_10prd.md` と `NNN_*_2ximpl.md` は必ず一緒に動かす。
- 完了の定義は git。実装が main に入った時点で `done/` へ移す。
- `frozen/` と `dropped/` に足す 1 行は「状態」ではなく「再開条件・理由」。フォルダでは
  表現できない情報だけを書く(状態の二重管理はしない)。
- 番号は時系列 ID であって状態ではない。`900` / `999` は正式採番前の暫定番号で、着手時に
  正式番号へ採番し直す。
- 未対応と対応中は分けない。暫定番号が末尾に固まるため直下の一覧で見分けが付く。

## リンクの注意

サブフォルダへ移すと相対リンクの深さが 1 段変わる。

- 移動するファイル内の `](../` は `](../../` になる。
- 直下に残るファイルを指すリンクには `](../` を足す。
- 他ディレクトリ(`docs/design` 等)から移動先を指すリンクにはフォルダ名を挿入する。
- 同じ行き先へ一緒に移る組(PRD と対応する実装計画など)のリンクは無修正で生き残る。

移動後は必ずリンク切れ検査を実行する。

```bash
find docs -name '*.md' | while read f; do
  grep -ohE '\]\([^)#][^)]*\)' "$f" | sed 's/^](//; s/)$//' | grep -v '^http' | while read l; do
    [ -e "$(dirname $f)/${l%%#*}" ] || echo "BROKEN: $f -> $l"
  done
done
```
