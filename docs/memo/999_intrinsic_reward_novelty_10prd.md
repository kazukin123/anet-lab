## 1. 目的と問題

エージェントの側に、ゲームに依らない汎用の内的報酬（観測の新しさへのボーナス）を足す。狙いは 3 つ。

1. 報酬に出ない途中の進み具合に手応えを与える。KFM ではボスに当てても 0 点で、撃破はクリップ後 +1 と雑魚と同じなので、挑んでいる間の上達が報酬に出ない（§2.3）。当てるたびにバーが縮み、そのゲームでまだ見ていない画面になるので、エピソード内の新しさは命中ごとのボーナスになることを期待する（埋め込みがバーの差を保持するかは未検証）。
2. 何度も見た状態（KFM の 1 面での稼ぎ）より、そのゲームでまだ見ていない状態（ボスへ向かう道、ボス戦、出口の換算、2 面）の価値を高くし、練習の場をそちらへ寄せる。
3. 学習の分布の外でも壊れないようにする。ε や UQE の揺らぎは点数の方策の Q から作るので、Q が収束すると、集まるデータも点数の方策の通る状態のまわりに縮み、外れた状態では Q が正しくならない（GridMaze、§2.7）。新しさを目的にする探索役が状態を覆い続け、点数の方策がその遷移からも学ぶことで、点数の方策がほとんど通らない状態からの到達率を改善したい。到達は保証せず、§9 で測る。

### ゴール

- 新しさのボーナスを、DQN 系 Agent の報酬に加えられる。既定は無効で、無効のときは今と同じ学習系列になる。
- 逆動力学の埋め込みとエピソード内の新しさを足す。NGU の k 近傍方式と E3B を差し替えられる構成を必須とする。初期採用方式と両方式を実装する時期は未決（§8 の 1）。
- RND による一生の新しさを、NGU 型の倍率として組み合わせられる。エピソード内だけ・RND 単独も比較対象にする。E3B との合成・尺度は別に決める。
- ボーナスの重み β と割引率 γ が違う方策の家族を学ぶ。方策インデックスは lane ごとのエピソード開始時に選び、そのエピソード内で保持する。lane 数と方策数は独立である。
- BTR を基にした既存 DQN 学習との組み合わせを検証する。原論文の RNN・Retrace を導入するかは、それぞれ独立した論点として扱う。採否と性能を原論文の再現と混同しない。
- ボーナスの大きさ・学習の様子・報酬全体に占める割合と、埋め込みが命中を区別しているかを指標で見られる。
- 評価（configured eval と EvalPanel）は、新しさを使わない点数の方策で行動する。点数の方策の価値は、探索役の lane を含む全 lane の遷移から学ぶ。点数の方策が収束しても、探索役が状態を覆い続ける（§2.7。学習の形は §8 の 2）。
- 埋め込み・新しさ・方策の家族は、観測の種類（ベクトル・画像）や env の知識に依らず、観測の仕様と設定だけで組める（§8 の 5）。

### 非ゴール

- ゲーム固有の知識で報酬を作ること（RAM の値への報酬、ボス体力の減りへのシェーピング）。ユーザーの裁定で採らない（§2.4）。RAM メトリクスは効き目を測るためだけに使う。
- 環境の仕様を変えること。KFM の途中の状態からの開始（§2.4 の裁定）と、GridMaze の学習時の開始位置を到達できるセル全体からばらすこと・迷路の盤面を観測に入れること（2026-10-24 のユーザーの方針: Env 固有の前提を入れず、Agent 側のアルゴリズムで対策する）を含む。どれも技術上の制約ではなくユーザーの裁定なので、裁定が変われば移せる。GridMaze の位置や盤面は、効き目を測るためだけに使う（§9.1）。
- 実行時に、そのエピソードの経験で価値を補正する仕組み（EVA 型）と、eval の遷移（EvalPanel の手操作を含む）を学習に流すこと。学習の分布の外へ連れて行かれたときの備えだが、学習のデータの分布を広げる本 PRD とは別の関心なので別 PRD にする（§6）。
- 認識論的な不確かさ（アンサンブル）による楽観。別の機構なので、必要になったら別 PRD にする（§6）。
- LLM の好みを内的報酬にする方式（Motif 型）。[999_llm_actor_10prd.md](999_llm_actor_10prd.md) と [LLM の事前知識で RL の探索と報酬を補助する手法のサーベイ](../../reports/llm_prior_knowledge_rl_survey_2026-10-18.md)（2026-10-18）の側で扱う。
- 成功したエピソードのリターンを記憶して Q の下限にする仕組み（EMDQN 型）。別の関心なので別 PRD にする（§6）。

## 2. 背景: KFM のボス討伐と GridMaze の学習の分布の外

### 2.1 ゲームの仕組み（2026-09-25 のエミュレータ調査）

- ボスは距離で出る。左へ歩くだけで約 3,000 フレーム（750 step）でボスの位置に着く。雑魚は動いているときに出てくる。
- ボス戦は約 340 フレーム（85 step）。11 発当てると倒せる。当てても点は入らず、点は撃破のときの 2,000 点だけ。
- ボスの体力は RAM の 0xCC（満タン 39）で、画面上部の ENEMY バーの長さと一致する。1 発で 4 減るので、1 発でバーの全長の約 1 割が縮む。自機の体力は 0xCB（満タン 39）で PLAYER バーと一致する（出典: [082 §2](082_atari_ram_progress_metrics_10prd.md)）。
- 撃破後も雑魚は出続け、攻撃しながら約 1,000 フレーム（250 step）歩くと出口で残りの体力（最大 39）とタイマー（最大 31）が得点に換算される。報酬クリップでは換算の間の毎 step が +1（最大約 70 回）、生の得点では最大約 26,000 点。
- やられると面の最初に戻り、ボスの体力も元に戻る。
- 観測は 84×84 の灰色、4 フレーム飛ばし、4 枚重ね（直近 16 フレーム）。報酬クリップ、sticky action 0.25、γ = 0.997、n-step 3（実時間優先の構成）。

### 2.3 分析の結論（2026-10-16〜20）

- **観測は足りる。** seed 3 は安定して倒していたので、ボス戦に勝つための情報は今の観測に入っている。
- **報酬では途中経過が見えない。** 当て 1 発は 0 点、撃破はクリップ後 +1 で雑魚と同じ。成功を区別できるのは出口の換算（収益の側）だけ。
- **価値の視野。** γ = 0.997 の視野は約 333 step。ボスに触れてから換算の始まりまで約 335 step で、重みは約 0.37。残機の差はゲームオーバー（数千 step 先）にしか出ず、見えない。
- **2 つの戦略がほぼ同価値。** クリップ後の 1 step あたりの報酬は、ボス行きの seed 3 が 0.042、1 面の稼ぎが 0.048。どちらに落ちるかは序盤の経験で決まる。
- **挑むことは珍しくなく、壁は挑んでいる間の上達にある（2026-10-19〜20）。** 既定の 16 seed のうち 7 本がボスに挑んだが、撃破 ÷ 命中が上がった Run は無い。seed 3 は挑み始めの撃破 ÷ 命中が 0.24 で、その後 0.40 → 0.71 と上がった。s08 は始まりが 0.22 とほぼ同じでも上がらずに退いた。既定の設定でボス行きが定着するのは、seed 3 を含めて約 20 本に 1 本。
- **PER は珍しい経験を強めていない。** 1 遷移が寿命中に引かれる回数の期待値は約 1.0、4 件に 1 件は一度も引かれずに消える。`per_alpha` 0.2 では優先度が 20 倍でも引かれやすさは 1.8 倍。新しい遷移は最大の優先度で入るので、初回の抽選は TD と関係しない。ボスに当てた step は報酬 0 で TD 誤差も小さいので、TD の優先度では目立たない。
- **人間との差。** 人間がボスを倒せるのは、事前知識（目的・表示の意味・戦い方）、内的な動機（好奇心・達成感・稼ぎへの飽き・上達の見込み）、成功の記憶があるから。このうち「飽き＋好奇心」と「当てたらバーが縮んだことへの手応え」に当たるのが新しさのボーナスで、本 PRD の対象である。事前知識は [999_llm_actor_10prd.md](999_llm_actor_10prd.md)、成功の記憶は EMDQN 型の価値の下限・SIL（未起票、§6）の側。

### 2.4 ユーザーの裁定（2026-10-16）

ボスの手前から始めること（状態の保存と復元）と、ボス体力の減りへの報酬は「ゲーム仕様を別にするのはやり過ぎ」で採らない。sticky action を切るのは本来のゲームに戻すので可。エージェント側の汎用の工夫は歓迎。

### 2.5 新しさのボーナスが KFM に効くと見込む理由

新しさの測り方には、一生の履歴と比べるもの（回数、RND、ICM の予測誤差）と、今のゲームの中の履歴と比べるもの（NGU のエピソード内の新しさ）がある。KFM の壁（§2.3）に効くのは後者と見込む。

- **一生の新しさは、要る時期に消える。** ボス戦の画面は、挑む前はまれなのでボーナスが大きい。しかし挑み始めると（s08 は 5.5M の 0.5M 窓で約 220 ゲームの 71%）すぐ見慣れて、勝ち方を覚える前にボーナスが消える。ICM も、「蹴ったらバーが縮む」を前向きモデルが予測できるようになると意外さが無くなる。挑むきっかけは今も起きているので、一生の新しさが効く時期は既に足りている。
- **エピソード内の新しさは、ゲームごとに記憶を空にするので一生の訪問回数だけでは消えない。** バーの長さの差が埋め込みに残れば、報酬 0 の命中に手応えを与えられると見込む。個々の命中が必ず新規と判定される保証は無く、k 近傍と E3B でも判定が異なる。
- **ボスの体力が戻る仕組みとかみ合う。** やられると面の最初に戻りボスの体力も戻るので、同じゲームの 2 機目以降でボーナスが付くのは、それまでより深く削ったときだけになる。「このゲームでの自己ベストを更新する」向きの動機が撃破まで続く。
- **稼ぎにはボーナスが付きにくい。** 同じゲームの中で似た画面を繰り返すので、すぐ新しくなくなる。ボスへ向かう道と、撃破の先（出口の換算・2 面）は、毎ゲームそのゲームで初めて見る。
- **埋め込みは逆動力学で学ぶ。** 連続する観測から行動を当てる課題は、行動の予測に役立つ特徴を残す方向へ学習を促す。ただし、制御可能な変化をすべて保存する保証は無い。バーの縮みより自機の姿勢だけで行動を当てられる可能性もあり、命中の差が残るかを §9 で測る。
- **観測でのバーの見え方。** 1 発で全長の約 1 割が縮むので、84×84 に縮めた観測にも数画素の変化として残るはず（画素数は未計測）。埋め込みが画面全体の中の小さな変化を保つかを、特徴距離と命中時のボーナスで確かめる（§9.1）。
- **文献の留保。** Taiga ら（2020）の追試では、探索の易しいゲームでボーナス型の探索が ε-greedy を上回らなかったが、これは平均の成績の話で、特定の局所解から抜けるかは示していない。R2D2 は内的報酬なしで KFM 233k（Atari-5 の公開データ）なので、大規模な学習では必須ではない。

### 2.6 方策の多様性の段（2026-10-18 の整理）

多数の Actor や lane があっても、方策がどう違うかで効き方は大きく違う。

| 段 | 何が違うか | 例 |
| --- | --- | --- |
| ① 行動のゆらぎ | 同じネットワークを共有し、ε だけ Actor ごとに変える | Ape-X、R2D2、anet の spatial exploration のラダー |
| ② 目的を変えた方策の家族 | 1 つのネットワークに方策の番号を入力し、β と γ の違う方策のうち 1 つを使う | NGU、Agent57 |
| ③ 別々のパラメータ | ネットワークや価値関数そのものが別 | 独立の seed、PBT、Bootstrapped DQN の複数の Head |

[NGU 原論文の付録 A「Distributed training」](https://arxiv.org/pdf/2002.06038#page=14) は、各 Actor に固定の β を割り当てる。方策の家族を使うことと、いつ方策を選び直すかは別の選択である。本 PRD ではユーザー指定に従い、lane ごとのエピソード開始時に方策を選ぶ（§4.1）。

- KFM で seed 3 だけがボス行きに入ったのは ③ の違い（設定の差は `run.seed` だけ）で、ネットワークが別の谷に落ちた。seed 3 は 3-4M にボス命中 10%・撃破 ÷ 命中 0.03 だったのが、4-5M に命中 51% へ跳ね、6-7M に撃破 ÷ 命中 0.71、11-16M に 0.9 まで上がった。
- ① では「ボスを練習し続ける性格」は生まれなかった。2026-10-17 の UQE（低い ε）の Run で、4〜12M のボス命中を lane の 4 区分で見ると 7.1% / 7.6% / 10.8% / 10.2% とほぼ一様で、lane ごとの τ の違いがあっても全 lane が 1 つの戦略として挑み、1 つの戦略として撤退した。
- R2D2 は ① だけで KFM 233k（Atari-5 の公開データ）なので、② は必須ではない。ただ ② は、点数の方策が稼ぎに固まっていても、内的報酬の重みや割引率が異なる方策がまれな場面（ボス戦）を練習し続け、その経験を共有のパラメータ越しに点数の方策が使える形で、人間の「飽き・好奇心で練習し、得になったら使う」に近い。

### 2.7 GridMaze: 学習の分布の外から再開すると届かない（2026-10-24）

**観察（ユーザー、2026-10-24）。** GridMaze で、学習が進んで安定してゴールできるようになった後でも、EvalPanel の手操作で点数の方策がほとんど通らないセルへ誘導してから再開させると、ゴールに着かない。Run 名と、どのセルへ何 step 誘導したかの記録は無い。固定の開始位置からの評価で成功していても、通らない状態から届くことは示さない。

**今の構成（2026-10-24 にコードと設定で確認）。**

- 観測は位置の (x, y) を 0〜1 に正規化した 2 次元のベクトルだけ（[GridMazeEnv.cpp](../../core/envs/gridmaze1/src/GridMazeEnv.cpp) の `GetObservation`）。迷路は固定の seed で毎回同じなので（[GridMaze.txt](../../apps/runner/config/GridMaze.txt) の `GridMazeEnv.randomize_seed ?= false`）、壁の配置は観測に無く、ネットワークの重みに覚え込まれる。
- 開始位置は (0, 0) に固定（同 `GridMazeEnv.init_pos_x ?= 0`・`GridMazeEnv.init_pos_y ?= 0`）。学習のデータは (0, 0) から出た軌跡だけになる。
- 学習と評価の方策は UQE、Body は 2 層の MLP（同 `A1.actor.[train].policy.policy_type = UQE`・`A1.actor.[eval].policy.policy_type = UQE`・`DefaultDQNAgent.net.body.$ = net.body.@MLP2`）。
- 手操作の step は、EvalPanel が eval の runner へ行動を渡すだけで（[EvalPanel.cpp](../../apps/runner/src/EvalPanel.cpp) の `DoStep(int64_t action)`）、eval の runner は Learner を呼ばないので、その遷移は学習に入らない（[999_input_target_train_forced_action §1.1](999_input_target_train_forced_action_10prd.md)）。
- 壁や盤の外へ向かう行動では位置が変わらない（GridMazeEnv.cpp の `Step`）。手操作の step もエピソードの step 数に数えられ、`max_steps`（既定 100）で打ち切られる。

**見立て（Run では未確認）。**

- 点数の方策の Q が正しくなるのは、replay に入った状態のまわりだけである。ε や UQE の揺らぎは点数の方策の Q から作るので、Q が収束すると、集まるデータも最短路のまわりに縮む。
- ε には向きが無い。最短路から決まった向きへ 3 歩外れるには、決まった向きの乱択が 3 回続く必要があり、ε = 0.05（GridMaze.txt の `uqe_eps_end`。spatial exploration は [agent.txt](../../apps/runner/config/agent.txt) の既定で無効）・行動 4 つなら確率は (0.05 / 4)³ ≈ 2×10⁻⁶ になる。実際の Run の値は config dump で確かめる。
- UQE の分位点の幅は収益のばらつきで、「この状態を知らない」ことを表す量ではない。通っていない状態で幅が広がる保証は無い。
- 座標を入力にする MLP は、通っていないセルの値を座標の近いセルから補う。壁の向こうのセルの値も補うので、そのセルで最善とされる行動が壁を向くと位置が変わらず、決定的な方策は同じ行動を `max_steps` まで繰り返す。Evaluation Trace（[094](094_evalpanel_step_history_10prd.md)）で、再開後に壁への衝突の回数（`wall_collisions`）が増え続けるかで確かめられる。
- 留保: エピソード内の新しさは、そのエピソードで何を見たかで決まり、今の観測だけでは決まらない。NGU は再帰型の Agent（R2D2）で使っているが、anet の DQN 系は再帰を持たない。探索役が 1 エピソードの中で状態を覆えるかは、§9 の GridMaze の測定 で確かめる。

**Agent 側に要るもの。**

- 新しさを目的にする探索役が、点数の方策の収束と関係なく状態を覆い続けること（§2.6 の ② の、β の大きい方策）。
- 点数の方策が、探索役の遷移からも学ぶこと。DQN の目標値の max は行動した方策に依らないので、探索役の遷移も点数の方策の学習データにできる（n-step の途中は行動した方策に依る。§8 の 14）。
- 評価が新しさを追わないこと。
- env の知識（観測が座標であること、開始位置を選べること、盤面）を使わないこと。Agent が知るのは、観測がベクトル（観測キー `vector`）であることまでとする。

**このゴールに対して残る設計課題（2026-10-27 更新）。**

- 条件付き Q を保存済みインデックスだけで学ぶと、探索役の遷移で β=0 の Q を直接更新することにはならない。共有パラメータを通した転移と、β=0 を教師値で直接学ばせることを区別する。後者を満たす追加学習の形は §8 の 2 で決める。
- 評価は β=0 の方策で行う。内的報酬の係数が 0 であることと、NN の条件付け入力や共有重みから内的報酬の影響が完全に無くなることは別である（§4.5）。
- ベクトル観測と画像観測を同じ仕組みで扱い、Embedding や Q の特徴抽出は観測仕様と NN 設定で組む。画像専用の入力・CNN を Agent の固定仕様にしない。
- GridMaze の既存 UQE と組み合わせるには、方策インデックスとは別に、分位点の使い方と target policy の意味を揃える必要がある（§8 の 15）。

**この事例で選ばなかった対策。** 学習時の開始位置を到達できるセル全体からばらすこと（exploring starts）と、迷路の盤面を観測に入れて CNN で読むことは、env の側の対策なので採らない（§1 の非ゴール）。探索の設定（ε・UQE の τ）を上げることは、揺らぎが点数の方策の Q から作られる構造のままなので、Q が収束するとデータが縮むことは変わらない。

### 2.8 NGU・E3B・BTR の関係と、比較結果の適用範囲

- [NGU（2020）](https://arxiv.org/abs/2002.06038) は、逆動力学の埋め込みによるエピソード内ボーナス、RND の倍率、方策インデックスで条件付けた価値関数を組み合わせる。原論文は R2D2 を基に再帰型ネットワークと transformed Retrace を用いる。これらを既存の feedforward DQN へ移すと、NGU の探索機構を使った派生構成になる。原論文と同じ成績を保証するものではない。
- [E3B（NeurIPS 2022）](https://arxiv.org/abs/2210.05805) も逆動力学の埋め込みを使えるが、エピソード内の新しさの測り方が異なる。個々の訪問ベクトルとの局所的な近さを調べる NGU に対し、E3B は特徴の外積を集約した行列から、まだ十分に経験していない特徴方向を評価する。通常の平均を引いた共分散とは区別する。新しい観測でも、既知の特徴方向の組み合わせならボーナスが小さくなることがあり、探索の好みが変わる。
- E3B の固定サイズの記憶と rank-1 更新には実装上の利点があるが、埋め込み次元、正則化、数値精度、特徴の変化への対処は残る。記憶容量だけで方式を決める要求は無い。初期方式は保留し、両方式へ対応できる設計を必須とする（§4.1）。
- [Henaff ら（ICML 2023）](https://proceedings.mlr.press/v202/henaff23a.html) の NGU 型ボーナスとの比較は主に MiniHack であり、Atari 全体における NGU Agent と E3B の優劣の証拠にはしない。同論文の Montezuma's Revenge では E3B 単独と RND・併用の結果も異なる。E3B を NGU の無条件な上位互換とは扱わない。
- [RLeXplore](https://arxiv.org/abs/2405.19548) の Atari 比較は、共通の学習器へ内的報酬モジュールを加えた比較である。原論文 NGU の方策群・学習予算と同じ実験ではなく、公開スコアを横並びにして順位を決めない。
- [BTR（ICML 2025）](https://proceedings.mlr.press/v267/clark25a.html) は NGU より後の DQN 系の構成で、[IQN（2018）](https://proceedings.mlr.press/v80/dabney18a.html) 自体は NGU より前である。2026-10-27 までの本件の調査では、anet と同じ BTR 要素と NGU 全体を組み合わせた、直接比較に使える実績は確認できていない。存在しないと断定せず、個々の要素の成立と組み合わせの実測を分ける。

## 3. 現状（2026-10-27 に関連文書・コードを確認）

- 内的報酬は本 PRD で追加する機能である。[048](done/048_quantile_tail_metrics_10prd.md) の量子化分布の指標とは別の関心になる。既存 Q 学習の位置は [DQN 系 Agent 設計](../design/200_dqn_agents.jp.md) を参照する。
- reward scaler を通してから Replay へ渡す経路がある（[default_dqn_agent.cpp](../../core/anet-core/src/default_dqn_agent.cpp) の UpdateFromBatch）。Atari の報酬クリップは [AtariEnv.cpp](../../core/envs/atari1/src/AtariEnv.cpp) の Env 側で行う。内的報酬をどこで合成し、どの尺度を保存するかは §8 の 7・11 で決める。
- Replay は **1 step ごとの報酬・終わり方・判断の旗を保持する**。[ADR 0063](../adr/0063-replay-slot-keeps-per-step-reward-and-end-and-samples-variable-windows.md) により、窓の規則から可変長の収益と窓の終点の観測をサンプル時に組める。旧記述の「1 step の報酬は後から取り出せない」は撤回する。
- n-step の収益は、γ が定数なら Push 時の保存値を使い、schedule なら抽選後に保存済み step 報酬から現在の γ で作り直す（[ADR 0065](../adr/0065-scheduled-gamma-recomputes-return-at-sample.md)、[PRD101](101_exploration_schedule_profiled_value_10prd.md) D20）。これは共通の γ の経路であり、同じ学習バッチ内で方策ごとに異なる γ を使う契約は追加の検討が要る。
- [ExperienceSamples](../../core/anet-core/include/anet/rl.hpp) の Q 用 next_state.next_obs は n-step 先で、window.next_obs は窓の長さ先である。unroll の行動・収益を得られることは、任意の未来観測列をそのまま取得できることを意味しない。SamplingHistoryProbeRequest は抽選履歴の診断であり、時系列観測の取得 API ではない。
- [ReplayBufferConfig](../../core/anet-core/include/anet/replay_buffer.hpp) の window_rule は 1 つで、TempoRL が使っている。長さ 1 の窓を使う案だけでは、TempoRL と Embedding 学習を同時に満たす契約は決まらない。done の最終観測の保持と autoreset の境界も含め、§8 の 10 で調べる。MuZero の [専用 Replay](../../core/anet-core/src/muzero_rb.hpp) の系列取得を、共通 Replay に既に存在する機能とみなさない。
- Actor の frame stack と Replay の stack 再構成は、使う時点が異なる。[ADR 0044](../adr/0044-replay-frame-history-start-from-episode-start-at-push.md) の履歴開始と [Replay 設計](../design/150_replay_buffer.jp.md) の境界を守る。短期記録用 Replay への統合は未決で、内的報酬の追加と同時に統合することは決めていない。
- TempoRL は、現状では SKIP 継続中も full batch で primary と skip の forward を行い、継続 lane の提案行動を保持中の行動へ置き換える（[dqn_based_agent.cpp](../../core/anet-core/src/dqn_based_agent.cpp) の MakeAction）。skip の学習は判断区間内の窓の収益と、終点の primary Q による bootstrap を使う。[ADR 0062](../adr/0062-networkmodel-holds-auxiliary-network-fed-by-primary-outputs-with-target-used-only-for-acting.md) の skip target は target Actor 用であり、skip 自身の bootstrap 用ではない。
- Q の保存には online・target と、有効なら skip が含まれる。Actor の進行中状態と Replay 全体の保存は既存 checkpoint の範囲ではない（[DQN 系 Agent 設計](../design/200_dqn_agents.jp.md)）。本機能の学習済み状態とエピソード途中状態の保存を分けて決める。
- KFM の RAM メトリクスは 1 = 面クリア、2 = 撃破、3 = 命中の回数（[Atari.txt](../../apps/runner/config/Atari.txt)）。ボス体力の最小を指標化する案と、群番号 56 を内的報酬へ使う旧案は残すが、現用設定・番号との衝突確認を §8 の 20 に置く。

## 4. 提案の骨子と、今回整理した要件

「確定」は本件でユーザーが指定した方針、「基準案」は以後の PRD 精査の出発点を表す。未決表の候補や数値を、確定済みの実装契約として扱わない。旧版の段階 1〜3 は、評価のゴールと整合しなかったため、そのまま実装順には使わない（§10）。

### 4.1 確定した方向

| 事項 | 方針と理由 |
| --- | --- |
| NGU／E3B | 両方へ対応できる構成を必須とする。初期採用方式は保留する。環境ごとの効果を比べるため、局所的な訪問密度と特徴方向の被覆という違いを残す |
| 方策の保持 | ユーザー指定に従い、lane ごとのエピソード開始時に方策インデックスを選び、そのエピソード内で保持する。1 エピソードを同じ報酬目的・割引率で収集するためである。原論文の Actor 固定割り当てとの違いは §2.6 に記す。割り当て分布は未決 |
| 既存学習器 | BTR を基にした DQN を土台とする。探索機構の効果を調べる目的であり、NGU 原論文の完全再現をゴールにしない |
| 時系列モデル | 初期検討は既存の複数フレーム入力を基にする。既存 BTR 学習器を基準に、探索機構の効果と長期履歴を扱うモデルの効果を分けて評価するためである（§2.8・§6）。RNN／Transformer は独立した検討軸とし、frame stack が長い履歴と同じ能力を持つとはみなさない |
| 評価と転移 | 評価では β=0 の点数の方策を使い、その方策を探索役の遷移からも学ばせたいという既存ゴールを維持する。共有重みだけでこのゴールを満たしたことにはしない |
| 対象 | 本件の土台である既存 BTR 学習器の実装先なので、ベクトル・画像観測を扱う DefaultDQNAgent 系を対象に精査する（§3）。TempoRL は同じ DQN の行動保持と学習窓に関わるため（§3）、保持区間内の内的報酬・方策条件が整合するよう、併用時の条件を §4.8 で精査する |

### 4.2 エピソード内の新しさを差し替える境界

説明上の用語として、「新しさ」と「新規性」は同じ novelty を指す。「埋め込み（Embedding）」は観測の特徴表現を指し、以下で Embedding と略すときは、その表現を出すネットワークを意味する。設定キーや公開名の確定は §8 の 20 で扱う。

基準案では、次の責務を分ける。

1. 観測から、行動の予測に役立つ埋め込みを作って学ぶ。
2. lane のエピソード内の履歴に照らして、埋め込みの新しさを算出・記録する。
3. エピソード内ボーナスと、一生の新しさを組み合わせる。
4. 方策ごとの β・γ に従って Q 学習の報酬・教師値を作る。

NGU／E3B の切替は主に 2 に置く。外側から必要なのは、新しさの算出、記録の更新、対象 lane のリセット、診断値である。内部記憶を「訪問ベクトルの列」に固定しない。NGU は訪問ベクトルと近傍の統計、E3B は特徴の外積を集約した状態を、それぞれ必要な形で管理する。共通化するのは役割であり、ボーナスの尺度・閾値・特徴次元・保存内容が同じだとは要求しない。

初期化、現在観測を算出に使ってから記録する順序、エピソード終了時のリセットを揃える。方策・Q・RND・Replay を方式ごとに複製しない。Embedding を共用できる構成にするが、方式別に学習設定を比較できる余地を残す。新規性の計算式は §7.1、数値と契約の確定は §8 の 1・5〜9 による。

### 4.3 ネットワークの役割と更新

| 系統 | 学ぶ内容 | 固定・同期する相手 |
| --- | --- | --- |
| 行動価値 Q | 方策インデックスに対応する報酬と割引率で行動価値を学ぶ | Q target は既存の同期方式を基にする |
| Embedding と逆動力学の行動予測器 | 隣接する 2 観測から、その遷移で選ばれた行動を予測する | 新規性の算出にはエピソード中の座標系を揃えた推論用 Embedding を使う基準案 |
| RND predictor | 同じ観測に対する固定 target の出力を近似する | RND target はランダム初期化後に固定し、predictor から同期しない |

逆動力学は、同じ Embedding を 2 観測それぞれへ適用し、2 つの特徴から行動分布を出す。共有パラメータには両方の経路の勾配が合算される。1 つの損失に対する backward でよく、時点ごとに別ネットワークを学ぶ意味ではない。特徴から行動を予測する部分は補助学習で使い、新規性の算出は Embedding だけで行う。

RND は同じ入力・同じ出力形状を使うが、重みを共有しない。内部構造まで同一である必要は無い。1 観測の二乗誤差と、学習バッチで集約した RND loss を区別する。初期化方式・出力尺度・入力の正規化は §8 の 9 で決める。ランダム target の有用性は seed だけで保証されず、学習前後の誤差と探索の結果を測る。

基準案では 3 系統の学習パラメータを分ける。Q loss から内的報酬の算出器へ逆伝播する構成にはしない。特徴の共有を採る場合は、更新の独立性が変わるため、勾配をどこまで通すかを改めて決める。

### 4.4 推論用 Embedding と lane のエピソード

[NGU 付録 F の Table 6](https://arxiv.org/html/2002.06038v1) は Embedding の target update をエピソードごととしている。これは Q target や RND 固定 target とは別の役割で、記憶済みの特徴と現在の特徴を同じ座標系で比べるための論点になる。「target の概念は Q と RND のみ」とは整理しない。

基準案は、エピソード開始時に推論用 Embedding の重みを確定し、その lane のエピソード内では変えない形である。lane ごとに終了時刻が違うため、全 lane で 1 つの推論用重みを終了のたびに上書きすると、進行中の lane の記憶と不整合になる。

複数世代の推論用重みを保持し、同じ世代の lane が共有する案を精査する。**lane ごとに独立したネットワークを学習する要件ではない。** 保持する世代数、長いエピソード、コピー・forward の回数、参照されなくなった世代の解放が未決（§8 の 6）。共有重みを低頻度で更新してずれを許容する近似や、過去観測を再度埋め込む案は、同じ意味の実装として黙って置き換えない。

E3B でも、蓄積した特徴方向と現在の特徴の座標系がずれる問題は残る。方式を E3B に変えただけで、この論点が無くなるとはみなさない。

### 4.5 方策インデックスと β=0 の意味

方策インデックス i は、あらかじめ定める内的報酬の重み β_i と割引率 γ_i の組を識別する。i=0 を β=0 の方策とする基準案で、N、β・γ の値と並びは未決である。lane 数 B と方策数 N は独立で、複数の lane が同じ i を使ってよい。エピソード開始時の割り当ては均等、重み付き、乱択などを比較し、成績に応じた Agent57 型の選択は別の拡張とする。

基準案の Q への条件付けは、観測の特徴、i の one-hot、直前の行動、直前の外的報酬・内的報酬である。特徴軸へ連結し、lane は混ぜない。形状例は §7.2 に置く。one-hot は「この 1 回の推論がどの方策の価値を求めるか」を指定し、複数方策の Q を混ぜる重みではない。IQN の τ は別の入力である。

学習の基準は、Replay のサンプルに保存された i を使い、現在状態の Q、次状態の行動選択と価値、報酬の β_i、割引の γ_i を揃えること。収集 Actor の現在の i から推測し直さない。終端の遷移は終了したエピソードの i に属し、次のエピソードの i と混ぜない。

β=0 は **学習目標の報酬から内的報酬の加算を除く** 意味である。探索役の経験、共有パラメータ、NN に入力する直前の内的報酬を通した影響まで 0 になる保証は無い。NN 入力の内的報酬は、出力 Q に足すボーナスではなく、履歴を知らせる条件である。評価時だけその入力を一律 0 にすると、学習時と異なる条件になる可能性があるため、評価入力の仕様を §8 の 16 で決める。

旧 §8 の「方策入力を無くし外的・内的の 2 Head にする」案は採用済みにしない。共有重みを通した転移、別 i で同じ経験を直接学ぶ方法、[Agent57](https://arxiv.org/abs/2003.13350) 型の価値分解は別の選択肢である。価値を分けるだけで全方策の γ や bootstrap policy の整合が解決するわけではない。β=0 を全 lane の遷移で直接学ばせる形を §8 の 2 で優先して決める。

### 4.6 収集・保存・補助学習の時点

基準案では、Env に渡した行動、その結果の次観測、外的報酬を 1 つの遷移として扱い、次観測から内的報酬を算出する。新規性はその観測をエピソード記憶へ加える前に算出し、その後に記録を更新する。エピソード終了時には、終了する lane の状態だけをリセットする。autoreset 後の初期観測を、終了前の行動の次観測として学習しない。

内的報酬は収集時の事実として保存し、学習時に「現在の Actor の記憶」で過去の内的報酬を再計算しない基準案とする。外的・内的を別に残すか、合成した収益をどこまで保持するかは §8 の 11 に残す。別 i の学習や β・γ の時間変化の採否がこの選択に影響する。

Q 用の n-step 遷移と、Embedding 用の隣接した 1-step 遷移を区別する。後者に必要なのは現在観測・次観測・その間の行動であり、Q 用の n-step 先観測で代用しない。学習時の直前行動・報酬も、ライブの Actor 状態ではなくサンプルに対応する履歴から再現する。episode 開始時の初期値と、末尾の不完全サンプルのマスクも仕様化する。

[NGU 原論文の付録 A「Learner」](https://arxiv.org/pdf/2002.06038#page=14) は、サンプル系列の末尾 5 時点を行動予測器と RND predictor の学習に使うとしている。これは各系列から 5 時点分の補助学習データを選ぶ意味である。通常はそれらをまとめて 1 回の補助更新に使え、optimizer を 5 回実行する要件ではない。RNN を採用しない構成に、原論文と同じ系列長や burn-in を形式的に要求しない。

### 4.7 Retrace、n-step、分布型 Q

Retrace は、収集時の行動方策と学習対象の方策が異なる系列を使う際に、将来側の TD 誤差をどこまで伝えるかを補正する。係数 c_s は γ の代わりではなく、γ とともに将来側の TD 誤差への重みを作る。サンプル全体の loss を、方策のずれに応じて一律に小さくする機構とも異なる（式は §7.3）。

- 通常の n-step 収益は、目的の β・γ が確定し固定なら Push 時に計算できる。ただし、i を保存するだけで既存の共通 γ の計算が方策別になるわけではない。
- Retrace の学習時方策や TD 誤差は最新のネットワークに依存するため、Push 時に補正済み教師値を固定できない。採用する場合は収集時の実行行動の確率 μ と系列情報を保存する。
- NoisyNet、UQE、TempoRL の継続行動を含む μ の定義を、単純な ε-greedy の確率式で代用しない。学習対象方策 π も、既存 target policy と区別して定義する。
- NGU 原論文の scalar Q に対する transformed Retrace を、QR／IQN の loss へそのまま挿入することは確定していない。Munchausen、分布の教師値、PER の優先度と重要度補正を含め、§8 の 14・15 で決める。

Retrace なしでもエピソード内ボーナス・RND・条件付き Q の組み合わせは構成できる。原論文と同じ学習法とは呼ばず、通常の off-policy n-step の偏りも無くなったとはみなさない。

### 4.8 TempoRL との併用

基準案では、SKIP の新しい判断を行わない step でも、Env が返した観測ごとに新規性の算出と記録の更新を行う。途中状態を抜かすと、行動を続ける長さによって「何を訪れたか」が変わってしまうためである。Env の 1 step と ALE の生フレームは区別する。

- 逆動力学の教師行動と直前行動には、保持中の行動を含む **Env へ渡した行動** を使う。forward が提案したが SKIP により採用されなかった行動を使わない。ALE の sticky action による内部の行動変更は別の確率性であり、取得できない内部行動を教師とする前提を置かない。
- skip の価値も、選択中の i に対応する目的で学ぶ。i を含む primary の特徴経由で渡すか、skip 側へ明示して渡すかは未決。
- 長さ k の窓の収益と終点の primary Q の bootstrap は同じ β_i・γ_i を使い、割引の回数は実際の区間長に合わせる。判断境界を越えて、たまたま同じ行動が続いた部分を連結しない。
- [ADR 0062](../adr/0062-networkmodel-holds-auxiliary-network-fed-by-primary-outputs-with-target-used-only-for-acting.md) の primary／skip の役割と、[ADR 0063](../adr/0063-replay-slot-keeps-per-step-reward-and-end-and-samples-variable-windows.md) の 1 つの Replay に step 記録を持つ形を出発点とする。これを変更する案を採るときは、どの判断を変更するかを PRD 精査で示す。

### 4.9 並列学習、保存・再開

独立したパラメータなら Q・Embedding・RND の学習を並行実行する余地はある。ただし CPU のスレッドと CUDA stream は別で、GPU の使用率・帯域・一時メモリ次第では並行化の利点が無い。既存の実行経路を基準にし、追加 stream は計測して判断する。GPU 律速だとも CPU 律速だとも未測定で断定しない。

並列化のために補助学習を無制限に回すと、経験 1 件あたりの更新回数が変わり、RND の誤差が減る速さや Embedding の変化そのものが変わる。学習比率を揃えた比較とし、重みのコピー完了、利用中の特徴と重みの寿命、CPU 同期の増加を検証する。

| 保存対象 | 含めるものと理由 |
| --- | --- |
| 学習を継続する知識 | Q online／target、Embedding と行動予測器、RND predictor **と固定 target**、optimizer、学習回数・schedule、正規化の継続に必要な統計。RND target を乱数で作り直すと、学習済み predictor の教師が変わる |
| エピソードの進行状態 | i、エピソード内の記憶または E3B の状態、推論用 Embedding の世代、直前行動・報酬、frame stack、SKIP 残り。途中再開には Env 自身と RNG の整合も必要 |

既存 checkpoint が Actor／Replay を保存しないことから、学習済み状態を復元して **新しいエピソードから再開する案** を出発点にする。途中から完全再現する要求は未決で、古いエピソード記憶だけを新しい Env に引き継がない。保存形式と対応する方式の一致は読み込み時に検証する（§8 の 18）。

## 7. 精査時に使う計算・既存接続の参考

この節は機構の意味と調査先を共有するための参考であり、内部の型・配置・呼び出し方を固定しない。公開設定名・クラス候補・責任分担は §8 で精査する。

### 7.1 ボーナスの計算

NGU は [原論文 §2・付録 A.1](https://arxiv.org/html/2002.06038v1) に従い、k 近傍までの二乗距離を距離統計で正規化し、近すぎる距離の閾値処理後に類似度 K を求める。概形は次のとおり。

\[
\tilde d_j^2=\max(d_j^2/\overline{d^2}-\xi,0),\quad
K_j=\frac{\epsilon}{\tilde d_j^2+\epsilon},\quad
s=\sqrt{\sum_j K_j}+c,\quad
r^{episodic}=\begin{cases}1/s & s\le s_{\max}\\0 & s>s_{\max}\end{cases}
\]

c は平方根の外に加える。全件の距離を計算する実装でも、集約に使うのは局所的な k 近傍である。距離と類似度は別の量で、遠い記憶の数に報酬が引っぱられる度合いが変わる。記憶が空、件数が k 未満、距離統計が未確立の場合の挙動は §8 の 8 で決める。

E3B は [原論文 §4・Algorithm 1](https://arxiv.org/html/2210.05805) の、正則化した特徴の外積の和を使う。現在観測の特徴 z を記録する前の状態を C とすると、

\[
C=\lambda_{\rm E3B}I+\sum_{\text{過去の観測}}zz^\top,\qquad
b=z_{\rm current}^{\top}C^{-1}z_{\rm current}
\]

となる。逆行列を毎回取り直す代わりに rank-1 更新が使える。特徴が状態の one-hot なら、その状態の既訪問回数 n に対して \(b=1/(\lambda_{\rm E3B}+n)\) になる。NGU のボーナスと尺度は一致しない。λ の正則化、特徴次元、数値精度と合成後の尺度を別に確認する。

NGU の RND 合成は、

\[
e_t=\|g_{\rm predictor}(x_t)-g_{\rm target}(x_t)\|_2^2,\qquad
\alpha_t=1+\frac{e_t-\mu_e}{\sigma_e},\qquad
r_t^{int}=r_t^{episodic}\operatorname{clip}(\alpha_t,1,L)
\]

である。誤差の次元方向の和・平均、分散のゼロ回避、統計を更新する順序は実装時に統一する。**下限が 1 なので、見慣れた状態の倍率は 1 に戻るが、エピソード内だけの報酬より小さくはならない。** L が制限するのは倍率であり、内的報酬全体や β_i 倍した値の上限ではない。旧版の「RND によりエピソード内ボーナス自体を弱める」は、この意味へ訂正する。E3B と生の RND 誤差を掛ける方式は、この式と同一ではない。

### 7.2 Tensor 形状の例

B は同時に処理する lane 数、F は Q 用の観測特徴の数、N は方策数、A は行動数とする。Embedding の特徴次元とは別に考える。

| Q の条件付け入力 | 例の形状 |
| --- | --- |
| 観測の特徴 | [B, F] |
| 方策 i の one-hot | [B, N] |
| 直前行動の one-hot | [B, A] |
| 直前の外的報酬 | [B, 1] |
| 直前の内的報酬 | [B, 1] |
| 特徴軸で連結した結果 | [B, F+N+A+2] |

たとえば B=3、N=4 で i=[0,3,1] としてよい。1 つの forward の各行が、その行の i で条件付けされる。学習時は B を学習バッチの大きさと読み替え、各サンプルが保存していた i と履歴を使う。既存 IQN の τ・分位点軸と Dueling の出力構成を、この方策軸と混同しない。

spatial exploration は lane ごとに探索パラメータを変える既存の軸で、NGU は価値の目的を条件付ける軸になる。ε は行動選択に効くが、UQE の τ は IQN 入力にも効くため、「spatial はすべて NN 出力後の処理」とは整理しない。

### 7.3 n-step と Retrace の違い

固定 i の通常の n-step 教師値では、到達観測への報酬を \(r_{t+1}\) と書くと、概形は次のようになる。

\[
y_t=\sum_{h=0}^{n-1}\gamma_i^h
(r^{ext}_{t+h+1}+\beta_i r^{int}_{t+h+1})
+\gamma_i^n V_{\rm target}(u_{t+n},i)
\]

終端では継続価値をマスクし、truncation は既存の意味に合わせて区別する。ここで u は観測と条件付け入力をまとめた記号であり、新しい公開名ではない。TempoRL では、同じ考え方で n を判断区間内の窓長 k とし、終点を primary Q で評価する。

scalar Q に対する Retrace の概形は、

\[
c_s=\lambda_{\rm trace}\min\left(1,\frac{\pi(a_s\mid u_s,i)}
{\mu(a_s\mid u_s,i)}\right),\qquad
Q^{ret}_t=Q(u_t,a_t,i)+
\sum_{s=t}^{T-1}\left(\prod_{j=t+1}^{s}\gamma_i c_j\right)\delta_s
\]

となる。空積は 1、δ は対象方策の継続価値から作る 1-step TD 誤差である。E3B の正則化 λ と trace の λ は別の量。原論文の transformed Retrace の厳密な式は [NGU 付録 E](https://arxiv.org/html/2002.06038v1) を参照し、分布型 Q と Munchausen へ適用する仕様は未決とする。

### 7.5 ホットパスの見積もりと計測

1 回の batch Env step を単位にすると、追加する推論は Embedding を B 観測分、RND を使う場合は target と predictor を各 B 観測分、新規性の問い合わせ・記録更新を B lane 分である。Embedding の重みが複数世代なら、同時に使う世代ごとの forward に分かれうる。

NGU は保持件数 M・特徴次元 d に対して概ね BMd の距離計算と近傍選択、E3B は概ね Bd² の演算を毎 step 行う。どちらも単価の実測は無い。加えて、経験件数に対して設定する頻度で Embedding・RND の補助更新と、エピソード境界での重みコピーが増える。

旧案の「速度低下 15% 以内」は暫定候補で、合意済みの受入値ではない。モデル別の forward／backward、重みコピー、記憶操作、CPU 待ちを分けて試作で測り、既存との割合と実時間を出して §8 の 19 で予算を決める。性能予算の半分を超える見積もりとなる構成は、採用前に試作で測る。未測定のまま「E3B の方が速い」「stream 分割で改善する」と確定しない。

## 9. 成功の測り方と受入の候補

### 9.1 効果の測定

既存の KFM の問題設定・比較データ（§2.2・§2.3）は維持する。内的報酬の増大や RND loss の低下だけを成功とせず、外的報酬・到達率・タスクの進展を併せて見る。

- **KFM**: 既定の 10M × 16 seed を比較基準に、挑んでいる窓（命中 10% 以上の 0.5M 窓）の撃破 ÷ 命中、挑む窓が出る本数、挑むことの継続、ボス体力の最小、評価の生スコア・面クリアを測る。旧候補の「撃破 ÷ 命中が 0.3 を超える Run が複数」を正式な合否にするには、何 seed 中何本かを §8 の 21 で確定する。
- **GridMaze**: 今の設定を基準に、到達可能な空きセルから開始した評価のゴール到達率、収束後も探索役が訪れ続けるセル数、手操作で到達できなかったセルからの再開結果を測る。評価用開始位置を変える場合は空きセルに限り、壁を空きへ変えて別の迷路にしない。基準値と対象セルを先に記録する。
- **害の確認**: 探索の易しいゲームで外的報酬と学習速度を比較し、元の成績を悪化させていないか測る。対象 Env、seed 数、許容差は未解決。
- **機構の確認**: 命中前後と通常遷移の特徴距離・ボーナス、方策ごとの経験数と成績、エピソード内ボーナス・RND 誤差・倍率・β 倍後の値の分布、記憶量または E3B の数値状態、Embedding の世代数と古さ、補助 loss と行動予測精度を測る。学習した特徴の被覆だけを、独立した真の状態被覆と呼ばない。

比較腕は、既存 DQN、エピソード内ボーナスと方策群、RND 併用、RND 単独、k 近傍／E3B を候補とする。RNN・Retrace・価値分解・方策選択は、追加する場合に別軸で切り分ける。すべての直積を機械的に実行することは要求しない。NGU と E3B は生の尺度が違うので、β を同じ数値にしただけの比較で優劣を結論しない。

Env step と ALE frames を区別し、経験予算・学習比率・seed を揃えた比較に加え、実時間とメモリ量を記録する。打切りと採用する集約値を事前に決める。成績が上がらない場合も、被覆不足、表現が必要な差を落とす、探索から活用への学習不足、尺度の干渉を指標で分け、仮説を支持しない結果として記録する。

### 9.2 正しさの受入候補

以下は契約を確定した後の、外から確かめる検証候補である。方式固有の数値と近似誤差の許容値、seed を含む学習テストの条件は §8 の 21・22 で確定する。

| 観点 | 観測する結果 |
| --- | --- |
| 無効時 | 同 seed・決定的モードの同じ短い Run で、既存と行動列・学習報酬・指定 metrics checksum が一致する。対象設定・区間は確定後に固定する |
| 方策 | B と N が異なる複数 lane で i がエピソード内不変、終了 lane だけ次の選択へ移り、終端サンプルは旧 i を保持する |
| 報酬と割引 | 同じ保存済み遷移を異なる既知の β・γ で計算し、手計算した収益・実際の区間長の割引と一致する。β=0 では教師報酬への内的加算が 0 になる |
| NGU／E3B | 特徴を固定した人工系列で方式ごとの参照計算と一致し、記録前に採点される。対象 lane のリセットが他 lane の値を変えない。未知状態なら必ず高い、という保証は要求しない |
| RND | 学習後も target の出力・重みが変わらず、有限な誤差から倍率が [1,L] に収まる。同一入力への predictor 学習と、保存・復元前後の一致を確認する |
| Embedding | 隣接観測ペアを使い、両入力経路と予測器へ勾配が届く。採用した世代管理で、進行中 lane の特徴と記憶の座標系が整合する |
| Replay・終端 | n-step>1 と TempoRL の窓を使っても、Embedding 用ペアの次観測が 1-step 先である。done／truncation／autoreset／上書き境界を跨ぐ不正ペアが学習されない |
| TempoRL | SKIP 継続中の観測も記録され、教師行動が Env へ渡した保持行動と一致する。窓の収益・bootstrap が同じ i を使い、実際の k で割り引かれる |
| 評価・再開 | 評価が定めた β=0 条件を使い、学習側の統計を変更しない。新規エピソード再開で旧記憶・旧 i・旧 SKIP 状態が漏れず、RND target と継続統計が復元される |
| 診断・失敗 | 設定で明示した方式が使われ、不正値・未対応指定で対象と値を含むエラーになる。診断値を所定の metrics・trace から読める |
| 性能 | §7.5 の処理別時間・実時間・メモリ量を記録し、合意した予算に照らす。thread／stream 比較では学習比率を揃える |

## 10. 精査する順序と、今回の改訂の範囲

次の精査は、(1) β=0 を全 lane の経験で学ぶ形、(2) NGU／E3B の初期方式と共通の境界、(3) 報酬・i・履歴・1-step 観測の保存、(4) Embedding の世代・統計・評価・再開、(5) TempoRL と BTR 要素、(6) 数値・実験・公開名、の依存順に進める。会話で明示された「初期方式は後で決める」を、NGU 先行または E3B 先行の決定に読み替えない。

実装順は未決である。エピソード内ボーナスだけを比較する腕は必要だが、β=0 の評価と探索からの直接学習を後回しにしたまま、GridMaze のゴールを満たしたとはしない。RND はエピソード内だけとの比較を成立させる独立の腕であり、RND 単独はそれだけでも検証できる。

今回の成果物はこの暫定 PRD の更新である。KFM・GridMaze の背景は保持し、旧案の不整合、数式の誤り、古い Replay の前提を訂正した。新しい実験、コード・設定の変更、正式採番、実装計画の作成は行わない。既存資料は出典として保持し、未決は §8 を正本とする。

文書の検証（2026-10-27）: 本文の相対リンク先、LF、状態行の不在、対象 PRD の git diff --check を確認した。NGU の式と Embedding 更新周期は原論文の Algorithm 1・Table 6 と照合し、Replay の前提は現行の API と ADR 0063・0065 に照合した。コードを変更していないため、ビルド・学習 Run・性能測定は実施していない。§8 の未決は、ユーザーが求めた暫定 PRD に残す扱いとし、本改訂で採否を補わない。
