## 1. 目的と問題

エージェントの側に、ゲームに依らない汎用の内的報酬（観測の新しさへのボーナス）を足す。狙いは 3 つ。

1. 報酬に出ない途中の進み具合に手応えを与える。KFM ではボスに当てても 0 点で、撃破はクリップ後 +1 と雑魚と同じなので、挑んでいる間の上達が報酬に出ない（§2.3）。当てるたびにバーが縮み、そのゲームでまだ見ていない画面になるので、エピソード内の新しさは命中ごとのボーナスになる。
2. 何度も見た状態（KFM の 1 面での稼ぎ）より、そのゲームでまだ見ていない状態（ボスへ向かう道、ボス戦、出口の換算、2 面）の価値を高くし、練習の場をそちらへ寄せる。
3. 学習の分布の外でも壊れないようにする。ε や UQE の揺らぎは点数の方策の Q から作るので、Q が収束すると、集まるデータも点数の方策の通る状態のまわりに縮み、外れた状態では Q が正しくならない（GridMaze、§2.7）。新しさを目的にする探索役が状態を覆い続け、点数の方策がその遷移からも学べば、点数の方策がほとんど通らない状態からでも届く。

### ゴール

- 新しさのボーナスを、DQN 系 Agent の報酬に加えられる。既定は無効で、無効のときは今と同じ学習系列になる。
- 段階 1 で、逆動力学の埋め込みとエピソード内の新しさ（NGU の本体）を足す。一生の新しさの倍率は 1 で固定する。
- 段階 2 で、RND による一生の新しさを足す。NGU の倍率として使うほか、RND 単独のボーナスも比較の腕として選べる。
- 段階 3 で、ボーナスの重み β と割引率 γ が違う方策の家族を 1 つのネットワークで学び、lane ごとに違う方策で動かす（NGU・Agent57 型）。
- ボーナスの大きさ・学習の様子・報酬全体に占める割合と、埋め込みが命中を区別しているかを指標で見られる。
- 評価（configured eval と EvalPanel）は、新しさを使わない点数の方策で行動する。点数の方策の価値は、探索役の lane を含む全 lane の遷移から学ぶ。点数の方策が収束しても、探索役が状態を覆い続ける（§2.7。形は §8 の 24）。
- 埋め込み・新しさ・方策の家族は、観測の種類（ベクトル・画像）や env の知識に依らず、観測の仕様と設定だけで組める（§8 の 25）。

### 非ゴール

- ゲーム固有の知識で報酬を作ること（RAM の値への報酬、ボス体力の減りへのシェーピング）。ユーザーの裁定で採らない（§2.4）。RAM メトリクスは効き目を測るためだけに使う。
- 環境の仕様を変えること。KFM の途中の状態からの開始（§2.4 の裁定）と、GridMaze の学習時の開始位置を到達できるセル全体からばらすこと・迷路の盤面を観測に入れること（2026-10-24 のユーザーの方針: Env 固有の前提を入れず、Agent 側のアルゴリズムで対策する）を含む。どれも技術上の制約ではなくユーザーの裁定なので、裁定が変われば移せる。GridMaze の位置や盤面は、効き目を測るためだけに使う（§8 の 26）。
- 実行時に、そのエピソードの経験で価値を補正する仕組み（EVA 型）と、eval の遷移（EvalPanel の手操作を含む）を学習に流すこと。学習の分布の外へ連れて行かれたときの備えだが、学習のデータの分布を広げる本 PRD とは別の関心なので別 PRD にする（§6）。
- 認識論的な不確かさ（アンサンブル）による楽観。別の機構なので、必要になったら別 PRD にする（§6）。
- LLM の好みを内的報酬にする方式（Motif 型）。[999_llm_actor_10prd.md](999_llm_actor_10prd.md) と [LLM の事前知識で RL の探索と報酬を補助する手法のサーベイ](../../reports/llm_prior_knowledge_rl_survey_2026-10-18.md)（2026-10-18）の側で扱う。
- 成功したエピソードのリターンを記憶して Q の下限にする仕組み（EMDQN 型）。別の関心なので別 PRD にする（§6）。

## 2. 背景: KFM のボス討伐と GridMaze の学習の分布の外

### 2.1 ゲームの仕組み（2026-09-25 のエミュレータ調査）

- ボスは距離で出る。左へ歩くだけで約 3,000 フレーム（750 step）でボスの位置に着く。雑魚は動いているときに出てくる。
- ボス戦は約 340 フレーム（85 step）。11 発当てると倒せる。当てても点は入らず、点は撃破のときの 2,000 点だけ。
- ボスの体力は RAM の 0xCC（満タン 39）で、画面上部の ENEMY バーの長さと一致する。1 発で 4 減るので、1 発でバーの全長の約 1 割が縮む。自機の体力は 0xCB（満タン 39）で PLAYER バーと一致する（出典: [082 §2](082_atari_ram_progress_metrics_10prd.md)）。
- 撃破後も雑魚は出続け、攻撃しながら約 1,000 フレーム（250 step）歩くと出口で残りの体力（最大 39）とタイマー（最大 31）が得点に換算される。報酬クリップでは換算の間の毎 step が +1（最大約 70 回）、生の得点では最大約 26,000 点。
- やられると面の最初に戻り、ボスの体力も元に戻る。
- 観測は 84×84 の灰色、4 フレーム飛ばし、4 枚重ね（直近 16 フレーム）。報酬クリップ、sticky action 0.25、γ = 0.997、n-step 3（実時間優先の構成）。

### 2.3 分析の結論（2026-10-16〜20）

- **観測は足りる。** seed 3 は安定して倒していたので、ボス戦に勝つための情報は今の観測に入っている。
- **報酬では途中経過が見えない。** 当て 1 発は 0 点、撃破はクリップ後 +1 で雑魚と同じ。成功を区別できるのは出口の換算（収益の側）だけ。
- **価値の視野。** γ = 0.997 の視野は約 333 step。ボスに触れてから換算の始まりまで約 335 step で、重みは約 0.37。残機の差はゲームオーバー（数千 step 先）にしか出ず、見えない。
- **2 つの戦略がほぼ同価値。** クリップ後の 1 step あたりの報酬は、ボス行きの seed 3 が 0.042、1 面の稼ぎが 0.048。どちらに落ちるかは序盤の経験で決まる。
- **挑むことは珍しくなく、壁は挑んでいる間の上達にある（2026-10-19〜20）。** 既定の 16 seed のうち 7 本がボスに挑んだが、撃破 ÷ 命中が上がった Run は無い。seed 3 は挑み始めの撃破 ÷ 命中が 0.24 で、その後 0.40 → 0.71 と上がった。s08 は始まりが 0.22 とほぼ同じでも上がらずに退いた。既定の設定でボス行きが定着するのは、seed 3 を含めて約 20 本に 1 本。
- **PER は珍しい経験を強めていない。** 1 遷移が寿命中に引かれる回数の期待値は約 1.0、4 件に 1 件は一度も引かれずに消える。`per_alpha` 0.2 では優先度が 20 倍でも引かれやすさは 1.8 倍。新しい遷移は最大の優先度で入るので、初回の抽選は TD と関係しない。ボスに当てた step は報酬 0 で TD 誤差も小さいので、TD の優先度では目立たない。
- **人間との差。** 人間がボスを倒せるのは、事前知識（目的・表示の意味・戦い方）、内的な動機（好奇心・達成感・稼ぎへの飽き・上達の見込み）、成功の記憶があるから。このうち「飽き＋好奇心」と「当てたらバーが縮んだことへの手応え」に当たるのが新しさのボーナスで、本 PRD の対象である。事前知識は [999_llm_actor_10prd.md](999_llm_actor_10prd.md)、成功の記憶は EMDQN 型の価値の下限・SIL（未起票、§6）の側。

### 2.4 ユーザーの裁定（2026-10-16）

ボスの手前から始めること（状態の保存と復元）と、ボス体力の減りへの報酬は「ゲーム仕様を別にするのはやり過ぎ」で採らない。sticky action を切るのは本来のゲームに戻すので可。エージェント側の汎用の工夫は歓迎。

### 2.5 新しさのボーナスが KFM に効くと見込む理由

新しさの測り方には、一生の履歴と比べるもの（回数、RND、ICM の予測誤差）と、今のゲームの中の履歴と比べるもの（NGU のエピソード内の新しさ）がある。KFM の壁（§2.3）に効くのは後者と見込む。

- **一生の新しさは、要る時期に消える。** ボス戦の画面は、挑む前はまれなのでボーナスが大きい。しかし挑み始めると（s08 は 5.5M の 0.5M 窓で約 220 ゲームの 71%）すぐ見慣れて、勝ち方を覚える前にボーナスが消える。ICM も、「蹴ったらバーが縮む」を前向きモデルが予測できるようになると意外さが無くなる。挑むきっかけは今も起きているので、一生の新しさが効く時期は既に足りている。
- **エピソード内の新しさは、ゲームごとに記憶を空にするので慣れで消えない。** ボスに当てるたびにバーはそのゲームでまだ見ていない長さになり、報酬 0 の命中が 11 段の手応えになる。
- **ボスの体力が戻る仕組みとかみ合う。** やられると面の最初に戻りボスの体力も戻るので、同じゲームの 2 機目以降でボーナスが付くのは、それまでより深く削ったときだけになる。「このゲームでの自己ベストを更新する」向きの動機が撃破まで続く。
- **稼ぎにはボーナスが付きにくい。** 同じゲームの中で似た画面を繰り返すので、すぐ新しくなくなる。ボスへ向かう道と、撃破の先（出口の換算・2 面）は、毎ゲームそのゲームで初めて見る。
- **埋め込みは逆動力学で学ぶ。** 2 枚の連続した観測から行動を当てるように学ぶので、自機の行動が変えた物（バーの縮み、倒れる敵）が残り、行動と関係しない画面の揺れは残りにくい。バーの縮みは攻撃が当たった証拠なので、行動を当てる手がかりになる。
- **観測でのバーの見え方。** 1 発で全長の約 1 割が縮むので、84×84 に縮めた観測にも数画素の変化として残るはず（画素数は未計測）。懸念は見えるかどうかより、埋め込みが画面全体の中の小さな変化を保つかどうかで、段階 1 の指標で確かめる（§4、§8 の 9）。
- **文献の留保。** Taiga ら（2020）の追試では、探索の易しいゲームでボーナス型の探索が ε-greedy を上回らなかったが、これは平均の成績の話で、特定の局所解から抜けるかは示していない。R2D2 は内的報酬なしで KFM 233k（Atari-5 の公開データ）なので、大規模な学習では必須ではない。

### 2.6 方策の多様性の段（2026-10-18 の整理）

多数の Actor や lane があっても、方策がどう違うかで効き方は大きく違う。

| 段 | 何が違うか | 例 |
| --- | --- | --- |
| ① 行動のゆらぎ | 同じネットワークを共有し、ε だけ Actor ごとに変える | Ape-X、R2D2、anet の spatial exploration のラダー |
| ② 目的を変えた方策の家族 | 1 つのネットワークに方策の番号を入力し、β と γ の違う方策をエピソードごとに 1 つ使う | NGU、Agent57 |
| ③ 別々のパラメータ | ネットワークや価値関数そのものが別 | 独立の seed、PBT、Bootstrapped DQN の複数の Head |

- KFM で seed 3 だけがボス行きに入ったのは ③ の違い（設定の差は `run.seed` だけ）で、ネットワークが別の谷に落ちた。seed 3 は 3-4M にボス命中 10%・撃破 ÷ 命中 0.03 だったのが、4-5M に命中 51% へ跳ね、6-7M に撃破 ÷ 命中 0.71、11-16M に 0.9 まで上がった。
- ① では「ボスを練習し続ける性格」は生まれなかった。2026-10-17 の UQE（低い ε）の Run で、4〜12M のボス命中を lane の 4 区分で見ると 7.1% / 7.6% / 10.8% / 10.2% とほぼ一様で、lane ごとの τ の違いがあっても全 lane が 1 つの戦略として挑み、1 つの戦略として撤退した。
- R2D2 は ① だけで KFM 233k（Atari-5 の公開データ）なので、② は必須ではない。ただ ② は、点数の方策が稼ぎに固まっていても、新しさ重視で遠くまで見る方策がまれな場面（ボス戦）を練習し続け、その経験を共有のパラメータ越しに点数の方策が使える形で、人間の「飽き・好奇心で練習し、得になったら使う」に近い。

### 2.7 GridMaze: 学習の分布の外から再開すると届かない（2026-10-24）

**観察（ユーザー、2026-10-24）。** GridMaze で、学習が進んで安定してゴールできるようになった後でも、EvalPanel の手操作で点数の方策がほとんど通らないセルへ誘導してから再開させると、ゴールに着かない。Run 名と、どのセルへ何 step 誘導したかの記録は無い。固定の開始位置からの評価で成功していても、通らない状態から届くことは示さない。

**今の構成（2026-10-24 にコードと設定で確認）。**

- 観測は位置の (x, y) を 0〜1 に正規化した 2 次元のベクトルだけ（[GridMazeEnv.cpp](../../core/envs/gridmaze1/src/GridMazeEnv.cpp) の `GetObservation`）。迷路は固定の seed で毎回同じなので（[GridMaze.txt](../../apps/runner/config/GridMaze.txt) の `GridMazeEnv.randomize_seed ?= false`）、壁の配置は観測に無く、ネットワークの重みに覚え込まれる。
- 開始位置は (0, 0) に固定（同 `GridMazeEnv.init_pos_x ?= 0`・`GridMazeEnv.init_pos_y ?= 0`）。学習のデータは (0, 0) から出た軌跡だけになる。
- 学習と評価の方策は UQE、Body は 2 層の MLP（同 `A1.actor.[train].policy.policy_type = UQE`・`A1.actor.[eval].policy.policy_type = UQE`・`DefaultDQNAgent.net.body.$ = net.body.@MLP2`）。
- 手操作の step は、EvalPanel が eval の runner へ行動を渡すだけで（[EvalPanel.cpp](../../apps/runner/src/EvalPanel.cpp) の `DoStep(int64_t action)`）、eval の runner は Learner を呼ばないので、その遷移は学習に入らない（[999_input_target_train_forced_action §1.1](999_input_target_train_forced_action_10prd.md)）。
- 壁や盤の外へ向かう行動では位置が変わらない（GridMazeEnv.cpp の `Step`）。手操作の step もエピソードの step 数に数えられ、`max_steps`（既定 100）で打ち切られる。

**見立て（Run では未確認）。**

- 点数の方策の Q が正しくなるのは、replay に入った状態のまわりだけである。ε や UQE の揺らぎは点数の方策の Q から作るので、Q が収束すると、集まるデータも最短路のまわりに縮む。
- ε には向きが無い。最短路から決まった向きへ 3 歩外れるには、決まった向きの乱択が 3 回続く必要があり、ε = 0.05（GridMaze.txt の `uqe_eps_end`。spatial exploration は [agent.txt](../../apps/runner/config/agent.txt) の既定で無効）・行動 4 つなら確率は (0.05 / 4)³ ≈ 2×10⁻⁶ になる。実際の Run の値は config dump で確かめる。
- UQE の分位点の幅は収益のばらつきで、「この状態を知らない」ことを表す量ではない。通っていない状態で幅が広がる保証は無い。
- 座標を入力にする MLP は、通っていないセルの値を座標の近いセルから補う。壁の向こうのセルの値も補うので、そのセルで最善とされる行動が壁を向くと位置が変わらず、決定的な方策は同じ行動を `max_steps` まで繰り返す。Evaluation Trace（[094](094_evalpanel_step_history_10prd.md)）で、再開後に壁への衝突の回数（`wall_collisions`）が増え続けるかで確かめられる。
- 留保: エピソード内の新しさは、そのエピソードで何を見たかで決まり、今の観測だけでは決まらない。NGU は再帰型の Agent（R2D2）で使っているが、anet の DQN 系は再帰を持たない。探索役が 1 エピソードの中で状態を覆えるかは、§8 の 26 の (2) で確かめる。

**Agent 側に要るもの。**

- 新しさを目的にする探索役が、点数の方策の収束と関係なく状態を覆い続けること（§2.6 の ② の、β の大きい方策）。
- 点数の方策が、探索役の遷移からも学ぶこと。DQN の目標値の max は行動した方策に依らないので、探索役の遷移も点数の方策の学習データにできる（n-step の途中は行動した方策に依る。§8 の 27）。
- 評価が新しさを追わないこと。
- env の知識（観測が座標であること、開始位置を選べること、盤面）を使わないこと。Agent が知るのは、観測がベクトル（観測キー `vector`）であることまでとする。

**今の段階の形と合わない所。**

- 段階 1 の 6・§8 の 7: 価値が 1 本で、評価も和の Q で選ぶので、評価の方策が新しさを追う。
- 段階 3 の 3・4: 各遷移は、その lane の方策 j の Q だけを学ぶ。j = 0 の Q は j = 0 の lane の遷移でしか学ばないので、探索役が通った珍しい状態での j = 0 の値は、方策の番号の入力を変えた推測にとどまる。
- 段階 1 の 1・§8 の 2・3・19: 埋め込みの入力（84×84 の最新 1 枚）、Nature CNN、画素ごとの正規化、方策の番号を「畳み込みの後の特徴」に足すこと、は画像の観測を前提にしている。GridMaze の観測は 2 次元のベクトル。
- §8 の 21: 段階 3 と UQE の組み合わせは対象外だが、GridMaze の今の設定は学習・評価とも UQE。

**この事例で選ばなかった対策。** 学習時の開始位置を到達できるセル全体からばらすこと（exploring starts）と、迷路の盤面を観測に入れて CNN で読むことは、env の側の対策なので採らない（§1 の非ゴール）。探索の設定（ε・UQE の τ）を上げることは、揺らぎが点数の方策の Q から作られる構造のままなので、Q が収束するとデータが縮むことは変わらない。

## 3. 現状（2026-10-18 に確認したこと）

- 内的報酬の仕組みは無い。[048](done/048_quantile_tail_metrics_10prd.md) は NGU・RND・ICM を対象外と明記している。
- 報酬は、Agent の `UpdateFromBatch` で reward scaler を通してから replay に入る（[default_dqn_agent.cpp](../../core/anet-core/src/default_dqn_agent.cpp) の `reward_scaler_->Scale(batch_exp.reward)`）。観測は生のまま replay に渡す。
- replay は系列が確定した時点で n-step の割引報酬和を計算して保存する（[replay_buffer_impl.cpp](../../core/anet-core/src/replay_buffer_impl.cpp) の `ProcessQueue` と `builder_->Build`、保存先は `ReplayExperience.target_return`）。1 step ごとの報酬は後から取り出せない。したがって、内的報酬は Push の前に報酬へ足すのが自然な位置になる。
- Atari の報酬クリップは env の側で行う（[AtariEnv.cpp](../../core/envs/atari1/src/AtariEnv.cpp) の `reward_clip`）。
- 観測の正規化の仕組み（`obs_norm_` の `NormalizeAndUpdateStats`）と、動的なスケーラ（[scaler.hpp](../../core/anet-core/include/anet/scaler.hpp)）がある。埋め込みと RND の入力の正規化、ボーナスの正規化に流用できる可能性がある。
- 指標の群番号は、32〜50 の agent 系（48 は attention、50 は [098](098_temporl_skip_policy_10prd.md) の `50_agent_skip`）と 51〜53 の評価の群が使用中で、59 は [999_replay_eviction_sample_count](999_replay_eviction_sample_count_10prd.md) が予約している（2026-10-24 に `apps/runner/config/*.txt` と同 PRD の §5 の 3 で確認。起票時の「50 は eviction が予約」は、その後の群番号の変更で古くなった）。
- KFM の RAM メトリクスは 1 = 面クリア、2 = 撃破、3 = 命中の回数（`AtariEnv.ram_metric.[kung_fu_master].metrics`、[Atari.txt](../../apps/runner/config/Atari.txt)）。ボス体力の最小（`0xCC min_seen`）は定義だけあって番号が無いので、エピソードの値として出ない。番号を足せば設定だけで出せる（2026-10-21 にコードで確認）。

## 4. 提案の骨子

下の段階 1〜3 は、KFM を起点にした起票時の案である。§2.7 のゴール（評価は新しさを使わない点数の方策で、その方策を全 lane の遷移で学ぶ。観測の種類に依らない）には合わない所がある（§2.7「今の段階の形と合わない所」）。どう直すか、段階をどう組み直すかは §8 の 24・25 で決める。

### 段階 1: 逆動力学の埋め込みとエピソード内の新しさ（NGU の本体）

1. **埋め込み**: 小さな CNN の埋め込み φ（既定 32 次元）を持つ。入力は 4 枚重ねのうち最新の 1 枚（84×84）。φ(s_t) と φ(s_{t+1}) から行動 a_t を当てる分類器（逆動力学モデル）と一緒に、交差エントロピーで学ぶ。学習は Learner の更新に足し、replay から引いたバッチの一部の連続する 2 枚と行動を使う（専用の optimizer）。
2. **エピソード内の記憶**: lane ごとに、今のゲームの中で見た φ を記憶する。ゲームの始まりで空にする。
3. **ボーナス**: 次の観測の φ と、記憶の k 近傍との近さを足し合わせたソフトな回数からボーナスを作る（NGU の式）。

   ```
   r_epi = 1 / √( Σ_{k近傍} K(φ(s), φ_k) + c )
   K = ε / ( d² / d̄² + ε )      d̄ は k 近傍の距離の移動平均
   ```

   近さの和が上限を超えたら 0 にする（NGU の打ち切り）。
4. **一生の倍率**: 段階 1 では 1 で固定する（段階 2 で RND に置き換える）。
5. **報酬へ足す**: ボーナスをその移動標準偏差で割って正規化し、係数 β を掛けて、reward scaler を通した後の報酬に足してから replay に入れる。ボーナスは計算した時点の埋め込みで決まり、replay に入った後は更新しない。
6. **価値は 1 本のまま**（外的報酬とボーナスの和で学ぶ）。終端は外的報酬の終端をそのまま使う。評価の行動も和の Q で選ぶ。
7. **指標**: ボーナスの生の平均と最大、正規化後の平均、報酬全体に占める割合、逆動力学の損失と正解率、k 近傍の距離の移動平均 d̄、記憶の件数。学習側のゲームごとのボーナスの合計を trace に載せ、RAM メトリクス（ボス命中など）と並べて見られるようにする。

段階 1 だけで、命中ごとの手応えがボス戦の上達につながるか（挑んでいる間の撃破 ÷ 命中が上がるか、ボスに挑むことが 10M 以降も続くか）を確かめられる。

### 段階 2: RND による一生の新しさ

1. 固定の乱数初期化のネットワーク（target）と、それを真似る学習するネットワーク（predictor）を持つ。入力は 4 枚重ねのうち最新の 1 枚を、画素ごとの移動平均と標準偏差で正規化したもの。
2. 各 lane の次の観測について、predictor と target の出力の二乗誤差を求める。predictor は Learner の更新で、replay から引いたバッチの一部の観測に対して二乗誤差で学習する（専用の optimizer）。
3. **NGU の倍率**: 誤差を移動平均と標準偏差で標準化し、α = clip(1 + 標準化した誤差, 1, L)（既定 L = 5）を段階 1 のボーナスに掛ける。下限が 1 なので、一生で見飽きた状態でもエピソード内のボーナスは消えない。
4. **RND 単独**: 誤差そのものを正規化してボーナスにする形も選べるようにし、段階 1 との比較の腕にする（§2.5 のとおり、KFM では効き目は小さいと見込む）。

段階 2 は「毎ゲーム同じ所を初めて見ること」を、一生の新しさで弱める。KFM では、毎ゲーム歩く 1 面の道のボーナスが下がり、ボス戦とその先が残る見込み。

### 段階 3: 方策の家族（NGU・Agent57 型）

1. 方策を N 個（既定 8）用意する。方策 j は、ボーナスの重み β_j（0 から β_max まで）と割引率 γ_j（0.99 から 0.999 まで）を持つ。j = 0 は β = 0 の点数の方策。
2. ネットワークに方策の番号 j を入力として渡し（埋め込みを特徴に足す）、1 つのネットワークで N 個の Q を表す。
3. lane ごとに j を固定して割り当てる（spatial exploration のラダーと同じ発想で、lane の番号から決める）。その lane の遷移は、その方策の β_j で報酬を作り（外的報酬 ＋ β_j × ボーナス）、replay に方策の番号を持たせる。
4. Learner は、遷移ごとにその方策の γ_j で n step の割引と bootstrap を計算し、target もその方策の番号で評価する。
5. 評価（eval）は j = 0 の方策で行う。
6. 指標: 方策ごとの学習中のエピソードの点数と長さ、方策ごとの RAM メトリクス（KFM のボス命中など）。trace に方策の番号を載せる。

段階 3 は段階 1 のボーナスを前提にする（β_j を掛ける相手が要る）。β をすべて 0 にして γ だけ変える形なら、段階 1 が無くても試せる。

## 5. User Stories

1. 研究者として、ゲーム固有の報酬を作らずに、報酬に出ない途中の進み具合（ボスに当てたこと）への手応えをエージェントに与えたい。
2. 研究者として、ゲーム固有の報酬を作らずに、エージェントが稼ぎの局所解から離れる動機を足したい。
3. 研究者として、新しさのボーナスがどの場面で出ているかを、ボス命中などの RAM メトリクスと並べて確かめたい。
4. 研究者として、埋め込みがボスへの命中を区別しているかを指標で確かめたい。
5. 研究者として、ボーナスを切ったときに今と同じ学習系列になることを確かめたい。
6. 研究者として、ボーナスの係数や種類（エピソード内・RND 単独・組み合わせ）を変えた腕どうしで、点数への害と局所解からの脱出を比べたい。
7. 研究者として、env の知識を使わずに、点数の方策がほとんど通らない状態へ連れて行かれても、そこからゴールへ届く点数の方策を学ばせたい（GridMaze、§2.7）。
8. 研究者として、同じ内的報酬の設定を、観測がベクトルの env（GridMaze）にも画像の env（Atari）にも、観測の仕様に合わせた NN の設定だけで使いたい。

| ICM（前向きモデルの予測誤差をボーナスにする） | 不採用 | 一生の意外さなので、命中の効果を予測できるようになると消える（§2.5）。確率的な要素（sticky、雑魚の出方）にも引っぱられやすい。良い所である逆動力学の埋め込みは段階 1 で使う |
| 実行時に、そのエピソードの経験で価値を補正する（EVA 型、Hansen ら 2018。記憶にある軌跡で計画した値を Q に混ぜる） | 別 PRD（未起票） | 学習の分布の外へ連れて行かれたときの最後の備え（§2.7）。本 PRD は学習のデータの分布を広げる側で、実行時の補正は別の関心。本 PRD の探索役で覆えない状態が残ると分かったときに起こす |
| eval の遷移（EvalPanel の手操作を含む）を学習に流す | 範囲外 | 人の操作の遷移を学習に使う経路は [999_input_target_train_forced_action](999_input_target_train_forced_action_10prd.md)（Train 側の強制行動）が扱う。eval の遷移を流すと、評価が止めた snapshot の採点でなくなる |

## 7. 背景の補足（実装の位置）

- 段階 1 のボーナスは、Push の前（`UpdateFromBatch`）で次の観測から計算する。学習スレッドで 128 lane 分の埋め込みの CNN の forward と、lane ごとの k 近傍の検索（KFM の 1 ゲームで最大約 9,000 件 × 32 次元）が毎 step 1 回増える。
- 逆動力学モデルの学習は Learner の更新に足す。連続する 2 枚と行動は、replay の同じ lane の隣り合う遷移から取れる見込み（n-step 先の観測ではなく 1 step 先の観測が要る。§8 の 17）。
- 段階 2 の RND の forward も Push の前、predictor の学習も Learner の更新に足す。

## 9. 成功の測り方と受入の目安

成功の測り方:

- 比較の基準は、既定の実時間優先の 10M × 16 seed（§2.2）。定着は約 20 本に 1 本なので、定着の本数では比べない。挑んでいる窓（命中 10% 以上の 0.5M 窓）の撃破 ÷ 命中の最高（基準は最高 0.22、中央値 0）、挑む窓が 10M までに出る本数（基準は 16 本中 7 本）、ボスに残った体力（エピソードごとのボス体力の最小。§3 の番号を足して出す）の推移で見る。
- 段階 1: ボスに挑んでいる間の撃破 ÷ 命中が 0.3 を超える Run が複数出るか。挑むことが 10M 以降も続くか。命中の step のボーナスが、稼ぎの step より高いか（§8 の 9 の指標と、ゲームごとのボーナス合計とボス命中の関係で見る）。
- 段階 2: エピソード内だけ（`episodic`）と倍率つき（`ngu`）と RND 単独（`rnd`）を同じ seed の組で比べ、§2.5 の見込み（RND 単独は挑んでいる間に効かない）が当たっているかを確かめる。
- 段階 3: 方策ごとのボス命中を見て、β の大きい方策がボス戦を練習し続け、その間に j = 0 の方策がボス行きに入るか。
- 害の確認: Breakout など、探索の易しいゲーム 1 つで、評価の点数が基準の seed 幅の中に収まる。
- GridMaze（§2.7）: 内的報酬なしの基準（今の GridMaze の設定）と比べて、§8 の 26 の (1) のゴール到達率が上がる（基準の値は未計測なので、先に基準を測る）。(2) の探索役の訪れたセルの数が、点数の方策の収束後も下がらない。(3) で再現していたセルから再開してゴールに着く。

受入の目安（詳細はグリルで確定する）:

1. `intrinsic.type = none` で、本機能の前後の同 seed・決定的モードの短い Run の metrics checksum が一致する。
2. 単体テスト（エピソード内の新しさ）: 同じゲームの中で同じ埋め込みを繰り返すとボーナスが下がり、新しい埋め込みでは高い。ゲームの始まりで記憶が空になり、ボーナスが戻る。
3. 単体テスト（RND）: 同じ入力を繰り返し学習させると RND の誤差が下がり、見たことのない入力では高い。倍率が 1〜L に収まる。
4. smoke Run（`episodic`・`ngu`・`rnd`）で、新しい tag が `metrics.jsonl` と `metrics.scalar.defs` に出て、値が有限である。逆動力学の正解率が偶然（1 ÷ 行動数）より高い。
5. §8 の 1 の不正値で、Agent の構築時にエラーで止まり、メッセージに設定キーと値が出る。
6. learn の速度の低下を、ラウンドロビンの A/B で測って記録する（目安 15% 以内）。

## 10. 依存と順序

段階 1 に実装上の依存は無い。段階 2 は段階 1 の後（RND 単独の腕だけなら先にも作れる）。段階 3 は段階 1 の後（γ だけ変える形なら先にも試せる）。GridMaze の事例（§2.7）に効かせるには、§8 の 24 の形（評価の方策が全 lane の遷移で学ぶ）が段階 1 と同時に要る。段階 1 だけでは評価が新しさを追う。効き目の確認には [999_replay_eviction_sample_count](999_replay_eviction_sample_count_10prd.md) の計器（ボーナスで目立った遷移が何回引かれたか）と、[094](094_evalpanel_step_history_10prd.md) の Evaluation Trace（ボス戦の 1 step ずつの表示）があるとよい。
