## 今の結論

サンプル効率優先に RND（β 0.1）を載せた 30M（1 本、RND なしの対照なし）では、ε=0.01 の評価が 14.21M から 400 点（鍵と扉 1 枚）を続けた一方、Greedy は 20.4M まで 0 点で、25.45M に 9/16 が 400 点だった。30M の重みの Greedy は 400 点以上が 19/32 で、届かないゲームは部屋 1 のまま打ち切りまで続いた。評価時に ε 0.01 か τ の乱数を足すと 29〜32/32 になった。20.07M の重みは、評価の 4 条件とも全ゲーム 400 点だった。Taiga ら寄せの構成で β・Munchausen・Double DQN を変えた RND の Run では、β 0.01・Munchausen 無効の 2 本（seed 1・2）の Greedy が 20.2〜29.2M に 99/160・81/160 のゲームで 2500 点に届いて回ごとに揺れた。同じ β 0.01 で Munchausen を有効にした Run（seed 1）は 5/160 で、多くが 500 点（剣を取って敵を倒さない）で止まった。β 0.1 の 2 本は Munchausen の有無に依らず Greedy で 2500 点が 0 本だった（有効は 29.2M まで、無効は 22.2M まで）。seed 2 の Run と Munchausen 有効の Run の Greedy は、ほぼすべてのゲームが 27,000 step の打ち切りで、命を残して終わった。Taiga らの式の RND は、Munchausen の有無に依らず鍵より先へ進まなかった。RND の warm-up を PRD123 の既定にした β 0.01・Munchausen 無効の Run（seed 1）は、学習側で部屋 13・14・21・22 に入り 3500〜3700 点が出たが、Greedy の 2500 点以上は 26.2M からだった。その 30M の重みは、評価だけで流すと Greedy・ε 0.01 とも 16/16 が 2500 点以上だった。同じ設定を seed 2 で流すと、Greedy の 2500 点以上は 29.2M からで、学習側の 3500 点も 28〜30M の窓に初めて出た。学習の報酬は `reward_clip` で点が入るたびに +1 なので、点と報酬は食い違う。seed 1 の Run を 30M の重みから通算 50M まで延ばすと、ε 0.01 の評価の点は 2,445〜2,740 で横ばいだったが、報酬は 25〜30M の 4.45 から 5.05〜5.60 に上がり、35M 以降は平らだった。学習側は 3,000 点の敵を倒す道から、報酬の多い鍵を取る道へ寄った。延長の 50M の重みでも Greedy は部屋 6 と部屋 14 で止まり、部屋 14 では画面がまったく変わらず、内的報酬は 0 だった。同じ PRD123 の既定で β を 0.003 にした Run（seed 1）は、学習側で部屋 7 より先へ 30M まで 1 度も進まず最高は 2500 点だったが、Greedy は β 0.01 より早く 2500 点にそろい、20.2〜29.2M に 100/160 だった。

## 分かっていること

- RAM の番号付き定義は `1:room_max`（0x83 の最大）、`2:rooms_visited`（0x83 の種類数）、`3:key_get`（0xC1 の鍵のビット 30 の 0→1）、`4:sword_kill`（0xC1 の剣のビット 32 の 1→0）、`5:sword_get`（剣のビットの 0→1）、`6:door_open`（鍵のビットの 1→0）、`7:lives_lost`（0xBA の減少）。面の区切りもボスも無いので、1 には到達した最大の部屋番号を使い（開始の部屋は 1、開始の左の部屋は 0）、2〜6 は部屋と持ち物を追うのに使う。0xC1 は持ち物のビットで、鍵は 2、部屋 6 の剣は 32。グラフの tag は 1〜4 だけにあり、5〜7 は trace とログ行で読む（出典: [220_atari_env.jp.md](../../design/220_atari_env.jp.md)、§4.9 RAM メトリクス）。
- 0xC1 の鍵と剣のビットは同時に 1 になりうる。部屋 7 で剣を持ったまま鍵を取ると 32 から 34 になった（ALE、sticky 0、1 フレームずつの探索で、Run ではない）（出典: [PRD126](../../memo/126_atari_ram_metric_distinct_and_bit_reducers_10prd.md)、§2.2）。ビットの畳み方はビットごとに数えるので、鍵と剣を同時に持っていても両方を数える（出典: [220_atari_env.jp.md](../../design/220_atari_env.jp.md)、§4.9 RAM メトリクス）。
- 部屋番号の種類数だけでは左右の扉を見分けられない。左の扉から部屋 0 へ入ったゲームも、右の扉で部屋 2 へ入ったゲームも 2 になる（出典: [PRD126](../../memo/126_atari_ram_metric_distinct_and_bit_reducers_10prd.md)、§8）。
- サンプル効率優先＋RND の 30M（seed 1）で、Greedy（ε=0・τ 固定、16 ゲーム、約 5.05M ごと）は 0.2〜20.4M が全ゲーム 0 点、25.45M が 243.8（400 点 9、100 点 3、0 点 4）だった。同じ重みの別 session は 20.4M に 25.0（400 点 1/16）、25.45M に 231.2（9/16）。5.25M 以降の Greedy のゲームは、1 本を除いて 108,000 フレームの打ち切りで終わった（出典: [2026-11-08_montezuma-rnd-se-30m.md](../../experiments/default-dqn/atari/2026-11-08_montezuma-rnd-se-30m.md)、現時点のまとめ1・探索ブロック01。Run: run_20261108-003056_mz_se_rnd_k32_s1）。
