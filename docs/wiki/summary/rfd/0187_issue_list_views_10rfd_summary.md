# 課題一覧の依存関係と表示方式の比較

## 元の材料

[RFD0187　課題一覧の依存関係と表示方式の比較](../../../memo/0187_issue_list_views_10rfd.md) blob:0d5936a551e033b01443ac8c6369bdc3cdf4353d

## 要点

- 課題単票の Markdown を正本として、次に扱う仕事、親子関係、依存、全体の状況をPCやスマートフォンから見つけやすくする暫定 RFD である。
- 起草時は HTML の表、折り畳める親子の木、Mermaid の依存図、CSV を作る案を置いた。出力ツールの Node.js 採用や置き場を含め、§4 の全項目は再検討する暫定案である。
- 初版では一覧からの編集を範囲外とした。その後の相談で、AI 経由の更新、人が見る一覧の鮮度、外出先での閲覧を検討材料に加えた。
- Obsidian Bases の試用では、単票の絞り込み・並べ替えはできた。一方、親子の木、依存図、ブラウザからの配信には別の方法が要った。
- 独自 Viewer、既存ツールの拡張、自然文での AI 選定などを比較している。どの方式を採るかは未決である。

## 内容

### 背景と目的

課題を1件ずつ Markdown にすると、単票は読めても親子関係や依存の全体を横断しにくい。起草時は移行後に100件を超えると見積もっていた。作業候補を探す、全体を眺める、関係や状態の誤りを拾うという用途で、一覧の使い方を検討した。

### 起草時の暫定案

初版の五つの既定はすべて再検討の対象である。静的な表・親子の木・依存図・CSV の出力を、課題採番と同じ Node.js の道具と一覧スキルから作る案を置いた。初版の想定は単票を読む派生物であり、Wiki のトピック別まとめは既存の道具で更新する。

### 再グリルで決めること

単票が変わるたびに更新するか、必要なときに書き出すかで、表示の鮮度と運用費用が違う。CSV で足りるか、独自の Viewer を動かすか、見る場所が異なるときにどこから配信するかは未決である。独自 Viewer を採れば、初版の一覧ファイルや「書き出し」の扱いも見直す。

### 試用と相談で増えた材料

実際の試用では保管庫を課題管理フォルダに絞った。docs 全体には Doxygen の生成物が17,190ファイル、143 MBあったためである。Obsidian Bases の表と Redmine の絞り込み表示を比べ、選んだ課題を AI へ依頼する案や、自然文で選んだ結果に理由を添えて表示する案を挙げた。いずれも採用前の比較材料である。
