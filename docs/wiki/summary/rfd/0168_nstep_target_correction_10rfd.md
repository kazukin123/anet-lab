# 窓の途中の Munchausen 項と方策差を補う n-step 案

## 元の材料

[RFD0168　窓の途中の Munchausen 項と方策差を補う n-step 案](../../../memo/0168_nstep_target_correction_10rfd.md) blob:1d4184f28e994d080c01a3244d64422eb80e116d

## 要点

- n-step の途中の行動と方策のずれを補正する暫定案であり、採用する補正方式は未決である。
- DropMerge の比較では n-step 3 が1より約1割低く、合法 DROP がある場面で NOOP を続ける挙動も増えた。
- 従来のターゲットでは窓の先頭と最後にだけ Munchausen の計算があり、途中の行動に対応する項が入らない。
- 途中の項を含める方式を選択できるようにし、対象方策と行動方策の違いによる影響と分けて比較する。
- 途中の log π を行動時に保存する方式と学習時に再計算する方式には、保存量と追加 forward の違いがある。
- 対象方策から外れた途中行動で窓を切る、または以降の寄与を減らす補正も検討する。

## 内容

### 目的と問題

探索の手が目標値に混ざる: 補正のない n-step return は、窓の途中で挙動方策が実際に打った手の報酬と、その結果の状態をそのまま含む。ε の大きい lane のランダムな手が混ざると、精密な続きが要る組み立ての価値が低く見積もられ、安全で伸びない打ち方に寄る（局所解）。n = 1 の Q 学習では、探索の手は「どの状態を見たか」の広さにだけ効き、目標値には入らない。

### 起草時点の現状

全 lane の平均で、約 7% の手がランダムになる。
n = 3 の窓の後ろ 2 手にランダムな手が混ざる割合は、全 lane の平均で約 12%、ε 0.6 の lane では 84% になる。

### 提案の骨子

途中の状態の log π は、学習時に target net で求めるか、行動時に保存するかを選ぶ。前者は、窓の長さのぶん forward が増える。
Retrace(λ): 挙動方策の確率と target の方策の比で、続きを入れる重みを決める。

### User Stories

研究者として、n-step を使っても NEET が悪化しない形で、報酬の遡りを速くしたい。
研究者として、探索の手が混ざった目標値のせいで組み立ての価値が低く見積もられないようにし、局所解に寄るのを避けたい。

### 決めること

途中の状態の log π を学習時に求めるか、行動時に保存するか。
