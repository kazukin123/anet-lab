# 資料別サマリと会話からの wiki の利用

## 元の材料

[RFD0202　資料別サマリと会話からの wiki の利用](../../../memo/0202_wiki_accumulate_and_lookup_10rfd.md) blob:2dae65800ff65b85e5c47b5d1d789811bd3f3e31

## 要点

- 資料をまたぐ質問を受ける前から、条件をそろえた比較や未検証の見立てが wiki にあり、材料ごとの要点からも探せる状態を目指す。
- 確かめた数値・結果の正本は実験記録などに置く。wiki には原本への出典を付け、横断的知見と仮説を分ける。
- Codex が構造の移行、実験記録・報告、RFD・設計文書・ADR の取り込みを順に行い、ステージ3の最後に会話から引く・書く入口を設けた。
- ステージ3末に実装前と同じ16問を判定すると、「答えがある」は4問のままで、仮説の終わり方の線に当たった。再グリルで、節・種類・基準は戻さず、開発者の質問を起点に答えの項目を書く作業をステージ4に足した。
- 仮説は、ステージ4のあとに来る質問で測る。会話の入口が、引いた時点で wiki に答えがあったかを毎回記録し、別の枠が、ステージ3末の wiki の控えでの判定と対にして比べる。
- Claude Code はステージ4で、規約と skill の直し、会話記録の道具、最初の点検、過去の質問29問、開発者の発言の見立て、判定の付け直しと正しさの確かめを順に行う。
- 点検の見立てに過去の問いの型を当てるかは、最初の点検の前に試して決める。

## 内容

### 目的と効果の測定

新しい数を計算する調査を毎回やり直す負担と、集めた報告が個別の資料の中に留まる問題を扱う。実装前に、複数の材料を合わせて答える16問を選び、既存 wiki の判定を固定した。「答えがある」4問、「答えの種がある」12問、「無い」0問である。ステージ3末に同じ問いを同じ基準で判定すると、16問とも実装前と同じだった。12問のうち7問は事実が項目にあるのに問いに答える読み取りになっておらず、5問は問いの一部に当たる記述が概念のページに無かった。
欠けた前提を2つの試しで確かめた。問いを知らせずに点検の手順どおり見立てを作ると、5ページで17件できたが、問いの全部に答えたのは12問中1問だった。問いを起点に書くと、読み取りが欠けていた7問中6問に答えの項目を書けた。問いに当たるかを分けたのは、何を起点に書くかだった。
改めた仮説は、取り込みと2つの節に加えて、開発者の質問を起点に項目を書けば、次の質問が来る前に答えが wiki にある状態になる、である。ステージ4のあとの4週間の質問の記録から、別の枠が20件を取り、質問の時点で答えがあった数が、同じ問いのステージ3末の控えで答えがあった数より増えていなければ、再検討する。ステージ4で足した横断的知見と見立ては、合わせて最大20件を別の枠が原本で確かめ、誤りが2割以上でも再検討する。

### 設計の根拠と採用した形

材料は実験記録、報告、RFD、日本語の設計文書、ADR。資料単位のサマリは原本へのリンクとその時点の Git blob を持ち、元資料の中身だけをまとめる。概念のページは複数の資料を束ねる。実装の範囲はトピック別まとめ、観測された知見は題材・手法・測り方・現象で引けるようにする。RFD が採用した設計は資料別サマリに残り、知見の実験事実には混ぜない。
横断的知見では複数の出典が報じた値と条件を比較する。見立てには未検証であること、支える事実と合わない事実、条件の違い、確かめ方と出どころを書く。独自の計算や実験結果は先に正本へ記録する。質問の索引や章見出しだけの検索用ページは増やさない。再グリルでは、サマリ、知見の4種とフォルダ、横断的知見と見立ての節、漏れなく載せる基準、「今の結論」の長さを、どれも保つと決めた。

### 取り込み、点検と会話からの利用

取り込みは原本全体を読み、サマリ、該当する概念、目録、作業記録を更新する。主張の全文は主となる概念に置き、ほかの該当ページからは要旨と出典で案内する。scan は原本とサマリの blob、欠けたサマリ、行き先のないサマリやリンクなどを調べる。点検は撤回や出典の変化を確認したうえで、未検証の見立てを更新する。
点検が見立てを作るときは、項目どうしと横断的知見、関連のページの項目を比べ、作る前に原本を開く。原本に答えがあるものは見立てにせず、項目に足す。置き場は、1つの手法で説明できれば手法、次に測り方、触れる題材が1つならその題材、どれでもなければ現象のページである。上限を超えたら、支える事実の多いものから残す。
質問に答える前に目録から概念、原本のサマリ、報告の索引と本文をたどる。実験の新しい集計は実験記録、外部調査は報告、コードの説明は設計文書を先に更新する。今の動作の変更は課題、設計判断は RFD・ADR の手続きへ送る。会話の入口は、質問に答えるたびに query 行を足し、引いた時点の判定（答えがある・答えの種がある・無い。答えは事実と見立てに分ける）と根拠の節、書いた所を記録する。何も書かなかった質問も記録する。検証済みの知見を memory に移す運用は採らない。
過去の質問は、指標の候補に挙げた29問を1問ずつ同じ決まりで書き直す。過去の会話の AI の答えは写さず、今の正本と概念のページから書く。設定を見れば分かる答えと外の調べものは、調べて正本に書いてから取り込み、分からなかった部分は「分かっていないこと」に問いとして残す。
発言を残さないという指定、公開できない値、仕事や私生活の話、課題の判断材料にならない話は掲載しない。過去の会話から拾った発言、第三者についての評価や内情、本人以外の発言、分類に迷う内容は、要旨と書く先を示して確認する。今の会話に出た当該プロジェクトの仮説・判断や正本に収録済みの発言は、定めた範囲で日付付きの要旨として扱う。
- 段 4 の実装で、未決表の U23 を試し（§5.13。型ありで問いの全部に答える見立てがある問いが 13 個中 1 個、型なしが 0 個）、点検が見立てを探すときに 4 つの型を順に当てることを足した（S52）。設定の値から出る事実は、実験記録と、記録がリンクする Run の実効設定の控えを出典にし、Run と日付を添える。控えは材料に入れず、記録の主張として扱い、今の設定ファイルは出典にしない（§4・S52。開発者の選択）。

### 担当と判定の時期

ステージ1は Codex が規約、道具、検証資材、既存ページとリンクを移行する。ステージ2は実験記録・報告94本の再取り込みで、最初の5本と中間で使用量を測る。Claude Code が横断的知見の正しさを照合して開発者に示してから、ステージ3の RFD・設計文書・ADR を取り込む。RFD 起草時の見積もりはこの3種で314本で、最初の5本を実測する。
ステージ3末に Codex が会話から wiki を引くスキル、共通の開始条件と query 記録を追加する。この時点で Claude Code は16問を再判定する。ステージ4は Claude Code が次の順で行う。規約と skill の直し、会話記録を引く道具、選ばれなかった13問の確認と問いの型の試しと最初の点検、過去の質問29問（選ばれた16問を先に書き、残りの13問の書く前の判定を早い目安にする）、開発者の発言の見立て、16問の付け直しと正しさの確かめである。過去の会話から開発者の見立てを取り込む際は本人への確認を通す。

### 受入とその後の記録

ステージ4を終えた日の翌日から4週間追うのは、これからの質問の記録と、横断的知見数、見立ての状態別件数、報告1本から知見に入った項目数の中央値、質問や RFD づくりで wiki を開いた割合、会話から書いた件数、サマリの無い材料数である。会話の入口が呼ばれた割合も出し、半分に満たなければ指標を未確認とする。実装前とステージ3末の判定は各問いの根拠とともに実装記録に残し、4週間の値は RFD に追記する。
実地の確認は調査を要した会話の最初の3回を数え、Plan Mode を除く。4週間で3回に足りない場合や、ステージ4最初の点検で見立てが生まれない場合は、理由と件数を記録して未確認とする。

### その後の変更

RFD0208 は、作業中に得た知見と調べた事例を作業ノートに置き、サーベイ・論文解説・作業ノートを外の事例の材料にした。ハーネスを知見の種類に追加し、主張と見立ての置き場の判定では先に当てる。サマリのファイル名には `_summary` を付ける。
