# RFD0203: wiki のページに YAML ヘッダを付け、Obsidian で一覧にする RFD

## 元の材料

[RFD0203 wiki のページに YAML ヘッダを付け、Obsidian で一覧にする](../../../memo/0203_wiki_page_yaml_header_10rfd.md) blob:a5aa8c1773bfdc7f937e8b4bd781cde4018866ed

## 要点

- wiki のページ（サマリのページ 410 本と概念のページ 51 枚）には YAML ヘッダが無く、Obsidian の Bases の表ではファイルの属性しか列にできなかった。
- 全ページの先頭に YAML ヘッダを置き、題名・ページの種類・材料・材料の種類・主要な概念・別名・説明・最後に直した日を、ページの種類に応じて持たせる。
- 値はどれも、本文・目録・フォルダ・作業の記録にすでにある値の写しで、新しく内容を書く値と、人が見ない数は持たない。材料の日付も持たない。
- 写しは新しい道具の口 `wiki_support.py headers` が作り直し、手で直さない。開発者が足した知らないキーは残す。`maps` と課題の道具は変えない。ページと作業の記録を書く手順（読んで気づいた食い違いの是正を含む）は、書いたあとに `headers` を回す。
- YAML の中のリンクは、保管庫の根からのパスと拡張子と表示名を付けた `"[[…]]"` で書く。本文の出典は今の Markdown の相対リンクのまま。
- `scan` は、YAML ヘッダが作る内容と違うページと、実在しない概念を指す「主要な概念」のリンクを警告に挙げ、点検を回す条件には入れない。
- 一覧の定義（`.base`）は Git に入れず、手元の `wiki.base` に表を足す。実装は 2 段で、先に 2 枚で開発者が Obsidian での働きを確かめる。

## 内容

### 目的と範囲

開発者は Obsidian でリポジトリ全体を保管庫にし、課題を Bases の表で見ている。Bases の列は、YAML のプロパティ、ファイルの属性、式の 3 つで、本文や見出しは読めない。wiki のページは YAML ヘッダを持たないので、表に並べても題名や材料で絞れなかった。ゴールは、ページの種類ごとに意味のある列で並べ替え・絞り込みでき、題名からページへ、材料の列から材料へ移れること、値が正と食い違わないこと、今あるページにもこれから書くページにも同じ形で入ることである。一覧のページを目録などに置く案、規約・目録・作業の記録に YAML を付ける案、Pages の見え方は範囲に入れない。課題の `rfd` 欄が RFD とそのサマリの 2 つに当たる件は、別の課題に記録した。作業の記録の区切りの食い違いは、`updated` を区切りによらずに読むことで受け、起票は見送った。

### 項目の組と出どころ

サマリのページは `title`・`page_kind`・`material`・`material_kind`・`concepts`・`updated`、知見のページとトピック別まとめは `title`・`page_kind`・`aliases`・`description`・`updated` を持つ。題名は本文の最初の見出し、種類はフォルダ、材料は `scan` と同じ置き場の対応、主要な概念は本文の節のうち実在する概念のページへのリンク、別名と説明は目録の行、最後に直した日は作業の記録で `→` より後ろにそのページのパスを含む最後の行から取る。開発者の基準は「題名で記事に行ければよく、統計は人が見ない」で、要点の 1 行、古いままかの印、項目や課題の数は外した。材料の日付は、git の日付ではコミットの日とずれ、取り込んだ日では古い材料で意味が崩れるので、持たないことにした。

### 持ち主と道具

YAML ヘッダの道具のキーは写しで、Obsidian で直しても次に道具を回すと戻る。正は本文・目録・フォルダ・作業の記録のままで、目録は今のとおり取り込みで AI が書く。作り直しを `maps` に載せると、課題の道具が回すたびに wiki のページに差分が出て、課題の skill の範囲の文とも食い違うので、別の口 `headers` にした。ページと作業の記録を書く手順（取り込み・点検・RFD づくりの書き戻し・会話から書く・読んで気づいた食い違いの是正）が、書いたあとに回す。`headers` はすべての入力を検証してから書き、区切りの閉じていない YAML、読めないかキーと値の組でない YAML、題名の無いページ、決まったフォルダの外のページ、同じサマリに当たる 2 本の材料、目録の重なった行、目録か作業の記録のファイルが無いときは、どのファイルも書かずに止まる。読んだ値が空になる YAML ヘッダは、キーの無い組として扱う。`scan` は、作る内容が決まらないページを止めずに警告に挙げる。知らないキーは、課題の管理外の欄と同じく残し、どのキーにも属さないコメントは残さない。材料・概念・種類を Bases の式で出す案は、式が Git に入らない手元の定義にだけ置かれ、相対リンクの扱いも文書に無いので採らなかった。

### 規約・検査・実装

wiki の規約に YAML ヘッダの項目を足し、出典の「`[[ ]]` を使わない」に YAML ヘッダの中を除くと添え、サマリの長さは YAML を除いて数える。`scan` の取り込み漏れの判定と blob の読み方は変えない。表示名と拡張子を付けたリンクが Obsidian で働くかは、文書で確かめきれていない。そのため実装は、段 1 で道具とテストを作り、サマリ 1 本と概念のページ 1 枚で開発者がリンクと表示名と題名の式を確かめ、働かなければ形を直してから、段 2 で規約と skill と AGENTS.md の是正の行を直して全ページに入れ、手元の表を足す。RFD0202 のステージ 3 が終わってから実装する。ADR は起こさない。

### その後の変更

RFD0208 で、サマリのファイル名に `_summary` を付け、課題にある名前だけの RFD リンクの重複を解消した。報告のヘッダの材料パスは新しい置き場を指し、材料の種類はサーベイ・論文解説・作業ノートで表す。
