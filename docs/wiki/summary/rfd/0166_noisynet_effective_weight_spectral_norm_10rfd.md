# NoisyNet のノイズ込み重みを正規化する案

## 元の材料

[RFD0166　NoisyNet のノイズ込み重みを正規化する案](../../../memo/0166_noisynet_effective_weight_spectral_norm_10rfd.md) blob:ebe92631978428441cf40c3c941ac60473d3dafb

## 要点

- ノイズを含む重みを正規化する方式を検討する暫定案で、必要性、公開設定、数値的な受入条件は未裁定である。
- 平均重みだけを正規化する方式と、ノイズを加えた実効重み全体を正規化する方式を区別する。
- 後者ではノイズを再抽選するたびに正規化対象が変わり、スペクトル推定の状態を前回から引き継ぐ条件が問題になる。
- 評価時にノイズを切ると摂動と分母の両方が変わるため、推定精度を高めるだけでは両方式は一致しない。
- 学習と評価、追加診断で使う重みの意味と、推定状態の更新・保存方法を整理する。
- ノイズ込み正規化が必要な具体例を確かめてから採用を判断する。

## 内容

### 問題と目的

本 RFD は、ノイズ込み重みを正規化する具体的な必要性と、そのための推定・状態・評価・検証契約を検討する。SN の演算自体が原理的に不可能だと判断した記録ではない。084 は μ 正規化 \(\mathcal{S}(\mu^w)+\sigma^w\odot\varepsilon^w\) までで独立して完了できる。

### 起草時点の現行契約とレビューの根拠

NN 設計 と ADR 0032 は、学習可能な重みを追う u/v を named buffer として保持する。初期化で 15 回の power iteration を行い、以後は train mode かつ GradMode 有効の forward だけで 1 回更新する。

### User Stories

実験者として、μ 正規化では満たせない比較目的があるとき、ノイズ込み重みの正規化を独立した実験条件として評価したい。
実験者として、Actor・Learner・target・診断で、推定方法や状態更新の差が結果へどう影響するかを理解したい。

### RFD0084（NoisyNet）との責任分担

084 には正規化対象の切替設定や、未実装のノイズ込み SN を選ぶ予約値を追加しない。本 RFD の採用時に、設定と公開契約の変更を別途裁定する。

### 検証候補と昇格条件

shared / independent、同じ状態の τ 間共有、ノイズ保持中の parameter 更新で、対応する重みが正規化対象になることを確認する。
