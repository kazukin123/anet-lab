# ブランチを main へ取り込むときの衝突を解く支援の案

## 元の材料

[RFD0204　ブランチを main へ取り込むときの衝突を、両側の内容と文脈を読んで解く支援の RFD](../../../memo/0204_branch_merge_conflict_assist_10rfd.md) blob:f3d5fe0c31bff09f5baf2ab9210ab29443396155

## 要点

- 暫定の起票で、確定した決定は無い。§7〜§9 は §6 の未決表の暫定の既定を前提にした試案である。
- 発端は、RFD0202 の番号が main（wiki の積み上げと引き方）とブランチ `feature/20261125-ppo`（PPO 系）で重なったこと。ファイル名が違うので、git はこれを衝突として示さない。
- 2026-11-26 の試しのマージでは、テキストの衝突は wiki の 4 ファイル（作業の記録と、トピック別まとめ 3 つ）だった。トピック別まとめでは、同じ事実を両側が別の文で書いていた。
- 作業の記録は行の順が道具の結果を変え、生成物は行の単位で合わせた結果が正しいか分からず、振り直しの行は旧い番号を使い続ける RFD を考えていない。
- 案は、衝突を 6 種類（生成物、追記だけのファイル、番号の重なり、置き場の移動、wiki の書く部分、中身の衝突）に分け、決まった解き方がある種類は手順で、中身の衝突だけを AI の案と開発者の選択で解く。
- 入口は新しい skill `anet-merge-branch`。AI は作業ツリーのファイルだけを直し、ステージとコミットは開発者が行う。
- 番号の重なりは、マージの前に、番号を変えられない記録に引かれていない側で振り直す。振り直しの行に旧い番号のコミットを名指す形を足す。
- 衝突を起こさない仕組み（採番がほかのワークツリーとブランチを見る）は範囲外で、別の課題の候補にした。

## 内容

### 問題と現状

ワークツリーのセッションで main と並行に作業すると、PR で main へ入れるときに衝突が起きる。main 側は wiki の RFD0202 を ADR 0097・0098 が引き、ブランチ側は PPO の RFD0202 をテストのタグを含む 22 件のファイルが引く。マージで両側の行が同じファイルに入ると、番号だけではどちらの RFD かを読み分けられない。RFD0202（wiki）の実装が wiki のフォルダを移すので、ブランチが旧い置き場に足した新しいページは、移した先に入らない。

### 未決表に置いた既定

試しのマージ（`git merge-tree --write-tree`）と、両側の差分から、番号の重なり・置き場の移動・生成物の変更を引く。生成物は道具で作り直し、作業の記録は日付の順に両側の行を残して道具の点検で確かめ、wiki の書く部分は出典を正として同じ事実を 1 行にまとめる。中身の衝突は、両側のコミットと件名が名指す RFD・課題を読み、両側の意図と解き方の案を示して開発者に選ばせる。読む文脈はリポジトリの中のものに限り、会話の履歴は読まない。取り込む向きは、main をブランチへ取り込んでブランチ側で解き、PR を衝突の無い状態にする。

### 条件付きの仕様と受入

仕様は、確かめ・検出・振り直し・マージの開始・種類ごとの解消・確かめの 6 つの手順と、上から順に当てる種類の表である。受入は、skill の写しの一致、読む表の行、振り直しの行のコミットの名指しのテスト、最初の適用（`feature/20261125-ppo` の取り込み）での番号の一意・道具が止まらないこと・衝突の印 0 件・経緯の日付の順・ビルドとテスト、報告の件数である。これらは暫定の既定を採った場合の試案で、再グリルで見直す。
