# 終了時の評価セッション排水

## 元の材料

[終了時の評価セッション排水](../../../memo/done/0076_eval_session_drain_on_exit_10rfd.md) blob:87f9be9a091c4e63c933b1ad83cb2571f7b449a8

## 要点

- 学習予算に達した時点で背景評価が進行中だと、完了前に破棄されて評価結果が欠けた。
- 通常終了時は新たな評価を増やさず、すでに始めた評価セッションの終わりを待つ。
- Observer の背景処理と MetricsLogger の寿命をそろえる。
- 評価完了のイベントと結果が出力されてから終了処理を進める。
- 進行中の評価がある場合とない場合で、結果と終了時の待ち合わせを確認する。

## 内容

### 学習予算の末尾で欠けていたもの

背景評価を起動した直後に学習が終了すると、評価の集計が確定する前にログの出力先が閉じ、終了行・scalar・trace が揃わない。実例では末尾の評価を取り直すために学習を無効にした Run を約25分実行した。予算末尾の方策を他の Run と比較するには、予定した全エピソードが完了した時点の結果が必要になる。

### スロットごとの終了方針

`run.eval_schedule.[tag].wait_on_exit` は既定で有効とし、終了時に実行中のセッションだけを待つ。不要なスロットは無効にして即時キャンセルできる。待ち時間にはすべてのスロットを通じた上限（既定3600秒）があり、超過したら残りをキャンセルして記録済みの出力を flush する。キャンセルしたセッションの一部だけを集計するとエピソード数の異なる点を混ぜるため、完了イベントは発行しない。

### Observer と出力先の寿命

Runner の終了では保存処理の後、Run ログと MetricsLogger を閉じる前に Notifier が各 Observer の停止・待ち合わせを行う。Runner の種類別に通知先を包む Observer も終了要求を実体に転送する。通常のウィンドウ終了を通らない経路にも同じ処理を置き、二度呼ばれても二重終了しないようにする。セッションを実際に待った場合のみ、その開始をログに残す。

### 受け入れ条件

予算末尾に開始した評価が完走した場合、終了ログ・scalar・エピソード数と一致する trace が残ることを確認する。即時キャンセルでは1ステップ以内で評価ループから戻り、キャンセルの記録を残す。実行中セッションがなければ待機を設けない。
