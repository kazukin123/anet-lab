# QValuePanel の Q 値と手動行動の対象状態

## 元の材料

[RFD0176　QValuePanel の Q 値と手動行動の対象状態](../../../memo/0176_qvaluepanel_manual_action_state_alignment_10rfd.md) blob:acff4f75d6a4ce7f2bad08c02091651cf5daa8c7

## 要点

- 表示でずれを明示するのは起草時の暫定案であり、先読みや二回のクリックと比べて決める。
- EvalPanel が待機しているとき、QValuePanel にある値は直前の判断に使った状態の Q である。
- その場で選んだ手動行動は既に進んだ次の状態へ働くため、表示された Q との間に1 step のずれがある。
- 暫定案は見出しに Q を評価した step を明示し、クリックが次の状態に適用されることを知らせる。
- 先に次の状態で推論して結果を再利用する案、クリックを確認と実行の二回にする案も比較する。
- 終端の画面と次のクリックが当たるリセット後の初期状態を区別する。初期状態をどう表示するかは未決である。

## 内容

### 目的と対象

手動で EvalPanel を進める研究者が、行動を選ぶ対象の状態と Q の関係をその場で判断できるようにする。Evaluation Trace の各行は元から状態と行動が対応する。学習側の強制行動は別の設計で扱う。

### 調査時の評価処理

EvalRunner は状態に対して行動を決定し、環境を一歩進めた後に通知する。QValuePanel は通知に入った行動決定時の Q、EvalPanel は環境が進んだ後の画面を表示する。次のクリックは新しい状態で決めた行動を上書きする。

### 表示と先読みの案

暫定案は Q を計算した step を見出しに出す。先読み案では通知後に次の状態を推論し、次回の実行で再利用する。推論回数は増えないが、探索の乱数を使う時点が移り、モデルを同期した場合の再計算も要る。二回のクリックで確認・確定する案は手動時に推論が一回増える。

### エピソードの切り替わり

自動リセットを含む Step は、終端の遷移の結果と、実行を続ける初期状態を別々に返す。終端の画面を通知して止めたとき、次のクリックが当たるのはリセット後の状態である。開始を知らせる通知を足すか、Step の戻り値から画面を作るかは判断を残した。
