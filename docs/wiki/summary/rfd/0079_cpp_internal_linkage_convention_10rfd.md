# RFD0079: .cpp の内部リンケージと namespace インデント規約

## 元の材料

[RFD0079: .cpp の内部リンケージと namespace インデント規約](../../../memo/0079_cpp_internal_linkage_convention_10rfd.md) blob:bb9e22910849cda29eac0bd5a19427880c5cbc92

## 要点

- .cpp 内だけで使う関数・定数・型のリンケージとインデントをそろえる。
- 調査では37ファイルに39個の無名 namespace があり、そのほとんどで中身をインデントしていなかった。
- ファイルローカルな関数は static、定数は namespace スコープの const または constexpr とする。
- 画面幅を使いながら、インデントがソースの実際の構造を表すことを重視する。
- 既存事例を分類し、プロジェクトの規約としてどの記法を使うかを明示する。

## 内容

### 読み手が区別できなかったスコープ

37ファイルにある39個の無名 namespace のほとんどで、中身がインデントされていなかった。最大のブロックはテストファイルの1,465行で、途中にあるヘルパー関数は離れた開始括弧まで戻らなければ内部リンケージかどうかを判断できない。一方、ヘッダーの名前付き namespace ではインデントしており、見た目とスコープの対応がファイルによって違っていた。

### 関数・定数・型ごとの記法

ファイルローカルな関数は宣言と定義に `static` を書く。namespace スコープの `const`・`constexpr` 定数には既定で内部リンケージがあり、追加の `static` は不要。型には同じ方法が使えないため、無名 namespace は型定義に限り、中身をインデントする。`TEST_CASE` はマクロが内部で必要な宣言を生成するので外に置く。名前付き namespace は意味を持つスコープとして維持し、中身をインデントする。

### 移行と判定

39ブロックのうち型を含まない20個は無名 namespace を外せる。型と関数が混在する場合は型だけを短いブロックに残す。前方宣言を持つ関数は定義と宣言のリンケージをそろえる。規約と既存例を同時に更新し、検出器で未インデントのブロック、関数やテストを含む無名 namespace と、規約に適合する反例を確認する。
