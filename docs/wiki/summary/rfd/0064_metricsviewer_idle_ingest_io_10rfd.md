# Metrics Viewer 定常取り込み I/O 抑制 PRD

## 元の材料

[Metrics Viewer 定常取り込み I/O 抑制 PRD](../../../memo/done/0064_metricsviewer_idle_ingest_io_10rfd.md) blob:6b86811c088a65d5fbd8bece8404d26f9c89890c

## 要点

- Metrics Viewer は未接続時も Run を定期走査し、変更のない入力と SQLite キャッシュを検証し直していた。
- 完全検証済みの Run とファイル属性を、現在の Viewer プロセスのメモリに保持する。
- 確定した ready または error の Run は、属性に変化がなければ再読込の前で戻る。
- 属性変更や Run の消失、workspace 切替、プロセス再起動では完全な検証へ戻る。
- 未処理データの残る変換だけを直ちに再試行し、定常時のディスクアクセスを抑える。

## 内容

### 無変更 Run への再アクセス

Viewer はブラウザを接続していないときも約10秒ごとに Run を調べる。原本が増えていない Run でも、従来はマスタの先頭と確定済み末尾をそれぞれ最大64 KiB読んで照合し、SQLite に接続して同じ状態を書き込んでいた。同じ1件の Run を1周期の最大4枠で繰り返し調べる場合もあった。

### 属性だけで終了できる条件

完全検証を済ませた `ready` または `error` の Run について、選んだ原本のパス・種別・サイズ・更新時刻と、キャッシュ本体の存在・サイズ・更新時刻をメモリに保持する。前回と一致すればファイル本文や SQLite には触れずに戻る。短命な SQLite 接続が作る WAL・SHM は比較対象にしない。属性が変わったとき、Run が消えたとき、workspace を切り替えたとき、プロセスを再起動したときは完全検証へ戻る。

### 再試行と受け入れ

1周期の中ですでに処理するものが尽きた Run は再検査せず、未処理データの残る変換だけを直ちに続ける。優先・通常のどちらの Run にも残作業があれば処理枠を3対1に配る。少量を取り込んでも、その時点の末尾に達していれば確認だけのための即時再試行は要らない。

測定では原本・ブラウザ要求を固定し、完成した Run に対する原本の読み出しや DB 書き込みが発生しないことを調べる。DB 本体のサイズ・更新時刻が変われば失敗とし、属性が変わっている最中には検証済みとして記録しない。
