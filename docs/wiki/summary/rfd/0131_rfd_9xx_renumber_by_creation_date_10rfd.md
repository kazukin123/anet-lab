# 9xx の RFD を起票順の連番へ移す

## 元の材料

[RFD0131　9xx の RFD を起票順の連番へ移す](../../../memo/0131_rfd_9xx_renumber_by_creation_date_10rfd.md) blob:4fd011fb31f027c48805c13304b0b14224d0d45b

## 要点

- 900番台に仮置きされた RFD が通常の番号列から離れ、新しい資料を番号順に探しにくかった。
- 直下と保管先を含む57本を、実装開始時の最大番号に続く起票日順の番号へ移す。
- 番号の後ろの名前とフォルダは保ち、対応する実装計画も同じ番号にする。
- 旧番号は各 RFD の宣言から読めるようにし、過去のコミット件名からも追跡する。
- 現用の参照・道具・規約を改め、振り直し後は900番台も通常の番号として使用できるようにする。

## 内容

### 問題・ゴール・非ゴール

番号が 1000 に届いたときの 4 桁の形。先送りする。

### 起草時点の現状

数は、出力を切らずに引いた検索の結果である。
課題の検査は、`rfd` 欄が直下に実在する RFD を指すことを求める（wiki_support.py:315）。`rfd` で 9xx の RFD を指す課題は 51 件で、直下の 49 本をすべて覆う。状態は未着手 45・調査中 3・対応中 1・解決 2。
ADR のうち、9xx の RFD のファイル名をリンクに持つのは 3 本で、どれも RFD0938 へのリンク 1 個である（ADR 0031 の 4 行（先頭の注記）、ADR 0055 の 3 行（先頭の注記）、ADR 0072 の 3 行（本文））。
9xx の RFD に結び付いた課題の状態から、いま実装の途中の RFD は 925（課題 23d185 が対応中）である。938・944・081 は調査中で、`episode_end_test.cpp`・`trainer_test.cpp` を触る予定を持つ。

### 確定事項

振り直すのは 9xx の番号の RFD 57 本すべて（直下 49 本、保管場所 8 本）と、918 の実装計画 1 本である。フォルダは動かさず、先頭の 3 桁だけを変え、番号のあとの名前は変えない。実装計画は RFD と同じ新しい番号にする。
番号が 1000 に届いたときの 4 桁の形（ファイル名の検査 `^\d{3}_`、道具の `RFD(\d{3})`）は、本 RFD では扱わない。

### 実装契約

`.agents/skills/` と `.claude/skills/` に写しがあるファイルは、両方を同じに直す。
`<旧>`・`<新>`・`<nnn>` は 3 桁の数字。RFD0114 の既にある行（``）も、この形に当たる。
当てた RFD は、今と同じ行の形（文字が `RFD<今の番号>` で今のパスへのリンク、続けて ` — <今の題>`）の 1 行で載せる。同じ RFD に当たった番号が複数あっても 1 行にまとめ、今の番号の順に並べる。

### 受入

`--list-tests "[rfd<918 の新しい番号>-config]"` で、隠したテストが 1 件見える。
memo README の「リンクの注意」の検査を、`find docs` を `find docs reports` に替えて回し（`reports/` のレポートが改名した RFD を指すリンクも見るため）、実装を始める前の結果と比べて、リンク切れが増えていない（増えた分 0 件）。始める前の結果は実装計画に残す。
110_runner_app・316_config・318_rl_core の「RFD の一覧」に、918 の新しい番号の行がある。
`wiki_support.py scan` の `pending` と `moved` に、それらの材料のどれも出ない。

### 成功の測り方

実装のあとの最初の wiki の点検で、`unresolved_rfds` に 9xx の番号が出ない。RFD0918 を指していた 3 ページの行が、新しい番号で開ける。
