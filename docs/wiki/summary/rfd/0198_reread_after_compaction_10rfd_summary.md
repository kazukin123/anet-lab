# 会話要約後の工程手順の読み直し

## 元の材料

[RFD0198　会話要約後の工程手順の読み直し](../../../memo/0198_reread_after_compaction_10rfd.md) blob:bb6963fffea560f48591497eb45771b20287c4cc

## 要点

- 長い工程の途中で会話が要約され、続く工程の手順を読み直さずに同じ種類の差し戻しを繰り返した例があった。
- 要約直後に hook で読み直しを促し、必要な工程手順、作業記録、まとめページの所在を示す。
- 要約後も同じ実行の続きとして、現物と記録から直前の判断・次の作業を復元する。
- Claude Code と Codex の要約後に残る情報の違いを考慮して開始条件を定める。
- 関連資料を全部無条件に読ませず、その工程に必要なものへ戻れるかを確認する。

## 内容

### 目的と問題

会話が要約された直後に、読み直しを促す文を自動で差し込む。Claude Code と Codex の両方で行う。
その文で、続けている工程の skill の今いる段の手順と、作業記録（RFD づくりでは RFD 本文、実装では実装計画）を読み直させる。
続行中のまとめページがある会話での読み方を決める（要約のあとと、新しい会話で続けるとき）。
題材の課題 issue-20261119-25e4d0 が片付く。

### 起草時点の現状

試しの hook は SessionStart だけを、前と同じ場所に一時的に置いた（試しのあとに外した）。しきい値はターミナルで起動するときだけ渡し、ほかの会話に効かないようにした。Claude Code は `CLAUDE_CODE_AUTO_COMPACT_WINDOW=90000` の環境変数で `claude` を、Codex は `codex -c model_auto_compact_token_limit=80000` を起動した。
開発者が、どちらにも同じ依頼（3 つの大きなファイルを、この順に Read で最後まで読み、1 つごとに一言書く）を出した。

### 確定事項

要約のあとに残る skill の本文は全部とは限らないこと（Claude Code は先頭 2 万文字まで）。

### 仕様

目印の面の値は、`claude` の引数に「Claude Code」、`codex` の引数に「Codex」を当てる。面の欄が無い目印は、どちらの面でも候補に入れない。

### 実装契約

なし（Python のスクリプトとテストを足すだけで、C++ のクラスを足さない・変えない・消さない）。
wiki の 311 開発ツールのトピック別まとめ は、この RFD の起草で書き戻す（実装では直さない）。
この RFD は、ファイルやフォルダを移す・改名する・分ける・消すことをしない。位置に依る計算、旧いパスを書くファイル、移る先が無いリンクは当たらない。
