# RFD0208: 作業の中で分かったことを残す（reports を作った流れで分けた置き場、wiki の種類「ハーネス」、サマリの名前）RFD

## 元の材料

[RFD0208 作業の中で分かったことを残す](../../../memo/0208_work_notes_harness_kind_summary_names_10rfd.md) blob:b70e265f5ce58e52257b0c6b00de25109f4da7c0

## 要点

- Run・コード・外の調べもののどれでもない、作業の中で分かったこと（道具の振る舞いや費用の実測、作業の進め方の効き目）を書く正本が無く、会話の書く先の表で「記録しない」に落ちるか、Claude Code の memory に残っていた。
- `reports/` の下を、記録を作った流れでフォルダに分ける。survey スキルの出力は `reports/survey/`、paper-details の出力は `reports/paper/`、作業の中で分かったこと（作業ノート）は `reports/notes/` に置き、直下には索引だけを置く。今の直下の 54 本を移す。
- 作業の中で survey スキルを使わずに調べた外の事例も、RFD づくりを含めて作業ノートに書く。書く先の表に作業ノートの行を足し、事例を引く順に作業ノートの索引を足す。
- 汎用の survey と paper-details の skill は、anet の決まりの出力先に書き、置き場に当たらない Markdown は `scan` が警告に挙げる。
- wiki の概念のページに、分野で分ける種類「ハーネス」（`concepts/harness/`）を足す。答える問いで分けた 4 種は残す（ADR 0100）。
- 311 のトピック別まとめの範囲に、AGENTS.md・skill・`docs/process`・`docs/quality` などのハーネスのファイルを足す（`.claude/skills/` の写しは除く）。
- 課題の rfd 欄の名前だけのリンクが RFD とサマリの 2 つに当たる件は、サマリの名前に `_summary` を足して重なりを無くし、rfd 欄は今のままにする。
- 移動と改名で中身の変わる材料（見込み 68 本）は、取り込み直す。

## 内容

### 目的と範囲

問題は 5 つで、作業の中で分かったことの正本が無いこと、作業の中で調べた事例を書く決まりがはっきりしないこと、ハーネスの知見の載せ先が無いこと、`reports/` 直下に流れの違う記録が混ざること、rfd 欄のリンクが 2 つのファイルに当たることである。ゴールは、見聞きを両方の面から読める正本に残して wiki から引けること、調べた事例が正本に残って次に先に見つかること、ハーネスの知見の載せ先が決まって取り込みで載ること、rfd 欄のリンクが RFD の 1 つだけを指すことで、題材の課題 2 件を 1 本の RFD の 2 つの部として扱う。memory の知見を移す作業（RFD0112）、RFD0202 の指標の判定の決まり、RFD0203 の YAML ヘッダのキーの組、Obsidian の手元の設定、汎用の skill そのものの決まりは範囲に入れない。

### 現状

`reports/` 直下の 54 本は、サーベイ 43、論文解説 9、公開実装のコード読解 1、anet の道具の調査 1 で、作った道具はファイルから決めきれない（survey の様式は 25 本）。下のフォルダは作業資材である。直下の報告をファイル名で指すファイルは 136 本、パスで指すファイルは 140 本で、30 本の報告が中に相対リンクを持つ。書く先の表は 8 行で、Run でもコードでもない見聞きの行が無い。知見の種類にハーネスの置き場は無く、311 の範囲は道具・テスト・CI だけで、足すハーネスのファイル 88 本はどの分類にも当たっていない。rfd 欄は 182 件が名前だけのリンクで、RFD と同じ名前のサマリが 204 本ある。開発者が Obsidian で確かめると、今は RFD が開き、バックリンクも RFD に付いたが、選び方は文書に無い。survey と paper-details の skill は、自分の決まりで `reports/` 直下に書き出す。移動とサマリの改名で中身が変わる材料は 68 本で、変わるのはリンクのパスだけだが、今の点検は取り込み直しの対象に挙げる。

### 決定

置き場は開発者の選択で、`docs/` の下は GitHub Pages で配信する公開文書なので `reports/` にし、流れでフォルダに分けた（AI は `docs/` の下の新しい置き場を推した）。フォルダ名は `notes`（呼び名は作業ノート）で、`observations`・`findings`・`worklog` は既にある語と紛れる。論文解説は `paper/` に分けた。作業の中の外の調べものを作業ノートに書くのは、`survey/` を survey スキルの出力だけにする線引きによる。ハーネスの種類は開発者の選択で、AI は今の 4 種で分けて目録に小見出しを置く案を推した。311 の範囲を広げるのも開発者の選択で、AI は今の範囲でほぼ載っていることから広げない案を推した。rfd 欄は、サマリの改名で RFD0120 の前提（名前は一意）が成り立ち直るので変えない。根からのパスにする案は、Obsidian で選び直すと名前だけが書かれる見込みで、形が混ざる。取り込み直しは開発者の選択で、AI は、リンクの丸括弧の中だけが変わったことを記録する新しい種別を推した。聞かずに決まったこととして、書く先の表の行 5 の送り先と作業ノートの行、材料の集合、anet-survey-queue の出力先、トピック別まとめの「外の事例」の材料に作業ノートを足すこと、今使っている文書の旧いパスはリンクの丸括弧の外も直し、過去の記録は丸括弧の中だけを直し、作業の記録の過去の行は直さないこと、新しい語は wiki の規約で定めることがある。

### 細部

54 本は `_paper_` の 9 本を `paper/`、Viewer の調査を `notes/`、残る 44 本を `survey/` へ移す（作った道具を決められない今の報告は、過去の記録として `survey/` にまとめる）。索引は `reports/INDEX.md` に残し、作業ノートの索引 `reports/notes/INDEX.md` を置く。作業ノートは題ごとに 1 本で日付を名前に付けず、確かめた日・手段・分かったこと・出典を項目に書き、YAML ヘッダは付けない。サマリの名前は拡張子の前に `_summary` を足し、報告のサマリは `summary/reports/<フォルダ>/` に置いて `material_kind` を流れごとに分ける。ハーネスのページは知見のページの 7 節で、目録の見出しは現象の次に置き、主のページは主張の主語で決め、主語に AI のエージェント、ハーネスのファイル、ほかのソフトウェア（`src/` と `apps/` が組み込むか起動するもの（LibTorch・ALE・Runner・Metrics Viewer・`apps/` の bat など）のほかの、すべてのソフトウェア）のどれかが入ればハーネスを主にし、そうでなければ今の 4 種で決める（この線はレビューのあとに開発者が選んだ）。311 には 9 個の正規表現を足す。置き場の警告は、直下と 3 つのフォルダの下のフォルダの Markdown を挙げる。出力先の決まりは AGENTS.md に 1 行置き、anet-create-rfd と anet-improve に作業ノートの決まりを書き添える。RFD0202 の指標を測る期間にも実装してよい。

### 実装と受入

移すもの、改名するもの、道具・規約・skill・設計文書の移行対象を挙げ、ほかの RFD（RFD0202・0112・0199・0157・0204・0187）との順序を書いた。置き場を変えるときの扱いは、位置に依る計算、旧いパスを書くファイルの線引き（課題・検証資材・生成物・英訳・過去の記録・Git の設定）、人が作り直すもの、消すものの 4 つで書いた。受入は、直下が索引だけになること、54 本の中身がリンクの丸括弧の中のほかは同じであること、リンク切れと旧いパスが残らないこと、サマリの名前と RFD の名前の重なり、取り込み漏れ 0、警告と種類のテスト、311 の範囲、規約と skill の文面、ADR、rfd 欄が変わらないこと、Obsidian での人の確かめである。取り込み直しは実装の中で行い、未決は無い。
