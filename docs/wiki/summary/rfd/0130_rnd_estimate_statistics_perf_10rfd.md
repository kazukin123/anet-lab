# RND 採点時の統計更新と計測

## 元の材料

[RFD0130　RND 採点時の統計更新と計測](../../../memo/0130_rnd_estimate_statistics_perf_10rfd.md) blob:23740a47c6538c1e73a3ded61f109f6c39702845

## 要点

- Atari の比較では RND 有効時の実時間は無効時の1.661倍で、RND 時間の62.66%を採点時の統計区間が占めた。
- 内訳を分けて測ると、観測統計を更新する際のバッチ方向の平均と分散の集計が主な負荷だった。
- whiten と variance_feedback の違いを型で分け、採点と補助学習に共通する処理をそろえる。
- 統計区間の処理を追跡できる計測を置き、最適化対象を実測で選ぶ。
- 単独の高速化に加え、採点値と保存・復元時の統計の一致を確かめる。

## 内容

### 目的と問題

既定の RND（`statistics_mode = whiten`）を有効にした Atari の Run は、RND なしの 1.661 倍の実時間がかかる。RND の時間の 62.66% は、採点（`Estimate`）の中の統計の区間が占める。この区間は CPU の 1 スレッドで動く。放っておくと、RND を使う実験（Montezuma の β の比較、価値の分解、RFD0173 の NGU）の 1 本ごとの実時間が、この分だけ長いままになる。
Tracy で、採点の統計の区間に、捨てている正規化の区間が出ない。
整理のあと、`RndNoveltyEstimator` の中で、統計方式によって分かれる箇所が、構築時に型を選ぶ 1 か所だけになる。

### 起草時点の現状

出典は Atari の RND 性能測定（条件と比較方法、通常比較の結果、Tracy による内訳）。Montezuma、64 lane、CUDA、Release で、RND なし・既定 RND・Taiga 設定を各 6 本、順を入れ替えて 3 巡した。
kernel は 387,563 個で、合計 3.705 秒だった。kernel が動く時間の割合は、最大でも 37.1% である（kernel の合計を、最初の kernel から最後の kernel までの時間で割った値。重なりを数えるので上限）。
見積もり: 主の構成では、500 learn step は 125 intake（16,000 経験）である。RND ありの 1 intake を 118 ms とすると、14.75 秒ごとに約 2.3 秒が足され、実時間の約 13% に当たる。30M 経験では 1,875 回で、約 1.2 時間になる。
1 intake の長さは、学習用のスレッドの時間で決まる。Env を進める時間は学習の時間より短く、学習と重なる。RND の時間は、1 intake の長さにそのまま足される。GPU への処理は学習用のスレッドが出すので、RND の CPU の計算の間は、GPU の処理も出ない。

### 規約と過去の判断

課題 f9790d には、2026-11-14 の課題の整理での開発者の判断が記録されている。入れる時期は、RFD0121 の実装のあと、Montezuma で確かめの Run を回す前とする。0ddffa と束ねて 1 回で直す。Run は非決定論の設定で回しているので、RND を有効にした Run の学習の系列が変わることは問題にしない。確かめは、RND 無効の構成で学習の値が変わらないことと、速さの 3 巡とする。本 RFD の確定事項は、この記録を理由に引く。

### 確定事項と進め方

正規化は NN の外のままにする。 NN の中の前処理は変えない。RND 独自の型の変換（連続の byte の観測を浮動小数点へ変える処理）は残し、置き場だけが計算 device になる。
統計だけを更新する口。 共通の観測の正規化の部品に足し、RND の統計更新が使う。Q 入力用の正規化の 2 つの呼び出しは変えない。
平均と標準偏差の写し。 統計つきの正規化は、正規化に使う平均と標準偏差の写し（今の正規化が毎回作っているものと同じ値）を持つ。写しは、統計を更新した時点で、更新に使った入力の device に作る。正規化の入力の device が写しと違うときと、写しが無いとき（読み込みやリセットの直後）は、今と同じく、その場で作って使い、写しには書き込まない。読み込みとリセットで、写しを捨てる。統計を更新しない正規化（`Normalize`）は、写しを書き換えない。値は変えない。
clip の割合。 統計を更新しない正規化（`Normalize`）は、clip した割合を数えない。値は変えない。
