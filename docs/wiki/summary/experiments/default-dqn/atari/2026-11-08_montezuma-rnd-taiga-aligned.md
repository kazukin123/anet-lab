# Montezuma's Revenge の RND（Taiga ら寄せの構成、β と Munchausen）

## 元の材料

[Montezuma's Revenge の RND（Taiga ら寄せの構成、β と Munchausen）](../../../../../experiments/default-dqn/atari/2026-11-08_montezuma-rnd-taiga-aligned.md) blob:5364dbb12bdf0669108df20359f28d54c978527d

## 要点

- まとめ1で β と Munchausen を比べた5本では、β 0.01・Munchausen 無効の b001 と b001_s2 が Greedy で繰り返し2,500点に達した。後続の β 0.003 の b0003 でも、20.2〜29.2M に160ゲーム中100ゲームが2,500点だった。
- b001 の Greedy の 2500 点は、回ごとに 0/16〜16/16 で揺れた。
- 学習側の 2500 点は 6 本に出たが、続いたのは b001 と b001_s2 だった。
- b001_s2 の Greedy は、ほぼ全ゲームが 27,000 step の打ち切りで終わり、命が残っていた。
- 延長の 50M の重みを評価だけで流すと、30M の重みより点は低く、ε=0.01 の報酬は多かった。
- n-step を 10 にした n10・n10_s2 は、Greedy で剣で敵を倒すゲームが 16 本中 8 本以上になった最初の回が 12.2M・14.2M で、g99ne_rr4 の 2 本（26.2M・18.2M）と RR8 の g99ne の 2 本（18.2M・18.2M）より早かった。
- n10（seed 1）から RND の predictor の学び方だけを変えた 2 本は、Greedy で剣で敵を倒すゲームが 16 本中 8 本以上になった最初の回が、補助学習を rollout で 4 倍にした reuse4 で 10.2M、学習率を 3e-4 にした lr3e4 で 11.2M だった（n10 は 12.2M）。
- lr3e4 は、学習側で部屋 7 より先へ入るゲームが 16〜20M に 17%、28〜30M に 56% になり（n10 は 0〜9%、reuse4 は 2〜26%）、Greedy の最後の 5 回は 80 本中 41 本が部屋 7 より先まで行った（部屋 14 の 2600 点が主。n10 は 0 本、reuse4 は 14 本）。

## 内容

### 目的と比較条件

共通の構成: サンプル効率優先のチェーンに、Taiga ら寄せの Q 側（replay ratio 8、target の hard update 250 learn step、PER α 0.5・β 0.5）と、RND の補助学習（`learn_ratio` 1、`learn_batch_size` 128）を足した。BTR の NN（Impala の conv の初期値は既定）、128 env、replay 2,097,152、γ 0.997、n-step 3、IQN（τ 32 本）、学習率 1e-4、replay batch 256。sticky 0.25、打ち切り 108,000 フレーム、ライフ区切りなし。予算 30M（exp step）、seed 1（略称が `_s2` で終わる Run は seed 2）。Taiga ら寄せの基準の 2 本（rbw_tg・rbw_tg_s2）は、この共通の構成を使わない（下の群の表）。

得点: 鍵 100、扉 300、剣 100、剣で敵を倒す 2,000。400 点は鍵と扉 1 枚、500 点はそれに剣、2500 点はそれに剣での撃破（下の「Run 以外の確認」）。r123 では、倒すと 3,000 点の敵（EvalPanel では部屋 13 の蜘蛛）と、2 本目・3 本目の鍵（100 点ずつ）も入った（探索ブロック11・12）。部屋は RAM の指標 1（`room_max`、そのゲームで入った部屋番号の最大。開始の部屋は 1、その左は 0）。

### 探索ブロック02: Greedy（`53_evalg` / `54_evalgs`）

tr40k の Greedy（`53_evalg`）は、12.2M 250.0、13.2M 412.5（500 点 10）、14.2M 325.0、15.2M 175.0、16.2M 400.0、17.2M 400.0 だった。

18.2M と 19.2M の `53_evalg` は 600 点（500 点に部屋 7 の鍵 100）が 12 本ずつだった。

### 探索ブロック03: ε=0.01（`52_eval2`）

g99ne の 4 本の 20.21〜28.21M（50 ゲーム）の点は、g99ne が 3700 点 19・3600 点 29・3500 点 1・500 点 1、g99ne_s2 が 3600 点 39・3500 点 10・500 点 1、g99ne_split_s2 が 6600 点 8（28.21M、8 本とも部屋 23）・3600 点 16・3500 点 21・500 点 2・400 点 3、g99ne_cap4m が 3600 点 28・3500 点 2・500 点 20（20.21M と 22.21M は 10 本とも 500 点・部屋 7）だった。g99ne の 4 本の 14 回の平均報酬は、点からの対応（探索ブロック20 の「最後の 10M の報酬」）で数えた値が、どれも Run の記録（`21_eval/02_policy_reward`）と一致した。

### 探索ブロック04: 学習側の 2500 点（2M 窓）

終わったゲームの数と、そのうち 2500 点以上の本数（ログの Game 行）。

r123 と r123_s2 は 2500 点以上の本数。r123 は 8〜10M に 96 本中 43 本だった（それより前は 0 本）。r123_s2 は 10M より前は 0 本。b0003 は `42_env` の trace から数えた。10M より前は 0 本。

### 探索ブロック05: 扉の向き（b01・b001）

400 点以上の学習側のゲームを、左の扉（`room_max` 1）と右の扉（`room_max` 2 以上）で数えた（1M 窓）。

b01 は左の扉の間（2〜5M）、400 点より上のゲームが無かった。12M 台以降の b01 の左の扉は 1M 窓あたり 0〜7 本。

### 探索ブロック06: b001 の 2500 点のあと

2026-11-10 11:35〜11:53 に Training を止め、EvalPanel で b001 の重み（29.71M 前後）を見た。

2500 点を取ったあと、部屋 1 の開始の足場で UP を押し続け、27,000 step の打ち切りまで動かなかった（lives 1）。

### 探索ブロック07: 可塑性の probe

learn step 15 万ごとの窓の平均（`34_agent_plasticity`）。30M は learn step 約 94 万。

### 探索ブロック08: Taiga らの式の RND

taiga_nmdd（Munchausen 無効・Double DQN 有効）。 学習側の 1〜2M 台の終わったゲームは 1,494 本で、鍵は 1.19M と 2M 台に計 3 本だった。

Q の最大の平均は 0.5M 窓で 0.005〜0.012、最大は 2.0M 台に 0.076 で、2.5M 台は 0.009 だった。内的報酬の平均は −3.1e-06 から −1.5e-05。

### 探索ブロック09: rnd_b001（β 0.01・Munchausen 有効）

学習側の終わったゲームのうち、打ち切りで終わった本数（打ち切り / 終わったゲーム、ログの Game 行）。

Greedy（`53_evalg`）は 1.2〜29.2M の 29 回すべてで、16 ゲームとも打ち切りで終わった。20.2〜29.2M の終わったときの lives の平均（`30_lives_mean`）は 2.13〜3.44（b001 は 2.00〜4.00）。

### 探索ブロック10: b001_s2（seed 2）

ep_step 92（100 点、lives 6）の Q は 18 行動とも 2.692〜2.698 で、UPFIRE（2.698）を押した。ep_step 88〜97 はおもに UPFIRE で、ep_step 95 に lives 5 になった。ep_step 246 に 500 点（扉と剣）になった。

ep_step 955（部屋 1、lives 4）の Q は 0.133〜0.146。ep_step 1,238〜1,272（部屋 1、lives 2）は DOWN を押し続け、Q は 0.105〜0.107 だった。そのまま episode が終わった。

### 探索ブロック11: r123（PRD123 の RND の既定）

8〜14M の 2500 点以上の 88 本は、2500 点 87・2600 点 1 で、`room_max` は 7 が 50、6 が 38。14〜20M の 2,148 本は、500 点 1,535・600 点 429・400 点 163・2500 点以上 8 だった。

b001 の値（探索ブロック06・10）と比べると、内的報酬の平均は 2.3〜14 倍（0〜4M が 14 倍、20〜24M が 2.3 倍）、誤差の標準偏差は 0〜4M が 0.098 倍、4M 以降が 0.33〜0.40 倍だった。

### 探索ブロック12: r123 の 30M の重みの評価だけ

どのゲームも、点は 鍵 100 × `key_get`、扉 300 × `door_open`、剣 100 × `sword_get`、倒した敵（2,000 か 3,000）× `sword_kill` の和と一致した（ログの Game 行。数えた 32 本のほかに同じ session で終わったゲームを含む）。`sword_get`・`sword_kill`・`door_open` は全ゲームで 1。

`room_max` 7 の 2600 点は鍵 2 本（`key_get` 2）だった。3500〜3700 点のゲームはどれも `room_max` 14 で、倒した敵が 3,000 点だった（2700 点のゲームも `room_max` 14 だが、倒した敵は 2,000 点で鍵が 3 本）。ゲームオーバーで終わったゲームは `lives_lost` が 5。

### 探索ブロック13: r123_s2（r123 の seed 2）

r123（探索ブロック11）と比べると、誤差の標準偏差は 0〜4M が 0.68 倍、4M 以降が 0.33〜0.45 倍、内的報酬の平均は 0.6〜2.8 倍だった。

### 探索ブロック14: r123 の延長（通算 30M→50M）

`52_eval2` の平均報酬は Run が記録した値（`21_eval/02_policy_reward`）。点からの対応で数えた値と 9 回とも一致した。

### 探索ブロック15: 延長の 50M の重みの評価だけ

3,000 点の敵を倒したゲームは 32 本中 0 本（30M は `53_evalg` 4 本・`52_eval2` 3 本）。2700 点のゲームは鍵 3 本（`key_get` 3）だった。

### 探索ブロック16: 延長の 50M の重みの EvalPanel

内的報酬の列（`intrinsic.bonus`）は全行が空欄だった。評価だけの Run では学習の入口を通らないので、β が無い（PRD127 の D7）。

### 探索ブロック17: b0003（r123 の β を 0.003 に）

学習側の最高は 2500 点で、`room_max` の最大は 7、入った部屋の数（`rooms_visited`）の最大は 5 だった。r123 は 18〜20M に `room_max` 13 以上のゲームが初めて出て、30M までに 687 本だった（探索ブロック11）。

### 探索ブロック18: vd（r123 に価値の分解を足す）

学習側の最高は 2500 点で、`room_max` の最大は 7、入った部屋の数の最大は 5 だった。2500 点の 15 本は、14 本が `room_max` 7、1 本が 6。

### 探索ブロック19: vd の 30M の重みの評価だけ（Greedy の β 0）

`53_evalg` の 16 本は、入った部屋の数（`rooms_visited`）がどれも 1 だった。400 点の 8 本は扉を開けていて（`door_open` 1）、そのうち 2 本はゲームオーバー（301 step・367 step、命を 5 つ失う）で終わった。0 点の 3 本は鍵を取っておらず、100 点の 5 本は扉を開けていない。

### 探索ブロック20: g99ne_split（vd の内的の割引率を分けて切らず、損失ごとに更新）

失った命の平均は、どの 2M 窓も 4.94〜5.00。1 ゲームの長さの平均（4M 窓）は、g99ne_split が 580〜2,737 step、vd が 772〜16,611、r123 が 849〜16,546、r123_s2 が 1,601〜14,078 だった。

### 探索ブロック21: g99ne（損失を合わせて更新）、seed 2、replay の容量（g99ne・g99ne_s2・g99ne_split_s2・g99ne_cap4m）

学習側で 3500 点以上のゲームが初めて出たのは、g99ne 13.77M、g99ne_s2 15.56M、g99ne_split_s2 19.31M、g99ne_cap4m 15.86M（g99ne_split は 18.61M）。4 本とも `room_max` の最大は 23、入った部屋の数の最大は 10 だった。

### 探索ブロック22: Taiga ら寄せの基準（rbw_tg・rbw_tg_s2）

学習側の 100 点以上のゲームは、rbw_tg が 0.03〜5.10M に 11 本（400 点は 4.73M と 5.10M）。rbw_tg_s2 は 0.24〜4.81M に 16 本（400 点は 3.27M と 3.66M）、13.49〜18.79M に 32 本（400 点は 16.83M と 17.42M）で、4.81〜13.49M の間は 0 本だった。

### 探索ブロック23: replay ratio 4（g99ne_rr4・g99ne_rr4_s2）と n-step 10（n10・n10_s2）

節目。 Greedy の「半数」は 16 本中 8 本以上。「保持」は、倒すゲームが初めて半数になった回から後で、半数以上だった回の数。学習側の 1M 窓は終わったゲームが 50 本以上の窓だけ数え、立ち上がりは、倒すゲームが 1 割以上で、そのあとの窓（100 本以上）で 1 割を割らない最初の窓。

### 探索ブロック24: 剣を使った相手と、seed による RND の大きさ（g99ne の 9 本）

24〜30M に 3500 点以上が 6 割以上だった 5 本は、部屋 2 の敵を倒したゲームが 4〜332 本、2500〜2700 点が 5 割以上だった 4 本は 934〜8,261 本だった。g99ne は 9.19〜13.77M に部屋 2 の敵を倒したあと、3500 点以上へ移った。

### 探索ブロック25: RND の predictor の学び方（reuse4・lr3e4、PRD191）

lr3e4 の 20.2〜29.2M に `room_max` が 7 より大きかった Greedy の 72 本は、2600 点・部屋 14 が 33 本、2500 点・部屋 21 が 15 本で、3,000 点の敵を倒したゲームは無かった。26.2M の 16 本は 400 点・部屋 6 が 13 本だった。

### Run 以外の確認（ALE、sticky 0、frame_skip 1）

ale_py 0.12.0 で状態の保存と復元を使い、RAM と得点を 1 フレームずつ確かめた（2026-11-06・11-09）。

### 比較の目安（文献）

Taiga ら（ICLR 2020、arXiv 2109.11052）の Rainbow＋RND は、Montezuma の 5 seed すべてが 90M フレームまでに 4,400 点を超えた（図 7 を目で読んだ値）。NoisyNets の 5 seed は 35〜40M フレームから 200M フレームまで 2500 点だった。表 5 の 200M フレームの値は RND 5,199、ε-greedy 780。本記録の 30M exp step は 120M フレーム、延長の通算 50M は 200M フレーム。
