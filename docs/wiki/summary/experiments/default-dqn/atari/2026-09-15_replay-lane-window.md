## 要点

- 保つべき不変量は `replay_capacity / num_envs`（以下 lane 窓）である。
- 効き方は閾値的で、貪欲エピソード長との比で決まる。
- ε=0 のブレ幅は 2 種類ある。 eval プロトコル自体（同一スナップショットを 2 回）は今回 2.12 点、 `≥600` は完全一致。ただし 2026-09-01 探索ブロック 30 の 4 対では 9.5〜16.2 点で、水準が上がるほど広い。学習 Run どうしの複製幅は ε=0 で 18.7 点（同記録）。
- eval のコストは `replay_ratio` で regime が変わる。
- lane 窓は 16,384 が飽和点ではない。
- 2026-09-20 に検出した RB の観測履歴不整合は、lane 窓の効果を説明しない。

## 内容

### 探索ブロック 01: `num_envs` 128 の断面

学習中 eval（ε=0.01）を、既存の envs64 複製 2 本（r1 / r2）の両方と並べる。

5 窓平均は −4.7 で複製幅 6.7 の内側、5 窓中 2 窓はプラス。 学習中 eval では差が立たない。

−69.4。 ε=0.01 の −4.8 の 14 倍。`≥600` は 0.62 → 0.45 で 17pp 落ちている。

envs128 は同じ ε=0.01 水準に到達しているのに、貪欲化で伸びない。

### 探索ブロック 02: lane 窓の確定

685.12 対 685.30、差 0.18 点。 ε=0 の学習 Run 複製幅 18.7（探索ブロック 03）の 1/100 で、 区別がつかない。`≥432` は 0.82 で完全一致、`≥600` は 0.62 対 0.64 で複製幅の内側。 −69.4 は同じ物差しの 3.7 倍である。

追従する 3 量は代数的に同じもの（`L` を固定すれば lane 窓の一次式）なので、 制御変数は lane 窓ひとつである。

「完全なエピソードが同居している更新数が多いほど良い」は否定された。 G1 と G2 は同居時間が更新数で 8,634 対 17,268 と 2 倍違うのに ε=0 は 685.12 対 685.30 で一致する。

遷移の総寿命も否定される。 G1 と B は総寿命が 16,384 更新で等しいのに −69.4 離れ、 G2 は G1 の 2 倍なのに一致する。

### 探索ブロック 03: ε=0 eval プロトコルの複製幅

この対は 2026-09-15 に bat の取り違えで偶然生じたもので、設定・スナップショットとも完全に同一である。

この対では 2.12 点。`≥600` は完全一致、`≥432` は 0.01。

`sticky actions`（`repeat_action_probability = 0.25`）があるので eval は決定的ではないが、 400 エピソードで平均すればこの幅に収まる。

エピソード長だけは幅が広い（679 = 10%）。長さ由来の議論は 2 桁目を読んではいけない。

### 探索ブロック 04: ε=0 断面の予算依存性

ε=0 断面は 50M でしか取っていなかった。20M のスナップショットが 4 本揃ったので、 同じ軸を 20M で測ると何が見えるかを確認する。SN 軸は 50M で −98.7 と分かっているので、 これが再現するかで 20M の感度が分かる。

SN を全部外した群が基準をわずかに上回る（+5.0）。 50M では同じ軸が −98.7 である。 20M の ε=0 断面は SN 軸に対して無感度であり、この予算では群の判定に使えない。

学習 Run 複製幅 18.7（探索ブロック 03）を当てると、基準に対する差は SN 12/15 −16.6・`actor_approx` −22.1・0/15 +5.0 で、内側 2 件・境界上 1 件。 4 群とも判定できていない。

SN の役割は「ε=0 を上げる」ではなく、長い訓練で貪欲変換が潰れるのを防ぐことである。 20M ではまだ潰れていないので差が出ない。

### 探索ブロック 05: eval の実時間コスト

スケジュールが要求する間隔より 1 セッションの所要時間の方が長いので、eval が止まらない。

瞬間レートは新しい Run の方が速い（5,980 対 5,060）。`run.@rfit` のコストは見えない。 落ちているのは eval に止められている区間だけである。

eval コストは RR で regime が変わる。 RR1 は env stepping が律速なので eval が半分以上を奪い、 RR4 は learner が律速なので 2 割で済む。上の「1:1 で奪う」は RR1 に固有の現象である。

### 探索ブロック 06: ゲーム別のエピソード長

lane 窓の要求量は貪欲エピソード長で決まるので、Breakout 以外での傾向を確認する。 `atari-5` workspace の 5 本（2026-08-27、いずれも 20M 到達。 `soft_update_tau` 誤設定キャンペーンのものだが、エピソード長の観測には使える）。

Breakout だけ裾が桁違いに長い。 他ゲームは最大が p95 の 1.2〜2.1 倍に収まるのに対し、 Breakout は p95 4,550 に対し最大 26,995（打ち切り上限）で 5.9 倍。

`num_envs = 128` / `capacity = 1M`（lane 窓 8,192）を Atari-5 に当てると、 breakout と name_this_game は lane 窓がエピソード長に対して 1〜2 本ぶんしかない。 他の 3 ゲームは 5〜12 本ぶんの余裕がある。

### 探索ブロック 07: lane 窓ラダーの拡張（4,096 / 12,288 / 32,768）

ε=0 断面（`53_evalg/10_game_score_mean`、背景実行 400 エピソード）。 seed 1 の cap2M のみ断面グリッドが 4.95M で、他は 5.05M。k 番目どうしで対にする。

32,768 − 16,384(2 seed 平均) の 9 点ペア平均は +42.4、SE 10.8（3.9σ）。

10M 窓 4 本平均は ε=0.01 で +17.2 ± 5.4、train EMA で +5.7 ± 0.7。

ev 終端（500 エピソード、最終スナップショット固定）でも 719.85 対 688.86 = +31.0 ± 7.2。 これは本キャンペーンで記録した ε=0 の最高値である。

### 探索ブロック 08: RB の観測履歴不整合が lane 窓の効果を説明するかの切り分け

内部指標も一致する（exp 50%–80%、括弧内は seed 複製幅で割った値）。

不具合が lane 窓の効果を説明していたなら、修正後は lane 16,384 の水準へ戻るはずで、 `52_eval2` の差は +40 前後になる。実測は −8.5 ± 6.2 で +40 から 7.8σ 離れる。 2σ 上限（+3.9）から、不具合の寄与は lane 効果の 10% 未満である。

全 workspace の走査で `bad_alloc` 停止は 9 本（Atari 4 本）あるが、 サイズとスタックが残っているのは診断導入後のこの 1 本だけである。
