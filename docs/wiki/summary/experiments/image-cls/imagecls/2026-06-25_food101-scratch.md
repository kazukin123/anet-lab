## 要点

- 到達点は ResNet18ish_hr＋cosine＋Mixup/CutMix の 86.0〜86.4% だった。
- Flatten → GAP2D だけを変えると、eval は 8.71M で 44.5 → 61.1% に上がった。
- 定数 LR・10M の Body の比較では、ResNet18ish_hr（最終の空間解像度 14×14）が peak 76.5%・final 71.9% で最も高かった。
- ConvNeXt では、stem の stride を 4 → 2（最終 7×7 → 14×14）にすると Atto の eval が 10M で 67.1 → 72.8% に上がった。
- Mixup/CutMix を入れて 20M に延ばすと、ResNet18ish_hr は 83.7 → 86.0%、Atto は 79.2 → 83.1% になった。
- BF16（learner だけ）の 20M は 86.4% で、FP32 の 20M（86.0%）より低くならなかった。
- Mixup を入れた ConvNeXt の 2 本は、Body の大きさを変えても 83.1% と 83.7% だった。

## 内容

### この文書の読み方

数値は Run の Metrics マスタから `inspect_run.py` で取得した。parameter 数は各 Run の `dot/net.detail.dot` のブロックごとの params の和である。

final は最後の eval の時点の EMA、peak は EMA の最大値とその exp step である。学習予算に届かずに止まった Run は、止まった exp step を添える。

### 探索ブロック 01: 過学習対策（データ拡張と GAP）

拡張を入れる前の基準の Run（値は PRD 030 の背景）は Run フォルダが残っておらず、この文書では値を確かめていない。

GAP にすると parameter は約 1/14 になり、eval は同じ 8.71M で 16.6pt 上がった。train の正解率も同じ step で 70.3 → 73.9% と上がったので、PRD 023 が挙げた「容量を削りすぎて train も eval も下がる」は起きなかった。

### 探索ブロック 02: Body の比較（定数 LR・10M）

同じ条件では ResNet18ish_hr が最も高かった。DropHead と droppath を入れた最終 14×14 の 3 本（hr、mr、Res18_do1）は peak 73.4〜77.1% で、7×7 の 3 本（67.0〜69.0%）を上回った。ただし 7×7 の Body は stem と parameter 数も違う。正則化の無い 14×14（Res18）は 69.6% だった。

幅を半分にした mr（parameter 約 1/4）は、hr より final で 1.6pt、peak で 3.1pt 低いだけだった。

### 探索ブロック 03: ConvNeXt の stem の stride と batch（定数 LR）

Femto の 20M 時点は 68.7%（20M までの peak 68.9%）、train 93.2%、実時間 4.21h。

Nano は ResNet18ish_hr と同じ条件で final 57.3%（hr 71.9%）、train 96.6% だった。peak が最後の点にあり、10M でもまだ上がっていた。

### 探索ブロック 04: LR の cosine（15M）

ResNet18ish_hr は 11.8pt 上がったが、batch と RRC も同時に変えたので、cosine の分を切り出せない。ブロック 03 の Atto では batch 256 → 128 が 10M で 1.4pt だった。

### 探索ブロック 05: Mixup/CutMix、学習予算、BF16

`target_prob_mix_norm` は、混ぜた 2 つのラベルに対する確率の重み付き和を、label smoothing を含めた理論上の上限で割った値である。`accuracy_either` は予測が混ぜた 2 つのラベルのどちらかに当たる割合、`pred_max_prob` は予測の最大確率の平均（定義は image_cls_agent.cpp の `UpdateFromBatch`）。
