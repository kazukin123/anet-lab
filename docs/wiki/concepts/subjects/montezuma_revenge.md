# Montezuma's Revenge

[anet-lab](../../../../README.md) › [wiki の目録](../../index.md) › [題材](../../index.md#題材)

## 今の結論

サンプル効率優先＋RND（β 0.1）の 30M、1 seed では、ε=0.01 の評価は 14.21M から鍵と扉で 400 点を繰り返した。Greedy の主評価は 20.4M まで全ゲーム 0 点。同じ重みの別評価では 20.4M に 16 ゲーム中 1 ゲームが 400 点だった。この Run には RND なしの対照がない。
高得点の経路、部屋 2 での停滞、打ち切りは、部屋番号だけでなく鍵・扉・敵撃破の記録と評価方策を合わせて読む。

## 分かっていること

### anet の知見

- RAM の番号付き定義は `1:room_max`（0x83 の最大）、`2:rooms_visited`（0x83 の種類数）、`3:key_get`（0xC1 の鍵のビット 30 の 0→1）、`4:sword_kill`（0xC1 の剣のビット 32 の 1→0）、`5:sword_get`（剣のビットの 0→1）、`6:door_open`（鍵のビットの 1→0）、`7:lives_lost`（0xBA の減少）。面の区切りもボスも無いので、1 には到達した最大の部屋番号を使い（開始の部屋は 1、開始の左の部屋は 0）、2〜6 は部屋と持ち物を追うのに使う。0xC1 は持ち物のビットで、鍵は 2、部屋 6 の剣は 32。グラフの tag は 1〜4 だけにあり、5〜7 は trace とログ行で読む（出典: [220_atari_env.jp.md](../../../design/220_atari_env.jp.md)、§4.9 RAM メトリクス）。
- 0xC1 の鍵と剣のビットは同時に 1 になりうる。部屋 7 で剣を持ったまま鍵を取ると 32 から 34 になった（ALE、sticky 0、1 フレームずつの探索で、Run ではない）（出典: [RFD0126](../../../memo/0126_atari_ram_metric_distinct_and_bit_reducers_10rfd.md)、§2.2）。ビットの畳み方はビットごとに数えるので、鍵と剣を同時に持っていても両方を数える（出典: [220_atari_env.jp.md](../../../design/220_atari_env.jp.md)、§4.9 RAM メトリクス）。
- 部屋番号の種類数だけでは左右の扉を見分けられない。左の扉から部屋 0 へ入ったゲームも、右の扉で部屋 2 へ入ったゲームも 2 になる（出典: [RFD0126](../../../memo/0126_atari_ram_metric_distinct_and_bit_reducers_10rfd.md)、§8）。
