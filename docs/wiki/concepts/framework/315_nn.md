# 315 ニューラルネットワーク

[anet-lab](../../../../README.md) › [wiki の目録](../../index.md) › [フレームワーク](../../index.md#フレームワーク)

## 概要・責務

- TensorDictから設定でNetworkを構築し、Bodyのbranch DAGとHead、forward、clone/sync、可視化の境界をまとめる。（出典: [ニューラルネットワーク](../../../design/130_neural_networks.jp.md)、§1.1・§2.1・§2.3）。
- NetworkはHeadの出力とBodyの公開特徴量を返し、bindのshapeと初期化・射影の設定はNNの共通処理で検証する。DQN固有Headの設定を読む責任はAgent側に置く（出典: [ニューラルネットワーク](../../../design/130_neural_networks.jp.md)、§2.1・§2.2・§6.1・§7）。
- NN Headは基盤の外で書ける拡張点で、`anet/nn_head.hpp`の実行器・初期化・汎用Headで`NetworkHead`・`NetworkHeadFactory`を実装し、`NetworkBuilder::BuildNetwork`のHead factoryに渡す。NN module（`NetworkModule`）は登録口が非公開のため、基盤の外では書けない（出典: [ANETフレームワーク全体概要](../../../design/010_framework_overview.jp.md)、§4.3）。
- structureに現れたblockは、module factoryが読み終えたあとに閉じたスキーマで読まれない設定キーを検査して構築時に止め、現れないblockとconfig profileは参照されたときにだけ検査する。重みの初期化の設定は`ConfigReader`が完全キーを欄ごとに記録して読み、`ValidateWeightInitConfig`が方式・`nonlinearity`・数値を検査する（出典: [ニューラルネットワーク](../../../design/130_neural_networks.jp.md)、§2.4・§7.1）。
- `InitNN`は標準のmoduleを`NetworkModuleRepository`へ1回だけ登録し、同じtype名を直接登録すると例外になって先の登録が残る。forwardの名前付き出力は`ForwardCapture`の鍵の要求で持ち帰り、nn_traceも要求したforwardでだけ作る。`Network`は共通の`Forwarder`としても呼べる（出典: [ニューラルネットワーク](../../../design/130_neural_networks.jp.md)、§4.1・§6.3・§7.6）。
- Networkの入力specは、Agentが作るspecの尺度とstack軸の宣言に従う。stack軸を持つ入力がbranchに届くのに先頭のmoduleがstack軸を扱う宣言を持たないときは、構築時にWARNを出す。`StackMerge`は`[B, S, C, H, W]`を受け、離散Gridの整形はspecのstack軸の属性で軸を見分けてクラスとstackをchannelへまとめる（出典: [ニューラルネットワーク](../../../design/130_neural_networks.jp.md)、§2.2；[Forwarder と Perception](../../../design/135_forwarder_and_perception.jp.md)、§2）。
- 出力の大きさで指定する max pooling（`AdaptiveMaxPool2d`）は登録していない。Atari の `AtariPool6` は `MaxPool2d`（kernel 2・stride 2・padding 1）で代える（出典: [ニューラルネットワーク](../../../design/130_neural_networks.jp.md)、§4.1）。

## 選ばなかった形

- IQN専用のNetworkクラスを設ける形 — 不採用: 既存のbind DAGと最小Headで表す（出典: [RFD0001](../../../memo/done/0001_iqn_10rfd.md)、目的）。
- 独立した公開NoisyLinearブロック型 — 不採用: 既存LinearとHead最終射影へ対応する形を採る（出典: [RFD0084](../../../memo/done/0084_noisynet_10rfd.md)、§4.1）。
- AMPの実行設定への集約とノイズ込み重みのSN — 範囲外: 精度は用途ごとに異なり、ノイズ込みSNの推定・保持・比較契約も別の暫定RFDで裁定する（出典: [RFD0084](../../../memo/done/0084_noisynet_10rfd.md)、§8.1・§8.2・§14.2）。
- Noisyの有無フラグ・機能登録・実行条件の汎用比較と独立実行基盤 — 不採用: 固有の解釈と検証を具象の計算部品へ閉じる（出典: [RFD0084](../../../memo/done/0084_noisynet_10rfd.md)、§4.2・§14.2）。
- εを引き直す総ノイズ測定と曲率を含む臨界batch測定 — 先送り: 追加forward・専用乱数やヘッセ行列との積が要る。再開条件: 分岐の結果が条件付き値の読みと食い違いNoisy probeのQ差が大きいとき、または単純版とBの効き目が食い違ったとき（出典: [RFD0092](../../../memo/done/0092_gradient_noise_scale_10rfd.md)、§8）。
- PPO/SAC・複数損失・別optimizer向けの拡張口 — 先送り: 単一損失・AdamWの現用途で完結させる。再開条件: 対象Learner・観測したい損失とoptimizerが具体化したとき（出典: [RFD0092](../../../memo/done/0092_gradient_noise_scale_10rfd.md)、§8 5・§10.2）。
- head単位統計とattention entropy最小値 — 先送り: 層平均で足りる間は公開値と保持データを増やさない。再開条件: 層平均が下がったRunで内訳が必要になったとき。最小値は6層構成で読みにくくなったとき（出典: [RFD0093](../../../memo/done/0093_attention_entropy_diagnostics_10rfd.md)、§5・§7）。
- TraceCallbackのcaptureへの統合 — 範囲外: 1関心2機構の痛みは未計測で、別の暫定RFDのゲートで扱う。再開条件: traceに要求フィルタが要るとき、または名前付き出力の3つ目の経路が要るとき。参照先999の前提は、093のNetworkForwardCaptureがコミット済みであること。（出典: [RFD0093](../../../memo/done/0093_attention_entropy_diagnostics_10rfd.md)、§5・§7）。 → RFD0170で採用（出典: [RFD0170](../../../memo/0170_nn_trace_capture_unification_10rfd.md)、§4 D5・D9）
- TQLのattention entropy正則化 — 先送り: anetでは本指標で集中の進行をまだ観測していない。再開条件: 層平均の集中と成績の頭打ち・下降が時期として重なったとき。因果は別途判断する（出典: [RFD0093](../../../memo/done/0093_attention_entropy_diagnostics_10rfd.md)、§7 1）。
- moduleのbufferにεを置きreset_noiseで引き直す形 — 不採用: shared networkの同時forwardで競合し、snapshotとhard updateで別用途のεが混入する（出典: [ADR 0048](../../../adr/0048-noisynet-epsilon-in-caller-execution-state-and-nn-forward-key.md)、Considered Options）。
- 毎forwardでの設定解釈と内容別キャッシュ — 不採用: 速度が重要な経路に検索・比較・同期が残る（出典: [ADR 0051](../../../adr/0051-nn-forward-prepares-concrete-calls-and-purpose-owned-execution.md)、Considered Options）。
- 型別Map・RTTI・型トークンによる具象設定管理 — 不採用: 具象設定の管理が共通層へ移る（出典: [ADR 0051](../../../adr/0051-nn-forward-prepares-concrete-calls-and-purpose-owned-execution.md)、Considered Options）。
- 公開PrepareCallによる二段階操作 — 不採用: 呼出操作が増える。別に構築するCallInfoをForwardへ渡す形で足りる（出典: [ADR 0051](../../../adr/0051-nn-forward-prepares-concrete-calls-and-purpose-owned-execution.md)、Considered Options）。

- DropPath・Dropout などの確率的 module の乱数を purpose stream に分ける形 — 先送り（deferred gate）: 標準 Dropout は generator 引数が無くマスクの自前実装（cuDNN 融合経路の喪失）が要り、移行は既存 Run との同 seed の連続性を切る。再開条件: 構成変更に対する再現性の直交化の実益が決まったら、等価性の説明を持つ別 RFD で（出典: [RFD0065](../../../memo/done/0065_nn_spectral_norm_10rfd.md)、複雑度監査）。
- zero_grad の変更 — 不採用（対象外）: LibTorch 2.11 の zero_grad は set_to_none = true が既定で、既にカーネル起動がゼロである（出典: [RFD0011](../../../memo/done/0011_fused_adamw_10rfd.md)、Context（背景・目的）・11. Out of Scope）。
- 設定レベルの taus-bind fail-fast と推移的到達性の検査（旧 D7） — 不採用（D15 で廃止）: フレームワークは局所的・決定的に判定できる契約だけを検証し、未使用入力の WARN と IQN Head の rank 検証に置き換え、NN 設定の整合は使う側の責任とする（出典: [RFD0001](../../../memo/done/0001_iqn_10rfd.md)、確定した設計判断 D7・D15）。
- 定義しただけで使わない block を Run のたびに検査する形（一覧に出す、または止める） — 不採用: 作って捨てれば検査できるが、Run の構築の経路に、乱数を消費しない扱い・補間の印の仮の値・未知の `type` の扱いが増え、誤りを含む書きかけの定義が印を付け続けるか関係のない Run を止める。使わない定義は出荷設定の検査のテストで見る（出典: [RFD0117](../../../memo/0117_warn_policy_and_unread_config_10rfd.md)、D13・§8）。
- `type` が上書きされた block だけ、読まれない設定キーの検査を緩める形 — 不採用: 上書きされたかを運ぶ配線と例外の規則が増え、読まれない設定キーが黙って通る経路が残る。種類を変えるときは別の名前の block を定義する（出典: [RFD0117](../../../memo/0117_warn_policy_and_unread_config_10rfd.md)、D3・§8）。

- 初期化の設定を今の読み方のまま、14か所の読み手に1キーずつ足す形 — 不採用: blockだけ不正な値が最初のforwardまで止まらず、文に設定キーが出ない差が残る（出典: [RFD0193](../../../memo/0193_variance_scaling_weight_init_10rfd.md)、§6.2）。
- 初期化の設定の読み取りの口を読むだけにし、検査は14か所の読み手がそれぞれ呼ぶ形 — 不採用: 今ある読み取りの口は読むときに検査していて形が揃わず、あとから足す読み手が検査を呼び忘れうる（出典: [RFD0193](../../../memo/0193_variance_scaling_weight_init_10rfd.md)、§6.2）。

- GraphVizの設定と観測の正規化の設定の読み取りの口を、初期化の設定と一緒に作る形 — 範囲外: 別の関心で、読み取りの口の課題に残す（出典: [RFD0193](../../../memo/0193_variance_scaling_weight_init_10rfd.md)、§1.4・§6.1 D6）。

- 共通の口にspecの変換も持たせ、Networkが出力のspecを持つ形 — 先送り: 出力のspecを導くにはHeadまで仮のforwardを通すことになり、乱数を引くmoduleがあると同seedの等価性が崩れうる。使う側もまだ無い。再開条件: Networkの出力のspecを使う部品が出たとき、または並びとNetworkを1本の`SpecForwarder`の並びとして組む要求が出たとき（出典: [RFD0161](../../../memo/0161_observation_pipeline_10rfd.md)、§6.3 D22・§6.6；[ADR 0084](../../../adr/0084-forwarder-is-common-interface-and-chain-serves-requests-named-by-input-and-product.md)、Considered Options）。

- NNの入口が離散のGridのstack軸とクラスをchannelへ畳むことを、stack軸の扱いの決まりにそろえる形 — 範囲外: 見分け方だけを属性に直した。再開条件: 離散のGridを、stack軸を残したまま扱うmoduleを足すとき（出典: [RFD0161](../../../memo/0161_observation_pipeline_10rfd.md)、§6.4 D32・§15）。
- NNの入口の整形（byteからfloat、離散のone-hot）を観測の加工の並びへ移す形 — 範囲外: Perceptionを作る仕組みの外の責務で、stack軸の見分け方だけを直した（出典: [RFD0161](../../../memo/0161_observation_pipeline_10rfd.md)、§2 のNG6）。
- AdamW を foreach 演算の列で組み立てる — 不採用: fused 演算よりカーネル起動数とコードが増え、必要とする CPU/CUDA 構成は直接の fused 演算で扱える（出典: [ADR 0003](../../../adr/0003-fused-adamw-via-aten.md)、Considered Options）。

- 特徴と読み出しの重みを body・head の境界で分ける形 — 不採用。Atari の Dueling 設定では V・A の分岐が body 内にあり、読み出し側の重みが特徴側に混ざる（出典: [RFD0063](../../../memo/done/0063_plasticity_weight_norm_10rfd.md)、計測の定義）。

## 変えるときの条件

一般の条件は[リファクタリング観点](../../../quality/refactor.md)の「ガードレール」、テストの充足は[定点統計](../../../../reports/stats/trend.md)の「テスト充足」を見る。

- self_attnの登録名とパラメータ名を維持し、既存checkpointを利用できるようにする（出典: [RFD0012](../../../memo/done/0012_sdpa_attention_10rfd.md)、1.2 MultiheadAttentionImpl のメンバ）。
- dropout/drop-pathのrateが0の経路は従来出力と一致することを確かめる（出典: [RFD0024](../../../memo/done/0024_nn_dropout_droppath_10rfd.md)、受け入れ基準）。
- ImageClsのhead化はFP32の等価性を先に確認し、そのあとBF16を検証する（出典: [RFD0033](../../../memo/done/0033_imagecls_bf16_head_10rfd.md)、確定した設計判断）。
- 既存のHead/SN FP32保護と用途別AMP精度を維持する。Noisy無効の既存チェーンは決定論backendでmetrics checksumを比較し、sample時の乱数列の割当変更を無効側へ持ち込まない。比較の相手は実装前に保存した基準の実行体・依存DLL・出力とする（RFD0060は基準を取り損ねた）（出典: [RFD0084](../../../memo/done/0084_noisynet_10rfd.md)、§8.2・§12・§13）。
- 診断ON/OFFで同seed・決定的モードの学習系列を比較し、学習の.grad・optimizer state・RNGを変えない。費用は反復A/Bで実測しprofiler合計でend-to-end増加率を代用しない（出典: [RFD0092](../../../memo/done/0092_gradient_noise_scale_10rfd.md)、§7.1・§7.2）。
- captureへ移す既存branch出力の値とdetachを保ち、captureなしforwardは不変とする。同seed・決定論設定の診断ON/OFFで学習由来metrics checksumとRNG・buffer等への非干渉を確認する（出典: [RFD0093](../../../memo/done/0093_attention_entropy_diagnostics_10rfd.md)、§6 1・5）。
- Body の公開出力を Network の出力に残しても、Head の出力・forward の数値・RNG の消費を変えない（出典: [RFD0098 TempoRL](../../../memo/0098_temporl_skip_policy_10rfd.md)、§5.3・§5.9）。
- Bodyの公開特徴量はdtypeと勾配接続を保ち、Headの既存出力の精度を変えない。特徴量を別の学習へ渡す際のdetachは利用側が行う（出典: [ニューラルネットワーク](../../../design/130_neural_networks.jp.md)、§2.1）。
- 呼び出し情報に倍率を省いたとき（倍率1）は、NoisyNetの部品の値と乱数の消費を今と同一に保つ（出典: [RFD0107](../../../memo/0107_noisy_gain_lane_ladder_10rfd.md)、§5.3・§7の受入1）。
- nn_traceをcaptureへ移す前後で、同じseedの`nn_trace/*`の鍵・形・型・値を、変更前と変更後のビルドの書き出しで突き合わせて完全に一致させる。captureを渡さないforwardの数値は、決定的な設定の短いRunのmetrics checksumで確かめる（出典: [RFD0170](../../../memo/0170_nn_trace_capture_unification_10rfd.md)、§4 D17・§7のA1・A11）。
- captureをforwardの公開の口でContextに入れても、Headへ渡すContextにはcaptureを入れず、前回値の破棄と出口の検査はBodyの入口と出口のままにする（出典: [RFD0170](../../../memo/0170_nn_trace_capture_unification_10rfd.md)、§4 D10）。
- forwardの中でblockの出力を上書きしない。captureに書いたTensorをforwardのあとで読んでも値が同じであることが、nn_traceの前提である（出典: [RFD0170](../../../memo/0170_nn_trace_capture_unification_10rfd.md)、§2.3・§4 D7）。
- 公開ヘッダは内部ヘッダを読まない。拡張点を「書ける」に変えるときは、interface・部品・登録口を同じ変更で公開し、拡張点の表と設計文書を同時に直す（出典: [RFD0182](../../../memo/0182_source_layout_10rfd.md)、§5.6）。
- 初期化の設定の読み方を変えても、既存の6つの初期化方式の結果と乱数の消費の順、読み手が読む前に置く既定を変えない。同じseed・決定的モードの短いRunのmetrics checksumを実装前に保存した実行体と比べ、出荷設定から読んだ設定の採取の前後の一致と、設定を書かないblockの初期値の形でも確かめる（出典: [RFD0193](../../../memo/0193_variance_scaling_weight_init_10rfd.md)、§8.3・§9.2の1・10・11）。
- 初期化の設定を設定ファイルから読まずに直接組み立てる経路（ImageCls・MuZeroのHead）があるので、`WeightInitializer::Initialize`の中の検査を消さない（出典: [RFD0193](../../../memo/0193_variance_scaling_weight_init_10rfd.md)、§2 P24・§6.1 D10）。
- blockの閉じたスキーマの検証は、複製や別の読み口の既読記録があっても省かない。共有とAgentの設定を合成したblockでも、各欄の診断にはその値を与えた側の完全キーを使う（出典: [ニューラルネットワーク](../../../design/130_neural_networks.jp.md)、§2.4）。
- 持ち帰りの器の名前や置き場を変えても、鍵で要求する決まりと、満たされない要求をNetworkの出口で止める検査を変えない（出典: [RFD0161](../../../memo/0161_observation_pipeline_10rfd.md)、§6.3 D21）。
- Networkを`Forwarder`として受けた`Forward`の出力とcaptureの値を、`Network::Forward`を直接呼んだときと同じに保つ（出典: [ニューラルネットワーク](../../../design/130_neural_networks.jp.md)、§7.6；[RFD0161](../../../memo/0161_observation_pipeline_10rfd.md)、§6.3 D20）。
- FusedAdamW の数学的な更新式が同じでも浮動小数点の演算順が変わる。学習曲線の厳密な比較には従来の optimizer 経路を使う（出典: [ADR 0003](../../../adr/0003-fused-adamw-via-aten.md)、Consequences）。
- SDPA の backend が異なると演算順が変わる。従来実装とのビット単位の一致を性能比較の前提にしない（出典: [ADR 0004](../../../adr/0004-sdpa-attention-via-aten.md)、Consequences）。
- V・A の分岐を宣言していない DropMerge の設定で起動し、net.detail と net.structure が従来と同型で学習できることを確かめる（出典: [RFD0009](../../../memo/done/0009_dueling_dag_head_10rfd.md)、後方互換・エッジケース、検証）。
- 勾配ノルムは各パラメータの二乗和の平方根と照合し、クリップ後の値は以前の手計算と照合する。LunarLander では optimizer_step 区間と steps/sec を同じ条件で比べる（出典: [RFD0011](../../../memo/done/0011_fused_adamw_10rfd.md)、§10）。
- 重み初期化方式の設定表現を変えたときは、対応する方式と同じ seed で数ステップを実行し、出力と loss の完全一致を確認する（出典: [RFD0027](../../../memo/done/0027_weight_init_mode_string_10rfd.md)、検証）。
- LayerNorm の eps を指定しない既存の LunarLander・Hybrid・ViT の分岐では、既定値 1e-5 と動作を保つ（出典: [RFD0028](../../../memo/done/0028_cnblock_convnext_10rfd.md)、受け入れ基準）。
- ブロック補間マーカーを含まない既存の ResNet18ish などの branch は、変更後もそのまま起動して学習できることを確かめる（出典: [RFD0029](../../../memo/done/0029_config_profile_param_interp_10rfd.md)、検証）。
- 可塑性を測る設定の有無を同じ seed で比べ、loss・td_mean などの学習系列と保存した agent_close.anet の一致を確認する（出典: [RFD0062](../../../memo/done/0062_plasticity_metrics_10rfd.md)、受入基準）。

## 外の事例

- PyTorch の `nn.Linear` と `nn.Conv2d` の既定の初期値は、重みも bias も U(−√k, √k)（k = 1/fan_in。Conv2d は groups ÷（C_in × kernel の要素数））で、コードは `kaiming_uniform_(weight, a=math.sqrt(5))` と書く。保守者は、乱数を直接引いていた既定と結果を変えないための書き方で、元は Torch7・Torch5 から続く形だと説明している。コードは取得の道具の抜き書きで読んだ（出典: [weight_init_normalization_adam_survey_2026-11-27.md](../../../../reports/weight_init_normalization_adam_survey_2026-11-27.md)、§7.1）。
- Dopamine の TF 版（e7d780d）の `RainbowNetwork` と `ImplicitQuantileNetwork` は、conv 3 層・全結合・出力（IQN では τ の射影も）を `VarianceScaling(scale=1.0 / np.sqrt(3.0), mode='fan_in', distribution='uniform')` で初期化し、`NatureDQNNetwork` は指定しない（Keras の既定）。JAX 版は Rainbow・QR・IQN が同じ variance scaling、`NatureDQNNetwork` と `FullRainbowNetwork` の conv が `xavier_uniform` で、`ImpalaEncoder` は各段の最初の conv だけ `xavier_uniform`、残差 block の conv は Flax の既定（`lecun_normal`、bias 0）である。コードは取得の道具の抜き書きで読んだ（出典: [weight_init_normalization_adam_survey_2026-11-27.md](../../../../reports/weight_init_normalization_adam_survey_2026-11-27.md)、§7.2）。
- BTR の公開実装（093ca77）は、conv、τ の cos の埋め込み、ノイズなしの線形層と Dueling の層に初期化を書かず、PyTorch の既定のまま使う。SN は `torch.nn.utils.parametrizations.spectral_norm` で、IMPALA の各段の残差 block の 2 つの conv にだけ掛け、各段の最初の conv には掛けない。コードは取得の道具の抜き書きで読んだ（出典: [weight_init_normalization_adam_survey_2026-11-27.md](../../../../reports/weight_init_normalization_adam_survey_2026-11-27.md)、§7.3）。
- Stable-Baselines3 の DQN の Q ネット（`QNetwork`、CnnPolicy の `NatureCNN`）は初期化を書かず、PyTorch の既定のまま使う。PPO・A2C の `ActorCriticPolicy` は `ortho_init=True` が既定で、特徴抽出と隠れ層を gain √2、行動の出力を 0.01、価値の出力を 1 の直交初期化にし、bias を 0 にする。コメントは、この gain が openai/baselines から来たと書く。コードは取得の道具の抜き書きで読んだ（出典: [weight_init_normalization_adam_survey_2026-11-27.md](../../../../reports/weight_init_normalization_adam_survey_2026-11-27.md)、§7.4）。
- CleanRL の DQN 系の Atari の実装（`dqn_atari.py`、IMPALA CNN の `qdagger_dqn_atari_impalacnn.py`、JAX 版の `dqn_atari_jax.py`）は初期化を書かず、PyTorch か Flax の既定のまま使う。`dqn_atari.py` の学習率の既定は 1e-4 で、Adam の ε は指定しない。PPO の `ppo_atari.py` は全層を直交初期化（gain √2、方策の出力 0.01、価値の出力 1、bias 0）にし、`ppo_procgen.py` の IMPALA CNN は conv と隠れの線形層を PyTorch の既定のまま、方策と価値の出力だけ直交初期化にする。コードは取得の道具の抜き書きで読んだ（出典: [weight_init_normalization_adam_survey_2026-11-27.md](../../../../reports/weight_init_normalization_adam_survey_2026-11-27.md)、§7.5）。
- CleanRL の `pqn_atari_envpool.py`（PQN）は、conv 3 層と 512 の線形層の後ろに LayerNorm を置き、出力を含む全層を gain √2 の直交初期化にして、RAdam の学習率を既定で線形に下げる。コードは取得の道具の抜き書きで読んだ（出典: [weight_init_normalization_adam_survey_2026-11-27.md](../../../../reports/weight_init_normalization_adam_survey_2026-11-27.md)、§7.5）。
- OpenAI の phasic-policy-gradient の IMPALA CNN は、conv と線形層の重みを、出力のユニットごとの L2 ノルムが指定の scale になるように縮め（`NormedConv2d`・`NormedLinear`）、bias を 0 にする。残差 block の scale は段の数と block の数の平方根で割って決め、最後の線形層は scale 1.4 にする。コードは取得の道具の抜き書きで読んだ（出典: [weight_init_normalization_adam_survey_2026-11-27.md](../../../../reports/weight_init_normalization_adam_survey_2026-11-27.md)、§7.6）。
