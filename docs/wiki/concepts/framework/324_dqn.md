# 324 Agent個別実装 DQN系列

[anet-lab](../../../../README.md) › [wiki の目録](../../index.md) › [フレームワーク](../../index.md#フレームワーク)

## 概要・責務

- DefaultDQNAgentとRainbowAgentが共通DQN componentを合成する具象実装を扱う。共用部品は学習・行動・Network・組み立て・共通の計算の5つに分かれ、両Agentは`DqnComponentAssembler`を呼んで構築する。方式の概要と本実装の対応は§2.1、部品の合成は§2.2を参照する。（出典: [DQN系Agent](../../../design/200_dqn_agents.jp.md)、§1.3・§2.1・§2.2）。
- DefaultDQN は `frame_stack.*` の重ね方を ReplayBuffer と依頼に配る。3 種類の Perception の出力 spec を、Network の構築に使う可視化用の出力と照合する（出典: [Forwarder と Perception](../../../design/135_forwarder_and_perception.jp.md)、§3）。
- DefaultDQNは、部品列の最終出力で、重ねる対象のキーにstack軸が無ければ長さ1の軸を足し、開始の印が残っていれば除く。行動選択用とSample用の出力のspecは、可視化用の出力（Networkの入力）と構築時に照合する。可視化用のForwarderの図を`perception.structure`と`perception.detail`としてRunの`dot/`に記録する（出典: [Forwarder と Perception](../../../design/135_forwarder_and_perception.jp.md)、§3・§5；[DQN系Agent](../../../design/200_dqn_agents.jp.md)、§2.4；[可観測性](../../../design/140_observability.jp.md)、§7）。
- DefaultDQNの内的報酬は、外側Agentが持つ非公開の`IntrinsicRewardCoordinator`が扱う。外的報酬をスケールしたあと、学習の有効・無効によらずexp stepのβを評価し、学習が有効なら観測（既定は次観測）を採点して、終端の処理・内的報酬スケーラ・β倍を当てたボーナスを返す。報酬へ足すのはAgentで、そのあとCoordinatorが補助学習を進める。補助学習の刻みと抽選もCoordinatorが管理し、intakeから引く形とrolloutをためてエポックで学ぶ形がある。RNDの段階とモード、式、設定、指標、保存は212を正本とする（出典: [DQN系Agent](../../../design/200_dqn_agents.jp.md)、§6.2・§7.2、[RNDによる新しさの評価と内的報酬](../../../design/212_rnd_lifelong_novelty.jp.md)、§1・§2・§5）。
- `intrinsic.value_mode`の既定`combined`は内的報酬を報酬へ畳み、`decomposed`はβを掛けない内的の成分を外的と別にReplayへ渡す。分解では外的と内的のHeadの出力をDQN側がβで合わせて`q`・`q_dist`にし、TBOが有効なら実空間で足す。Replayは成分の意味を持たない（出典: [DQN系Agent](../../../design/200_dqn_agents.jp.md)、§6.2・§9.10、[外的と内的の価値の分解](../../../design/214_value_decomposition.jp.md)、§1.2・§2.1〜§2.3）。
- 価値の分解の目標値は Head ごとの n-step 収益と割引率で作り、`y_ext = R_ext + gamma_ext^n (1 - done) Q_ext,target(s_next, a_ext)`、`y_int = R_int + gamma_int^n (1 - done_int) Q_int,target(s_next, a_combined)`（n は実際の step 数）である。`discount_mode=separate` は明示した内的の割引率を使い、定数の成分は Push 時の収益を保存し、schedule の成分だけ抽選後に保存した step 報酬から収益を作り直す。`terminal_mode=non_episodic` では終端後の最初の観測から内的だけ bootstrap し、done と truncated が同時に真なら両方とも切る。PER の誤差は `abs(delta_ext) + priority_lambda * abs(delta_int)` である（出典: [外的と内的の価値の分解](../../../design/214_value_decomposition.jp.md)、§3.1・§3.3）。
- 内側の Learner は、成分ごとの割引率の設定が定数か schedule かで `needs_return_recompute` を決め、schedule の成分だけ抽選時に保存した step 報酬から収益を作り直す。QR・IQN の PER に書き戻す優先度は、current と target の分位点の平均の差の絶対値に `per_eps` を足した値から作り、分位点の組ごとの誤差の絶対値の平均ではない（出典: [DQN系Agent](../../../design/200_dqn_agents.jp.md)、§2.5）。
- 可塑性の指標（`34_agent_plasticity`）は DQN の online の Network を測り、RND の target と predictor は測らない（出典: [RND による新しさの評価と内的報酬](../../../design/212_rnd_lifelong_novelty.jp.md)、§9.4）。
- 価値の分解の `non_episodic` でも n-step の和は終端で閉じ、終端のあとのエピソードの報酬は `R_int` に入らない（出典: [外的と内的の価値の分解](../../../design/214_value_decomposition.jp.md)、§3.1）。

- 既存のHead/SN FP32保護と用途別AMP精度を維持する。Noisy無効の既存チェーンは決定論backendでmetrics checksumを比較し、sample時の乱数列の割当変更を無効側へ持ち込まない。比較の相手は実装前に保存した基準の実行体・依存DLL・出力とする（RFD0060は基準を取り損ねた）（出典: [RFD0084](../../../memo/done/0084_noisynet_10rfd.md)、§8.2・§12・§13）。
- 診断ON/OFFで同seed・決定的モードの学習系列を比較し、学習の.grad・optimizer state・RNGを変えない。費用は反復A/Bで実測しprofiler合計でend-to-end増加率を代用しない（出典: [RFD0092](../../../memo/done/0092_gradient_noise_scale_10rfd.md)、§7.1・§7.2）。
- captureへ移す既存branch出力の値とdetachを保ち、captureなしforwardは不変とする。同seed・決定論設定の診断ON/OFFで学習由来metrics checksumとRNG・buffer等への非干渉を確認する（出典: [RFD0093](../../../memo/done/0093_attention_entropy_diagnostics_10rfd.md)、§6 1・5）。
- ヒント計算の共有化前後でactor_approxの同seed・決定的Runの学習metrics checksumを一致させ、既定のEvalPanel networkとRunnerカウンタの通知前後の時機を変えない（出典: [RFD0094](../../../memo/done/0094_evalpanel_step_history_10rfd.md)、§4.2 D6/D7・§8 3）。
- スキップが無効のとき、forward の回数・順序、RNG の消費、loss、優先度、checkpoint の形を今と同一に保ち、metrics checksum の一致で確かめる（出典: [RFD0098 TempoRL](../../../memo/0098_temporl_skip_policy_10rfd.md)、§5.9・§7 段 0）。
- skip の新しい設定が既定（`feature_gradient` は今の値、`sample_weight = uniform`）のとき、Learner の forward と backward の回数・順序、RNG の消費、loss、優先度、checkpoint の形を今と同一に保ち、RFD0098 の検証資材の段 0 と同じ比較で metrics checksum を一致させる。skip 有効の構成は、新しい実行体で、評価 session `[greedy]` と評価側の指標を足す前の設定（着手前の snapshot）を動かして比べる（出典: [RFD0103](../../../memo/done/0103_temporl_reference_alignment_10rfd.md)、§4 D11・D14・§7 受入 1）。
- `skip.nn_forward_mode`を足す前後で、既定（`shared`）のときskip側のforwardのseedの派生・時計の種別・forwardの回数と順序を変えず、RFD0103の検証資材の6構成とskip有効のLunarLanderに`run.@noisy`を足した構成のmetrics checksumを、着手前のsnapshotの同じ設定を前後のビルドへ渡して一致させる。着手前と今の設定を4 env×既定・skip有効で解決して比べ、違いが各Actorの`skip.nn_forward_mode = shared`の追加だけであることも確かめる（出典: [RFD0106](../../../memo/done/0106_temporl_skip_forward_noise_key_10rfd.md)、§5.3・§7の受入1・4）。
- ノイズの倍率を足す前後で、既定（倍率1）のとき値と乱数の消費を今と同一に保ち、RFD0103の検証資材の6構成とskip有効のLunarLanderに`run.@noisy`を足した構成のmetrics checksumを一致させる（出典: [RFD0107](../../../memo/0107_noisy_gain_lane_ladder_10rfd.md)、§5.3・§7の受入1）。
- 既定のfull・decisionの組み合わせではActorの行動・乱数消費とReplayの抽選列を変えず、RFD0103の検証資材でmetrics checksumを一致させる（出典: [RFD0104](../../../memo/done/0104_temporl_skip_auxiliary_only_10rfd.md)、§5.7・§7の受入1）。
- `intrinsic.enabled`の既定（false）では、今と同じ学習系列を保ち、全scalarの点のchecksumとscalarの定義の一致で確かめる。有効のcheckpointの読み書きを足しても、無効で保存したcheckpointのバイト配置を変えない（出典: [RFD0116](../../../memo/0116_rnd_lifelong_novelty_10rfd.md)、§1.2・§6.1）。
- 学習の入口のボーナスとEvaluation Traceのボーナスは、`IntrinsicRewardCoordinator`の`CalculateBonus`で同じ式から作る（出典: [DQN系Agent](../../../design/200_dqn_agents.jp.md)、§6.2）。
- 新しい方策や診断のforwardを足すときは、Headの出力に結合の処理を当ててから`q`・`q_dist`を読む。内的のHeadの重みもreadout側に入るので、可塑性・Noisy・policy churn・Replay fitの診断を広げるときは、結合したQを使う経路と各Headのパラメータを扱う経路を分ける（出典: [外的と内的の価値の分解](../../../design/214_value_decomposition.jp.md)、§7）。
- `intrinsic.use_done_mask` の既定（true）では、doneのlaneの学習報酬をスケール済みの外的報酬だけに保ち、truncatedだけのlaneの扱いと、採点・統計の更新・補助学習がdoneのlaneも対象にすることを変えない（出典: [RFD0123](../../../memo/0123_rnd_intrinsic_reward_scale_10rfd.md)、§4 D16・§5.5）。
- Evaluation Traceの内的報酬の採点は、学習の入口の採点・補助学習・ロックの取り方を変えず、predictorの重み・誤差と観測の統計・採点の件数・群56の診断値を変えない。採点を挟んだ学習と挟まない学習で、学習へ渡る報酬の列と診断値が一致することを、`clone_model`がtrueとfalseの両方で確かめる（出典: [RFD0127](../../../memo/0127_eval_trace_intrinsic_reward_columns_10rfd.md)、§1.2 G2・§4 D4・§7の10）。
- step診断がAgentの読み取りロックを取るのは、写しを持たないActorで内的報酬の鍵を求められたときだけで、stepごとである。写しを持つActorでは、Actorがnetworkを写し直すロックの中で推定器とβも写し、step診断はロックを取らない。写すのはEvaluation Traceのpaneを開いている間だけで、開いたときに写しが無ければ、EvalPanelがその場でActorを同期する。内的報酬の列を宣言しないstep診断もロックを取らず、Traceを使わないRunのmetrics checksumを、着手前に保存した実行体と一致させる（出典: [RFD0127](../../../memo/0127_eval_trace_intrinsic_reward_columns_10rfd.md)、§4 D4・§5.2・§5.4・§7の7・11）。
- Actorのnetworkの同期を、学習のスレッドが写しを作って公開する形（実装の規約どおりの形）へ直すときは、step診断の推定器とβの写しも一緒に移す（出典: [RFD0127](../../../memo/0127_eval_trace_intrinsic_reward_columns_10rfd.md)、§4 D4の帰結）。
- Evaluation Traceのボーナスに使うβを、構築時と学習を止めた入口で評価しても、学習へ渡る報酬・Replay・内的報酬の診断値・メトリクス・checkpointの書式を変えない。RFD0127の「Traceを挟んでも学習が変わらない」テスト2本を、断定を変えずに通す（出典: [RFD0129](../../../memo/0129_eval_trace_bonus_beta_before_learning_10rfd.md)、§4 D5・D11・§7の4）。
- Runのstep数をcheckpointから復元するようになったら、Evaluation Traceのボーナスに使うβの構築時の評価を、復元したstepで評価する形に直す（出典: [RFD0129](../../../memo/0129_eval_trace_bonus_beta_before_learning_10rfd.md)、§4 D1）。
- 価値の分解と報酬スケーラの新しい設定キーが既定のとき、forwardの回数と順、乱数の消費、loss、優先度を今と同じに保つ。checkpointの形は、状態を持つ報酬スケーラを使わない構成では今と同じに保つ。記録されるメトリクスのtagも変えない（足すtagは、既定では選ばれない組に置く）。Actor Qヒントを使う構成では、ヒントが5列になっても初期優先度の値を同じに保つ。実装前に保存した実行体と、同seed・決定的モードの短いRunのmetrics checksumを比べる（出典: [RFD0121](../../../memo/0121_extrinsic_intrinsic_value_decomposition_10rfd.md)、§5 D17・D20・§9.2の1）。
- DQN系のAgentまわりの挙動を変えない直しでは、設定キー、メトリクスの名前、checkpointの形式、ログとWARNとERRORの文言・順・回数、乱数の消費の順、Agentが記録する設定を変えない（RFD0128では、設定のエラー文を2つの形にそろえることだけを意図して変えた）。実装前に保存した実行体と、RFD0125の短縮条件の組にRNDの2組と診断の6群を購読する組を足して、全scalarの点・`config/DefaultDQNAgent.txt`・ログのWARNとERRORの行を比べる（出典: [RFD0128](../../../memo/0128_dqn_agent_refactor_bundle_10rfd.md)、§6.2・§6.4・§7の1〜3）。
- RainbowAgentは、Rainbow相当まで設定を絞った、DQN系の共通部品の2つ目の利用者として保つ。共通部品は具象Agentの設定の型を受け取らず、Agentが持たない部品を任意の入力として受ける。RainbowAgentは学習の経路を通す特性テストで確かめる（出典: [RFD0128](../../../memo/0128_dqn_agent_refactor_bundle_10rfd.md)、§5 D2・D3・§6.3）。
- DQNのファイルを分けるときは、関数と型の本体を変えず、分ける前後で定義の本文の集まりが一致することを道具で確かめる。RainbowとDefaultDQNが互いの名前を持たず、共通部品が具象のヘッダを読まないことを検索で確かめる（出典: [RFD0182](../../../memo/0182_source_layout_10rfd.md)、§5.3・§6 のS2-1・S3-4）。
- （RFD0161でWithActionは消え、強制行動はActorが反映する。期待値は強制行動つきの`MakeAction`のテストへ移した）WithActionのdeviceの扱いを変えても、ヒントの値を渡された行動の値に取り直す計算と、取り直しに要る値が無いとき・形が合わないときに止める検査を変えない。WithActionを呼ぶ今のテストが、期待値を変えずに通ることを確かめる（出典: [RFD0192](../../../memo/0192_concurrency_and_boundary_defect_fixes_10rfd.md)、§5 D9・§6.4・§7のA5）。
- DQNの共通部品の通知の文面を変えるときは、設定キーを完全キーで書き、共通部品のファイルに具象Agentの名前を書かない（登録の2行を除く）。RainbowAgentが読まない設定は、完全キーの形で名指さない（出典: [RFD0194](../../../memo/0194_config_key_full_names_in_messages_10rfd.md)、§5 D1・§7 A4）。
- 出荷設定で学習の挙動を変えないことを、LunarLander・GridMaze・DropMerge・Atari（qbert）の4環境で確かめる。変更前後とも同じseedと`backend.$=backend.@deterministic`を指定し、性能・資源のtagを除くscalarとtraceの全レコードを一致させる。checkpointのraw checksumは使わない（出典: [RFD0161](../../../memo/0161_observation_pipeline_10rfd.md)、§6.5 D35・§9；[RFD0200](../../../memo/0200_forwarder_public_interface_rework_10rfd.md)、§5.5 D25・§7 の「等価性の比べ方」）。
- 設定の基準（17構成）を移すときは、解決結果を丸ごと採り直さず、移したキーの項目だけを入れ替え、ほかのキーと値・並びが変わっていないことを比べる（出典: [RFD0200](../../../memo/0200_forwarder_public_interface_rework_10rfd.md)、§7 の「基準の直し方」）。
- 方策変化を測る3回の推論には同じ probe 状態と同じ分位を渡す。測定専用の乱数を学習や可塑性の抽選と共有しない（出典: [ADR 0033](../../../adr/0033-policy-churn-fixed-probe-and-target-lag.md)、Consequences）。
- QR 既定の回帰は LunarLander で quantile_mode=qr、32分位にそろえ、設定ダンプと短い Run の動作で照合する（出典: [RFD0001](../../../memo/done/0001_iqn_10rfd.md)、検証）。
- τ 配置方式を増やしても、既存の random は独立同分布の抽出・指定範囲・再現性を保つ。CPU と利用可能な CUDA で形状、float32、出力先デバイスを確認する（出典: [RFD0044](../../../memo/done/0044_iqn_tau_stratified_sampling_10rfd.md)、Testing Decisions）。
- IQN の探索計測は導入前後で loss、行動、raw priority、ReplayBuffer に反映した優先度、乱数列が一致することを確認する（出典: [RFD0047](../../../memo/done/0047_iqn_search_p0_metrics_10rfd.md)、Testing Decisions）。
- stack の独立軸を扱う変更でも、先頭が Flatten の既存 MLP と、先頭が StackMerge の既存画像ネットワークが同じ挙動を保つことを確かめる（出典: [RFD0057](../../../memo/done/0057_native_stack_dim_handling_10rfd.md)、維持すべき不変条件）。
- feature と readout の重みノルム計測は乱数を消費しない。同じ seed で計測を有効・無効にし、学習系列と保存重みが一致することを確認する（出典: [RFD0063](../../../memo/done/0063_plasticity_weight_norm_10rfd.md)、テスト項目・受入基準）。
- churn の計測を有効・無効にした同一ビルドで、学習パラメータ、通常の Replay サンプル、可塑性 probe と既存メトリクスが一致することを確かめる（出典: [RFD0066](../../../memo/done/0066_policy_churn_metrics_10rfd.md)、将来実装の受入条件）。
- Munchausen 無効時の比較は Q・TD と loss のタグ、step、値を正規化したチェックサムで行う。直列化の非決定性を含む checkpoint ファイル自体のハッシュは使わない（出典: [RFD0067](../../../memo/done/0067_MunchausenRL_10rfd.md)、テスト契約・実装時の受入基準）。
- replay_fit と既存 probe を同時に購読しても、互いのサンプル系列を変えない。事前基準を確保できなかった比較はチェックサム一致として扱わない（出典: [RFD0073](../../../memo/done/0073_replay_fit_metrics_10rfd.md)、§8）。
