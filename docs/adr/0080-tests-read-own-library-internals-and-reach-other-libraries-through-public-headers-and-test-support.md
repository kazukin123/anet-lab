# テストは自分のライブラリの内部まで読み、ほかのライブラリは公開ヘッダとテスト用の口だけを通して使う

ライブラリの境界をテストが素通りしないように、単体テストは対象のライブラリの中に置いて内部まで読めるとし、ほかのライブラリは、公開ヘッダと、そのライブラリが出すテスト用の口だけを通して使う。テストは上位や兄弟のライブラリに依存せず、相手が主題でないときは代役を使う。テスト用の口は、公開ヘッダと同じ include の下の `anet/test/` に置いて別のターゲットにし、ヘッダの先頭のガードで、製品のコードが読むとコンパイルが止まるようにする。

## Considered Options

- テストを境界の対象にしない: テストのケースを動かさずに済むが、テストが公開面の外の何にでも依存できるので採らない。
- 系統のテストが基盤の `src/` を直接読む: 同じリポジトリにあることに頼るので採らない。
- テスト用の口を別のライブラリのフォルダにする: include パスだけで止まるが、そのライブラリが別のフォルダの `src/` を読む箇所が残るので採らない。
- Env と系統のテストが互いのライブラリを使ってよいとする: テストの置き場が主題しだいで割れ、相手が壊れると使う側のテスト実行体が作れないので採らない。
