# DropMergeのNoDropTimeoutをtruncationではなく敗着(done+罰)とする

DropMergeのショットクロック超過(NoDropTimeout)は、RL慣習のtime-limit truncationではなく、done+非0罰の敗着として扱う。ショットクロックはagentのNOOP選択でのみ進み、残量は`no_drop_timeout_ratio`としてObservationに可視であるため、この終端はagent支配下のMarkovな帰結であり外因による観測打ち切りではない。現行のdone+罰0はBLK/Overflowの`game_over_penalty`(−10)と組み合わさってguaranteed-0の避難港を作り、危険盤面での停滞を報酬合理的にし、さらにNoLegalDrop投了(罰なし)と停滞が報酬上無差別になるため投了の強化に学習圧が掛からない——この構造がNEET(合法DROPがあるのにNOOPを続ける病理)の上流と目される。truncated化(`use_no_drop_timeout_gameover=false`)は報酬定数を発明しない代替だったが、過去議論で却下済みであることに加え、同flagがObservationのscalar次元(4/5)にも結合しており一軸比較を壊す罠がある。罰値は`game_over_penalty`と同値(−10)を初期値の起点とするが独立の自由値であり、同値規律・自動参照・warn/fail-fastは設けない。有効化はPRD039 Phase 2の受理安全網(blocked persistenceが連続N=60物理frameに達したら settled に依らず必ずNoLegalDrop受理)と併せて行う意図——受理保証なしに罰だけ入れると、裁定に失敗した真の詰みでの正しい投了が敗着扱いされるため。
