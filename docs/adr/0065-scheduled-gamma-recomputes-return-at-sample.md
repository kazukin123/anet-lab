# 時間で変わる割引率は、schedule のときだけ抽選時に保存済みの step 報酬から収益を作り直す

割引率 γ を ProfiledValue で時間変化させると、Push 時に γ で計算して保存した n-step 収益と、学習時の bootstrap の γ^n の γ がずれる。Replay は step ごとの報酬を Push のたびに保存している（ADR 0063）ので、γ が schedule の構成では学習に使う収益を抽選時にその保存値から今の γ で作り直し、γ が定数の構成では今どおり Push 時の収益を使うことに決める。作り直しは Push 時と同じ逆順の和で足し、定数のときに保存値と一致する形にする。Push 時の収益は初期優先度のヒントの完成に使い、slot の保存形は変えない。報酬スケーラの自動 post_scale は構築時の γ を使う。Replay は γ を自分で持たず、Push と Sample の入力として受け取る。

## Considered Options

- **保存済みの収益は Push 時の γ、bootstrap は学習時の γ の 2 時点を契約にする**: 変化中は学習の target の中に既知のずれを作る。保存形を変えずに作り直せるので、ずれを抱える理由が無い。却下
- **γ は定数だけ許す**: 時間変化の器としては γ だけ空く。schedule のときだけ作り直す形で両立できる。却下
- **常に抽選時に作り直す**: 定数でも計算が増え、足す順を揃えないと既存 Run との checksum が変わる。定数は保存値の経路に留める。却下
