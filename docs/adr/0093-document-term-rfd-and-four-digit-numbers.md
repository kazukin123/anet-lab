# 変更ごとの文書の呼び名を PRD から RFD に改め、番号を 0 埋めの 4 桁にする

1 回の変更ごとに書く文書の呼び名を、製品の要求書を指す「PRD」から「RFD」（Request for Discussion）に改め、番号を 0 埋めの 4 桁にした（[PRD195](../memo/195_rename_prd_document_term_10prd.md)）。中身（要求から設計の契約まで、AI がそのまま実装する指示、判断の記録）を 1 語で表す呼び名は無いので、呼び名は記号とみなして既存の語との衝突の無さと文字数を優先し、ソフトウェアで RFC の仲間として通じ、番号を取って下書きから議論して決め理由を残す流れが同じ RFD を選んだ。指示の側面は名前に出ないので用語集の定義が補い、過去の記録とコミット件名には「PRD」が残るので、道具は件名の旧い記号も値で同じ文書に当てて読み続ける。

## Considered Options

- **呼び名は PRD のまま、用語集に注記する**: 手間は小さいが、skill 名・ファイル名・件名・テストのタグのように名前を目にする場所ごとに取り違えの入口が残る。却下
- **SPEC**: Spec Kit・Kiro では作り方を書かない要求、OpenSpec では今の仕様を指し、似て非なる。語の一部としての衝突も 1 万か所を超える。却下
- **RFC**: 一般の語として広く使われ、anet の文書と結びつかない。却下
- **ORDER（変更指示）**: 指示の側面に最も合うが、文字数が多く、anet では order が順序を指す。却下
- **ECO（Engineering Change Order）**: 製造業で定着した変更指示だが、ソフトウェアでは通じにくく、変更は少ないほどよいという響きがある。却下
- **CR（Change Request）**: 一般の語で、改行の CR と紛れ、2 文字で検索できない。却下
- **番号の桁の数を変えてよいことにする、または番号が 990 に届いてから桁の形を決める**: 呼び名を改めるとファイル名と記号を全部書き換えるので、同じ改名で 4 桁にそろえれば、後でもう一度全部を改名せずに済む。却下
