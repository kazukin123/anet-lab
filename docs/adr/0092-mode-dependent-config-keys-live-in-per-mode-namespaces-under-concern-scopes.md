# モードで使う設定キーが変わるときは、関心ごとのスコープに mode を置き、設定キーはモードの名前空間に持つ

段階ごとのスコープに `mode` を置き、モードの名前の名前空間にそのモードの設定キーを持つ形は、RND と補助学習だけの決定（[ADR 0088](0088-rnd-config-is-scoped-by-stage-with-per-mode-namespaces.md)）で、名前の決まりは平らな `<何の>_mode` だけを書き、ほかの設定をそろえる基準が無かった（[issue-20261122-2fc208](../management/issues/issue-20261122-2fc208.md)）。**モードによって使う設定キーが変わるときは、モードを持つ関心ごとにスコープを切って `mode` を置き、モードによって使うかどうか、または意味・単位・適した値が変わりうる設定キーは、ほかのモードと名前が被ってもモードの名前空間（`<スコープ>.<モード>.<キー>`）に持ち、この形に沿わない今あるまとまりに設定キーを足す・変えるときは、そのまとまりを同じ変更でこの形へ移す**ことを決定する。同じ名前の設定キーがモードの数だけ並び、移す手間もかかる代わりに、モードを切り替えても、ほかの設定キーの意味が変わらない。

## Considered Options

- **モードはすべてこの形にする**: 値を選ぶだけのモード（`AtariEnv.resize_mode` など）まで、スコープと `mode` に組み替えることになる。使う設定キーが変わらないなら、平らな `<何の>_mode` でよい。却下。
- **RND だけの決定に留める**: ほかの設定をそろえるときの基準が無いまま、部品ごとに設定の持ち方が違う。却下。
- **スコープの直下には `mode` だけを置く**: どのモードでも同じに使う Network の設定まで、モードの数だけ書くことになる。どのモードでも同じに使う部品の設定は、スコープの直下に置く。却下。
- **新しく足すまとまりにだけ当てる**: 今あるまとまりに今の形で設定キーが増え、あとで移すときに直す量が増える。却下。
- **今の契約として書くだけで、足すときの扱いは書かない**: 沿わないまとまりを移す要否に、レビューで初めて気づくことになる。却下。

## Consequences

- 名前の付け方の 4（モードの設定キーには何のモードかが分かる名を付け、`skip.mode` は悪い例）は残る。この形でモードのためにスコープを切ったときだけ、スコープの名が何のモードかを言うので、`mode` でよい（`rnd.error_norm.mode`）。
