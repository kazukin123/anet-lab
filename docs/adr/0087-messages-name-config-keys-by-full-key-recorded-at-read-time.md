# 通知が示す設定キーは完全キーで書き、完全キーは読み口が読むときに記録して部品へ運ぶ

共通の部品のエラー文が、相対キー（`learner.per_eps`）や、特定の利用側の root を固定した名前（`DefaultDQNAgent.…`）で設定を名指していて、文面のキーを設定に貼っても効かない、別の Agent のキーを指す、という不整合が基盤全体に約 200 か所あった（[PRD194](../memo/0194_config_key_full_names_in_messages_10rfd.md)）。**エラー・WARN・INFO が設定キーを示すときは完全キーで書き、完全キーは `ConfigData` の項目と読み口（`anet::Config`）が読むときに記録して、設定の型と一緒に部品へ運ぶ。部品は、利用側が読んでいない設定を完全キーの形では名指さない**ことを決定する。値を与えた置き場（既定か上書きか、共有の block か Agent の下か）を知っているのは、読むときだけだからである。

## Considered Options

- **利用側が root までの接頭辞を渡し、部品が欄の名前を足す**: 利用側が読まない設定でも完全キーを組み、書いても効かないキーを指す。却下。
- **利用側が、名指す設定ごとに完全キーを手で渡す**: 上書きの置き場から読んだかを利用側が自分で判定することになり、合成された block の設定はどちらの置き場の値かを示せない。却下。
- **設定だけで決まる検査を具象の読み口へ移す**: 型の検査を型の共通処理に置く決まりに反し、block の検査は移せない。却下。
- **相対キーに置き場の名前を添える形を認める**: 文面のキーをそのまま設定に貼れない。却下。
