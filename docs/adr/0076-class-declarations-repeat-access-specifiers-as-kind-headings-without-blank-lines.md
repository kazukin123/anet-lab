# クラスの宣言は、種類の切れ目でアクセス指定を書き直して見出しにし、アクセス指定の前に空行を入れない

新しく書くクラスは、型・定数・関数・データメンバの切れ目ごとに、アクセスの範囲が同じでも `public:`・`private:` などを書き直して種類の見出しにし、同じアクセス指定の下では意味の違う群（生成とほかの関数など）の間に空行を入れる（[impl.md](../quality/impl.md) の「C++ コード」、項番 78）。**アクセス指定の前後には空行を入れず、アクセス指定そのものを区切りにする**ことを、Google の Class Format（アクセスの範囲ごとにアクセス指定を 1 回書き、その前に空行を入れる）と比べて決定する。1 つのアクセス指定の下の宣言が 3 個以下なら、空行を入れるほうが読みやすさを損なうので、群の空行も入れない。

## Consequences

- clang-tidy を使うなら、`readability-redundant-access-specifiers` が、書き直したアクセス指定を余分と指摘する。意図した書き方なので、指摘に合わせて消さない。
- 既存のクラスには当てず、[課題 657248](../management/issues/issue-20261115-657248.md) でまとめて直す。
