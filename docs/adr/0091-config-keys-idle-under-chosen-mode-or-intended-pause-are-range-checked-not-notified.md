# 選んだモードや意図した休止で値が結果を変えない設定キーは、知らせずに値域だけを検証する

Fail-Fast 原則の表は、ほかの設定で値が使われない設定キーを WARN とし（[PRD117](../memo/0117_warn_policy_and_unread_config_10rfd.md) の D1 は、書いた値が今のモードで効かないことを知らせる既存の WARN を残した）、モードを切り替えて比べたいだけの Run で、関係のない設定を書き直すか、WARN を受けることになっていた（[issue-20261122-2fc208](../management/issues/issue-20261122-2fc208.md)）。**選んだモードや意図した休止（有効フラグの偽・間隔 0・schedule の無い評価タグ）のために、書いた値が結果を何も変えない設定キーは、WARN も INFO も出さずに読み、そのキーだけで決まる値域を検証して外れたら止め、ほかの設定と突き合わせる検査は、そのモードや機能が使われるときだけ当てる**ことを決定する。書き間違いに気づける通知を捨てる代わりに、モードを切り替えるだけで関係のない設定を直させずに済む。

## Considered Options

- **モードの名前空間に置いた設定キーだけ知らせない**: 平らな設定キーは、名前空間へ移すまで WARN が残り、移すまでの例外を決まりに書くことになる。却下。
- **INFO に下げる**: 警告の印は消えるが、モードを切り替えるたびに、関係のない通知が並ぶ。却下。
- **使われない側は検証しない**: 値域の外の値が、そのモードに切り替えたときに初めて止まる。却下。
- **ほかの設定との突き合わせも常に当てる**: lane の数を変えると、使っていないモードの値で Run が止まる。却下。
- **組み合わせの片方がモードか有効フラグなら、弱まる構成も知らせない**: `use_tbo` と動的な報酬スケーラで目標が二重に縮む構成が、黙って通る。却下。

## Consequences

- どちらの設定も効いて結果を歪めるか弱める組み合わせ（`use_tbo` と動的な報酬スケーラ）の WARN と、休止そのものの INFO は残す。
- [ADR 0071](0071-warn-means-user-must-fix-and-unread-config-leaves-are-detected.md) の判断（WARN は利用者が直すべき状態に限る、読まれない設定キーは検出する、実体化しなかったカタログ項目は Run のたびには検査しない）は変わらない。使われない側の設定キーも読むので、読まれない設定キーの一覧には出ない。
- PRD117 の D1 が残した、書いた値が今のモードで効かないことを知らせる WARN（文が `Ignored` で始まるものなど）は、この決まりに沿わなくなる。消す仕事は [issue-20261122-d9499f](../management/issues/issue-20261122-d9499f.md) が持つ。
