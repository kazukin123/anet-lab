# トップの階層は、ビルドの入力（src）・実行時の配置（apps）・実行時にできるもの（data）で分け、ビルドは apps へ直接出す

置き場の規則を 1 つにするため、ビルドの入力は `src`、配る形でもある実行時の配置は `apps`、マシンごとに増える Run や利用者の状態は `data`、配らないビルドの出力は `out` に置く。build と install を分ける形は採らず、日常はビルドが `apps` へ直接出す。ビルドしてすぐ動かせることと、開発と配布で同じ配置と同じ bat を使うこと（[ADR 0017](0017-release-zip-mirrors-repo-layout.md)）を保つためで、配る物の組み立てだけが、入れるものを選ぶ。

## Considered Options

- アプリのソースを `apps` に残す: 規則が「ライブラリのソースは `src`、アプリは `apps`」の 2 つになるので採らない。
- 設定をソースの側に置き、ビルドで `apps` へ写す: 設定を直してすぐ走らせる回し方に、写しの手順が挟まるので採らない。
- 実行時のデータを `apps/runner` の下に残す: 配るものと増えるものが同じフォルダに混ざるので採らない。
