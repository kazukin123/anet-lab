# Auto Recolor は選択中だった Run の色を変えず、新しく選んだ Run へ毎回最良の色を配る

[ADR 0041](0041-run-color-is-comparison-role-not-run-identity.md) は `Auto` を維持優先パスとし、選択中の各 Run について、今の色が先行 Run の色から `min(0.16, 今の palette で取れる最良)` 以上離れていれば残すと決めた。
この判定には 2 つの問題があった。

1 つ目は、新しく選んだ Run の今の色が基本色（Run list の先着順で付いた色）であることである。基本色がしきい値を満たせば、もっと離れた色が空いていてもそのまま使われる。
0.16 は「選択 5 本までは初期色に関わらず確保できる下限」として選んだ値で、見分けやすさの目標ではない。
`#2F7DE1` / `#00A99D`（0.183）や `#7A5CFF` / `#C678DD`（0.160）のような組が残り、選択中の色を変えたいわけではない場面でも `Recolor` を押す必要があった。
基本色を一様に引いて 1 本ずつ足す操作では、最も近い組の分離距離の平均が 2〜5 本で 0.32 / 0.25 / 0.22 / 0.20、最悪は常に 0.16 だった（`Recolor` は 0.41 / 0.33 / 0.22 / 0.20）。

2 つ目は、選択中だった Run の色も判定にかけるため、Run を外すと残った Run の色が変わりうることである。
外すと先行 Run の集合が縮んで「今の palette で取れる最良」が上がり、しきい値も上がる。
ADR 0041 が保証した解除安定は 6 本以下でしか成り立たず、1 本ずつ足して作った選択から 1 本外すと、7 本で 24%、8 本以上で 81〜100% の確率で残りの色が変わった。

**`Auto` は、前回 Run 色を解決したときに選択されていなかった Run だけに色を配り、選択中だった Run の色は条件なしに変えない**ことを決定する。
新しく選んだ Run は、基本色や近さを見ずに、選択順に、ほかの選択中 Run の色から最も離れた色を取る。
初回表示で自動選択する最新 Run と、1 本だけを新しく選んだ場合もこれに含め、palette 先頭 `#2F7DE1` を取る。
変えない色は、選択順の位置に関係なく先にすべて確定させてから新しい Run の色を選ぶ。`Select All` は選択を runId 昇順へ並べ直すので、選択順の後ろにある既存 Run の色と重ねないためである。
維持判定が無くなるので、しきい値 `RUN_COLOR_MIN_DISTANCE` は廃止する。
`Recolor` は選択中 Run をすべて新しく選んだ Run として扱う同じ処理とし、選択 1 本でも `#2F7DE1` を配る（ADR 0041 の「選択 1 本以下では何もしない」を改める）。
solo 選択（同じ Run 行の連続 click）は 2 回の click を 1 つの操作として扱う。元から選択中だった Run は色を保ち、選択していなかった Run は新しく選んだ 1 本として `#2F7DE1` を取る。

基本色は workspace 内の位置で決まる色で、graph にはまだ描かれていない。残しても守られるものが無く、分離だけが犠牲になる。
ADR 0041 の Consequences も、基本色が選択した瞬間に上書きされるのを常態としている。
一方、選択中だった Run の色は graph で見ている色そのものである。ADR 0041 が `Auto` で守ろうとした「見ている最中の graph の色が理由なく入れ替わらない」を、条件付きでなく保証するには判定にかけないのが最も単純である。
新しく選んだ Run は毎回その時点で最良の色を取るので、1 本ずつ足していく限り `Recolor` と同じ並びになり、分離距離も `Recolor` と同じになる。
これで役割は「`Auto` = 選択中の色を保ったまま、新しく選んだ Run へ最良の色を配る」「`Recolor` = 選択中の色も含めて組み直す」に分かれる。
solo 選択は 1 回目の click で選択を反転させてから 2 回目で成立する。反転した状態を前回の選択とみなすと、選択中だった Run が新しく選んだ Run になって色が変わり、選択していなかった Run は 1 回目で配られた色のまま残る。
そこで solo 選択の Run だけ、前回の選択を 1 回目の前の状態へ戻してから解決する。

## Considered Options

- **しきい値を上げる（例 0.25）**: 1 定数の変更で済むが、基本色を残す理由が無いことは変わらず、しきい値に原理的な値が無い。Run を外したときに残りの色が変わる問題も残る。却下。
- **選択中だった Run だけをしきい値で判定し、新しく選んだ Run へは最良の色を配る**: 1 つ目の問題は解けるが、2 つ目の問題が残る。却下。
- **選択が変わるたびに `Recolor` と同じ最適配色を行う**: 最も見分けやすいが、途中の Run を外すと後ろの Run の色が入れ替わる。却下。
- **新しく選んだ Run の色を、選択順で前にある Run の色だけから選ぶ**: 処理は 1 回の走査で済むが、`Select All` のように既存 Run が選択順の後ろへ回ると、新しい Run が既存 Run と同じ色を取りうる。却下。
- **`Auto` を ON にした時点で、OFF の間に選んだ Run を新しく選んだ Run として配り直す**: ON にした意図には沿うが、graph に描かれている色が変わる。ON / OFF の切替でも選択中だった Run の色は変えず、組み直しは `Recolor` に任せる。却下。
- **`Recolor` の選択 1 本は何もしないまま残す**: ADR 0041 の決定どおりだが、`Auto` は新しく選んだ 1 本へ `#2F7DE1` を配る。Run を外して 1 本だけ残った Run（例 `#D1D83B`）で `Recolor` を押しても先頭色にならず、ボタンが効かないように見える。却下。
- **solo 選択を 2 回目の click の時点の選択だけで扱う**: 処理は最小だが、選択中だった Run を solo すると色が変わる。却下。

## Consequences

- 新しく選んだ Run の chip は、基本色に関係なく選んだ瞬間に変わる。初回表示の最新 Run も `#2F7DE1` になり、同じ色を基本色に持つ未選択 Run と chip の色が並ぶ（ADR 0041 で許した重複）。
- 選択中だった Run の色は、Run の追加・解除・`Select All`・`Auto` の切替では変わらない。変わるのは `Recolor` を押したときだけである。
- `Auto` OFF で描いた色（基本色）は、ON にしても残る。見分けにくい組が描かれていれば `Recolor` で組み直す。
- 選択を外して選び直した Run は新しく選んだ Run として配り直され、前の色に戻るとは限らない。ほかの選択が同じなら同じ色になる。
- 6 本以上は palette の 20 色に律速される（総当たりの上限は 6 本で 0.178、8 本で 0.148）。palette の拡張は別の決定とする。
- `RUN_COLOR_MIN_DISTANCE` を廃止する。`MetricsViewerClientApp` が前回の解決時の選択を持ち、色を配る Run を 1 つの処理へ渡す（`Auto` は新しく選んだ Run、`Recolor` は選択中の全 Run）。server、HTTP API、`localStorage` は変更しない。
