# reports の下は、記録を作った流れでフォルダに分け、直下に報告を置かない

`reports/` 直下には、survey スキルの出力、論文解説、コード読解、anet の道具の調査が並んでいて、作業の中で分かったことまで足すと、何の記録か分からなくなる。RFD0208 で、survey スキルの出力を `reports/survey/`、paper-details スキルの出力を `reports/paper/`、作業の中で分かったこと（作業ノート）を `reports/notes/` に分け、直下には索引だけを置くことにした。`docs/` の下は GitHub Pages で配信する公開文書なので、作業ノートの置き場にしなかった。

## Considered Options

- **作業ノートを `docs/` の下の新しい正本の置き場にする**: ほかの正本と並び、役割が名前で分かる。`docs/` は公開文書として配信するので、棄却した。
- **`reports/` 直下に混ぜ、ファイル名か索引の見出しで分ける**: 道具を変えずに済む。流れの違う記録が混ざるので、棄却した。
- **出どころ（外から得たか、中で分かったか）で分ける**: 外の調べものを全部 1 か所に集められる。どの skill の出力かで置き場を決めたいので、棄却した。
