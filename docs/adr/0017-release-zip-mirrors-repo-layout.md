# リリース zip はリポジトリ配置のミラーサブセットとする

GitHub Release で配布する実行用パッケージ(bin)のレイアウトを決める必要があった。リリース zip の内部配置は**リポジトリの配置そのまま**(`apps/` + `docs/design/` + `licenses/` のサブセット)とし、起動 bat も開発時と同一のもの(`apps/*.bat`)を同梱する。ビルド出力パス(`apps/metrics-viewer/target/metrics-viewer.jar`)もリリース内でそのまま使う。理由は、配布専用レイアウトを作ると起動スクリプト・ドキュメント・パス参照の二重メンテが発生するため。開発動線とリリース動線が常に同一パスを通ることで、リリース物の起動 bat はリポジトリ内で日常的に検証され続ける。

## Considered Options

- **平坦レイアウト + 専用起動スクリプト**: zip ルートに exe/jar を並べる。見た目は簡潔だが、bat の分岐(開発用/配布用)と `target/` 除去のためのコピー工程が必要になり、配布用 bat はリリース時にしか検証されない。却下。
- **配置ミラー(採用)**: パッケージングは「対象パスをコピーして zip」だけ。bat は無改造で双方に有効。

## Consequences

- リリース zip 内に `bin/Release/` や `target/` というビルド出力ディレクトリ名が残る(許容)。
- bat は作業ディレクトリを `apps/runner` に固定してから実行する規約(どこから起動しても同一挙動)。
- リポジトリのディレクトリを動かす変更は、リリースパッケージング(.github/workflows/release.yml のコピー対象)への追随が必要。
