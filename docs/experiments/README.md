# ハイパーパラメータ探索記録

このディレクトリは、Agent アルゴリズムごとのハイパーパラメータ探索を、再検討可能な履歴として残すためのものです。
完成した結論だけでなく、その時点の `探索観点 → 探索結果 → 考察 → 次の探索` を時系列で記録します。

## ディレクトリ構成

```text
docs/experiments/
└─ <agent-algorithm>/
   ├─ README.md
   └─ <env>/
      ├─ README.md
      └─ <campaign>.md
```

- Agent アルゴリズム単位で、共通する学習機構とハイパーパラメータをまとめる。
- Env 単位で、報酬設計、観測、行動空間、局所解などに依存する結果を分離する。
- campaign 文書は、比較可能な一連の Run lineage または一つの探索テーマを起案単位とする。
- campaign が長くなりすぎた場合は、日付ではなく「比較の前提を引き継げるか」を基準に分割する。

## 記録上の正本

- 実効設定の正本は、各 Run artifact の `config/config_data.txt` とする。
- 到達 step、停止理由、メトリクスは Run artifact を参照する。
- このディレクトリの文書は、artifact から得た証拠、当時の判断、次の検証案を結び付ける索引兼実験台帳とする。
- `docs/runs/` の生成物を複製せず、Run 名と比較条件を記録する。

## campaign 文書の基本形

文書先頭に「現時点のまとめ」を置き、その後に次のブロックを時系列で繰り返します。

1. 探索観点
2. 探索条件・対象 Run
3. 探索結果
4. 考察
5. 次の探索

後続の知見によって当時の解釈が変わっても、過去ブロックを消して完成形へ書き換えません。
代わりに `superseded`、`invalidated` などを追記し、何が現在も有効な証拠かを明示します。

## 状態と確度

- `active`: 現在の主力候補または継続中の探索。
- `completed`: 当初の比較を完了した探索。
- `pending`: 未実行または判定待ち。
- `superseded`: 後続結果により、現在の判断材料としての優先度を下げた探索。
- `invalidated`: 設定反映や比較条件に問題があり、その効果を判定できない探索。

確度は seed 数、同一 checkpoint からの分岐、比較 step、非決定論性などを併記し、単一 Run の小差を一般化しません。

## 知見の書き戻し

採用した知見の要約は[wiki](../wiki/index.md)へまとめる。新しい独自の分析は、先にcampaign文書、またはREADMEの「独自の分析」へ書き、wikiはその正本を出典にする。wikiだけにある知見を作らない。

campaign表は期間・文書・主題・状態の索引とし、長い結果の要約や日付つき追記を積まない。既存記述を整理するときは記述ごとにcampaign本文と突き合わせ、同内容が見つかる要約だけをwikiへ畳む。見つからない独自の分析はREADMEに残す。campaign文書の当時の記録は書き換えない。
