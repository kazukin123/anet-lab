## この文書の読み方

- 実効設定の正本は各 Run の `config/config_data.txt` で、複製を [config/](config/) に置いた。
- 数値は Run の Metrics マスタから `inspect_run.py` で取得した。parameter 数は各 Run の `dot/net.detail.dot` のブロックごとの params の和である。
- **eval の正解率**は `51_eval1/04_accuracy_ema`。eval 1 回は、test の分割から復元抽出で選んだ 100 枚の正解率で（当時の eval は 1 エピソード 100 枚。[PRD 034](../../../memo/done/034_imagecls_batch_input_10prd.md) で今の形に変わった）、その EMA（α 0.01）を読む。
  eval は train step 10 ごとに 1 回、2026-07-06 以降の Run は 50 ごとに 1 回。eval の画像には拡張をかけない。
- **final** は最後の eval の時点の EMA、**peak** は EMA の最大値とその exp step である。学習予算に届かずに止まった Run は、止まった exp step を添える。
- **train** は `38_agent/04_accuracy_ema`（学習 batch の正解率の EMA、α 0.01）。拡張をかけた画像に対する値で、Mixup/CutMix の Run では混ぜる前のラベル 1 つで採点する。
- exp step は学習に使った画像の枚数である。1 train step で `train.num_envs` 枚を集め、それを batch にして 1 回 learn する。この文書の batch は `train.num_envs` である。
- **実時間**は `90_perf/90_elapse_hour` の最終値。exp step/s は、そこまでの exp step を実時間で割った平均である。
- 最終の空間解像度は、config の stem と downsample の stride から求めた（入力 224×224）。ViT と Hybrid はトークンの格子を書いた。
- `51_eval1/04_accuracy_ema` の EMA の窓は eval 約 100 回分で、2026-07-06 以降の Run（eval の間隔 50）は exp step で約 5 倍長い。
- PRD 030 の背景にある拡張後の eval と ConvNeXt の eval・train は、この読み方の final と一致した（探索ブロック 01・03）。

## 探索ブロック 01: 過学習対策（データ拡張と GAP）

### 探索観点

train の正解率が高く eval が低い過学習（[PRD 022](../../../memo/done/022_imagecls_augmentation_10prd.md)・[PRD 023](../../../memo/done/023_imagecls_gap_head_10prd.md) の背景）に対して、train だけのデータ拡張と、最終段の Flatten → GAP2D を確かめる。

### 探索条件・対象 Run

Body は FoodResNet13（ResBlock 4 個、最終の特徴は 28×28×128）。batch 256、学習予算 10M、拡張の `rrc_scale_min` 0.7。2 本の実効設定の差は最終段だけである。

| Run | 最終段 | params |
|---|---|---:|
| `run_20260625-231716_imgcls_022aug` | Flatten > Drop 0.5 > LinearOut | 10.91M |
| `run_20260626-012847_imgcls_023gap` | GAP2D > Drop 0.5 > LinearOut | 0.79M |

### 探索結果

| Run | final（到達） | peak | 8.71M 時点 | train | 実時間 |
|---|---:|---:|---:|---:|---:|
| `run_20260625-231716_imgcls_022aug` | 45.0%（10.0M） | 45.9%（8.22M） | 44.5% | 71.7% | 1.74h |
| `run_20260626-012847_imgcls_023gap` | 61.2%（8.71M で停止） | 62.7%（6.62M） | 61.1% | 73.9% | 1.40h |

- 拡張を入れる前の基準の Run（値は PRD 030 の背景）は Run フォルダが残っておらず、この文書では値を確かめていない。

### 考察

- GAP にすると parameter は約 1/14 になり、eval は同じ 8.71M で 16.6pt 上がった。train の正解率も同じ step で 70.3 → 73.9% と上がったので、PRD 023 が挙げた「容量を削りすぎて train も eval も下がる」は起きなかった。
- 1 本ずつだが、差はブロック 02 の同じ設定の 2 本のずれ（1pt 以下）より 1 桁大きい。

- 同じ条件では ResNet18ish_hr が最も高かった。DropHead と droppath を入れた最終 14×14 の 3 本（hr、mr、Res18_do1）は peak 73.4〜77.1% で、7×7 の 3 本（67.0〜69.0%）を上回った。ただし 7×7 の Body は stem と parameter 数も違う。正則化の無い 14×14（Res18）は 69.6% だった。
- DropHead 0.2 と droppath を一緒に入れると、ResNet18ish は 5.07M で 7.4pt 上がった。DropHead だけを標準の ResNet18 に入れた比較では上がらなかった（7.32M で −0.6pt）。DropHead と droppath のどちらが効いたかは切り分けていない。
- weight decay 0.1 は効かず、7.57M で約 5pt 下がった。
- DropHead と droppath を入れた ResNet 系の 4 本（hr、mr、Res18_do1、Res_ish）は 4.1〜4.6M に peak を付け、そのあと下がった（hr は 10M で −4.6pt）。train の正解率はその間も上がった（hr は 4.5M で 93.3%、10M で 96.5%）。
- 幅を半分にした mr（parameter 約 1/4）は、hr より final で 1.6pt、peak で 3.1pt 低いだけだった。
- ViT は 2M 前後で peak を付けて下がり、train は 95% を超えた。LR を 1e-3 → 5e-4 にしても 1pt 前後しか変わらず、CLS を GAP1D にすると 6pt 前後上がった（2.05M で 6.6pt、6.75M で 5.8pt）。Hybrid は逆に CLS のほうが 4.1pt 高かった。
- 同じ実効設定・同じ seed の 2 本でも、同じ exp step で 0.3〜1.0pt ずれた（deterministic の設定でも）。1pt 前後の差は 1 本ずつの比較では判定しない。

### 考察

- Nano は ResNet18ish_hr と同じ条件で final 57.3%（hr 71.9%）、train 96.6% だった。peak が最後の点にあり、10M でもまだ上がっていた。
- droppath 0.3 と `rrc_scale_min` 0.5 の Femto と Atto は 10M で 65.3〜65.7% で、Nano（droppath 0.1、RRC 0.7）より約 8pt 高い。Nano との差は Body と droppath・RRC を同時に変えたもので、どれが効いたかは切り分けていない。
- Atto と Femto（parameter 1.43 倍）は 10M で 0.4pt の差で、Body を大きくしても上がらなかった。
- batch 128 は 256 より 10M で 1.4pt 高く、train は 4.2pt 低かった（1 本ずつ）。
- stem の stride を 2 にすると、同じ 10M で 5.7pt 上がった。実時間は 10M で 2.6 倍になった。
- 定数 LR の Femto は 10M → 20M で 3.4pt、20M → 26M で peak がさらに 1.3pt 上がり、そのあと 32.2M で 69.0% に下がった。train は 91.3 → 94.2% と上がり続けた。

## 探索ブロック 04: LR の cosine（15M）

### 探索観点

定数 LR では ResNet18ish_hr が peak のあと下がった（ブロック 02）。LR を warmup ＋ cosine で 1e-5 まで下げると、最終の正解率がどうなるかを見る。

## 探索ブロック 05: Mixup/CutMix、学習予算、BF16

### 探索観点

cosine の上に Mixup/CutMix（[PRD 030](../../../memo/done/030_imagecls_mixup_cutmix_10prd.md)）を入れて、学習予算を 15M → 20M・30M に延ばす。BF16（[PRD 033](../../../memo/done/033_imagecls_bf16_head_10prd.md)）で正解率と実時間が変わるかを見る。ConvNeXt は Atto と Femto（どちらも stem 2）で比べる。

### 探索条件・対象 Run

Mixup α 0.2、CutMix α 1.0、適用確率 1.0、CutMix を選ぶ確率 0.5。cosine は学習予算 − 0.5M の長さ。batch 128、`rrc_scale_min` 0.5、eval は train step 50 ごと。

| Run | Body | 学習予算 | 精度 | backend |
|---|---|---|---|---|
| `run_20260706-124351_imgcls_ResNet18HRmix` | ResNet18ish_hr | 20M | FP32 | deterministic |
| `run_20260707-084617_imgcls_ResNet18HR32_30` | ResNet18ish_hr | 30M | FP32 | non-deterministic、fused |
| `run_20260708-020741_imgcls_ResNet18HR` | ResNet18ish_hr | 20M | BF16（learner だけ。eval の Actor は FP32） | non-deterministic、fused |
| `run_20260708-090643_imgcls_CnAttoHR` | ConvNeXt Atto、stem 2 | 20M | BF16（同上） | non-deterministic、fused |
| `run_20260708-210559_imgcls_CnFemtoHR` | ConvNeXt Femto、stem 2 | 20M | BF16（同上） | non-deterministic、fused |

- 124351 と 084617 の実効設定の差は、学習予算（と cosine の長さ）、backend の 2 つの deterministic の設定、`use_fused_optimizer`（084617 にだけキーがある）と、084617 で増えた eval の `clone_model` のキーである。
- 124351 と 020741 の差は、BF16、backend、`use_fused_optimizer`、LinearOut を Body から Head へ移したこと（PRD 033）と、020741 で増えたキー（BN の `force_fp32 = false`、eval の `clone_model`）である。
- 090643 と 210559 の差は Body だけである。
- ブロック 04 の Run（Mixup なし・15M）との差は、Mixup、学習予算、eval の間隔（10 → 50）。Atto はさらに BF16・backend・fused も違う。

### 探索結果

| Run | 4M 時点 | 15M 時点 | 20M 時点 | final | peak | train | 実時間 | exp step/s |
|---|---:|---:|---:|---:|---:|---:|---:|---:|

| Run | `target_prob_mix_norm` | `accuracy_either` | `pred_max_prob` | loss |
|---|---:|---:|---:|---:|
| `run_20260706-124351_imgcls_ResNet18HRmix` | 0.801 | 0.945 | 0.644 | 1.762 |

- `target_prob_mix_norm` は、混ぜた 2 つのラベルに対する確率の重み付き和を、label smoothing を含めた理論上の上限で割った値である。`accuracy_either` は予測が混ぜた 2 つのラベルのどちらかに当たる割合、`pred_max_prob` は予測の最大確率の平均（定義は [image_cls_agent.cpp](../../../../core/anet-core/src/image_cls_agent.cpp) の `UpdateFromBatch`）。

  Mixup なしのブロック 04 の hr も 5〜6M に 74.7% まで下がったが、7〜9M は 76.0% 以上に戻っていた（124351 は 7〜9M も 74.0〜74.2%）。

### 考察

- Mixup/CutMix を入れて 20M に延ばすと、ResNet18ish_hr は Mixup なしの 15M より 2.3pt、Atto は 3.9pt 上がった。どちらも学習予算を同時に延ばしたので、Mixup の分だけを切り出せない。
- 20M の Run の 15M 時点（82.0%）は、Mixup なしで cosine を 15M で終える Run の最終（83.7%）より低かった。30M の Run の 15M 時点はさらに低い 74.5% で、最終は 3 本の中で最も高い。cosine の長さが違う Run は、途中の step では LR が違うので比べない。最終同士で比べる。
- 30M は 20M より 0.4pt 高かった。同じ設定の 2 本のずれ（ブロック 02、0.3〜1.0pt）の中で、backend の設定も違うので、延ばした効果とは判定しない。学習側の `target_prob_mix_norm`・`accuracy_either`・train は 30M のほうが高く、学習側の指標が上がり続けても eval は 20M とほぼ同じだった。
- BF16 の 20M は FP32 の 20M と eval が 0.4pt 差、学習側の指標は小数第 3 位までほぼ同じだった。実時間は 0.67 倍になった。BF16 だけの効果とは言えないが、backend と fused が BF16 の Run と同じ FP32 の 30M（645 exp step/s）と比べても、BF16 は 1.39 倍速かった。
- Mixup ありの ConvNeXt は、Atto と Femto で 0.6pt の差だった。parameter を 1.43 倍にしても上がらず、ResNet18ish_hr との差（2.7〜3.3pt）は残った。
- Mixup の Run の train は 55〜61% で、eval（83〜86%）より低い。train は混ぜる前のラベル 1 つで採点するので、Mixup の Run の収束の判定には使わない。
