## 現時点のまとめ

1. **sticky actions が Breakout で支配的**。0.25 → 0.0 で train 生スコア 42 → 119（2.8 倍）。v5 プリセットのまま回すと 5M step で 42 に飽和し、以降 22M step 分がほぼ無駄になる。sticky 0 では 50M まで伸び続けた。
2. **episodic_life は単独では効果ゼロ**。sticky 0.25 固定で false / true を 27M step 比較し、train 生スコア 42.0 対 41.9、median 41 対 41 で差がない。中間指標（`q_gap_rel` 上昇、`q_max` 低下）は設計どおり動いており、機構は効いているがスコアに繋がらなかった。`lives` が 3.45 対 3.64 と変わらないことが決定的で、死ぬ頻度そのものが改善していない。
3. **sticky 0 では `lives` が明確に上昇する**（3.4 → 4.3）。episodic_life で動かなかった同じ指標が動いたことから、Breakout のプラトーはパドル制御の精度で律速されていたと解釈できる。
4. **eval が wall-clock を支配しうる**。Pong で `interval` 100 → 500 にすると真の throughput が 478 → 1,198 steps/s（2.5 倍）。train 曲線は完全一致しており、差分は eval の実行コストのみ。
5. **num_envs は N=128 が最適**（探索ブロック 06）。実構成 2M ラダーで throughput が N=128 で頭打ち（+9.1%、それ以上は差がブレ幅内）、学習効率は N=128 まで無傷で N=256 から崩れる（−17%）。wall-clock 効率は N=128 が最良（+5.2%）。この結論は現在の learner コストに依存するため、RR / batch / quantile / NN 構成を変えたら再評価が要る。参考として DropMerge は N=256 を採用している。
6. **Breakout 50M（sticky 0 / episodic_life true / noop 0 / fire_reset false）で train 生スコア 119.4、eval1 115.7**。43-44M で train 140.1 のピークを打ち、以降 -15% で 119 台に安定。100 点超が 50.1%、300 点超が 3.6%、ピーク期の max 427（1 画面 432 点にほぼ到達）。
7. Pong は v5 プリセット・num_envs 64 で 1M step から動き出し、2.5M で eval1 +7.10。
8. **NN は IMPALA-CNN を採用**（探索ブロック 07）。同じ 50M で train 生スコア 134.7 対 121.2、eval1 147.7 対 115.7。差の本体はサンプル効率で、中盤（10-25M）に 2 倍前後がつく。加えて **Nature CNN は 44M でピークアウトして −12.0% 劣化するのに対し IMPALA は −1.6% で、ピークが最後尾にあり 50M でも飽和していない**。高得点の裾も違い、≥400 点は IMPALA だけが出す（1.0% 対 0.0%、max 431 対 384）。
9. **`fire_reset = false` は Breakout で無報酬 step を生む**。ライフ喪失でボールが消え FIRE を押すまで再投入されないため、1 ゲームに 4 回、エージェントが自力で FIRE を選ぶまで待ちが入る。上記 8 までの全 Run がこの条件下にある。2026-08-18 に life-loss 後の soft-reset でも FIRE 系列を打つよう実装を修正した（`fire_reset=false` では挙動不変）。
10. **100M 長期で eval1 best window 337.5、HNS57 1166%**（探索ブロック 08）。Nature DQN の Breakout 401.2（HNS57 換算 1387%）の 84% に相当する。50M 以降で一段上のレジームに入り、eval1 が 50M までの最高 160.1 から 2 倍超へ伸びた。`fire_reset` の A/B は 0-50M で交差パターン（中盤 −30%、終盤拮抗、eval で逆転）となり **判定保留**。fire_reset は env 力学を変えるため単一 seed では軌道分岐と切り分けられない。
11. **ピークアウト劣化が 3 例目**。Nature CNN −12.0%（44M）、IMPALA fire_off −1.6%（49.4M、未飽和で終了）、IMPALA fire_on −19.9%（66.8M）。長く回すと必ずピークを打ち −10〜20% 落ちる。なお **Nature の Methods は評価値について "the highest average episode score is reported" と明記**しており、401.2 も best checkpoint の値である。比較値は best window で取るのが土俵として正しい。

## 探索ブロック 01: num_envs

**記録時点:** 2026-08-15、Pong 2.5M
**状態:** superseded（探索ブロック 05・06 が実測で置き換えた）。wall-clock 比較は invalidated（PRD 053 の eval 発火バグによる）。学習効率の傾向（大きい N が不利）はブロック 06 で再現された
**確度:** low。single-seed、Pong のみ

### 探索観点

num_envs をいくつに置くか。Random Policy によるラダー測定（8〜1024）で env スループット天井を測り、実構成での必要量とのマージンで決める。

### 探索結果

Random Policy ラダーの `exp_step_per_sec` は num_envs に対し単調増加（n32 5.1k → n512 11.5k → n1024 12.1k）。しかし実構成では learner 律速であり、この天井は一度も binding しない。

実構成 n512 対 n64 の 2.5M 比較:

| | n512 | n64 |
|---|---|---|
| eval1 [2.0-2.5M] | **-5.79** | **+7.10** |
| eval2 [2.0-2.5M] | -5.31 | +6.06 |
| train score EMA @2.5M | -19.45 | -13.16 |
| episode_len @2.5M | 3,093 | 5,342 |
| 真の throughput | 1,264 steps/s | 478 steps/s |

wall-clock では n512 が 2.65 倍速く見えたが、これは eval 発火頻度の差によるものだった（n512 は `LCM(16,100)=400` 更新周期、n64 は 100 更新周期で 4 倍発火）。n64 の eval interval を 500 にして頻度を揃えると 1,198 steps/s となり、n512 の 1,264 steps/s とほぼ一致する。

### 考察

学習効率の差は実在する。lane あたりの進行量が n512 で 4,878 step（完了エピソード 3.5 本）に対し n64 は 38,995 step（18.7 本）であり、同時に終端する lane 数の実測が n512 2.98 / n64 1.11 と、n512 では lane 位相が揃っている。`noop_max=0` で全 lane が同一初期状態から同時発進し、かつ lane あたりのエピソード数が少ないため位相がほどけない。RB 1M を per-lane 時間で見ると n512 は 2,048 lane-step 分しか覆わず、状態カバレッジが薄くなる。

同一 config の反復（eval interval のみ違う 2 Run）で train 曲線が小数以下まで完全一致したため、この環境での Run 間ブレは実質ゼロであり、n512 対 n64 の差はノイズではなく num_envs 由来と確定できる。

### 状態

num_envs の測定は eval 発火バグの影響下で行われ、値の解釈が複雑になった。PRD 053 実装後に探索ブロック 05・06 で再取得し、本ブロックは superseded とする。ただし「lane 位相の同期が大きい N の学習効率を下げる」という機序はブロック 06 でも再現しており、その部分は現在も有効な証拠である。

## 探索ブロック 02: eval interval の wall-clock 影響

**記録時点:** 2026-08-15、Pong 2.5M
**状態:** completed
**確度:** high。同一 config の反復で train 曲線が完全一致

### 探索観点

eval が wall-clock をどれだけ食っているか。

### 探索結果

num_envs 64 固定で eval interval のみ 100 → 500 に変更:

| | interval 100 | interval 500 |
|---|---|---|
| eval 発火間隔 | 3,200 exp_step | 16,000 exp_step |
| eval エピソード総量 | 3.24M single-env step | 0.64M |
| 真の throughput | 478 steps/s | **1,198 steps/s** |
| 2.5M 到達 | 1.452h | **0.580h** |
| train score EMA @2.5M | -13.16 | **-13.16**（完全一致） |

`exp_step_per_sec` メトリクスの表示値は 1,830 対 1,531 で、真値（478 対 1,198）と乖離していた。旧実装は 200ms 窓の瞬間値を時間重みなしで拾うため、stall 区間が観測から抜けていた（PRD 053 で修正）。

### 考察

train 曲線・loss・episode_len が小数以下まで一致したことから、eval 頻度は学習に一切影響せず、差分は純粋に eval の実行コストである。eval エピソード長はスキル向上に伴って伸びる（Pong で 764 → 5,342 step）ため、固定 interval では Run 後期ほど eval が高くつく。interval 100 の後期（2.0-2.5M）は 334 steps/s まで落ちた。

## 探索ブロック 03: Breakout プロトコル（sticky / episodic_life）

**記録時点:** 2026-08-16
**状態:** completed
**確度:** medium。single-seed だが、飽和後 20M step 以上の平均で判定しており差は明瞭

### 探索観点

v5 プリセット（Machado 2018 準拠）で Breakout が 5M step・42 点で飽和した。文献値（Nature DQN 401.2）との差が大きく、プロトコル条件のどれが効いているかを切り分ける。

### 探索条件

`E` 層で 1 要素ずつ変更。ベースラインは v5（sticky 0.25 / noop 0 / episodic_life false / fire_reset false）。

### 探索結果

**episodic_life（sticky 0.25 固定、27M / 29M）**

| 指標（直近 3M） | false | true |
|---|---|---|
| train 生スコア mean | 42.0 | 41.9 |
| median | 41 | 41 |
| p90 | 59 | 63 |
| max | 229 | 210 |
| eval1（直近 5M） | 46.1 | 43.4 |
| `lives` | 3.45 | 3.64 |
| `q_max_mean` @25M | 2.33 | 1.60 |
| `q_gap_rel` @25M | 0.010 | 0.018 |
| `loss_ema` @25M | 0.064 | 0.164 |

1M ごとの推移でも、序盤（〜3M）は true がやや速く、5〜15M は false が上、20M 以降は拮抗し、両者とも 41〜43 の同じプラトーに収束した。

**sticky（episodic_life true 固定、50M）**

| | sticky 0.25 | sticky 0.0 |
|---|---|---|
| train 生スコア mean（直近 3M） | 41.9 | **119.4** |
| median | 41 | 100 |
| p90 | 63 | 247 |
| max | 210 | 384（ピーク期 427） |
| 100 点超の割合 | — | 50.1% |
| 200 点超 | — | 14.9% |
| 300 点超 | — | 3.6% |
| eval1（直近 5M） | 43.4 | 115.7 |
| `lives` | 3.4〜3.6 で横ばい | **4.03 → 4.33 と上昇** |
| `game_len` | 約 1,030 | 1,509〜2,579 |

### 考察

episodic_life は `q_max`（1 ライフ分の価値へ低下）と `q_gap_rel`（行動間の価値差が拡大）に設計どおりの変化を与えたが、`lives` が動かなかった。ボールを落とす直前の状態ではパドルが既に間に合わない位置にあり、そこへ負の信号を積んでも「先回りする」能力は上がらなかったと解釈できる。

sticky 0 では同じ `lives` が明確に上昇した。sticky は 4 回に 1 回前の行動が固着するため、パドルの精密制御を直接阻害する。Breakout は狙った列に当て続けてトンネルを掘る戦略が高得点の要件であり、そこが塞がれていた。

episodic_life=true 下では eval の記録周期が 5 倍（160,000 → 800,000 exp_step）になる。`RunEvaluationEpisode` が最初の done で停止し、life-loss done ではスコアが未確定（NaN）で記録されないため。記録時点の `lives` 平均が 3.04 で、理論値 (4+3+2+1+5)/5 = 3.0 と一致した。**値そのものは正しく、周期だけが 5 倍になる**（生スコアは soft-reset で切れない）。

## 探索ブロック 04: Breakout 50M 長期

**記録時点:** 2026-08-17
**状態:** completed
**確度:** medium。single-seed、eval は 1 本評価

### 探索観点

sticky 0 で飽和が解けた後、どこまで伸びるか。文献の比較点（Nature DQN の 50M steps = 200M emulator frames）まで回す。

### 探索結果

`run_20260816-162140_atari_breakout`、50,017,728 exp_step、8.30h、真の throughput 1,674 steps/s。

train 生スコアの 1M ごと平均は 4 フェーズに分かれた。

| 区間 | 推移 | 特徴 |
|---|---|---|
| 0M-5M | 0 → 43 | 急上昇 |
| 5M-30M | 43 → 77 | 緩やか（約 +1.3/M） |
| 30M-44M | 77 → 140 | 再加速。29-30M で +14.3、35-36M で +19.5 の階段状ジャンプ |
| 44M-50M | 140 → 119 | ピークアウト後 -15% で横ばい |

ピークアウトは train 側で一貫している（43-44M 140.1 → 44-45M 126.1 → 47-48M 119.9 → 49-50M 119.1）。eval1 の window 平均も 195.3（42-45M）→ 142.2（45-47M）→ 80.3（47-50M）と低下した。

max スコアは 360 → 402 → 427 と推移し、1 画面 432 点にほぼ到達した。

マイルストーン:

| step | score_ema | game_len | lives | q_max | q_gap_rel | loss_ema |
|---|---|---|---|---|---|---|
| 1M | 5.73 | 544 | 3.20 | 0.618 | 0.1178 | 0.1630 |
| 5M | 38.84 | 1,244 | 4.03 | 1.684 | 0.0395 | 0.1649 |
| 10M | 43.71 | 1,177 | 3.33 | 1.729 | 0.0442 | 0.1531 |
| 20M | 53.98 | 1,611 | 3.67 | 1.844 | 0.0379 | 0.1315 |
| 25M | 59.93 | 1,509 | 4.33 | 1.904 | 0.0603 | 0.1507 |

### 考察

30M 以降の階段状ジャンプと max スコアの上昇は、トンネル戦略の獲得と整合する。1 画面クリア相当（432 点）に手が届いており、300 点超が 3.6% 出ている。

44M 以降の低下は train・eval が独立に同じ向きに動いているため、単独 Run のノイズではなく実際の性能低下と見る。DQN 系で長期学習の後半に現れる典型的な劣化の範囲であり、コラプスではない。ただし**最終時点の値を成績として採ると、ピーク時より約 15% 低く出る**。

文献との比較には条件差が残る。

| 項目 | Nature DQN | 本 Run |
|---|---|---|
| スコア | 401.2 | 119.4（train）/ 115.7（eval1） |
| 学習量 | 50M steps（= 200M emulator frames） | 50.0M exp_step（同一） |
| sticky | 0.0 | 0.0 |
| episodic_life | true | true |
| noop_max | 30 | **0** |
| fire_reset | true | **false** |
| 評価 | 30 本平均、ε=0.05、18,000 frames 上限 | **1 本**、eval1=target net / eval2=policy、108,000 frames 上限 |
| 参考 | 人間 31.8、random 1.7 | — |

Nature DQN の「50 million frames（approximately 38 days of game experience）」は agent step を指す。50M agent step × frame_skip 4 = 200M emulator frames、÷60fps = 38.6 日で論文記述と整合するため、本フレームワークの `exp_step` と直接対応する。

eval1 の直近 7 点は `[148, 227, 59, 135, 77, 44, 120]` で 44〜227 の幅がある。1 本評価では平均値の推定精度が 30 本平均と比較できる水準にない。

## 探索ブロック 05: num_envs の env 天井（Random Policy）

**記録時点:** 2026-08-17
**状態:** completed
**確度:** medium。single-seed、各 N 1 本だが定常性は確認済み

### 探索観点

num_envs の上限を決めるため、まず env 側だけのスループット天井を測る。実構成の必要量とのマージンを見るための基準値。

### 探索条件

`DefaultDQNAgent.$ = DefaultDQNAgent.baseline > B`（`eps 1.0` 固定 / `learner.alpha = 0` / `update_warmup_steps = 999,999,999` により **learner が一度も動かない**）。Breakout / v5 / 各 195,000 exp_step。

### 探索結果

| N | true steps/s | 前段比 | 対 N=8 の線形効率 | lane あたり step |
|---|---|---|---|---|
| 8 | 2,582 | — | 100% | 24,375 |
| 16 | 3,788 | ×1.47 | 73% | 12,188 |

## 探索ブロック 06: num_envs の実構成ラダー（学習あり）

**記録時点:** 2026-08-17
**状態:** completed
**確度:** medium-high。single-seed だが 7 点 × 2 周で再現性を確認、n64 を各周の先頭・末尾に置いてドリフト検証済み

### 探索観点

learner を含む実構成で num_envs を決める。ブロック 05 の天井に対する実際の利用率と、exp_step あたりの学習効率の両方を同時に測る。

### 探索条件

Breakout / v5 素（sticky 0.25、episodic_life false）/ BF16 learner / `backend.non-deterministic` / `main_runner_type = pipeline` / **eval OFF**（`train.eval_schedule.[eval1,eval2].interval = 0`）/ 各 2,000,000 exp_step。

eval を切ったのは、`eval_batch_size = 1` のため eval コストが num_envs に依存せず、大きい N ほど相対コストが下がって系統誤差になるため。

2M にしたのは RB capacity 1,048,576 を超えさせるため。前半 0-1M は eviction が起きず、後半 1M-2M が実運用条件になる。

順序は `64a → 32 → 128 → 256 → 512 → 1024 → 64b` を 2 周。

### 探索結果

**測定の妥当性: 1 周目の前半は暖機で系統的に遅い。**

| N | 1 周目（後半 1M-2M） | 2 周目 | 差 |
|---|---|---|---|
| 64a | 2,081 | 2,467 | +18.6% |
| 32 | 2,101 | 2,516 | +19.7% |
| 128 | 2,329 | 2,709 | +16.3% |
| 256 | 2,301 | 2,647 | +15.0% |
| 512 | 2,575 | 2,668 | +3.6% |
| 1024 | 2,566 | 2,694 | +5.0% |
| 64b | 2,457 | 2,499 | +1.7% |

1 周目の 5 本目（512）以降は 2 周目と一致する。**最初の 4 本が 15〜20% 遅い**。以下は安定区間（2 周目 + 1 周目 64b）で評価する。

**throughput は N=128 で頭打ち。**

| N | 後半 throughput | n64 比 |
|---|---|---|
| 32 | 2,516 | +1.3% |
| 64 | 2,483（3 本平均） | 基準 |
| 128 | 2,709 | +9.1% |
| 256 | 2,647 | +6.6% |
| 512 | 2,668 | +7.5% |
| 1024 | 2,694 | +8.5% |

N=128 以上は 2,647〜2,709 に収まり、差 ±1.2% は同一設定のブレ幅（2 周目 n64 の 2 本で 1.3%）内。

**学習効率は N=256 から崩れる。**

| N | 2M 時点 train 生スコア EMA（2 周平均） | 2 周のレンジ | 完了ゲーム数 |
|---|---|---|---|
| 32 | 20.34 | [20.08, 20.60] | 3,680 |
| 64 | 19.52（4 本平均） | [18.49, 20.94] | 3,508 |
| 128 | 19.36 | [19.33, 19.38] | 3,200 |
| 256 | 16.17 | [16.09, 16.26] | 2,822 |
| 512 | 11.91 | [11.26, 12.57] | 2,132 |
| 1024 | 6.42 | [6.27, 6.57] | 1,324 |

N=128 と N=256 はそれぞれ 2 周で ±0.3% に収まっており、両者の差 −17% は確実に有意。n64 のみレンジが 12.6% と広いのは、lane 数が少なく train 平均のサンプルノイズが大きいため。

**wall-clock 効率（throughput × 学習、n64 基準）**

| N | throughput | 学習 | 積 |
|---|---|---|---|
| 32 | 97.1% | 104.2% | 101.3% |
| 64 | 100.0% | 100.0% | 100.0% |
| 128 | 106.0% | 99.2% | **105.2%** |
| 256 | 104.1% | 82.8% | 86.3% |
| 512 | 110.3% | 61.0% | 67.3% |
| 1024 | 110.7% | 32.9% | 36.4% |

### 考察

**N=128 を採用する。** throughput が +9% 上がって学習効率は無傷（−0.8% はブレ幅内）。N=256 以上は throughput が伸びないまま学習だけ落ちるため、選ぶ理由がない。

学習効率の劣化は完了ゲーム数と対応している（N=256 で −16%、N=1024 で −62%）。同じ exp_step を集めても lane あたりの進行が浅いとゲームが完了せず、エピソード終端という学習信号が減る。根にあるのはブロック 01 と同じ lane 位相の同期で、`noop_max = 0` により全 lane が同一初期状態から同時発進する構成に起因する。

env 天井（ブロック 05）に対する実構成の利用率は N=64 で 31%、N=256 で 25% であり、**env は律速していない**。N を上げて速くなる分は env の並列度ではなく、actor forward が batch N で 1 回にまとまることによる step あたりコストの低下と考えられる。それが N=128 で頭打ちになるのは、そこから先は learner 側が律速に回るため。

RB が満杯になる後半では throughput が 14.5〜20% 落ちる。2 周目では N 依存の傾向はない（1 周目で見えた「N が大きいほど RB コストが大きい」は暖機の artifact であり、invalidated）。

本結論は現在の learner コストに依存する。RR / batch / num_quantiles / NN 構成を変えると env と learn のバランスが移動するため、そのときは再評価が要る。メモリ消費も N に比例して増える（N=1024 でも本機では収まった）。参考として DropMerge は N=256 を採用している。

## 探索ブロック 07: NN 構成（Nature CNN vs IMPALA-CNN）

**記録時点:** 2026-08-17
**状態:** completed
**確度:** medium。single-seed 1 本ずつだが、差が大きく曲線全体で一貫している

### 探索観点

Breakout が 50M で 119 点に留まり、文献（Nature DQN 401.2）と開きがある。NN の表現力が律速かを確かめる。

### 探索条件

`net.branch.[main_feature].$` を `AtariNature`（論文と同一の Nature CNN）と `AtariImpala`（IMPALA-CNN、Conv16 + ResBlock×2 → Conv32 + ResBlock×2 → Conv32 + ResBlock×2）で振る。env は sticky 0.0 / episodic_life true / noop 0 / fire_reset false、各 50M。

**速度設定が揃っていない**: Nature 側（`run_20260816-162140`）は BF16 なし・`backend` 既定、IMPALA 側は BF16 + `backend.non-deterministic`、num_envs も 64 対 128。したがって throughput（1,674 対 1,786 steps/s）は NN の重さの比較にならない。exp_step 軸の学習比較のみ有効。

### 考察

差の本体は**サンプル効率**である。中盤（10-25M）で 2 倍前後がつくが、Nature CNN は 35M 以降に急追し 40-45M で一度逆転する。したがって IMPALA の優位は表現力の天井そのものではなく、同じ経験からより速く学べる点にある。

決定的なのは**終盤の挙動**で、Nature CNN は 44M でピークアウトして 12% 劣化するのに対し、IMPALA はピークが最後尾（49.4M）にあり劣化しない。50M で飽和していないため、より長い予算では差が開く可能性がある。

`grad_clip_ratio` がこれを裏付ける。Nature CNN は 50M 時点で clip 発動が 9% まで落ちており、勾配が小さくなって停滞している。IMPALA は 74% で clip され続けており、まだ大きな勾配が出ている＝学習が進行中。同時に、IMPALA は `grad_clip_tau = 5`（baseline 値、Atari 用に未検証）に 74% の頻度で頭を押さえられた状態でこの成績を出している。

高得点の裾も質的に違う。median はほぼ同じ（100 対 101）だが p90 以上で開き、**1 画面クリア（432 点）に到達する試行は IMPALA だけが出す**（max 431、≥400 が 1.0%）。Nature CNN は 50M を通じて 400 点に一度も届かなかった。

なお両 Run とも `fire_reset = false` であり、ライフ喪失後にボールが再投入されず、エージェントが自力で FIRE を選ぶまで無報酬 step が流れる条件下にある（Breakout は 1 ゲームに 4 回ライフを失う）。この分のハンデは両者に等しくかかっている。

### 考察

**A/B は 0-50M では判定できない。** 中盤で fire_on が −30% 劣後し、終盤で拮抗し、eval で逆転する交差パターンになった。`fire_reset` は env 力学そのものを変える（life-loss 後に自動でボールが投入される）ため、同一 seed でも軌道が完全に分岐する。中盤の差はトンネル戦略の獲得時期のずれ（fire_off ≈30M / fire_on ≈40M）として説明でき、終盤の拮抗と eval の逆転がそれを支持する。単一 seed では効果と軌道分岐を切り分けられない。

**50M 以降が本題である。** eval1 の best window 337.5 は fire_off の全区間最高（160.1）の 2 倍超で、HNS57 1166%。Nature DQN の Breakout 401.2（HNS57 換算 1387%）の 84% に相当する。ただし 50M 以降は対照が無いため、この伸びが `fire_reset` の寄与か単に長く回した結果かは分離できない。

**ピークアウト劣化が 3 例目。** fire_off が劣化しなかった（−1.6%）のはピーク直後に Run を終えたためで、fire_on を 102M まで回すと 66.8M でピークを打ち 19.9% 落ちた。探索ブロック 04（Nature CNN −12.0% @44M）と合わせ、**長く回すと必ずピークを打ち −10〜20% 落ちる**パターンが 3 例で揃った。両 Run とも `per_beta_step` が Run 長の 10〜20% で飽和しており、PER の重要度サンプリング補正が残り 80% 以上の期間で最大値に張り付いた状態にある。

**文献はピーク値で報告している。** Mnih et al. 2015 の Methods は評価について "the highest average episode score is reported" と明記しており、401.2 も best checkpoint の値である。したがって本記録でも比較値は best window で取るのが土俵として正しく、現在の到達点は「eval1 337.5 / HNS57 1166%」となる。
