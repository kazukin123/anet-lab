## 現時点のまとめ

1. **sticky actions が Breakout で支配的**。0.25 → 0.0 で train 生スコア 42 → 119（2.8 倍）。v5 プリセットのまま回すと 5M step で 42 に飽和し、以降 22M step 分がほぼ無駄になる。sticky 0 では 50M まで伸び続けた。
2. **episodic_life は単独では効果ゼロ**。sticky 0.25 固定で false / true を 27M step 比較し、train 生スコア 42.0 対 41.9、median 41 対 41 で差がない。中間指標（`q_gap_rel` 上昇、`q_max` 低下）は設計どおり動いており、機構は効いているがスコアに繋がらなかった。`lives` が 3.45 対 3.64 と変わらないことが決定的で、死ぬ頻度そのものが改善していない。
3. **sticky 0 では `lives` が明確に上昇する**（3.4 → 4.3）。episodic_life で動かなかった同じ指標が動いたことから、Breakout のプラトーはパドル制御の精度で律速されていたと解釈できる。
4. **eval が wall-clock を支配しうる**。Pong で `interval` 100 → 500 にすると真の throughput が 478 → 1,198 steps/s（2.5 倍）。train 曲線は完全一致しており、差分は eval の実行コストのみ。
5. **num_envs は N=128 が最適**（探索ブロック 06）。実構成 2M ラダーで throughput が N=128 で頭打ち（+9.1%、それ以上は差がブレ幅内）、学習効率は N=128 まで無傷で N=256 から崩れる（−17%）。wall-clock 効率は N=128 が最良（+5.2%）。この結論は現在の learner コストに依存するため、RR / batch / quantile / NN 構成を変えたら再評価が要る。参考として DropMerge は N=256 を採用している。
6. **Breakout 50M（sticky 0 / episodic_life true / noop 0 / fire_reset false）で train 生スコア 119.4、eval1 115.7**。43-44M で train 140.1 のピークを打ち、以降 -15% で 119 台に安定。100 点超が 50.1%、300 点超が 3.6%、ピーク期の max 427（1 画面 432 点にほぼ到達）。
7. Pong は v5 プリセット・num_envs 64 で 1M step から動き出し、2.5M で eval1 +7.10。
8. **NN は IMPALA-CNN を採用**（探索ブロック 07）。同じ 50M で train 生スコア 134.7 対 121.2、eval1 147.7 対 115.7。差の本体はサンプル効率で、中盤（10-25M）に 2 倍前後がつく。加えて **Nature CNN は 44M でピークアウトして −12.0% 劣化するのに対し IMPALA は −1.6% で、ピークが最後尾にあり 50M でも飽和していない**。高得点の裾も違い、≥400 点は IMPALA だけが出す（1.0% 対 0.0%、max 431 対 384）。
9. **`fire_reset = false` は Breakout で無報酬 step を生む**。ライフ喪失でボールが消え FIRE を押すまで再投入されないため、1 ゲームに 4 回、エージェントが自力で FIRE を選ぶまで待ちが入る。上記 8 までの全 Run がこの条件下にある。2026-08-18 に life-loss 後の soft-reset でも FIRE 系列を打つよう実装を修正した（`fire_reset=false` では挙動不変）。
10. **100M 長期で eval1 best window 337.5、HNS57 1166%**（探索ブロック 08）。Nature DQN の Breakout 401.2（HNS57 換算 1387%）の 84% に相当する。50M 以降で一段上のレジームに入り、eval1 が 50M までの最高 160.1 から 2 倍超へ伸びた。`fire_reset` の A/B は 0-50M で交差パターン（中盤 −30%、終盤拮抗、eval で逆転）となり **判定保留**。fire_reset は env 力学を変えるため単一 seed では軌道分岐と切り分けられない。
11. **ピークアウト劣化は 6 例観測**。Nature CNN −12.0%（44M）、IMPALA fire_off −1.6%（49.4M、未飽和で終了）、IMPALA fire_on −19.9%（66.8M）、b50 −16.8%（80.6M）、tau30 −25.3%（91.5M）、wd01 −29.5%（38.4M）。ただし **tau30 は train EMA の値だけが落ちており、median と 432 超え率は最終 window が最高値**（323 / 16.14%）で、b50 の実質的な崩れ（最終 window で median 134）とは別物である。EMA ピークは一過性のスパイクを拾うため、劣化の判定は分布側（median / 432 超え率）で行うべき。なお **Nature の Methods は評価値について "the highest average episode score is reported" と明記**しており、401.2 も best checkpoint の値である。
12. **ViT ハイブリッドは exp_step 軸では優位だが、throughput −46% で相殺される**（探索ブロック 09）。壁時計 12.6h を揃えると eval1 は IMPALA 419.2 対 ViT 348.4 で逆転する。ViT の優位の実体は **ε 摂動への頑健性**で、同一重みから ε=0.01 を外すと IMPALA は 1.82 倍に跳ね、ViT は 0.99 倍で変わらない。IMPALA は後期に二峰化し（45-50M で p25 60 / median 97 / p75 323）、この下側の峰が「ポカミス」として観測される。**ただしこの測定は両腕 `grad_clip_tau = 5` で行っており、tau = 30 で揃えると効果量は 3 分の 1 に縮む（探索ブロック 14）。**
13. **PER beta スケジュールは `per_beta_step` 10M < 50M**（探索ブロック 10）。30M 以降で開き、30-40M の train 生スコアが 80.9 対 134.1。**予算 100M に対しても `per_beta_step = 50M` のままが最良**で、「総予算に合わせる」という当初の運用則は実測が反証した。beta とクリップ飽和の交絡は探索ブロック 12 で解けた（飽和は利益ではなく handicap だった）。`per_beta_end = 0.55` は 50M 時点では 50M 条件と優劣が付かない。
14. **Breakout 100M で eval1 直近 20 本平均 411.2、単発最高 753**（探索ブロック 11）。1 画面（432 点）超えは 40M まで 0 件だったのが 90-100M で 9.99% まで上がり、max 812。ただし測定条件は Nature（30 本平均・ε=0.05・no-op ランダムスタート）より本記録側に有利であり、同列には置けない。
15. **`grad_clip_tau` は 5 ではなく 30**（探索ブロック 12）。実測 `grad_norm_ema` が 6.0〜15.4 なのに対し tau=5 は低すぎ、`clip_ratio` 0.45〜0.99 で毎 update 発動していた。**毎回発動する安全弁は安全弁ではなく正規化器**であり、更新が方向のみを持ち大きさを失う。tau=30 にすると clip_ratio は全区間 0.01〜0.03 になり、1 画面（432 点）超えが 40-50M → **30-40M** と前倒し、90-100M で **16.14% 対 5.60%**、median **323 対 134**。throughput は同等。beta の効きがクリップ飽和経由という仮説はこれで否定された。
16. **`weight_decay = 0.1` は不採用**（探索ブロック 13）。0-30M では +40〜99% と大きく先行するが 30M で交差し、45-50M で **−43.4%**。1 画面超えは全期間 0.09%（tau30 は 5.12%）で壁をほぼ破れない。**機序自体は働いており**、中央値を揃えた比較で `q_gap/q_max` が 0.0301 → 0.0225（−25%）、loss 1.26 → 0.69 と Q は狙いどおり滑らかになった。**それでも成績は落ちた**ため、Q の過鋭化は症状であって直接下げにいく対象ではないと結論する。
17. **eval1（target net）は全 Run で eval2（online net）よりスコアも安定性も上**。`soft_update_tau = 0.001` の重み EMA が Polyak 平均として働く。比は構成が良くなるほど 1 に近づき（tau30 で 1.06、同 step 対比較の eval1 勝率 48.3%）、**online net の健全性指標として使える**。文献比較には eval2 を用いる。
18. **ViT の効果は分布の下側に限られ、greedy 評価には出ない**（探索ブロック 14）。`grad_clip_tau = 30` で揃えると 35-40M の train median 比は **+57%**（tau=5 では +166%）。p25 は +124%（148 対 66）だが **p75 / p90 と 1 画面超え率は IMPALA が上回り**（391 / 426 対 377 / 408、40-45M で 2.41% 対 0.71%）、eval1 40-50M は 331.4 対 314.0 でブレ幅内。**ViT は下振れを潰す装置であって上限を上げる装置ではない**。軽量版（d96 / 2 層 / ff 384）は 44.4M で頭打ちになり、d128 / 4 層は 50M 時点でまだ上昇中だった。
19. **現在の eval 設定は NN 構成の A/B を判定できない**（探索ブロック 14）。確率的要素が皆無で、ある重みに対する eval は毎回同一の 1 軌道になる。40-50M の eval1 で 5% の差（331.4 対 314.0）が判定不能だったのはこの構造による。
20. **崩壊の正体は可塑性喪失で、レバーは `replay_ratio`**（探索ブロック 15）。BTR 準拠バンドル（IQN + IMPALA Scale=2 + γ 0.997）は **2.5M step で median 335** に達し、旧ベースラインが 101M で記録した最高値 332 を **約 38 分の 1 のサンプル**で超えたが、その後崩壊した。`weight_decay` / プロトコル / `per_beta_step` / `replay_capacity` / BF16 を単変数で順に排除し、**`replay_ratio` 8 → 4 で解決**。勾配 step 数で揃えるとピークが 197 → 295（+50%）、底が対ピーク 37.6% → 47.5% で回復もする。機序も直接測れており、同一勾配 step・同一 `q_max`（6.64 対 6.65）で **`q_gap` が 2 倍**（0.0679 対 0.1361）。throughput も 1,047 → 2,063 steps/s で**両軸で勝ち**。γ = 0.997 を使う BTR と BBF は**どちらも可塑性保護機構（Spectral Norm / reset）を持っており、本コードベースはどちらも未実装**である。
21. **v5 の eval は ε = 0 だと FIRE デッドロックに落ちる**（探索ブロック 16）。`fire_reset = false` + Greedy の組み合わせで、ボール未投入の局面から抜けられず上限 27,000 step まで空転する（`lives` 5.00 が証拠）。sticky は「直前行動の繰り返し」なので脱出手段にならない。**`q_gap` が大きい良い方策ほど発生率が高い**（RR4 24% 対 RR8 8%）。eval ε = 0.01（BTR 値）で解消する。
22. **RR=4 は 200M frames でも崩壊しないが、30M で天井を打つ**（探索ブロック 17）。50M / 6.07h を完走し、探索ブロック 15 の崩壊署名（ピーク後劣化・識別性崩壊・勾配縮小・loss 縮小・`q_max` 頭打ち）はどれも出なかった。ただし **train 生スコアの window 平均は 30M 以降 4 窓で 246.8 / 242.7 / 247.5 / 246.0 と完全に横ばい**で、分布の形（CV・p25・p90・`<100` 率）も動かない。その間 td_mean 0.332 → 0.352、grad_norm 1.61 → 1.72、loss 0.241 → 0.267 と学習側は上昇しており、**動いているのに前に進まない**状態である。throughput は 200M frames / 6.07h で BTR（同 frames / 12h）の約 2 倍。
23. **低スコア裾は予算では消えず、アーキでだけ動く**（探索ブロック 18）。低スコア帯の実体は「停止」ではなく「短命」で、`score<50` かつ `game_len>3000` は 0 本、train 側に FIRE デッドロックは 1 本も無い。tau30 の `<100` は 70M 以降 33.8% → 33.9% で飽和する一方、同じ Run の `≥432` は 1.0% → 17.4% と伸び続ける。**「上手いエピソードは伸びるがポカる率は下がらない」という分離**が起きている。同一 protocol・同一 window で `<100` は ViT 13.5% 対 IMPALA 36.3% で、ViT だけが 31.2% → 18.6% → 13.5% と下げ続ける。sticky を切ってあった旧 Run のほうが低スコア側は酷い（34% 対 19%）ので、**protocol でも eval ε でもない**。また **432 は能力上限ではない**（tau30 は 96-101M で max 773）。ラック掃き切りは 50M〜75M で立ち上がる遅い現象である。
24. **γ 0.997 で相対 action gap が 4〜5 分の 1 に潰れ、BF16 の余裕も失われた**（探索ブロック 19）。γ 0.99 の `q_gap / q_max` は 3.6〜4.1% だが、γ 0.997 では `q_max` が 3.6-4.0 → 11.9 と 3 倍に膨らみ 絶対 `q_gap` は 0.145 → 0.097 と縮んで **0.81%** になる。BF16 の相対分解能 2⁻⁸ に対する比は 9〜10 → **2.08**（1.55 ULP）。探索ブロック 15 の「RR4 は 4.36 ULP で余裕がある」は `q_max` 6.65 時点の値で、`q_max` の成長とともに余裕は消えた。actor / eval の forward は FP32 なので行動選択は量子化されないが、**識別性を教える learner 側が 1.5 ULP しか差を持たない**。ただし **低スコア裾は action gap では説明できない** — ViT は gap/max 0.0223 と tau30 の 0.0362 より狭いのに `<100` は 13.5% 対 36.3% で良く、向きが逆である。
25. **spatial exploration（Ape-X 型 ε ラダー）が低スコア裾を潰した**（探索ブロック 20）。`use_spatial_exploration` の 1 行だけを変えた 2 本で、eval1（15-50M・各 n=219）の `<100` が **15.5% → 2.7%（ラダー 0.01-1.0）→ 1.4%（0.01-0.4）**、平均が **257.7 → 306.2 → 358.3**、p10 が **83 → 145 → 273**。**上側はほとんど動かず（p75 373 → 393 → 408）下振れだけが消えた**。throughput は 2,288 → 2,180 → 2,130 step/s でコストはほぼゼロ。探索ブロック 14・18 で ViT に見た「下振れを潰す装置」と同じ署名を、アーキ変更なしで再現したことになる。**追試で `eps_start` 0.2 を加えた 4 点（0.01 / 0.2 / 0.4 / 1.0 → mean 257.7 / 295.3 / 358.3 / 306.2、`<100` 15.5% / 7.3% / 1.4% / 2.7%）は単峰で、0.4 が内点最適**（0.4 対 0.2 は平均差 5.8σ、`<100` 3.0σ）。冷やしすぎると被覆が足りず、熱すぎると探索コストを終盤まで払う。
26. **裾の原因は margin ではなく被覆である**（探索ブロック 19・20）。45-50M の `q_gap/q_max` は baseline 0.0081 > apex 0.0080 > **e04 0.0046** で、eval1 の順位 257.7 < 306.2 < **358.3** と**完全に逆相関**する。e04 は BF16 の ULP 余裕が **0.81**（1 ULP 未満）でありながら最良である。ViT（探索ブロック 19）に続く 3 例目の反例で、**action gap 仮説は棄却してよい**。探索ブロック 19 で挙げた BF16 の余裕消失も、成績とは結びついていない。ただし `q_gap` は replay バッチ上の平均なので、ε ラダーでバッファ構成が変わると「方策の決然さ」ではなく「バッファに入っている状態の質」を測る。**ラダー設定をまたいだ `q_gap` 比較は成立しない**（探索ブロック 19 の tau30 / ViT / baseline 比較は全て single-ε なのでそちらは有効）。
27. **5-6M の過渡は grad-step 固定の可塑性ひずみが最有力**（探索ブロック 21）— **「grad-step 固定」の部分は探索ブロック 23・24 が棄却した。正しくは `replay_ratio`（= 各遷移の平均抽出回数）の関数であり、RR1 で消える。以下は当時の切り分け記録**。多くのメトリクスが 5-6M でピーク→急落→緩回復する現象を 5 Run・5 仮説で切り分けた。**β スケジュール説は棄却**（β 半減点 25M と 50M の 2 Run で過渡位置が不動。ピーク時 β は 0.538 対 0.469 と別値で同 step に発生）、**リプレイかき混ぜ説は棄却**（バッファ満杯は実測 1,048,704 = 1.05M で 5-6M と不一致、PER 実測指標は全区間ほぼ 0）、**新規状態波説は棄却**（RR8 は median≈197 のまま同 grad step で崩壊。流入量と谷の深さが逆行）、**価値波・過大推定の自己修正説は中核が棄却**（`q_max` は全 5 Run で単調上昇のみ。過衝も修正局面も無い）。生存したのは **grad-step 説**で、RR8 と RR4 のスコア/td ピークが grad 軸の同一ビン（62.5k-78.1k / 117k）で一致し exp 軸では 2 倍ずれる。**落ちているのは価値の水準ではなく行動の識別性（`q_gap`）**であり、これは Kumar 2021 の実効ランク低下・Sokar 2023 の dormant neuron（RR が高いほど速い）と同じ署名である。
28. **100M で相転移が起きた**（探索ブロック 22）。ラダー 0.4 構成を 100M（10.95h / 2,538 step/s）まで伸ばすと、**train `≥432` が 0.27%（40-50M）→ 0.82%（70-80M）と約 3 倍**、**eval1 `≥432` は 3.2% → 12.7%（80-90M）と約 4 倍**に立ち上がった。eval1 は 60M 以降プールで **mean 374.0 / median 404 / `≥400` 54.2% / 最高 796**（2 ラック 864 の目前）で、**エピソードの過半がラック 1 枚をほぼ掃き切る**水準。`<100` は 1.6%。tau30 の相転移が 50M〜75M だった件と時期が重なる。**予算延長が初めて報われた Run** であり、探索ブロック 17（対照は 30M で天井）とは対照的である。
29. **5-6M の過渡は再発せず、`q_gap` は元のピークを超えて伸び続けた**（探索ブロック 22）。100M Run の `q_gap` は 15-20M の谷 0.0399 から単調回復し、**55M 頃に当初ピーク 0.0485 を超えて 100M で 0.0580** に達した。第 2 の過渡は無い。BF16 の ULP 余裕は谷で **0.64**（1 ULP 未満）まで落ち 100M で 0.93 まで戻ったが、依然 1 を割ったままで、**成績は同区間で最良**である（探索ブロック 19・20 の反例に続く 4 例目）。45-50M 以降の `grad_norm` / `loss` の緩やかな上昇は β が 50M で 1.0 に到達した時刻と一致し、**β はレベルを動かすが転換点の位置は動かさない**という探索ブロック 21 の結論と整合する。
30. **`replay_ratio` 2 が三軸すべてで RR4 に勝った**（探索ブロック 23）。`replay_ratio` 以外は seed まで完全同一の 100M ペアで、**eval1 の 10M 窓 10 本すべて**（10-40M では 1.4〜1.6 倍）、**勾配 step 軸の 100k 窓8 本すべて**（更新回数は半分なのに）、**壁時計**（5.90h 対 10.95h、1.85 倍）で RR2 が上。RR4 が 10.95h で到達した最終水準 390.1 に **RR2 は 1.49h（25.3M exp）で到達**する（7.3 倍）。90-100M は mean **439.5** / p25 405 / `≥432` **19.4%** / 単発最高 **857**（2 ラック 864 の 99.2%）で、`<100` は 10M 以降ゼロ。サンプル効率と速度のトレードオフではなく、**更新を減らすほど 1 更新の質が上がる**。8 → 4 → 2 と 3 点そろって同じ向きで、まだ底に達していない。
31. **過渡は「固定 grad step」ではなく「grad step と新規サンプルの比」で決まる**（探索ブロック 23）。`q_gap` の落ち込みの深さは **RR8 −62% / RR4 −31.5% / RR2 −11.8%** と RR に単調だが、**ピーク位置は grad 軸で 1.69 倍・exp 軸で 3.36 倍ずれ、どちらにも揃わない**（86k 対 145k grad）。探索ブロック 21 の grad-step 説は**強い形が棄却され、弱い形が残った** — 0-100k grad では 2 本の `q_gap` が完全に重なるので軌道自体は勾配 step で決まっており、**折れる位置だけが RR で動く**。RR2 は 100k grad 以降**650k 勾配 step にわたり 0.078-0.082 で平坦**、RR4 は 0.039 まで落ちて 100M でも 0.048 までしか戻らない（定常の識別性が 1.7 倍）。Kumar 2021 / Sokar 2023 / Nikishin 2022 の "updates per datum" と同型である。
32. **探索ブロック 22 の「後期の `grad_norm` / `loss` 上昇は β 到達によるもの」は反証された**（探索ブロック 23）。両 Run とも `per_beta_step` は 50M だが、**RR2 は 45M 以降 `grad_norm` 1.15-1.23 / `loss` 0.285 → 0.257 / `td_mean` 0.341 → 0.336 と平坦**で、RR4 だけが +27% / +14% / +11% と上昇する。**β ではなく RR 依存**であり、探索ブロック 17 の「動いているのに前に進まない」と同じものを見ている（RR4 の後期の働きは学習ではなく損傷への対処、という読み。機序は未特定）。なお BF16 の ULP 余裕は**RR2 のほうが広く**（1.66 対 1.25）、本記録で初めて「余裕が広い側が成績も良い」ペアになった。

33. **`replay_ratio` は下限 1 まで効き続けた**（探索ブロック 24）。90-100M の eval1 は RR4 391.6 → RR2 439.5 → **RR1 487.1** で、**増分が +47.9 / +47.6 とほぼ等しく exp 軸では逓減していない**。60-100M プールで mean **474.7** / p25 418 / `≥400` **88.9%** / `≥432` **28.6%** / `<300` **0.0%**、**単発最高 864 = 2 ラック（432×2）の完全掃き切り**（800 超が 6 本）。勾配 step 軸でも壁時計軸でも勝つ（4.16h / 6,670 step/s）。ただし **0-20M では RR1 が 3 本中最下位**で、exp 軸の交差は 40M 前後、壁時計の交差は約 1.5h。**短予算なら RR2 のほうが良い**。逓減しているのは速度側で、RR4→RR2 の 2.16 倍に対し RR2→RR1 は **1.41 倍**にとどまる（learner が縮むと env / actor / eval が裏に隠れなくなり、固定費 `a` が 3.09e-5 → 8.74e-5 s に増える。探索ブロック 23 の線形外挿 8,219 step/s は23% の過大予測だった）。
34. **5-6M の過渡は `replay_ratio` ただ 1 つの関数で、RR1 で消える**（探索ブロック 24）。`q_gap` の落ち込みは **RR8 −62% / RR4 −31.5% / RR2 −11.8% / RR1 なし** の 4 点で、**RR1 の `q_gap` は 80M まで単調上昇するだけ**である。`replay_ratio` は「収集した遷移が平均何回引かれるか」（`dqn_based_agent.cpp:1804-1808`）なので、**RR = 1 は各サンプルを 1 回だけ使う点**にあたる。**過渡は「同じデータを繰り返し当てること」そのものが生む損傷**だった、と読める。`q_max` 12.62/12.33/11.90、`grad_norm` 0.85/1.18/2.20、`td_mean` 0.303/0.336/0.342 もすべて RR に単調である。
35. **`q_gap` の定常値と BF16 の ULP 余裕は、どちらも成績の予測子ではない**（探索ブロック 24）。95-100M の `q_gap` は **RR2 0.0798 > RR1 0.0734 > RR4 0.0571** でスコアの順（RR1 > RR2 > RR4）と一致せず、探索ブロック 23 の「定常での識別性が高いほど良い」という読みは **RR1 が反証した** — 可塑性の代理として使えるのは**過渡の深さ**であって定常のレベルではない。ULP 余裕も RR1 が **1.48** と 3 本中もっとも狭いのにもっとも成績が良く、探索ブロック 19 以来 6 例目の反例になる。**この 2 指標は監視対象から外してよい**。
36. **律速がスコアの下側から上側と測定側へ移った**（探索ブロック 24）。RR1 の eval1 は 60-100M で `<300` が **0.0%**、**60.3% が 400-432 に集中**し、「ほぼ 1 ラック掃き切るが 2 面目で落ちる」に収束した。探索ブロック 18 で分離した「ポカる率」側は**消滅**している。`600-900` 帯は 0.4% → 2.4% → **15.9%** とRR に単調で能力自体は伸び続けているが、**`≥432` は 40M 以降 25-31% でほぼ横ばい**。ところが train 側の `≥600` 本数は 10M ごとに 4/5/5/9/11/**17** と増え続けており、両者が食い違う。eval interval が learn_step 基準のため **RR1 は 10M 窓あたり 15.7 点**（RR4 は 63.1）しか取れず、**この食い違いは現在の eval 構成では判定できない**。

## 探索ブロック 03: Breakout プロトコル（sticky / episodic_life）

**記録時点:** 2026-08-16
**状態:** completed

### 探索観点

v5 プリセット（Machado 2018 準拠）で Breakout が 5M step・42 点で飽和した。文献値（Nature DQN 401.2）との差が大きく、プロトコル条件のどれが効いているかを切り分ける。

### 探索条件

`E` 層で 1 要素ずつ変更。ベースラインは v5（sticky 0.25 / noop 0 / episodic_life false / fire_reset false）。

### 探索結果

**episodic_life（sticky 0.25 固定、27M / 29M）**

| train 生スコア mean | 42.0 | 41.9 |

### 考察

episodic_life は `q_max`（1 ライフ分の価値へ低下）と `q_gap_rel`（行動間の価値差が拡大）に設計どおりの変化を与えたが、`lives` が動かなかった。ボールを落とす直前の状態ではパドルが既に間に合わない位置にあり、そこへ負の信号を積んでも「先回りする」能力は上がらなかったと解釈できる。

## 探索ブロック 06: num_envs の実構成ラダー（学習あり）

**記録時点:** 2026-08-17
**状態:** completed
**確度:** medium-high。single-seed だが 7 点 × 2 周で再現性を確認、n64 を各周の先頭・末尾に置いてドリフト検証済み

### 探索観点

learner を含む実構成で num_envs を決める。ブロック 05 の天井に対する実際の利用率と、exp_step あたりの学習効率の両方を同時に測る。

### 探索条件

Breakout / v5 素（sticky 0.25、episodic_life false）/ BF16 learner / `backend.non-deterministic` / `main_runner_type = pipeline` / **eval OFF**（`train.eval_schedule.[eval1,eval2].interval = 0`）/ 各 2,000,000 exp_step。

eval を切ったのは、`eval_batch_size = 1` のため eval コストが num_envs に依存せず、大きい N ほど相対コストが下がって系統誤差になるため。

2M にしたのは RB capacity 1,048,576 を超えさせるため。前半 0-1M は eviction が起きず、後半 1M-2M が実運用条件になる。

順序は `64a → 32 → 128 → 256 → 512 → 1024 → 64b` を 2 周。

### 探索結果

**測定の妥当性: 1 周目の前半は暖機で系統的に遅い。**

| N | 1 周目（後半 1M-2M） | 2 周目 | 差 |
|---|---|---|---|
| 64a | 2,081 | 2,467 | +18.6% |
| 32 | 2,101 | 2,516 | +19.7% |
| 128 | 2,329 | 2,709 | +16.3% |
| 256 | 2,301 | 2,647 | +15.0% |
| 512 | 2,575 | 2,668 | +3.6% |
| 1024 | 2,566 | 2,694 | +5.0% |
| 64b | 2,457 | 2,499 | +1.7% |

1 周目の 5 本目（512）以降は 2 周目と一致する。**最初の 4 本が 15〜20% 遅い**。以下は安定区間（2 周目 + 1 周目 64b）で評価する。

**throughput は N=128 で頭打ち。**

| N | 後半 throughput | n64 比 |
|---|---|---|
| 32 | 2,516 | +1.3% |
| 64 | 2,483（3 本平均） | 基準 |
| 128 | 2,709 | +9.1% |
| 256 | 2,647 | +6.6% |
| 512 | 2,668 | +7.5% |
| 1024 | 2,694 | +8.5% |

N=128 以上は 2,647〜2,709 に収まり、差 ±1.2% は同一設定のブレ幅（2 周目 n64 の 2 本で 1.3%）内。

**学習効率は N=256 から崩れる。**

| N | 2M 時点 train 生スコア EMA（2 周平均） | 2 周のレンジ | 完了ゲーム数 |
|---|---|---|---|
| 32 | 20.34 | [20.08, 20.60] | 3,680 |
| 64 | 19.52（4 本平均） | [18.49, 20.94] | 3,508 |
| 128 | 19.36 | [19.33, 19.38] | 3,200 |
| 256 | 16.17 | [16.09, 16.26] | 2,822 |
| 512 | 11.91 | [11.26, 12.57] | 2,132 |
| 1024 | 6.42 | [6.27, 6.57] | 1,324 |

N=128 と N=256 はそれぞれ 2 周で ±0.3% に収まっており、両者の差 −17% は確実に有意。n64 のみレンジが 12.6% と広いのは、lane 数が少なく train 平均のサンプルノイズが大きいため。

**wall-clock 効率（throughput × 学習、n64 基準）**

| N | throughput | 学習 | 積 |
|---|---|---|---|
| 32 | 97.1% | 104.2% | 101.3% |
| 64 | 100.0% | 100.0% | 100.0% |
| 128 | 106.0% | 99.2% | **105.2%** |
| 256 | 104.1% | 82.8% | 86.3% |
| 512 | 110.3% | 61.0% | 67.3% |
| 1024 | 110.7% | 32.9% | 36.4% |

### 考察

**N=128 を採用する。** throughput が +9% 上がって学習効率は無傷（−0.8% はブレ幅内）。N=256 以上は throughput が伸びないまま学習だけ落ちるため、選ぶ理由がない。

学習効率の劣化は完了ゲーム数と対応している（N=256 で −16%、N=1024 で −62%）。同じ exp_step を集めても lane あたりの進行が浅いとゲームが完了せず、エピソード終端という学習信号が減る。根にあるのはブロック 01 と同じ lane 位相の同期で、`noop_max = 0` により全 lane が同一初期状態から同時発進する構成に起因する。

env 天井（ブロック 05）に対する実構成の利用率は N=64 で 31%、N=256 で 25% であり、**env は律速していない**。N を上げて速くなる分は env の並列度ではなく、actor forward が batch N で 1 回にまとまることによる step あたりコストの低下と考えられる。それが N=128 で頭打ちになるのは、そこから先は learner 側が律速に回るため。

RB が満杯になる後半では throughput が 14.5〜20% 落ちる。2 周目では N 依存の傾向はない（1 周目で見えた「N が大きいほど RB コストが大きい」は暖機の artifact であり、invalidated）。

本結論は現在の learner コストに依存する。RR / batch / num_quantiles / NN 構成を変えると env と learn のバランスが移動するため、そのときは再評価が要る。メモリ消費も N に比例して増える（N=1024 でも本機では収まった）。参考として DropMerge は N=256 を採用している。

## 探索ブロック 07: NN 構成（Nature CNN vs IMPALA-CNN）

**バンドルは異常に強く、そして崩壊した。**

classic で **2.5M step の median が 335**。対照 `run_20260821-122717`（tau30）が全 101M で記録した最高の 5M 窓 median は **332（95-100M）**であり、**約 38 分の 1 のサンプル数で同水準に到達**した。noop 30 のぶん土俵は新しい側が厳しい。

その後 median は単調に低下し、classic は 10M で 60（対ピーク 18%）、v5 は 35〜47% で振動した。

**壁時計 29.4 分で eval1 = 423**（`game_len` 4,496 = 18,000 frames 上限に到達しており打ち切り値）。同区間は 388 / 423 / 357 で平均 389。Nature DQN の 401.2 は 200M frames・30 本平均・ε=0.05 の best checkpoint 値であり、本記録側は 10.3M frames・1 本・ε=0・target net なので**上振れ補正 3 つと下振れ補正 1 つ**が入るが、同水準と言ってよい。**frames で約 19 分の 1。**

**仮説の排除。** 崩壊の原因を単変数で順に潰した。

| 仮説 | 検証 | 結果 |
|---|---|---|
| `weight_decay` 0.01 | classic-wd 対 classic | **無罪**。median 軌跡が一致（2.5M 335/319、3.0M 330/338、7.0M 63/62） |
| プロトコル / `episodic_life` | classic 対 v5 | **無罪**。両方 2.5M でピーク |
| `per_beta_step` | 5M 対 10M | **無罪**。ピーク時の β が 0.70 対 0.55 と全く違うのに位置が同一 |
| `replay_capacity` | 1,048,576 対 524,288 | **無罪**。比例予測のピーク 1.25M を過ぎても上昇継続 |
| BF16 | v5-fp32 | **無罪**。FP32 でも 3.0M でピークを打ち崩壊 |
| **`replay_ratio`** | 8 対 4 | **有罪** |

**replay_ratio 8 → 4。** 勾配 step 数（= `exp_step × replay_ratio / batch`）で揃えて比較した。

| grad step | RR8 の exp_step / median | RR4 の exp_step / median |
|---|---|---|
| 31,250 | 1.00M / 14 | 2.00M / 19 |
| 62,500 | 2.00M / 151 | 4.00M / **207** |
| 78,125 | 2.50M / **197** | 5.00M / **295** |
| 93,750 | 3.00M / 162 | 6.00M / **262** |
| 125,000 | 4.00M / 90 | 8.00M / **140** |
| 140,625 | 4.50M / 77 | 9.00M / **182** |
| 156,250 | 5.00M / 74 | 10.00M / **163** |

**機序が直接測れた。** 勾配 step 93,750 の時点:

| | `q_max` | `q_gap` | `q_gap/q_max` |
|---|---|---|---|
| RR8 | 6.64 | 0.0679 | 0.0102 |
| **RR4** | **6.65** | **0.1361** | **0.0205** |

`q_max` がほぼ同一（6.64 対 6.65）なのに `q_gap` がちょうど 2 倍。**価値の水準は同じで、行動の識別性だけが 2 倍保たれている。**

| grad step | RR8 | RR4 |
|---|---|---|
| 62,500 | 199.6 | 236.3 |
| 93,750 | 295.2 | **389.0** |
| 125,000 | 196.8 | 295.4 |
| 156,250 | 109.5 | **333.0** |

throughput は RR8 1,047.3 steps/s（10M で 2.65h）に対し RR4 **2,062.6 steps/s（1.35h）**。exp_step 軸でも 5.0M 時点で 74 対 295 と RR4 が 4 倍であり、**両軸で勝ち**。

### 考察

**崩壊の実体は可塑性喪失（capacity loss）である。** 症状が文献の署名と一致する — ピーク後の劣化、識別性の崩壊（相対 `q_gap` が 0.0229 → 0.0051 で 4.5 倍）、勾配の縮小（3.36 → 1.64）、loss の縮小（0.45 → 0.18）、`q_max` の頭打ち。加えて **weight_decay・プロトコル・β・capacity・精度のいずれを変えても同じように起きる**という頑健さが、ハイパラではなくネットワーク側の現象であることを示す。

**γ = 0.997 を使う論文は 2 本とも可塑性保護機構を持っている。**

| | replay ratio | 可塑性対策 | γ |
|---|---|---|---|
| BTR | **4** | Spectral Normalization（全 conv residual layer） | 0.997 |
| BBF | 8 | shrink-and-perturb reset（40k 勾配 step ごと）+ weight decay 0.1 | 0.997 |
| **本記録** | **8** | **なし** | 0.997 |

**BBF の replay ratio を BBF の対策なしで、BTR の γ を BTR の spectral norm なしで回していた。** 本コードベースには spectral normalization も reset 機構も実装が存在しない（grep でヒットゼロ）。ピーク時点の 78,125 勾配 step は BBF の reset 間隔 40,000 で数えるとちょうど 2 回目の直前にあたる。

**BTR の `replay_ratio` 4 は計算都合ではなく安定性の一部だった。** 本記録は以前これを「計算のための妥協であり、性能のために採る理由はない」と評価していたが、実測が反証した。

**BF16 の精度問題は可塑性喪失の下流だった。** RR8 では `q_gap/q_max` が 0.0051 まで落ち、BF16 の相対分解能 2⁻⁸ ≈ 0.0039 に迫って `q_gap` が 1 ULP を割っていた（0.62 ULP）。RR4 では同じ勾配 step で 4.36 ULP と余裕がある。**識別性が保たれていれば精度は問題にならない。**

**短予算運用そのものは成功している。** 10M / 1.35h で、旧ベースラインが 100M かけて到達した水準を大きく超えた。`per_beta_step = 予算/2` の運用則も探索ブロック 10 と本ブロック（予算 10M で 5M 対 10M、5M が勝ち）の 2 つの予算で確認された。

## 探索ブロック 16: eval の FIRE デッドロック（v5 プロファイル固有）

**記録時点:** 2026-08-23
**状態:** completed
**確度:** high。`lives` の値で機序が一意に確定する

### 探索観点

v5 プロファイルの eval1 に、スコア 0 のまま上限まで走り切る評価が断続的に現れた。原因を特定する。

### 探索結果

`run_20260823-191548`（RR4）の eval1 に、**8.18M から 9.62M まで 10 本連続で同一パターン**が出た。

| step | score | `game_len` | `lives` |
|---|---|---|---|
| 8.02M | 204 | 1,331 | 5.00 |
| 8.18M〜9.62M | **0** | **27,000** | **5.00** |
| 9.78M | 396 | 2,028 | 5.00 |

`game_len` 27,000 は `max_episode_frames` 108,000 ÷ `frame_skip` 4 の上限そのもの。**`lives` が 5.00 のまま**＝ 27,000 step のあいだ一度もミスしていない＝**ボールが一度も投入されていない**。

直後の 9.78M で 396 に戻っているため、方策そのものは無傷である。

**機序。** v5 は `fire_reset = false` なので env はボールを投入しない。eval は `eval_policy.policy_type = Greedy`（ε = 0）で完全に決定的。ボール未投入の局面で argmax が FIRE でないと、画面がほぼ静止しているため次 step も同じ argmax になり、上限まで抜けられない。

**sticky actions では脱出できない。** `repeat_action_probability` は「直前の行動を繰り返す」だけで、別の行動を導入しないため、決定的デッドロックを破る確率性にならない。

**発生率は方策が良いほど高い。**

| Run | デッドロック | 発生区間 |
|---|---|---|
| RR8 対照 | 10 / 125 本（8%） | 0.02M〜4.74M |
| RR4 | 15 / 63 本（24%） | 0.02M〜9.62M |

RR4 は `q_gap` が 2 倍で argmax がより固いため抜けにくい。RR8 は方策が崩れた 4.74M 以降は発生しなくなっている。

### 考察

**v5 プロファイルの eval1 は、eval ε = 0 のままでは信用できない。** 探索ブロック 15 までに取った v5 系の eval1 window 平均は、スコア品質とデッドロック頻度の混合を測っていた。本記録の v5 系 eval1 は**デッドロックを除外して読むこと**。

対処は eval を ε-greedy にすること。ε = 0.01・4 行動なら 1 step あたり FIRE を引く確率が 0.0025 で、1,000 step 以内の脱出確率は 92%。

```
R.eval_policy.policy_type = EpsilonGreedy
R.eval_policy.eps_start = 0.01
R.eval_policy.eps_end = 0.01
```

**BTR の評価 ε が 0.01、Nature 2015 が 0.05** であり、文献側は最初からこの値を持っている。BTR 比較に必要な条件でもあるため、v5 プロファイルの既定とする。

Classic プロファイル（`fire_reset = true`）ではライフ喪失時に env が FIRE を打つため本症状は発生しない。**v5 固有の問題である。**

## 探索ブロック 19: action gap の γ 依存と BF16 の余裕

### 探索観点

FIRE デッドロック（探索ブロック 16）と低スコア裾（探索ブロック 18）は、どちらも「argmax がわずかな差で
決まっている」ことに帰着するのではないか。top-1 と top-2 の Q 差を Run 間で比較する。

### 探索結果

| Run | γ | window | `q_max` | `q_gap` | **`q_gap/q_max`** | BF16 誤差 | **SNR** | ULP |
|---|---|---|---|---|---|---|---|---|
| tau30 IMPALA | 0.99 | 45-50M | 3.98 | 0.144 | **3.62%** | 0.016 | **9.28** | 9.23 |
| tau30 IMPALA | 0.99 | 96-101M | 3.61 | 0.146 | **4.05%** | 0.014 | **10.38** | 9.35 |
| ViT hybrid | 0.99 | 45-50M | 3.74 | 0.084 | 2.23% | 0.015 | 5.72 | 5.35 |
| **本 Run** | **0.997** | 45-50M | **11.91** | 0.097 | **0.81%** | 0.047 | **2.08** | **1.55** |

（BF16 誤差 = `q_max` × 2⁻⁸、SNR = `q_gap` / BF16 誤差、ULP = `q_gap` / 2^(floor(log2 `q_max`)−7)）

**γ 0.99 → 0.997 で相対 action gap が 4〜5 分の 1 に潰れた。** 地平が 100 → 333 step になり `q_max` が
3.6-4.0 → 11.9 と 3 倍に膨らむ一方、絶対 `q_gap` は 0.145 → 0.097 と**縮んだ**。結果 `q_gap / q_max` は
3.6-4.1% から **0.81%** になる。

**BF16 の余裕も同時に失われた。** SNR は 9〜10 から **2.08**、ULP 換算で **1.55**。探索ブロック 15 で
「RR4 は 4.36 ULP で余裕がある」と記録したが、あれは `q_max` 6.65 時点の値であり、`q_max` の成長とともに
ULP が粗くなって余裕が消えた。本 Run 内でも 15-20M の 0.70 ULP から 45-50M の 1.55 ULP まで動いており、
1〜2 ULP のレンジに留まり続けている。actor / eval の forward は FP32 なので行動選択そのものは量子化
されないが、**識別性を教える learner 側が 1.5 ULP しか差を持たない**。

**低スコア裾は action gap では説明できない。** 45-50M で ViT は `q_gap/q_max` 0.0223 と tau30 の 0.0362 より
**狭い**のに、`<100` は 13.5% 対 36.3% で**良い**。向きが逆である。

### 考察

**γ 0.997 は action gap を犠牲にして地平を買っている。** BTR が γ 0.997 と Munchausen（action gap を
広げる操作子）を同時に採っているのに対し、本記録は gap 拡大機構なしで γ だけを 0.997 にしていた。
探索ブロック 17 で「`q_max` は伸びるのに `q_gap` が頭打ち」という形で現れているのは同じ現象である。

**探索ブロック 15 の BF16 に関する結論は条件付きだった。** 「識別性が保たれていれば精度は問題にならない」は
`q_max` 6.65 / 4.36 ULP の時点では正しかったが、`q_max` が 11.9 まで育った現在は 1.55 ULP であり、
同じ条件が成立していない。探索ブロック 15 の FP32 対照は RR8 崩壊の切り分けであり、この局面の検証には
なっていない。

**低スコア裾（探索ブロック 18）と action gap は別の現象である。** 両者を 1 つの機序で説明する試みは
ViT の反例で否定される。

**ラダーには内点最適があり、それは 0.4 である。** 4 点（0.01 / 0.2 / 0.4 / 1.0 → 257.7 / 295.3 /

**測定契約が 1 つ変わった。** spatial Run の `42_env/*` は方策の質を測らない。

**本ブロックは Breakout 単独の結果である。** reward_clip で 1/4/7 が全て +1 になること、

ラダーの効きが被覆由来であれば env 非依存のはずだが、これは未検証である。

## 探索ブロック 21: 5-6M 過渡の機序（多指標の上昇→急落→緩回復）

> **後続で更新**: 本ブロックの結論「固定 grad step で起きる」は探索ブロック 23（RR2）で位置が動くことが分かり、探索ブロック 24（RR1）で過渡そのものが消えた。最終的な読みは **`replay_ratio` = 各遷移の平均抽出回数の関数**である。以下は 5 仮説を排除した当時の切り分け記録として残す。

- 対象: baseline（探索ブロック 17）/ apex / e04 / e02 / e04_100m の 5 Run + RR8・RR4 の 10M Run 2 本
- 期間: 2026-08-25

### 探索観点

「多くのメトリクスが 5-6M 付近まで向上してから急激に下がり、その後徐々に戻る」という観察の機序を特定する。
Q 値関連は全体を通して滑らかに上がるのが望ましい、という期待に対して何が起きているのか。

### 探索結果

**「多くのメトリクス」の中身は 3 種類に分かれる**（5 Run・1M ビン）。

| 形 | メトリクス | 実測 |
|---|---|---|
| 上昇→急落→緩回復 | `q_gap`、eval1、train スコア | ピーク 4.5-6.5M → 谷 11.5-18.5M（対ピーク −20〜−35%）→ 18-20M で 70-89% 回復 |
| 上昇→単調減衰（回復なし） | `grad_norm`、`loss` | 同位置でピーク → 20M まで下がり続ける |
| **単調上昇のみ** | **`q_max`** | **全 5 Run で急落局面が存在しない**（depth 形式負値、18-20M で対ピーク 105-109%） |

**価値の水準は滑らかに上がっている。落ちているのは行動の識別性（`q_gap`）だけである。**

**仮説の判定**（各仮説に敵対検証を当てた）。

| 仮説 | 判定 | 決め手 |
|---|---|---|
| β スケジュール犯人 | **棄却** | e04（β 半減 25M）と e04_100m（同 50M）で過渡位置のずれは ±1M（プラトー幅内）。犯人なら 2 倍ずれるはず。ピーク時 β は **0.538 対 0.469** と別の値で同じ exp_step に発生。探索ブロック 15 の β 5M/10M 比較（ピーク時 β 0.70 対 0.55 で位置同一）と同じ結論 |
| PER / リプレイかき混ぜ | **棄却的** | バッファ満杯は実測 **1,048,704**（`07_evicted_unsampled_ratio` の発火開始時刻）で 5-6M と不一致。同指標と `64_priority_stale_ratio` は全区間ほぼ厳密 0 |
| 新規状態波（2 画面目流入） | **棄却** | RR8 は **median≈197**（400 に遠く届かない）のまま同 grad step で崩壊。`≥432` 初出は Run 間で 2M ばらつくのに押し戻し開始は全 Run で 5-6M 固定。流入量（`≥400` 率 baseline 0.145 対 e02 0.048）と谷の深さ（q_gap depth 0.355 対 0.351）が逆行 |
| 価値波・過大推定の自己修正 | **中核が棄却** | 過衝→修正なら `q_max` が下降するはずだが**全 5 Run で単調上昇のみ**。「勾配が鎮まると回復」の順序も、grad/loss が単調減衰で回復局面を持たないため成立しない |
| **固定 grad-step の可塑性ひずみ** | **最有力** | ↓ |

**grad-step 軸での整合**（RR8 = exp/32、RR4 = exp/64、15,625 grad-step ビン）。

| | RR8 | RR4 | 判定 |
|---|---|---|---|
| スコアピーク（grad 軸） | 62.5k-78.1k | 62.5k-78.1k | **一致** |
| 同（exp 軸） | 2.25M | 4.50M | **2 倍ずれ** |
| `td_mean` ピーク（grad 軸） | 117k | 117k | **一致** |
| ピーク時 train median | 197 | 294.5 | **1.5 倍違う** |
| `q_gap` 谷の深さ | −62.0%（崩壊、回復せず） | −8.5%（浅い減衰） | RR で質が変わる |

**同一 grad step で異なるスコア水準からピークアウトする**ため、スコア到達が引き金という説明は成立しない。
探索ブロック 15 の「同 grad step 93,750 で `q_max` ほぼ同一（6.64/6.65）なのに `q_gap` が 2 倍（0.0679/0.1361）」と
合わせて、**価値スケールは grad step の時計で進み、識別容量は更新回数依存で損耗する**。

**その他の確認事項**（いずれも 5-6M と無関係）。

- `40_agent_rs/01_scale`（reward scaler）は e04 全期間で 1.0 定数。
- `uqe_tau`（0.9→0.5 / 10M）は設定上存在するが**消費経路ゼロ**。`EpsilonGreedyActionPolicy::SelectAction` は ε のみ使用し、
  tau を読むのは `UQEActionPolicy` / `ThompsonSampling` だけ。learner 側も `target_policy = Greedy` で不使用。
  メトリクス `32_agent_base/04_uqe_tau` は e04 の jsonl に **1 行も出力されない**（実測で不活性を確認）。
- 候補イベント（warmup 20k / ε decay 終了 250k / RB 満杯 1.05M / RB 1 周入替 2.1M）はどれも 5-6M と一致しない。

**谷の深さは探索の強さで決まる。** train median の落ち込みは baseline −54% ≫ e02 −41% > **e04 −20%**。
ピーク位置も探索が強いほど遅い（baseline 4.5M < e04/e02 5.5M < apex 6.5M、最大 +2.0M）が、
プラトー幅 ~2M・ビン量子化・Run 間ジッタと同オーダーで、この ≤2M のずれ自体は有意とは言えない。

### 考察

**機序の描像**: γ=0.997 の下で価値スケールが急成長する序盤に勾配が最大化し（`grad_norm` 3.6-4.6、`loss` ピーク）、
保護機構が無い（Spectral Norm 無し・reset 無し・`weight_decay` 0）まま大更新の連打を受けて
**識別性だけが削れる**（`q_max` は上がり続けるのに `q_gap` が落ちる）。argmax が乱れて方策が劣化し、
勾配が鎮まるにつれ識別性を再学習する。RR8 ではこれが破局に至り（探索ブロック 15）、RR4 では減衰で済む。

**文献との対応**: Kumar et al. 2021 は bootstrap 更新の反復で penultimate 特徴の実効ランクが低下し、
データあたり更新回数が多いほど悪化すると報告している。Sokar et al. 2023 は dormant ニューロン率が
replay ratio に比例して速く増え性能崩壊と同期すると報告している。**どちらも本記録の署名と一致する**。
RR8 のピーク 78,125 grad step が BBF の reset 間隔 40,000 の 2 回目直前にあたることも既に記録済み（探索ブロック 15）。

**ただし証拠は全て代理指標経由である。** `q_gap` とスコアは表現の健康状態そのものではない。
実効ランク（srank）や dormant 率のような直接指標は本コードベースに存在しない。

**弱点 2 点。** (1) 学習系メトリクス（`grad_norm` / `q_gap` / `loss`）のピークは grad 軸でも一致しない
（RR8 85,937 対 RR4 132,812、比 1.55）。ただし RR4 10M はピークが終端 2 ビン目にあり打ち切りの汚染がある。
(2) 50M 系 5 本は全て RR4 なので grad 軸と exp 軸が縮退しており、50M スケールでの判別ができていない。

### 考察

**`replay_ratio` は本記録で最大のレバーであり、まだ底に達していない。**
8 → 4（探索ブロック 15）に続いて 4 → 2 も **exp / grad / 壁時計の三軸すべてで勝った**。
サンプル効率を犠牲にして速度を買う類のトレードオフではなく、**更新を減らすほど 1 更新の質が上がる**。
RR8 の崩壊は「壊れるか壊れないか」の閾値現象ではなく、**RR に対して連続的に効く損傷の極端な側**だったことになる。

**探索ブロック 21 の grad-step 説は、強い形は棄却され、弱い形が残った。**
「過渡は固定 grad step で起きる」は成立しない（86k 対 145k）。しかし前半 100k grad まで `q_gap` が
2 本で完全に重なることは、**軌道そのものは勾配 step で決まっている**ことを示す。折れる位置だけが RR で動く。
整合する読みは「**損傷は勾配 step あたりで蓄積し、修復は新規サンプルの流入で進む。破綻点はその比 = `replay_ratio` で決まる**」
であり、これは Kumar 2021 / Sokar 2023 / Nikishin 2022 の "updates per datum" そのものである。
深さが −62% / −31.5% / −11.8% と RR に単調なことも、閾値ではなく比で決まることを支持する。

**探索ブロック 26（action gap 仮説の棄却）とは矛盾しない。** あちらは *ε ラダー設定をまたいだ* `q_gap` 比較で、
バッファ構成が変わるため「方策の決然さ」を測っていなかった。本ブロックは **ラダーが完全に同一**なので
`q_gap` 比較が成立し、可塑性の代理指標として使える（探索ブロック 15・21 と同じ用法）。
**低スコア裾の説明としての action gap は棄却されたままで、可塑性の代理としての `q_gap` は有効**、という切り分けである。

**「動いているのに前に進まない」の正体が一段見えた。** 探索ブロック 17 で RR4 が 30M 以降
「td_mean / grad_norm / loss は上昇するのにスコアが横ばい」になる状態を記録した。
本ブロックで、その上昇が **RR2 では起きない**ことが分かった。同じ β・同じ NN・同じデータ分布で、
RR だけが後期の TD 誤差と勾配ノルムを押し上げている。**RR4 の後期の「働き」は学習ではなく損傷への対処**
だと解釈できるが、機序は未特定である。

**`replay_ratio` は単変数だが、target net の遅れは道連れで動く。** `SoftUpdate()` は learn_step ごとに呼ばれる（`dqn_based_agent.cpp:435-446`）ので `soft_update_tau = 0.001` は**更新あたり**の EMA である。時定数 1/τ = 1,000 更新を exp_step に直すと **RR4 で 64,000、RR2 で 128,000、RR1 で 256,000** となり、**RR を半分にすると target net の遅れは exp 軸で 2 倍**になる。遅い target = 安定した bootstrap 目標なので、向きは観測された改善と同じであり、exp 軸の勝ちにはこの寄与が混じっている可能性を排除できない。
**ただし勾配 step 軸の勝ちはこの交絡を受けない** — 同じ更新回数なら target net の EMA 進行も同一だからである。その条件で RR2 は 100-300k grad で 1.5〜1.6 倍勝っており、**「更新あたりの新規データ量」だけで説明が付く**。結論は保たれるが、`replay_ratio` を厳密に単独で動かしたければ **τ ∝ RR でスケールさせた対照**が要る。
なお `train_actor.sync_interval` は `step.exp_step` で判定しており（`dqn_based_agent.cpp:1689`）、actor 側の遅れは RR に依存しない。

**スループット構造も測れた。** 1 exp step あたりの時間を `a + b·RR` で当てはめると
`a` = 3.09e-5 s（env + オーバーヘッド）、`b` = 9.08e-5 s（learn 1 単位）で、**RR2 でも learn が 85.5%** を占める。
外挿すると **RR1 は 8,219 step/s、100M で 3.38h** になる。

**RR2 は 100M で飽和していない。** 80-90M の 406.1 から 90-100M の 439.5、95-100M 窓は 441.8 で
`≥432` が 31.2%、train `≥600` も 10M ごとに増え続けている。探索ブロック 22 の対照が 70-100M で
`≥432` 0.78-0.82% の帯に入って鈍化したのとは対照的である。

**BTR 比較。** 90-100M mean 439.5 は BTR の Breakout 682 に対し **64.4%**、
公開 CSV の最終値 602.01 に対し **73.0%**（対照はそれぞれ 57.2% / 64.8%）。
HNS57 換算 1520%。ただし BTR は 100 本平均・online net・最良チェックポイント報告であり、
本記録は 1 本・target net・window 平均なので、依然として同列ではない
（`reports/btr_hyperparams_survey_2026-08-26.md` §11）。

### 考察

**`replay_ratio` は 8 → 4 → 2 → 1 の全区間で効き、下限まで効き続けた。**
90-100M の eval1 は 391.6 → 439.5 → 487.1 で、**RR4→RR2 が +47.9、RR2→RR1 が +47.6 と増分がほぼ等しい**。
exp 軸のスコア側では逓減していない。逓減しているのは速度側（2.16 倍 → 1.41 倍）と、
立ち上がりの遅さ（0-10M で 199.9 → 212.4 → **97.0**）である。

**前半の過渡は `replay_ratio` の関数であり、RR1 で消える。** −62% / −31.5% / −11.8% / なし の 4 点で、
探索ブロック 21 以来の現象は「サンプル再利用回数」というただ 1 つの量で説明が付いた。
RR = 1 は各遷移を平均 1 回しか引かない点であり、**過渡は「同じデータを繰り返し当てること」そのものが
生む損傷**だったことになる。Kumar 2021 / Sokar 2023 / Nikishin 2022 の枠組みと整合する。

**ただし `q_gap` の定常値はスコアの単調な予測子ではない。** 95-100M の `q_gap` は
**RR2 0.0798 > RR1 0.0734 > RR4 0.0571** で、スコアの順（RR1 > RR2 > RR4）と一致しない。
探索ブロック 23 で「定常での識別性は RR2 が 1.7 倍」と書いたのは RR4 との対比としては正しいが、
**「`q_gap` が高いほど良い」という読みは RR1 が反証した**。可塑性の代理として使えるのは
**過渡の深さ**のほうであって、定常のレベルではない。ここは訂正する。
（探索ブロック 19・20・26 の「action gap は成績を説明しない」系の反例に、これで 5 例目が加わる。）

**BF16 の ULP 余裕も同様に成績と結びつかない。** RR1 は 95-100M で **1.48** と 3 本中もっとも狭いのに
もっとも成績が良い。探索ブロック 19 以来 6 例目の反例で、**この指標は監視対象から外してよい**段階にある。

**律速がスコアの下側から上側へ完全に移った。** RR1 の eval1 は 60-100M で `<300` が 0.0%、
**60.3% が 400-432 に集中**する。つまり「ほぼ 1 ラックを掃き切るが 2 面目で早々に落ちる」に収束した。
探索ブロック 18 で分離した「上手いエピソードは伸びるがポカる率は下がらない」の**ポカ側は消滅**し、
残っているのは 2 面目の攻略能力だけである。`600-900` が 0.4% → 2.4% → **15.9%** と伸びているので
能力自体は上がり続けているが、**`≥432` は 40M で 25-31% の帯に入って以降ほぼ横ばい**である。

**次の律速は測定側である。** `≥432` の窓推移が 40M 以降フラットに見えるのが本当に飽和なのか
n=16 のノイズなのかを、現在の eval 構成では判定できない。同時に train 側の `≥600` 本数は
10M ごとに 4/5/5/9/11/**17** と増え続けており、**能力はまだ伸びている**ことを示唆する。
両者の食い違いを解くには eval の本数が要る（`060_eval_batch_episodes_10prd.md`）。

**`replay_ratio` < 1 は別の regime になる。** RR は「各遷移が平均何回引かれるか」なので、
0.5 は**収集した半分のデータを一度も学習に使わない**ことを意味する。単調性がまだ折れていないので
1 本試す価値はあるが、これまでの 4 点とは意味が違う軸に入る。
（探索ブロック 23 の `soft_update_tau` 交絡も RR1 では時定数 256,000 exp step まで伸びており、
exp 軸の効果量の内訳は依然として未分離である。）
