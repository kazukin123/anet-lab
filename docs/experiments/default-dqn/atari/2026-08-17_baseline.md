## 現時点のまとめ

1. **sticky actions が Breakout で支配的**。0.25 → 0.0 で train 生スコア 42 → 119（2.8 倍）。v5 プリセットのまま回すと 5M step で 42 に飽和し、以降 22M step 分がほぼ無駄になる。sticky 0 では 50M まで伸び続けた。
2. **episodic_life は単独では効果ゼロ**。sticky 0.25 固定で false / true を 27M step 比較し、train 生スコア 42.0 対 41.9、median 41 対 41 で差がない。中間指標（`q_gap_rel` 上昇、`q_max` 低下）は設計どおり動いており、機構は効いているがスコアに繋がらなかった。`lives` が 3.45 対 3.64 と変わらないことが決定的で、死ぬ頻度そのものが改善していない。
3. **sticky 0 では `lives` が明確に上昇する**（3.4 → 4.3）。episodic_life で動かなかった同じ指標が動いたことから、Breakout のプラトーはパドル制御の精度で律速されていたと解釈できる。
4. **eval が wall-clock を支配しうる**。Pong で `interval` 100 → 500 にすると真の throughput が 478 → 1,198 steps/s（2.5 倍）。train 曲線は完全一致しており、差分は eval の実行コストのみ。
5. **num_envs は N=128 が最適**（探索ブロック 06）。実構成 2M ラダーで throughput が N=128 で頭打ち（+9.1%、それ以上は差がブレ幅内）、学習効率は N=128 まで無傷で N=256 から崩れる（−17%）。wall-clock 効率は N=128 が最良（+5.2%）。この結論は現在の learner コストに依存するため、RR / batch / quantile / NN 構成を変えたら再評価が要る。参考として DropMerge は N=256 を採用している。
6. **Breakout 50M（sticky 0 / episodic_life true / noop 0 / fire_reset false）で train 生スコア 119.4、eval1 115.7**。43-44M で train 140.1 のピークを打ち、以降 -15% で 119 台に安定。100 点超が 50.1%、300 点超が 3.6%、ピーク期の max 427（1 画面 432 点にほぼ到達）。
7. Pong は v5 プリセット・num_envs 64 で 1M step から動き出し、2.5M で eval1 +7.10。
8. **NN は IMPALA-CNN を採用**（探索ブロック 07）。同じ 50M で train 生スコア 134.7 対 121.2、eval1 147.7 対 115.7。差の本体はサンプル効率で、中盤（10-25M）に 2 倍前後がつく。加えて **Nature CNN は 44M でピークアウトして −12.0% 劣化するのに対し IMPALA は −1.6% で、ピークが最後尾にあり 50M でも飽和していない**。高得点の裾も違い、≥400 点は IMPALA だけが出す（1.0% 対 0.0%、max 431 対 384）。
9. **`fire_reset = false` は Breakout で無報酬 step を生む**。ライフ喪失でボールが消え FIRE を押すまで再投入されないため、1 ゲームに 4 回、エージェントが自力で FIRE を選ぶまで待ちが入る。上記 8 までの全 Run がこの条件下にある。2026-08-18 に life-loss 後の soft-reset でも FIRE 系列を打つよう実装を修正した（`fire_reset=false` では挙動不変）。
10. **100M 長期で eval1 best window 337.5、HNS57 1166%**（探索ブロック 08）。Nature DQN の Breakout 401.2（HNS57 換算 1387%）の 84% に相当する。50M 以降で一段上のレジームに入り、eval1 が 50M までの最高 160.1 から 2 倍超へ伸びた。`fire_reset` の A/B は 0-50M で交差パターン（中盤 −30%、終盤拮抗、eval で逆転）となり **判定保留**。fire_reset は env 力学を変えるため単一 seed では軌道分岐と切り分けられない。
11. **ピークアウト劣化は 6 例観測**。Nature CNN −12.0%（44M）、IMPALA fire_off −1.6%（49.4M、未飽和で終了）、IMPALA fire_on −19.9%（66.8M）、b50 −16.8%（80.6M）、tau30 −25.3%（91.5M）、wd01 −29.5%（38.4M）。ただし **tau30 は train EMA の値だけが落ちており、median と 432 超え率は最終 window が最高値**（323 / 16.14%）で、b50 の実質的な崩れ（最終 window で median 134）とは別物である。EMA ピークは一過性のスパイクを拾うため、劣化の判定は分布側（median / 432 超え率）で行うべき。なお **Nature の Methods は評価値について "the highest average episode score is reported" と明記**しており、401.2 も best checkpoint の値である。
12. **ViT ハイブリッドは exp_step 軸では優位だが、throughput −46% で相殺される**（探索ブロック 09）。壁時計 12.6h を揃えると eval1 は IMPALA 419.2 対 ViT 348.4 で逆転する。ViT の優位の実体は **ε 摂動への頑健性**で、同一重みから ε=0.01 を外すと IMPALA は 1.82 倍に跳ね、ViT は 0.99 倍で変わらない。IMPALA は後期に二峰化し（45-50M で p25 60 / median 97 / p75 323）、この下側の峰が「ポカミス」として観測される。**ただしこの測定は両腕 `grad_clip_tau = 5` で行っており、tau = 30 で揃えると効果量は 3 分の 1 に縮む（探索ブロック 14）。**
13. **PER beta スケジュールは `per_beta_step` 10M < 50M**（探索ブロック 10）。30M 以降で開き、30-40M の train 生スコアが 80.9 対 134.1。**予算 100M に対しても `per_beta_step = 50M` のままが最良**で、「総予算に合わせる」という当初の運用則は実測が反証した。beta とクリップ飽和の交絡は探索ブロック 12 で解けた（飽和は利益ではなく handicap だった）。`per_beta_end = 0.55` は 50M 時点では 50M 条件と優劣が付かない。
14. **Breakout 100M で eval1 直近 20 本平均 411.2、単発最高 753**（探索ブロック 11）。1 画面（432 点）超えは 40M まで 0 件だったのが 90-100M で 9.99% まで上がり、max 812。ただし測定条件は Nature（30 本平均・ε=0.05・no-op ランダムスタート）より本記録側に有利であり、同列には置けない。
15. **`grad_clip_tau` は 5 ではなく 30**（探索ブロック 12）。実測 `grad_norm_ema` が 6.0〜15.4 なのに対し tau=5 は低すぎ、`clip_ratio` 0.45〜0.99 で毎 update 発動していた。**毎回発動する安全弁は安全弁ではなく正規化器**であり、更新が方向のみを持ち大きさを失う。tau=30 にすると clip_ratio は全区間 0.01〜0.03 になり、1 画面（432 点）超えが 40-50M → **30-40M** と前倒し、90-100M で **16.14% 対 5.60%**、median **323 対 134**。throughput は同等。beta の効きがクリップ飽和経由という仮説はこれで否定された。
16. **`weight_decay = 0.1` は不採用**（探索ブロック 13）。0-30M では +40〜99% と大きく先行するが 30M で交差し、45-50M で **−43.4%**。1 画面超えは全期間 0.09%（tau30 は 5.12%）で壁をほぼ破れない。**機序自体は働いており**、中央値を揃えた比較で `q_gap/q_max` が 0.0301 → 0.0225（−25%）、loss 1.26 → 0.69 と Q は狙いどおり滑らかになった。**それでも成績は落ちた**ため、Q の過鋭化は症状であって直接下げにいく対象ではないと結論する。
17. **eval1（target net）は全 Run で eval2（online net）よりスコアも安定性も上**。`soft_update_tau = 0.001` の重み EMA が Polyak 平均として働く。比は構成が良くなるほど 1 に近づき（tau30 で 1.06、同 step 対比較の eval1 勝率 48.3%）、**online net の健全性指標として使える**。文献比較には eval2 を用いる。
18. **ViT の効果は分布の下側に限られ、greedy 評価には出ない**（探索ブロック 14）。`grad_clip_tau = 30` で揃えると 35-40M の train median 比は **+57%**（tau=5 では +166%）。p25 は +124%（148 対 66）だが **p75 / p90 と 1 画面超え率は IMPALA が上回り**（391 / 426 対 377 / 408、40-45M で 2.41% 対 0.71%）、eval1 40-50M は 331.4 対 314.0 でブレ幅内。**ViT は下振れを潰す装置であって上限を上げる装置ではない**。軽量版（d96 / 2 層 / ff 384）は 44.4M で頭打ちになり、d128 / 4 層は 50M 時点でまだ上昇中だった。
19. **現在の eval 設定は NN 構成の A/B を判定できない**（探索ブロック 14）。確率的要素が皆無で、ある重みに対する eval は毎回同一の 1 軌道になる。40-50M の eval1 で 5% の差（331.4 対 314.0）が判定不能だったのはこの構造による。

## 探索ブロック 01: num_envs

**記録時点:** 2026-08-15、Pong 2.5M
**状態:** superseded（探索ブロック 05・06 が実測で置き換えた）。wall-clock 比較は invalidated（PRD 053 の eval 発火バグによる）。学習効率の傾向（大きい N が不利）はブロック 06 で再現された
**確度:** low。single-seed、Pong のみ

### 探索観点

num_envs をいくつに置くか。Random Policy によるラダー測定（8〜1024）で env スループット天井を測り、実構成での必要量とのマージンで決める。

### 探索結果

Random Policy ラダーの `exp_step_per_sec` は num_envs に対し単調増加（n32 5.1k → n512 11.5k → n1024 12.1k）。しかし実構成では learner 律速であり、この天井は一度も binding しない。

実構成 n512 対 n64 の 2.5M 比較:

| | n512 | n64 |
|---|---|---|
| eval1 [2.0-2.5M] | **-5.79** | **+7.10** |
| eval2 [2.0-2.5M] | -5.31 | +6.06 |
| train score EMA @2.5M | -19.45 | -13.16 |
| episode_len @2.5M | 3,093 | 5,342 |
| 真の throughput | 1,264 steps/s | 478 steps/s |

wall-clock では n512 が 2.65 倍速く見えたが、これは eval 発火頻度の差によるものだった（n512 は `LCM(16,100)=400` 更新周期、n64 は 100 更新周期で 4 倍発火）。n64 の eval interval を 500 にして頻度を揃えると 1,198 steps/s となり、n512 の 1,264 steps/s とほぼ一致する。

### 考察

学習効率の差は実在する。lane あたりの進行量が n512 で 4,878 step（完了エピソード 3.5 本）に対し n64 は 38,995 step（18.7 本）であり、同時に終端する lane 数の実測が n512 2.98 / n64 1.11 と、n512 では lane 位相が揃っている。`noop_max=0` で全 lane が同一初期状態から同時発進し、かつ lane あたりのエピソード数が少ないため位相がほどけない。RB 1M を per-lane 時間で見ると n512 は 2,048 lane-step 分しか覆わず、状態カバレッジが薄くなる。

同一 config の反復（eval interval のみ違う 2 Run）で train 曲線が小数以下まで完全一致したため、この環境での Run 間ブレは実質ゼロであり、n512 対 n64 の差はノイズではなく num_envs 由来と確定できる。

### 状態

num_envs の測定は eval 発火バグの影響下で行われ、値の解釈が複雑になった。PRD 053 実装後に探索ブロック 05・06 で再取得し、本ブロックは superseded とする。ただし「lane 位相の同期が大きい N の学習効率を下げる」という機序はブロック 06 でも再現しており、その部分は現在も有効な証拠である。

## 探索ブロック 02: eval interval の wall-clock 影響

**記録時点:** 2026-08-15、Pong 2.5M
**状態:** completed
**確度:** high。同一 config の反復で train 曲線が完全一致

### 探索観点

eval が wall-clock をどれだけ食っているか。

### 探索結果

num_envs 64 固定で eval interval のみ 100 → 500 に変更:

| | interval 100 | interval 500 |
|---|---|---|
| eval 発火間隔 | 3,200 exp_step | 16,000 exp_step |
| eval エピソード総量 | 3.24M single-env step | 0.64M |
| 真の throughput | 478 steps/s | **1,198 steps/s** |
| 2.5M 到達 | 1.452h | **0.580h** |
| train score EMA @2.5M | -13.16 | **-13.16**（完全一致） |

`exp_step_per_sec` メトリクスの表示値は 1,830 対 1,531 で、真値（478 対 1,198）と乖離していた。旧実装は 200ms 窓の瞬間値を時間重みなしで拾うため、stall 区間が観測から抜けていた（PRD 053 で修正）。

### 考察

train 曲線・loss・episode_len が小数以下まで一致したことから、eval 頻度は学習に一切影響せず、差分は純粋に eval の実行コストである。eval エピソード長はスキル向上に伴って伸びる（Pong で 764 → 5,342 step）ため、固定 interval では Run 後期ほど eval が高くつく。interval 100 の後期（2.0-2.5M）は 334 steps/s まで落ちた。

## 探索ブロック 06: num_envs の実構成ラダー（学習あり）

**記録時点:** 2026-08-17
**状態:** completed
**確度:** medium-high。single-seed だが 7 点 × 2 周で再現性を確認、n64 を各周の先頭・末尾に置いてドリフト検証済み

### 探索観点

learner を含む実構成で num_envs を決める。ブロック 05 の天井に対する実際の利用率と、exp_step あたりの学習効率の両方を同時に測る。

### 探索条件

Breakout / v5 素（sticky 0.25、episodic_life false）/ BF16 learner / `backend.non-deterministic` / `main_runner_type = pipeline` / **eval OFF**（`train.eval_schedule.[eval1,eval2].interval = 0`）/ 各 2,000,000 exp_step。

eval を切ったのは、`eval_batch_size = 1` のため eval コストが num_envs に依存せず、大きい N ほど相対コストが下がって系統誤差になるため。

2M にしたのは RB capacity 1,048,576 を超えさせるため。前半 0-1M は eviction が起きず、後半 1M-2M が実運用条件になる。

順序は `64a → 32 → 128 → 256 → 512 → 1024 → 64b` を 2 周。

### 探索結果

**測定の妥当性: 1 周目の前半は暖機で系統的に遅い。**

### 考察

**N=128 を採用する。** throughput が +9% 上がって学習効率は無傷（−0.8% はブレ幅内）。N=256 以上は throughput が伸びないまま学習だけ落ちるため、選ぶ理由がない。

学習効率の劣化は完了ゲーム数と対応している（N=256 で −16%、N=1024 で −62%）。同じ exp_step を集めても lane あたりの進行が浅いとゲームが完了せず、エピソード終端という学習信号が減る。根にあるのはブロック 01 と同じ lane 位相の同期で、`noop_max = 0` により全 lane が同一初期状態から同時発進する構成に起因する。

env 天井（ブロック 05）に対する実構成の利用率は N=64 で 31%、N=256 で 25% であり、**env は律速していない**。N を上げて速くなる分は env の並列度ではなく、actor forward が batch N で 1 回にまとまることによる step あたりコストの低下と考えられる。それが N=128 で頭打ちになるのは、そこから先は learner 側が律速に回るため。

RB が満杯になる後半では throughput が 14.5〜20% 落ちる。2 周目では N 依存の傾向はない（1 周目で見えた「N が大きいほど RB コストが大きい」は暖機の artifact であり、invalidated）。

本結論は現在の learner コストに依存する。RR / batch / num_quantiles / NN 構成を変えると env と learn のバランスが移動するため、そのときは再評価が要る。メモリ消費も N に比例して増える（N=1024 でも本機では収まった）。参考として DropMerge は N=256 を採用している。

eval1 直近 20 本平均は 388.6 対 411.2 で差が無い。これは 80M 以降の eval が 18,000 frames 上限に 6〜9% 到達して打ち切られているため（メタデータ「eval 上限が拘束側へ」参照）。

### 考察

**飽和相は利益ではなく handicap だった。** tau30 は b50 を全区間で上回り、1 画面突破の初出が 40-50M から 30-40M へ 10M 以上前倒しになった。したがって探索ブロック 10 で残した「beta の効きはクリップ飽和を抜けたことが本体では」という可能性は否定される。beta の寄与はむしろ**それが誘発するクリップ飽和によって一部打ち消されていた**ことになり、実効は測定値より大きい。

`grad_clip_tau = 5` は `DefaultDQNAgent.baseline` から継承した値で Atari 用に検証されていなかった。実測 `grad_norm` の半分以下という設定は、**異常時の安全弁ではなく毎 update 発動する正規化器**として働く。`clip_ratio` が 1.0 に張り付く区間では更新が方向のみを持ち大きさの情報を失うため、最適化の regime そのものが変わっていた。

**劣化判定は分布側で行うべきである。** train EMA だけ見ると tau30 は 302.42 @91.5M から −25.3% でピークアウトに見えるが、median は最終 window が 323 で全区間最高、432 超え率も 16.14% で最高である。b50 は同じ最終 window で median 134 まで落ちており、こちらは実質的な崩れ。EMA は一過性のスパイクをピークとして拾うため、単独では劣化の指標にならない。

## 探索ブロック 13: weight_decay

**記録時点:** 2026-08-22
**状態:** completed（不採用）
**確度:** medium。single-seed、48M で停止

### 探索観点

実力帯を揃えた `q_gap/q_max`（= Q_top1 と Q_top2 の差を Q_top1 で正規化）が構成ごとに大きく違い、値が小さい構成ほど成績も頑健性も良い、という相関が出ていた（med 244 で b50 0.0759 / tau30 0.0362 / ViT 0.0244）。この「Q の過鋭化」を weight decay で直接下げると成績が改善するかを見る。

BBF（Schwarzer et al. 2023）は同じ `replay_ratio = 8` で AdamW の weight decay 0.1 を採用し、高い replay ratio では過学習しやすいことを理由に挙げている。本実装は既に AdamW を使い `weight_decay` が config から配線済みのため、設定のみで再現できる。

### 探索条件

tau30（`run_20260821-122717`）に対し **`weight_decay` を 0 → 0.1 に変えた 1 行のみ**の差分。config dump 差分でも `DefaultDQNAgent.learner.weight_decay` 以外に実効差は無い。48,000,000 step で停止。

### 考察

**機序は働いたが、成績は落ちた。** `q_gap/q_max` は 25% 下がり、loss も分散も下がり、Q は狙いどおり滑らかになった。それでも 30M 以降は一貫して劣後し、壁も破れなかった。したがって **Q の過鋭化は症状であって、直接下げにいく対象ではない**と結論する。

ViT の滑らかさは表現から来た結果であり、weight decay の滑らかさは重みを一律に縮めた結果である。同じ `q_gap/q_max` という数値が出ていても中身が異なり、後者は容量を削るため終盤の 2 面プレイや長時間ラリーで不足する。0-30M で大きく先行したのは、序盤は容量を絞るほど汎化が速いという同じ効果の表側と解釈できる。

BBF が 0.1 を採用できたのは Atari-100k（10 万 step）という過学習が支配的で容量が余る領域だからで、1 億 step の設定には転移しない。

`q_gap/q_max` は診断指標としては引き続き有効だが、**それ自体を目的関数に据えると誤誘導される**。

## 探索ブロック 14: NN 構成（ViT 軽量版 / grad_clip_tau 30 での再評価）

### 考察

**tau = 30 で ViT の効果量は 3 分の 1 になるが消えない。** 35-40M の median 比が +166% から +57% へ縮んだ。探索ブロック 09 の測定は両腕 tau=5 で行っており、探索ブロック 12 が tau=5 を handicap と判定した以上、あのブロックの効果量は過大評価である。飽和は IMPALA 側をより強く傷めていた。

**ViT が動かすのは分布の下側だけである。** p25 は IMPALA 63〜66 に対し ViT 140〜148（+124%）だが、p75 / p90 は imp_t30 が最高（391 / 426 対 377 / 408）で、1 画面超え率も imp_t30 が上（40-45M で 2.41% 対 0.71%）。**ViT は下振れを潰す装置であって、上限を上げる装置ではない。** 探索ブロック 09 の「IMPALA は後期に二峰化する」という所見は tau = 30 でも残っている。

**greedy 評価では差が消える。** 40-50M の eval1 は imp_t30 331.4 対 lite_t30 314.0 で、n = 25〜29・p25-p75 幅 130〜150 に対してブレ幅内である。train median で +81%（304 対 168）ついた差が eval に出ない。探索ブロック 09 が「差の実体は ε 摂動への頑健性」と結論した内容を、tau = 30 で再現したことになる。**採用判断は探索ブロック 09 から変わらない。**

**現在の eval は NN 構成の A/B を判定できない。** eval は `eval_batch_size = 1`・`eval_policy.policy_type = Greedy`・`tau_rule.sample_mode = fixed`・`use_amp = false`、env 側は sticky 0 / `noop_max = 0` で、確率的要素が 1 つも無い。したがって**ある重みに対する eval は毎回同一の 1 本の軌道**であり、本数を増やしても複製にしかならない。eval 生値のばらつきは標本分散ではなく、重み更新に対する軌道の不連続性である。上表で 5% の差が判定不能なのはこの構造による。

**軽量版で十分とは言えない。** lite_t30 は 44.4M で EMA ピークを打ち、45-50M で median 310 → 297、1 画面超え 0.71% → 0.20% と落ちた。一方 vit_t5（d128 / 4 層）は 50M 時点で median・1 画面超え率ともに最終 window が最高値で、EMA ピークも最後尾にある。tau が異なるため直接比較はできないが、d96 / 2 層が 45M 付近で頭打ちになる側の証拠になっている。
