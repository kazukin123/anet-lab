## 現時点のまとめ

1. **sticky actions が Breakout で支配的**。0.25 → 0.0 で train 生スコア 42 → 119（2.8 倍）。v5 プリセットのまま回すと 5M step で 42 に飽和し、以降 22M step 分がほぼ無駄になる。sticky 0 では 50M まで伸び続けた。
2. **episodic_life は単独では効果ゼロ**。sticky 0.25 固定で false / true を 27M step 比較し、train 生スコア 42.0 対 41.9、median 41 対 41 で差がない。中間指標（`q_gap_rel` 上昇、`q_max` 低下）は設計どおり動いており、機構は効いているがスコアに繋がらなかった。`lives` が 3.45 対 3.64 と変わらないことが決定的で、死ぬ頻度そのものが改善していない。
3. **sticky 0 では `lives` が明確に上昇する**（3.4 → 4.3）。episodic_life で動かなかった同じ指標が動いたことから、Breakout のプラトーはパドル制御の精度で律速されていたと解釈できる。
4. **eval が wall-clock を支配しうる**。Pong で `interval` 100 → 500 にすると真の throughput が 478 → 1,198 steps/s（2.5 倍）。train 曲線は完全一致しており、差分は eval の実行コストのみ。
5. **num_envs は N=128 が最適**（探索ブロック 06）。実構成 2M ラダーで throughput が N=128 で頭打ち（+9.1%、それ以上は差がブレ幅内）、学習効率は N=128 まで無傷で N=256 から崩れる（−17%）。wall-clock 効率は N=128 が最良（+5.2%）。この結論は現在の learner コストに依存するため、RR / batch / quantile / NN 構成を変えたら再評価が要る。参考として DropMerge は N=256 を採用している。
6. **Breakout 50M（sticky 0 / episodic_life true / noop 0 / fire_reset false）で train 生スコア 119.4、eval1 115.7**。43-44M で train 140.1 のピークを打ち、以降 -15% で 119 台に安定。100 点超が 50.1%、300 点超が 3.6%、ピーク期の max 427（1 画面 432 点にほぼ到達）。
7. Pong は v5 プリセット・num_envs 64 で 1M step から動き出し、2.5M で eval1 +7.10。
8. **NN は IMPALA-CNN を採用**（探索ブロック 07）。同じ 50M で train 生スコア 134.7 対 121.2、eval1 147.7 対 115.7。差の本体はサンプル効率で、中盤（10-25M）に 2 倍前後がつく。加えて **Nature CNN は 44M でピークアウトして −12.0% 劣化するのに対し IMPALA は −1.6% で、ピークが最後尾にあり 50M でも飽和していない**。高得点の裾も違い、≥400 点は IMPALA だけが出す（1.0% 対 0.0%、max 431 対 384）。
9. **`fire_reset = false` は Breakout で無報酬 step を生む**。ライフ喪失でボールが消え FIRE を押すまで再投入されないため、1 ゲームに 4 回、エージェントが自力で FIRE を選ぶまで待ちが入る。上記 8 までの全 Run がこの条件下にある。2026-08-18 に life-loss 後の soft-reset でも FIRE 系列を打つよう実装を修正した（`fire_reset=false` では挙動不変）。
10. **100M 長期で eval1 best window 337.5、HNS57 1166%**（探索ブロック 08）。Nature DQN の Breakout 401.2（HNS57 換算 1387%）の 84% に相当する。50M 以降で一段上のレジームに入り、eval1 が 50M までの最高 160.1 から 2 倍超へ伸びた。`fire_reset` の A/B は 0-50M で交差パターン（中盤 −30%、終盤拮抗、eval で逆転）となり **判定保留**。fire_reset は env 力学を変えるため単一 seed では軌道分岐と切り分けられない。
11. **ピークアウト劣化は 6 例観測**。Nature CNN −12.0%（44M）、IMPALA fire_off −1.6%（49.4M、未飽和で終了）、IMPALA fire_on −19.9%（66.8M）、b50 −16.8%（80.6M）、tau30 −25.3%（91.5M）、wd01 −29.5%（38.4M）。ただし **tau30 は train EMA の値だけが落ちており、median と 432 超え率は最終 window が最高値**（323 / 16.14%）で、b50 の実質的な崩れ（最終 window で median 134）とは別物である。EMA ピークは一過性のスパイクを拾うため、劣化の判定は分布側（median / 432 超え率）で行うべき。なお **Nature の Methods は評価値について "the highest average episode score is reported" と明記**しており、401.2 も best checkpoint の値である。
12. **ViT ハイブリッドは exp_step 軸では優位だが、throughput −46% で相殺される**（探索ブロック 09）。壁時計 12.6h を揃えると eval1 は IMPALA 419.2 対 ViT 348.4 で逆転する。ViT の優位の実体は **ε 摂動への頑健性**で、同一重みから ε=0.01 を外すと IMPALA は 1.82 倍に跳ね、ViT は 0.99 倍で変わらない。IMPALA は後期に二峰化し（45-50M で p25 60 / median 97 / p75 323）、この下側の峰が「ポカミス」として観測される。**ただしこの測定は両腕 `grad_clip_tau = 5` で行っており、tau = 30 で揃えると効果量は 3 分の 1 に縮む（探索ブロック 14）。**
13. **PER beta スケジュールは `per_beta_step` 10M < 50M**（探索ブロック 10）。30M 以降で開き、30-40M の train 生スコアが 80.9 対 134.1。**予算 100M に対しても `per_beta_step = 50M` のままが最良**で、「総予算に合わせる」という当初の運用則は実測が反証した。beta とクリップ飽和の交絡は探索ブロック 12 で解けた（飽和は利益ではなく handicap だった）。`per_beta_end = 0.55` は 50M 時点では 50M 条件と優劣が付かない。
14. **Breakout 100M で eval1 直近 20 本平均 411.2、単発最高 753**（探索ブロック 11）。1 画面（432 点）超えは 40M まで 0 件だったのが 90-100M で 9.99% まで上がり、max 812。ただし測定条件は Nature（30 本平均・ε=0.05・no-op ランダムスタート）より本記録側に有利であり、同列には置けない。
15. **`grad_clip_tau` は 5 ではなく 30**（探索ブロック 12）。実測 `grad_norm_ema` が 6.0〜15.4 なのに対し tau=5 は低すぎ、`clip_ratio` 0.45〜0.99 で毎 update 発動していた。**毎回発動する安全弁は安全弁ではなく正規化器**であり、更新が方向のみを持ち大きさを失う。tau=30 にすると clip_ratio は全区間 0.01〜0.03 になり、1 画面（432 点）超えが 40-50M → **30-40M** と前倒し、90-100M で **16.14% 対 5.60%**、median **323 対 134**。throughput は同等。beta の効きがクリップ飽和経由という仮説はこれで否定された。
16. **`weight_decay = 0.1` は不採用**（探索ブロック 13）。0-30M では +40〜99% と大きく先行するが 30M で交差し、45-50M で **−43.4%**。1 画面超えは全期間 0.09%（tau30 は 5.12%）で壁をほぼ破れない。**機序自体は働いており**、中央値を揃えた比較で `q_gap/q_max` が 0.0301 → 0.0225（−25%）、loss 1.26 → 0.69 と Q は狙いどおり滑らかになった。**それでも成績は落ちた**ため、Q の過鋭化は症状であって直接下げにいく対象ではないと結論する。
17. **eval1（target net）は全 Run で eval2（online net）よりスコアも安定性も上**。`soft_update_tau = 0.001` の重み EMA が Polyak 平均として働く。比は構成が良くなるほど 1 に近づき（tau30 で 1.06、同 step 対比較の eval1 勝率 48.3%）、**online net の健全性指標として使える**。文献比較には eval2 を用いる。
18. **ViT の効果は分布の下側に限られ、greedy 評価には出ない**（探索ブロック 14）。`grad_clip_tau = 30` で揃えると 35-40M の train median 比は **+57%**（tau=5 では +166%）。p25 は +124%（148 対 66）だが **p75 / p90 と 1 画面超え率は IMPALA が上回り**（391 / 426 対 377 / 408、40-45M で 2.41% 対 0.71%）、eval1 40-50M は 331.4 対 314.0 でブレ幅内。**ViT は下振れを潰す装置であって上限を上げる装置ではない**。軽量版（d96 / 2 層 / ff 384）は 44.4M で頭打ちになり、d128 / 4 層は 50M 時点でまだ上昇中だった。
19. **現在の eval 設定は NN 構成の A/B を判定できない**（探索ブロック 14）。確率的要素が皆無で、ある重みに対する eval は毎回同一の 1 軌道になる。40-50M の eval1 で 5% の差（331.4 対 314.0）が判定不能だったのはこの構造による。
20. **崩壊の正体は可塑性喪失で、レバーは `replay_ratio`**（探索ブロック 15）。BTR 準拠バンドル（IQN + IMPALA Scale=2 + γ 0.997）は **2.5M step で median 335** に達し、旧ベースラインが 101M で記録した最高値 332 を **約 38 分の 1 のサンプル**で超えたが、その後崩壊した。`weight_decay` / プロトコル / `per_beta_step` / `replay_capacity` / BF16 を単変数で順に排除し、**`replay_ratio` 8 → 4 で解決**。勾配 step 数で揃えるとピークが 197 → 295（+50%）、底が対ピーク 37.6% → 47.5% で回復もする。機序も直接測れており、同一勾配 step・同一 `q_max`（6.64 対 6.65）で **`q_gap` が 2 倍**（0.0679 対 0.1361）。throughput も 1,047 → 2,063 steps/s で**両軸で勝ち**。γ = 0.997 を使う BTR と BBF は**どちらも可塑性保護機構（Spectral Norm / reset）を持っており、本コードベースはどちらも未実装**である。
21. **v5 の eval は ε = 0 だと FIRE デッドロックに落ちる**（探索ブロック 16）。`fire_reset = false` + Greedy の組み合わせで、ボール未投入の局面から抜けられず上限 27,000 step まで空転する（`lives` 5.00 が証拠）。sticky は「直前行動の繰り返し」なので脱出手段にならない。**`q_gap` が大きい良い方策ほど発生率が高い**（RR4 24% 対 RR8 8%）。eval ε = 0.01（BTR 値）で解消する。
22. **RR=4 は 200M frames でも崩壊しないが、30M で天井を打つ**（探索ブロック 17）。50M / 6.07h を完走し、探索ブロック 15 の崩壊署名（ピーク後劣化・識別性崩壊・勾配縮小・loss 縮小・`q_max` 頭打ち）はどれも出なかった。ただし **train 生スコアの window 平均は 30M 以降 4 窓で 246.8 / 242.7 / 247.5 / 246.0 と完全に横ばい**で、分布の形（CV・p25・p90・`<100` 率）も動かない。その間 td_mean 0.332 → 0.352、grad_norm 1.61 → 1.72、loss 0.241 → 0.267 と学習側は上昇しており、**動いているのに前に進まない**状態である。throughput は 200M frames / 6.07h で BTR（同 frames / 12h）の約 2 倍。
23. **低スコア裾は予算では消えず、アーキでだけ動く**（探索ブロック 18）。低スコア帯の実体は「停止」ではなく「短命」で、`score<50` かつ `game_len>3000` は 0 本、train 側に FIRE デッドロックは 1 本も無い。tau30 の `<100` は 70M 以降 33.8% → 33.9% で飽和する一方、同じ Run の `≥432` は 1.0% → 17.4% と伸び続ける。**「上手いエピソードは伸びるがポカる率は下がらない」という分離**が起きている。同一 protocol・同一 window で `<100` は ViT 13.5% 対 IMPALA 36.3% で、ViT だけが 31.2% → 18.6% → 13.5% と下げ続ける。sticky を切ってあった旧 Run のほうが低スコア側は酷い（34% 対 19%）ので、**protocol でも eval ε でもない**。また **432 は能力上限ではない**（tau30 は 96-101M で max 773）。ラック掃き切りは 50M〜75M で立ち上がる遅い現象である。
24. **γ 0.997 で相対 action gap が 4〜5 分の 1 に潰れ、BF16 の余裕も失われた**（探索ブロック 19）。γ 0.99 の `q_gap / q_max` は 3.6〜4.1% だが、γ 0.997 では `q_max` が 3.6-4.0 → 11.9 と 3 倍に膨らみ 絶対 `q_gap` は 0.145 → 0.097 と縮んで **0.81%** になる。BF16 の相対分解能 2⁻⁸ に対する比は 9〜10 → **2.08**（1.55 ULP）。探索ブロック 15 の「RR4 は 4.36 ULP で余裕がある」は `q_max` 6.65 時点の値で、`q_max` の成長とともに余裕は消えた。actor / eval の forward は FP32 なので行動選択は量子化されないが、**識別性を教える learner 側が 1.5 ULP しか差を持たない**。ただし **低スコア裾は action gap では説明できない** — ViT は gap/max 0.0223 と tau30 の 0.0362 より狭いのに `<100` は 13.5% 対 36.3% で良く、向きが逆である。

## 探索ブロック 01: num_envs

**記録時点:** 2026-08-15、Pong 2.5M
**状態:** superseded（探索ブロック 05・06 が実測で置き換えた）。wall-clock 比較は invalidated（PRD 053 の eval 発火バグによる）。学習効率の傾向（大きい N が不利）はブロック 06 で再現された

### 探索観点

num_envs をいくつに置くか。Random Policy によるラダー測定（8〜1024）で env スループット天井を測り、実構成での必要量とのマージンで決める。

### 探索結果

Random Policy ラダーの `exp_step_per_sec` は num_envs に対し単調増加（n32 5.1k → n512 11.5k → n1024 12.1k）。しかし実構成では learner 律速であり、この天井は一度も binding しない。

実構成 n512 対 n64 の 2.5M 比較:

| | n512 | n64 |
|---|---|---|
| eval1 [2.0-2.5M] | **-5.79** | **+7.10** |
| eval2 [2.0-2.5M] | -5.31 | +6.06 |
| train score EMA @2.5M | -19.45 | -13.16 |
| episode_len @2.5M | 3,093 | 5,342 |
| 真の throughput | 1,264 steps/s | 478 steps/s |

wall-clock では n512 が 2.65 倍速く見えたが、これは eval 発火頻度の差によるものだった（n512 は `LCM(16,100)=400` 更新周期、n64 は 100 更新周期で 4 倍発火）。n64 の eval interval を 500 にして頻度を揃えると 1,198 steps/s となり、n512 の 1,264 steps/s とほぼ一致する。

### 考察

学習効率の差は実在する。lane あたりの進行量が n512 で 4,878 step（完了エピソード 3.5 本）に対し n64 は 38,995 step（18.7 本）であり、同時に終端する lane 数の実測が n512 2.98 / n64 1.11 と、n512 では lane 位相が揃っている。`noop_max=0` で全 lane が同一初期状態から同時発進し、かつ lane あたりのエピソード数が少ないため位相がほどけない。RB 1M を per-lane 時間で見ると n512 は 2,048 lane-step 分しか覆わず、状態カバレッジが薄くなる。

同一 config の反復（eval interval のみ違う 2 Run）で train 曲線が小数以下まで完全一致したため、この環境での Run 間ブレは実質ゼロであり、n512 対 n64 の差はノイズではなく num_envs 由来と確定できる。

### 状態

num_envs の測定は eval 発火バグの影響下で行われ、値の解釈が複雑になった。PRD 053 実装後に探索ブロック 05・06 で再取得し、本ブロックは superseded とする。ただし「lane 位相の同期が大きい N の学習効率を下げる」という機序はブロック 06 でも再現しており、その部分は現在も有効な証拠である。

## 探索ブロック 03: Breakout プロトコル（sticky / episodic_life）

**記録時点:** 2026-08-16
**状態:** completed
**確度:** medium。single-seed だが、飽和後 20M step 以上の平均で判定しており差は明瞭

### 探索観点

v5 プリセット（Machado 2018 準拠）で Breakout が 5M step・42 点で飽和した。文献値（Nature DQN 401.2）との差が大きく、プロトコル条件のどれが効いているかを切り分ける。

### 探索条件

`E` 層で 1 要素ずつ変更。ベースラインは v5（sticky 0.25 / noop 0 / episodic_life false / fire_reset false）。

### 探索結果

**episodic_life（sticky 0.25 固定、27M / 29M）**

| 指標（直近 3M） | false | true |
|---|---|---|
| train 生スコア mean | 42.0 | 41.9 |
| median | 41 | 41 |
| p90 | 59 | 63 |
| max | 229 | 210 |
| eval1（直近 5M） | 46.1 | 43.4 |
| `lives` | 3.45 | 3.64 |
| `q_max_mean` @25M | 2.33 | 1.60 |
| `q_gap_rel` @25M | 0.010 | 0.018 |
| `loss_ema` @25M | 0.064 | 0.164 |

1M ごとの推移でも、序盤（〜3M）は true がやや速く、5〜15M は false が上、20M 以降は拮抗し、両者とも 41〜43 の同じプラトーに収束した。

**sticky（episodic_life true 固定、50M）**

| | sticky 0.25 | sticky 0.0 |
|---|---|---|
| train 生スコア mean（直近 3M） | 41.9 | **119.4** |
| median | 41 | 100 |
| p90 | 63 | 247 |
| max | 210 | 384（ピーク期 427） |
| 100 点超の割合 | — | 50.1% |
| 200 点超 | — | 14.9% |
| 300 点超 | — | 3.6% |
| eval1（直近 5M） | 43.4 | 115.7 |
| `lives` | 3.4〜3.6 で横ばい | **4.03 → 4.33 と上昇** |
| `game_len` | 約 1,030 | 1,509〜2,579 |

### 考察

episodic_life は `q_max`（1 ライフ分の価値へ低下）と `q_gap_rel`（行動間の価値差が拡大）に設計どおりの変化を与えたが、`lives` が動かなかった。ボールを落とす直前の状態ではパドルが既に間に合わない位置にあり、そこへ負の信号を積んでも「先回りする」能力は上がらなかったと解釈できる。

sticky 0 では同じ `lives` が明確に上昇した。sticky は 4 回に 1 回前の行動が固着するため、パドルの精密制御を直接阻害する。Breakout は狙った列に当て続けてトンネルを掘る戦略が高得点の要件であり、そこが塞がれていた。

episodic_life=true 下では eval の記録周期が 5 倍（160,000 → 800,000 exp_step）になる。`RunEvaluationEpisode` が最初の done で停止し、life-loss done ではスコアが未確定（NaN）で記録されないため。記録時点の `lives` 平均が 3.04 で、理論値 (4+3+2+1+5)/5 = 3.0 と一致した。**値そのものは正しく、周期だけが 5 倍になる**（生スコアは soft-reset で切れない）。

## 探索ブロック 06: num_envs の実構成ラダー（学習あり）

**記録時点:** 2026-08-17
**状態:** completed
**確度:** medium-high。single-seed だが 7 点 × 2 周で再現性を確認、n64 を各周の先頭・末尾に置いてドリフト検証済み

### 探索観点

learner を含む実構成で num_envs を決める。ブロック 05 の天井に対する実際の利用率と、exp_step あたりの学習効率の両方を同時に測る。

| 1024 | 110.7% | 32.9% | 36.4% |

### 考察

**N=128 を採用する。** throughput が +9% 上がって学習効率は無傷（−0.8% はブレ幅内）。N=256 以上は throughput が伸びないまま学習だけ落ちるため、選ぶ理由がない。

学習効率の劣化は完了ゲーム数と対応している（N=256 で −16%、N=1024 で −62%）。同じ exp_step を集めても lane あたりの進行が浅いとゲームが完了せず、エピソード終端という学習信号が減る。根にあるのはブロック 01 と同じ lane 位相の同期で、`noop_max = 0` により全 lane が同一初期状態から同時発進する構成に起因する。

env 天井（ブロック 05）に対する実構成の利用率は N=64 で 31%、N=256 で 25% であり、**env は律速していない**。N を上げて速くなる分は env の並列度ではなく、actor forward が batch N で 1 回にまとまることによる step あたりコストの低下と考えられる。それが N=128 で頭打ちになるのは、そこから先は learner 側が律速に回るため。

RB が満杯になる後半では throughput が 14.5〜20% 落ちる。2 周目では N 依存の傾向はない（1 周目で見えた「N が大きいほど RB コストが大きい」は暖機の artifact であり、invalidated）。

本結論は現在の learner コストに依存する。RR / batch / num_quantiles / NN 構成を変えると env と learn のバランスが移動するため、そのときは再評価が要る。メモリ消費も N に比例して増える（N=1024 でも本機では収まった）。参考として DropMerge は N=256 を採用している。

**したがって 50M 時点では b50 と b055 の優劣は付いていない。** b50 の優位が明確になるのは 50M 以降（探索ブロック 11）であり、b055 はその区間を走っていない。

**予算との関係.** b50 は予算 100M に対して `per_beta_step` を 50M のまま回して最良の結果を出した。「`per_beta_step` は回しきる総ステップ数に合わせる」という当初の運用則は本 Run が反証しており、実測上は 50M 固定が最良である。

**未分離の交絡.** beta を動かすと `clip_ratio` の regime も動く。b10 は 0.12〜0.68 で非飽和、b50 と b055 は 0.85〜1.00 で飽和している。`grad_clip_tau = 5` は固定なので、b50 は `grad_norm` が 12.8 → 5.6 と下がるにつれ飽和を抜けた（clip 1.00 → 0.39）が、b055 は最後まで抜けていない。`clip_ratio` が 1.0 の区間では更新が方向のみを持ち大きさの情報を失うため、**「beta が効いた」のか「クリップ飽和を抜けたことが効いた」のかは本ブロックでは分離できない**。

なお `q_max` は 3 本とも 2.06〜4.00 に収まっている。`reward_clip` と `gamma 0.99` による理論上限 100 に対して十分低く、Q 値の発散は観測されていない。

## 探索ブロック 12: grad_clip_tau（クリップ飽和の切り分け）

**現在の eval は NN 構成の A/B を判定できない。** eval は `eval_batch_size = 1`・`eval_policy.policy_type = Greedy`・`tau_rule.sample_mode = fixed`・`use_amp = false`、env 側は sticky 0 / `noop_max = 0` で、確率的要素が 1 つも無い。したがって**ある重みに対する eval は毎回同一の 1 本の軌道**であり、本数を増やしても複製にしかならない。eval 生値のばらつきは標本分散ではなく、重み更新に対する軌道の不連続性である。上表で 5% の差が判定不能なのはこの構造による。

**軽量版で十分とは言えない。** lite_t30 は 44.4M で EMA ピークを打ち、45-50M で median 310 → 297、1 画面超え 0.71% → 0.20% と落ちた。一方 vit_t5（d128 / 4 層）は 50M 時点で median・1 画面超え率ともに最終 window が最高値で、EMA ピークも最後尾にある。tau が異なるため直接比較はできないが、d96 / 2 層が 45M 付近で頭打ちになる側の証拠になっている。

**仮説の排除。** 崩壊の原因を単変数で順に潰した。

|---|---|---|
| 62,500 | 199.6 | 236.3 |

### 考察

**崩壊の実体は可塑性喪失（capacity loss）である。** 症状が文献の署名と一致する — ピーク後の劣化、識別性の崩壊（相対 `q_gap` が 0.0229 → 0.0051 で 4.5 倍）、勾配の縮小（3.36 → 1.64）、loss の縮小（0.45 → 0.18）、`q_max` の頭打ち。加えて **weight_decay・プロトコル・β・capacity・精度のいずれを変えても同じように起きる**という頑健さが、ハイパラではなくネットワーク側の現象であることを示す。

**γ = 0.997 を使う論文は 2 本とも可塑性保護機構を持っている。**

| | replay ratio | 可塑性対策 | γ |
|---|---|---|---|
| BTR | **4** | Spectral Normalization（全 conv residual layer） | 0.997 |
| BBF | 8 | shrink-and-perturb reset（40k 勾配 step ごと）+ weight decay 0.1 | 0.997 |
| **本記録** | **8** | **なし** | 0.997 |

**BBF の replay ratio を BBF の対策なしで、BTR の γ を BTR の spectral norm なしで回していた。** 本コードベースには spectral normalization も reset 機構も実装が存在しない（grep でヒットゼロ）。ピーク時点の 78,125 勾配 step は BBF の reset 間隔 40,000 で数えるとちょうど 2 回目の直前にあたる。

**BTR の `replay_ratio` 4 は計算都合ではなく安定性の一部だった。** 本記録は以前これを「計算のための妥協であり、性能のために採る理由はない」と評価していたが、実測が反証した。

**BF16 の精度問題は可塑性喪失の下流だった。** RR8 では `q_gap/q_max` が 0.0051 まで落ち、BF16 の相対分解能 2⁻⁸ ≈ 0.0039 に迫って `q_gap` が 1 ULP を割っていた（0.62 ULP）。RR4 では同じ勾配 step で 4.36 ULP と余裕がある。**識別性が保たれていれば精度は問題にならない。**

**短予算運用そのものは成功している。** 10M / 1.35h で、旧ベースラインが 100M かけて到達した水準を大きく超えた。`per_beta_step = 予算/2` の運用則も探索ブロック 10 と本ブロック（予算 10M で 5M 対 10M、5M が勝ち）の 2 つの予算で確認された。

## 探索ブロック 16: eval の FIRE デッドロック（v5 プロファイル固有）

**記録時点:** 2026-08-23
**状態:** completed
**確度:** high。`lives` の値で機序が一意に確定する

### 探索観点

v5 プロファイルの eval1 に、スコア 0 のまま上限まで走り切る評価が断続的に現れた。原因を特定する。

### 探索結果

`run_20260823-191548`（RR4）の eval1 に、**8.18M から 9.62M まで 10 本連続で同一パターン**が出た。

| step | score | `game_len` | `lives` |
|---|---|---|---|
| 8.02M | 204 | 1,331 | 5.00 |
| 8.18M〜9.62M | **0** | **27,000** | **5.00** |
| 9.78M | 396 | 2,028 | 5.00 |

`game_len` 27,000 は `max_episode_frames` 108,000 ÷ `frame_skip` 4 の上限そのもの。**`lives` が 5.00 のまま**＝ 27,000 step のあいだ一度もミスしていない＝**ボールが一度も投入されていない**。

直後の 9.78M で 396 に戻っているため、方策そのものは無傷である。

**機序。** v5 は `fire_reset = false` なので env はボールを投入しない。eval は `eval_policy.policy_type = Greedy`（ε = 0）で完全に決定的。ボール未投入の局面で argmax が FIRE でないと、画面がほぼ静止しているため次 step も同じ argmax になり、上限まで抜けられない。

**sticky actions では脱出できない。** `repeat_action_probability` は「直前の行動を繰り返す」だけで、別の行動を導入しないため、決定的デッドロックを破る確率性にならない。

**発生率は方策が良いほど高い。**

| Run | デッドロック | 発生区間 |
|---|---|---|
| RR8 対照 | 10 / 125 本（8%） | 0.02M〜4.74M |
| RR4 | 15 / 63 本（24%） | 0.02M〜9.62M |

RR4 は `q_gap` が 2 倍で argmax がより固いため抜けにくい。RR8 は方策が崩れた 4.74M 以降は発生しなくなっている。

### 考察

**v5 プロファイルの eval1 は、eval ε = 0 のままでは信用できない。** 探索ブロック 15 までに取った v5 系の eval1 window 平均は、スコア品質とデッドロック頻度の混合を測っていた。本記録の v5 系 eval1 は**デッドロックを除外して読むこと**。

対処は eval を ε-greedy にすること。ε = 0.01・4 行動なら 1 step あたり FIRE を引く確率が 0.0025 で、1,000 step 以内の脱出確率は 92%。

```
R.eval_policy.policy_type = EpsilonGreedy
R.eval_policy.eps_start = 0.01
R.eval_policy.eps_end = 0.01
```

**BTR の評価 ε が 0.01、Nature 2015 が 0.05** であり、文献側は最初からこの値を持っている。BTR 比較に必要な条件でもあるため、v5 プロファイルの既定とする。

Classic プロファイル（`fire_reset = true`）ではライフ喪失時に env が FIRE を打つため本症状は発生しない。**v5 固有の問題である。**

| 本 Run（v5） | 30-35M | 2,585 | 246.8 | 0.52 | 71 | 116 | 274 | 402 | 19.5% | 0.1% |
| 本 Run（v5） | 45-50M | 2,578 | 246.0 | 0.53 | 70 | 117 | 268 | 408 | 19.6% | 0.3% |

**ViT だけが `<100` を下げ続ける**（31.2% → 18.6% → 13.5%）。IMPALA 系は 34% 前後で止まる。

**protocol でも eval ε でもない。** 08-23 より前の Run は全て `sticky=0 / noop=0 / episodic_life=true`
であり、**環境は完全に決定論的だった**。それでも tau30 の `<100` は 34% で、sticky 0.25 を入れた本 Run
の 19% より悪い。eval ε の導入前から観測されていることも合わせて、裾は環境側の確率性でも評価設定でもなく
**学習された方策そのものの性質**である。

### 考察

**探索ブロック 09・14 の「ViT は下振れを潰す装置」は、より長い地平と別 protocol でも保たれた。**
ブロック 14 の p25 +124%（148 対 66）は 35-40M の値だったが、45-50M でも 148 対 74 で同じ構造である。

**低スコア裾はサンプル数で消えない。** tau30 は 100M まで回しても 34% のまま。予算は上側の裾
（`≥432`）だけを伸ばす。

**本 Run はラック掃き切りの軌道に乗っていない。** 45-50M で `≥432` 0.3% に対し tau30 の同区間は 1.0% で、
しかも本 Run は増加していない。

## 探索ブロック 19: action gap の γ 依存と BF16 の余裕

### 探索観点

FIRE デッドロック（探索ブロック 16）と低スコア裾（探索ブロック 18）は、どちらも「argmax がわずかな差で
決まっている」ことに帰着するのではないか。top-1 と top-2 の Q 差を Run 間で比較する。

### 探索結果

| Run | γ | window | `q_max` | `q_gap` | **`q_gap/q_max`** | BF16 誤差 | **SNR** | ULP |
|---|---|---|---|---|---|---|---|---|
| tau30 IMPALA | 0.99 | 45-50M | 3.98 | 0.144 | **3.62%** | 0.016 | **9.28** | 9.23 |
| tau30 IMPALA | 0.99 | 96-101M | 3.61 | 0.146 | **4.05%** | 0.014 | **10.38** | 9.35 |
| ViT hybrid | 0.99 | 45-50M | 3.74 | 0.084 | 2.23% | 0.015 | 5.72 | 5.35 |
| **本 Run** | **0.997** | 45-50M | **11.91** | 0.097 | **0.81%** | 0.047 | **2.08** | **1.55** |

（BF16 誤差 = `q_max` × 2⁻⁸、SNR = `q_gap` / BF16 誤差、ULP = `q_gap` / 2^(floor(log2 `q_max`)−7)）

**γ 0.99 → 0.997 で相対 action gap が 4〜5 分の 1 に潰れた。** 地平が 100 → 333 step になり `q_max` が
3.6-4.0 → 11.9 と 3 倍に膨らむ一方、絶対 `q_gap` は 0.145 → 0.097 と**縮んだ**。結果 `q_gap / q_max` は
3.6-4.1% から **0.81%** になる。

**BF16 の余裕も同時に失われた。** SNR は 9〜10 から **2.08**、ULP 換算で **1.55**。探索ブロック 15 で
「RR4 は 4.36 ULP で余裕がある」と記録したが、あれは `q_max` 6.65 時点の値であり、`q_max` の成長とともに
ULP が粗くなって余裕が消えた。本 Run 内でも 15-20M の 0.70 ULP から 45-50M の 1.55 ULP まで動いており、
1〜2 ULP のレンジに留まり続けている。actor / eval の forward は FP32 なので行動選択そのものは量子化
されないが、**識別性を教える learner 側が 1.5 ULP しか差を持たない**。

**低スコア裾は action gap では説明できない。** 45-50M で ViT は `q_gap/q_max` 0.0223 と tau30 の 0.0362 より
**狭い**のに、`<100` は 13.5% 対 36.3% で**良い**。向きが逆である。

### 考察

**γ 0.997 は action gap を犠牲にして地平を買っている。** BTR が γ 0.997 と Munchausen（action gap を
広げる操作子）を同時に採っているのに対し、本記録は gap 拡大機構なしで γ だけを 0.997 にしていた。
探索ブロック 17 で「`q_max` は伸びるのに `q_gap` が頭打ち」という形で現れているのは同じ現象である。

**探索ブロック 15 の BF16 に関する結論は条件付きだった。** 「識別性が保たれていれば精度は問題にならない」は
`q_max` 6.65 / 4.36 ULP の時点では正しかったが、`q_max` が 11.9 まで育った現在は 1.55 ULP であり、
同じ条件が成立していない。探索ブロック 15 の FP32 対照は RR8 崩壊の切り分けであり、この局面の検証には
なっていない。

**低スコア裾（探索ブロック 18）と action gap は別の現象である。** 両者を 1 つの機序で説明する試みは
ViT の反例で否定される。
