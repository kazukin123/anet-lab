# Atari Breakout: 高 replay_ratio で成績が落ちる機序 — 2026-09-08

対象 workspace: `atari-3rd`。ゲームは breakout 固定。すべて seed 1、`backend.@non-deterministic`。

基準は **Munchausen 入りの現行構成**で、`run.@v5_iqn_impala_x2 > run.@a5 > run.@a5_apex > run.@va_base` に
RR と target 更新間隔を重ねる。各腕はそこから 1 変数だけを変えている。

起点は [2026-09-01](2026-09-01_btr-feedback-arms.md) 探索ブロック 31（RR4 が Munchausen 下でも RR1 に届かなかった）。
本記録はその**原因の特定**を主題にする。判定軸は同じく `42_env/10_game_score_mean` の 25-50M プールで、
`≥432`（1 画面）と `≥600` を数える。

**target 更新は env 時間 32,000 exp step で揃える。** 1 勾配あたりの exp step は
`U = num_envs × replay_ratio / replay_batch_size` の逆数なので、**RR と batch の両方で C が変わる**。

| 構成 | 1 勾配 = exp step | C |
|---|---|---|
| RR1 / B256 | 256 | 125 |
| RR2 / B256 | 128 | 250 |
| RR4 / B256 | 64 | 500（BTR 値） |
| RR4 / B512 | 128 | 250 |

## 現時点のまとめ

1. **犯人は再利用回数で、勾配回数ではない。** `RR4 / B512`（再利用 ×4・勾配は RR2 と同じ頻度）は
   25-50M プールで **8.84%** となり、`RR4 / B256` の 8.85% と小数第 2 位まで一致した。
   一方、同じ勾配頻度で再利用を ×2 にした RR2 は **14.33%**。**勾配頻度を固定して再利用だけを変えると成績が
   半分になり、再利用を固定して勾配頻度を変えても何も動かない**（探索ブロック 04）。
2. **過学習の署名が出ている。** 25-50M で `01_loss` が RR4 系 0.36-0.40 対 RR1/RR2 系 0.56-0.64、
   `01_td_mean` が 0.29-0.31 対 0.34-0.37、`04_td_std` が 0.37-0.40 対 0.54-0.59。
   **replay バッチへの当てはまりが良い腕ほど成績が悪い**という完全な逆順で、しかも `RR4 / B512` は
   勾配頻度が RR2 と同じでも**当てはまりは RR4 側に付く**。当てはまりも成績と同じく再利用回数の関数である（探索ブロック 05）。
3. **可塑性は成績を予測しない。上下どちらの方向でも。** 勾配数を揃えた `41_probe_dormant_ratio` は
   C=125 が 0.0396（RR1 の 0.040-0.043 より低い）で成績は最下位 6.83%、RR2 は 0.0768（RR1 の 1.8 倍）で
   成績は最高 14.33%。3 腕で治しても悪化しても成績は動かなかった（探索ブロック 01・02・03）。
4. **target 鮮度を勾配時間で揃えると悪化する。** RR4 に C=125 を当てると `15_target_sync_age` は 225.6 → 59.9 と
   RR1 並みになり dormant も 0.1102 → 0.0396 まで治るが、**壁突破率は 8.85% → 6.83%**。
   C=125 は env 時間では 8,000 exp step で、**32,000 の 4 分の 1 = 速すぎる側**にあたる（探索ブロック 01）。
5. **env 時間 32,000 exp step は両側から挟まれた内点最適になった。** 遅すぎる側は τ=0.001（env 256K、3.48%、
   [2026-09-01](2026-09-01_btr-feedback-arms.md) 探索ブロック 14）、速すぎる側が本記録の env 8K（6.83%）である（探索ブロック 01）。
6. **全層 `spectral_cap` は①（重み成長）を止め、発散しなかった。** 781k 勾配で生ノルムが 50.4 → 154.6（+207%）
   伸びる間、実効ノルムは 30.7 → 34.2（**+11%**）で平坦。`q_max` は 9.8 前後で安定していた。
   2026-08-30 探索ブロック 01 の「**①が止まる範囲と発散しない範囲に両立点が無い**」は**覆った**（探索ブロック 02）。
7. **それでも成績は動かなかった。** capall は 8.60% で RR4 の 8.85% と同水準（eval1 458.3 対 461.2）。
   dormant は半減したが（0.0546 対 0.1102）、`03_feature_norm` は 3 腕とも 11.0-11.3 で同一だった。
   **LN512 が既に①→②を切っているため、①を止めても表現のスケールは変わらない**（探索ブロック 02）。
8. **`replay_ratio` の山が RR1 から RR2 へ移った。** 25-50M プールで RR1 11.40 / 11.64% に対し **RR2 14.33%**、
   eval1 は 514.0 / 512.7 対 **554.9**。RR1 の複製幅（0.24pt）の 11 倍の差である。
   [2026-08-17](2026-08-17_baseline.md) まとめ 37 の「これは**保護機構が無い前提の最適**で、
   入れれば損傷側の壁が後退して上へ動く可能性がある」が、**Munchausen を保護機構として実現した形**になる（探索ブロック 03）。
9. **新バンドルで RR2 は一度も測り直されていなかった。** README の「RR1 = 内点最適（新バンドルで再確認）」の
   再確認は RR1 対 RR4 だけで、RR2 の点は旧バンドル（τ=0.001 / Munchausen 無し）の 418.2 対 474.7 を
   持ち越していた（探索ブロック 03）。
10. **壁時計軸では RR1 が依然有利で、トレードオフが復活した。** 同じ 4.85h なら RR1 は約 86M まで進み、
    85-90M 窓は 18.25%（[2026-09-01](2026-09-01_btr-feedback-arms.md) 探索ブロック 29）で、RR2 の 45-50M 窓 15.24% を上回る。
    [2026-08-17](2026-08-17_baseline.md) まとめ 38 の「サンプル効率と壁時計が同じ点で最大化される」は
    **exp 予算固定の話に限定される**（探索ブロック 03）。
11. **PER の「捨てる」チャネルは RR1 と RR2 の間で閉じる。** `07_evicted_unsampled_ratio` は
    RR1 0.249 → RR2 0.0265 → RR4 0.00012。**RR1 は経験の 4 分の 1 を一度も学習に使わずに捨てているが、
    RR4 は 0.01% しか捨てていない**。1 遷移あたりの平均抽選回数は `replay_capacity` に依らず `replay_ratio` そのもので、
    PER は層化抽出なので Poisson（`e^-4` = 1.8%）よりさらに均等になる（探索ブロック 05）。
12. **ただし `07` だけでは山の形を説明できない。** RR2 は既に捨てるチャネルが 9 割閉じている（0.0265）のに
    成績は最高である。`07` は RR に単調だが成績は RR2 で山を作るので、**PER の退化は主犯ではない**（探索ブロック 05）。
13. **`04_srank` / `05_srank_ratio` は batch を変える腕では別の物差しになる。** 分母は
    `min(サンプル数, 特徴次元)`（`nn_impl.cpp:219`）＝ `replay_batch_size` なので、B256 では 256、B512 では 512。
    実測でも B256 の `04_srank` は 219-232 で上限 256 に張り付き、B512 では 379-399 まで伸びる。
    **腕をまたいだ比較は probe 側（`44` / `45`、分母は特徴次元 512 固定）だけで行う**（探索ブロック 05）。
14. **網側の正則化 4 本のうち、天井を動かしたのは DropPath 0.1 だけである。** 25-50M プールで
    DropPath 0.1 が 10.02 / 11.08%、`spectral_cap` 全層 8.60%、`weight_decay` 0.01 は 25-33M 窓で
    RR4 素と区別がつかず、`per_alpha` 0.6 は **5.97% で RR4 素より悪化**した。
    DropPath 0.1 も RR2 の 14.33% には届かない（探索ブロック 06）。
15. **当てはまりと成績の逆順は 6 腕で成立している。** 25-50M の `01_loss` は
    RR2 0.609 → DropPath 0.443 → B512 0.391 → capall 0.365 → RR4 素 0.360 → alpha06 0.320 で、
    ≥432 の 14.33 → 11.08 → 8.84 → 8.60 → 8.85 → 5.97 とほぼ単調に対応する。
    機序も設定軸もばらばらな 6 腕で崩れない（探索ブロック 06）。
16. **DropPath の用量反応は単調ではない。** 0.1 は `01_loss` を baseline 比 +22% に上げたまま 50M まで維持するが、
    **0.2 は 15-17M で既に ±0%**（0.411 対 RR4 素 0.418）に戻る。`weight_norm_feature` は用量に単調減少
    （96.6 → 94.3 → 92.5）、`q_max_mean` も単調減少（10.87 → 10.35 → 9.90）した（探索ブロック 07）。
17. **可塑性が最良の腕が成績最下位になった。** learn_step 231-262k の `41_probe_dormant_ratio` は
    DropPath 0.2 が **0.030** で 3 腕中最良（0.1 は 0.041、RR4 素は 0.129）だが、同区間の ≥432 は最下位である。
    まとめ 3 の「上下どちらの方向でも予測しない」に、**治しすぎても悪い**という事例が加わった（探索ブロック 07）。
18. **`46_agent_replay_fit`（PRD 073）で記憶が直接測れた。** `03_unsampled_td_ratio` は RR4 で
    **1.09 → 1.15** と緩やかに上昇する。比を押し上げるチャネルは記憶だけ（PER 選択と年齢は押し下げ）なので、
    1 を超えていること自体が記憶の証拠になる。計測コストは同一バイナリの A/B で **+2.7%**（探索ブロック 08）。
19. **ただし DropPath は記憶を減らしていない。** 交絡（`23`/`24` 年齢、`21` 件数、`33` 選択性）が 3% 以内で

## 探索ブロック 01: target 鮮度を勾配時間で揃える（C=125）

- Run: `run_20260907-235121_rr4_hard125_munch`
- 期間: 2026-09-07 〜 09-08

### 探索観点

[2026-09-01](2026-09-01_btr-feedback-arms.md) 探索ブロック 31 の残件。RR4 の dormant は勾配数を揃えても
RR1 の 2.6 倍で、同時に `15_target_sync_age` が 225.6 対 60.2（C=500 は env 時間で揃えた値なので
勾配時間では 4 倍古い）だった。C=125 にすれば勾配時間で target が揃うので、
「データ再利用」と「target 鮮度」のどちらが dormant を押し上げているかを切り分けられる。

### 探索結果

**可塑性は完全に治り、成績は下がった。**

勾配数を揃えた 150-195k。

| 指標 | RR4 + C=125 | RR4 | RR1 r1 | RR1 r2 |
|---|---|---|---|---|
| `41_probe_dormant_ratio` | **0.0396** | 0.1102 | 0.0435 | 0.0403 |
| `42_probe_dead_ratio` | **0** | 0.00086 | 0.00002 | 0 |
| `44_probe_srank` | **483.7** | 470.7 | 475.2 | 472.5 |
| `15_target_sync_age` | 59.9 | 225.6 | 60.2 | 60.2 |
| `11_target_disagreement` | 0.1059 | 0.1439 | 0.0952 | 0.0789 |
| `03_q_delta_abs` | **0.0252** | 0.0192 | 0.0210 | 0.0210 |

**dormant は RR1 より低い。** 全行程でも C=125 は 0.040 → 0.047 → **0.085**、C=500 は
0.110 → 0.150 → **0.206** で終始半分以下。dead はゼロ、srank は全腕最高。

**それでも壁突破率は 8.85% → 6.83%、eval1 は 461.2 → 430.5。** 窓別では 5-10M で C=125 がリードし
（5.01% 対 4.53%）、10-20M で並び、**20M 以降に離される**（20-30M 5.79 対 7.50、40-50M 7.49 対 9.30）。
eval1 は 10M 以降 421 → 430 でほぼ平坦である。

### 考察

C=125 を RR4 に当てると、**勾配時間では RR1 と揃うが env 時間では 4 倍速すぎる**（125 × 64 = 8,000 exp step）。

| 腕 | 勾配時間の target 齢 | env 時間の target 齢 | ≥432 |
|---|---|---|---|
| RR1 + C=125 | 125 | 32,000 | 11.40 / 11.64% |
| RR4 + C=500 | 500 | **32,000** | 8.85% |
| RR4 + C=125 | **125** | **8,000** | 6.83% |

この軸が env 時間で決まることは [2026-09-01](2026-09-01_btr-feedback-arms.md) 探索ブロック 14 / 21 / 23 と
`940_target_update_step_axis_10prd.md` で確定していたが、**速すぎる側の実測は本ブロックが初めて**である。
遅すぎる側（τ=0.001 = env 256K、3.48%）と合わせて、**32K は両側から挟まれた内点最適になった**。

そして帰属が割れる。

- **勾配時間の target 鮮度 → dormant**（齢 60 で 0.040、齢 226 で 0.110）
- **env 時間の target 鮮度 → 成績**（8K で 6.83%、32K で 8.85%）

**別々の時計で動く 2 つの効果**であり、dormant は RR4 の成績を律速していない。

`61_weight_norm_feature` は C=125 84.4 / C=500 83.4（150-195k）、終端でも 161.8 / 157.4 とほぼ同じで、
**重み成長は target 鮮度ではなく勾配数で決まる**。

## 探索ブロック 02: 全層 `spectral_cap`（capall）

- Run: `run_20260908-073326_rr4_capall_munch`
- 期間: 2026-09-08

### 探索観点

2026-08-30 探索ブロック 01 は「①が止まる範囲と発散しない範囲に両立点が無い」と結論していた。
全層 `spectral` は実効ノルムを平坦化した唯一の例だが `q_max` が 2,700 まで発散し、
BTR 範囲（residual conv のみ）の `spectral` / `spectral_cap` は生ノルムと一緒に伸びて実質 no-op だった。

未試行なのは**全層 `spectral_cap`**である。`spectral` は常時除算なので **σ<1 の層を拡大**するが、
`spectral_cap` は `|σ|>1` のときだけ割るのでその経路を踏まない。また BTR 範囲で `63` が伸びたのは
**素の Linear512 がノルムの大半を占める**ためで、cap を Linear512 まで広げた組が無かった。

### 探索条件

`net.branch.@AtariImpalaX2LNCAP` を新設（現行基準 `@AtariImpalaX2LN` の全ブロックを CAP 版へ置換し LN512 は維持）。
`run.@capall` が branch と metrics チェーン（`metrics.scalar.@sn` = 63-66）を差し替える。

### 探索結果

**①は止まり、発散しなかった。**

## 探索ブロック 04: 再利用と勾配回数の分離（B=512）

- Run: `run_20260909-142738_rr4_b512_munch`
- 期間: 2026-09-09

### 探索観点

`U = num_envs × replay_ratio / replay_batch_size`（`dqn_based_agent.cpp:1939`）なので、
**batch を上げると再利用回数を保ったまま勾配回数だけ減らせる**。RR4 / B512 は
「RR4 の再利用（×4）・RR2 の勾配頻度（128 exp step / 勾配）」にあたる。

なお `replay_ratio` は**環境遷移 1 件あたり平均何サンプルを学習に使うか**であって更新回数ではない
（`earned_credit_` は train step 1 回につき 1 度加算され、train step は num_envs 件の遷移を進める）。

### 探索結果

**RR4 と区別できなかった。**

| 25-50M | RR4 / B512 | RR4 / B256 | RR2 / B256 |
|---|---|---|---|
| 再利用 | ×4 | ×4 | ×2 |
| 1 勾配 = exp step | 128 | 64 | 128 |
| ≥432 | **8.84%** | **8.85%** | **14.33%** |
| ≥600 | 1.98% | 1.91% | 5.30% |
| eval1 | 459.4 | 461.2 | 554.9 |
| eval2 | 454.2 | 458.1 | 548.1 |

窓別でも 4 窓すべてで差は 1pt 未満だった。

| 窓 | B512 | RR4 | RR2 |
|---|---|---|---|
| 10-15M | 6.27% | 5.97% | 8.02% |
| 15-20M | 6.45% | 6.33% | 10.25% |
| 20-25M | 6.91% | 7.53% | 11.38% |
| 25-30M | 8.24% | 7.47% | 11.77% |

### 2 因子表

| 1 勾配 = exp step | 再利用 ×1 | ×2 | ×4 |
|---|---|---|---|
| 64 | — | — | **8.85%** |
| 128 | — | **14.33%** | **8.84%** |
| 256 | **11.52%**（RR1 平均） | — | 未実施 |

- **行（勾配頻度を固定して再利用を変える）**: 128 の行で ×2 → ×4 が **14.33% → 8.84%**
- **列（再利用 ×4 を固定して勾配頻度を変える）**: 64 → 128 が **8.85% → 8.84%**

**再利用回数が成績を決め、勾配回数は決めない。** 「RR4 は更新しすぎ」という読みは成立しない。

throughput は 2,323 step/s で B256（1,676）の **+39%**（更新回数が半分でカーネル発行が減るため）、実時間 5h54m。

ただし held-out の TD を測る計器が無い（probe チャネルは RB からの一様抽出で同じ分布）ため、
train / held-out ギャップの直接測定はできていない。

### PER の「捨てる」チャネル

25-50M。

| 腕 | `07_evicted_unsampled_ratio` |
|---|---|
| RR1 r1 | 0.2487 |
| RR1 r2 | 0.2502 |
| **RR2** | **0.0265** |
| RR4 | 0.000116 |
| RR4 + C=125 | 0.000141 |
| RR4 + capall | 0.000117 |
| RR4 + B512 | 0.000124 |

**RR1 は経験の 4 分の 1 を一度も学習に使わずに捨てているが、RR4 は 0.01% しか捨てていない。**

1 遷移の寿命は `replay_capacity` 分の env step、その間に引かれるサンプルは `replay_ratio × capacity` なので、
**平均抽選回数は capacity に依らず `replay_ratio` そのもの**（RR1 は 1 回、RR2 は 2 回、RR4 は 4 回）。
PER は層化抽出なので Poisson（`e^-4` = 1.8%）よりはるかに均等になり、実測 0.01% はその帰結である。
`per_alpha = 0.2` は `p ∝ TD^0.2` で TD 100 倍差が抽選 2.5 倍にしかならないため、
**RR4 では実質「一様に 4 回配る」**になっている。

**ただし `07` だけでは山の形を説明できない。** RR2 は既に 0.0265（RR1 の 1/9）まで閉じているのに成績は最高であり、
`07` は RR に単調だが成績は RR2 で山を作る。**PER の退化は再利用の帰結として同時に起きるが、主犯ではない。**

## 探索ブロック 08: `46_agent_replay_fit` の初測定

### 探索観点

ブロック 05 の残件「held-out の TD を測る計器が無い」に対して PRD 073 が実装された。
Replay の全件を「一度でも学習に引かれたか」（`sampled_once_`）で 2 群に割り、各群から
一様・非復元で 1024 件引いて、更新の直前に同じ網で誤差を測る。
probe は NoGrad / eval mode / FP32 / IQN tau 32（学習は 8）で、IS 重みを掛けない
（`dqn_based_agent.cpp:2128-2131`）。**DropPath も bf16 も測定値に混ざらない。**

### 計測コスト

同一バイナリ・同一 exp 区間（200,192 → 398,592）で `@rfit` の有無だけを変えた 400k の A/B。

| | 所要 | exp step/s |
|---|---|---|
| 計測なし | 67.88s | 2,923 |
| `@rfit` あり | 69.73s | 2,845 |

**+2.72%。** PRD 073 §8.5 の 5% 以内に収まる。

### 記憶は起きている

DropPath 0.1 r2（50M 完走）の `03_unsampled_td_ratio`。

| learn_step | 100-120k | 180-200k | 250-269k | 380-400k | 580-600k | 760-778k |
|---|---|---|---|---|---|---|
| `03` | 1.105 | 1.118 | 1.143 | 1.109 | 1.144 | **1.150** |
| `13` | 1.088 | 1.135 | 1.149 | 1.122 | 1.144 | **1.165** |

`03` を押し上げるチャネルは記憶だけである。PER 選択（S 群は高 TD が濃い）と年齢
（U 群は必ず若い）は両方とも押し下げに働く。したがって **1 を超えていること自体が記憶の証拠**であり、
学習を通じて緩やかに増える。

**ゼロ点は 1.0 ではない**（押し下げ 2 本の大きさが未知）ので、絶対値から過学習の量は読めない。

### DropPath は記憶を減らしていない

learn_step で揃えた DropPath 0.1 r2 対 0.2。

| learn_step | `03` 0.1 | `03` 0.2 | `23` U 年齢 | `24` S 年齢 | `21` U 件数 | `33` 選択性 |
|---|---|---|---|---|---|---|
| 100-120k | 1.105 | 1.091 | 931 / 957 | 4501 / 4511 | 118.8k / 122.3k | 1.144 / 1.118 |
| 180-200k | 1.118 | 1.107 | 918 / 926 | 4496 / 4499 | 117.1k / 118.1k | 1.131 / 1.102 |
| 250-269k | **1.143** | **1.116** | 917 / 925 | 4496 / 4500 | 116.9k / 118.2k | 1.131 / 1.145 |

**交絡は 3% 以内で揃っている**（`24` は 0.1% 以内）。その上で `03` は成績が良い 0.1 の方が高い。
`13` も同じ向きである。**「再利用 → 記憶 → 成績低下」の経路で DropPath が効いている、という説は成立しない。**

なお同区間の ≥432 は 7.07% 対 5.53%（差 1.48pt）で、DropPath 腕の複製幅 2.47pt（ブロック 09）の中にある。
**成績差そのものが有意でない**ため、この対は「`03` が成績を予測するか」の検定にはならない。

### PER の選択性と新規データの優遇

同じ probe から副産物として 2 つ出た。

- **`33_per_selectivity` = 1.10-1.15。** PER が引くバッチの平均 |TD| はバッファ全体平均より 10-15% 高いだけで、
  **α=0.2 はほぼ一様抽選**である。
- **`21_unsampled_count` = 117k（バッファの 11.2%）、`23_unsampled_age_mean` = 919。**
  一様抽選の理屈値は U 比率 `(1-e^-4)/4` = 24.5%、U 平均年齢 0.23 × 8,192 = 1,900 なので、
  **実測は両方とも約半分**。`per_initial_priority_mode = max`（新規に走行中の最大優先度を与える）が
  新規データを約 2 倍引きやすくしている。

## 探索ブロック 09: 複製幅の再測定

### 探索観点

判定に使う物差しを、腕ごとに測り直す。同一設定 2 本の差を窓ごとに取る。

### 探索結果

| 対 | 5-10M | 10-15M | 15-17M | 25-50M | 45-50M |
|---|---|---|---|---|---|
| B512（`014535` / `142738`） | 0.69pt | 0.35pt | **0.15pt** | — | — |
| DropPath 0.1（`202940` / `192132`） | — | — | **2.47pt** | **1.06pt** | 2.32pt |
| RR1（[2026-09-01](2026-09-01_btr-feedback-arms.md)） | — | — | — | 0.24pt | — |

**複製幅は腕によって 1 桁違う。** DropPath はサンプル単位で枝を落とすので Run 間分散が増える、が素直な読みである。

この結果、**判定は 25-50M プールで行う**のが正しい。45-50M だと幅が 2.3pt に広がり、
RR4 系の腕どうし（9.89 / 9.91 / 10.03 / 12.35%）は互いに区別できない。

なお全 Run が `train.seed = 1` かつ `backend.@non-deterministic` なので、

## 探索ブロック 10: BTR 公開実装のローカル実行（進行中）

### 探索観点

同じ再利用 4 回で BTR 公開実装が崩れるかを直接見る。NoisyNet を切って（`--noisy 0`）走らせ、
論文の公開値（`results.csv`）と本記録の腕の両方に当てる。

WSL2 Ubuntu-24.04 上で実行した。Windows では `AsyncVectorEnv(context="spawn")` が env 数だけ
Python プロセスを起こすためメモリが足りず、`--envs 64` が使えなかった。WSL で env worker だけ
`fork` に変えると 64 env が **1.2 秒で生成・WSL 全体 RSS 3.6GB** になる。

### 再利用量とプロトコルの一致

| | BTR | 本記録 |
|---|---|---|
| 1 更新あたり遷移 | 64（`--envs 64 --rr 1`、`Agent.py:519`） | 64（RR4 / B256） |
| batch | 256 | 256 |
| **1 遷移あたりサンプル** | **4** | **4** |
| warmup | 200,000 遷移 | 200,000 |
| target 更新 | hard C=500 | hard C=500 |
| sticky / noop / frameskip / life 終端 | 0.25 / 30 / 4 / 無し | 同一 |
| gamma / n_step / tau 数 / `per_alpha` / Adam eps | 0.997 / 3 / 8 / 0.2 / 1.95e-5 | 同一 |

**Double DQN も grad_clip 10 も weight_decay 0 も一致している。**

### eval 比較（`52_eval2`、exp_step で揃える）

| 窓 | BTR(off) | RR2 | DropPath 0.1 r2 | RR4 素 |
|---|---|---|---|---|
| 10-15M 平均 | **490.3** | 460.9 | 428.0 | 423.7 |
| 10-15M ≥432 | **42.9%** | 33.1% | 30.8% | 25.9% |
| 20-23M 平均 | **524.5** | 516.8 | 465.4 | 431.9 |
| 20-23M ≥432 | **52.9%** | 48.7% | 38.9% | 28.1% |

**BTR は同じ再利用 4 回で、本構成の RR4 素を大きく上回り RR2 に並ぶ。**

### NoisyNet を切っても論文と互角

| | 今回 noisy OFF | 論文 noisy ON |
|---|---|---|
| 10M frames | 332.3 | 173.5 |
| 41-91M frames 平均 | **504.5** | 490.3 |
| 同区間 max | 643.4 @84M | 574.5 @75M |

max はこちらが eval 20 エピソード・論文が 100 なので、点あたりの標準誤差が √5 倍あり上振れする。
平均で見るとほぼ同じである。**NoisyNet は BTR の性能の鍵ではない。**

### checkpoint 由来の可塑性（learn_step 280-350k）

BTR の checkpoint は 10M frames ごと、online 網の `state_dict` のみ。
全 checkpoint へ同一の観測 512 件を食わせて測った。

| | BTR | DropPath 0.1 r2 | RR4 素 | RR2 |
|---|---|---|---|---|
| `41_probe_dormant_ratio` | **0.419** | 0.037 | 0.146 | 0.085 |
| `45_probe_srank_ratio` | **0.723** | 0.909 | 0.886 | 0.895 |
| `61_weight_norm_feature` | **37.2** | 103.5 | 107.2 | 99.3 |
| `62_weight_norm_readout` | **77.5** | 51.6 | 50.5 | 48.6 |
| `11_q_max_mean`（exp 18-23M） | 10.99 | 10.24 | 10.88 | 11.54 |

**dormant は本記録の全腕より 3-14 倍悪く、しかも 10M frames の 0.135 から 90M の 0.429 まで単調に増える。**
それでも成績は上である。一方 `45_probe_srank_ratio` は 0.703 → 0.721 でほぼ動かず、**階数は保たれている**。

ただし **BTR の特徴次元は 2304、本構成は 512** である。dormant は層幅に依存するので、
この比較には幅の差が混ざる。`45` は分母が両者とも `min(512, 次元)` = 512 で揃う。

**重みの配分は逆向き**である。BTR は readout 重心（37.2 : 77.5）、本構成は feature 重心（103.5 : 51.6）。
BTR には共有トランクが無く V/A が各自 `Linear(2304→512)` を持つので、質量が readout 側へ寄る。

`17_q_gap` は BTR 0.083 対 RR2 0.164 / RR4 素 0.099 だが、**probe が揃っていない**
（BTR は自身の greedy 方策、本構成は ε ラダー 0.01-0.4 で集めた replay バッチ）ので水準比較には使えない。

### 構造差は RR1 では出ていなかった

`atari-2nd` の 2026-09-02 に、同じ構造差を RR1 で引いた腕が残っている。
当時は `ge432` タグが無いため、`42_env/10_game_score_mean` の点から直接数えた（25-50M）。

| 腕 | 構造末尾 | mean | ≥432 |
|---|---|---|---|
| `run_20260902-041010_v3_rr1_ln_hr_va` | `ReLU > Flatten > Linear512 > LN512 > ReLU` | 208.5 | 3.48% |
| `run_20260902-065010_o_rr1_va_pool6` | `ReLU > Pool6 > Flatten > Linear512 > LN512 > ReLU` | 195.4 | 1.55% |
| `run_20260902-090042_z_rr1_va_fuse2304` | `ReLU > Pool6 > Flatten`（トランク除去・2304 融合） | 211.0 | 3.46% |
| `run_20260902-111530_z2_rr1_va_btrstruct` | 同上 | 211.3 | 4.18% |

`fuse2304` と `btrstruct` は構造が同一で、複製対として 0.72pt 離れている。
**RR1 では BTR 構造の利得が複製幅を超えない。** 再利用が低いところで差が出ないことは、
「構造と再利用の交互作用」という読みと矛盾しない。

## 判断

**高 replay_ratio の劣化は、同じ遷移を繰り返し学習に入れることによる replay 分布への過学習である。**

- 勾配回数ではない（探索ブロック 04）
- 可塑性の損傷ではない（探索ブロック 01・02・05・07・10）
- 重み成長ではない（探索ブロック 02）
- PER の退化は同時に起きるが主犯ではない（探索ブロック 05）

**ただし再利用 4 回そのものが害なのではない。** BTR 公開実装は同じ再利用 4 回・同じプロトコル・
同じ主要ハイパラで崩れず、exp 20-23M の eval で本構成の RR4 素を 92.6 上回る（探索ブロック 10）。
したがって正しくは **「本構成が再利用 4 回に耐えていない」** であり、差は構成側にある。

記憶が起きていること自体は `03_unsampled_td_ratio` = 1.09-1.15 で直接確認できた（探索ブロック 08）。
一方、**網側の正則化 4 本のうち天井を動かしたのは DropPath 0.1 だけで、しかもそれは記憶を減らしていない**
（探索ブロック 06・08）。記憶は実在するが、対策との因果はまだ繋がっていない。

`replay_ratio` の現行の内点最適は **RR2**（n=1）。ただし壁時計軸では RR1 が有利で、
[2026-08-17](2026-08-17_baseline.md) まとめ 38 の「トレードオフが存在しない」は exp 予算固定の話に限定される。

## 残件

- **RR2 の複製は未取得。** +2.69pt は複製幅（25-50M で 0.24-1.06pt）を超えるが n=1 である
- **RR3 / RR2 の反対側は未実施。** 山は RR1 11.52 / RR2 14.33 / RR4 8.85 で挟まれているが、
  2 と 4 の間の形は分かっていない
- **`RR4 / B1024`（再利用 ×4・勾配頻度 RR1 相当）は未実施。** 2 因子表の 256 行が空いている
- **`46_*` は RR4 の 2 腕でしか測っていない。** RR2 / RR1 / RR4 素との比較が無いので、
  「再利用が記憶を増やすか」「記憶が成績を下げるか」はどちらも未検証である。
  なお RR を跨ぐと U 群の構成（RR2 では約 40%）と年齢分布が変わるため、`03` の水準比較には
  `21` / `23` / `24` による交絡の定量が要る
- **`38_agent_loss` / `37_agent_qtd/01_td_mean` / `46_*` は BTR 側から取れない。** checkpoint は
  online 網の重みのみで、target 網と buffer が無い。BTR の `--analy 1` は保存が O(n²)
  （`Analytic.py:88-92` が 10 回ごとに配列全体を `np.save`）で 200M frames には載せられない
- **BTR との構成差で RR4 未検証のもの**: 6×6 maxpool + 共有トランク除去 + 2304 融合、LayerNorm の有無、
  spectral norm（BTR は `--spectral 1`、checkpoint の `parametrizations.weight.original` で確認）、
  `train.num_envs` 64、探索方式（BTR は単一 ε、本構成は ε ラダー 0.01-0.4）
- **`per_initial_priority_mode = actor_approx` は RR4 では未実施。** ブロック 08 で
  `max` が新規データを約 2 倍引きやすくしていることが測れたので、配分を変える軸として動機が付いた
- **データ拡張（random shift 等）は Atari 経路に未実装**（`core/envs/atari1` と `core/anet-core/src` を走査して 0 件）
- **周期 checkpoint 保存が無い。** `agent_close.anet` と手動スナップショットだけなので、
  BTR の 20 点に対して重み空間の軌跡を片側しか引けない。`.anet` 76MB の内訳は
  model 39.5MB + adam 39.4MB で、後解析に要るのは model 側だけである
