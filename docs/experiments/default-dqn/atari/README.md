## Atari での評価観点

### ラック境界を基準に読む

Breakout の 1 画面は 6 段 × 18 個で **432 点**、2 画面で 864 点。
平均スコアだけでなく `≥432` の割合を見る。平均が +6% しか動かない区間で `≥432` が 4 倍になることがあり、
**予算延長は上側の裾だけを買う**ことがはっきり出る。

低スコア帯の実体は「停止」ではなく「短命」である（`score<50` かつ `game_len>3000` は 0 本、
train 側に FIRE デッドロックは 1 本も無い）。「上手いエピソードは伸びるがポカる率は下がらない」という
分離が起きるため、**上側（`≥432`）と下側（`<100`）は別々に読む**。

### 集約の分母に注意

`game_score` / `game_len` / `game_frames` は実 game over / truncation でのみ非 NaN になり、
バッチ集約は NaN を分母から除外する。したがって `mean.` の分母は num_envs ではなく
**その step で実際にゲームを終えた env の数**である。同時完了率は λ = num_envs / 平均ゲーム長 で決まり、
Breakout（128 env / 約 1,900 step）では実測 97% が単独完了なので、`mean.` は事実上
「ゲーム 1 回の素点の列」になる。**ゲーム長が短い題材ほど平均化が効いてピークを潰す**ため、
ゲーム横断の比較では `max.` を併置して読む（`42_env/16_game_score_max` 等）。
`lives` だけは常時確定なので分母は num_envs であり、これは本物のバッチ平均。

### eval 点の密度は `replay_ratio` に依存する

eval interval は learn_step 基準なので、**RR を下げるほど exp 軸上の eval 点が減る**。
100M / interval 2500 の実測で 10M 窓あたり RR4 63.1 点 / RR2 31.3 / RR1 15.7 / RR0.5 7.9。
窓別の比較はこの粒度に律速されるため、**RR をまたぐ比較では点数差を必ず確認する**。

**`btreval_r1` / `btreval_r2` / `btreval_r4` はこれを env step 換算で揃えるために作った**
（977 × 256 = 3906 × 64 = 約 250k exp step）。exp 軸の密度は揃うが、**実時間の密度は揃わない**。
RR1 は同じ env step を 4 倍速く進むので、eval が実時間に占める割合が 4 倍になる。
RR1 では 1 セッション 108s に対し間隔が 42s になり、**デューティが 99.7% まで飽和した**
（[2026-09-15](2026-09-15_replay-lane-window.md) 探索ブロック 05）。

### 判定はブレ幅基準

成績差は単一 Run の last 値ではなく、同等設定の複数 Run / seed 違いの終盤平均ブレ幅で判断する。
ブレ幅内は有意差なし、超えてはじめて構造差として扱う。
実効設定の確認は live config ではなく `runs/<name>/config/config_data.txt`（実行時ダンプ）を正本とする。

**ブレ幅は腕ごとに違う。** 2026-09-05 に 4 対を実測した結果、壁突破率の複製差は
hard C=125 が 0.16pt、BTR 構造が 1.12pt、BTR 構造+τReLU（seed 違い）が 1.18pt、
soft τ=0.008 が **1.65pt** と桁が違った（[2026-09-01](2026-09-01_btr-feedback-arms.md) 探索ブロック 27）。
**Poisson 標準偏差（0.2〜0.3pt）は下限にしかならず、他の腕へ流用できない。**
したがって **1 本しか無い腕は 1pt 前後の差で順位づけしない**。これは追加測定を待つ保留ではなく**運用規則**として扱う（全腕の厳密な順位付けは目的ではないため、複製を取るのは判定が要る軸に限る）。
**シードを変えても幅は広がらない**（同 seed の非決定性と同程度）ので、複製は seed を変えずに取ってよい。
複製対が 25M まで一致してから発散する例があり、**予算を延ばしても幅は縮まらない**。

**ε=0 断面は別の物差しを使う。** ブレ幅が 2 種類あり、混同しやすい。

| 種類 | 値 | 用途 |
|---|---|---|
| eval プロトコル（同一スナップショットを 2 回） | **2.12〜16.2 点** | 測定の再現性。**水準が上がるほど広い**ので一般の物差しにしない |
| **学習 Run どうし（ε=0）** | **18.7 点** | **腕の判定はこれで読む** |
| 学習 Run どうし（ε=0.01） | 6.7 点 | 学習中 eval の判定 |

**2026-09-17 の 2 チャネル構成（ε=0.01 を 10 本 / ε=0 断面を 400 本）で引き直した。**
上表の 18.7 / 6.7 は旧プロトコル（100 本 eval）の値で、下表が現行。

| チャネル | 窓 | 2-Run 差の sd |
|---|---|---|
| `42_env/11_game_score_mean_ema` | 5M | **2.1** |
| `42_env/41_game_score_ge432_ema` | 5M | **0.0089** |
| `52_eval2/10_game_score_mean` | 5M | **18.9** |
| 〃 | 10M | **12.3** |
| 〃 | 40M 全区間 | **6.7** |
| `53_evalg/10_game_score_mean`（ε=0 断面） | 1 点 = 400 エピソード | **44** |
| 〃 | Run 平均（8 点） | **15.6** |

**窓幅を倍にすると sd が 1/√2 で落ちる**（18.9 → 12.3）ので、seed 差に持続的なオフセット成分は無い。
**train 側 EMA が飛び抜けて鋭い**（5M 窓で sd 2.1）が、lane 窓のような
「ε=0 にだけ出る」故障には構造的に無感度なことがあるので、主判定には使わない。
ev 終端（500 エピソード）のセッション間 sd は 9.6〜22.4（SEM 4.8〜11.2）
（[2026-09-15](2026-09-15_replay-lane-window.md) 探索ブロック 07）。

**ε=0 のほうが ε=0.01 より広い。** 腕の差を拡大するのと同じ比率でブレ幅も広がるので、
ε=0 で差が出たからといって ε=0.01 より鋭いとは限らない
（[2026-09-01](2026-09-01_btr-feedback-arms.md) 探索ブロック 30、[2026-09-15](2026-09-15_replay-lane-window.md) 探索ブロック 03）。

### 過渡は深さで読む

多くのメトリクスが序盤にピーク → 急落 → 緩回復する過渡が観測されるが、
**位置は grad 軸にも exp 軸にも揃わず、深さだけが `replay_ratio` に単調**である
（RR8 −62% / RR4 −31.5% / RR2 −11.8% / RR1 なし / RR0.5 なし）。
`q_gap` の過渡の深さは可塑性の代理として使えるが、**定常のレベルは使えない**（前掲）。

表現側を `34_agent_plasticity` 群で直接測った結果、**摩耗そのものは勾配 step の関数で `replay_ratio` に
ほぼ依存しない**ことが分かった（同 grad step で `weight_norm_feature` 63.9 対 67.4、`dead_ratio` の
谷からの倍率 5.9 対 5.8）。RR が決めるのは摩耗量ではなく、**その摩耗を買うのに何件の新規データが
付いてきたか**である。したがって価値側（`q_gap`）が RR の関数、表現側が勾配 step の関数、という
役割分担になる（[2026-08-28_plasticity.md](2026-08-28_plasticity.md)）。

主読みは `dead_ratio`（谷が転換点を予告）と `weight_norm_feature`（絶対値が勾配軸で揃う）の 2 本。
**srank は今回の損傷モード（ユニットの死）には反応しない** — δ 3 種・probe batch 2 種で深さ −3〜6%、
同じ事象で `dead_ratio` は +490%。読み方は `docs/design/030_user_guide_analysis.jp.md` 4.7 節。

**srank は probe 側（`44_probe_srank`）だけを読む。** 分母は `min(サンプル数, 特徴次元)`
（`nn_impl.cpp:219`）＝ `replay_batch_size` なので、`04_srank` は B256 では上限 256 に張り付き、
**batch を変える腕（B512 等）では分母そのものが変わって腕間比較が成立しない**。
probe は batch 4096 なので次元 512 が効き、こちらだけが有効である
（[2026-09-01](2026-09-01_btr-feedback-arms.md) 探索ブロック 31）。

**可塑性指標は成績を予測しない — 上下どちらの方向でも。** 2026-09-08 に 3 腕で確定した。
dormant を RR1 以下（0.0396）まで下げた C=125 が壁突破率 6.83% で最下位、
①（重み成長）を止めた capall（実効ノルム +11% に対し生ノルム +207%）が 8.60% で不変、
dormant が RR1 の 1.8 倍（0.0768）の RR2 が **14.33% で最高**である
（[2026-09-08](2026-09-08_replay-ratio-mechanism.md) 探索ブロック 01・02・03・05）。
**機序指標を動かす腕を引くときは、成績が付いてこないことを既定として設計する。**

2026-09-10〜11 に**治しすぎる側**と**外部実装**でも確認された。DropPath 0.2 は dormant を
0.030（RR4 素 0.129 の 1/4）まで潰すが同区間の成績は 3 腕中最下位、BTR 公開実装は dormant 0.419・
`45_probe_srank_ratio` 0.723 と全腕より悪いのに eval は最も高い
（[2026-09-08](2026-09-08_replay-ratio-mechanism.md) 探索ブロック 07・10）。
**`41_probe_dormant_ratio` は層幅に依存する**ので、特徴次元が違う実装どうしの比較には使えない
（BTR 2304 対 本構成 512）。`45_probe_srank_ratio` は分母が `min(サンプル数, 次元)` で揃う。

**可塑性群は `$learn_step` 軸なので、RR をまたぐ比較では exp 軸ではなく勾配数で揃える。**
RR4 は 1 勾配 = 64 exp step、RR1 は 256 exp step。exp 軸のまま並べると勾配数が 4 倍違う点を比べることになる。

## 探索環境としての位置付け

Atari は文献比較の土俵が明確な唯一の env であり、BTR（arXiv:2411.03820）/ Nature DQN 2015 /
Dopamine 系のどれと比べるかでプロトコルプロファイルを選ぶ。**スコアはプロファイル間で直接比較できない**ため、
比較先がどの wrapper 構成かを毎回確認する（`docs/design/220_atari_env.jp.md` 3 章）。

**Breakout 単独での判断には固有の危険がある。**

- `reward_clip=true` により learner にはどのブロックも +1 だが、`game_score` は 1 / 4 / 7 で数える
- 432 / 864 のラック境界が作る相転移は他ゲームに無い構造である
- ε ラダーが下振れを潰す効果が被覆由来なら env 非依存のはずだが、1 ゲームでは検証できない

このため 57 ゲームの median を推定するサブセット **Atari-5**（battle_zone / double_dunk /
name_this_game / phoenix / qbert）を横断確認に使う。設定は `run.@a5*`（`apps/runner/config/Atari.txt`）と
`apps/12_batch_run_atari5.bat` にある。

初回スイープ（20M）の実測で、この懸念は裏付けられた。5 ゲームの hns57 は **−77.3%（double_dunk）〜
174.1%（name_this_game）** に散らばり、正規化バンド幅も 2.2 〜 34,828 と 4 桁違う。
**生スコアの横断比較は成立しない**ので、集約は必ず hns57 と Atari-5 回帰で行う
（[2026-08-27_atari5.md](2026-08-27_atari5.md)）。

詳細な条件、当時の解釈、判断の更新履歴は campaign 文書を参照してください。
