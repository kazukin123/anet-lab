### 新バンドルの内容

`2026-08-17_baseline.md`（旧バンドル）からの差分。**環境は BTR へ寄せ、探索で結果が出ている項目は探索結果を採用し、未探索の項目は BTR 初期値を採る**という方針で組んだ。

|---|---|---|---|
| 環境（BTR 寄せ・**不発**） | `noop_max` | **0**（意図は 30） | 0 |
| 探索結果を採用 | `replay_ratio` | **1** | 1（探索ブロック 25 で内点最適と確定） |

| 未探索 → BTR 初期値（**不発**） | `adam_eps` | **1e-4**（意図は 1.95e-5） | 1e-4 |
| 未探索 → BTR 初期値 | `update_warmup_steps` | **200,000** | 20,000 |
| 未探索 → BTR 初期値 | `grad_clip_tau` | **10** | 30 |

| 未探索 → BTR 初期値 | eval interval | **1,000 learn_step** | 2,500 |

**実効値は 2 項目が意図と異なる（2026-08-29 に実行時ダンプで判明）。** どちらも選択チェーンの後段レイヤが前段の変更を打ち消していた。

- **`noop_max`**: root ラダーを `@v5_noop30` へ変更したが、本 campaign の BASE である `run.@v5_iqn_impala_x2` が `AtariEnv.$ = AtariEnv.@v5_noop0 > E1` を再指定して戻していた（`Atari.txt:25` 対 `:246`）。**環境は旧プロトコル（noop 0）のまま走っている。**
- **`adam_eps`**: `A1` に `1.95e-5` を置いたが、チェーン `@baseline > @iqn > A1 > @bf16 > A2 > A3` の `@bf16` が後段で `1e-4` を設定する（`agent.txt:91`）。**実効値は `1e-4`。**

残る 5 項目（`per_alpha` 0.2 / `update_warmup_steps` 200,000 / `grad_clip_tau` 10 / IQN `num_taus` 8 / eval interval 1,000）と探索結果採用分（`replay_ratio` 1 / ε 上端 0.4 / `num_envs` 128 / `weight_decay` 0）は実行時ダンプで意図どおりを確認済み。

**5 項目を同時に動かしているため、相関で最適でない組み合わせが混じっている可能性がある。** これは方針として許容し、今後の探索へ委ねる。

## 現時点のまとめ

1. **Atari-5 median 推定 = 55.4% HNS**（20M step = 80M frames）。5 ゲームの hns57 単純 median 62.3% / 平均 52.3% の間に入り、極端な外れ値に引きずられていない。
2. **20M は明確に短い。** battle_zone / name_this_game / qbert の 3 ゲームが 15-20M 窓でも上昇中で、頭打ちの気配がない。特に qbert は 5M ごとにほぼ倍増している（408 → 1,871 → 3,071 → 4,451）。**55.4% は到達値ではなく途中経過**である。
3. **name_this_game で初めて人間を超えた**（12,316 対 人間基準 8,049 = **hns57 174.1%**）。酸素補給という資源管理が要る題材で、20M で獲得している。
4. **battle_zone が最大の稼ぎ頭**（重み 0.382、hns57 70.2%、2,579 → 26,800 と急上昇中）。84×84 グレースケールでレーダーを読めている証拠。
5. **double_dunk はランダム以下**（−20.3 対 ランダム −18.6、hns57 **−77.3%**）。20M 通して −22〜−20 の帯から出ない。**この 1 ゲームが推定を約 21 ポイント削っている**（人間水準なら合計 φ が 1.751 → 1.887、推定 55.4% → 76.1%）。
6. **phoenix は生存戦略に落ちて劣化し、`bad allocation` で落ちた**（12.28M / 全 20M）。エピソード長が 656 → 上限 27,000 に張り付き、スコアは 4,998（5-10M）でピークを打って 4,633 へ低下。throughput も 6,916 → 3,761（−46%）。**5 ゲームで phoenix だけがこの挙動を示す**。
7. **1 ゲーム約 57 分、5 本で 4.75h**（実効 5,335〜5,905 step/s）。Breakout の RR1 実測 6,670 step/s より 10〜20% 遅い。

クラッシュ直前 2 分間に 17.3 秒と 33.9 秒の停止が 1 回ずつ入っている（通常は 200 train_step あたり約 5 秒）。

**確保元は特定できていない。** 次は排除済みである。

- **EvalPanel は動いていない** — ログは `eval tag 'eval_panel': definition-only`、ALE インスタンス数は 130 で完走した name_this_game と同数
- **PER の `pending_` deque** — `PendingEntry` は約 50 バイトで write head の前進により drain する。エピソード長に比例しない
- **eval ループ** — `do { DoStep } while(!episode_end)` のみで軌跡を保持しない
- **replay buffer** — 容量固定（1,048,576 × 84×84 ≈ 7.4GB）で 1.05M step 時点で満杯。12.28M でのクラッシュと時期が合わない

プロセスのメモリ使用量を出すメトリクスが存在せず、事後には追えない。

### 考察

**spatial exploration は env 非依存とは言えない。** Breakout では低スコア裾を潰した（`<100` 15.5% → 1.4%）が、本スイープでは **qbert の eval に min 500 / max 8,375（17 倍）の開き**が残り、**double_dunk はランダム以下**である。ただし本スイープはラダー ON の単腕のみで OFF 対照がないため、**ラダーの寄与は分離できていない**。「被覆由来なら env 非依存」という仮説は肯定も否定もされていない。

**Breakout は易しい側の題材だった。** 旧バンドルの Breakout は 100M で hns57 1685% に達したが、本スイープの 5 ゲームは 20M で −77% 〜 174% に散らばる。バンド幅も 2.2（double_dunk）〜 34,828（battle_zone）と 4 桁違い、**Breakout 1 本で見ていた「うまくいっている感」は題材に依存していた**。

**double_dunk の失敗は構造的である可能性が高い。** このゲームは開始前にスティック方向でフォーメーションを選ぶ**プレイ選択フェーズ**を持ち、「選んでから実行する」という階層構造が入る。素の DQN 系がここで詰まるのは説明が付く。ただし 20M では「難しいから遅い」と「構造的に不可能」を分離できない。

**phoenix の生存戦略はスコアと長さの分離として観測できる。** スコアが 4,998 でピークを打った後もエピソード長は伸び続け、10M 以降は上限に張り付いた。**スコアを捨てて生き延びる方策**への収束であり、`game_score` と `game_len` を併せて見ないと「学習が進んでいる」と誤読する形である。上限 27,000 step は文献準拠（Dopamine の `max_steps_per_episode` 相当）だが、**train 側にも同じ上限が効いており、eval のコストと安定性の両方を押し上げた**。

**総合推定は「途中経過」として読むべきである。** 3 ゲームが上昇中で終わっており、55.4% は収束値ではない。Nature DQN の Atari-57 median 約 79% / Rainbow 約 227%（いずれも 200M frames）と比べる場合、**フレーム数が 40% しかない**ことを併記しないと意味を持たない。なお本記録の環境は **sticky 0.25 + noop 0**（noop 30 への変更は不発）であり、noop 由来の初期状態多様化は入っていない。

## pending

- **予算 20M の不足**。3 ゲーム（battle_zone / name_this_game / qbert）が 15-20M 窓でも上昇中で、飽和点が未観測。50M（BTR の 200M frames 相当）で頭打ちするかも未確認。
- **ラダー ON/OFF の対照が無い**。本スイープは apex 単腕。`run.@a5_base`（ラダー OFF）との A/B を取らないと、Breakout で観測した裾の改善が env 非依存かは判定できない。
- **`replay_ratio` の env 汎化**。Breakout では RR1 が内点最適（探索ブロック 25）だが、他 env では未検証。**1 腕あたり 50M 以上が必要**（Breakout では 0-20M で RR4 が RR1 を上回り、優位が立つのは 40M 前後から）。
- **phoenix の `bad allocation` の確保元**。上記 4 候補は排除したが未特定。**プロセスメモリのメトリクスが存在しない**ことが追跡不能の直接原因。
- **エピソード長上限の train / eval 分離**。現在は env 既定の 108,000 frames が train と eval の両方に効く。phoenix では eval 1 本が 27,000 step かかり、eval interval 1,000 learn_step（= RR1 で 256,000 exp）との比が崩れて train 側の停止を生んだ。
- **double_dunk が構造的に不可能かどうか**。20M では「遅い」と「不可能」を分離できない。
- **qbert の分散**。終盤プールで min 500 / max 8,375 と 17 倍の開きがあり、方策が安定していない。1 本評価では原因（探索ノイズか方策の不安定性か）を分離できない。
- **新旧バンドルの断絶**。7 項目を同時に動かしたため、旧バンドルの Breakout 記録と絶対値の比較ができない。Breakout を新バンドルで 1 本引き直さないと連続性が回復しない。
