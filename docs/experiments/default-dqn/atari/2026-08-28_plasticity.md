## 現時点のまとめ

1. **摩耗は勾配 step の関数で、`replay_ratio` にほぼ依存しない。** 同一 grad step（約 150k = RR8 の 5M、RR4 の 10M）で `weight_norm_feature` が 63.9 対 67.4（差 5.5% = ブレ幅内）、`dead_ratio` の谷からの倍率が 5.9 対 5.8 で一致する（探索ブロック 01）。
2. **変わるのは「その摩耗を買うのに何件の新規データが付いたか」。** 同じ 150k grad で RR8 は 5M 分、RR4 は 10M 分しか見ておらず、RR8 は崩壊し RR4 は凹んで回復した。`q_gap`（価値関数側の症状）が RR 依存だったのと役割分担している。
3. **膨らむのは feature 側で readout ではない。** feature / readout の成長比が全腕で 4.2〜5.6 倍。PRD062 で残った「Q 横ばい + ‖φ‖ 成長」の二択が閉じた（探索ブロック 01）。
4. **`dead_ratio` の谷が転換点を予告する。** 上昇開始と `weight_norm_feature` の底が、どちらも eval ピークの直後の窓に来る。5 腕すべてで一貫（探索ブロック 01・04・05）。
5. **srank は今回の損傷モードを見ない。** δ=0.01 / 0.05 / 0.20 の 3 種、probe batch 512 / 4096 の両方で、崩壊時の深さは −3〜6%。同じ事象で `dead_ratio` は +490%（探索ブロック 03）。srank は生き残った方向の分布を、dead はユニットの脱落数を測るので**設計上ほぼ直交**する。
6. **RR8 / 5M / 旧バンドルは 54 分で回る崩壊アッセイになる。** eval1 が 2.0-2.5M 窓でピークを打って落ちる。ただし**同一 config 5 本のうち 1 本は崩壊しない**（4/5）ので、n=1 の腕は判定に使えない（探索ブロック 01）。
7. **メトリクスのコストは `1/interval` に比例し、interval 500 で実質ゼロになる。** probe チャネルは interval 100 で −2.10%、500 で +0.01%。actual は −0.43%、weight_norm は +0.21%（探索ブロック 02）。
8. **`probe.batch_size` は隠れた測定パラメータで、`dead_ratio` を 5 倍変える。** 512（= 特徴次元 D）は Marchenko-Pastur 境界に乗り、たまにしか発火しないユニットが死んで見える。4096 での真値は 0.0078 に対し 512 では 0.0409（探索ブロック 03）。
9. **GroupNorm 単独は悪化させ、weight_decay は `weight_norm_feature` を用量順に制御するが崩壊は止めない。** 「LayerNorm + WD」はこの形では効かなかった（探索ブロック 04）。
10. **weight_decay は重み成長を「抑える」のではなく「均衡する」。** 10M では 45.8 → 30.5（3.0M で底）→ 43.4（8.0M）と V 字を描き、早期に稼いだ分の大半を押し戻される（探索ブロック 05）。
11. **`dead_ratio` の水準とスコアは設定をまたぐと乖離する。** 同一設定内の時間軸では転換点を予告するが、腕をまたいだ水準比較は成立しない（探索ブロック 04）。

## 探索ブロック 01: RR ラダーでの器の初回検証

### 探索観点

可塑性メトリクスが実際に損傷を検出するかを、**正解が既知の軸**で確かめる。`replay_ratio` は `q_gap` の過渡の深さが RR8 −62% / RR4 −31.5% / RR2 −11.8% / RR1 なしと記録済みで（`2026-08-17_baseline.md` 探索ブロック 15・23・24・25）、唯一のラベル付き軸である。

### 探索結果

**摩耗系は勾配軸で揃う。**

| | RR8 @148k grad | RR4 @140k grad |
|---|---|---|
| `weight_norm_feature` | ≈63.9 | ≈67.4（差 5.5%） |
| `dead_ratio` 谷からの倍率 | 5.9× | 5.8× |

**feature / readout の分離。**

| | RR8 (5M) | RR4 (20M) | RR1 (20M) |
|---|---|---|---|
| `weight_norm_feature` | 1.47× | 2.04× | 1.12× |
| `weight_norm_readout` | 1.10× | 1.25× | 1.02× |
| 成長比 | 4.7× | 4.2× | 5.6× |

同 exp（5M）で切ると feature 側は RR8 1.47× > RR4 1.28× > RR1 1.02× と RR 単調。

**反復のブレ幅**（r1 / r2、非決定 backend）: srank ±2%、`q_max` ±5%、`dead` / `feature_norm` ±10〜19%。RR8 の崩壊は eval ピークが**同一窓・同値**（65.0 / 64.2）で再現した。

**ただしアッセイは 4/5。** 同一 config 5 本のうち `run_20260828-204855` だけが崩壊せず、立ち上がりが遅いまま単調に 63.7 まで上昇した（有効 config 差分ゼロを確認済み）。

### 考察

摩耗量そのものは RR に依存せず、勾配 step で決まる。RR が決めるのは「その摩耗を買うのに何件の新規データが付いてきたか」であり、Kumar 2021 / Sokar 2023 の "updates per datum" がそのまま観測されている。`2026-08-17_baseline.md` の「RR=1 が内点最適」という実測結果に、機序の説明が付いた。

`dead_ratio` は**谷からの倍率**が grad 軸で揃う一方、**絶対値は揃わない**（同 grad で 0.041 対 0.076）。水準ではなく倍率で読む指標である。`weight_norm_feature` は絶対値で揃うので物差しとしては素直。

## 探索ブロック 02: コスト A/B

### 探索観点

メトリクスを常時 ON にできるか。チャネル別・`interval` 別・`probe.batch_size` 別のコストを分離する。

### 探索条件

RR8 / 1M exp / eval 無効 / 7 腕 × 3 巡のラウンドロビン。**この機械は 1 時間で最大 8% ドリフトする**ため、腕をブロック配置すると符号を誤る。

### 探索結果

3 巡の中央値（`90_perf/12_exp_step_per_sec`、20%:100%）。

| 腕 | 中央値 | vs なし | 1 測定あたり |
|---|---|---|---|
| なし | 1654.0 | — | — |
| actual のみ | 1646.9 | −0.43% | 8.3 ms |
| probe 512 | 1619.3 | −2.10% | 41.4 ms |
| 両方 | 1614.1 | −2.41% | — |
| probe 512 / interval 500 | 1654.1 | **+0.01%** | — |
| probe 4096 | 1504.3 | −9.05% | 192.6 ms |
| weight_norm のみ | 1657.5 | +0.21% | — |

チャネルコストは**加算的**（P1 増分 12.9s + P2 増分 2.6s = 15.5s に対し P3 実測 14.9s）。probe batch を 8 倍にすると増分は 4.65 倍で**劣線形**。

3 巡のうち 3 本（P2-r1 / P3-r1 / P6-r3）がバックグラウンド負荷で低い側の外れ値になった。1 巡だけでは actual が probe より高いという逆の結論が出る。

### 考察

`weight_norm` は forward も SVD も伴わないため実質無料。actual は学習 forward を再利用するので probe の 1/5。コストが `1/interval` に比例することが確定したので、**間引きの議論自体が不要**になった。

需要駆動化（購読された統計だけ計算する変更）の後、probe batch 4096 で srank の interval だけを 10 分の 1 にした比較では、ドリフト補正後で coarse が +1.09% 速い（control 3 本と coarse 3 本が完全分離、p≈0.05）。**SVD は batch 4096 のペナルティ 6.81% のうち約 1/6** で、支配的なのは probe forward 側である。

## 探索ブロック 03: srank の感度

### 探索観点

srank が崩壊に反応しないのは、δ=0.01 が裾統計だからか、`probe.batch_size` が特徴次元と同じ（N=D=512）で経験スペクトルがノイズに支配されているからか。

### 探索結果

**probe batch を 4096 にしても救えない。** 終盤に −1.6% の低下は出るがブレ幅 ±2% の中。ただし 366 → 450 の上昇で、512 の推定が**下方バイアス**だったことは確認できた。

| 終端値 | b512 | b4096 | 差 |
|---|---|---|---|
| `probe_srank` | 366.0 | 449.9 | +23% |
| `probe_dead` | 0.0409 | **0.0078** | **−81%** |
| `probe_dormant` | 0.2161 | 0.2293 | +6% |
| `probe_feature_norm` | 10.69 | 10.38 | −3% |

**δ を緩めても救えない。** 崩壊した Run（`a1_delta_wd0`、eval ピークは 40-50% 窓）での深さ:

| | ピーク | 谷 | 深さ |
|---|---|---|---|
| srank δ=0.01 | 361.6 | 346.0 | −4.3% |
| srank δ=0.05 | 248.5 | 240.1 | −3.4% |
| srank δ=0.20 | — | — | **谷なし**（17.4 → 133.6 単調上昇） |
| （参考）`dead_ratio` | 0.0069 | 0.0409 | **+490%** |

### 考察

δ=0.20 が最も鈍い。「80% の質量を担う方向の本数」は表現が育つほど増えるので、**損傷ではなく成長を測っている**。上位構造を見れば感度が上がるという想定は成立しなかった。

`dead_ratio` の N 依存が大きい理由は、512 サンプルでは「たまにしか発火しないユニット」が死んで見えるため。4096 での真値 0.0078 = 512 ユニット中 4 個であり、**b512 の 0.0409 は 5 分の 4 がサンプリング由来**だった。ただし指標としては b4096 のほうが明確で、健全な間は厳密にゼロ、谷が eval ピークと同一窓に揃う。

N 感度の順位: `dead_ratio`（5 倍）≫ `srank`（23%）> `dormant_ratio`（6%）≈ `feature_norm`（3%）。

## 探索ブロック 04: 正規化 × weight_decay

### 探索観点

feature 側の重み膨張は崩壊の**原因か症状か**。weight_decay は既存機能なので実装ゼロで問える。正規化があると直前 conv の重みスケールが `(x−μ)/σ` で割り切れて ‖w‖ 成長が機能的に無害になるため、WD 単独（正規化なし）は文献が効かないとする条件にあたる。2×2 で分離する。

### 探索条件

GroupNorm は ResBlock 内部のみ（`res.norm_type = group`、`group_norm_groups = 4`）。ダウンサンプリング Conv 3 本と最終 Linear512 は素のまま。

### 探索結果

| 腕 | n | eval1 ピーク | eval1 末 | `wn_feat` 倍率 | `dead` 末 |
|---|---|---|---|---|---|
| none WD0 | 3 | 64 / 58 / 64 | 31 / 35 / 64 | 1.47 / 1.47 / 1.08 | .041 / .050 / .012 |
| none WD0.1 | 2 | **90 / 90** | 42 / 41 | **0.94 / 0.97** | .004 / .029 |
| group WD0 | 2 | **36 / 45** | **17 / 22** | 1.35 / 1.34 | **.071 / .068** |
| group WD0.01 | 1 | 50 | 24 | 1.24 | .044 |
| group WD0.03 | 1 | 48 | 20 | 1.08 | .032 |
| group WD0.1 | 2 | 58 / 49 | 18 / 21 | 0.80 / 0.79 | .0096 / .0120 |
| group WD0.3 | 1 | 74 | **73** | 0.45 | .047 |

### 考察

**GroupNorm 単独は明確に悪化した。** 2 本ともピーク・終端の両方で対照より下、`dead` は 2 倍。ピーク位置も早い。

**weight_decay は `weight_norm_feature` を用量順に完全制御する。** 1.47 → 0.94（none）、1.35 → 0.80 → 0.45（group）。複製の一致も 0.79 / 0.80 と極めて良い。「WD は wn_feat を寝かせるか」の答えは yes。

**`none + WD0.1` はピークを 61 → 90 に上げた**（複製 90.1 / 90.4）。ただし終端は 41 で崩壊自体は残る。WD が単なる症状抑制ではないことを示す一方、崩壊の解にもなっていない。

`group + WD0.3` だけが回復したが n=1 で、対照の 2 割は自然に崩壊しないため確定できない。ただし形は違い、対照の非崩壊例が「一度も高くならなかった」のに対しこちらは「上がって落ちて戻った」。

**この試験は「LayerNorm + WD」の公正な検証になっていない。** 正規化が ResBlock 内部だけで、`main_feature` を作る最終 Linear512 が素のまま（7 つの重み層のうち 4 つが素）。‖w‖ 成長が機能的に無害になるという機序が、測っている特徴の直前で成立していない。

`dead_ratio` とスコアの乖離も観測された。WD0.1 は死亡が最小（0.012）なのにスコア最悪、WD0.3 は死亡が多い（0.047）のにスコア最良。**同一設定内の時間軸では転換点を予告するが、設定をまたいだ水準比較は成立しない。**

## 探索ブロック 05: 保護の持続（10M）

### 探索観点

`group + WD0.1` の効果が 5M より先で持つか。

### 探索結果

列は exp M。

```
eval1     4.2 27.7 41.8 49.7 41.2 44.0 38.8 31.8 25.7 18.9 15.0 12.8 11.0 10.6 10.3 10.8 10.7 12.3 21.2 11.3
wn_feat  45.8 39.7 35.2 32.3 30.8 30.5 31.0 32.1 33.7 35.6 37.4 39.2 40.8 42.0 43.0 43.4 43.1 42.5 41.9 41.4
dead     .231 .058 .038 .037 .022 .013 .012 .013 .017 .021 .025 .029 .039 .047 .047 .066 .080 .077 .077 .081
```

前半 5M は 5M 版 2 本と一致する（`wn_feat` 45.8 / 39.7 / 35.2 対 45.8 / 39.7 / 35.3）。

### 考察

**崩壊は止まらず回復もしない。** eval1 は 2.0M で 49.7 のピーク、6.5M 以降 10-11 で底ばい、10M 時点 11.3（ピークから −77%）。5M で切ったときの 18-21 よりさらに悪化する。

**weight_decay は抑制ではなく均衡である。** `wn_feat` は 30.5（3.0M で底）→ 43.4（8.0M）の V 字。減衰項 λ·w は w が小さくなるほど弱まるので、勾配側の押し上げと釣り合う点で止まる。水準は抑える（10M で 41 対 無保護の 5M 時点 63）が、早期に稼いだ分の大半を押し戻される。

`dead` は谷 0.0121（3.5M）から 0.0814（10M）へ 6.7 倍。同 exp 5M では保護あり 0.0209 対 無保護 0.0409 で、**死亡率は半分になるが蓄積は止まらない**。

タイミング則はここでも成立し、`dead` の谷（3.5M）と `wn_feat` の底（3.0M）がどちらも eval ピーク（2.0M）の直後に来る。

## 次の検証

- **正規化の配置。** ResBlock 内部だけでは `main_feature` を作る最終 Linear512 が素のままで、機序が測定点の直前で成立していない。`Linear512 > LayerNorm > ReLU` を加えた条件が未測定。
- **`group + WD0.3` の複製。** 唯一回復した腕だが n=1 で、対照の非崩壊率 2 割と区別できていない。
- **抑制系以外。** 抑制（weight decay / 正規化）が総じて振るわなかったため、摩耗をリセットする系統（reset / Shrink-and-Perturb）が未評価で残る。摩耗が勾配 step の関数であることは 01 で確定している。
