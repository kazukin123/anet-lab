# Atari Breakout: BTR NN構成の移植検証 — 2026-09-12

対象 workspace: `atari-3rd`。ゲームは breakout 固定。すべて seed 1、`backend.@non-deterministic`。

基準は Munchausen 入りの RR4 構成で、`run.@v5_iqn_impala_x2 > run.@a5 > run.@a5_apex > run.@va_base` に
`run.@hard500 > run.@rr4 > run.@munch` を重ねる。各腕はそこから**NN構成だけ**を変えている。

起点は [2026-09-08](2026-09-08_replay-ratio-mechanism.md) 探索ブロック 10
（BTR 公開実装は同じ再利用 4 回で崩れず、本構成の RR4 素を大きく上回った）。
本記録は**その差が NN構成のどこから来るか**の分解を主題にする。

判定軸は `52_eval2/10_game_score_mean`（ε=0.01）と `42_env/41_game_score_ge432_ema`。
Breakout の満点は **864**（2 画面 × 432、216 ブロック）。

**eval2 のセッション構成が腕ごとに違う。** btrfull は interval 1009 learn step / 10 エピソード、
btrtrunk 以降は interval 3906 / **100 エピソード**である。平均値は不偏だが、
**セッション内の max（`16_game_score_max`・`24_game_len_max`）は本数が違うので直接比較できない**（探索ブロック 05）。

6. **機序は `22_grad_norm_ema`。** SN 無しは累計 22M → 40M で **4.096 → 4.605** と単調上昇し、

   クリップ率は 0.03% 据え置き。**成績の符号反転と同じ区間で起きている**（探索ブロック 04）。

   30-40M で SN 有り 0.258% 対 SN 無し 0.225%、20-30M で 0.129% 対 0.100%。

## NN構成（3 軸）

| | Pool6 | trunk512<br>(融合位置) | SN | Run | 総params | main_feature | readout<br>(V/A + τ) |
|---|:---:|:---:|:---:|---|---:|---:|---:|
| **A** | − | 有(512) | − | RR4 素 | 4,914,080 | 4,355,488 | 558,592 |
| **B** | 有 | 有(512) | − | 未測 | 2,128,800 | 1,570,208 | 558,592 |
| **C** | 有 | 有(512) | 有 | btrtrunk | 2,128,800 | 1,570,208 | 558,592 |
| **D** | 有 | −(2304) | − | btrnosn / 継続 | 2,899,104 | 389,024 | 2,510,080 |
| **E** | 有 | −(2304) | 有 | btrfull | 2,899,104 | 389,024 | 2,510,080 |

`AtariPool6` = `MaxPool2d(kernel 2 / stride 2 / padding 1)`。11×11×64 = 7744 を 6×6×64 = 2304 にする。
**`AtariLinear512` の入力が 7744 → 2304 になり、そこだけで 3,965,440 → 1,180,160 パラメータ減る**（A → B/C）。

**B と C の学習パラメータ数は完全に同一**である。SN は `u` バッファしか足さないので、
checkpoint の `model_size` が 17,211,990 対 17,286,434 と 74,444 バイトだけ違う（online + target の 2 本ぶん）。

B の配線は `run_20260913-071609_tmp_wiring_btrtrunknosn` で解決させてあり、
**C との設定差分は `main_feature.structure` の 1 行（SN 接尾辞）だけ**である。
A との差分は `AtariPool6` の挿入と `train.num_envs` 128 → 64 の 2 行。

## 探索ブロック 01: BTR 公開実装との突き合わせ

### 探索観点

[2026-09-08](2026-09-08_replay-ratio-mechanism.md) 探索ブロック 10 で、BTR 公開実装は同じ再利用 4 回で
本構成の RR4 素を大きく上回った。BTR の NN構成（Pool6 + 融合 2304 + SN、共有トランク無し）を移植して
差が埋まるかを見る。

### BTR の eval ε は途中で切り替わる

BTR の `main.py` は eval の ε を **index 125 まで 0.01、以降 0** にする。
eval は 250,000 遷移ごとに 200 回なので、**切り替え点は exp 31.25M** である。
コード側のコメントはこれを速度対策としている（"agents get stuck in some games, causing evals to last a very long time"）。

したがって **31.25M 未満の窓だけが ε を揃えた比較**になる。

## 探索ブロック 02: NN構成の分解

### 探索観点

btrfull は RR4 素から **Pool6・融合位置・SN の 3 つ**を同時に変えている。1 つずつ戻して寄与を測る。

### 探索結果（12-15M）

```
A RR4素 423.7 ──(+31.3)── C btrtrunk 455.0 ──(+39.9)── E btrfull 494.9 ──(+32.9)── D btrnosn 527.8
                Pool6 ∧ SN              融合位置 512→2304          SN 除去
                （2 変数）               （SN 有りの下）            （2304 の下）
```

18-20M では同じ辺が **+31.8 / +80.3 / +7.7** になる（SN の辺は探索ブロック 03）。

| 腕 | eval2 12-15M | `≥432` | `02_loss_ema` | `17_q_gap` |
|---|---|---|---|---|
| A RR4 素 | 423.7 | 5.51% | 0.428 | 0.107 |
| C btrtrunk | 455.0 | 7.31% | 0.544 | 0.132 |
| E btrfull | 494.9 | 9.58% | **0.718** | **0.209** |
| D btrnosn | **527.8** | **11.95%** | 0.680 | 0.177 |

### 考察

**最大の寄与は融合位置**（+39.9 / +80.3）で、`AtariLinear512` を τ 融合の**後ろ**へ移すことにあたる。
readout が 558,592 → 2,510,080 パラメータになり、main_feature は 1,570,208 → 389,024 に減る。
総パラメータは 2,128,800 → 2,899,104 と増えるが、**A（4,914,080）よりは依然 41% 少ない**。

`02_loss_ema` は成績と単調ではない。A → C → D は成績と同順だが、**E は loss が最高（0.718）なのに
成績は D（0.680）より低い**。[2026-09-08](2026-09-08_replay-ratio-mechanism.md) まとめ 2 の
「replay への当てはまりが良い腕ほど成績が悪い」は、**SN ぶんの上積みでは成立しない**。

**A → C の +31.3 は Pool6 と SN の 2 変数のままである。** SN の寄与が D↔E の −32.9 と同じなら
Pool6 単独は +64.2、SN がトランク構造で中立なら +31.3 になるが、どちらかは測っていない。

`AtariPool6` を共有トランクの前に置く構成（= B）は **RR1 では測られており、明確なマイナスだった**。
[2026-09-01](2026-09-01_btr-feedback-arms.md) 探索ブロック 13 段 1（`run_20260902-065010`）:

| 窓 | V/A 基準（A 相当） | 段 1（B 相当） | 差 |
|---|---|---|---|
| 12-15M `51_eval1` ema | 375.5 | 347.4 | **−28.1** |
| 18-20M `51_eval1` ema | 426.1 | 398.1 | **−28.0** |
| 25-50M `51_eval1` ema | 469.0 | 406.4 | −62.7 |
| 25-50M 壁突破率 | 3.48% | **1.55%** | 半減 |

**RR1 では全期間でマイナスであり、早期の優位が後で消えるという形ではない。**

## 探索ブロック 03: SN の符号反転

### 探索観点

btrnosn（D）が btrfull（E）を上回ったため、20M で打ち切らず継続 Run で 50M まで延ばして
差が維持されるかを見る。

### 探索結果

継続 Run の軸に +20M して累計で揃えた。

| 累計 | D SN 無し | E SN 有り | 差 | D `≥432` | E `≥432` |
|---|---|---|---|---|---|
| 12-15M | 527.8 | 494.9 | **+32.9** | 11.95% | 9.58% |
| 18-20M | 549.4 | 541.8 | **+7.7** | 12.93% | 12.55% |
| 22-25M | 540.9 | 555.5 | **−14.6** | 13.64% | 14.10% |
| 25-28M | 560.6 | 566.6 | −6.0 | 14.35% | 14.15% |
| 28-31M | 578.2 | 588.1 | −9.9 | 14.41% | 14.55% |
| 31-34M | 573.5 | 577.9 | −4.4 | 14.74% | 15.70% |
| 34-37M | 564.5 | 594.0 | **−29.5** | 15.00% | 16.28% |
| 37-40M | 570.8 | 583.4 | −12.6 | 15.68% | 16.31% |

**符号が 20-22M で反転する。** 22M 以降は 6/6 窓で SN 有りが上、`≥432` も 5/6 窓で上。
28-40M プールでは **571.8 対 585.9 = −14.1**（複製幅 10.6 の 1.3 倍）。

22-25M の −14.6 は継ぎ目の凹み（探索ブロック 06）を含むため SN 無しに不利側へ振れているが、
回復後の 28M 以降だけでも 4/4 窓で負ける。

### 考察

**SN は早期コスト・後期利益である。** 20M 以下の予算では外したほうが速くて強く、
それ以上では入れたほうが強い。Breakout では交差点が **20-22M** にある。

[2026-09-01](2026-09-01_btr-feedback-arms.md) 探索ブロック 07（RR1 / 50M で SN 腕が全腕最下位 0.43%）とは
腕の構成が違う。同記録は residual ブロックのみ SN + he init で、本記録は全 15 conv の SN である。

## 探索ブロック 04: grad_norm と勾配クリップ

### 探索結果

累計ステップで揃えた `37_agent_qtd/22_grad_norm_ema` と `25_grad_clip_ratio_ema`（`grad_clip_tau = 10`）。

| 累計 | D SN 無し norm | clip 率 | E SN 有り norm | clip 率 |
|---|---|---|---|---|
| 22-25M | 4.096 | 0.20% | 2.802 | 0.03% |
| 28-31M | 4.394 | 0.23% | 2.833 | 0.03% |
| 34-37M | 4.551 | 0.27% | 2.669 | 0.03% |
| 37-40M | **4.605** | **0.37%** | **2.697** | 0.05% |

**SN 無しは単調上昇（+12.4%）、クリップ率は 1.85 倍。SN 有りは平坦どころか微減（−3.7%）、
クリップ率は横ばい。** 差は norm で 1.7 倍、クリップ率で 7〜12 倍。

20M 以前の 4 腕でも順序は同じである。

| 腕 | 12-15M | 18-20M |
|---|---|---|
| A RR4 素 | 2.816 | 2.485 |
| C btrtrunk（SN 有） | 3.242 | 3.108 |
| E btrfull（SN 有） | 3.145 | 2.966 |
| D btrnosn（SN 無） | **3.866** | **4.069** |

### 考察

**SN が入っている 2 腕（C・E）は 12-15M → 18-20M で norm が下がり、入っていない腕のうち
D だけが上がる。** 成績の符号反転（探索ブロック 03）と同じ区間で grad_norm が分岐しており、
SN の Lipschitz 制御が効いている形になっている。

`grad_clip_tau = 10` に対して平均 4.6 なので飽和はしていない。

## 探索ブロック 05: エピソード長キャップとセッション本数のバイアス

### 探索観点

btrnosn の `52_eval2/24_game_len_max` が 9.70M で 27,000（`max_episode_frames 108,000 / frame_skip 4`）に
到達し、btrfull の初到達 26.16M より 2.7 倍早く見えた。**eval2 のセッション本数が違う**ため、
これが実体か測定バイアスかを切り分ける。

### セッション内 max は本数でバイアスする

| 腕 | エピソード/セッション | セッション数 | 初キャップ |
|---|---|---|---|
| btrfull | 10 | 772 | 26,159,616 |
| btrnosn | **100** | 79 | **9,699,456** |
| 継続 | **100** | 86 | — |

`24_game_len_max` は**セッション内の最大値**なので、100 本の max と 10 本の max を並べている。

### エピソードで正規化すると差は無い

| 累計 | SN 有り（10本/セッション） | SN 無し（100本/セッション） |
|---|---|---|
| 0-10M | 0.000% (0 / 1,520) | 0.025% (1 / 4,000) |
| 10-20M | 0.000% (0 / 1,550) | 0.051% (2 / 3,900) |
| 20-30M | **0.129%** (2 / 1,550) | 0.100% (4 / 4,000) |
| 30-40M | **0.258%** (4 / 1,550) | 0.225% (9 / 4,000) |
| 40-50M | 0.194% (3 / 1,550) | — |

**両方にデータがある 2 窓では SN 有りのほうがわずかに高い。** 0-20M で SN 有りが 0 件なのは、
3,070 エピソードしか見ておらず、真の率 0.038% なら期待値 1.2 件で、0 件は p ≈ 0.30 で普通に起きるためである。
**初キャップ到達点の 2.7 倍差は測定バイアスであり、構成差ではない。**

率はセッション内で複数本キャップしても 1 本としか数えないため**下限**である。

### README 記述の修正

README の eval 行は「`24_game_len_max` が 27,000 に張り付き、ε=0 の 2 本は全セッションでキャップ到達、

## 探索ブロック 06: RB を引き継がない継続 Run

### 探索観点

checkpoint は config + Adam + model のみで、**replay buffer は直列化されない**
（`total_size=46,635,426 = config 6,346 + adam 23,270,167 + model 23,358,866`）。
20M で打ち切った btrnosn を継続したときに何が起きるかを測る。

### eval には段差が出ない

| | eval2 |
|---|---|
| 親 18-20M 窓 | 549.4 |
| **継続 初回セッション**（軸 200,064） | **542.1** |

初回セッションで `16_game_score_max` = 864、`20_game_len_mean` = 4,013.6。
親の 17-20M の個別セッションは 521.1〜581.2 に散らばっており、**542.1 はその内側**である。

[2026-09-01](2026-09-01_btr-feedback-arms.md) 探索ブロック 29 の hard125 継続（親最終 3M 533.98 →
継続 :1M 534.67）に次ぐ **2 例目**になる。

`replay_capacity` は 1,048,576 で、20M 時点の連続 Run の RB も直近 1.05M しか保持していない。
継続後 1M 程度で実質同じ分布に戻るため、**真の不連続は最初の約 1M（PER 優先度リセットと
`learn_start` ゲート）に限られる**。

### train 側の EMA は暖機が要る

hard125 継続での `42_env/41_game_score_ge432_ema`（α=0.001）:

| 窓 | 値 | 親比 |
|---|---|---|
| 親 最終 3M | 13.77% | — |
| 継続 :1M | 6.11% | **44%** |
| 継続 1-3M | 12.77% | 93% |
| 継続 3-6M | 13.67% | 99% |

1M は約 490 エピソードなので EMA の理論収束は 1 − e^(−0.49) = **39%**。実測 44% はこれと一致する。
**学習の後退ではなくメトリクスの暖機**である。

### 継ぎ目に 1 窓ぶんの凹みはある

| 累計 | eval2 |
|---|---|
| 親 18-20M | 549.4 |
| 継続 20-22M | **534.3** |
| 継続 22-25M | 540.9 |
| 継続 25-28M | 560.6 |

eval の段差は無いが、RB 再充填と PER 優先度リセットのぶんの**遅れ**は出る。累計 25-28M で回復する。

### learner は 1 分で定常に戻る

継続開始直後は RB が空のため 1 更新あたり 350 exp だが、**67 秒後には 64 exp/更新**
（`num_envs 64 × replay_ratio 4 / replay_batch_size 256` の理論値）に達した。

## 探索ブロック 07: 実時間

| 腕 | NN構成 | 総params | eval2 設定 | throughput | 実時間 |
|---|---|---|---|---|---|
| A RR4 素（envs128） | trunk512 | 4,914,080 | 1009 / 10ep | 1,744 | 7h57m / 50M |
| C btrtrunk | trunk512 + Pool6 + SN | 2,128,800 | 3906 / 100ep | 1,328 | 4h11m / 20M |
| D btrnosn | 2304 + Pool6 | 2,899,104 | 3906 / 100ep | **1,486** | 3h44m / 20M |
| D 継続（同一構成） | 同上 | 2,899,104 | 3906 / 100ep | 1,349 | 5h08m / 24.9M 時点 |
| E btrfull | 2304 + Pool6 + SN | 2,899,104 | **1009 / 10ep** | 952 | 14h34m / 50M |

**SN の実時間コストは分離できていない。** btrnosn 対 btrtrunk の −10.6% は SN と融合位置の
両方が違う対であり、しかも**同一構成の再実行（btrnosn 対 その継続）でも 1,486 対 1,349 = −9.2% 出ている**。
実験機のドリフト（1 時間で最大 8%）と同程度である。

btrfull の 952 は eval2 の interval が他の 4 倍あることによる。NN構成の重さだけの値ではない。
