## 探索ブロック 01: 崩壊アッセイのバンドル移行

### 探索観点

崩壊アッセイは `run.@breakout_rr1_100m`（**旧バンドル**）に固定されていた。信号が存在すると分かっている条件で測る必要があったためだが、その状態で保護機構を screening すると「旧バンドルで選抜して新バンドルへ適用する」ことになる。

BTR 寄せで `per_alpha` 0.5→0.2 / `grad_clip_tau` 30→10 / `num_taus` 32→8 / `warmup` 20k→200k が動き、さらに今回 `noop_max` と `adam_eps` が乗った。**過渡が消えている可能性**があるため、器が生き残るかを先に確認する。

### 探索結果

`51_eval1/10_game_score_mean` の 1M 窓平均。

| exp 窓 | 旧バンドル | 新バンドル r1 | 新バンドル r2 |
|---|---|---|---|
| 0-1M | 13.5 | 10.9 | 8.6 |
| 1-2M | 125.8 | 187.5 | 135.9 |
| **2-3M** | **165.8** | **323.7** | **239.7** |
| 3-4M | 51.2 | 249.9 | 164.8 |
| 4-5M | 51.2 | 139.0 | 113.0 |
| ピークからの落差 | −69% | **−57%** | **−53%** |

**2/2 で崩壊し、ピーク窓が旧バンドルと一致した。** ピーク高の 323.7 / 239.7 は −26% 差で、既知の変動幅（±26%）と整合する。

実効 config は `AtariEnv.noop_max = 30` / `DefaultDQNAgent.learner.adam_eps = 1.95e-5` / `replay_ratio = 8` / `plasticity.probe.batch_size = 4096` を実行時ダンプで確認済み。

**崩れ方は旧バンドルと違う。** 旧は 3-4M で底を打って 51.2 / 51.2 と平らになるが、新は 5M 時点でまだ落下中（249.9 → 139.0）。

**throughput は 1,545 → 1,270 step/s（−17.8%）。** 原因はバンドルではなく **eval interval** で、旧チェーンは `run.@breakout_rr1_100m` が 2500 を指定していたのに対し新チェーンは root の 1000 を継ぐ（eval 点数 63 → 150）。

### 考察

器は生き延びた。保護機構の screening を新バンドル上で回せるので、選抜と適用のバンドル差という懸念は解消した。

ただし**崩壊が遅くなっている**ため、「5M 時点の深さ」は旧バンドルでは底値だったが新バンドルでは途中経過である。腕を揃えれば比較子として成立するが、平坦部を読むより分散は大きい。

ピークが約 2 倍（165.8 → 323.7 / 239.7）になったのは大きな変化だが、BTR 寄せ 5 項目と今回の修正 2 件のどれが効いたかは本記録では分離していない。

eval interval を 2500 に戻せば 18% の throughput が返るが、150 点は 63 点に対して窓平均の標準誤差を 0.7 倍にする。eval1 が 1 エピソードで ±26% 振れることを踏まえ、**1000 のまま**とした。

## 探索ブロック 02: RR1 の新アンカー（50M）

### 探索観点

修正 2 件が実効になった構成での「現在地」を取る。予算は **50M**（= BTR の 200M frames）とし、旧ラダーの 100M（BTR の 2 倍予算）ではなく文献比較可能な座標に置く。

act dead     .440   .020   .031   .072   .135   .186   .191   .221   .221

### 考察

**修正 2 件は Breakout の軌道を動かさなかった。** 差はブレ幅の内側で、`noop_max` 0 → 30 の初期状態多様化も `adam_eps` 1e-4 → 1.95e-5 も、この題材・この予算では有意な差を生んでいない。**新アンカーは 50M 時点で約 440**（終盤 2 窓）とする。

**50M はまだ天井ではない。** 35M 以降で初めて 700 超が 3 本出ており、上側の裾が伸び始めた区間で予算が尽きている。旧バンドルの 100M Run が 60-100M プールで 474.7 まで伸びたことと整合する。

**運用点にも摩耗は蓄積している。** 195k 勾配 step は崩壊アッセイの崩壊点（〜150k）の 1.3 倍で、`act dead` は谷の 11 倍、`probe srank_ratio` は −20%。**それでもスコアが登り続ける**のは、同じ摩耗に 8 倍の新規データが付くためである（探索ブロック 04）。

**srank が初めて意味のある大きさで動いた。** RR8 アッセイでは δ 3 種 × probe batch 2 種で −3〜6% にとどまり「この損傷モードを見ない」と結論していたが、RR1 の長期では単調 −20% である。ユニット死とは別の**ランク浸食**が長時間スケールで進んでいる可能性があり、**RR8 アッセイはこのモードを再現しない**。保護機構の screening をアッセイのみで判定してはならない。

`act |phi|` の成長（3.42x）が `wn_feature`（1.52x）を大きく上回る。RR8 アッセイでは両者が 1.04 / 1.26 倍だったので別レジームであり、**両者の比を分布シフトの証拠に使うことはできない**（n=1 のため機序は未特定）。

## 探索ブロック 03: RR4 の天井（50M）

### 探索観点

BTR の `replay_ratio` は 4 である。旧バンドルでは「崩壊しないが 30M で天井」と記録されていた（[2026-08-17_baseline.md](2026-08-17_baseline.md) 探索ブロック 17）。新バンドルで天井が動いたかを見る。

### 探索結果

| exp 窓 | eval1 |
|---|---|
| 0-5M | 197.6 |
| **5-10M** | **324.6** |
| 10-15M | 318.1 |

**天井は 5-10M。** 旧バンドルの 30M より大幅に早い。以後 40M ぶん回して横ばい〜微減。

**スコアと可塑性の時系列**（`exp = grad × 64 + 0.2M`）。

| exp | grad | eval1 | `42_probe_dead` | `02_act_dead` | `45_srank_r` | act/prb |
|---|---|---|---|---|---|---|

| 50M | 778k | 295.7 | **0.359** | **0.412** | **0.557** | **1.1x** |

**50M 到達時点の RR1 との対比。**

| | RR1 | RR4 |
|---|---|---|
| eval1 終盤 | **427〜454（登り中）** | 273〜296（天井） |
| 勾配 step | 195k | 778k |
| throughput | 5,411 step/s | 2,739 step/s |
| `wn_feature` | 64.6（1.52x） | **132（3.11x）** |
| `act dead` | .221 | **.412** |
| `prb srank_ratio` | .691 | **.557** |

### 考察

**RR4 は 4 倍の勾配 step と 2 倍の実時間を使って、RR1 の 2/3 で頭打ちになる。** 摩耗はすべての指標で約 2 倍。BTR の RR=4 を保護機構なしで写すことに利がないことが、新バンドルでも確認された。

**死亡は天井の原因ではない。** 天井を打った 10M 時点の `probe dead` はまだ 5.3% である。36% は**停滞中に積み上がった**もので、因果は「死んだから止まった」ではなく「止まった後も回り続けて死んだ」。

**後半 80% の勾配 step は表現を削るためだけに使われた。** 10M → 50M で 625k 勾配 step を消費し、スコア −9%、死亡率 5.3% → 35.9%、実効ランク 380 → 285。探索ブロック 17 の「動いているのに前に進まない」の中身がこれである。

**actual / probe の収束が真正性の検証になる。** 序盤の 8.5 倍差は既知の N 依存 artifact（256 バッチでは「たまにしか発火しないユニット」が死んで見える）だが、終盤は 1.1 倍まで潰れる。**どのサンプルで測っても死んで見える = 入力によらず発火しないユニットが実在する**ことの証拠であり、チャネル差の収束そのものを診断に使える。

## 探索ブロック 04: 勾配軸での三腕整合

### 探索観点

[2026-08-28_plasticity.md](2026-08-28_plasticity.md) 探索ブロック 01 は「摩耗は勾配 step の関数で `replay_ratio` に依存しない」を RR8 / RR4 の 2 点で示した。新バンドルで RR1 を加えた 3 点、かつ 7.7 倍の exp スパンで成立するかを確認する。

### 探索結果

勾配 step で揃えた比較（`exp = grad × 256 / RR + 0.2M`）。

| 勾配 150k 時点 | RR8 | RR4 | RR1 |
|---|---|---|---|
| exp 換算 | **5.0M** | **9.8M** | **38.6M** |
| `61_weight_norm_feature` | 68.56 | 67.81 | 59.32 |
| `42_probe_dead_ratio` | .0254 | .0664 | .0254 |
| `45_probe_srank_ratio` | .8125 | .7383 | .7090 |

| 勾配 50k / 100k | RR8 | RR4 | RR1 |
|---|---|---|---|
| `wn_feature` @50k | 46.54 | 47.83 | 46.95 |
| `wn_feature` @100k | 57.09 | — | 53.64 |

### 考察

**`weight_norm_feature` が勾配軸で揃う。** 50k で 46.5〜47.8、150k で 59.3〜68.6。exp 軸では 7.7 倍離れた 3 点が、勾配軸ではほぼ重なる。**摩耗量は `replay_ratio` に依存せず勾配 step で決まる**という結論が、RR 8/4/1 の全域で確認された。

**結果を分けるのはデータ量である。** 勾配 150k 前後で摩耗が閾値を越え、そこから先の運命は付いてくるデータ量で決まる。

| | 150k 勾配時点のデータ量 | 結果 |
|---|---|---|
| RR8 | 5M | 崩壊（−57% / −53%） |
| RR4 | 10M | 天井で足踏み |
| RR1 | 38.6M | **まだ登る** |

**RR4 の天井位置（勾配 75〜153k）は RR8 の崩壊点（〜150k）と同じ座標にある。** 同じ摩耗が、データ量に応じて「崩壊」「天井」「無症状」として現れている。

この読みからの予測: **RR1 も 778k 勾配（= 200M exp）まで回せば同じ壁に当たる**はずである。保護機構が要るのはその領域であり、RR を上げて壁を早く引き寄せる理由はない。

`42_probe_dead_ratio` は RR4 だけ 150k で高い（.0664 対 .0254）が、これは水準比較が成立しない指標である（[2026-08-28_plasticity.md](2026-08-28_plasticity.md) まとめ 11）。倍率で読むこと。

## 次の検証

- **保護機構の screening。** 崩壊アッセイ（RR8 / 5M / 65 分）が新バンドルで使えるようになった。config のみで試せる腕（init2=he / 活性化の SiLU 化 / Linear512 直後の LayerNorm）と、[PRD 065](../../../memo/065_nn_spectral_norm_10prd.md) の Spectral Norm を同じ器で比較する。
- **screening が再現しないモードの扱い。** RR1 長期で観測されたランク浸食（`probe srank_ratio` −20%）を RR8 アッセイは再現しない。screening 合格を運用点有効の証明として扱わず、RR1 @ 50M での confirmation を必須とする。アンカーは本記録の **約 440**（終盤 2 窓）。
- **RR1 の 100M / 200M 側。** 50M でまだ登り坂であり、天井も摩耗の閾値も未観測。778k 勾配（200M exp）で RR4 と同じ壁に当たるかは未確認。
- **新バンドルのピーク 2 倍の帰属。** BTR 寄せ 5 項目と修正 2 件のどれが効いたかは未分離。
