# BTR 公開実装の qbert 再現と、序盤の学習の遅れ（初期値） 探索履歴

## メタデータ

| 項目 | 内容 |
|---|---|
| 対象 Agent | DefaultDQNAgent（IQN + Munchausen + NoisyNet） |
| 対象 Env | AtariEnv（ALE v0.12.0 直結）。qbert |
| 開始日 | 2026-10-23 |
| 主目的 | BTR 公開実装を手元で回して qbert の第 8 面の突破を確かめ、anet をできるだけ BTR に寄せても残る差を切り分ける |

## 現時点のまとめ

1. **BTR 公開実装は、この環境でも第 8 面を越えた。** train の突破率は r0 が 37.5-40M 0.4% → 45-47.5M 44.1% → 47.5-50M 56.4%、r1 が 22.5-25M 1.7% → 27.5-30M 42.8% → 37.5-40M 79.6%。
   初突破の時期は 2 本で 15M 違う。評価の曲線は公表 CSV とほぼ同じだった（探索ブロック 01）。
2. **BTR も第 9 面（L3R1）で止まる。** r0 の 47.5-50M の train で第 9 面を越えたゲームは 2.0%（715 本中 14 本）、r1 の 35-40M は 0.4〜0.5%（探索ブロック 01）。
3. **anet を BTR に寄せても、第 8 面はほぼ越えなかった。** 64 env・replay 1M・毎 step 同期・NoisyNet σ0 0.5 の Run は 45-50M で突破 0.0〜0.2%、縮小方式を `pixel_area` にした Run は 50M まで 0%（探索ブロック 02・03）。
4. **ε を BTR と同じ経過にすると、25M 以降の第 8 面の到達は約 2 倍になったが、33M までに突破は出なかった。** 32.5-35M の到達率は 67.3%（`pixel_area` の Run は 28.6%）。train の ε が 0 になった分の見かけの効果を含む（探索ブロック 04）。
5. **anet の qbert は、どの設定でも序盤の学習が BTR の半分ほどの速さだった。** 評価の 5-7.5M は、過去の anet の qbert 20 本以上で最高 8,675、BTR は 9,651〜10,766（探索ブロック 05）。
6. **胴体の conv の初期値を PyTorch の既定に戻すと、序盤の遅れは消えた。** 評価の 5-7.5M は 11,450、7.5-10M は 14,918 で、BTR の帯に入った。ε=0 の評価（5.25M）は 7,865 で、従来の初期値の 3,994 の約 2 倍。
   Munchausen の log π を online にした上乗せは見えなかった（探索ブロック 06）。
7. **実時間優先の構成（SN なし、LayerNorm あり）では、初期値を戻しても上がらなかった。** 評価の 7.5-10M は 4,448 で、従来の 2 本（7,306・5,068）を下回った（探索ブロック 07）。
8. **初期値を戻し、ε を BTR と同じ経過にした 50M で、第 8 面の突破は BTR と同じ帯になった。** train の突破は 20-22.5M に初出、32.5-35M 62.8%、47.5-50M 86.8%（BTR は r0 が 47.5-50M 56.4%、r1 が 37.5-40M 79.6%）。
   ε=0 の評価（100 本）は 40.6M で突破 100%、平均 43,621。第 9 面は BTR と同じく越えない。
   平均点の上回りには、第 9 面で 27,000 step の上限近くまで続いて点を重ねるゲームが入っている（探索ブロック 08）。
9. **30M 以降の train の平均点とゲームの長さの伸びは、第 9 面で終わるゲームが増えたことと、第 9 面で重ねる点が増えたことによる。BTR の 2 本も同じ形だった。** aln_btreps で第 9 面で終わったゲームは 32.5-35M 62.7% → 47.5-50M 86.5%、その得点の中央値は 31,975 → 39,488、平均の長さは 3,378 → 7,063 step で、第 9 面の突破はどの窓も 0.9% 以下。
   BTR は、第 9 面で終わったゲームの得点の中央値が r1 で 30,050（27.5-30M）→ 36,650（37.5-40M）、r0 で 30,800（42.5-45M）→ 32,388（47.5-50M）（探索ブロック 09）。

以下、Run 名の末尾（se_nz・btrlike・btrpa・btreps・aln_im・aln_init・aln_btreps）で呼ぶ。
「初期値」は、先頭の conv 3 本（`AtariImpalaConv32`・`AtariImpalaConv64`）、SN 付き残差 conv 12 本（`AtariImpalaRes32SN`・`AtariImpalaRes64SN` の `init1`・`init2`）、τ の埋め込み（`AtariIQNTauProj2304`）の `init.mode` を `default`（libtorch の既定のまま）にしたもの。
btrlike・btrpa・btreps の Head は、3 本とも NoisyNet σ0 0.5 と PyTorch 既定の初期値。

## 探索ブロック 06: コードの照合と初期値の修正

### 探索観点

BTR 公開実装と anet を、env と前処理、学習の更新式、replay と PER、ネットワークと NoisyNet と行動選択の 4 つに分けてコードで照合した。
btreps の実効 config と BTR の既定値・実行引数を突き合わせた結果、次のとおりだった。

| 区分 | 結果 |
|---|---|
| 一致 | sticky 0.25（エミュレータの 1 フレームごと）、NOOP 1〜30、frame skip 4 と直近 2 フレームの最大、ALE のグレースケール、先頭フレームの複製によるスタック、終端と 108k フレームの打ち切りの扱い、報酬の clip、lr 1e-4、γ 0.997、n=3、Adam eps 1.95e-5、grad clip 10（全体の L2 ノルム）、batch 256、64 遷移ごとに 1 更新、target の hard 更新 500、Double DQN なし、Munchausen（α 0.9、τ 0.03、下限 −1）、IQN の τ 8 本と cos 基底 64、PER α 0.2、IS 指数 0.2、新しい遷移の優先度は過去最大値、Dueling の形、NoisyNet（factorised、σ0 0.5、Head の 4 層、行動ごとに引き直す） |
| 違い（大きさの差） | 先頭の conv と SN 付き残差 conv の初期値（anet は he = kaiming_normal・fan_out、BTR は PyTorch 既定。標準偏差は anet が 0.87〜2.45 倍、bias は anet が 0）。τ の埋め込みの初期値（anet は xavier、約 0.4 倍） |
| 違い（計算の差） | Munchausen の追加項の log π（anet は target ネット、BTR は online ネット）。学習の精度（anet は BF16、BTR は FP32）。最後の pool（anet は MaxPool2d 窓 2・刻み 2・余白 1、BTR は AdaptiveMaxPool2d(6)）。PER に書き戻す優先度（anet は期待値どうしの差の絶対値、BTR は量子のペアごとの TD の絶対値の平均） |
| 違い（小さい） | 学習時の online ネットの雑音の引き直し、SN の反復の回数、target のコピーの 1 更新のずれ、先読みによる優先度の 1 更新の古さ、打ち切り時の γ^n |

SN 付きの層は出力が重みの大きさに依らない。一方 Adam の 1 回の更新幅は重みの大きさに依らないので、初期値が 2.45 倍大きいと、1 回の更新で重みが変わる割合が約 0.4 倍になる。
これを初期値で確かめる腕と、Munchausen の log π を合わせた腕を、btreps の設定から 10M 回した。

### 結果

**初期値を PyTorch の既定に戻すと、評価は BTR の帯に入った。**

| Run | 0-2.5M | 2.5-5M | 5-7.5M | 7.5-10M | ε=0 の評価（5.25M、100 本） |
|---|---:|---:|---:|---:|---:|
| BTR r0 / r1 | 799 / 531 | 5,303 / 3,916 | 10,766 / 9,651 | 14,858 / 14,423 | — |
| btreps（従来の初期値） | 482 | 2,404 | 5,544 | 10,065 | 3,994 |
| aln_init（初期値） | 528 | 4,644 | 11,450 | 14,918 | 7,865 |
| aln_im（初期値 + Munchausen online） | 568 | 4,392 | 11,313 | 13,778 | 8,392 |

- 5-7.5M の 11,450 と 11,313 は、探索ブロック 05 の anet の Run の最高（8,675）を大きく超える。
- Munchausen online を足した aln_im は、2.5M 以降の 3 窓とも aln_init を上回らなかった（差は 252・137・1,140）。
- btrpa の ε=0 の評価（5.25M）は 4,273 だった。

## 探索ブロック 07: 実時間優先の構成で初期値を戻す

### 探索観点

実時間優先の構成（[2026-09-21](2026-09-21_realtime-profile-atari5.md)。RR1、128 env / 2M、ラダー 0.4〜0.01）は残差ブロックに SN を持たず、胴体の後ろに `AtariLinear512 > AtariLN512` を置く。
LayerNorm も手前の層の重みの大きさを打ち消すので、PyTorch 既定より大きい初期値の層を既定に戻した。
対象は先頭の conv（he）、残差の 1 本目の conv（he）、`AtariLinear512`（xavier）、τ の埋め込み `AtariIQNTauProj512`（xavier）。残差の 2 本目の conv は 0 から始まる既定のまま。
Run は `run_20261025-224454_a5_qb_rt_aln_s1`（seed 1、10M、2026-10-25 の実行ファイル、LunarLander の Run と並列）。
`run_20260923-163113_a5_qbert_rr1_100m_seed2` との実効 config の差は、初期値、seed、ε=0 の評価の間隔、device 指定の書き方、既定値の追加（`force_fp32` など）だけ。

## 探索ブロック 09: 第 9 面で終わるゲームの点と長さ（train）

- 新しい Run は流していない。aln_btreps はゲームごとの trace（`42_env/episode`）、BTR は Run 形式に変換したゲームごとの値（`42_env/10_game_score_mean` と `42_env/50_ram_metric_1_mean` を同じ step で組にした）から数えた。
