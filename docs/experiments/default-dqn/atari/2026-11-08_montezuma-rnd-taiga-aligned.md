## 目的と比較条件

Montezuma で、サンプル効率優先の構成を Taiga ら（ICLR 2020）の Rainbow＋RND の条件へ寄せた構成に RND を載せ、30M までの到達を測る。あわせて、RND の式（anet の既定と Taiga らの式）、β（0.1 と 0.01）、Munchausen（有効と無効。無効のときは Double DQN を有効）を変えて、Greedy で 2500 点に届くかを比べる。

- 共通の構成: サンプル効率優先のチェーンに、Taiga ら寄せの Q 側（replay ratio 8、target の hard update 250 learn step、PER α 0.5・β 0.5）と、RND の補助学習（`learn_ratio` 1、`learn_batch_size` 128）を足した。BTR の NN（Impala の conv の初期値は既定）、128 env、replay 2,097,152、γ 0.997、n-step 3、IQN（τ 32 本）、学習率 1e-4、replay batch 256。sticky 0.25、打ち切り 108,000 フレーム、ライフ区切りなし。予算 30M（exp step）、seed 1。
- Train Actor の探索: lane ごとの ε ラダー（0.4〜0.01、log）と UQE（ε 0.05）。lane と ε の割り当ては逆順で、lane 0 が 0.01、lane 127 が 0.4。下の lane の群は、lane 0〜42 が ε 0.01〜0.034、43〜85 が 0.034〜0.12、86〜127 が 0.12〜0.4。
- RND（anet の既定の式）: `clipped`・`whiten`、倍率の上限 5（1 step の内的報酬は β × (α − 1) で、α − 1 は 0〜4）、採点は次観測、出力 512、warm-up 12,800、predictor の学習率 1e-4。
- RND（Taiga らの式、`run.@rnd_taiga`）: β 5e-05、`unclipped`・`variance_feedback`、採点は行動した観測、`learn_batch_size` 1、warm-up 0、Adam の ε 1e-5。
- Munchausen: α 0.9。無効にした群は Double DQN を有効にした（taiga_nm を除く）。
- 評価: `[eval]`（`52_eval2`）は ε=0.01、10 ゲーム、62,528 learn step ごと（約 2.0M）。`[greedy]`（`53_evalg`）と `[greedy_single]`（`54_evalgs`）は ε=0・τ 固定、16 ゲーム、31,250 learn step ごと（約 1.0M）で、同じ設定の別 session。
- 得点: 鍵 100、扉 300、剣 100、剣で敵を倒す 2,000。400 点は鍵と扉 1 枚、500 点はそれに剣、2500 点はそれに剣での撃破（下の「Run 以外の確認」）。部屋は RAM の指標 1（`room_max`、そのゲームで入った部屋番号の最大。開始の部屋は 1、その左は 0）。
- 値の出どころ: 評価と学習側のゲームは metrics の episode trace（`53_evalg`・`54_evalgs`・`52_eval2`・`42_env`）。2M 窓の 2500 点の本数と、扉の向きはログの Game 行（400 点以上で `room_max` 1 なら左の扉、2 以上なら右の扉）。指標の平均は `metrics_cache.db`（走行中の b01 は `metrics.jsonl`）。

Taiga ら（ICLR 2020、[arXiv 2109.11052](https://arxiv.org/abs/2109.11052)）の Rainbow＋RND は、Montezuma の 5 seed すべてが 90M フレームまでに 4,400 点を超えた（図 7 を目で読んだ値）。NoisyNets の 5 seed は 35〜40M フレームから 200M フレームまで 2500 点だった。表 5 の 200M フレームの値は RND 5,199、ε-greedy 780。本記録の 30M exp step は 120M フレーム。
