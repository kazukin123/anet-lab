## 目的と比較条件

Montezuma で、サンプル効率優先の構成を Taiga ら（ICLR 2020）の Rainbow＋RND の条件へ寄せた構成に RND を載せ、30M までの到達を測る。あわせて、RND の式（anet の既定と Taiga らの式）、β（0.1・0.01・0.003）、Munchausen（有効と無効。無効のときは Double DQN を有効）、外的と内的の価値の分け方を変えて、Greedy で 2500 点に届くかを比べる。

- 共通の構成: サンプル効率優先のチェーンに、Taiga ら寄せの Q 側（replay ratio 8、target の hard update 250 learn step、PER α 0.5・β 0.5）と、RND の補助学習（`learn_ratio` 1、`learn_batch_size` 128）を足した。BTR の NN（Impala の conv の初期値は既定）、128 env、replay 2,097,152、γ 0.997、n-step 3、IQN（τ 32 本）、学習率 1e-4、replay batch 256。sticky 0.25、打ち切り 108,000 フレーム、ライフ区切りなし。予算 30M（exp step）、seed 1（略称が `_s2` で終わる Run は seed 2）。Taiga ら寄せの基準の 2 本（rbw_tg・rbw_tg_s2）は、この共通の構成を使わない（下の群の表）。
- Train Actor の探索: lane ごとの ε ラダー（0.4〜0.01、log）と UQE（ε 0.05）。lane と ε の割り当ては逆順で、lane 0 が 0.01、lane 127 が 0.4。下の lane の群は、lane 0〜42 が ε 0.01〜0.034、43〜85 が 0.034〜0.12、86〜127 が 0.12〜0.4。
- RND（anet の既定の式）: `clipped`・`whiten`、倍率の上限 5（1 step の内的報酬は β × (α − 1) で、α − 1 は 0〜4）、採点は次観測、出力 512、warm-up 12,800、predictor の学習率 1e-4。
- RND（Taiga らの式、`run.@rnd_taiga`）: β 5e-05、`unclipped`・`variance_feedback`、採点は行動した観測、`learn_batch_size` 1、warm-up 0、Adam の ε 1e-5。
- Munchausen: α 0.9。無効にした群は Double DQN を有効にした（taiga_nm を除く）。
- 評価: `[eval]`（`52_eval2`）は ε=0.01、10 ゲーム、62,528 learn step ごと（約 2.0M）。`[greedy]`（`53_evalg`）と `[greedy_single]`（`54_evalgs`）は ε=0・τ 固定、16 ゲーム、31,250 learn step ごと（約 1.0M）で、同じ設定の別 session。
- 得点: 鍵 100、扉 300、剣 100、剣で敵を倒す 2,000。400 点は鍵と扉 1 枚、500 点はそれに剣、2500 点はそれに剣での撃破（下の「Run 以外の確認」）。r123 では、倒すと 3,000 点の敵（EvalPanel では部屋 13 の蜘蛛）と、2 本目・3 本目の鍵（100 点ずつ）も入った（探索ブロック11・12）。部屋は RAM の指標 1（`room_max`、そのゲームで入った部屋番号の最大。開始の部屋は 1、その左は 0）。
- 報酬: `AtariEnv.reward_clip = true` で、点が入るたびに学習の報酬は +1（点の大きさは効かない）。1 ゲームの報酬は、点から次のとおり決まる。400 点 2、500 点 3、2500 点 4、2600 点 5、2700 点 6、3500 点 4、3600 点 5、3700 点 6、5600 点 8。この対応で数えた ε=0.01 の評価の平均報酬は、延長の 9 回とも Run が記録した値（`21_eval/02_policy_reward`）と一致した（探索ブロック14）。学習の報酬には、ほかに RND の内的報酬が step ごとに足される。
- 値の出どころ: 評価と学習側のゲームは metrics の episode trace（`53_evalg`・`54_evalgs`・`52_eval2`・`42_env`）。2M 窓の 2500 点の本数と、扉の向きはログの Game 行（400 点以上で `room_max` 1 なら左の扉、2 以上なら右の扉。r123・r123_s2・延長は `42_env` の trace から数えた）。指標の平均は `metrics_cache.db`（b01 は走行中に `metrics.jsonl` から集計した。r123_s2 と延長は `metrics.jsonl` から）。
- メイン機（RTX 5090）。rbw_tg_s2 だけサブ機（RTX 4060）。
