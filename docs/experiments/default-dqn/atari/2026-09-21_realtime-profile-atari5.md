## 現時点のまとめ

1. **実時間優先プロファイルの Atari-5 median は 358.0% HNS（eval2 40-50M 窓）、Atari-5 回帰で 344.8%。**
   `2026-08-27` の初回スイープ 20M（median 55.4%）から **6.7 倍**。ただし **4/5 ゲームが 40-50M で上昇中**で、
   50M はこの構成には短い（探索ブロック 01）。

2. **double_dunk と phoenix に 25M 前後の相転移がある。** double_dunk の ε=0 断面は
   `−1 −1 −1 −1 −0` から `11 14 17 18 17` へ、phoenix は 48,298 → 143,421 へ 1 点で跳ぶ。
   `2026-08-27` の 20M スイープで double_dunk が −143% だったのは、相転移の手前で切っていたため（探索ブロック 01）。

3. **BTR との差は 2 ゲームに集中している。** BTR の集計方法（学習中の最良・100 エピソード × 3 seed）へ
   揃えると Atari-5 で **370.7 対 555.2 = 66.8%** だが、内訳は battle_zone 66.9% / double_dunk 87.2% /
   name_this_game 80.1% に対し **phoenix 36.2% / qbert 57.0%**。全面的な劣位ではない（探索ブロック 01）。

4. **eval が消費した env step は train 予算の 83%。** 5 本合計で greedy_dist 155.0M / eval2 53.8M に対し
   train 250M。double_dunk は **133%** で学習より評価のほうが多い。**ゲーム間の実効スループット差
   （3,049〜5,343 exp/s）はほぼ全部この eval 負荷**で、清浄値（peak 8,107〜10,930）は揃っている（探索ブロック 01）。

5. **`replay_capacity` 2M → 4M（lane 窓 16,384 → 32,768）は RR1 + 旧 net では効かない。**
   name_this_game で機構は完全に作動した（`46_agent_replay_fit` の age / count が **+98〜102%**）が、
   evalg 共有 8 点で **−2.2%**（1σ 内）、eval2 40-50M −2.5%、train −1.8%。
   **比率が一切動かない** — 未サンプル割合 56.0% → 55.5%、`03_unsampled_td_ratio` 1.019 → 1.016、
   `07_evicted_unsampled_ratio` 0.2731 → 0.2668。W/L は 1.67 → 3.30 で Breakout の 2.11 を跨いでいる（探索ブロック 02）。

6. **`2026-09-15` の lane 窓の結果とは 3 軸が同時に違う。** あちらは **RR4 + btrsn12 + Pool6 + 融合 2304**
   で取った値（config 複製 8 本すべて `rr4_btrsn12` / `rr4_btrfull`）。同じ lane 移動でも
   **ゲーム・RR・net が同時に違う**ため、効かない原因は分離できていない。「ゲーム横断で一般化しない」とは言えない（探索ブロック 02）。

7. **旧 net への `AtariPool4` 投入は成績で明確に負ける。** qbert 20M の A-B-A-B（腕内 2 本ずつ）で、
   15-20M の eval2 は base 15,720 / 14,550 に対し pool4 10,830 / 8,550 と**重なりがゼロ**。
   train EMA 18-20M・evalg @15.4M も同様に重ならない。差は eval2 15-20M で **−36.0%**、train EMA で −27.1%。
   `q_gap` −19.4%（対ブレ幅 3.32 倍）・`q_max` −25.5% で、容量不足の署名（探索ブロック 03）。

8. **`AtariLinear512` の入力を 7,744 → 1,024 に落としても実時間は改善しない。**
   最大層のパラメータが 3.96M → 0.52M になるが、総実時間は base 0.895h 対 pool4 0.928h。
   pool4 腕自身のブレが 11.4% あるため「利得は確認できなかった」までが言える（探索ブロック 03）。

9. **qbert 20M の複製幅は予算とともに縮む。** eval2 の腕内差は 0-5M で 49〜74%、10-15M で 33〜58%、
   **18-20M で 8〜25%**。train EMA は 18-20M で 7〜16%。**中間窓は腕を判定できないが、終端窓は判定できる**（探索ブロック 03）。

10. **eval 予算の内訳は greedy_dist が支配する。** 5 本で greedy_dist 155.0M 対 eval2 53.8M の **2.9 倍**、
    発火回数は 10 対 199 と逆。**`eval_episodes` を 400 → 100 にすると 155.0M → 38.8M** になる。
    ev Run（固定方策 × 5 セッション × 100 エピソード）で測った 100 本のセッション間 CV は
    name_this_game 0.46% / double_dunk 0.47% / qbert 1.36% / **battle_zone 4.32% / phoenix 5.26%**（HNS 空間、探索ブロック 01）。

11. **eval の lane 数を増やしても総仕事量は変わらない。** name_this_game の ev Run で
    `eval_batch_size` 16 → 128（8 倍）に対し実時間は 1.27 倍（14m45s → 11m36s）、成績は −0.26% で同じ。
    **8 コアで 16 lane が既にほぼ飽和**しており、残りは小バッチ GPU forward のレイテンシ・スラック（探索ブロック 01）。

## 探索ブロック 01: Atari-5 実時間優先 50M 横断

### 探索観点

`2026-09-12` で Breakout に確定した実時間優先プロファイル（旧 net + RR1 + hard C=125）に
Munchausen と `replay_fit` を載せ、Atari-5 の 5 本を 50M（= 200M frames）で横断する。
`2026-08-27` の初回スイープ（20M / soft τ 誤設定）からの更新値を取る。

`metrics.scalar.$` から Breakout 固有の閾値率（`ge432` / `ge600`）を落とす `run.@a5_metrics` を導入した。
5 本すべてで該当タグの出力行は 0 である。

### 探索結果

**Atari-5 median は 358.0%、回帰値は 344.8%。**

|---|---:|---:|---:|---:|---:|---:|

| double_dunk | −21.1 | −13.3 | 6.9 | 14.7 | 17.1 | 1,621.9% |
| phoenix | 12,037.9 | 51,360.0 | 85,581.7 | 104,293.4 | 114,158.6 | 1,749.6% |

`52_eval2/10_game_score_mean`（ε=0.01 / 10 エピソード）の 10M 窓平均。

こちらも max へ揃える。HNS の正規化定数は `AtariEnv.cpp` の 57 ゲーム表と BTR 側が一致する
（double_dunk の random だけ −18.6 対 −18.55 の丸め差）。

| ゲーム | BTR hns% | 本記録 evalg max hns% | 比 |
|---|---:|---:|---:|
| battle_zone | 476.6 | 318.6 | 66.9% |
| double_dunk | 1,932.6 | 1,684.9 | 87.2% |

| phoenix | 6,584.0 | 2,382.7 | **36.2%** |
| qbert | 321.7 | 183.3 | **57.0%** |

**負けは phoenix と qbert の 2 ゲームに集中している。** 他の 3 本は 80〜91%。

`52_eval2` の max（10 エピソード × 199 セッション）で揃えると 450.0 = 81.1% になるが、
1 セッションあたりの本数が BTR の 1/10 なので max バイアスが強く、evalg 側の 66.8% を読む。

こちらは 1 seed、BTR は 3 seed。またこちらは sticky 0.25 を踏んでいる。

### eval の本数と lane 数

学習を止めた ev Run（`run.@evalonly > run.@eval2only > run.@greedy_eval`、固定方策 × 5 セッション × 100 エピソード）で
セッション間のばらつきを測った。HNS 空間の CV。

| ゲーム | 100ep の CV | 400ep 相当 |
|---|---:|---:|
| name_this_game | 0.50% | 0.25% |
| double_dunk | 0.47% | 0.24% |
| qbert | 1.36% | 0.68% |
| battle_zone | **4.32%** | 2.16% |
| phoenix | **5.26%** | 2.63% |

**必要精度とコストが逆相関している。** evalg env step が最大の double_dunk（58.1M）は CV 0.47% で最小、
最小の battle_zone（10.4M）は CV 4.32% で最大。

`eval_batch_size` の A/B（name_this_game、100 エピソード × 5 セッション）。

| | mean | sd | hns% | 実時間 |
|---|---:|---:|---:|---:|
| lane 16 | 23,827.7 | 199.0 | 374.09 | 14m45s |
| lane 128 | 23,766.6 | 96.9 | 373.03 | 11m36s |

**成績は −0.26% で同じ、実時間は −21%。** ただし lane を 8 倍にして 1.27 倍にしかならない。
100 エピソードの総 env step は lane で変わらず、**8 コア / 16 スレッドの環境で 16 lane が既にほぼ飽和**している。

## 探索ブロック 02: `replay_capacity` 4M の他ゲーム展開

### 探索観点

`2026-09-15` で Breakout に確認された「lane 窓 32,768 は 16,384 より ε=0 断面で +42.4 ± 10.8」が
他ゲームでも成立するか。name_this_game は Atari-5 で W/L が最小（1.7）で、最も効くはずの球である。

対照は `run_20260921-213901_a5_name_this_game_rr1_50m`。実効 config の差分は
`app.run_name` を除いて **`DefaultDQNAgent.learner.replay_capacity` の 1 キーのみ**。

### 探索結果

**機構は完全に作動した。** `46_agent_replay_fit`（learn_step 軸、終盤 20%）。

| metric | cap2m | cap4m | delta |
|---|---:|---:|---:|
| `23_unsampled_age_mean` | 6,469 | 12,880 | **+99.1%** |
| `24_sampled_age_mean` | 10,390 | 20,760 | **+99.9%** |
| `21_unsampled_count` | 1.174M | 2.328M | **+98.3%** |
| `22_sampled_count` | 0.922M | 1.865M | **+102.3%** |

W/L は greedy L 基準で **1.67 → 3.30**。Breakout の 2.11 を跨いでいる。

**成績は動かなかった。** ε=0 断面（400 エピソード）の全点。

```
cap2m   9点  0 11,797 14,288 18,714 19,927 21,631 22,335 22,809 22,374
cap4m  10点  0 11,314 15,728 18,037 19,824 20,285 21,125 21,529 21,854 22,508
```

共有 8 点の差は −4.1 / +10.1 / −3.6 / −0.5 / −6.2 / −5.4 / −5.6 / −2.3、**平均 −2.2%** で 8 点中 6 点が負。

| 40-50M 窓 | cap2m | cap4m | delta |

| `52_eval2/10_game_score_mean` | 22,900 | 22,390 | −2.2% |

`03_unsampled_td_ratio` 1.019 → 1.016、`39_agent_per/07_evicted_unsampled_ratio` 0.2731 → 0.2668。
**倍になって構成は相似のまま**である。

学習信号自体は動いている（`q_max_mean` 35.06 → 31.69 の −9.6%、`q_gap` 0.2289 → 0.2673 の +16.8%）が、
成績が追随しなかった。

### 留保

**`2026-09-15` とは 3 軸が同時に違う。**

| | `2026-09-15` の lane 実験 | 本ブロック |
|---|---|---|
| lane 窓 | 16,384 → 32,768 | 16,384 → 32,768 |
| `replay_ratio` | **4** | **1** |
| net | **btrsn12 + Pool6 + 融合 2304** | **旧 net + trunk LN512 + 融合 512** |
| ゲーム | **breakout** | **name_this_game** |

lane の動かし方だけが同じで、**ゲーム・RR・net が同時に違う**。効かない原因は分離できていない。

**バイナリも異なる。** 対照は 2026-09-21 21:39 の実行で、PRD 076 の排水を入れたビルドより前である。
**ε=0 断面が 9 点 → 10 点になっている**のがその差の現れで、最終セッションが捨てられなくなった。
訓練経路は変わらないはずだが、完全な同一条件ではない。

**seed は 1 本ずつ。** −2.5% はこのゲームの複製幅を持たないため、
「改善しなかった」は言えるが「悪化した」は言えない。ただし `2026-09-15` の Breakout の利得を
% に直すと ev 終端 +4.5% / ε=0 9 点ペア +6.2% であり、
1 点あたり複製幅（sd 44 ≈ 6.4% 相当）から 8 点平均の標準誤差を 2.3% 相当と置くと、
実測 −2.2% は 1σ 以内、Breakout 並みの効果との差は 2.9〜3.7σ になる。
**Breakout 並みの効果があれば検出できたはず**という水準ではある。

### 実時間

総実時間は 4.36h → 4.16h（−4.6%）。ただし実行時刻が深夜と日中で異なり、
実験機のドリフト（±8%/h）の内側なので読まない。

## 探索ブロック 03: 旧 net への `AtariPool4` 投入

### 探索観点

`2026-09-12` で btrnet の RR4 上に測られた「`AtariPool6` 単独が +55.1 で最大寄与、
6×6 は内点ではなく 4×4 がさらに +25.8」が、実時間優先プロファイルの旧 net でも成立するか。

旧 net（`@AtariImpalaX2LN`）は `… ReLU > Flatten > AtariLinear512 > AtariLN512 > ReLU` で、
Flatten の入力が 11×11×64 = 7,744。ここへ `AtariPool4` を 1 個挟むと 4×4×64 = 1,024 になり、
`AtariLinear512` のパラメータが 3.96M → 0.52M へ落ちる。融合次元は trunk 出力の 512 のままなので
`@iqn` の差し替えは不要。差分は `net.branch.[main_feature].structure` の 1 箇所だけ。

qbert 20M を A-B-A-B（base / pool4 / base / pool4）で回し、腕内 2 本ずつで複製幅も同時に取る。
`backend.deterministic_algorithms = false` なので同一設定でも結果は異なる。

### 探索結果

**15-20M で 3 チャネルとも重なりがゼロ。**

| チャネル | base_r1 | base_r2 | pool4_r1 | pool4_r2 |
|---|---:|---:|---:|---:|
| `52_eval2` 15-20M | 15,720 | 14,550 | 10,830 | 8,550 |
| `42_env` EMA 18-20M | 9,450 | 8,782 | 7,226 | 6,141 |
| ε=0 断面 @15.4M | 14,866 | 13,521 | 6,583 | 7,939 |

base の最小値が pool4 の最大値を上回る。ε=0 断面（100 エピソード）では **1.7〜2.3 倍**の差。

| 窓 | base 平均 | pool4 平均 | 差 | 対ブレ幅 |
|---|---:|---:|---:|---:|
| `52_eval2` 15-20M | 15,135 | 9,690 | **−36.0%** | 1.53× |
| `52_eval2` 18-20M | 14,940 | 10,390 | −30.5% | 1.20× |
| `42_env` EMA 15-20M | 8,617 | 6,278 | **−27.1%** | 1.69× |
| `42_env` EMA 18-20M | 9,116 | 6,684 | −26.7% | 1.64× |

機序も揃っている。15-20M で `q_max_mean` −25.5%（対ブレ 1.48×）、
**`q_gap` −19.4%（対ブレ 3.32×）**。価値関数が小さく、行動間の差が狭く、成績が低い。

**実時間の利得は確認できなかった。** base 平均 0.895h 対 pool4 平均 0.928h。
pool4 腕自身のブレが 11.4% あるため符号は判定できない。
最大層のパラメータ削減（3.96M → 0.52M）はこの構成では実時間へ効かない。

### 複製幅は予算とともに縮む

同一設定 2 本の腕内差。

| 窓 | eval2 | train EMA |
|---|---:|---:|
| 0-5M | 49〜74% | 24〜49% |
| 5-10M | 11〜46% | 13〜38% |
| 10-15M | 33〜58% | 13〜47% |
| **18-20M** | **8〜25%** | **7〜16%** |

**中間窓は腕を判定できない。** 0-10M の共通区間では pool4 が base 平均に対し
+24.1% / +8.2%（eval2）と正側にいるが、いずれも対ブレ幅 0.18〜0.45 倍で内側にある。
**判定は終端窓（18-20M）で行う。**

`q_gap` も窓で解像度が違う。5-10M の腕内差は base 5.1% / pool4 20.0% で差 +7.2% は内側（0.36×）、
15-20M では base 4.1% / pool4 5.9% で差 −19.4% が 3.32 倍外にある。**符号が窓で逆転する。**
