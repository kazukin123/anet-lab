## 現時点のまとめ

1. 同一のB256/RR1、`alpha=1e-4`、PER alpha 0.2、initial priority fixed 0.3、`use_optimistic_target=false`で、IQN32 randomとQR51の100M scratch比較が成立した。実効設定差はquantile modeとそれに伴うhead / tau経路が中心である。
2. 90–100MのQR51はEval target reward EMA約1629、Policy reward EMA約1584で、IQNの約1508 / 1398をそれぞれ約8.1% / 13.4%上回った。QRは序盤から優位で、IQNが20–40Mに一度接近した後、40M以降に再び差が開いた。
3. QR51の90–100M target rewardは過去B128/RR1.25 QRの約1628と同水準であり、B256/RR1は100M品質を保ちながら終盤throughputを約3822 exp/sまで上げた。IQNは約3518 exp/sで、QRが約8.6%高速だった。
4. QR / IQNともQ、TD、loss、gradient、PERは安定し正常closeした。差は単純な発散ではなく、現在のDropMergeではrandom tau IQNのsample efficiencyがQRより低いという観測である。ただしnon-deterministic backendの各1 Runであり、因果確定や最終汎化性能の優劣とはしない。
5. QR51のPRD048診断ではquantile crossing約36%、lower-risk/full-Q不一致約60%、upper-tail/PER priority Spearman約0.62だった。期待値成績は有効だが、tailを整列した分位関数として読む信頼性は低く、今後のstratified IQNでもcrossingを先に確認する。
6. 20Mのtau sampling比較ではstratified / antitheticがrandomを上回り、systematicはrandom同等、fixedは10M以降に停滞した。seed 2再現でも両finalistの改善は維持され、tau sampling改善は単発上振れだけでは説明しにくい。

## 探索ブロック 01: IQN 32/32 の初期成立性と QR51 比較

**記録時点:** 2026-08-09、約 72M 時点
**状態:** completed / 正常成立、QR51のsample efficiencyには未達
**確度:** medium-low、single-seed、比較契約に差あり

### 探索観点

LunarLander で成立確認した IQN を DropMerge の既存 QR 長期ラインへ移し、学習成立、sample efficiency、Q 分布、PER、NEET、throughput を確認する。

### 探索結果

60–72M の同一 exp-step window では、IQN は QR51 baseline より遅かった。

| 指標 | IQN | QR51 | 差の概略 |
|---|---:|---:|---:|
| Eval target reward EMA 平均 | 約 1294 | 約 1605 | IQN 約 -19% |
| Eval policy reward EMA 平均 | 約 1220 | 約 1542 | IQN 約 -21%。policy 意味差あり |
| Eval1 max-rank EMA | 約 10.13 | 約 10.53 | IQN が低い |
| Eval2 max-rank EMA | 約 10.04 | 約 10.46 | IQN が低い |
| Double Suika | 両 Eval 0 | QR Eval2 で少数 | IQN は未到達 |
| throughput | 約 2303 exp/s | 約 2525 exp/s | IQN 約 -9% |

同じ wall-clock では QR がより多い exp-step へ到達するため、実時間差を含む性能差はさらに大きい。

### 成立性

- stderr は空で、NaN、OOM、持続的 loss / TD / Q 発散はない。
- 60–73M の `q_std` は IQN 約 0.039、QR 約 0.038 で、分布 collapse はない。
- PER unsampled eviction は両者とも約 20%で、IQN 固有の Replay coverage 破綻は見えない。
- Q 値の過渡変動はあるが、50M 以降は TD error、loss、grad norm とともに安定した。

### 比較上の制約

- QR baseline は QR51、IQN は N/M=32/32 であり、quantile 数と head parameterization が一致しない。
- IQN Eval2 は tail mean score を使う。古い QR artifact の Eval policy と意味が完全一致しない。
- 同じ seed でも NN 構造と乱数消費列が違うため、軌道一致は期待しない。

この Run から言えるのは「現在の IQN32/32 構成は歴史的 QR51 baseline より遅い」までであり、IQN 一般が QR より劣るとは結論しない。

## 探索ブロック 02: ReplayBuffer 満杯境界と Q 値遷移

**記録時点:** 2026-08-09
**状態:** completed / 満杯境界主因説を棄却
**確度:** medium

### 探索観点

LunarLander では ReplayBuffer が grow-only から overwrite へ切り替わる境界で Q、loss、grad、reward が同時に変化した。DropMerge の 30–50M Q 遷移も同じ機構かを確認する。

### 境界計算

```text
ReplayBuffer 満杯              = 524,288 exp-step
warmup 経験の overwrite 開始  = 524,288 exp-step
warmup 経験の完全 overwrite    = 524,288 + 25,600
                              = 549,888 exp-step
```

256 env 換算では、warmup 終了が train step 100、満杯が 2,048、warmup 経験の完全忘却が 2,148 である。

### 満杯直前・直後

| 区間 | `q_max_real_max` | TD mean EMA | Eval target reward EMA |
|---|---:|---:|---:|
| 0.450–0.525M | 1.93 | 0.02425 | 563.9 |
| 0.525–0.600M | 2.26 | 0.02409 | 564.5 |

Q は滑らかに増えており、TD error と reward に急変はない。QR baseline も同様だった。

### 判断

30–50M の Q 遷移は、満杯境界から約 40M 遅れている。Replay 内の経験分布は方策成長に伴って満杯後も変わり続けるため間接影響は否定しないが、LunarLander と同じ満杯時点の相転移ではない。

## 探索ブロック 03: Q 値バブルと一時的 NEET

**記録時点:** 2026-08-09
**状態:** active hypothesis
**確度:** medium、強い時系列相関はあるが介入実験なし

### Q 値の推移

| exp-step | `q_sa_real_mean` | `q_max_real_max` | TD mean EMA | Eval target reward EMA |
|---|---:|---:|---:|---:|
| 10–20M | 8.50 | 15.57 | 0.0301 | 890 |
| 20–30M | 9.35 | 18.54 | 0.0364 | 1076 |
| 30–40M | **14.15** | **28.50** | **0.0412** | 1138 |
| 40–50M | 11.70 | 24.09 | 0.0405 | 1214 |
| 50–60M | 8.19 | 13.00 | 0.0315 | 1266 |
| 60–73M | 8.27 | 12.98 | 0.0311 | 1294 |

約 39.75M で `q_max_max=4.93`、`q_max_real_max=30.61` に達した。単発スパイクではなく、`q_sa_real_mean` も上昇したため、価値分布全体の広い Q 水準変化である。

Q が約半分へ下がる一方で Eval reward は上昇した。高い Q が性能向上を表したのではなく、一時的に膨らんだ価値尺度を実リターンへ再較正したと解釈する。

### NOOP 優位との同期

NOOP EMA 系 metric は `$exp_step`を指定しておらず、artifact 上の step 軸は train step である。以下は `num_envs=256` を掛けて exp-step へ換算した。

| exp-step | Eval1 NOOP 優位率 EMA | Eval2 NOOP 優位率 EMA | `q_sa_real_mean` |
|---|---:|---:|---:|
| 30–32M | 2.8% | 3.3% | 13.3 |
| 34–36M | 21.8% | 17.2% | 14.5 |
| 36–38M | **48.0%** | **30.8%** | 14.0 |
| 40–42M | 14.6% | 0.2% | 13.9 |
| 44–46M | 10.6% | 1.1% | 12.0 |
| 46–48M | 0.3% | 0.4% | 10.4 |
| 50–52M | 0.1% | 2.6% | 8.1 |

NOOP margin の区間平均は負を維持したため、全状態で強い NOOP 優位になったわけではない。NOOP と DROP が近い状態で順位が広く揺れたと考える。

Eval episode step EMA は 32–34M の約 563 / 496 から、52–54M の約 250 / 243 へ短縮した。max rank と fruit count が維持され、reward は上昇しているため、単なる早期 GameOver より待機行動の減少と整合する。

NoDrop timeout 終端は NOOP 優位期に張り付かなかった。100 step 連続 NOOP する単純 NEET ではなく、タイムアウト前に DROP を混ぜる一時的な待機方策だった可能性がある。

### 機構仮説

`gamma=0.997`、n-step 1 では、NOOP に近い自己遷移の 1-step Bellman 差は小さい。Q(NOOP) が近傍 DROP をわずかに上回ると、NOOP 経験が Replay へ増え、bootstrap により近い価値を自己維持しやすい。

一方、100 step 待つ割引は `0.997^100 ≈ 0.74` であり、本来は長期的に不利である。長い待機軌跡と後続の失敗が Replay に十分蓄積されると、n-step 1 で遅れて不利が伝播し、NOOP 順位と Q 水準がともに訂正されたと考える。

この仮説では、IQN が NEET を新設したのではなく、既存の NOOP 近傍不安定性を大きな Q 値バブルへ増幅したことになる。

## 探索ブロック 04: QR から IQN への変更が Q 応答を増幅する理由

**記録時点:** 2026-08-09
**状態:** active hypothesis
**確度:** medium-low、LunarLander と DropMerge の cross-Env 傾向あり

### 観測事実

- 過去の QR でも一時的 NEET スランプはあったが、Q 全体の明瞭な山として記憶・記録されていない。
- DropMerge IQN では NOOP 順位だけでなく learner の平均 Q 水準も上昇した。
- LunarLander でも IQN 化後に Q、loss、grad の変化が QR より大きく見える傾向があった。

### IQN 固有の増幅候補

1. **train-policy の tail tau sampling**
   QR は固定 quantile 出力の上側を評価する。現在の IQN train policy は actor ごとの上側 tau 範囲から 32 点を毎 forward ランダム生成する。NOOP と DROP が近い状態では、train 時の順位が QR より揺れやすい。
2. **learner target の Monte Carlo 分散**
   IQN learner は current N=32 と target M=32 を毎 update 独立にランダム生成する。target action は deterministic Greedy だが、選択 action の target value には M=32 の Monte Carlo 分散が残る。
3. **tau 条件付き共有表現**
   IQN は `main_feature * tau_embedding` を head へ流し、quantile 間で表現を共有する。共有 value 表現がずれると、多数の tau と全 action の基準値が同方向へ動きやすい。
4. **Replay feedback**
   tail score の小さな順位誤差が NOOP 経験分布を変え、その変化が learner の全域平均 Q まで押し上げる。引き金と平均 Q バブルは別段階と考える。

learner の `37_agent_qtd/*` は全域 tau を使った平均 Q である。したがって 30–40M の広い Q 山は、Eval UQE tail score の表示だけでは説明できない。random 32 点による瞬間ノイズも、10M 規模の平均変化に比べて小さい。

### LunarLander との統合解釈

- LunarLander の引き金: ReplayBuffer 満杯・初期経験 overwrite に伴う経験分布切替が有力。
- DropMerge の引き金: NOOP 近傍の方策自己強化が有力。
- 共通の増幅器: IQN の stochastic tau と共有 quantile function が、経験分布変化に対する Q 応答を大きくする可能性。

cross-Env の方向は一致するが、まだ各 single-seed であり一般則とはしない。

## 探索ブロック 05: IQN fixed-grid control

**記録時点:** 2026-08-13、20M close後
**状態:** completed / fixedは10M以降に停滞。詳細は探索ブロック07
**確度:** medium、同一seedだがnon-deterministic backendの単一Run

### 探索目的

長期の IQN ハイパラ探索へ入る前に、tau sampling を決定論的な`fixed`へ寄せた IQN が QR に近い傾向を再現するか確認する。

`train_policy.tau_rule.sample_mode=fixed` だけを変える診断は、train action score の Monte Carlo 揺れだけを外す。learner current / target が random のままなので、QR 近似 IQN とは区別する。

### config-only で作れる deterministic-grid IQN

最小の 32/32 control:

```ini
DefaultDQNAgent.learner.iqn.current_taus.num_taus = 32
DefaultDQNAgent.learner.iqn.current_taus.sample_mode = fixed
DefaultDQNAgent.learner.iqn.target_taus.num_taus = 32
DefaultDQNAgent.learner.iqn.target_taus.sample_mode = fixed
DefaultDQNAgent.train_policy.tau_rule.num_taus = 32
DefaultDQNAgent.train_policy.tau_rule.sample_mode = fixed
```

Eval と target policy は現在も fixed である。比較時は artifact で再確認する。

### QR 等価性の限界

fixed にすると learner の積分点と target が等間隔の中心へ固定され、QR の固定分位グリッドへ近づく。しかし次は残る。

- QR は固定 quantile 出力、IQN は tau embedding を通す共有関数であり、parameterization と gradient 経路が違う。
- IQN UQE tail mean は `[tau,1]`へ直接固定点を置く。QR は全域固定 quantile のうち tau 以上を抽出するため、action query の点数と位置が一致しない。
- 厳密な UQE action semantics の一致には、IQN でも全域固定 grid を query して QR と同じ index 規則で tail を抽出する実装 mode が必要である。

したがって名称は「QR 等価 IQN」ではなく `IQN fixed-grid control` とする。

### 比較案

| 目的 | 比較 | 長所 | 注意 |
|---|---|---|---|
| 現在 IQN の Q 山原因を切る | IQN32 random vs IQN32 fixed | tau sampling の寄与を一軸で確認 | QR との直接比較ではない |
| formal な実装差を切る | QR32 vs IQN32 fixed | quantile 数と pair 数を一致 | QR32 Run を新規に要する |
| 歴史的 QR51へ寄せる | QR51 vs IQN51 fixed | cy01とのquantile数を一致 | IQN51 は計算・メモリ負荷が大きい |

最初は IQN32 fixed を 20M gate で実行し、Eval reward、Q slope、TD、NOOP 優位率を確認する。QRとの差が縮む、または current random IQN より安定する場合だけ 50Mへ延長する。formal A/Bが必要なら QR32を追加する。

2. current有限本数scaleは概ね`1/√N`に従い、raw loss / gradはN方向sum契約に応じて増減した。normalized lossとfirst cancellationには破綻がなかった。
3. N16の速度改善は品質低下を補えず、N8 / N64にも独立した利得がないためN32を維持する。追加seed・50M延長・N変更に合わせたalpha探索は行わない。

### Completed: stratified / antithetic 100M matched A/B

1. K=N=M=32、B256/RR1を固定し、3か所の`sample_mode`だけを変えた2本を100Mまで完走した。
2. antitheticは0–40Mに先行したが、stratifiedが約40Mで逆転し、80–100MのTarget / Policyを約5–6%上回った。Train Double Suikaもstratifiedだけが3回達成した。
3. sampling方式はstratifiedを正式標準、antitheticを代替候補とする。追加100M A/Bは行わず、次はPER探索へ進む。

### P1: メトリクス契約修正

`51_eval1/41,42,51,52` と `52_eval2/41,42,51,52` の NOOP metric は `$exp_step`を指定しておらず、他の主要グラフとstep軸が一致しない。次の長時間Run前に設定を修正し、過去Runは `train_step * num_envs` で換算する。

追加すると有効な診断:

- full-range mean Q と risk-tail Q の NOOP-vs-DROP marginを分離
- `no_drop_timeout_ratio`帯ごとのNOOP margin、TD error、PER priority
- Replay sample中のNOOP比率と連続NOOP長
- Qバブル区間のepisode自動保存・事後調査

最後の項目は `docs/memo/932_episode_forensics_10prd.md` の対象とする。

### P1: PER探索

- K=N=M=32、stratified、B256/RR1を基準とし、PERだけを一軸ずつ変更する。
- 初回行がminibatchの約71%を占め、first cancellationが約52%であるため、初回Learner priority更新にquantile pairを考慮する方式を最初の候補とする。現行priority式をcontrolにし、学習lossや通常更新まで同時に変えない。
- fixed initial priority 0.3、`actor_approx`、PER alpha / betaはそれぞれ独立軸として後続比較し、一つのRunで同時変更しない。
- reward、MaxRank、Double Suikaに加え、first priority MC ratio、first cancellation、initial sample / mass ratio、priority / IS ESS、never-sampled evictionを採否に使う。

### P2: risk policy

- K8/K32は未決着だが、後続基準にはPolicy側の積分解像度が高いK32を採用する。K8/K32長期matched A/BはPER探索へ混ぜず独立候補として保持する。
- train tail tau / tail meanはK/N/M決定後に一軸で扱う。learner本数、policy本数、batch/RRを同時に変えない。
- `use_optimistic_target=true`: 過去に成績改善が乏しく不安定化懸念があるため、現時点ではfalseを維持する。

### P2: NEETへの介入

- 現 RunのNEET/Qバブルは自力で鎮火したため、`noop_penalty` / `time_penalty`を基準Runへ直ちに導入しない。
- fixed-gridでも持続的Eval NEETまたはQ再膨張が再現した場合、small `noop_penalty`を一軸A/Bする。
- n-step増加は遅延罰伝播に効き得るが、DropMerge過去結果で局所解懸念があるため、現在の第一候補にはしない。

### P2: QR長期lineage側の未解決

- [長期 Run: batch / replay 探索](2026-07-27_longrun-batch-replay.md)のB512/RR1診断は未実行。batch効果とsample budget効果の分離課題として維持する。
- 保存済みQR lineageの終点はcy07。cy08 B512/RR2は改善余地を示したが異常終了し、checkpointを保存できていない。
- IQN基礎比較中はbatch/RR探索を混ぜない。IQN採否後に、採用mode上で改めて実時間効率を測る。

### P3: 長期基盤・後続アルゴリズム

- `docs/memo/930_serialize_10prd.md`: Agentだけでなくoptimizer、ReplayBuffer、Env、step、schedulerを含むRun全体save/load契約。checkpoint継続時のalpha等を正しく制御する前提基盤。
- `per_initial_priority_mode=actor_approx`: 実装済みだが長期主力はfixed 0.3を維持。IQN基礎比較後の独立課題。
- BBF / BTR / multi-step系: 現IQN/QR差とQバブル機構を確定してから、次世代長期Runのsample efficiency改善として扱う。
