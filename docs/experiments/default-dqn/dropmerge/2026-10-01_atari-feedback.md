## 現時点のまとめ

1. Munchausen（温度 τ0.03、α0.9、clip −1、Double DQN OFF）は、この系列で最大の単独の改善だった。IQN の 100M checkpoint の評価専用 Run で、Eval1 は 1,524 → 1,796（+18%）、Eval3（Greedy）は 1,572 → 1,831（+16%）。IQN+M の 2 seed の差は 1〜2% だった。
2. 8 月から続いていた「IQN は QR51 に負ける」は、評価方策 UQE との相互作用だった。Greedy で評価すると IQN 1,572 対 QR51 1,552 で、IQN が負けるのは UQE で評価したときだけ（1,524 対 1,694）。QR51 は Greedy で評価すると 84〜88% の局が NoDropTimeout で終わる。Munchausen を入れた後は、評価専用 Run の 2 seed 平均で IQN+M が QR+M を上回った（Eval1 1,784 対 1,671）。ただし QR+M は 2 seed で 10〜15% ずれた。
3. 活性化関数を ReLU にする腕（A ストリーム、τ 埋め込み、V/A と τ と main_feature 末尾の全部）は持ち込まなかった。A ReLU は 50M で差がなく、全部 ReLU は main_feature 末尾の 90% が dormant になり、τ ReLU は Q バブル（実空間 Q の平均 55、基準 8）と長考型の NEET を起こした。
4. target の hard 更新（C=200、soft と同じ時定数）は、IQN+M で soft の 2 seed より 3 方策とも低く、NOOP が増えた。soft（0.005）のままにした。
5. NoDropTimeout の罰を −10 から −20 にすると、時間切れの終局は評価専用 Run で 21〜62% から 0〜5% へほぼ消えた。待つ行動は減らず、締切の直前に落とす長考型へ形が変わった。成績は −10 と同水準だった。
6. NEET の入口は、学習 Actor の UQE の ε ラダー（上端の lane で ε0.6）だった。ε を 0 にすると NEET は出なかった（NOOP 選択率 0%）。ε を 0 にしただけでは評価専用 Run で 7〜11% 下がり、NoisyNet で ε を置き換えると −20 の基準と同水準（+0.6〜+4.4%）に戻った。ε ラダーの上に NoisyNet を足しても NEET は防げなかった。以後は NoisyNet で ε を置き換えた構成（nzrep）を基準にした。
7. ε ラダーの上で試した n-step 3 と RR4+SN は、どちらも深い長考型 NEET に入り、評価専用 Run で 10〜16% 下がった。NoisyNet 基準の上で RR4 だけを試すと NEET は出ず、100M の学習中の評価は FB シリーズで最高の 1,851（nzrep 比 +4.1%）だった。同じ実時間では RR1 が大きく上回る（8 時間で 1,777 対 1,548）。
8. RR1 では、共有トランク `Linear_2048` が試した中で最良だった。512 と 4,096 はどちらも −8%、トランクを外して列の位置を残す縮約（map16）は −21%、Transformer を 8 層にすると −9% だった。大きくした 2 腕（4,096 と 8 層）は序盤から NEET が出た。scratch からの B512/RR2 も −5% で NEET が混じった。
9. RR1 のまま 300M まで継続すると、学習中の評価は 50M ごとに +81 → +50 → +37 と鈍りながら伸び続け、最後の 10M は 2,033 だった。RR4 の 100M とほぼ同じ実時間（25.8 時間）で約 10% 上だった。
10. γ0.999 は 100M で nzrep と同点（−0.6%）。序盤は速く中盤は遅い。
11. 100M checkpoint からの 20M 分岐では、PER 初期優先度の 2 腕は一度も sample されずに捨てられる割合を設計どおり 23% / 35% に動かしたが、学習側の平均点は ±0.8% 以内だった。B512/RR1 が +2.0%、B512/RR2 が +0.8% で、B512/RR1 の 50M 分岐（34b）も学習側の平均点で +2.0% → +0.6% と縮みながら上だった。
12. 後の系列（10/18〜19）で、学習側の平均点には NoisyNet の探索の損が含まれ、勾配ノイズを減らす腕は NoisyNet の揺らぎに鈍くなるだけで学習側の点が 2〜3% 上がり、決定的な評価（各ランナー 5,000 局）は変わらないことが分かった。11 の学習側の差（31 と 34 の分岐）は、評価側での確認が要る。学習中の評価と評価専用 Run に基づく結論はこの影響を受けないが、学習中の評価は 10M 窓で ±2% ほどぶれる。
13. Run ごとのぶれは、IQN+M の 2 seed で 1〜2%（評価専用 Run）、QR+M の 2 seed で 10〜15%（評価専用 Run）、nzrep と後の系列の seed 2 で約 6%（学習側の平均点）だった。1 Run どうしで 6% に満たない差（RR4 +4.1%、γ0.999、ε ラダー＋NoisyNet、B512/RR2 −5%、nzrep と −20 基準の差）は確定していない。

## この文書の読み方

### 成績の 3 つの物差し

| 物差し | 中身 | 局数 | 注意 |
|---|---|---|---|
| 学習中の評価 | 学習 Run の中で回す評価セッション。1 セッション 1 局。Eval1（target ネットの UQE）、Eval2（online ネットの UQE）、Eval3（target ネットの Greedy）。表の値は各セッションの return の 10M 窓の生の平均（EMA ではない） | 10M あたり Eval1・Eval2 は約 390 局、Eval3 は約 195 局 | 1 局の標準偏差が 250〜400 なので、10M 窓の平均は ±2% ほどぶれる。Eval3 は 10/03 以降の Run だけにある |
| 評価専用 Run | 学習 Run の最後の checkpoint を読み、学習を止めて評価だけを回した Run。各ランナー 100 局 × 4 セッション | 各ランナー約 400 局 | 値は 4 セッション平均の平均と、その標準誤差（±）。10/10 からは作らなくなった（探索ブロック 10） |
| 学習側の平均点 | 学習中の env の局のゲームの得点を、Run ログから 10M 窓で平均したもの | 10M あたり約 2〜6 万局 | 探索（ε ラダーや NoisyNet）の損を含む。探索が違う腕どうしでは比べられない。同じ探索の腕どうしでも、NoisyNet の揺らぎへの感度の差を含む（まとめ 12） |

- 評価の方策は UQE が τ0.85（上側の裾の平均で選ぶ）、Greedy が分位の平均の argmax。評価では ε を使わず、NoisyNet の揺らぎも使わない（`mu_only`）。
- return はゲームの得点に終局の罰を足したもの。罰を −10 から −20 にした腕の return のずれは 1.4 点以下で、比較には影響しない。
- 「NOOP 選択率」は Eval1 で NOOP が UQE の 1 位になった step の割合で、評価ランナー自身の step 軸の後半で平均した。
- 継続の Run（29、31a〜e、34a/34b）は、Run の中の経験数が 0 から数え直しになる。この文書では通算の位置（例: 100→120M）で書く。
- Q の水準（`37_agent_qtd/31_q_max_real_mean`）と Munchausen の指標（`36_agent_munchausen/*`）は経験数の軸で記録される。この文書の値は経験数の窓で引き直した。当時の分析の 10/03〜10/12 の値の一部は学習ステップの窓で切っていて、学習の最初の約 0.4M 経験だけを見ていた。該当するブロックに判断更新として書いた。
- τ が 3 種類ある。Munchausen の温度（`munchausen.entropy_tau`）、soft 更新の係数（`soft_update_tau`）、UQE の裾の位置（`uqe_tau`、lane ごとのラダー）。

### 用語

- NEET は合法な DROP があるのに NOOP を続けること。この文書では形で 2 つに分ける。時間切れ型は NOOP が 100 step 続いて NoDropTimeout で終わる局が増えるもの、長考型は締切の直前に落とすので終局の理由は変わらず局が長くなるもの。投了は詰み盤面での NOOP（NoLegalDrop）。
- R11/局・R12/局は、1 局あたりのスイカ（Rank 11）とダブルスイカ（Rank 12）の合体の回数。
- ε ラダーは学習 Actor の 256 lane に UQE の ε を対数で振ったもの（lane 0 が 1e-4、上端が 0.6）。`uqe_eps_start=0` にすると全 lane が下限の 1e-4 になり、この文書では「ε を 0 にする」と書く。τ ラダーは同じく `uqe_tau` を 0.85〜0.95 で振ったもの。

## 探索ブロック 01: 引き継ぎの照合と Munchausen の 20M スクリーニング

**記録時点:** 2026-10-01
**状態:** completed / Munchausen τ0.03 を 100M へ進めた
**確度:** low〜medium。各 1 Run の 20M。同じ設定の基準 2 本の 10–20M は Eval1 で 0.8% 差

### 探索観点

Atari 枠からの引き継ぎ文書の数値を、DropMerge の設定 dump・メトリクスと照合する。そのうえで、Atari で最も効いた Munchausen を DropMerge の Q の差の大きさに合わせた温度で入れ、20M で立ち上がりを見る。

### 探索条件・対象 Run

照合で直した主な点は次のとおり。

- 引き継ぎでは Munchausen の温度を 1e-3 / 3e-3 と見積もっていた。DropMerge は Q 値の変換（TBO の h 関数、ε 0.01）を使っていて、`17_q_gap` は h 空間の値、Munchausen の softmax は実空間で取る。実空間に直すと Breakout との差は 1/2〜1/5 で、温度は 0.01 と 0.03 の 2 点にした。`clip_value_min` は温度に比例させた（−0.333 / −1）。
- PER の β は経験数の絶対値でアニールするので、20M の Run の β の履歴は 100M の Run の前半と同じだった。

| Run | 基準からの差 | 到達 |
|---|---|---|
| `run_20261001-142856_dmfb_base_20m` | なし（基準） | 20M |
| `run_20261001-160442_dmfb_m1e-2_20m` | Munchausen τ0.01、clip −0.333、Double DQN OFF | 20M |
| `run_20261001-173811_dmfb_m3e-2_20m` | Munchausen τ0.03、clip −1、Double DQN OFF | 20M |

### 探索結果

学習中の評価（Eval1 / Eval2）。

| Run | 0–10M | 10–20M | 10–20M の基準比 |
|---|---:|---:|---:|
| 基準 | 732 / 698 | 1,013 / 933 | – |
| τ0.01 | 673 / 637 | 1,179 / 1,079 | +16% / +16% |
| τ0.03 | 955 / 924 | 1,212 / 1,197 | +20% / +28% |

- 同じ設定の基準 100M（探索ブロック 02）の 10–20M は 1,006 / 948 で、基準 20M との差は Eval1 0.8%、Eval2 1.6% だった。
- 8 月の同じ構成の 3 Run の 10–20M（Eval1）は 883〜983 で、このビルドの基準はその上にあった。8 月の値は物差しに使わなかった。
- τ0.01 の 10–20M では、Q の差（h 空間）0.0032 → 0.0125、target と online の行動の食い違い 0.67 → 0.32、dormant 0.012 → 0.004、Munchausen の softmax のエントロピー 0.60（最大 ln59 = 4.08）、clip 率 2.8% だった。
- 学習側の局の 8〜9% が NoDropTimeout で終わった（基準は 0.2〜0.4%）。
- 速さは 3 本とも約 1.6 時間 / 20M で、Munchausen で遅くならなかった。

### 考察

Munchausen は 20M で基準の幅を大きく超えた。τ0.03 は τ0.01 より上で、Eval1 と Eval2 の差も 80 から 15 に縮んだ。学習側では時間切れ型の NEET が出始めている。

### 次の探索

ユーザーの判断で、ViT を含む構成の良し悪しは最低 50M、最終は 100M で見ることにした。残りの 20M の腕は流さず、基準 100M・QR51 100M と、ReLU の腕を 50M で流した（探索ブロック 02・03）。

## 探索ブロック 02: 基準 IQN と QR51 の 100M、評価専用 Run による切り分け

**記録時点:** 2026-10-02〜2026-10-03
**状態:** completed / IQN の劣勢は UQE との相互作用と判断
**確度:** medium。学習 Run は各 1 本。評価専用 Run は各方策約 400 局

### 探索観点

8 月の記録では、同じ条件の QR51 が IQN32 を 90–100M で上回っていた。同じビルドで基準 IQN と QR51 を 100M 取り直し、差が IQN そのものか、評価方策との組み合わせかを切り分ける。

|---|---|---|
| `run_20261001-191232_dmfb_base` | 基準 IQN32 stratified | 100M、8.0 時間 |
| `run_20261002-031314_dmfb_qr` | 基準の `quantile_mode` を `qr`（51 分位）へ。τ 埋め込みと融合を外す | 100M、7.4 時間 |

### 探索結果

| checkpoint | 評価方策 | Eval1（target） | Eval2（online） | 局の長さ | NoDropTimeout の終局 |

| 基準 IQN | UQE | 1,524 ± 15 | 1,468 ± 19 | 267 / 259 | 0% / 0% |
| 基準 IQN | Greedy | 1,572 ± 17 | 1,500 ± 16 | 290 / 272 | 0% / 0% |

- Greedy で選ぶと IQN は QR51 と同等かやや上だった。IQN が負けたのは UQE で選んだときだけだった。
- QR51 は Greedy で選ぶと局の 84〜88% が NoDropTimeout で終わった。UQE の上側の裾で選ぶとそれが消えた。
- 評価専用 Run の Eval1 − Eval2 は IQN 56〜72、QR51 77〜89 で、学習中の評価で見えた IQN の大きな差は checkpoint では再現しなかった。

### 考察

IQN の劣勢は IQN の価値の学習そのものではなく、UQE で選ぶときの相性から来ていた。QR51 の平均値は終盤で「待つ」に傾き、UQE の上側の裾がそれを止めていた。IQN は UQE で選ぶと少し損をする。

学習中の評価で見た「IQN の online が同点付近で揺れる」と「IQN の Q が過大で max が過大評価される」という仮説は、評価専用 Run の Eval1 − Eval2 が QR51 と同程度だったので取り下げた。

報酬の構造として、NoDropTimeout と SpawnBlocked は同じ −10 で、100 step 先の −10 は γ0.997 で −7.4 に割り引かれる。負けが確定した局面では待つ方が 2.6 点得になる。

### 次の探索

評価専用 Run の結果を受け、学習 Run の中で Greedy のセッション（Eval3、target ネット、間隔 200 学習ステップ）を Eval1・Eval2 と並べて回すようにした（探索ブロック 04 以降の Run）。Munchausen は IQN と QR51 の両方で 100M を流した（探索ブロック 04）。

### 判断更新

NoisyNet が使えるようになったので、ε ラダーと NoisyNet の組み合わせで NEET の入口を切り分けた（探索ブロック 08）。

### 判断更新

- 当時の分析では「n-step 3 の Q の水準は基準の約 2 倍」「RR4+SN の Q は基準の 3.8 倍で直線的に増加」と読んでいた。これは学習ステップの窓で切った値だった。経験数の窓で引き直すと、どちらの Q も基準より低い。「Q が上がって固定の温度で softmax が鋭くなる」という当時の説明は、Q の水準ではなく Q の差の広がりとして読み直す。
- NoisyNet 基準の上で RR4 だけを試すと NEET は出ず、100M で nzrep を +4.1% 上回った（探索ブロック 09）。ここでの RR4+SN の悪化は、ε ラダー由来の NEET（と SN）によるもので、RR4 そのものの効果ではなかったと読む。

### 考察

- NEET の入口は ε ラダー側だった。ε を 0 にすると、NoisyNet の有無によらず NEET は出なかった。ε ラダーがある限り、NoisyNet を足しても NEET は防げず、成績も変わらなかった。
- ε を外しただけでは探索が足りず、約 1 割落ちた。NoisyNet はその探索を NEET 無しで補い、−20 基準と同水準に戻した。nzrep の序盤の遅れは NoisyNet が原因だった。
- spatial を切ると落ちたので、lane ごとの楽観の差（UQE の τ ラダー）には効き目がある。ε ラダーは外し、τ ラダーは残す。
- 候補の機序として、Munchausen の bonus は取った行動の log π に掛かるので、ε ラダーのランダムな DROP（π が小さい）は毎回大きく負の bonus を受け、DROP 側の Q が押し下げられて NOOP 側へ傾く、と考えた。Munchausen 無しの QR51 でも NEET が出たので、唯一の機序ではない。検証はしていない。
- 学習側の平均点は、ε ラダーのある腕と無い腕で探索の損が違うので比べなかった（nzrep の学習側 1,756 対 −20 基準 1,468 の差は主に ε の差）。

NEET の無い nzrep を基準にして、B512/RR2 と RR4、NN の構造を順に試した（探索ブロック 09・10）。

### 判断更新

- 5M 窓で見ると nzrep は 75M 以降に横ばい、−20 基準は 95–100M まで伸び続けて同点になり、「NoisyNet は早く上がって早く頭打ちになる」可能性を当時は残した。RR1 の 300M 継続では nzrep の系列は伸び続けた（探索ブロック 11）。
- nzrep と −20 基準の評価専用 Run の差（+0.6〜+4.4%）は、後に測った Run ごとのぶれ（nzrep の seed 1 と seed 2 で学習側の平均点が約 6%）の内側にある。nzrep を基準にした理由は、成績の差ではなく NEET が出ないことである。

- 通算約 294M で C ドライブが満杯になり、`metrics.jsonl` はそこで止まって最終行が切れた。300M の `agent_close.anet` も 230MB で切れて読めない。Run ログは最後まで書けたので、評価の集計は有効。

### 考察

RR1 の系列は 300M でも伸び続け、同じ実時間では RR4 より有利だった。伸びの鈍り方（50M ごとに +81 → +50 → +37）は 7 月の長期 lineage の停滞と似た形で、ユーザーとの議論で「同じ長期 Run を繰り返すのではなく、天井を上げる変更を探す」方針になった。100M でも後半（60–100M）の差が保たれるか開く腕を天井型、縮む腕を速さ型として読むと、Munchausen（+27% → +19%）は天井型、トランク縮小は差が開く（悪い向きの天井型）、RR4（+49% → +1〜4%）は速さ型、NoisyNet は中立だった。

### 次の探索

停滞の機序の仮説（一度も学ばれずに捨てられる経験、勾配ノイズ、序盤の過剰適合）を、nzrep の 100M checkpoint からの 20M 分岐で確かめた（探索ブロック 12）。300M の checkpoint は壊れたので、以後の分岐の出発点にはしていない。

## 探索ブロック 12: 100M checkpoint からの 20M 分岐（PER 初期優先度・B512/RR1・B512/RR2）

**記録時点:** 2026-10-14
**状態:** completed / 当時は「B（ノイズ）が効き、RR（更新回数）は足しにならない」と読んだ。評価側の確認が要る（判断更新）
**確度:** low。同じ checkpoint からの各 1 本、20M。主な物差しが学習側の平均点

### 探索観点

「RR や B を上げると停滞を抜ける」を、成績ではなく機序で確かめる。3 つの仮説を立てた。

- H1: 一度も sample されずに捨てられる 29% の経験の取りこぼし（珍しい出来事ほど損）
- H2: 勾配ノイズ（学習が進むとノイズが相対的に大きくなる）
- H3: 序盤の過剰適合

ここでは H1 と H2 のつまみを、同じ checkpoint から 1 つずつ動かす。

### 探索条件・対象 Run

5 本とも nzrep の 100M の `agent_close.anet` から +20M（通算 100→120M）。

| Run | 対照からの差 | 狙い | 到達 |
|---|---|---|---|
| `run_20261014-011900_dmfb_31a_21_ctl` | なし（B256/RR1） | 対照 | 20M、1.8 時間 |
| `run_20261014-030533_dmfb_31b_21_pmax` | `per_initial_priority_mode=max` | 取りこぼしを減らす | 20M |
| `run_20261014-044551_dmfb_31c_21_p003` | `per_initial_priority=0.03` | 取りこぼしを増やす | 20M |

| `run_20261014-080249_dmfb_31e_21_b512rr2` | B512、RR2 | ノイズを減らし、更新回数は変えず、取りこぼしを減らす | 20M、2.5 時間 |

### 探索結果

110–120M（通算）。学習側の平均点は 10M に約 3.4 万局。

### 考察

当時は次のように読んだ。

- H1（取りこぼし）は向きは合うが小さい。捨てられる割合を ±6 ポイント動かして ±0.7%、B512/RR2 で 29% → 5.6% にしても +0.8%。
- H2（ノイズ）が主。取りこぼしを変えない B512/RR1 が最大で、target と online の食い違いと Q も下がった。更新回数を倍にした B512/RR2 は伸びが小さい。「RR と B を上げる」は「B（ノイズを減らす）は効く、RR（更新を増やす）は足しにならない」に分解できる。停滞は最適化のノイズの床かもしれない。

この読みには当時から次の注意があった。20M・各 1 本であること。B512/RR1 は経験あたりの Adam の歩数も半分で、学習率を下げたのと同じ効果を含むこと。checkpoint から続けると optimizer の設定が checkpoint 側に戻るので、学習率の上書きでは試せないこと（`Learner::Load` が optimizer ごと読むことをコードで確認した）。

### 次の探索

Transformer 8 層（探索ブロック 10）と γ0.999（探索ブロック 13）を流した後、31a と 31d の 120M から 50M の分岐を流した（探索ブロック 14）。

### 判断更新

後の系列（10/18〜19、[勾配ノイズと batch / replay ratio](2026-10-15_gradient-noise-batch.md)）で、学習側の平均点には NoisyNet の探索の損が含まれ、勾配ノイズを減らす腕は NoisyNet の揺らぎに鈍くなるので学習側の点が 2〜3% 上がり、決定的な評価（各ランナー 5,000 局）は変わらないことが分かった。31d の +2.0% と、それを支えにした「B（ノイズ）が効く」という読みは、方策の強さの改善としては確かめられていない。PER 初期優先度の 2 腕が小さいことは、学習中の評価でも差が窓のぶれの中だったので変わらない。
