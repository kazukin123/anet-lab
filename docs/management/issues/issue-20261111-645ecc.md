## 背景

2026-11-10〜11 のリファクタリング候補の抽出（C++ の本体を 16 単位に分けて読み、観点は docs/quality/refactor.md による）で見つかった。開発者が候補の一覧から選び、起票を指示した。2026-11-11 に今のコードで場所を確かめ直した。

metrics.cpp の語の解析と、observers の解決済みの定義・語への変換は、同じ語と enum の対応を両側で持っているので、1 件にした。

## 事象

- 語の解析（core/anet-core/src/metrics.cpp の `ParseMetricTokens`）。
  - 語を種類に分ける if の連鎖（event 4 語、step 6 語、target 12 語）と、同じ語をもう一度比べて enum にする if の連鎖が別にある。属性形（`event:`・`step:`・`step_axis:`・`target:`）の振り分けもある。
  - 同じ意味の語を複数受け付ける（`$exp`／`$batch_experience`、`$update_result`／`$batch_update_result`／`$result`、`$action`／`$action_info`、step の `$exp_step`・`step:exp`・`step:exp_step`、属性名の `step`／`step_axis`）。どれが新しいかはコードから読めない。
  - 食い違いが 2 つある。`EventField::AGENT_STEP` は `MetricValueReader::Read` が扱うが、`ParseMetricTokens` の語に `$agent_step` が無く、StepTrace の列の Parse が生の文字列で別に受ける。属性形の step は `step:episode_step` などを受けるが、`step:train_step`・`step:learn_step` は受けない。
- enum から語へ戻す表が、observers.cpp にもある。`StepAxisToken`（core/anet-core/src/observers.cpp:1251）・`FieldToken`（1275）と、`MetricsLogTraceObserver::OnEpisodeEnd` の中の switch（858-866、エラー文の中だけで使う）。StepAxis から語へは rl.hpp の `toString` もある。
- 解決済みの定義（core/anet-core/include/anet/observers.hpp:495 の `ScalarMetricDef`、513 の `TraceMetricDef`）。
  - `ScalarMetricDef` は source_key・interval・scope・eval_name を自分で持ち、同じ 4 つを subscription の中にも持つ。event と target は文字列と enum の 2 形で持ち、記録の所（observers.cpp:1482-1500 付近）で同じ局所変数を 2 回ずつ書く。読む側は両方を混ぜて使う。
  - 2 つの定義は 9 個のメンバが同じで、JSON 化（`ScalarMetricDefsToJson` 1304、`TraceMetricDefsToJson` 1329）の 6 項目も同じ式である。
  - trace の定義は event を直書きの "episode_end" で入れ（1607）、scalar は `EventToken` を通す。

## 影響

- target を 1 種足すと、metrics.cpp の 3 か所（認識・変換・取得元）と observers.cpp の 2 つの表を直す。StepTrace の列で使うなら、その分も直す。1 か所漏れてもコンパイルは通り、実行時に WARN か `unknown` の表記になる。既に `$agent_step` と `step:train_step` で漏れている。
- 定義の項目を 1 つ変えると、def 側・subscription 側・JSON 側の 3 か所を合わせる。

## 対応方針

語と enum の組を 1 つの表（語・種類・enum 値）にして metrics_impl.hpp に置き、`ParseMetricTokens` と enum から語へ戻す関数がそれを引く。定義には enum を 1 回だけ持たせ、文字列は JSON 化のときだけ作る（subscription は定義から作る関数にする）。Scalar と Trace の共通のメンバを 1 つの struct に出し、JSON の共通の項目を 1 つの関数にする。受け付ける語、WARN の文言と回数、出力する JSON の形、設定キー、メトリクスの名前は変えない。2 つの食い違いを揃えるかは、受け付ける語が増えるので別に決める。
