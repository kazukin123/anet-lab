## 背景

2026-11-25 の監査（観点 refactor、範囲 321_agent_core）で見つけた。観点の分類は「既存の重複」で、「特例で支える汎用機構」「肥大化」が付随する。開発者には質問していない。

RFD0125（2026-11-12）は、Munchausen の評価（D10）と target の式（D11）を共通の関数にした。翌日以降の RFD0121 は、外的・内的の 2 成分の目標値を作る関数を基底の `Learner` に足した。RFD0125 が「価値の分解のための Head ごとの目標の口を先に足す形 — 範囲外。再開条件: RFD0121 のグリルで口の形が決まったとき」と書いた条件は、RFD0121 が実装されたので揃っている。

ホットスポット補正: `dqn_learner.cpp`（改名の前の `dqn_based_agent.cpp` は churn90 が 41）は、コードのファイルの上位 1% に入る。urgency を 3 から 5 へ 1 段上げた。

## 事象

- `Learner::MakeDecomposedTargets`（`dqn_learner.cpp:2641-2744`、104 行）は、基底の非仮想の関数で、`quantile_mode` の比較を 2 つ（2647・2648 行）持ち、そこから作った `quantiles`・`iqn` で値の鍵、平均、gather、score、τ の追加を分けている。分布ごとの違いを派生の上書きで表す `MakeTarget`（`dqn_learner.hpp` の仮想関数、`QuantileLearnerBase` が上書き）と、2 つ目の作りになっている。
- Munchausen の評価の写し: 入力の連結、τ の追加、行の対応付け、target の forward、capture の行数の検査と切り出し位置の書き込み、online の追加評価が、`Learner::ForwardMunchausenValues`（2113〜2167 行）と、`MakeDecomposedTargets` の 2661〜2696 行に並ぶ。違いは、読む出力が 1 つか 2 つか、TempoRL の 2B 行を扱うか（分解は TempoRL と併用できない。`default_dqn_agent.hpp:291`）、エラー文だけである。
- hard target の行動選択の写し: 「Double DQN なら online、そうでなければ target の実行器を選び、`target_policy_->SelectAction(next_obs, true, …, 診断なら DiagnosticActionEvaluation)` を呼ぶ」処理が 3 か所にある（`QuantileLearnerBase::SelectTargetActions` の 2233〜2242 行、`Learner::MakeTarget` の 2600〜2605 行、`MakeDecomposedTargets` の 2715〜2720 行）。
- 可塑性の target capture の切り出し位置（`plasticity_.target_capture_batch_size`・`target_capture_offset`）を書く箇所が 3 つある（2147・2148 行、2478・2479 行、2675・2676 行）。
- 検索語と件数: `ForwardMunchausenValues` は定義 1・呼び出し 2、`target_policy_->SelectAction` は 3。

## 影響

- target の作りを変える作業が 2 通りの場所に当たる。n-step の目標値の補正（RFD0168、[issue-20261103-75b8da](issue-20261103-75b8da.md)）、SMDP の経過時間（RFD0167、[issue-20261103-124da5](issue-20261103-124da5.md)）、分布の表し方や `log_policy_mode` を足すときは、combined の側と分解の側の両方を直す。
- 分解の側を直し漏らすと、`value_mode = decomposed` の Run だけが古い target で学び、ERROR は出ない。

## 対応方針

- `ForwardMunchausenValues` が読む出力の鍵を並びで受け、鍵ごとの current と next を返す形にし、`MakeDecomposedTargets` がそれを使う。hard target の行動選択は `SelectTargetActions` を基底に上げて 3 か所で使う。分布ごとの違い（選んだ行動の値、平均、risk の score）は、今ある仮想関数の型のまま派生に置く（関数を受け取る補助にはしない）。capture の切り出し位置は戻り値に載せ、書き込みを 1 か所にする。
- 性能の区分は「中立」（更新ごと。forward の数・順、τ の抽選の順を変えない）。
- トピック別まとめの「変えるときの条件」では、RFD0125 §4 D5・D13・D16・D17（乱数を引く位置と順、forward の順、AMP の範囲の端、更新 1 回あたりの実時間、31 組の短い Run）と、§4 D11（target の式は実空間の値だけを受け、h は 1 回）が当たる。31 組に、分解を有効にした組（TD・QR・IQN × Munchausen の方式 × `extrinsic_bootstrap_mode` × TBO）を足す。同 seed・決定的モードの metrics の一致を確かめる。
- テスト: `dqn_learner_test.cpp:1516`・`1666`・`2782`、`dqn_actor_test.cpp:1462`、`dqn_munchausen_test.cpp:379`・`631` が結果を通す。2 つの関数を名前で呼ぶテストは無い（検索語 0 件）。
- 不採用の形との突き合わせ: RFD0125 の「関数を受け取る補助にして分布ごとの違いを渡す形 — 不採用」「学習器のクラスを 1 つにまとめる形 — 範囲外」に当たらない形にした。RFD0125 D10・D12（方策と soft 価値を組む部分は、通常の Q と分位点のそれぞれに残す）と、ADR 0035・0074 は守る。
- [issue-20261112-4efa57](issue-20261112-4efa57.md)（replay fit の診断が更新の前半を別に書く）は、`MakeDecomposedTargets` を呼ぶ側を持つので、直す順を決めるとき一緒に見る。
