## 背景

PRD125（DQN の学習器の 1 回の更新の進行と Munchausen の target を 1 か所に寄せる）の起草で、別モデルの検討が見つけた。PRD125 は、TD・QR・IQN の `UpdateFromSamples` の進行を基底の 1 関数へ寄せ、分布ごとに違う current 側の計算を仮想関数にする。replay fit の診断は、PRD125 が範囲外にした（同 PRD の 3.2 節）。forward の仕方と τ の置き方が学習と違い、PRD125 が足す口をそのまま使えないためである。

開発者には質問していない。工程の終わりに起票の候補として示し、開発者が採った。

## 事象

`Learner::EvaluateReplayFit`（core/anet-core/src/dqn_based_agent.cpp の 2978〜3011 行。2026-11-12 時点）が、学習の 1 回の更新の前半と同じ進行を、別に書いている。

- 2984 行: 観測の正規化（`NormalizeSampleObservations`）
- 2988〜2991 行: `quantile_mode` が IQN のときだけ、τ を作って入力へ足す
- 2993 行: online network の forward
- 2994〜2998 行: 分布を持つかどうかで、読む出力（`q_dist` と `q`）と、選んだ行動の値の取り出し方を分ける
- 2999 行: `MakeTarget`
- 3000 行: loss を求める IQN のときだけ、τ の形を変える
- 3002 行: `ComputeElementError`

分布の表し方での分岐は 3 か所ある（2988・2994・3000 行）。基底の `Learner` の関数が、派生（QR・IQN）の事情を `quantile_mode` で見分けている。

学習の進行との違いは次のとおりである。

- τ は、診断用の指定（`MakeTargetEvaluation(true)`。4612 行から）で、等間隔の位置に置く。学習は乱数で引く
- AMP の範囲を持たない
- PER の重み、skip loss、学習時の指標を持たない（3003 行のコメント）

## 影響

current 側の計算（読む出力、τ の渡し方、選んだ行動の値の取り出し方）を変える、または分布の表し方を足す → 学習の進行と `EvaluateReplayFit` の 2 か所を同じに直す必要がある。片方を漏らすと、replay fit の診断（`46_agent_replay_fit/` の tag）が、学習と違う計算の値を出す。診断の値なので、学習の結果は変わらない。

## 対応方針

未定。PRD125 が足す current 側の計算の口を、診断からも使える形にできるかを調べる。forward のモードと τ の作り方を呼ぶ側が渡す形が候補である。PRD125 の実装で口の形が決まってから決める（そのため、PRD125 の課題に依存させた）。
