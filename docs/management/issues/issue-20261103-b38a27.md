## 背景

台帳 F-0036 から移した（2026-11-03）。
観点: process。分類: 決まりが無い。確度: high。

## 事象

PRD098 の性能の比較の道具は deterministic backend・replay 4096・replay ratio 1 で測った 1.51 倍を出し、それを前提に話した。評価のセッションが重なった取り込みで無効と有効を比べた。Nsight の CUDA トレースの下で膨らんだカーネルの起動の API を CPU の取り合いと読み、Tracy の取り込みで覆した。

- docs/quality/impl.md:275 ### 計測 の節に、性能を比べる計測の条件（構成・ほかの負荷・道具・回数）の規約が無い

## 影響

次に性能を比べるときも、本番と違う構成の比や、評価が重なった区間、トレースで膨らんだ比で判断し、取り直しと結論の出し直しになる。

## 対応方針

docs/quality/impl.md の計測の節に規約と項目を足す: 本番と同じ構成（backend・replay の大きさ・replay ratio・env の数・ビルド）で測る、評価とほかの Runner を止める、同じ exe と学習の時期で交互に 3 巡以上測り腕ごとの中央値を取る、比は 90_perf か Tracy で取り Nsight の CUDA トレースは同期の位置と GPU の時間軸を見るのに使う、記録に構成・ビルド・道具・区間・回数を書く。
