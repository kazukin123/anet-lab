## 背景

2026-11-10〜11 のリファクタリング候補の抽出（C++ の本体を 16 単位に分けて読み、観点は docs/quality/refactor.md による）で見つかった。開発者が候補の一覧から選び、起票を指示した。2026-11-11 に今のコードで場所を確かめ直した。

PRD939（NoisyNet のノイズ込みの重みへの SN）と PRD951（SN と residual の α ゲート）は SN を触る。

## 事象

- 行列化 `weight.reshape({ weight.size(0), -1 })` が core/anet-core/src/nn_impl.cpp の 356・392 のほか、`ComputeNoisyParameterStatistics`（2096 から）、`ComputeParameterNormSplit`（2163 から）、`ComputeSpectralNormValidity`（2267 から）にある。dqn_based_agent.cpp・image_cls_agent.hpp・テストにも同じ式がある。`ComputeSpectralSigma`（337 から）が行列を受け取る形なので、`SpectralNormEntry` を持つ呼び出し側が毎回自分で行列にしている。
- 実効の分母（`kSpectralCap` なら `sigma.abs().clamp_min(1.0)`、ほかは `sigma`）が `MakeSpectralNormalizedWeight`（384 から）・`ComputeNoisyParameterStatistics`・`ComputeParameterNormSplit` の 3 か所にある。
- 無効の判定（有限でない、または spectral で 0 以下）が `MakeSpectralNormState` の中（double で）・`ComputeParameterNormSplit`・`ComputeSpectralNormValidity` の 3 か所にあり、dqn_based_agent.cpp に 4 つ目がある。
- 無効の数を返す口が 2 つある。`ComputeParameterNormSplit` の `invalid_count` と `ComputeSpectralNormValidity` である。利用側は online に前者、target に後者を呼ぶ。
- 単位化 `x / x.norm().clamp_min(kEps)` と `constexpr double kEps = 1.0e-12` の定義が 4 か所にある（nn_impl.cpp:315、340、355、2588）。

## 影響

- 正規化の方式（`WeightNormMode`）を 1 つ足す、または無効の定義を変えると、分母 3 か所と判定 3〜4 か所を直す。写しの 1 つを直し忘れると、forward の重みと診断の値が食い違う。今は食い違いは見つかっていない。
- PRD939・PRD951 は SN の式を触るので、この写しの上に足すことになる。

## 対応方針

内部の関数に寄せる。`SpectralSigma(const SpectralNormEntry&)`（行列化を中で行う）、`EffectiveDenominator(mode, sigma)`、`IsInvalidSigma(mode, sigma)`、単位化の関数の 4 つにし、`kEps` は 1 つにする。`ComputeParameterNormSplit` の無効の集計と `ComputeSpectralNormValidity` は同じ関数を使う。`MakeSpectralNormalizedWeight` は SN 付き module の forward ごとに通るので、計算が同じで速さが変わらないことを確かめる。
