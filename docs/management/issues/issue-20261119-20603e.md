## 背景

2026-11-19 の PRD190（設計文書 200 の記述をコード・設定・用語集・ADR へそろえる）のグリルで見つけた。課題 [[issue-20261118-9c6895]] は、設計文書 200 の部品表と `CONTEXT.md` が書く `TauGenerator` という型が無く、実体は自由関数 `anet::rl::dqn::GenerateTaus` であることを挙げ、PRD190 は文書の側を `GenerateTaus` に直す。工程末の起票の候補で、開発者は「起票して今回の PRD で対応する」を選んだ。

## 事象

2026-11-19 に `git grep -n TauGenerator -- src apps` で引いた結果は次のとおり。`apps` には 0 件。

- `src/algo/dqn/src/dqn_based_math.cpp` のエラー文 4 か所（121・124・129・210 行）が「TauGenerator requires …」「TauGenerator received …」で始まる。
- 同じファイルの引数の検証関数の名前が `ValidateTauGeneratorArguments`（118 行で定義、194・213 行で呼ぶ。`static` で、ほかのファイルからは見えない）。
- `src/algo/dqn/src/dqn_based_test.cpp` の τ の生成のテスト 14 本（401〜672 行）の名前が「TauGenerator …」で始まる。エラー文の中の「TauGenerator」を断定するテストは無い（657 行のテストは `sample_mode=invalid` と方式の一覧だけを見る）。
- `TauGenerator` という型（class・struct）は `src` に無い。

## 影響

PRD190 で文書から `TauGenerator` を消すと、τ の生成のエラーやテストの一覧に出る名前で設計文書や用語集を引いても見つからない。読者はエラーを出した部品を探しにくい。

## 対応方針

PRD190 の D19 で対応する。エラー文 4 か所の先頭と検証関数の名前、テスト 14 本の名前の先頭を `GenerateTaus` にそろえ、旧い名前は残さない。
