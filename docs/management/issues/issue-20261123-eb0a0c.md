## 背景

2026-11-23 の監査（観点 defect、範囲 324_dqn）で見つけた。分類は境界である。開発者には質問していない。

AGENTS.md の「設定値の扱い」は、範囲外の値を `ANET_SYSTEM_ERROR` で止め、`0` を別の意味に読み替えたり範囲外を clamp したりしないとしている。`learner.use_grad_clip` と `learner.use_td_clip` の既定は true である（`src/algo/dqn/src/dqn_config.hpp:282`・284）。`learner.grad_clip_tau` は Atari・DropMerge・GridMaze の出荷設定で調整している値である（`apps/runner/config/Atari.txt:799`、`DropMerge.txt:755`、`GridMaze.txt:180`）。

## 事象

- `DefaultDQNAgentConfig::ReadLearner`（`src/algo/dqn/src/default_dqn_agent.hpp:463`）は `learner.grad_clip_tau`・`learner.td_clip_value`・`learner.update_interval` を読む（481・483・487 行）が、値域を検証しない。同じ関数は `noisy_weight_decay`・`tbo_epsilon`・probe の batch size などは検証する。`RainbowAgentConfig`（`rainbow_agent.hpp:55`〜62 行）も同じ 3 つを検証せずに読む。DQN の共通部品（`dqn_assembler.cpp`）と Learner にも、この 3 つの値域の検査は無い（検索語 `grad_clip_tau`・`td_clip_value`・`update_interval`）。
- 勾配の clip: `use_grad_clip` のとき、Learner は `anet::ForeachClipGradNorm_(grads, grad_norm, grad_clip_tau)` を呼ぶ（`src/algo/dqn/src/dqn_learner.cpp:1274`）。この関数は勾配に `(tau / (norm + 1e-6)).clamp_max(1.0)` を掛ける（`src/core/base/src/nn_util.cpp:188`〜196 行）。tau が 0 なら勾配は 0 になり、負なら勾配の向きが逆になる。
- TD の clip: 損失の前の clip は `config_.use_td_clip && config_.td_clip_value > 0.0f` のときだけ当てる（`dqn_learner.cpp:2449`）。`use_td_clip = true` でも `td_clip_value` が 0 以下なら、clip を黙って外す。
- 更新の間隔: `replay_ratio` が 0 以下のとき、1 step の credit を `1.0f / std::max(1, update_interval)` で作る（`dqn_learner.cpp:185`）。`update_interval` が 0 以下なら、黙って 1 として扱う。
- この 3 つのキーを 0 以下にするテストと出荷設定は無い（`src/` のテストと `apps/runner/config` を検索）。
- 2026-11-25 監査（defect）: 同じ原因（学習の設定の値域を検証しない）の設定キーが、本文の 3 つのほかに 4 つある。(1) `learner.quantile_huber_kappa`（QR）: 検査は IQN のときだけで、`κ = 0` なら `QuantileLearnerBase::ComputeQuantileHuberLoss`（`src/algo/dqn/src/dqn_learner.cpp:2329`）の損失と勾配が 0、`κ < 0` なら損失が負になる。RFD0001 は「QR は既存挙動のまま検証追加しない」と書く（IQN の RFD の範囲の決定で、`κ = 0` を意図した記述ではない）。(2) `learner.per_alpha`: `ValidateReplayPriorityConfig`（`dqn_math.cpp:240-285`）は 0 の WARN だけで、負と NaN を見ない。負なら誤差の小さい遷移ほど選ばれる（`replay_buffer_impl.cpp:1133`・1152 行の `std::pow`）。(3) `learner.replay_ratio = 0`: `> 0` でなければ間隔のモードに入り（`dqn_learner.cpp:257-263`）、`update_interval` の既定 1 で毎 step 1 更新する。コメントは「負数なら update_interval」とだけ書く。(4) `learner.replay_batch_size`: 0 なら RR のモードで credit が +inf になり（259 行）、更新の while（1786 行）の条件が偽にならない。負なら 1 回も更新しない。どれも範囲外を通すテストは無い。

## 影響

- `learner.grad_clip_tau = 0`（0 で clip を切れると思った指定や、打ち間違い）では、online の Network が一度も変わらないまま Run が最後まで回る。負の値では勾配の上りで学習する。どちらもエラーも WARN も出ず、違う条件の Run の結果が残る。
- `use_td_clip = true` を明示しても、`td_clip_value` の誤りで clip の無い学習になる（明示の要求が黙って守られない）。
- `update_interval = 0` の指定が、エラーにならずに毎 step の更新になる。

## 対応方針

- 3 つの値域（`grad_clip_tau` と `td_clip_value` は有限で 0 より大きい、`update_interval` は 1 以上）を、DQN の Learner の設定（`LearnerConfig`）の共通の検証として 1 か所に置き、DefaultDQN と Rainbow の設定の読み取りから呼ぶ。AGENTS.md の「設定値の扱い」のとおり、使われない側（`use_grad_clip = false` のときの `grad_clip_tau`、`replay_ratio` が正のときの `update_interval`）も、そのキーだけで決まる値域は検証する。
- 学習の値の計算（`ForeachClipGradNorm_` と TD の clip の式）は変えない。`td_clip_value > 0.0f` の条件は、検証を足したあとは常に真になるので、消すかを対応のときに決める。
- 正しい値の構成では挙動を変えない。エラー文は、[324_dqn のトピック別まとめ](../../wiki/concepts/framework/324_dqn.md) の「変えるときの条件」のとおり完全キーで書く（RFD0194）。
