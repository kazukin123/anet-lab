## 背景

ImageCls は、Food-101 をスクラッチから学習してきた（[wiki の ImageCls](../../wiki/subjects/imagecls.md)）。開発者の TODO メモの「適宜」の項に「転移学習対応（一般NNモデルの読み込み対応）」が残っていた。開発者がこれを課題として起票するよう指示した。この起票では質問をしていない。

## 事象

- ImageClsAgent が重みを読む口は、設定キー `ImageClsAgent.auto_load_file` だけである（[image_cls_agent.cpp](../../../core/anet-core/src/image_cls_agent.cpp) の 623〜627 行）。
  - 読むのは、ImageClsAgent が保存した anet の archive である。header が `ImageClsAgent` でなければ止まる（同 685〜692 行）。
  - network の全体と optimizer の状態を、そのまま復元する（同 703〜708 行）。構造が違う network（Head のクラス数が違う、Body だけを使うなど）へ一部だけを読む口は無い。
  - PyTorch などほかの道具で学習した重みのファイルを読む口は無い。
- optimizer は network の全部の parameter を 1 つの組で持ち、学習率も 1 つである（同 125〜132 行）。一部の Body の重みを止める、Body と Head で学習率を変える、といった口は無い。
- 画像の入力は、NN の入口で uint8 を 255 で割るだけで、平均と標準偏差による正規化はしない（[nn_impl.cpp](../../../core/anet-core/src/nn_impl.cpp) の 1239〜1241 行）。
- 開発者の TODO メモには、別の項として「ブランチ別 学習制御（学習有無、LR）」もある。この項はまだ課題にしていない。

## 影響

- 学習済みの Body から始められないので、ImageCls の Run は毎回スクラッチの学習になり、Food-101 でも 20M step の Run に 6〜9 時間かかる（[wiki の ImageCls](../../wiki/subjects/imagecls.md)）。
- 小さなデータセットや、学習済みの Body を使う一般的な手順と同じ条件で、anet の実装を試せない。

## 対応方針

未定。

- 決めることの候補は、読み込む重みの形（anet の archive の一部、PyTorch の重みのファイルなど）、parameter の名前の対応のさせ方、Head を作り直して Body だけを読むこと、入力の正規化を学習済みモデルに合わせること、である。
- 微調整（fine-tuning）には、Body の重みを止める口や、Body と Head で学習率を変える口も要る見込みである。TODO メモの「ブランチ別 学習制御」と重なるので、この課題に含めるか、別の課題に分けるかを決める。
