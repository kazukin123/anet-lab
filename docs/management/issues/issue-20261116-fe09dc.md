## 背景

[PRD131](../../memo/131_prd_9xx_renumber_by_creation_date_10prd.md)（9xx の番号の PRD 57 本を、起票の日の順に 900 未満の連番へ振り直す）の D15 で、番号が 1000 に届いたときの 4 桁の形を範囲外とし、先送りにした。再開の条件は「番号が 990 に届いたとき」である（同 PRD の §8）。PRD131 の D3 は、振り直しのあと 900〜999 も普通の番号として使うと決めたので、999 の次が 1000 になる。

PRD131 のグリルでは、9xx を再び使うかを決める材料としてこの先送りを話題にした。課題として記録することは、工程末の起票の候補から開発者が選んだ。

## 事象

- PRD のファイル名は 3 桁の番号を前提にしている。
  - PRD の観点の項番 2 は、ファイル名を `^\d{3}_.+_10prd\.md$` で確かめる（[docs/quality/prd.md](../../quality/prd.md) の 31 行）。
  - 課題の `prd` 欄の検査は、PRD の名前を `\d{3}_.+_10prd` で確かめる（[wiki_support.py](../../../reports/tools/wiki_support.py) の 315 行）。
  - トピック別まとめの「PRD の一覧」は、コミットの件名から `PRD(\d{3})` で番号を読む（同 188・191 行）。
- 2026-11-16 の時点で、900 未満の最大の番号は 130 で、PRD131 を起票した。PRD131 を実装すると、振り直した 57 本で 188 前後まで進む。2026-07 から 11 月までに約 130 本を起票しており、この速さ（月に 26〜29 本）なら、990 に届くのは 2 年余り先である。
- 2026-11-23 PRD195: この節の最初の行が引く行番号（315 行、188・191 行）は今のコードでずれている。課題の `prd` 欄の検査は `wiki_support.py` の 401 行、件名から番号を読む処理は同じファイルの 189・192 行にある。[出典](../../memo/195_rename_prd_document_term_10prd.md)

## 影響

- 番号が 1000 に届くと、新しい PRD のファイル名が観点の項番 2 と課題の検査に合わず、課題の `prd` 欄に書けなくなる（一覧の作り直しが止まる）。
- コミットの件名の `PRD1000` のような番号を道具が読めず、トピック別まとめの「PRD の一覧」に載らない。

## 対応方針

番号が 990 に届いたときに PRD を起こし、次をそろえて決める。

- ファイル名の番号の桁（4 桁にそろえるか、桁の数を変えてよいことにするか）
- 道具が件名から番号を読む形
- 観点の項番 2・3 と、課題の検査の形
- 今ある 3 桁のファイル名を改名するか（改名するなら、PRD131 と同じく振り直しの行で旧い番号を引く）
