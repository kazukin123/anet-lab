## 背景

開発者が記事 [Sparks of Weight-Space Programming](https://rikiyat.github.io/blog/weight-space-programming/) を挙げ、anet で何か試せないかを相談した。相談の中で 6 つの案と進め方を示し、最初のステージを試すかの問いに、開発者はまず起票すると答えた。どの案を採るかは決まっていない。

記事は、LLM が勾配法を使わずに重みを直接読み書きする試みの報告である。記事の記載は次のとおり。

- 小さい MLP を読み書きした。17,253 重みの方策から 4 ゲームすべてを言い当てた。初期重み 0 から書いた Breakout は 517.4 点で、PPO 500M の 25.3 点を上回った。Seaquest（53.1 対 88.9）と Asterix（53.2 対 55.2）は PPO 500M に届いていない。
- Kinetix の car-on-ramp では、171,664 重みの 3.5% を変えて細い別経路を足し、成功率を 0% から 100% にした。
- Qwen3.5-0.8B の GSM8K は、元が 13.8% で、forward 10 回で 25.7%、25 回で 25.1%、50 回で 67.1% だった。
- 迎合モデルの見分けは、重みだけだと 4 回とも失敗し、attention を見せると 3 組とも成功した。
- Gemma 3 270M の数学は 6.8% から最大 7.7% に留まり、著者は改善を確認できなかったとしている。編集は隠れた障害を取り除けても、モデルに無い能力は足せないと述べている。

割り引いて読む点が 3 つある。使ったのは GPT-6 Astra で、手元で使える LLM で同じことができるかは分からない。著者も初期の結果としている。実験 1・3 には、単純な統計で当てた場合などの比較対象の記載が無い。

## 事象

anet には、学習済みの重みの中身を後から見る道具が無い。`inspect_run.py` が `agent_close.anet` について見るのは有無と更新時刻だけである。

手持ちを 2026-11-05 に確かめた結果は次のとおり。

| Env | 重み数 | 確かめた Run |
|---|---|---|
| LunarLander | 143,941 | `run_20261105-012413_ll_tw_wu_s1` |
| GridMaze | 658,687 | `run_20261028-060552_t103_gm_eps_s3` |
| qbert | 2,902,695 | `run_20260926-022413_a5_qbert_btr50m` |
| DropMerge | 57,493,944 | `run_20261104-231500_dmfb_47f_aux_mrg` |

- `agent_close.anet` は 454 本あり、うち LunarLander-01 が 120 本である。短い確認 Run も含む。設定と成績が Run に揃っているので、正解付きの問題に使える。
- `.anet` は `torch::save` の zip を並べた形で、`.venv` に torch が無くても numpy と zipfile で重みを取り出せた。LunarLander の 1 本（`run_20261021-061521_ll`）で、zip の中のテンソル 28 個とログの形状一覧の 28 行は数が一致し、確認した先頭 12 個のサイズも順に一致した。書き戻しは未検証である。
- 重みの読み込みには `auto_load_file` が、評価には [`run.@evalonly`](../../../apps/runner/config/Atari.txt) が使える。`run.@evalonly` は LunarLander.txt と GridMaze.txt には無い。
- 途中の重みを定期保存する設定は、[Run のユーザーガイド](../../../docs/design/020_user_guide_run.jp.md)を検索した範囲では見つからなかった。

試しに LunarLander の 3 seed（`run_20261025-230909_t98_ll_off_s1`、`run_20261026-001350_t98_ll_off_s2`、`run_20261026-010415_t98_ll_off_s3`）で、入力ごとの第 1 層の重みの大きさを見た。入力の順序は[観測のラベル順](../../../core/envs/lunarlander1/src/LunarLanderEnv.cpp)と仮定した。

| 入力 | 重みの大きさ |
|---|---|
| x・y・vx | 2.62〜3.41 |
| angle | 2.32〜2.56 |
| leg_l・leg_r | 1.94〜2.72 |
| vy | 1.93〜2.01 |
| 直前の行動の 4 入力 | 1.26〜1.70 |
| v_angle | 0.80〜0.88（3 本とも最小） |

v_angle の重みが 3 本とも最小でも、入力の値の大きさを見ていないので、軽視しているとは言えない。

## 影響

重みを読むことが anet で役に立つかを判断する材料が無い。放置しても、既存の Run や工程は止まらない。

役に立つなら、再学習なしの原因調べ、局所的な修正、LLM Actor の蒸留の省略が選択肢に加わる。一方、読めるかを確かめないまま道具や編集の経路を作ると、誤った読みに基づく判断や、使われない実装を生む。

## 対応方針

以下は相談で示した案で、開発者の決定ではない。

| 案 | 内容 | 記事の手本 | 新たに要るもの | 見込みと弱点 |
|---|---|---|---|---|
| 1. 重みの診断道具 | 入力ごとの重み、死んだユニット、Head の向き、2 本の差を出す | 実験 1 | Python のみ | 確実に作れる。既存の checkpoint に後から当てられる |
| 2. ブラインド当て | Run 名と設定を隠し、「どちらが高得点か」「どの設定か」を当てさせ、Run の設定と成績で採点する | 実験 1・7 | 案 1 と出題スクリプト | 読めるかを確かめる最も安い方法。読めなければここで止められる |
| 3. LunarLander の編集 | x や vx を読む細い経路を足し、評価専用 Run で採点する | 実験 4 | 書き戻し、`run.@evalonly` | 入力がベクトルなので書きやすい。Q の大きさが崩れると、続きの学習で押し戻される |
| 4. DropMerge の NOOP 停滞 | 停滞を生む方向を探して取り除く | 実験 8 | checkpoint から forward する手段 | 記事で最も効いた形に近い。PRD115 の NOOP 判定修正の後も起きるかの確認が先 |
| 5. qbert 第 8 面 | 同じ設定で抜けた seed と抜けない seed の差を読む | 実験 3・4 | forward と画面フレーム | 一番難しい。能力不足なら編集では届かない。比べる checkpoint が残っているかは未確認 |
| 6. 重みに直接書く教師 | [LLM Actor](../../memo/926_llm_actor_10prd.md)（issue-20261103-969184）の蒸留を省き、小さな MLP に方策を書く | 実験 5・6 | 小さい NN 構成、書き戻し | デモを作るだけなら普通のコードの方が簡単で、重みにする利点は勾配で続きを学習できる点だけ。そのとき Q の大きさを合わせる問題が残る |

どの案も学習の外で動くので、本番 Run の性能には影響しない。差が出るのは保守と費用である。

進め方の案は次のとおり。

1. **ステージ 0（案 1・2）:** LunarLander の Run でブラインド当てをする。C++ と本番の設定には触らず、`.scratch/` の使い捨てスクリプトで試せる。比較対象として、重みの統計だけを使う単純な分類器も同じ問題に当てる。LLM がこれを超えなければ「読めていない」と判断して止める。
2. **ステージ 1（案 3）:** 重みを編集して評価する。合格は、Greedy の平均点（single＋full、3 回平均）の差が複数 seed の終盤のブレ幅を超えることとする。既に高得点の Run より、伸び悩んでいる Run を選ぶ。
3. **ステージ 2（案 4 か案 6）:** ステージ 0・1 の結果と開発者の興味で選ぶ。

案 4・5 に進むときは、forward の手段を決める。C++ 側に「checkpoint と観測を渡すと capture を返す」コマンドを足す形を推す。[既存の capture 機構](../../adr/0055-forward-capture-request-keyed-carries-module-diagnostics.md)を流用でき、Python で NN を作り直さずに済むからである。

可塑性の指標を治す編集は低優先とする。[可塑性の wiki](../../wiki/mechanisms/plasticity.md) のとおり、SiLU や LN512 で指標を改善しても、短期の比較で成績は動かなかった。

LunarLander の全重みをそのまま貼ると 40 万トークン級になる見込み（推定）なので、読むのは道具を通す。

ステージ 0 の結果で続けると決まったら、案ごとに課題を分けるか PRD を起こす。
