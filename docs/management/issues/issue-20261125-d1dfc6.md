## 背景

2026-11-25 の監査（観点 architecture、範囲 321_agent_core）で見つけた。分類は seam（locality）で、「暗黙の前提」が付随する。開発者には質問していない。

ADR 0096 は、stack 軸の確保と並びの妥当性を、Forwarder の機構ではなく使う側が受け持つと決めた。DQN の側が受け持つ決まりは「重ねる対象のキーに軸を足す」「開始の印を足し、残れば除く」「出力の spec を照合する」の 3 つで、依頼は 4 種類（経験の受入れ、可視化、行動選択、Sample）ある。RFD0200 §10 は、RFD0142（直前の行動の観測。RFD0200 のあとに再グリルの予定）で、D1・D11・D12・D21 が変わりうると書く。

ホットスポット補正: `default_dqn_agent.hpp`（churn90 が 5＋改名の前の 33）と `dqn_learner.cpp`（改名の前の `dqn_based_agent.cpp` は 41）は、コードのファイルの上位 1% に入る。urgency を 5 から 8 へ 1 段上げた。

## 事象

- 3 つの決まりが書かれている場所: `default_dqn_agent.cpp:64-106`（`ResolveReplayFrameStack`・`BuildActorPerception`）、571〜588 行（受入れ・可視化・行動選択の照合）、711〜717 行（`LearnerPerceptionSetup`）、941〜943 行（Actor ごと）、`dqn_learner.cpp:31-104`（`CompletedPerception`・`CompletePerception`・`RequirePerceptionSpecs`）、1036〜1043 行（Sample 用の作成・補完・照合）、`dqn_actor.cpp:1503-1512`（device への転送、開始の印を足す、出力に印が残っていないかの検査）。
- 重ねるキーを解決する関数（`ResolveReplayFrameStack`）が、開始の印の名前の衝突も調べる（90〜94 行）。`CompletePerception` が印を除くのに、Actor は `MakeAction` のたびに印が残っていないかを調べる（`dqn_actor.cpp:1507`）。
- Learner は `perception_setup`（借用の builder と照合の基準）と `frame_stack`（ReplayBuffer の重ね方）を別々の任意の引数で受け、前者があれば後者もあるという前提を `frame_stack_.value()`（`dqn_learner.cpp:1037`）が持つ。型からは読めない。
- `RequirePerceptionSpecs` は、依頼の種類の文字列が `FrameWithStatsUpdate` のときだけ照合を緩める（`dqn_learner.cpp:91`）。`TensorSpec` の照合は JSON の文字列化で行う（99 行）。
- 検索語と件数（テストを除く）: `BuildForwarder\(` 4、`CompletePerception\(` の呼び出し 3、`RequirePerceptionSpecs\(` の呼び出し 3。

## 影響

- RFD0142 は、行動選択・経験の受入れ・可視化の 3 つの入口で直前の行動を足す。今の形では、開始の印と同じ 3 ファイルへ、足す・除く・照合するの 3 つを別々に足す。依頼を 1 種類足すときも同じである。
- `frame_stack` と `perception_setup` の片方だけを渡す構成を、コンパイルでも検査でも止められない。

## 対応方針

- DQN の側に、`ForwarderBuilder`・解決済みの重ね方・Frame の spec・照合の基準を持ち、4 つの依頼の Forwarder を「作り、補い、照合した形」で返す module を置く（名前は `CONTEXT.md` の Perception の語で決める）。Agent は可視化用の出力 spec と受入れ用の Forwarder をここから受け、Actor と Learner はこの module を借りて自分の依頼を出す。Learner の引数は「Perception の作り手（任意）と重ね方」を 1 つの値にまとめ、片方だけを渡せない形にする。RFD0142 の再グリルで合わせて決める。
- 性能の区分は、構築時は「関わらない」、`Actor::MakeAction` の印の検査を外す部分は「軽くなる」。
- トピック別まとめの「変えるときの条件」では、RFD0083（観測の重ね → 転送 → 正規化の並びと乱数の消費の順）、RFD0161 §6.5 D35 と RFD0200 §5.5 D25（4 環境の同 seed・決定的な Run で scalar と trace の全レコードの一致）、RFD0200 §5.1 D1（開始の印は CPU の真偽値のまま）が当たる。
- テスト: `dqn_concrete_test.cpp:388-488`（印の衝突、印が残る部品）、`dqn_learner_test.cpp:4225`（`LearnerPerceptionSetup`）が通す。`CompletePerception` と `RequirePerceptionSpecs` を名指しで呼ぶテストは無い（検索 0 件）。
- 不採用の形・ADR との突き合わせ: ADR 0084 の「定義を持つクラス 1 つから各経路が部品を取り出して並べる形 — 却下」には当たらない（部品は取り出さず、依頼の Forwarder を返すだけ）。ADR 0095・0096 は守る。RFD0128 §5.1 の「DQN 系の共通部品が DefaultDQN の渡す入力をすべて必須で受ける形 — 不採用」により、Learner の Perception は任意のままにする（Rainbow は渡さない）。
- [issue-20261122-258ef8](issue-20261122-258ef8.md)（統計の読み書きの競合）と [issue-20261122-4c0af5](issue-20261122-4c0af5.md)（ためる仕組み）とは別の原因である。
