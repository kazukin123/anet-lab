## 背景

2026-11-28 の監査（観点 test-gap、範囲 311_dev_tools）で見つけた。定点統計の「テスト負債」は C++ が対象なので、Python ツールは実行の入口と既存のテストを突き合わせた。開発者への質問はしていない。

## 事象

- [DropMerge Optuna の設計](../../memo/done/0016_dropmerge_optuna_10rfd.md#L145)は、seed run の一部が失敗した trial を、成功した seed だけで集計せず `FAIL` として扱うと定める。
- [optuna_common.py](../../../apps/tools/optuna_common.py#L3033) の `execute_study_trial` は途中で Runner が失敗すると、その時点までの seed の結果と失敗理由を要約と trial 属性に保存して終了する。[`execute_asked_trial`](../../../apps/tools/optuna_common.py#L3159) は失敗を Optuna の trial の状態に反映する。
- [optuna_workspace_test.py](../../../apps/tools/optuna_workspace_test.py#L122) には保存先と再開引数の検査があるが、成功する CLI 試験は `--n-trials 0` であり、複数 seed のうち2本目以降を失敗させる試験は見当たらない。optuna_metrics_gzip_test.py が通すのは指標ファイルの選択である。

## 影響

たとえば seed 1 が成功し、seed 2 が失敗したときに、seed 1 の値だけで trial を成功扱いする変更が入っても既存の試験では検出できない。成功した trial として探索結果に残ると、次に選ぶパラメータに影響する。

## 対応方針

一時 workspace と代役の Runner で、1本目は既知の指標を出して成功し、2本目で非ゼロ終了する `run-study` を1 trial 回す。Optuna の状態が `FAIL` で trial value が無いこと、保存された要約に成功と失敗の2本が残ることを確かめる。
