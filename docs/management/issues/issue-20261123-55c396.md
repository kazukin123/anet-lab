## 背景

2026-11-23 の監査（観点 refactor、範囲 324_dqn）で見つけた。観点は `docs/quality/refactor.md` の「共通処理の置き場違い」と「不要コード」である。開発者には質問していない。

ProfiledValue の設定は、値を 1 つ書く形（`key = 0.99`）と、配下に type・value などを書く形（`key.type = linear` ほか）がある。任意の ProfiledValue（書かれていなければ使わない、または既定を持たない）を読むには、まず「key 自体か key の配下が書かれているか」を調べる。設定の型を読む共通の口 `ConfigReader<std::optional<T>>`（`src/core/base/include/anet/config.hpp:349`）は、1 つの値の設定キーだけを扱い、ProfiledValue を `static_assert` で受け付けない。

ホットスポット補正: `default_dqn_agent.hpp` は 90 日の変更回数が 5 回で、src の中で最も多い（`reports/stats/stats.json` の `flow.churn90`。RFD0182 の配置の移動のあとのパスで数えた値）。urgency を 2 から 3 へ 1 段上げた。

## 事象

- 「書かれているか」を調べる処理が、`DefaultDQNAgentConfig` の中に 3 か所あり、書き方が違う。
  - `ReadActors`（`default_dqn_agent.hpp:412`〜419 行）: Actor の配下の相対キーを回し、`leaf == "sync_interval" || leaf.starts_with("sync_interval.")` で調べてから `std::optional` を emplace して読む。
  - `ReadValueDecomposition`（232〜242 行）: 全体の設定を回し、既定の接頭辞のキー `gamma_key` と override の接頭辞のキー `gamma_override` のそれぞれに `key == X || key.starts_with(X + ".")` を当てて `has_gamma` を作る。
  - `FinalizeActors`（704〜717 行）: Actor の読み取り範囲を回し、既定と override の接頭辞のキーに同じ式を当てて、見つかれば `entry.skip.max_length` を emplace して読む。
- `DefaultDQNAgentConfig` は `anet::Config(config_data, "DefaultDQNAgent")` の 2 引数の構築（`default_dqn_agent.hpp:103`）だけで作られ、override の接頭辞は常に空である（`src/core/base/src/config.cpp:906` の構築は `override_prefix_` を設定しない）。そのため、上の 2 か所の `!GetOverridePrefix().empty() && (...)` の分岐（237〜238 行、709〜710 行）は通らない。`algo/` で `GetOverridePrefix`・`MakeOverrideConfigKey` を使うのは、この 2 か所と ImageCls の設定（`image_cls_agent.hpp:80`）だけである（検索語 `GetOverridePrefix\|MakeOverrideConfigKey`）。
- 3 つの設定キーを書くテストは、`sync_interval` が 38 行、`learner.intrinsic.gamma` が 11 行、`skip.max_length` の配下（`.max_length.`）が 5 行ある（`src/algo/dqn/src/*_test.cpp`）。

## 影響

- 任意の ProfiledValue を 1 つ足すたびに、同じ判定をもう 1 回書く。書き方が 3 通りあるので、読む人はどれに倣うかを選ぶことになる。
- override の接頭辞の分岐は、通らない経路を読む手間だけがある。

## 対応方針

- 「ProfiledValue の key 自体か配下が書かれているか」を、ProfiledValue の読み口（`src/core/base/include/anet/schedule.hpp` の `ConfigReader<ProfiledValueConfig<T>>` のそば）か `Config` の共通の口として 1 つ置き、3 か所がそれを呼ぶ。`std::optional<ProfiledValueConfig<T>>` を読む口にしてもよい。override の接頭辞の扱いはその口に任せ、`DefaultDQNAgentConfig` の分岐を消す。
- 挙動を変えない。[324_dqn のトピック別まとめ](../../wiki/categories/324_dqn.md) の「変えるときの条件」のとおり、設定キー、ログと WARN・ERROR の文言・順・回数、Agent が記録する設定（`my_config_json_` と完全キーの表）を変えない。上の 3 つの設定キーを書くテストが、期待値を変えずに通ることを確かめる。
- 設定の読み込みは起動時だけなので、性能の区分は「関わらない」。
