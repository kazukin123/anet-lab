## 背景

[RFD0204](../../memo/0204_branch_merge_conflict_assist_10rfd.md) は、ブランチを main へ取り込むときの衝突を解く仕組みを決めた。そのグリル（2026-11-27）で、衝突を起こさない仕組み（採番がほかのワークツリーとブランチを見る）は別の関心として範囲外にし、別の課題の候補にすると合意した（RFD0204 の D19）。この課題は、RFD0204 の完了報告で示した起票の候補から、開発者が「新規で起こす」を選んで起票した。

## 事象

- [memo README](../../memo/README.md) の「採番」は、RFD の番号を最大の番号の次から取る。ADR も、`docs/adr/` の最大の番号の次を取る（[ADR-FORMAT.md](../../../.agents/skills/anet-create-rfd/ADR-FORMAT.md) の「Numbering」）。どちらも、ほかのワークツリーのファイルと、main にまだ入っていないブランチのコミットを見る手順を持たない。
- 2026-11-25、ワークツリーのブランチ `feature/20261125-ppo` と main が、同じ RFD0202 を別の RFD に振った（[RFD0204](../../memo/0204_branch_merge_conflict_assist_10rfd.md) の §3・§5.1）。
- 2026-11-26、同じ作業ツリーの中で、RFD0204 の起票のときに番号を引いた時点では 0203 が空いていたが、書く直前に別のセッションが 0203 を取った（RFD0204 の §3）。
- RFD0204 は、振り直すときの空き番号の引き方（ローカルのブランチと手元にあるリモート追跡の参照の全部と、全部のワークツリー（未追跡のファイルを含む）の `docs/memo`・`docs/adr` のファイル名の最大の次）を決めたが、これは重なりを解くときだけの手順である（RFD0204 の D14）。

- 2026-11-28 監査（test-gap）: [memo の採番](../../memo/README.md#採番) はファイル名と Git 履歴を確認する規則のままで、ほかのワークツリーの未追跡ファイルを探す手順は、通常の採番には入っていない。

## 影響

- ブランチをまたいで番号が重なると、取り込むときにブランチの側の振り直しが要る。振り直しは、改名、テストのタグの直し、ビルドとテスト、振り直しの行のコミットの名指しを伴う（RFD0204 の D14・D15）。
- 同じ作業ツリーで番号を取り合うと、書く直前に番号を引き直す手戻りが出る。並行のセッションが多いほど起きる。

## 対応方針

未定。

- 2026-11-27 RFD0204: 案の材料。採番のときに、RFD0204 の D14 と同じ範囲（全部のブランチ、手元のリモート追跡の参照、全部のワークツリーの未追跡のファイル）を見る形が考えられる。同じ作業ツリーの取り合いには、番号を引いてからファイルを置くまでの間を短くするか、番号を押さえる仕組みが要るかを決める。[RFD0204](../../memo/0204_branch_merge_conflict_assist_10rfd.md)
