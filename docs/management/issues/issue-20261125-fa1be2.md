## 背景

2026-11-25 の監査（観点 refactor、範囲 321_agent_core）で見つけた。観点の分類は「可読性（直観との不一致）」で、「命名」「1 関心 1 機構違反」が付随する。開発者には質問していない。

ADR 0036（2026-09-04）は「Actor へ渡す `ActorQHintConfig` が `MunchausenConfig` と TBO を持つ」「ヒントを出すかは `emit_actor_q_hint`」を決めた。当時はヒントだけの設定で、RFD0121（2026-11-15）が分解・β・割引率を足して意味が広がった。

ホットスポット補正: `dqn_actor.cpp` は、`git log --since=2026-08-27 --follow` で 90 日に 9 回変わっており、コードのファイルの上位 5%（7 回以上）に当たる。urgency を 3 から 5 へ 1 段上げた。

## 事象

- `ActorQHintConfig`（`dqn_actor.hpp:224-233`）は `munchausen`・`use_tbo`・`tbo_epsilon`・`gamma`・`decomposed`・`beta`・`extrinsic_bootstrap`・`intrinsic_gamma` を持つ。
- `dqn::Actor` はこの設定で、行動の forward に掛ける β と合わせた Q を作るか（`dqn_actor.cpp:1525-1528`）、価値の分解の診断を作るか（1552〜1577 行）、`effective_gamma`・`effective_intrinsic_gamma`・Munchausen の値（1579〜1582 行。step 診断と Trace が読む）を決める。ヒントを作るのは 1585〜1603 行だけで、ヒントを出すかは別の引数 `emit_actor_q_hint_` が決める。
- そのため、ヒントを出さない Actor（評価の Actor、`per_initial_priority_mode` が `actor_approx` でない構成）でも、この設定が行動の選び方を決める。Rainbow は、行動の選択と関係の無い 2 欄だけを渡す（`rainbow_agent.cpp:128`）。
- 検索語: `actor_q_hint_config_`（`dqn_actor.cpp`）、`ActorQHintConfig`（本番の構築 2、テストの構築 4）。

## 影響

- 「ヒントを使わないなら関係ない設定」と読めるので、行動の β や分解を変える作業（RFD0183 の TempoRL の後続、RFD0142 の直前の行動、[issue-20261103-f33167](issue-20261103-f33167.md) のノイズのラダー）で、直す場所として見落とす。
- 行動の選択だけを変えたいテストが、ヒントの設定を組み立てる（`dqn_actor_test.cpp:1442`・2736）。

## 対応方針

- 設定を 2 つに分ける。行動の選択（分解、β、TBO、Head ごとの割引率、Munchausen の値。名前は `CONTEXT.md` の語で決める）と、ヒントの作り方（`extrinsic_bootstrap` ほか）。`emit_actor_q_hint` はヒントの側に入れる。設定キーは変えない（内部の構造体だけ）。
- 性能の区分は「関わらない」（構築時の受け渡し。step の計算は同じ）。
- トピック別まとめの「変えるときの条件」では、RFD0094 §4.2 D6・D7（actor_approx の同 seed・決定的 Run の checksum）、RFD0161 §6.2 D11、RFD0101 §4.4 D19（α・τ が Actor・step 診断・Learner で同じ step の同じ値）が当たる。
- テスト: `dqn_actor_test.cpp:1442`・2736、`dqn_munchausen_test.cpp:273`・305 が `ActorQHintConfig` を名指しで組み、`dqn_intrinsic_test.cpp:1394` が Actor ごとの β を通す。
- 不採用の形との突き合わせ: Learner の設定全体を Actor へ渡す形（ADR 0036 で棄却）にはしない。ADR 0075（ヒントの列の数をモードで変えない）にも触れない。
- [issue-20261111-4351bc](issue-20261111-4351bc.md)（Actor の mutable と一時値）とは別の原因である。
