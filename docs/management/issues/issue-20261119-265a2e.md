## 背景

[PRD182](../../memo/0182_source_layout_10rfd.md)（ソース配置の見直し）のグリルの調査（2026-11-17〜18）で見つかった（同書 §2.2）。同書は、公開ヘッダに置くものを「基盤の外で書けると宣言した拡張点の interface・部品・登録口の一式」と決め、Body を組む型（`NetworkBody` など）は内部に残す（同書 §4.1 の D6、§5.6）。工程末の候補から開発者が選び、起票した。開発者への質問はしていない。

## 事象

- 公開ヘッダ `core/anet-core/include/anet/nn.hpp` の `Network` のコンストラクタ（201 行から。2026-11-19 の行番号）は public で、引数に `std::shared_ptr<NetworkBody>` を取る。
- `NetworkBody` は、同じヘッダでは前方宣言だけである（185 行）。定義は内部ヘッダにある。
- 公開ヘッダに `NetworkBody` が出るのは、前方宣言、このコンストラクタの引数、メンバ `body_`（251 行）の 3 行である。
- 設定から Network を作る公開の入口は、同じヘッダの `NetworkBuilder::BuildNetwork`（396 行）である。
- 2026-11-23 監査（backlog）: 依存先 2dd820 は解決した。RFD0182 で基盤のテスト用の口ができ、`src/core/base/include/anet/test/nn.hpp` に `anet::test::MakeTestNetwork` がある。`Network` のコンストラクタは今も public のまま `std::shared_ptr<NetworkBody>` を取る（`src/core/base/include/anet/nn.hpp:205-211`）。

## 影響

公開のコンストラクタが、基盤の外からは組めない引数を取る。PRD182 の公開ヘッダの規約を入れたあとも、公開ヘッダに、見えるが基盤の外からは使えない入口が残る。

## 対応方針

未定。案: コンストラクタを公開の面から外し、`NetworkBuilder` と、基盤のテスト用の口だけが呼べる形にする。PRD182 のステージ 3（基盤の公開面とテスト用の口）のあとに決める。
