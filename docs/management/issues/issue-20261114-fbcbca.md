## 背景

ADR（`docs/adr/`）は「なぜ今この形か」の記録で、[AGENTS.md](../../../AGENTS.md) の「設計判断の記録(ADR)を読む条件」に、契約・構造を変えるときなどに読むと決めてある。たどり方は次の 4 つが決まりにある。

- ファイル名の一覧から領域の語で探す（AGENTS.md の ADR の節、anet-create-prd の質疑）。
- 設計文書に該当の章があれば、そこからの参照を優先する（AGENTS.md の ADR の節）。
- wiki のトピック別まとめの「成立の経緯」から PRD と ADR をたどる（AGENTS.md の wiki の節、2026-10-19 の PRD095 から）。
- PRD が挙げる ADR を読む（anet-impl-prd、anet-create-prd の改訂）。

2026-11-14 に、開発者の依頼で、ADR が wiki などを通して使われているかを調べた。改善の方向の選択肢（取り込みを回す・入口の方針を決める）を示したが、開発者は選ばずに、課題として記録するよう指示した。方針は決めていない。

## 影響

- 取り込み遅れの間は、トピック別まとめから新しい ADR（0069〜0071）と改訂の注記へたどれない。AGENTS.md の「成立の経緯から PRD と ADR をたどる」道筋で見落とす。
- ハーネスの判断（0056・0061・0069 など）には、トピック別まとめという入口が無い。
- ADR を一番多く開くのはサブエージェント（レビュー・調べ物）で、wiki をほぼ通らない。トピック別まとめの「選ばなかった形」「変えるときの条件」を見ずに判断し、ファイル名で当たらない ADR を見落とす恐れがある。
- 入口が 4 つに分かれていて、どれが主なのかが決まっていない。設計文書から参照されていない ADR は 51 件あり、anet-audit の drift の観点（設計文書から参照されていない ADR）で拾うと、これがすべて当たる。

## 対応方針

未定。案は次のとおり。

- 案 1：wiki の点検と取り込み（anet-lint-wiki・anet-ingest-wiki）を回して、取り込み遅れの 9 件を片づける。定常の作業で、方針は要らない。
- 案 2：ハーネスのファイル（`.agents/`・`docs/process/`・`docs/quality/`）を受ける機能カテゴリを作るかを決める。作れば、ハーネスの ADR にトピック別まとめの入口ができる。
- 案 3：ADR の入口の方針を決める。トピック別まとめを主の入口にするなら、anet-audit の「設計文書から参照されていない」の観点を外すかも決める。ただし、実際の主な経路は PRD とファイル名の検索で、wiki 経由は 1〜2 割である（事象の表）。入口をトピック別まとめに一本化する案は、今の使われ方と合わない。
- 案 4：サブエージェントの依頼文か手順（anet-review-agent など）に、トピック別まとめを引く段を入れるかを決める。ADR を一番多く開くのがサブエージェントなので、wiki の入口を強めるならここが効く。
- 案 5：案 1 のあとにも、トピック別まとめに載らない ADR が残るかを見て、原因を 1 件ずつ確かめる。[wiki の規約](../../wiki/README.md)は、まとめに載せる ADR を「経緯に載せた PRD が挙げる ADR と、設計文書の章が挙げる ADR」に限っている。この決まりから外れたのが原因と見ているが、確かめていない。

案 2〜4 は別々に決められる。PRD を起こすなら、親と子に分けることを検討する。
