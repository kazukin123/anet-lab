## 背景

2026-11-23 の定常整備（anet-audit、観点 drift・範囲 CONTEXT.md）で見つけた。分類は未文書。直すのは文書だけと見立てた。sim_step は issue-20261123-ad7829 が扱うので、ここでは扱わない。工程の中で開発者に質問はしていない。

ホットスポット補正: 直す場所の `CONTEXT.md`（churn90 が 63）は、2026-11-18 の定点統計で全ファイルの上位 1% に入るので、`urgency` を 2 から 3 へ 1 段上げた。

## 事象

- [CONTEXT.md](../../../CONTEXT.md) は、exp step（31・155・225〜226・577 行）、train step（225 行）、agent step（97・101・441 行）、lane（24 か所）を、定義なしで使う。
- step の軸の定義は [010](../../design/010_framework_overview.jp.md) §3.3 にしか無い。コードでは `StepCounts`（`src/core/base/include/anet/rl.hpp` 106〜112 行）と、メトリクスの軸（`src/core/base/src/metrics.cpp` 48〜49 行）に当たる。
- `$agent_step` は Evaluation Trace の列の取り出し先（Agent の step 診断）で（metrics.cpp 136 行、設計 214 の 118 行、020 の 576 行）、単位としての agent step とは別のものである。
- lane は 010 §3 の表にも無い。

## 影響

軸・interval・設定キーに名前を付けるとき（AGENTS.md の「用語(CONTEXT.md)を引く条件」）に、update_step と learn_step、agent step と `$agent_step`、agent step と exp step・エミュレータのフレームを取り違える。

## 対応方針

文書だけを直す見立て。010 §3.3 を正として、train・exp・update・learn の各 step、agent step（`_Avoid_` に `$agent_step` との取り違えを書く）、lane の項を足す。
