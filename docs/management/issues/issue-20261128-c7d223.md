## 背景

2026-11-28 の監査（観点 test-gap、範囲 311_dev_tools）で見つけた。BTR の Q*bert 実験の結果は、この変換器で Metrics Viewer から読める Run に変換された。定点統計の「テスト負債」は C++ が対象なので、Python ツールは実行の入口と既存のテストを突き合わせた。開発者への質問はしていない。

## 事象

- [btr_to_metrics.py](../../../apps/tools/btr_to_metrics.py#L110) の `eval_step` と `emit_evals` は、評価点の元の行番号から `exp_step` を計算し、ゼロだけの行を読み飛ばす。[`write_run`](../../../apps/tools/btr_to_metrics.py#L348) は指標の定義と値を `metrics.jsonl` に書く。
- 既存のツール・検証資材を `btr_to_metrics`、`emit_evals`、`eval_step` で検索した。BTR の `Experiment.npy` と `Evaluation.npy` を用意して CLI を呼び、評価時点、tag、値の組を検証するテストは見当たらない。

## 影響

評価配列の途中にゼロだけの行があるとき、空行を除いた連番を評価時点に使う回帰が入ると、それより後の評価点が実際より早い時点に並ぶ。生成した Run 自体は開けるので、anet の Run と並べて比較するときに時点のずれを見落としうる。

## 対応方針

一時ディレクトリに少量の合成 `Experiment.npy` と、途中にゼロ行を挟んだ合成 `Evaluation.npy` を置き、`--skip-checkpoints` で CLI を回す。評価点がゼロ行の位置を飛ばした `exp_step`、評価用の tag、平均値・閾値到達率で出力され、定義と値を既存の指標リーダーで読めることを確かめる。
