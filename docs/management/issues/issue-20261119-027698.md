## 背景

2026-11-19 の会話で、開発者が、今の RND の実装を Burda らの論文（[arXiv 1810.12894](https://arxiv.org/abs/1810.12894)）と比べるよう求めた。AI は論文の §2.3・§2.4・§3.3〜3.5 と付録 A.2〜A.5（擬似コードと表 2〜5）を読み、設定で変えられる差と Run の規模の差を除いて、実装に無いか実装の作りが違う要素に絞った。そのうちの 1 つで、開発者が起票を指示した。開発者への質問はしていない。

## 事象

- 論文の内的報酬は、target と predictor の出力の差の二乗ノルム（付録 A.2 の Algorithm 1）である。§2.4 で、内的の収益の標準偏差の移動推定で割って正規化する。表 2 で内的報酬の clip は無く、平均も引かない。
- anet の whiten は、α = 1 ＋（e − μ_e）÷ σ_e を返す。`intrinsic.rnd.error_norm.use_centering = false` のときは 1 ＋ e ÷ σ_e になる（[intrinsic_rnd.cpp](../../../core/anet-core/src/intrinsic_rnd.cpp) の 297〜300 行）。`multiplier_mode = clipped` なら [1, L] に切る。`variance_feedback` は Taiga らの再帰統計で別に正規化する。どの統計の方式も、誤差の統計で割らない値（生の e）は返さない。
- 内的報酬用の報酬スケーラの `return_std`（[PRD121](../../memo/121_extrinsic_intrinsic_value_decomposition_10prd.md)、[214](../../design/214_value_decomposition.jp.md) §4.2）は、lane ごとに R = γR ＋ r を持ち、R の標準偏差で r を割る。分解して内的の割引率を別にしたときは、その割引率を使う。
- そのため、論文の形に寄せる設定を組むと、e ÷ σ_e をさらに内的の収益の標準偏差で割る形になる。
- e は、anet では出力の次元で平均した二乗誤差、論文では二乗和である。違いは定数倍だけで、正規化で消える。

## 影響

- σ_e は Run の中で変わる（累積の統計なら序盤の大きな誤差を含む）。そのため、2 回割った値は論文の値に比例せず、内的報酬の時間の変わり方が論文と違う。
- Burda らの形を再現した比較を組むとき、内的報酬の式だけは論文に合わせられない。

## 対応内容

- 2026-11-22 PRD191 の再グリル: 誤差の式のモード（`rnd.error_norm.mode = standardize｜none`。D4）、割らない式の待ちの間に内的報酬スケーラの統計を実際の値で育てること（D3）、clip を誤差のモードごとに持つこと（D9）を決めた。確かめ: PRD のレビューが 3 往復目で OK。[PRD](../../memo/191_rnd_raw_error_and_recent_learning_10prd.md)
- 2026-11-22 PRD191 の実装: none の倍率と、採点前の待ちの判定に基づくスケーラ後の報酬の抑止を実装した。return_std の待ち 0 と待ち 4 で統計が一致し、待ちが明けて最初の報酬が一致した。 [実装記録](../../memo/191_rnd_raw_error_and_recent_learning_20impl.md)
