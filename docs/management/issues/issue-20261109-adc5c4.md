## 背景

[issue-20261103-e29c92](issue-20261103-e29c92.md)（4 つの Repository の重複と、重複登録の扱いの食い違い）を、2026-11-09 の課題のメンテで分けた子である。分けることは、AI が挙げた統合・分割の候補から開発者が選んだ。重複登録の扱いをそろえる部分（[issue-20261109-1499d0](issue-20261109-1499d0.md)）は小さな直しで先に済ませられ、こちらは構造の整理なので別々に直せるため、分けた。

## 事象

Agent・Env・View・NN モジュールの 4 つの Repository が、singleton・mutex・名前から factory への map・登録関数を、それぞれ別に持つ。登録と取り出しの関数名もそろっていない。2026-11-09 にコードで確かめた。

- core/anet-core/include/anet/agent.hpp:361 `AgentRepository`: 登録は `Register`、取り出しは `GetAgentFactory`
- core/anet-core/include/anet/env.hpp:287 `EnvRepository`: 登録は `Regist`
- core/anet-core/include/anet/gui.hpp:382 `ViewRepository`: 登録は `Register`、取り出しは `GetViewCreator`
- core/anet-core/src/nn_impl.hpp:468 `NetworkModuleRepository`: 登録は `Register`、取り出しは `GetFactory`
- 自動登録のマクロも、core/anet-core/include/anet/agent.hpp:429 の `ANET_REGISTER_AGENT_FACTORY` と core/anet-core/include/anet/gui.hpp:501 の `ANET_REGISTER_VIEW_CREATOR` で同じ形を写している

## 影響

未登録の名前のエラー文や、登録済みの名前の一覧の出し方を変えるにも、4 か所を別々に直すことになる。1 か所の直し漏れで、Repository ごとに振る舞いが食い違う（重複登録の扱いが既にそうなっている）。

## 対応方針

名前付きの factory の Repository をテンプレート 1 つにまとめ、関数名をそろえる。重複登録の扱いは [issue-20261109-1499d0](issue-20261109-1499d0.md) でそろえた形を引き継ぐ。使われていない自動登録のマクロの削除は、[PRD945](../../memo/945_outside_core_extension_layout_10prd.md)（anet-core の外で実装する拡張点の規約）の受入が持つので、そちらで扱う。

## 対応内容

- 2026-11-11 リファクタリング候補の抽出: Repository の利用側で、状態を持たない Factory・Creator のクラスを 1 つずつ書いている形を足す。Repository が登録するものを `std::function`（または型を引数に取るテンプレート 1 つ）にすると、次のクラスが消える。(1) NN モジュール: nn_modules.cpp の NetworkModuleFactory の派生 29 個はどれもメンバ変数を持たず、うち 10 個は `return std::make_shared<XModule>();` の 1 行だけである。型を渡して登録する `RegisterNetworkModuleFactory<T>`（nn_impl.hpp）は、呼び出しがコメントアウトの 1 行だけである。(2) View: `ViewCreator` の実装 6 つは、どれも `CreateView` が `make_shared<XxxView>(parent)` の 1 行で、引数 `config_data` と `notifier` を使わない。`DefaultViewFactory`（gui.hpp:411）は `config_data_` を渡すだけで、構築も呼び出しも RunnerApp の 1 か所ずつである。6 つの View のコンストラクタも `window_ = new XxxPanel(parent_)` の 1 行で、`GetTargetClassId` は Env 側の class_id と同じ文字列を別に書いている。(3) Env: Atari・GridMaze・CartPole の工場の `CreateSingleEnv` は型の名前を除いて同じ 2 行で、登録関数 4 つも 2 行ずつ、公開ヘッダは宣言 1 行ずつである。Atari の `GetDefaultConfigPrefix` の上書きは基底の既定と同じ値を返し、CartPole の工場のコンストラクタは空である。Repository をテンプレートにまとめるときに、登録するものの形も一緒に決めると、Env・View・NN モジュールを 1 つ足すときの写しが無くなる。確かめ: ViewCreator・DefaultViewFactory と Factory の位置を今のコードで確かめた。
