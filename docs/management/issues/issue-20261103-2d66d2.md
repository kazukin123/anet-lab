## 対応内容

- 2026-11-11 リファクタリング候補の抽出: 排他の精査の材料として、DefaultDQNAgent の値の読み出しを足す。`GetScalar`・`GetTensor`・`GetTensorVector`（default_dqn_agent.cpp:498、594、612 から）に、`std::shared_lock<std::shared_mutex> lock(*mutex_); return X->Get...(key);` の同じ 2 行が 9 回ある。ロックの有無が分岐ごとに違い、`intrinsic.` は atomic を読むのでロック無し、`target_policy.` はロック無しで `target_policy_->GetScalar` を呼ぶ（書く側は排他ロックの中で更新する）。ロック無しでよい理由はコードに書かれていない。接頭辞の比べ方も `starts_with`・`anet::StartsWith`・`find(...) == 0` の 3 通りが混ざる。「接頭辞→渡す先→ロックの要否」の小さな表にし、ロック無しの分岐に理由を書くと、精査の対象が 1 か所にまとまる。確かめ: 9 回の対と 3 つの関数の位置を今のコードで確かめた。`target_policy_->GetScalar` をロック無しで呼んでよいかは確かめていない。

監理の項目はAIの見立て（棚卸しの前）。AIの判定は移行時のコミット条件による見立てで、棚卸しで確認する。
