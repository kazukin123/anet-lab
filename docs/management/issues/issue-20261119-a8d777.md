## 背景

2026-11-19、課題の kind を「コード／文書／ハーネス」に分ける作業（PRD に沿わない変更）の中で、`reports/tools/wiki_support.py maps` を回して見つかった。今回の変更とは別の検出として開発者に示し、開発者が起票を選んだ。原因について開発者に質問はしていない。

## 事象

- `maps` を回すと、docs/wiki のトピック別まとめ 16 本の「PRD の一覧」から 199 行が消え、足される行は 0 行である。消えるのは、PRD046・053・054・061・069・076・097・103 など、過去の PRD の行である（例: `docs/wiki/categories/311_dev_tools.md`）。
- 「PRD の一覧」は、`wiki_support.py` の `prd_rows`（233 行から）が、ページに当たるファイルの `git log --date=short --format=%ad%x09%s -- <files>`（239 行）の件名から PRD 番号を拾って作る。改名をたどる指定は無い。
- PRD182 のコミット `f25ff82b`（ソース構成と実行時データの配置の再編）は、117 件の改名を含む。HEAD のトピック別まとめを最後に更新したのも、このコミットである。
- 原因は、移動後のパスで `git log` を引くと移動前のコミットが出ないためと見ている。確かめてはいない。

## 影響

- 誰がどの工程で `maps` を回しても（起票のたびに回る）、トピック別まとめの「PRD の一覧」から過去の PRD が落ちる。気づかずにコミットすると、wiki から過去の PRD への入口が消える。
- `anet-prepare-commit` は、消えた行をコミット済みの番号の「追いつき」としてコミット候補に挙げるので、コミットのたびに対象から外す判断が要る。

## 対応方針

未定。案は、改名をたどって履歴を引く（`git log --follow` は 1 つのパスにしか効かないので、ファイルごとに回す費用を測る）か、改名の対応表を作って移動前のパスも引くこと。

## 対応内容

- 2026-11-19 この場で直す: `reports/tools/wiki_support.py` に、全コミットの履歴を `git log -M --name-status -z` で 1 回だけ読み、改名をたどって各コミットが触ったファイルを今のパスに写す `commit_history` を足した。`prd_rows` は、その履歴をページのファイルと突き合わせて PRD 番号を拾う形にし、`maps` は履歴を 1 回だけ読んで全ページに渡す。`src/core/base/testdata/prd095/wiki_test.py` に、移したファイルの移す前のコミットの PRD が残り、関係の無いファイルのコミットは数えないテストを足し、既存のテストの履歴の差し替えを新しい出力の形に合わせた。確かめ: `wiki_test.py` 17 件と `issues_test.py` 32 件が通った。`maps` を回すと、HEAD と比べた「PRD の一覧」の差は、199 行の削除から、削除 11 行・追加 3 行になった。残った差は、PRD182 で分類の範囲から外れたファイル（`apps/runner/config/*.txt` など）と、分けて消したファイル（`core/anet-core/src/dqn_based_agent_test.cpp`）の履歴によるもので、改名の追い漏れではない。
