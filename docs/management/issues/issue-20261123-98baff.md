## 背景

[RFD0195](../../memo/0195_document_term_rfd_and_4digit_numbers_10rfd.md)（文書の呼び名を RFD に改め、番号を 4 桁にする）の受入 A2・A13 は、[memo README](../../memo/README.md) の「リンクの注意」のリンク切れ検査が何も出さないことを求めていた。実装で検査を回すと、実装の前から切れていたリンクが多数出て、受入を満たせなかった。直すと RFD0195 の範囲（名前と番号の形）を超えるので直さず、工程末に起票の候補として示し、開発者が起票を選んだ。

- 2026-11-23 RFD0195: 開発者が、RFD0195 の受入 A2・A13 に残るリンク切れを受入の対象外とし、受入の条件の課題 [issue-20261123-2338c0](issue-20261123-2338c0.md) を閉じた。リンク切れはこの課題で扱う。[実装記録](../../memo/0195_document_term_rfd_and_4digit_numbers_20impl.md)

## 事象

- 2026-11-23 に、RFD0195 の 1 回目と 2 回目のコミットを当てた使い捨ての clone で検査を回すと、`BROKEN` は 258 件だった。実装の前（HEAD `9183b046`）は 268 件で、RFD0195 で 10 件減った（昔の skill の名前を指すリンクを今のパスへ直した分ほか）。

- リンク先のうち 22 件は `.scratch` の下（追跡していない作業の置き場）を指す。23 件はリンク先に `.` を含まない（`int64_t rows` のように、コードの表記がリンクの形に読まれたものなど）。
- 一覧は `.scratch/rfd0195/broken_c18.txt`（実装の前は `.scratch/rfd0195/broken_before.txt`）。どちらも、リンク先の中の改行で 2 行に割れたものを含むので、行の数は件数より 2 多い。
- [RFD0114](../../memo/0114_findings_intake_and_fix_rfd_10rfd.md) の実装（2026-11-03）では、開始時からのリンク切れを 23 か所とし、受入を「増分 0 件」にしていた。
- 2026-11-23 RFD0195: 2 回のコミットのあとの実リポジトリでは、リンク切れの検査の `BROKEN` は 246 件だった。使い捨ての clone の 258 件との差は、検査がリンク先のファイルの有無で判定するためで（実リポジトリには `.scratch` の材料と未追跡の `docs/StampFly.md` があり、`docs/wiki/README.md` の `../../../README.md` は clone ではリポジトリの外にたまたまファイルがあった）、リンク切れの中身は同じ。一覧は `.scratch/rfd0195/accept_main/a2_broken.txt`。[実装記録](../../memo/0195_document_term_rfd_and_4digit_numbers_20impl.md)

## 影響

- リンク切れの検査を受入に使う RFD は、実装の前からのリンク切れで受入を満たせない（RFD0195 の A2・A13。[issue-20261123-2338c0](issue-20261123-2338c0.md)）。
- 新しく切ったリンクが 258 件の中に紛れ、検査の出力では見分けられない。実装のたびに、前後の一覧の差を取る手間がかかる。
