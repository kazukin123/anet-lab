## 背景

PRD161（観測パイプラインと強制行動の `MakeAction` 入力化）のグリル（2026-11-20〜22）で、stack の対象のキーは必ず stack 軸を持つと決め、NN の側は「branch の先頭の module で、軸の扱いを書く」決まり（PRD057）を保った（[PRD161](../../memo/0161_observation_pipeline_10rfd.md) の D27・D32）。そのとき、NN の入口が、離散の Grid だけは、定義に書かれないまま軸を畳んでいることが分かった。PRD161 は、stack 軸の見分け方だけを spec の属性に直し、畳む動きは変えない（同 D32）。

課題にするかは、グリルの中では質問していない。工程末に起票の候補として示し、開発者が記録すると選んだ。

## 事象

- NN の入口は、離散の Grid の入力を one-hot にするとき、stack 軸とクラスの次元を、チャネルへ畳む（[nn_impl.cpp](../../../src/core/base/src/nn_impl.cpp) の入口の変換）。
- ほかの入力（連続の Grid、vector）は、stack 軸を残したまま branch の先頭の module に渡り、畳み方は、module（`StackMerge`・`Flatten` など）が定義に書く（[130_neural_networks.jp.md](../../design/130_neural_networks.jp.md) の §2.2）。
- PRD161 を実装すると、入口は、次元の数ではなく、spec の属性で stack 軸のあるなしを見分ける。畳む動きは同じである。

## 影響

- 離散の Grid を受ける Network の定義を読んでも、stack 軸がどこで畳まれるかが分からない。
- 離散の Grid を、stack 軸を残したまま扱う module（時刻ごとに埋め込む、など）を足すとき、入口が先に畳むので、定義では書けない。

## 対応方針

未定。

着手の条件は、離散の Grid を、stack 軸を残したまま扱う module を足すときである。そろえる向きは 2 つある。入口の畳みをやめて、branch の先頭の module に書かせる（離散の Grid を受ける出荷設定の定義を直す）。または、入口の畳みを、決まりとして設計文書に書く。
