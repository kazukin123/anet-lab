## 背景

2026-11-25 の監査（観点 defect、範囲 321_agent_core）で見つけた。分類は境界（CPU/GPU）と例外である。開発者には質問していない。

コードの読みだけで、実行はしていない。libtorch の `Module::load` が parameter を差し替える所の実装は配布物に無く、device の扱いはヘッダのコメントで確かめた（下の事象）。起きることを確かめるには、CUDA の Agent を `Save` し、CPU の Agent で `auto_load_file` を指定して構築し、`GetOnlineParameters()[0].device()` と最初の `MakeAction` を見る短いテストが 1 本あればよい。

## 事象

- `NetworkModel::LoadCheckpoint`（`src/algo/dqn/src/dqn_network_model.cpp:297-313`）は `archive.ReadTorchObject(online_net_)`・`(target_net_)` を呼び、そのあと `eval()` だけを行う。device へ移すのは構築時だけである。
- `InputArchive::ReadTorchObject`（`src/core/base/include/anet/serialize.hpp:199-224`）は `torch::load(out_torch_obj, ss)`（219 行）を device 無しで呼ぶ。libtorch の `InputArchive::load_from` のコメントは「device を指定しなければ、元の device へ読む」と書く（libtorch 2.11 の `torch/serialize/input-archive.h`）。読んだ parameter の device と形を、今の Network と比べる処理は無い。
- 同じ口を、DQN の optimizer（`Learner::LoadCheckpoint`、`dqn_learner.cpp:1924`）、RND の target と predictor（`intrinsic_rnd.cpp` の `Load`）、ImageCls（`image_cls_agent.cpp`）が使う。
- 設計 200 の checkpoint の節は「Network構成とOptimizer payloadが互換である必要がある」、020 の 6.4 節は「Network構成やarchive contractが異なるcheckpointは読み込めない」と書くが、device と、形の検査が無いことには触れない。`ReturnStdRewardScaler::Save` は値を CPU に移して保存し、device をまたぐ読み込みを想定している。
- テスト: checkpoint の往復は CPU の中だけである（`dqn_concrete_test.cpp:1073`・1122・1449・2162、`dqn_intrinsic_test.cpp:815`〜1956、`dqn_learner_test.cpp:767`・2900・3503）。device をまたぐ読み込みと、形の違う読み込みを通すテストは無い。

## 影響

- 既定の `agent.device=auto`（CUDA）で学習した checkpoint を、ほかの設定は同じまま `agent.device=cpu`（`LunarLander.txt` が候補として書き、CPU 用の `run.@cpu` もある）と `auto_load_file` で読むと、online・target の parameter が cuda に載ったままになる。学習の Actor は `clone_model ?= false`（`agent.txt:441`）で online をそのまま使うので、観測を CPU へ移して forward した最初の step で、device の不一致の例外で止まる見込みである。CUDA の無い機械では `torch::load` が失敗して止まる。
- Network の構成の一部（`linear.out_features` など）だけが違う checkpoint は、読み込みでは止まらず、あとの処理で parameter の名前も設定キーも無いエラーになる。AGENTS.md の Fail-Fast 原則（発生点に近い早い段階で検出し、識別子と期待値を示す）と合わない。

## 対応方針

- `ReadTorchObject` に読み込み先の device を渡す（`torch::load(obj, ss, device)`）か、読み込みのあとで今の device へ移す。optimizer と RND の読み込みもそろえる。
- 読み込みの前後で parameter と buffer の形を今の Network と比べ、違えば名前・保存側の形・期待の形を示して止める。
- 同じ device・同じ形の checkpoint の読み込みの値は変わらない。hot path と乱数に触れない。
- 先に、上の短いテストで起きることを確かめる。
