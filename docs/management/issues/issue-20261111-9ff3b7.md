## 背景

2026-11-10〜11 のリファクタリング候補の抽出（C++ の本体を 16 単位に分けて読み、観点は docs/quality/refactor.md による）で見つかった。開発者が候補の一覧から選び、起票を指示した。2026-11-11 に今のコードで場所を確かめ直した。

ゲームごとの RAM メトリクスは、新しいゲーム（Montezuma など）を始める前に足していく（RAM の調べと Trace の列を Run より先に整える）ので、この記法の解析に当たり続ける。

## 事象

- RAM メトリクスの記法の解析。
  - `AtariEnvConfig` のコンストラクタ（core/envs/atari1/src/AtariEnv.cpp:378 から、72 行）のうち 41 行が RAM メトリクスである。設定値の読み取りと同じ関数に、正規表現 2 本の組み立て、全設定キーの走査、ゲームごとの定義の解析が並ぶ。
  - キーの形を 2 回確かめる。1 回目は既定のキーの正規表現に合わないキーを ERROR にし、2 回目は sub_key が `[..]` の形かを確かめる。
  - `run.eval.` で始まるか・`.env.ram_metric.` を含むか・正規表現に合うかの 3 条件の AND で判定するが、正規表現だけで同じ判定になる。`run.eval.[..].env.` という Run 側の設定の階層を、env の設定クラスが名指しで知っている。
  - ゲーム名の形の正規表現が、コンストラクタと `AtariEnv::ValidateConfig`（521 から）の 2 か所にある。
  - 実効設定への記録を `my_config_json_[...] =` で直接書く（439）が、基底の `Config::RecordConfigValue` が同じことをする。
  - `ParseRamMetricDefinition`（278 から）は、番地を `0x[0-9A-Fa-f]{2}` に全体一致させたあと `std::stoul` を try/catch し、読み残しも確かめる。全体一致を通った文字列でその 2 つの経路には入らない。2 つのエラーの文言も同じである。
  - reducer の名前は if の連鎖で読み、種別は `Begin` の条件・`Observe` の switch・ERROR の文言にも現れる。「`from_chars` で全部読めたかを確かめる」形が 3 か所にある。
- 縮小方式。
  - `resize_mode` は `std::string` で、`GrayscaleResizer` のコンストラクタも文字列で受け、中で `bool pixel_area_` に直す（core/envs/atari1/src/AtariPreprocess.cpp:71）。
  - 値域の検証が 3 か所にある。設定の読み取り（AtariEnv.cpp:385-392）、`AtariEnv::ValidateConfig`（525-526）、`GrayscaleResizer` のコンストラクタ（AtariPreprocess.cpp:79-87）。`pixel_area` のときの大きさの上限も 3 か所にあり、文言は層ごとに違う。
  - 今ある経路では、`ValidateConfig` の ERROR は読み取りの検証を通ったあとなので出ない。`GrayscaleResizer` の ERROR を出させるテストも無い。

## 影響

- 設定の読み取りを追うのに、記法の解析の細部を読むことになる。reducer を 1 つ足すと、enum・解析・`Begin`・`Observe`・ERROR の文言の 5 か所を直す。到達しない catch と重ねた検証が、どれが実際の関門かを分かりにくくしている。
- 縮小方式を 1 つ足すと、2 つの層の条件と文言、`pixel_area_` の bool（3 つ目の方式を表せない）を直す。

## 対応方針

- RAM メトリクスの読み取りを 1 つの関数（ゲーム別の定義と記録するキーの組を返す）へ出し、コンストラクタは呼ぶだけにする。reducer は名前と enum の表 1 つにし、番地は正規表現の一致のあと `stoul` と範囲の確認だけにする。記録は `RecordConfigValue` を使う。ERROR の文言は変えない。2 回目のキーの形の検査が実際に届くか（`MakeSubConfigData` がキーの途中の一致も拾うか）を先に確かめる。
- 縮小方式は enum にして、設定の読み取りで 1 回だけ文字列から直し、`GrayscaleResizer` は enum で受ける。`ValidateConfig` の検証は、設定の構造体を直接組み立てる使い方を認めるかを決めてから残すか消す。

## 対応内容

- 2026-11-12 PRD126: RAM 定義の読み取りを 1 関数へまとめ、語の名前と種別・引数の表から解析と診断を生成した。Run の階層を知る専用検査と届かない検査を除き、実効設定の記録は基底の処理を使った。縮小方式は読み取り時に `ResizeMode` へ変換し、重複した方式・画面寸法の検証を除いた。確かめ: Debug 全体ビルド、Atari の通常 55 テスト・1602 assertions、core の関連 49 テスト・1410 assertions が成功。旧語の結果・縮小画素・実効設定・診断は維持し、評価上書きは汎用の未読キー検査で拒否することを確認した。[PRD](../../memo/126_atari_ram_metric_distinct_and_bit_reducers_10prd.md)・[実装記録](../../memo/126_atari_ram_metric_distinct_and_bit_reducers_20impl.md)。
