## 背景

2026-11-10〜11 のリファクタリング候補の抽出（C++ の本体を 16 単位に分けて読み、観点は docs/quality/refactor.md による）で見つかった。開発者が候補の一覧から選び、起票を指示した。2026-11-11 に今のコードで場所を確かめ直した。

## 事象

- 2 つのクラスとも `is_recording_` と `local_episode_count_` を持つ（core/anet-core/include/anet/observers.hpp:301-303、460-461）。流れも同じで、エピソードの開始で、記録中なら強制終了の WARN を出し、`local_episode_count_ % episode_interval_ == 0` なら記録を始めて数を進め、終端（IsDone／IsTruncated）で記録を終える（core/anet-core/src/observers.cpp:704-767 と 1183-1234）。
- 開始と終端は lane 0 だけを見る（`BatchState` の IsDone などが添字 0 を読む）。そのことのコメントは Conv2d 側にだけある（observers.hpp:303）。
- 食い違いが 2 つある。
  - Conv2d は `episode_interval_` が 0 以下でも数を進め、開始のたびに INFO を出す（observers.cpp:714-731）。GraphViz は `episode_interval_ > 0` のときだけ開始の判定を通る（1192）。
  - Conv2d の終了の判定は、出力できたかどうかに関係なく通る（761-766）。GraphViz の終了の判定は `if (!provider) return;`・`if (!graph) return;` の後ろにあり（1221-1233）、出力できなかった step では通らない。
- Conv2d の 762 行の `if (is_recording_)` は、734 行で記録中でなければ戻ったあとなので、常に真である。
- 2 つのクラスを名指しするテストは無い（`Conv2dVisualizationObserver|GraphVizObserver|metrics\.graph` を `*_test.cpp` で検索して 0 件）。

## 影響

- 同じ規則が 2 か所にあり、既に食い違っている。どちらが意図かをコードから決められない。GraphViz では、エピソードの終端の step でグラフを出力できないと、記録中のまま次のエピソードの開始で強制終了の WARN が出る。
- エピソード単位で記録する Observer を 3 つ目に足すと、もう 1 つ写すことになる。

## 対応方針

先に、GraphViz の終了の判定が出力の成否に左右されるのが不具合かを決める。そのうえで「開始を知らせる・終端を知らせる・今記録中か」だけを持つ小さな部品へ状態 2 つを移し、2 つのクラスはそれを呼ぶ。ログの文言は各クラスに残す。テストが無いので、先に特性テストを足す。
