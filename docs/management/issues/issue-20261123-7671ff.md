## 背景

2026-11-23 の定常整備（anet-audit、観点 defect・範囲 318_rl_core）で見つけた。分類は境界。コードの誤りは確かだが、既定の構成で当たる経路は見つかっていない。工程の中で開発者に質問はしていない。

## 事象

- [rl.cpp](../../../src/core/base/src/rl.cpp) 461〜471 行は、index の無い device を `req_dev = cuda:0` に直したうえで、`gpu_ = std::make_pair(device, ...)` と元の `device`（index なし）をキャッシュの鍵として記録する。473 行は `gpu_->first != req_dev` で比べるので、同じ実体への 2 回目の呼び出しは cuda と cuda:0 の比較になり、`ANET_SYSTEM_ERROR` "GPU device mismatch" で止まる。
- 設定から来る device は index を持たない（`tensor_util.cpp` の ParseDevice の "cuda" と "auto"、`init_test.cpp` 209 行が index -1 を確かめる）。
- 起きる条件は、CPU にある行動（EvalPanel の強制行動。RFD0192 の後も結果の行動は CPU に残る）に、index の無い device で 2 回呼ぶこと。呼び出しの例は、`env.device = cuda` のときの `VectorizedDiscreteBatchEnv::Step` の `GetAction(device_)`（env.cpp 774 行）と、同じ step の learner 側の `GetAction(device_)`（dqn_learner.cpp 2162・2526・2641 行）である。
- 既定の構成は `env.device ?= cpu`（common.txt 56 行）。

## 影響

`env.device` を cuda にした構成で EvalPanel から手動の行動を打つなど、CPU にある行動を index の無い cuda で 2 回読む経路が通ると、Runner が "GPU device mismatch" で止まる。

## 対応方針

キャッシュの鍵に `req_dev` を記録する 1 行の直しにする。RFD0192 §5 D7（守りの無いキャッシュに守りを足さない）には触れない。確かめは、トピック別まとめの「変えるときの条件」の RFD0192 §5 D9（強制行動の device の扱い）による。毎 step の経路なので perf-neutral を確かめる（性能の区分は中立）。
