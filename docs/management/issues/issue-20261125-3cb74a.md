## 背景

2026-11-25 の監査（観点 defect、範囲 321_agent_core）で見つけた。分類は設定の検証である。開発者には質問していない。

設計 200 §9.8 は、勾配ノイズの測定を「単一損失・AdamW の用途に限定する」と書き、skip の損失を含めないことも書くが、価値の分解の split（損失 2 つ・optimizer 2 つ）を止めるかは書かない。RFD0092 は「複数損失・別 optimizer は別途」とする。今は、この限定を検査する所が無い。

ホットスポット補正: `dqn_learner.cpp`（改名の前の `dqn_based_agent.cpp` は churn90 が 41）は、コードのファイルの上位 1% に入る。urgency を 2 から 3 へ 1 段上げた。

## 事象

- split では、内的の損失を別の `intrinsic_optimizer_` で更新する（`dqn_learner.cpp:904-915`・1128〜1172 行）。`optimizer_` の側には、内的の Head の parameter の state が作られない。
- `CaptureGradientNoise`（1058〜1067 行）は、外的と内的を足した `weighted_element_loss` と、online の全 parameter と、`optimizer_` だけを `anet::MeasureGradientNoise` へ渡す。内的の Head の勾配は定義されるが `optimizer_` の state に無いので、Adam 版の前処理を作れず、その parameter の群と全体の群が未成立になる（`src/core/base/src/nn_util.cpp:120` の `group_valid[0] = group_valid[group] = false`）。
- raw 版は「足した損失」の勾配の統計で、split の実際の更新（損失ごとに clip し、別々の Adam で進める）のどちらの勾配でもない。
- 購読の検証 `ValidateDiagnosticSubscriptions`（393〜433 行）は、batch を割り切れない分割数と FP16 を止めるが、split を見ない。
- 出荷設定では、split（`FGS=DefaultDQNAgent.learner.intrinsic.feature_gradient=split`）は 11・12・13 の番号付き bat にあり、勾配ノイズの組（`metrics.scalar.@gradnoise`）と併用する段は無い。
- テスト: 勾配ノイズのテスト（`dqn_learner_test.cpp:3602`〜4004）は価値の分解を使わず、split のテスト（1770〜・1839〜）は勾配ノイズを購読しない。

## 影響

- 価値の分解の split の Run に `metrics.scalar.@gradnoise` を足すと、`49_agent_gradnoise` の Adam 版の tag（01・03・05 ほか）が Run の最後まで 1 点も出ない。理由を示す WARN も ERROR も出ない。raw 版には意味の合わない値が出る。
- 学習の値は変わらない。

## 対応方針

- 購読のときに split との組を止める（FP16 と同じ扱い）か、「この組では Adam 版を測れない」ことを Run に 1 回 WARN する。どちらにするかが 1 つの判断になる。学習と乱数に触れない。
- 設計 200 §9.8 の「単一損失・AdamW の用途に限定する」に、価値の分解の split を含むことを書く。
- split と勾配ノイズの購読の組の振る舞いを確かめるテストを足す。
