## 背景

RND の target と predictor は、DefaultDQNAgent の primary の Network とは別の 2 つの Network で、一生の新しさの推定器が持つ（[intrinsic_rnd.hpp:113-114](../../../src/core/base/src/intrinsic_rnd.hpp)）。どちらも畳み込みの層を持つ構成で使っている（Atari の `run.@rnd`）。

[PRD121](../../memo/0121_extrinsic_intrinsic_value_decomposition_10rfd.md) のお試し Run を見ていた開発者が、RND の Network が畳み込みの可視化にも出ないことを挙げ、起票を指示した（質問はしていない）。Network の構造図の側は [issue-20261115-ce0101](issue-20261115-ce0101.md) で扱う。

## 事象

- Runner の `Conv2dPanel` は、Actor が行動を選んだときの結果に付く nn trace（`ExtractNnTrace(event.action_info->GetAuxData())`）だけを描く（[Conv2dPanel.cpp:89](../../../src/apps/runner/src/Conv2dPanel.cpp)、同 226 行）。
- metrics.image の conv2d（`Conv2dVisualizationObserver`）も、同じ nn trace だけを読む（[observers.cpp:739](../../../src/core/base/src/observers.cpp)）。
- RND の推定（`Estimate`）は、Actor の行動の選択の中では呼ばれない。学習側で経験を取り込むときに `ScoreBonus` から呼ばれる（[default_dqn_agent.cpp:114](../../../src/algo/dqn/src/default_dqn_agent.cpp)）。評価側の Evaluation Trace の内的報酬は、推定器の写し（`Clone`）で計算する（[PRD127](../../memo/0127_eval_trace_intrinsic_reward_columns_10rfd.md)）。
- そのため、RND の 2 つの Network の畳み込みの出力は、nn trace に入らない。
- 2026-11-23 監査（backlog）: 依存先 6a32b4（RFD0170）は解決した（b45e15f5、2026-11-18）。RFD0191（2573b18e）で RND の構造図が `intrinsic.rnd.target.net.*`・`intrinsic.rnd.predictor.net.*` に記録されるようになった。畳み込みの出力は今も Panel に出ない。

## 影響

- RND の target と predictor が観測のどこに反応しているかを、畳み込みの出力で見られない。新しさの値（α）が大きい場面で、何を見て予測を外しているかを画面で確かめる手段が無い。

## 対応方針

未定。nn trace の受け渡しは [PRD170](../../memo/0170_nn_trace_capture_unification_10rfd.md)（[issue-20261103-6a32b4](issue-20261103-6a32b4.md)）で `NetworkForwardCapture` に一本化する予定なので、RND の Network の出力をどの経路で渡すかは、その形が決まってから決める。案として、評価側の推定器の写しが採点するときに出力を写し、Conv2dPanel から選べるようにする形がある。
