## 背景

台帳 F-0024 から移した（2026-11-03）。
観点: drift。分類: サンプル設定。確度: high。

## 事象

nn.txtのサンプルのbodyのうち、@ResNetは未定義のブロックを、@MLP_RESは未登録のtype（Composite）を使っており、どちらも選ぶと起動できない。

- apps/runner/config/nn.txt:241 @ResNetは定義の無いブロックLinear_128とMyReLUを参照する
- apps/runner/config/nn.txt:301 @MLP_RESが使う[ResBlock]のtypeが、登録の無いComposite
- core/anet-core/src/nn_impl.cpp:2575 未登録のtypeはUnknown module typeでANET_SYSTEM_ERRORになる

2026-11-09 追記（[issue-20261103-ef0c2b](issue-20261103-ef0c2b.md) を統合）: nn.txtの冒頭の対応typeの一覧が、登録済みの7種を欠き、typeではないAddを含む。init.modeのコメントもconstant・trunc_normal・defaultを欠く。

- apps/runner/config/nn.txt:16 対応typeの一覧（16〜41）にReshape・StackMerge・Dropout・LayerNorm2d・GAP2D・MaxPool2d・HybridSpatialEmbedderが無い
- apps/runner/config/nn.txt:19 Addをtypeとして挙げるが、Addは登録されたtypeではなくstructureの記法
- core/anet-core/src/nn_modules.cpp:3272 Reshape・StackMerge・Dropout（3274）・LayerNorm2d（3286）・GAP2D（3289）・MaxPool2d（3290）・HybridSpatialEmbedder（3293）を登録している
- apps/runner/config/nn.txt:311 init.modeのコメントがxavier・he・orthogonalだけ（5〜10行目も同じ）
- core/anet-core/include/anet/nn.hpp:69 init.modeはdefault・xavier・he・orthogonal・constant・trunc_normal

## 影響

サンプルを試すためにbodyとして@MLP_RESを選ぶ → [ResBlock]のtype=Compositeの解決でUnknown module typeになり、起動できない。@ResNetを選ぶと、未定義のブロック（Linear_128、MyReLU）の参照でエラーになる。

2026-11-09 追記（[issue-20261103-ef0c2b](issue-20261103-ef0c2b.md) を統合）: nn.txtの一覧を見てブロックを組む → MaxPool2dやDropoutは使えないと判断し、逆にnet.block.[X].typeにAddと書くとUnknown module typeで落ちる。trunc_normalの初期化も一覧に無いので選ばれない。

## 対応方針

サンプルを今の記法と登録済みのtypeで書き直すか、消す。

2026-11-09 追記（[issue-20261103-ef0c2b](issue-20261103-ef0c2b.md) を統合）: 一覧を登録済みのtypeに合わせ、Addは記法の節へ移す。init.modeのコメントにconstant・trunc_normal・defaultを足す。
