## 背景

2026-11-10〜11 のリファクタリング候補の抽出（C++ の本体を 16 単位に分けて読み、観点は docs/quality/refactor.md による）で見つかった。開発者が候補の一覧から選び、起票を指示した。2026-11-11 に今のコードで場所を確かめ直した。

観測の正規化と clip 率の計測の同居は、[issue-20261103-aa5758](issue-20261103-aa5758.md)（PRD944、観測パイプライン）に追記した。

## 事象

- 「範囲の外の割合を測ってから clamp する」数行が 4 か所にある。2 つの normalizer の `normalizeInternal`（core/anet-core/src/scaler_impl.cpp の 287 と 439 の手前）と、`ConstantRewardScaler::Scale`（741 から）、`RunningStdRewardScaler::Scale`（800 から）。
- 報酬の変換の式が、統計を更新する版（`Scale`）と更新しない版（`ScaleWithoutUpdate`、762 と 843 から）で 2 回ずつ書かれている。RunningStd の `ScaleWithoutUpdate` の上のコメントが、順序を `Scale` と合わせることを人に求めている。
- 食い違いがある。clip が無効のとき、`ConstantRewardScaler::Scale` は `last_clip_ratio_ = 0.0f` を書く（758）が、`RunningStdRewardScaler::Scale` は書かない。`last_clip_ratio_` の初期値も、Constant は NaN、RunningStd は 0 である。
- 「キーの文字列を比べて値を返す」並びが、4 つのクラスの `GetScalar`（300、561、770、853 から）に同じ形である。

## 影響

- 変換の順序（割る、post scale、clip）を変えると、2 つのクラス × 2 つの関数を同時に直す。clip 率の決め方を変えると、4 か所を直す。
- clip が無効のときの clip 率の値が scaler の種類で違い、メトリクスに残る値の意味がそろわない。

## 対応方針

ファイルの中に「clip して、範囲の外の割合も返す」関数を 1 つ置く。各 RewardScaler は変換を 1 つの const 関数にまとめ、`Scale` は「統計の更新、その関数、clip 率の記録」の順で呼ぶ。clip が無効のときの書き方と初期値の食い違いは挙動なので、この直しでそろえるかを別に決める。外から見える口と演算の数は変えない。
