## 背景

2026-11-10〜11 のリファクタリング候補の抽出（C++ の本体を 16 単位に分けて読み、観点は docs/quality/refactor.md による）で見つかった。開発者が候補の一覧から選び、起票を指示した。2026-11-11 に今のコードで場所を確かめ直した。

観測の正規化と clip 率の計測の同居は、[issue-20261103-aa5758](issue-20261103-aa5758.md)（PRD161、観測パイプライン）に追記した。

- 2026-11-22 PRD161 のグリル: PRD161 は、観測の正規化の部品の内部の整理を範囲に入れない（NG4）。aa5758 の 2026-11-11 の追記は、PRD161 の実装では直らないので、今のコードで確かめ直して、この課題の事象に写した。開発者が、工程末の起票の候補から選んだ。[PRD161](../../memo/0161_observation_pipeline_10rfd.md)

## 事象

- 「範囲の外の割合を測ってから clamp する」数行が 4 か所にある。2 つの normalizer の `normalizeInternal`（core/anet-core/src/scaler_impl.cpp の 287 と 439 の手前）と、`ConstantRewardScaler::Scale`（741 から）、`RunningStdRewardScaler::Scale`（800 から）。
- 報酬の変換の式が、統計を更新する版（`Scale`）と更新しない版（`ScaleWithoutUpdate`、762 と 843 から）で 2 回ずつ書かれている。RunningStd の `ScaleWithoutUpdate` の上のコメントが、順序を `Scale` と合わせることを人に求めている。
- 食い違いがある。clip が無効のとき、`ConstantRewardScaler::Scale` は `last_clip_ratio_ = 0.0f` を書く（758）が、`RunningStdRewardScaler::Scale` は書かない。`last_clip_ratio_` の初期値も、Constant は NaN、RunningStd は 0 である。
- 「キーの文字列を比べて値を返す」並びが、4 つのクラスの `GetScalar`（300、561、770、853 から）に同じ形である。
- 2026-11-22 PRD161 のグリル: 観測の正規化（[scaler_impl.cpp](../../../src/core/base/src/scaler_impl.cpp)）について、aa5758 の 2026-11-11 の追記を、2026-11-22 の main で確かめ直した。今もあるもの: `ObservationNormalizerFactory::CreateObservationNormalizer` は、設定の構造体を位置引数にばらして、2 つの部品へ渡す（同じ型の引数が隣り合う）。定数（`constant_mean`・`constant_std`）は、キー共通の 1 組で、形の違う float のキーが複数あると、構築で失敗する。追記のときから変わったもの: 読むだけの呼び出し（`Normalize`）は、clip 率を測らなくなった（`normalizeInternal` に、測るかの引数がある）。検証の関数は、Factory の構築で呼ばれている。確かめ直していないもの: `RunningStdSingleTensorNormalizer::NormalizeAndUpdateStats` の長さと入れ子、統計を更新する経路ごとの `last_outlier_ratio_` の書き方。

## 影響

- 変換の順序（割る、post scale、clip）を変えると、2 つのクラス × 2 つの関数を同時に直す。clip 率の決め方を変えると、4 か所を直す。
- clip が無効のときの clip 率の値が scaler の種類で違い、メトリクスに残る値の意味がそろわない。

## 対応方針

ファイルの中に「clip して、範囲の外の割合も返す」関数を 1 つ置く。各 RewardScaler は変換を 1 つの const 関数にまとめ、`Scale` は「統計の更新、その関数、clip 率の記録」の順で呼ぶ。clip が無効のときの書き方と初期値の食い違いは挙動なので、この直しでそろえるかを別に決める。外から見える口と演算の数は変えない。

- 2026-11-22 PRD161 のグリル: PRD161 を実装すると、観測の正規化の設定キーは、`mode` とモードの名前空間（`constant.*`・`running.*`）に分かれる（PRD161 の D43）。部品の内部の整理は、その実装のあとに行うと、設定の構造体の形の変更が重ならない。観測の正規化の側の着手の条件は、形の違う float のキーが複数ある構成で、統計つきか定数の正規化を使うときとした（PRD161 の NG4）。[PRD161](../../memo/0161_observation_pipeline_10rfd.md)
