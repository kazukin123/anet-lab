## 背景

2026-11-23 の監査（観点 refactor、範囲 324_dqn）で見つけた。観点は `docs/quality/refactor.md` の「既存の重複」（既に食い違っているもの）である。開発者には質問していない。

価値の分解（RFD0121、設計 [214](../../design/214_value_decomposition.jp.md)）では、`learner.intrinsic.discount_mode=shared` は内的の成分にも外的の割引率を使い、`separate` は明示した `learner.intrinsic.gamma` を使う（214 の 59・89 行）。分解が無効（`intrinsic.value_mode=combined`）のとき、`discount_mode` と `learner.intrinsic.gamma` は使われず、書けば Ignored の WARN が出る（`default_dqn_agent.hpp` 307〜324 行）。

## 事象

「内的の成分にどの割引率を使うか」を、次の 5 か所がそれぞれ式で書いている。検索語 `kDiscountSeparate`・`kDiscountShared` で、テストを除いて引いた。

- `src/algo/dqn/src/default_dqn_agent.cpp:510`（Agent の構築。内的の報酬スケーラへ渡す割引率）: `decomposed && discount_mode == separate ? intrinsic.gamma : gamma`。
- `src/algo/dqn/src/default_dqn_agent.cpp:946`（`CreateActor` の `ActorQHintConfig::intrinsic_gamma`）: `discount_mode == separate ? intrinsic.gamma : gamma`。decomposed を見ない。
- `src/algo/dqn/src/dqn_assembler.cpp:126`（step 診断。割引率が予定を持つか）: `decomposed && discount_mode == separate && intrinsic.gamma が定数でない`。
- `src/algo/dqn/src/dqn_learner.cpp:915`（Replay の構成。収益を抽選時に作り直すか）: decomposed の分岐の中で `discount_mode == shared ? gamma が定数でない : intrinsic.gamma が定数でない`。
- `src/algo/dqn/src/dqn_learner.cpp:2552`（`ComponentGammas`）: `discount_mode == shared ? gamma_ : intrinsic_gamma_`。decomposed を見ない。

今の読み手は、decomposed でないときに内的の割引率を読まない（Actor は `actor_q_hint_config_.decomposed` のときだけ `effective_intrinsic_gamma` を評価する。`dqn_actor.cpp:1584`）。そのため、条件の食い違いは今の結果を変えていない。

この選択の式を名指しで確かめるテストは、`discount_mode` を書くテストが 4 件ある（検索語 `discount_mode`、`src/algo/dqn/src/*_test.cpp`）。5 か所が同じ割引率を選ぶことを並べて確かめるテストは無い。

- 2026-11-25 監査（refactor）: 選び方を書く箇所は 6 か所ある。本文の 5 か所（今は `default_dqn_agent.cpp:558`・939、`dqn_assembler.cpp:126`、`dqn_learner.cpp:993`・2631）のほかに、step 診断が保存済みの内的の収益を使うかを `decomposed && (discount_mode == shared ? gamma が定数 : intrinsic.gamma が定数)` で決めている（`src/algo/dqn/src/dqn_assembler.cpp:181-182`）。

## 影響

- 割引率の選び方を変える（たとえば `discount_mode` に値を足す、combined でも内的の診断を出す）と、5 か所を同時に直すことになる。1 か所を直し漏らすと、内的の Q の目標値・Actor の近似の初期優先度・step 診断の割引率が別々の値になり、エラーにならずに違う条件の Run の結果が残る。
- decomposed を見ない 2 か所（946 行・2552 行）の値を、分解が無効の構成で読む読み手を新しく足すと、Ignored と知らせた `learner.intrinsic.gamma` が効いてしまう。

## 対応方針

- `LearnerConfig` に「内的の成分の割引率の設定（`ProfiledValueConfig`）を返す」関数を 1 つ置き、5 か所がそれを呼ぶ。decomposed でないときの扱いは、その関数が 1 か所で決める（外的の割引率を返すか、呼ぶ側を decomposed の分岐の中に限るか）。
- [324_dqn のトピック別まとめ](../../wiki/concepts/framework/324_dqn.md) の「変えるときの条件」のとおり、設定キー、メトリクスの名前、checkpoint の形式、ログと WARN・ERROR の文言・順・回数、乱数の消費の順、Agent が記録する設定を変えない。
- `ComponentGammas` は学習の step ごとに呼ばれる（hot path）。性能の区分は「中立」の見込みなので、ブレ幅基準の perf-neutral の確認と、同 seed の再現性（metrics の checksum の一致）を確かめる。分解を有効にした構成と無効の構成の両方で確かめる。

## 対応内容

- 2026-11-28 内的報酬の割引率の選択を LearnerConfig で共通化した。設定読取時の検証以外のモード分岐が共通関数に集まったことを検索で確認。共有・個別の短縮 Run の前側で両 Head の loss と内的 gamma が出て、個別では予定の値が変化することを確認した。 [RFD0207 実装メモ](../../memo/0207_dqn_small_fixes_and_refactors_20impl.md)


- 2026-11-28 前後とも、shared・separate で両 Head の loss と内的 gamma が出て、separate の内的 gamma が予定どおり変化した。両構成で診断の仕様差以外の scalar が一致。Release の更新性能は夜間の長い Run を控える指示に従い保留した。 [検証結果](../../memo/0207_dqn_small_fixes_and_refactors_20impl.md#検証結果)
