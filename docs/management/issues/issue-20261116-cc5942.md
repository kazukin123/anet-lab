## 背景

device 間の転送は、これまで箇所ごとに直してきた。

- [PRD020](../../memo/done/0020_device_transfer_common_part_10rfd.md) で転送の共通部品を作り、[PRD021](../../memo/done/0021_replay_per_priority_transfer_10rfd.md) で PER の優先度の読み戻しを非同期にした。
- 経験の終端の mask は、CPU への転送を結果ごとに 1 回へまとめている（[rl.cpp:1199-1206](../../../src/core/base/src/rl.cpp) の `BatchStepResult::GetEpisodeEndMask`）。行動も、CPU と device の写しを持って使い回す（同 455 行・475 行）。
- [PRD130](../../memo/0130_rnd_estimate_statistics_perf_10rfd.md)（RND の採点の統計の性能、[issue-20261112-f9790d](issue-20261112-f9790d.md)）で、RND の採点と補助学習の転送の一部を直した。既定の whiten では、観測を整数の画素のまま計算 device へ送り、変換と正規化をそこで行う。variance_feedback は対象外にした（同 PRD の §5.4）。

学習の経路の全体で、同じデータが何回 device をまたいでいるかは調べていない。開発者が、同じ tensor を何度も無駄に転送している分の分析と最適化を指示した。この起票では質問をしていない。

## 事象

- PRD130 の実装の前に測った Nsight Systems の記録（Atari の主の構成、RND あり、warm-up のあとの 10 秒、[PRD130](../../memo/0130_rnd_estimate_statistics_perf_10rfd.md) の §2.8）。RND の採点が浮動小数点の観測を送り、補助学習が往復していたころの数字である:
  - CPU から GPU への転送は 2,185 回で 3.95 GB、GPU から CPU への転送は 3,362 回で 35.6 MB だった。
  - `cudaMemcpyAsync` は 12,533 回で合計 0.501 秒だった。
  - 同じ 10 秒に入った intake は 54 回で、CPU から GPU へ 1 intake あたり約 73 MB になる。
  - どの tensor の転送がどれだけを占めるかの内訳は、記録に無い。
- **Replay のサンプル**：
  - Replay は観測を 1 フレームずつ CPU に持つ（[dqn_based_agent.cpp:3786-3789](../../../src/core/base/src/dqn_based_agent.cpp)。prefetch が有効なら、計算 device へ送ってから渡す）。
  - サンプルの組み立ては、同じリングから obs の stack と next_obs の stack を別々に切り出し、それぞれ stack の枚数分のフレームを持つ tensor にする（[replay_buffer_impl.cpp](../../../src/core/base/src/replay_buffer_impl.cpp) の 1477 行・1485 行・1527〜1528 行）。
  - obs は時刻 t−S+1 から t、next_obs は t+n−S+1 から t+n の S 枚である（S は stack の枚数、n は n-step）。n が S より小さいと、2 つの stack は S−n 枚のフレームを共有し、同じフレームを 1 サンプルの中で 2 回送る。
  - TempoRL の窓の規則があると、窓の終わりの next_obs の stack を 3 つ目として切り出す（同 1514 行）。
- **RND の採点と Actor**：
  - RND の採点は、経験の取り込みで `next_state.obs`（設定によっては `state.obs`）を採点する（[default_dqn_agent.cpp:240-243](../../../src/algo/dqn/src/default_dqn_agent.cpp)）。
  - 既定の whiten では、観測を整数の画素のまま計算 device へ送り、そこで浮動小数点に変えて正規化する（[intrinsic_rnd.cpp](../../../src/core/base/src/intrinsic_rnd.cpp) の 795 行と 177〜182 行）。PRD130 によると、送る量は整数の画素で 0.9 MB である。
  - variance_feedback では、観測の統計を CPU に置き（同 389 行）、CPU で正規化した浮動小数点の観測を計算 device へ送る（同 748 行）。送る量は、PRD130 によると 3.6 MB である。Atari の `run.@rnd_taiga` がこの方式を使う（[Atari.txt:44](../../../apps/runner/config/Atari.txt)）。
  - Actor は、次の step の `state.obs` を frame stack に入れるときに、新しいフレームだけを計算 device へ送る（[stacker.cpp:69](../../../src/core/base/src/stacker.cpp)、[dqn_based_agent.cpp:2701](../../../src/core/base/src/dqn_based_agent.cpp)）。
  - 終端でない lane では、ある step の `next_state.obs` は次の step の `state.obs` と同じなので、新しいフレームは採点と Actor で 2 回、計算 device へ送られる。これは、whiten と variance_feedback のどちらでも起きる。
- **RND の補助学習**：補助学習は、Replay のサンプルを統計の観測の device へ移してから正規化する（[intrinsic_rnd.cpp](../../../src/core/base/src/intrinsic_rnd.cpp) の 867〜869 行）。
  - whiten では、統計の観測の device が計算 device なので、サンプルは計算 device にあるまま正規化される。PRD130 の実装で往復は無くなった。
  - variance_feedback では、統計の観測の device が CPU なので、計算 device にあるサンプルをいったん CPU へ移して正規化し、計算 device へ戻す（同 748 行）。
- **経験の旗**：
  - 同じ step の `next_state.done` を、別々の箇所でそれぞれ CPU へ移している。[dqn_based_agent.cpp:711](../../../src/core/base/src/dqn_based_agent.cpp)、[default_dqn_agent.cpp:270](../../../src/algo/dqn/src/default_dqn_agent.cpp)、[rl.cpp:706](../../../src/core/base/src/rl.cpp)、同 1204 行である。
  - `truncated`・`episode_start`・報酬も、同じ形で別々に移す箇所がある。
  - Env が CPU の tensor を返す構成では、`.to(torch::kCPU)` は写しを作らない。旗が GPU にある構成があるかは確かめていない。
- 2026-11-23 監査（backlog）: 本文が指す `dqn_based_agent.cpp` は RFD0182（f25ff82b）で無くなった。RFD0191（2573b18e、2026-11-22）で、RND の設定が段階・モード別になり、rollout でためて学ぶ補助学習（`LaneTimeTensorStore`、`src/algo/dqn/src/default_dqn_agent.cpp:72-147`）が加わった。

## 影響

- 転送の量は、CPU から GPU へ 10 秒で 3.95 GB ある。重なるフレームや 2 回送る観測の分だけ、帯域と転送の呼び出しの時間（学習のスレッドの時間）を使っている見込みである。ただし、その割合は分かっていない。
- 内訳が無いので、どの箇所から直すと実時間に効くかを決められない。転送の直しは PRD130 のように題材ごとの PRD の中で少しずつ進み、全体の重複は残る。

## 対応方針

まず分析し、効く箇所から減らす。

- **分析**：主の Atari の構成（と CPU の構成の 1 つ）で、転送ごとに、どの tensor をどの箇所から送ったかを分ける。たとえば、転送の箇所に NVTX の区間を置くか、Nsight の memcpy の記録を呼び出し元と突き合わせる。重複の分（同じフレーム・同じ tensor の 2 回目以降）が、回数・量・時間のどれだけかを表にする。
- **減らし方の候補**（分析の結果で選ぶ）：
  - Replay：1 サンプルで使う重ならないフレームだけを送り、obs・next_obs・窓の next_obs の stack を計算 device で組む。
  - RND の採点：Actor の frame stack と、取り込みの観測の転送を 1 回にまとめる。採点は、経験の取り込みのときに観測を送る。Actor は、同じフレームを次の step で送る。
  - RND の variance_feedback：補助学習の往復と、採点の浮動小数点の転送を減らす。正規化を lane ごとに統計の更新と交互に行うので、whiten と同じ形にはならない（PRD130 の §5.1 の D12 の理由）。
  - 経験の旗：GPU にある構成があれば、CPU への写しを結果ごとに 1 回へまとめる（`GetEpisodeEndMask` と同じ形）。
- PRD130 の実装は済んだので、RND の採点と補助学習も、今の経路で分析に含める。
- 毎回の学習の経路に同期の転送を足さない。実時間は、ラウンドロビンの A/B で比べる。値を変えない直しでは、metrics checksum の一致で確かめる。
