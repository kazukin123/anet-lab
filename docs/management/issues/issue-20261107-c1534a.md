## 背景

2026-11-07 に Montezuma で RND を試した Run（`AtariRnd-01` の `mz_nm_rnd_b0p1_s1`）では、Train で鍵を何百回も取ったのに、学習中の評価はすべて 0 点だった。同じ重みで評価の τ をランダムにすると、鍵を取った。

開発者は、τ ランダムを評価に入れるべきだとしたうえで、学習中に評価の Runner を増やさないこと、評価専用の Run を都度流さないことを方針とした。ε 0.01 の eval を τ ランダムに替え、Greedy は τ 固定のまま残す案を選び、課題に記録してこの場で直すよう指示した（2026-11-07）。

## 事象

- Atari の評価の Actor はすべて τ 固定だった。`apps/runner/config/agent.txt` の `DefaultDQNAgent.actor.@eval_base.policy.tau_rule.sample_mode ?= fixed  # 決定的評価` を、eval が継承し、eval_target・EvalPanel・greedy・greedy_single がさらに継承する。
- IQN 論文（Dabney ら 2018、§3）の方策は、行動を選ぶたびに τ を K 本ランダムに引き、その平均で選ぶ。論文の実験は K=32。
- BTR の公開コードは評価でも τ を毎回 8 本ランダムに引く（`Agent.py` の `choose_eval_action` が `networks.py` の `qvals` → `calc_cos` の `torch.rand` を通る）。NoisyNet は切り、ε は 1 億 2,500 万 frame まで 0.01、以降 0。2026-08-31 のコード調査（`reports/btr_code_reading_2026-08-31.md`）は、評価の argmax と ε は書いたが、τ がランダムである点を差分に挙げていなかった。
- Montezuma（`mz_nm_rnd_b0p1_s1` の最後の重み、評価だけの Run `mz_nm_rnd_ev_taurnd`）では、τ ランダムの eval（ε 0.01）のセッション平均が 1.03・0.91、τ ランダムの greedy（ε 0）が 0.91・0.78 で、鍵を取る割合は約 85% だった。τ 固定の greedy は 64 ゲームとも 0 点で、27,000 step で打ち切られた。
- qbert では、50M の checkpoint で評価の τ を固定からランダムに替えると、8 面突破率がスキップなしで 50.5% → 66.0%、TempoRL 分割の full で 66.0% → 50.5% になった（[τ の配置の wiki](../../wiki/mechanisms/tau_sampling.md)、2026-10-29 の実験記録）。

## 影響

- Atari の BTR 比（Atari-5、qbert など）は、τ 固定・ε 0 の anet と、τ ランダムの BTR を並べていて、評価の作りの違いが混ざっていた。
- Montezuma では、学習した行動が τ 固定の評価に出ず、評価側が 0 点になった。τ 固定の eval は毎回 27,000 step に張り付き、評価の費用もかかった。

## 対応方針

ε 0.01 の eval を τ ランダムに替え、BTR と並べる物差しにする。Greedy（ε 0）は τ 固定のまま残し、学習した価値の平均で正しく動けるかを見る物差しにする。評価の Runner は増やさない。eval と Greedy の差を、学習の足りなさの目安として読む。

注意点は次の 3 つ。

- **過去の Run と比べられなくなる:** 学習中の評価の `52_eval2`（と `51_eval1`）は意味が変わり、変更前の Run とは比べられない。主な成績の Greedy（`53_evalg`・`54_evalgs`）は変わらない。
- **TempoRL の Run:** qbert の full では、評価の τ ランダムで突破率が下がった例がある。eval の値を読むときは、この点に気をつける。
- **走行中の Run:** AtariRnd-01 の凍結した設定と、サブ機の作業ツリーで走っている Run は変更前のまま。

## 対応内容

- 2026-11-07 RND の探索: `apps/runner/config/Atari.txt` に `A1.actor.[eval].policy.tau_rule.sample_mode = random` と `A3.actor.[greedy].policy.tau_rule.sample_mode = fixed` を足し、Eval 設定の注釈を直した。確かめ: 共通の設定を今の exe で 1 step 流し、解決後の値が eval・eval_target・eval_panel は random、greedy・greedy_single は fixed であること、Agent の実効の設定も同じであることを見た。
