## 背景

2026-11-10〜11 のリファクタリング候補の抽出（C++ の本体を 16 単位に分けて読み、観点は docs/quality/refactor.md による）で見つかった。開発者が候補の一覧から選び、起票を指示した。2026-11-11 に今のコードで場所を確かめ直した。

AGENTS.md は、もとからある死にコードを消さずに報告すると定めるので、消すには課題が要る。probe の外の呼ばれないコードは [issue-20261111-54c7e1](issue-20261111-54c7e1.md) にまとめた。PRD056（TimeHistogram）は `AgentTensorVectorProbe` を触る。

## 事象

- 使われていないもの（core と apps の範囲で、構築・呼び出しが 0 件）。
  - `ScalarProbe` の系統（core/anet-core/include/anet/probe.hpp:14 の `ScalarProbe`、64 の `StaticScalarProbe`、83 の `FunctionScalarProbe`）。
  - `BatchExperienceBasedVectorProbe`（111）、`BatchExperienceStateProbe`（139）、`BatchExperienceRewardProbe`（162）、`BatchUpdateResultTensorToVectorProbe`（208）。
  - extractor の 12 関数（MaxExtractor から BoundaryMaskedQdeltaAuto まで）と補助関数。`GetFlattenSize`（probe.cpp:763。テスト用の実装が override しているだけ）、`StateSweepProcessor` の `x_min_overridden_` ほか 3 つ（probe.cpp:674-677、代入だけ）。
  - 使われていないコードに誤りが残っている。`FunctionScalarProbe` の ctor は引数 name を `name_` に入れず、`BatchExperienceBasedVectorProbe::GetVector` は件数ぶん同じ引数で呼んで結果を先頭へ挿入する。
  - 合わせて約 590 行（probe.hpp 約 160 行、probe.cpp 約 430 行）。コメントアウトされた旧クラスも残っている。
- 使われている 2 つの Probe が写しになっている。`BatchExperienceVectorProbe`（180）と `AgentTensorVectorProbe`（246）は、ctor と GetVector が同じ並びで、違いは取得元の 1 行のほか、取れないときの WARN の有無、min・max の設定の仕方、action_spec で index が負のときの扱い、自動スケールの有無の 5 点である。dtype を float に直す分岐が計 4 回ある。auto_scale_mode に DISABLE 以外を渡す箇所は無く、そのための `mutable` の min_・max_ も動かない。
- 使われている 5 つの extractor（probe.hpp:349-353 の MaxIdxExtractor ほか）が同じ骨格（約 25 行ずつ）の写しで、名前から関数を選ぶ if の連鎖が呼び出し側の image.cpp と HeatMapPanel.cpp に同じ形で 2 つある。引数 `req` は 5 つとも使わない。5 つの extractor を実行するテストは無い。

## 影響

- probe.hpp を読むと VectorProbe の実装が 6 つ、ScalarProbe の系統が 3 つ、extractor が 17 個あるように見えるが、動くのは VectorProbe 2 つと extractor 5 つだけである。誤りの残った未使用のコードは、手本にすると誤りを写す。
- 2 つの Probe は既に 5 点が食い違っていて、意図した違いと偶然の違いが区別できない。集計を 1 種足すと 4 か所を足す。

## 対応方針

使われていないクラス・関数・メンバとコメントアウトされた旧クラスを消す（observers_test.cpp の `GetFlattenSize` の override も直す）。2 つの Probe は 1 つのクラスにし、取得元だけを ctor で受け取る。WARN の有無と index が負のときの扱いは、今の違いを取得元ごとの引数として残す（挙動と WARN の文言・回数を変えない）。extractor は「名前→集計の種類と 1 次元のときの扱い」の表と、関数を作る関数 1 つにし、2 つの呼び出し側はそれを呼ぶ。知らない名前を mean にする挙動は残す。extractor は先に特性テストを足す。PRD056 と時期を合わせる。
