## 背景

2026-11-18 の定常整備の監査（観点 drift、範囲 docs/design/200_dqn_agents.jp.md）で、§3 のコンポーネント定義の表を今のコードと突き合わせて見つかった。開発者には質問していない。設計文書 200 は直近 90 日の変更回数で上位（stats の churn90 で 2,320 ファイル中 13 位）なので、ホットスポット補正で urgency を 3 から 5 へ 1 段上げた。

## 事象

- 293 行の表は「`TDLearner` | scalar TD targetとTD lossを計算するLearner」、65 行は「通常Qのlossを`TDLearner`」、186 行は TBO の変換の実装リンクを「TDLearner / QuantileLearnerBase」とする。一方 292 行は `dqn::Learner` が「通常 Q の計算」を持つと書き、文書の中でも食い違う。コードの `class TDLearner final`（`core/anet-core/src/dqn_based_agent.hpp:1335-1345`）はコンストラクタだけで、コンストラクタ（`dqn_based_agent.cpp:5146`）も `SetupReplayBuffer` と `SetupOptimizer` を呼ぶだけ。計算は基底の `dqn::Learner` の `MakeTarget`（cpp:5321）・`ComputeElementError`（cpp:5268）・`ForwardCurrent`（cpp:5621）・`TransformH`/`TransformHInv`（cpp:4323/4329）にある。
- 295 行の表は「`TauGenerator` | …stateless component」とし、`CONTEXT.md:83` も「TauGenerator が担当し」と書く。クラスや構造体の `TauGenerator` は無く、実体は自由関数 `anet::rl::dqn::GenerateTaus` の 2 つの多重定義（宣言 `dqn_based_agent.hpp:306/315`）。名前が残るのは `ValidateTauGeneratorArguments`（cpp:169）のエラー文だけ。

## 影響

通常 Q の target・損失・TBO を直す開発者が `TDLearner` を開いても空のクラスしか見つからず、`TauGenerator` は探しても見つからない。

## 対応方針

未定。監査の案は、`TDLearner` を「通常 Q のとき選ばれる具象型で上書きを持たない」と書き、計算の置き場を `dqn::Learner` と明記して 186 行のリンク先も合わせる。`TauGenerator` は `GenerateTaus`（自由関数）と実名を書く。CONTEXT.md を同時に直すかは別に決める。
