## 背景

PRD122（小さなリファクタリングとテストの空白）の再グリルで、別モデルの検討が見つけ、コードで確かめた（2026-11-10）。誤りかどうかは確かめていない（疑い）。PRD122 は振る舞いを変えない範囲なので直さず、今の値のままテストで固定して、テストのコメントに疑いを書く（[PRD122](../../memo/122_small_refactor_and_test_gap_fixes_10prd.md) の D4・D15）。工程の終わりに候補として示し、開発者が起票を選んだ。開発者への質問はしていない。MuZeroAgent は試作の Agent である。

## 事象

エピソードが truncated で終わるとき、キューに残った各 step の価値ターゲットは、終端までの割引報酬に、最後の step の `root_value` を割り引いて足して作る。足しているのは、最後の step の観測（最後の行動の前の状態）の価値で、打ち切った次の状態の価値ではない。最後の step の報酬を足したうえで、その報酬を含むはずの価値も足すことになる。

- core/anet-core/src/muzero_rb.cpp:107 終端までの報酬を、最後の step の報酬まで足す
- core/anet-core/src/muzero_rb.cpp:113 truncated のとき、`current_gamma * last_step.root_value` を足す（113〜115 行）
- core/anet-core/src/muzero_rb.cpp:83 n-step の経路は、n 歩先の step の `root_value` を足す（補い方がそろっていない）

## 影響

truncated で終わるエピソードが多い Env で MuZeroAgent を学習する → 終端に近い step の価値ターゲットが、最後の報酬の分だけ高く（報酬が負なら低く）見積もられる。いまは試作の Agent で、主な実験では使っていない。

## 対応方針

未定。まず、意図した近似か誤りかを決める。打ち切った次の状態の価値はキューに無い（次の状態は探索していない）ので、直す場合は値の取り方（次の観測で探索して価値を得る、最後の報酬を足さずに最後の step の価値で補う、など）から決める。直したときは、PRD122 の D4 の (b) で固定したテストの期待値も直す。
