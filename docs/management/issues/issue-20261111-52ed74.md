## 背景

2026-11-10〜11 のリファクタリング候補の抽出（C++ の本体を 16 単位に分けて読み、観点は docs/quality/refactor.md による）で見つかった。開発者が候補の一覧から選び、起票を指示した。2026-11-11 に今のコードで場所を確かめ直した。

可塑性の指標（PRD062・063）の名前と並びを、nn の側と Agent の側の両方で手で合わせている点が同じなので、1 件にした。

## 事象

- 可塑性指標の一覧。指標 9 個が、enum（core/anet-core/include/anet/nn.hpp:319 の `PlasticityMetric`）、名前付きのメンバ（356 の `PlasticityMetrics`）、enum からメンバへの switch（core/anet-core/src/nn_impl.cpp:416 の `PlasticityMetrics::Get`）、文字列から enum への if の連鎖（402 の `ParsePlasticityMetricSuffix`）に 1 回ずつ並ぶ。srank 系は、さらに delta の配列（nn.hpp:373 の `kPlasticitySrankDeltas`）と、`ComputePlasticityMetrics` の中の enum の配列 2 本が添字で対応している。利用側は `Get(metric)` だけで読み、名前付きのメンバを直接読むのはテストだけである。
- 重みノルムのキー。6 つのキー名（`plasticity_weight_norm_feature` ほか）が、ImageCls では if の連鎖（core/anet-core/include/anet/image_cls_agent.hpp:157 から）と `||` の連鎖（core/anet-core/src/image_cls_agent.cpp:495 から）に、DQN では `||` の連鎖（core/anet-core/src/dqn_based_agent.cpp:2785 から）と読み出し（5633 から）に並ぶ。添字の意味は `torch::stack` の並び（ImageCls は 7 要素、DQN は 8 要素）で決まり、`numel() != 7` と `[6]`（image_cls_agent.hpp:170、174）はその並びに合わせた直書きである。
- `ValidateSpectralNormSentinel` が ImageCls（image_cls_agent.hpp:209）と DQN（dqn_based_agent.cpp:5699）に、文言の `ImageCls`／`DQN` と network 名を除いて同じ本体で 2 つある。特徴量側の可塑性の読み出しも同じ手順で 2 か所にある。

## 影響

- 可塑性の指標を 1 つ足すと、nn の側で 4 か所（srank の delta を足すなら 6 か所）を同時に直す。
- 重みノルムの指標を 1 つ足すと、ImageCls で 3 か所と個数の直書き 2 つ、DQN で 3 か所を同じ順に直す。順を 1 か所だけ変えると、別の値が別の名前で出る。型では守られていない。

## 対応方針

- `PlasticityMetrics` の中身を `std::array<std::optional<float>, 個数>` 1 本にし、`Get` は添字で返す。suffix と delta は「enum・suffix・delta の添字」の表 1 つにし、`ParsePlasticityMetricSuffix` と srank のループがその表を引く。公開の構造体のメンバが変わるので、テストの読み方も直す。
- 重みノルムのキー名の配列（添字＝stack の位置）を `NetworkParameterNormSplit` のそばに 1 つ置き、「キー→添字」と「norms→stack」を関数にする。sentinel の検証も network 名を引数にした 1 つの関数にし、ImageCls と DQN の両方がそれを呼ぶ。DQN の 8 要素目（target）の扱いを先に決める。
- メトリクスの名前とエラーの文言は変えない。メトリクスの出力が前後で同じことを確かめる。
