## 背景

2026-11-23 の監査（観点 drift、範囲 `docs/design/160_applications_and_tools.jp.md`）で見つけた。drift の観点は、範囲の ADR について「設計文書から参照されていない（入口なし）」を見る。開発者には質問していない。

AGENTS.md は、ADR を読むときは設計文書の該当章からの参照を優先するとしている。設計 200（DQN 系）の同じ種類の欠けは [issue-20261118-7f7757](issue-20261118-7f7757.md) で、200 §11.2 に ADR の一覧を設けて直した。ADR へのたどり方の全体の方針は [issue-20261114-fbcbca](issue-20261114-fbcbca.md) が扱う。

ホットスポット補正: 160 は 90 日の変更回数が 43 回で、設計文書（jp）の中で 200 に次いで多い（`reports/stats/stats.json` の `flow.churn90`）。urgency を 2 から 3 へ 1 段上げた。

## 事象

- 160 には `docs/adr/` へのリンクが無い（検索語 `adr/`、0 件）。ADR に触れるのは §5.1 の「ADR 0022 の限定例外」の文字だけである。
- 160 が本文で仕組みを書いているのに、どの設計文書（`docs/design/*.jp.md`）からもリンクされない ADR が 10 本ある（ファイル名の番号と `ADR 番号` の文字で検索）。
  - Runner の画面: [0016](../../adr/0016-runnerframe-aui-layout-roundtrip.md)（dock サイズを構造化シリアライザの往復と遷移時の同期で決める。160 §2.1 の `RunnerFrame`・§7.1）、[0066](../../adr/0066-main-panes-occupy-centre-dynamically-and-no-flow-empties-centre.md)（主 pane の Centre の動的な占有。§2.1・§7.1）
  - Evaluation Trace: [0057](../../adr/0057-eval-trace-columns-declared-apart-from-metrics-and-read-at-transition-time.md)（列を `app.eval_trace_panel.columns.[番号]` で宣言し、遷移の時点に合う target だけを読む。§3.4）
  - 起動と終了: [0021](../../adr/0021-run-classification-by-workspace-folder.md)（workspace のフォルダで Run を分け、`--config` は完全自己記述。§6）、[0045](../../adr/0045-eval-session-drain-on-exit-wait-or-discard.md)（終了時の背景評価の排水。§7.1 の close 順・§8 の `runner_close_drain`）、[0082](../../adr/0082-notifier-detach-does-not-wait-for-in-flight-notifications.md)（Notifier の Detach は進行中の通知を待たない。§5.1 の observer の detach）
  - 課題と wiki の保守: [0056](../../adr/0056-wiki-is-derived-summary-and-readme-keeps-original-analysis.md)・[0068](../../adr/0068-work-state-and-order-live-in-issues-prd-stays-an-instruction-document.md)・[0069](../../adr/0069-issues-point-to-prds-n-to-1-and-prd-completion-is-derived.md)・[0081](../../adr/0081-issue-kind-splits-product-into-code-and-document.md)（§7.4）
- ADR 0022（MLflow の DB の置き場）は、どの設計文書からもリンクされず、160 の文字だけが指す。
- 上の ADR の決定と 160 の本文は食い違っていない（決定の要点を 160 の該当節と突き合わせた）。0016 の先頭の後発の注記（PRD110 の 3 回目の改訂）も 160 §7.1 の記述と合う。

## 影響

- 160 の該当の節を読んでも、なぜその形なのか（Centre を空にする導線を持たない、Detach が待たない、列をメトリクスと分けて宣言する、など）にたどり着けない。ADR を読むべき変更（AGENTS.md の「ADR を読む条件」）で、ファイル名の一覧を引くしかない。
- 0066 の「Centre を空にする操作を導線に持たない」のような、見た目では冗長に見える判定を、理由を知らずに消す直しが起きうる。

## 対応方針

- 200 §11.2 と同じく、160 の「関連文書」（§9）に ADR の節を設け、上の 11 本（0022 を含む）を番号順に、対応する節とともに並べる。本文の「ADR 0022」の文字はリンクにする。英訳（`160_applications_and_tools.en.md`）も同じに直す。
- §7.4（課題と wiki の保守）を開発環境の文書へ移す課題 [issue-20261115-3e5b77](issue-20261115-3e5b77.md) が先に片づく場合は、0056・0068・0069・0081 のリンクは移した先の文書に置く。
