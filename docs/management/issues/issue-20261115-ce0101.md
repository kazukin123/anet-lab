## 背景

RND の target と predictor は、DefaultDQNAgent の primary の Network とは別の 2 つの Network で、一生の新しさの推定器が持つ（[intrinsic_rnd.hpp:113-114](../../../src/core/base/src/intrinsic_rnd.hpp)）。構成は Network の設定（`DefaultDQNAgent.intrinsic.rnd.target.net.*`・`DefaultDQNAgent.intrinsic.rnd.predictor.net.*`）で決まる（[PRD116](../../memo/116_rnd_lifelong_novelty_10prd.md)）。

[PRD121](../../memo/121_extrinsic_intrinsic_value_decomposition_10prd.md) のお試し Run の構造図を見ていた開発者が、RND の Network が図に無いことに気づき、起票を指示した。開発者は、早めに入れたいと述べた（質問はしていない）。

## 事象

- Network の構造図は、`DefaultDQNAgent::RecordNetworkStructure` が記録する。記録するのは primary の Network の `net.structure`・`net.detail` と、skip が有効なときの補助 Network の `skip.net.structure`・`skip.net.detail` だけである（[default_dqn_agent.cpp:455-470](../../../src/algo/dqn/src/default_dqn_agent.cpp)）。
- 一生の新しさの推定器のソース（`intrinsic_rnd.cpp`・`intrinsic.cpp`）は、`MakeGraphViz` も `MetricsLogger` も呼ばない。
- 例: Run `AtariRnd-01/runs/run_20261115-055326_mz_tg_r121_vd_s1` は `DefaultDQNAgent.intrinsic.enabled = true` で、RND の target の branch を設定している（設定の写しの 827-829 行）。この Run の `dot/` には `net.detail.dot` と `net.structure.dot` だけがある。

## 影響

- RND の target と predictor の構成（層の並び、入力の鍵、出力の鍵）を、図で確かめられない。確かめるには、設定の写しの `intrinsic.rnd.*.net.*` の行を読むしかない。
- RND の Network の設定を Run ごとに変える実験（Atari の Montezuma・KFM など）で、意図した構成になったかを図で見比べられない。

## 対応方針

未定。案として、skip の補助 Network と同じく、推定器が持つ 2 つの Network の `MakeGraphViz` の結果を、別の tag（`intrinsic.rnd.target.net.structure` のような名前）で記録する。そのためには、推定器から 2 つの Network を読み出す口が要る。記録する場所（DefaultDQNAgent か推定器か）と tag の名前は、対応のときに決める。

## 対応内容

- 2026-11-22 PRD191 の再グリル: 構造図の記録を PRD191 の範囲に入れると決めた（D5）。tag は `intrinsic.rnd.target.net.*` と `intrinsic.rnd.predictor.net.*` の 4 つで、primary の Network と同じ時機に記録する（D48）。確かめ: PRD のレビューが 3 往復目で OK。[PRD](../../memo/191_rnd_raw_error_and_recent_learning_10prd.md)
- 2026-11-22 PRD191 の実装: Runner の通常の構造図の記録に target と predictor の 4 図を追加した。Agent 初期化のテストで、有効時の出力と無効時の非出力を確かめた。 [実装記録](../../memo/191_rnd_raw_error_and_recent_learning_20impl.md)
