## 背景

2026-11-08、Montezuma の RND の Run を Taiga らの条件へ寄せる段取りを作る途中で、ユーザーが Atari.txt の Run プロファイルについて「大量すぎてワケワカメ」「BTR 寄せのサンプル効率優先は本流のプロファイルとして用意したいが、他プロファイルの組み合わせだと何が何だか分からない」「トップの Run プロファイルにフラットに設定を並べるなら人間でも分かる」と述べた。AI が棚卸しをして形の案を示したところ、ユーザーは Atari を題材に整理の形を考え、その結果をほかの env へ広げるかは後で考えるとして、課題と暫定 PRD の起票を指示した。質疑はしていない。

## 事象

- `apps/runner/config/Atari.txt` は 1,658 行で、Run プロファイルが 72 個（葉 267 行）ある。内訳は、本流の部品 20、機能を丸ごと入れる単位 22、値だけ違う腕 30。bat・テスト・文書のどれにも名前が出ないものが 17 個ある。
- 実時間優先は既定の `run.$`（156 行）の 11 個の連結、サンプル効率優先は 11 の bat の変数 `SE30`（30〜35 行）の 14 個の連結で、本流そのものに名前が無い。サンプル効率優先の連結では、`main_feature.$` が 4 回、`DefaultDQNAgent.$` と `metrics.scalar.$` と `replay_ratio` が 3 回ずつ書き換わる。
- 連結の順の決まりは Atari.txt のコメント（577・604・608 行）にしか書かれていない。
- 評価の間隔と target の同期は learn step で数えるので、replay ratio ごとに別のプロファイル（eval2ch／eval2ch_r1、hard125／250／500、btreval_r1／r2／r4）が要る。
- Run プロファイルの葉に、上書き層の別名（`A2.*`）と正式名（`DefaultDQNAgent.*`）が混ざっている。同じキーを両方で書くと正式名が勝ち、bat で別名の葉を足しても黙って効かない。

## 影響

- 本流の構成を確かめるのに、連結の全部と本体の A2 の行と bat の引数を重ねて読む必要があり、人が管理できない。実験の段取りのたびに AI が展開して確かめている。
- 連結の順を誤ると、黙って別の構成で Run が流れる。
- 値の腕と使われないプロファイルが増え続け、どれが今の構成かが分からなくなる。

## 対応方針

暫定 PRD118（[118_atari_run_profile_flatten_10prd.md](../../memo/118_atari_run_profile_flatten_10prd.md)）で、本流を 1 つの平らな Run プロファイルにし、Run プロファイルを本流・機能・予算の 3 種類に減らす形を置いた。グリルで未決を見直してから実装する。
