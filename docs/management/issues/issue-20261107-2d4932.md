## 背景

2026-11-07 に、Atari の評価の τ の配置を見直した（[issue-20261107-c1534a](issue-20261107-c1534a.md)）。eval・eval_target・EvalPanel は τ ランダム、Greedy は τ 固定になった。EvalPanel は eval_target を継承するので、τ ランダムになる。

開発者は、EvalPanel を「実方策をデモとして見る」ためのものとして使い、環境の側のランダム要素（sticky）は外してきた。IQN の τ の抽選は方策そのものなので、EvalPanel は τ ランダムを既定にすることを選んだ。そのうえで、見ている途中で τ 固定に切り替えて「学習した価値の判断」と見比べたいとして、起票を指示した（2026-11-07）。

きっかけは τ だが、τ に限らず EvalPanel の Actor の設定を Run の途中で変えられるようにすることも合わせて検討する、と開発者が添えた（2026-11-07）。

## 事象

- EvalPanel の τ の配置は、Run の起動時の設定（`DefaultDQNAgent.actor.[eval_panel].policy.tau_rule.sample_mode`）で決まり、画面から変えられない。
- 今の EvalPanel の Actor は、`policy_type = Greedy`（ε は使わない）、target NN、環境の sticky は 0 である。
- Montezuma（AtariRnd-01 の `mz_nm_rnd_b0p1_s1` の最後の重み、評価だけの Run `mz_nm_rnd_ev_taurnd`）では、同じ重みでも τ ランダムなら鍵を取る割合が約 85%、τ 固定なら 64 ゲームとも開始位置付近で止まって 0 点だった。どちらの方策を見るかで、画面の様子がまったく変わる。

## 影響

- 止まって見える場面で、τ を固定に替えて「学習した価値の平均ではどの行動を選ぶか」をその場で確かめられない。
- 見比べるには、評価だけの Run を別に流すか、設定を替えて Run を起動し直す必要がある。

## 対応方針

未定。候補は次のとおり。

- EvalPanel の操作部に、τ の配置（ランダム／固定）の切り替えを足す。切り替えたあとの行動選択と Q 値の表示（QValuePanel）、Evaluation Trace の記録に、どちらの配置かが分かるようにする。
- QValuePanel の Q 値も τ の配置で値が変わる。τ ランダムでは step ごとに揺れるので、表示を行動選択と同じ τ にするか、固定の τ で別に出すかを決める。
- 切り替えは EvalPanel の Actor だけに効かせ、学習中の評価（eval・Greedy）や Train には影響させない。

τ に限らず、EvalPanel の Actor の設定を Run の途中で変えられるようにする形も検討する。

- 変えたくなる設定の例は、τ の配置と本数（K）、ε、`policy_type`（Greedy／EpsilonGreedy など）、使う NN（online／target）、NoisyNet の扱い（`nn_forward_key`）である。環境の側の設定（sticky など）は Actor の設定ではないので、分けて扱う。
- 形の候補は 2 つある。1 つは、項目ごとに切り替えの部品を足す形。もう 1 つは、EvalPanel が Actor を作り直すときに設定の差分を渡せるようにする形である。EvalPanel は開始時に参照タグの Actor を作るので（[設計文書 100](../../design/100_runtime_and_configuration.jp.md) の EvalPanel と `CreateEvalRunner` の記述）、後者なら項目を増やしても仕組みは 1 つで済む見込みである（読み、未確認）。
- どちらの形でも、変えた設定を Evaluation Trace とログに残し、画面に映った行動がどの設定のものかをあとで追えるようにする。
