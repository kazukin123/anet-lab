## 背景

2026-11-10〜11 のリファクタリング候補の抽出（C++ の本体を 16 単位に分けて読み、観点は docs/quality/refactor.md による）で見つかった。開発者が候補の一覧から選び、起票を指示した。2026-11-11 に今のコードで場所を確かめ直した。

どちらも BatchEnv の lane ごとの結果の扱いで、食い違いが意図かどうかを先に決めれば一緒に直せるので、1 件にした。

## 事象

- lane 1 本分の結果の書き込み。
  - 「single の結果を batch の i 行目へ写す」本体が、`VectorizedDiscreteBatchEnv::Reset`（core/anet-core/src/env.cpp:740 から）と `ThreadPoolDiscreteEnv::Reset`（851 から）、`VectorizedDiscreteBatchEnv::Step`（761 から）と `ThreadPoolDiscreteEnv::Step`（892 から）で同じ内容である。その中の「obs を `CopyBatchItem` し、done・truncated・episode_start を `fill_` する 4 行」は 8 回現れる。
  - 食い違いが 3 つある。`n_episode_end` を、Vectorized はループの中で 1 ずつ足し（799）、ThreadPool は全 lane のあとで `done.logical_or(truncated)` を CPU へ移して `sum` で数える（964）。N の出どころが、Vectorized の Step は `batch_spec_.num_envs`、ほかの 3 つは `num_envs_` である。action の DEBUG ログは ThreadPool の Step にだけある。
- `GetAuxDataList` の実装が 3 つある。
  - `PlainBatchResetResult` と `PlainBatchStepResult`（core/anet-core/include/anet/env.hpp:68、90）は同じ 3 行で、メンバ `aux_data_` も同じである。
  - `DiscreteBatchEnvBase::Result::GetAuxDataList`（env.cpp:486 から）は、「lane の結果が null でなければ aux を足す」を lane 指定の枝と全 lane の枝で 2 回書く。
  - 食い違いが 2 つある。Plain の 2 つは範囲の外の `env_index` に空の一覧を返すが、Discrete の側は上限を確かめずに `single_results[env_index]` を引く。Discrete の側は全 lane の指定で null の lane を飛ばすので、返る一覧の位置が lane の番号とずれうるが、Plain の側は lane の番号のままである。
  - `Result` は `BatchEnvResult` を仮想継承し、`ResetResult`・`StepResult` は `Result` と `BatchResetResult`／`BatchStepResult` の両方を継承する。`Result` が持つのは `single_results` と `GetAuxDataList` だけである。

## 影響

- 1 lane の結果の持ち方（状態の項目を 1 つ足すなど）を変えると、4 つの関数の 8 か所を同じように直すことになる。2 つのクラスのあいだの食い違いが既に 3 つある。
- aux の返し方を決め直すと、3 つの実装を直す。同じ問い合わせが実装によって違う答えを返し、Discrete の側では範囲の外の添字で落ちうる。

## 対応方針

先に、食い違い（`n_episode_end` の数え方、範囲の外の `env_index`、null の lane の扱い）が意図かを決める。そのうえで、`DiscreteBatchEnvBase` に `ResetLane(i, result)` と `StepLane(i, action, result)` を置き、Vectorized はループから、ThreadPool はタスクの中から呼ぶ。`n_episode_end` は全 lane のあとで数える側にそろえられる。「lane ごとの aux の一覧から `env_index` で選ぶ」関数を 1 つ置き、3 つの実装から呼ぶ。Plain の 2 つは小さな基底かテンプレートへ寄せる。範囲の外の扱いをそろえると挙動が変わるので、そのことを書く。毎 step の経路なので、速さが変わらないことを確かめる。
