## 背景

2026-11-18 の定常整備の監査（観点 drift、範囲 docs/design/200_dqn_agents.jp.md）で、文書が書く設定キー、コードが読むキー、出荷設定のキーの 3 集合を突き合わせて見つかった。出荷設定の有効な行に死にキーは無く、ずれは文書の側だけだった。開発者には質問していない。設計文書 200 は直近 90 日の変更回数で上位（stats の churn90 で 2,320 ファイル中 13 位）なので、ホットスポット補正で urgency を 3 から 5 へ 1 段上げた。

## 事象

- 487 行の「Atariの`run.@munchausen`」。実在するのは `run.@munch`（`apps/runner/config/Atari.txt:614-615`、`LunarLander.txt:110-111`）で、`run.@munchausen` は全設定ファイルに無い。
- 706 行の「`metrics.scalar.full`へ登録し」。正しい名前は `metrics.scalar.@full`（`apps/runner/config/metrics_scalar.txt:209-210` ほか 117 行）。同じ誤記が `docs/design/140_observability.jp.md:301` にもある。
- 245 行と 393 行の図が frame stack のキーを `use_stacker`・`stack_count`・`stack_keys` と素の名前で書き、接頭辞 `stucker.` が文書全体に 0 件。コードは `default_dqn_agent.hpp:336-338` で `stucker.use_stacker` などを読み、出荷設定は `agent.txt:178-179` の `DefaultDQNAgent.@baseline.stucker.*`。
- 785 行の「num_micro_batchesの既定8…ema_alphaの既定0.05」に接頭辞 `learner.grad_noise.` が無い（コードは `default_dqn_agent.hpp:493-494`）。733 行と §9.5 は probe の件数のキー `learner.plasticity.probe.batch_size`（既定 512）と `learner.policy_churn.probe.batch_size`（既定 1024）を名指ししていない（コードは `default_dqn_agent.hpp:500-501`）。

## 影響

文書のとおりに書くと、存在しないプロファイル名や読まれないキーになり、Munchausen の Run が組めない、probe の件数を変えられない。`ema_alpha` は metrics の `$ema ema_alpha:` と同じ名前なので、GNS の EMA 係数を取り違える。読まれないキーは ADR 0071 の検出で起動時に止まるので、黙って違う条件の Run が残るわけではない。

## 対応方針

未定。監査の案は、`run.@munch`・`metrics.scalar.@full`（140 も）に直し、`DefaultDQNAgent.stucker.*`・`learner.grad_noise.*`・2 つの probe の件数のキーを該当の節に 1 語ずつ添える。
