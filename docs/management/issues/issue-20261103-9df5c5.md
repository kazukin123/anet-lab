## 背景

`Notifier::AttachScoped()` は `RunnerScoped*Observer` wrapper を生成して **wrapper を Attach** し、**inner observer を返す**。一方 `Notifier::Detach(shared_ptr)` はポインタ一致(`o == obs`)で消す。したがって **AttachScoped の戻り値を Detach へ渡すと必ず一致せず、静かに失敗する**。

## 対応方針

対応するPRDと保存済み実装計画に従う。

- 2026-11-11 リファクタリング候補の抽出: この契約の不備で効いていない解除のコードが、Runner のパネルに次のとおり残っている。`AttachScoped` の戻り値（包む前の中身）を `Detach` へ渡す箇所が 4 つある（Conv2dPanel.cpp:110、EvalPanel.cpp:92 と 329、QValuePanel.cpp:1005）。`QValuePanel::OnCloseWindow`（1002）は `wxEVT_CLOSE_WINDOW` に結んであるが、パネルに `Close()` を呼ぶ箇所は見当たらない。`EvalPanel::OnClose`（325）と `TrainPanel::OnClose`（TrainPanel.cpp:116）は、結ぶ箇所も呼ぶ箇所も無い。`EvalTracePanel::observer_` は代入（EvalTracePanel.cpp:202）だけで読まれず、`QValuePanel::notifier_` と `Conv2dPanel::notifier_` はこの解除のためだけに持っている。破棄後の安全は、コールバックの先頭の `wxWeakRef` の確認が受け持っている。同じ EvalPanel の中には、包みを自分で作って `Attach` し、その包みを `Detach` する効く書き方もある（`source_counts_observer_`、EvalPanel.cpp:98）。PRD146 で包みを返す形にするときに、これらを効く解除に直すか、消して「弱参照で止める」と書くかを一緒に決める。確かめ: 呼び出しの位置を今のコードで確かめた。
- 2026-11-20 PRD192 のグリル: PRD146 の R3・G3・AC5（「Detach は Runner の停止後だけ」をコメントの決まりにする）と NG1（排他を入れない）は、PRD192 の D1〜D3（Notifier の口は同時に呼んでも Observer の列が壊れない。Detach は進行中の通知を待たず、Observer はロックの外で呼ぶ）と食い違うので、PRD146 を使うときに直す。あわせて決めること: Detach が効くようになると、Panel への弱い参照（`wxWeakRef`）を持つ Observer が学習中に列から外れ、PRD192 の決まりでは、通知を呼んだスレッドで壊れうる。弱い参照は、GUI スレッドの外で壊すと、Panel の破棄と重なって守られない。[PRD192](../../memo/192_concurrency_and_boundary_defect_fixes_10prd.md)（§6.2、§9 の U2）・[ADR 0082](../../adr/0082-notifier-detach-does-not-wait-for-in-flight-notifications.md)
