## 背景

`Notifier::AttachScoped()` は `RunnerScoped*Observer` wrapper を生成して **wrapper を Attach** し、**inner observer を返す**。一方 `Notifier::Detach(shared_ptr)` はポインタ一致(`o == obs`)で消す。したがって **AttachScoped の戻り値を Detach へ渡すと必ず一致せず、静かに失敗する**。

## 対応内容

- 2026-11-11 リファクタリング候補の抽出: この契約の不備で効いていない解除のコードが、Runner のパネルに次のとおり残っている。`AttachScoped` の戻り値（包む前の中身）を `Detach` へ渡す箇所が 4 つある（Conv2dPanel.cpp:110、EvalPanel.cpp:92 と 329、QValuePanel.cpp:1005）。`QValuePanel::OnCloseWindow`（1002）は `wxEVT_CLOSE_WINDOW` に結んであるが、パネルに `Close()` を呼ぶ箇所は見当たらない。`EvalPanel::OnClose`（325）と `TrainPanel::OnClose`（TrainPanel.cpp:116）は、結ぶ箇所も呼ぶ箇所も無い。`EvalTracePanel::observer_` は代入（EvalTracePanel.cpp:202）だけで読まれず、`QValuePanel::notifier_` と `Conv2dPanel::notifier_` はこの解除のためだけに持っている。破棄後の安全は、コールバックの先頭の `wxWeakRef` の確認が受け持っている。同じ EvalPanel の中には、包みを自分で作って `Attach` し、その包みを `Detach` する効く書き方もある（`source_counts_observer_`、EvalPanel.cpp:98）。PRD942 で包みを返す形にするときに、これらを効く解除に直すか、消して「弱参照で止める」と書くかを一緒に決める。確かめ: 呼び出しの位置を今のコードで確かめた。
