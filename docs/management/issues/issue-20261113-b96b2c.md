## 背景

PRD121（価値の分解）のグリル（2026-11-12〜13）で、報酬スケーラの状態を checkpoint に保存する形を決めた（PRD121 の D16）。同じ場所に、観測の正規化の統計を保存していない未対応がある。PRD121 の機構が要るのは報酬スケーラだけなので、PRD121 は観測の正規化を範囲の外に置いた（PRD121 の §1.4）。

グリルの中では、開発者に質問していない。工程末に起票の候補として示し、開発者が記録すると選んだ。

## 事象

- `DefaultDQNAgent::Save` は、観測の正規化の状態を書かない。未対応の印（「ObservationNormalizerの永続化対応」）がある（[default_dqn_agent.cpp](../../../src/algo/dqn/src/default_dqn_agent.cpp)）。`DefaultDQNAgent::LoadNetwork` も読まない。
- 観測の正規化の部品（`DictObservationNormalizer`・`RunningStdSingleTensorNormalizer`・`RunningMeanStd`）には、`Save` と `Load` がある（[scaler_impl.cpp](../../../src/core/base/src/scaler_impl.cpp)）。DQN 系と MuZero 系の Agent のソースに、これを呼ぶ箇所は無い（2026-11-13 に検索で確かめた）。
- 出荷の設定の既定は `obs_norm.pass_through ?= true` で、観測をそのまま使う（[agent.txt](../../../apps/runner/config/agent.txt)）。解決済みの設定の基準（`core/anet-core/testdata/prd072/baseline/` の 17 構成）は、どれも `pass_through` が真である。
- 統計を使う正規化が動くのは、`obs_norm.pass_through = false` かつ `obs_norm.use_dynamic_scaling = true` を指定した構成だけである。

## 影響

- 統計を使う正規化の構成で checkpoint 引き継ぎをすると、統計が 0 から始まる。引き継いだ Network は、学習したときと違う尺度の観測を受ける。ERROR も WARN も出ない。
- 出荷の設定の既定では起きない。

## 対応方針

未定。

PRD121 は、同じ保存の並びに報酬スケーラの状態を足し、種類が設定と checkpoint で違えば ERROR にする形を決めている（PRD121 の D16・§8.5）。観測の正規化も同じ形にそろえると、扱いが 1 つになる。PRD121 の実装のあとに足すと、checkpoint の形の変更が重ならない。
