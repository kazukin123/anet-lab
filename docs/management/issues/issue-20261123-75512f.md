## 背景

2026-11-23 の定常整備（anet-audit、観点 drift・範囲 CONTEXT.md）で見つけた。分類は用語ずれ。直すのは文書だけと見立てた。工程の中で開発者に質問はしていない。

ホットスポット補正: 直す場所の `CONTEXT.md`（churn90 が 63）は、2026-11-18 の定点統計で全ファイルの上位 1% に入るので、`urgency` を 2 から 3 へ 1 段上げた。

## 事象

- [CONTEXT.md](../../../CONTEXT.md) 15 行は、定期同期の周期を Actor 設定 `actor.[train].sync_interval` が持ち、宣言されたときだけ定期 snapshot を行うと書く。
- `src/algo/dqn/src/default_dqn_agent.cpp` 949 行は `cfg.clone_model ? cfg.sync_interval : std::nullopt` を渡し、[200](../../design/200_dqn_agents.jp.md) の 496 行も「clone_model=true かつ sync_interval.* を宣言した Actor」と書く。
- `apps/runner/config/agent.txt` 437〜438 行の baseline は `clone_model ?= false` と `sync_interval ?= 400` を両方書く。LunarLander・GridMaze・CartPole はこの既定のままで、`clone_model = true` は Atari.txt 828 行と DropMerge.txt 209 行だけである。ADR 0091 により、使われない側の `sync_interval` は通知なしで読まれる。
- CONTEXT.md 445 行（評価セッション）は「一つの network snapshot を使い」と書くが、MuZero の評価 Actor は `clone_model ?= false` で（agent.txt 491・496・515 行）、common.txt 9 行は false のとき学習中の network を共有すると書く。

## 影響

config dump の `sync_interval = 400` を見て、LunarLander・GridMaze の学習 Actor が 400 step 遅れの写しで動いていると読み違える。Run の分析で、学習の遅れの原因を存在しない同期の遅れに求める。

## 対応方針

文書だけを直す見立て。「clone_model が真の Actor だけが snapshot を持ち、sync_interval を宣言したときに定期同期する」と書き、評価セッションにも同じ条件を足す。
