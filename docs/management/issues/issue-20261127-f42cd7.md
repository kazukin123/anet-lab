## 背景

2026-11-27 の会話で、開発者が、wiki にハーネス保守の観点の知見があるとよい、と述べた。skill を作るときなどに一般の事例をよく調べるので、それをうまく残していきたい、という要望である。あわせて、流れで整備したいと述べた（開発者の発言、2026-11-27）。AI は、今の wiki に入る経路を、wiki の規約、311 のトピック別まとめ、ハーネスの RFD のサマリ、サーベイの索引、categories.json で確かめた。

wiki の外の事例の扱いは、[RFD0202](../../memo/0202_wiki_accumulate_and_lookup_10rfd.md)（課題 [issue-20261125-822a3e](issue-20261125-822a3e.md)、対応中）が決めた。「分かっていること」を「anet の知見」と「外の事例」に分け（D13）、トピック別まとめに節「外の事例」を足して、その材料を報告（`reports/` 直下）にした（D14）。同じ RFD の再グリルは、知見の 4 種とフォルダ、節、基準を保つと決めている（D21）。

- 2026-11-27 会話: 開発者が、ハーネスに限らず、「その他」の枠でもよいので、有用な知見が得られたら記録に残せたほうがよい、と述べ、この課題の範囲を広げるよう指示した（開発者の発言、2026-11-27）。題と影響範囲を、これに合わせて改めた。ハーネスの知見は、広げた範囲の一例として扱う。

## 事象

- 知見のページの種類は、題の主語で決める。解かせる相手なら題材、値の出し方・比べ方・読み方なら測り方、設定やコードで入れたり切り替えたりできるものなら手法、残りは現象である（[wiki の規約](../../wiki/README.md) の「置き場と書式」）。ハーネスの知見をどの種類に置くかの定めは無い。目録を skill・ハーネス・レビュー・エージェント・プロンプトで引いて、当たる行は 0 件だった。
- [311 のトピック別まとめ](../../wiki/concepts/framework/311_dev_tools.md) の「外の事例」は「記述なし」である。
- [サーベイの索引](../../../reports/INDEX.md) に、ハーネスを題にした報告は無い。索引の説明を skill・harness・エージェント・プロンプト・claude・codex などで引いて当たったのは、LLM で RL を補う報告と、内的報酬の報告だけだった。
- ハーネスの RFD のサマリ 7 本（RFD0087・0095・0114・0189・0197・0198・0202）は、主要な概念がどれも 311 のトピック別まとめだけである。
- [categories.json](../../../reports/tools/categories.json) の `311_dev_tools` の対応は `^apps/tools/`・`^reports/tools/`・`^\.github/` の 3 つである。skill（`.agents/skills`・`.claude/skills`）、AGENTS.md、`docs/process`、`docs/quality` は、311 の「ファイル」の節に出ない。
- [RFD0202](../../memo/0202_wiki_accumulate_and_lookup_10rfd.md) の §5.7 に書いた、skill の起動の数と公開の比較実験の記事（P24）は、wiki のどのページにも無い（`docs/wiki` を記事のサイト名で検索して 0 件）。
- AGENTS.md の「wiki(docs/wiki)を引く条件」は、会話で調べた答えが出たら `anet-query-wiki` の手順で書くと定め、同 skill の書く先の表は、外の調べものを報告に足す（無ければ短い報告を作って取り込む）と定める。skill や工程を作る作業（この場で直す、anet-improve、anet-create-rfd の比べる表の事例の行）で調べた事例がこれに当たるかは、どちらにも書かれていない。
- ハーネスの実測（レビューの費用、サブエージェントの振る舞いの実測など）は Claude Code の memory にある。wiki は memory を主張の出典にしない（[wiki の規約](../../wiki/README.md) の「原則と正本」）。
- 2026-11-27 会話: 知見の種類の決まりでは、題材・手法・測り方に当たらない残りは現象である。目録の現象のページは 2 枚（勾配ノイズと batch、可塑性指標と成績）で、どちらも RL の学習の話である。[wiki の規約](../../wiki/README.md) の「置き場と書式」、[目録](../../wiki/index.md) の「現象」
- 2026-11-27 会話: 取り込みの材料は、実験記録、報告（`reports/` 直下）、RFD、設計文書、ADR の 5 種類である。[wiki の規約](../../wiki/README.md) の「anet-ingest-wiki」
- 2026-11-27 会話: 会話で出た内容の書く先の表は、外の調べものを報告、今のコードの働きを設計文書、Run の新しい集計・分析を実験記録、今の正本から導ける答えを知見の項目へ回し、最後の行で、ここまでの条件に当たらないものを記録しない。Run でもコードでもない anet での見聞き（道具を使って分かった振る舞い、作業の進め方で効いたこと・効かなかったことなど）がどの行に当たるかは、表から決まらない。[wiki の規約](../../wiki/README.md) の「anet-query-wiki」

## 影響

- skill や工程を作るたびに、一般の事例を調べ直す。前に調べた事例と、そのとき選ばなかった理由が、会話とともに消える。
- RFD づくりの比べる表の「事例」の行は、web より先にサーベイの索引を引くが、ハーネスの報告が無いので、ハーネスの問いでは毎回 web から調べることになる。
- ハーネスの工夫が効いた・効かなかったの知見が、memory と RFD の本文に散る。memory は Claude Code だけが読むので、Codex の枠からは見えない。
- 2026-11-27 会話: ハーネスのほかでも、Run・コード・外の調べもののどれにも当たらない知見は、記録されないか memory に残り、wiki から引けない。

## 対応方針

未定。

- 2026-11-27 会話: AI が挙げた案（開発者はまだ選んでいない）。
  - A: skill や工程を作る作業で調べた事例も、`reports/` の短い報告に残す決まりにする。今の経路（報告 → サマリ → 311 の「外の事例」）に乗るので、wiki の規約はほぼ変えない。効いた・効かなかったの知見は、これでは束ねられない。
  - B: 知見のページにハーネスの置き場を足す（新しい種類にするか、「手法」の定義にハーネスの工夫を含めると書く）。効いた・効かなかったも束ねられる。種類の決まり・目録・点検の見立ての型を直し、memory にある実測を正本（報告など）へ移す作業が出る。RFD0202 の D21（知見の 4 種とフォルダを保つ）を開き直すことになるので、RFD0202 の段 4 と成功の測り方の作業との順序を決める。
  - AI の推奨は、A を先にして、ハーネスの報告が数本たまってから B を考える順である。置き場だけ先に作っても材料が無く、A だけで一般の事例を残す要望に応えられるためである。
- 2026-11-27 会話: 範囲を広げたのに合わせて、AI が足した案（開発者はまだ選んでいない）。
  - C: Run 以外の、anet での見聞き（道具を使って分かった振る舞いの実測、作業の進め方で効いたこと・効かなかったことなど）を書く正本を決め、書く先の表の最後の行（記録しない）の前に、その行を置く。正本は、報告の一種にするか、実験記録に Run でない記録の置き場を作るか、を決める。あわせて、書くきっかけに、作業の途中（skill と工程を作るときなど）を足すかを決める。
  - 知見のページの置き場は、今の「現象」（残り）で受けるか、案 B の置き場で受けるかを決める。
  - AI の推奨は、A と C で書く先（正本）を先に決め、知見のページは今の「現象」で受けて、材料がたまってから B を考える順である。正本が無いと、どの置き場も材料を取り込めないためである。
