## 背景

PRD122（小さなリファクタリングとテストの空白）の再グリルで、別モデルの検討が見つけ、コードで確かめた（2026-11-10）。PRD122 は振る舞いを変えない範囲なので、この不具合は直さない。ヒートマップの加工を関数に切り出すときに、この入力を「契約の外」としてテストで使わないことにしている（[PRD122](../../memo/122_small_refactor_and_test_gap_fixes_10prd.md) の §5.2・§7）。工程の終わりに候補として示し、開発者が起票を選んだ。開発者への質問はしていない。

## 事象

Histogram の平滑化の重みは、コンストラクタが `use_hist_smooth` が真で `smooth_radius` が正のときだけ作る。加工は `use_hist_smooth` だけを見て重みを読む。`use_hist_smooth = true` で `smooth_radius` を 0 以下にすると、重みが空のまま、加工が重みの 0 番を読む。

- apps/runner/src/QValuePanel.cpp:138 重みを作る条件は `config_->use_hist_smooth && config_->smooth_radius > 0`
- apps/runner/src/QValuePanel.cpp:627 加工が重みを読む条件は `config_->use_hist_smooth` だけ
- apps/runner/src/QValuePanel.cpp:638 `hist_weights_[r + config_->smooth_radius]` を読む（半径 0 なら 0 番）
- apps/runner/src/QValuePanel.cpp:30 `smooth_radius` は `float` で、既定は 4。値域の検証は無い

## 影響

設定で `smooth_radius` を 0 以下にして Histogram を表示する → 空の入れ物の範囲外を読み、振る舞いが決まらない（Runner が落ちるか、でたらめな値で描く）。既定の設定（半径 4）では起きない。

## 対応方針

未定。候補は、設定の読み込みで `smooth_radius` の値域を検証して止める形と、半径 0 以下を「平滑化なし」として扱う形である。後者は特定の値に別の意味を持たせることになるので、値域の検証を先に検討する。`smooth_radius` を整数として使っているのに `float` で持つ点も、あわせて見る。PRD122 の実装（加工の切り出し）のあとに直すと、直す場所が 1 つの関数にまとまる。

## 対応内容

- 2026-11-11 リファクタリング候補の抽出: 同じ原因の作りを足す。PRD122 で加工を `ComputeQValueHeatMap`（QValuePanel.cpp:420 から）へ切り出したあとも、平滑化の指定は `QValueHeatMapRequest` の `use_hist_smooth`（bool）・`smooth_radius`（float）・`hist_weights`（span）の 3 つで重ねて渡している。重みの長さは `smooth_radius * 2 + 1` で決まり（139）、半径は float のまま添字に使われる（556 の `request.hist_weights[r + request.smooth_radius]`）。重みの列 1 つから「平滑化するか」と半径が導けるので、request は重みの列だけを持ち（空なら平滑化なし、半径は `(size - 1) / 2`）、`smooth_radius` は int で読む形にすると、この不具合の組み合わせが作れなくなる。小数を書いた設定の読み方は変わる（今は切り捨てと丸めが混ざる）。確かめ: 重みの作り方と添字の行を今のコードで確かめた。
