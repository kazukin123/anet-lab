## 背景

台帳 F-0039 から移した（2026-11-03）。
観点: drift。分類: fail-fastの方針。確度: high。

- 2026-11-03 open: 初出

## 事象

stack_keysに観測に無いキー名を書いても、どの経路も検出せず、そのキーは黙ってstackされない。

- core/anet-core/src/default_dqn_agent.cpp:153 spec畳みでstack_keysに一致するキーだけをstack対象にし、一致しない名前は黙って無視する
- core/anet-core/src/default_dqn_agent.cpp:399 可視化の側も同じ判定
- AGENTS.md:185 未宣言の対象への参照はfail-fast
- 2026-11-23 監査（backlog）: 同じ名前の一致だけの扱いが、`ReplayBuffer`（`src/core/base/src/replay_buffer_impl.cpp:709-711`）と `DictFrameStacker`（`src/core/base/src/stacker.cpp:56-57`）にもある。

## 影響

stack_keysの綴りを誤ると（例: obsをob）、frame stackが効かないまま学習が進み、設定どおりに動いていないことに気づけない。

## 対応方針

構築時に、stack_keysの各名前がobs_specにあるかを確かめ、無ければANET_SYSTEM_ERROR

## 対応内容

- 2026-11-22 PRD161 のグリル: 重ねる対象のキーに、観測に無い名前を書いた設定を、構築時にエラーにする形を決めた（D30、§7.6 の 5、受入 21）。キーの一覧は、`keys.mode = listed` のときの `keys.listed.names` になる（D44）。確かめ: PRD のレビューは 4 回目で OK。実装はしていない。[PRD](../../memo/0161_observation_pipeline_10rfd.md)

- 2026-11-23 RFD0161 の実装: `perception.block.[stack].keys.mode=listed` の構築時に `keys.listed.names` を Frame の spec と照らし、未知のキーまたは空の一覧をエラーにした。`[perception]` の構築検査と、同じ対象一覧を用いる Actor の出力・Replay sample の往復で確認した。[実装記録](../../memo/0161_observation_pipeline_20impl.md#経過)
