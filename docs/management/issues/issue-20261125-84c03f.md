## 背景

2026-11-25 の監査（観点 architecture、範囲 321_agent_core）で見つけた。分類は依存（深さの無い module）である。開発者には質問していない。

ホットスポット補正: `dqn_learner.cpp`（改名の前の `dqn_based_agent.cpp` は churn90 が 41）は、コードのファイルの上位 1% に入る。urgency を 2 から 3 へ 1 段上げた。

## 事象

- `RuntimeVars`（`src/algo/dqn/src/dqn_math.hpp:225-230`）の欄は `uqe_tau`（読み書き 0。[issue-20261111-54c7e1](issue-20261111-54c7e1.md)）、`learn_step`、`per_beta` の 3 つである。
- `learn_step` の読み書きは `dqn_learner.cpp` だけにある（518・632・682・750・846・1811・1815〜1817・1832・1864・1870・2413・2442 行）。`per_beta` の書き込みは Learner の 2 行（1016・1672）、読み手は Learner の 1 行（1791）と、Agent の scalar の振り分け 1 行（`dqn_assembler.cpp:411`）だけである。
- DefaultDQN と Rainbow は、`RuntimeVars` を作って Learner と振り分けへ渡すだけで、中を見ない。
- テストは Learner を作るために `RuntimeVars` に触れる（検索語 `RuntimeVars`。`dqn_learner_test.cpp` 61 行、`dqn_actor_test.cpp` 10 行ほか、合わせて 88 行）。値を読むのは `learn_step` と `per_beta` の 11 行である。
- 設計 200 は、`RuntimeVars` を Agent の State の置き場として書く（288・329・354・627・629・654 行）。

## 影響

- Learner の構築の引数が 1 つ増え、Learner より長く生きる State の寿命を Agent が守る（参照のメンバ `RuntimeVars& vars_`）。
- 学習の進みを保存する作業（[issue-20261103-aa8701](issue-20261103-aa8701.md)、RFD0143 は `RuntimeVars` を Agent の runtime state に挙げる）で、Learner の checkpoint と別の所から保存することになる。

## 対応方針

- `learn_step` と `per_beta` を Learner のメンバにし、`per_beta` は Learner の `GetScalar` で答える。`RuntimeVars` と構築の引数を消し、設計 200 と RFD0143 の記述を合わせる。`per_beta` のメトリクスの名前と値、評価の時機（前回の更新の終わりに次回分、初期値は step 0）は変えない。
- 性能の区分は「関わらない」（参照をたどる 1 回が無くなるだけ）。
- トピック別まとめの「変えるときの条件」では、RFD0101 §4.2 D7（PER β だけは今の時機を保つ）と RFD0182 §4.1 D24（テストのケース数）が当たる。
- テスト: `dqn_actor_test.cpp:1913` は `vars.learn_step = 1` を先に書くので、Learner の側に置き換える形（更新を 1 回進めるか、テスト用の派生で持つ）が要る。
- 不採用の形・ADR との突き合わせ: `docs/` を `RuntimeVars` で検索し、当たるものは無い。ADR 0048 は名前の衝突に触れるだけである。
- Agent の scalar の振り分け（[issue-20261125-6a8e46](issue-20261125-6a8e46.md)）と同時に直せる。
