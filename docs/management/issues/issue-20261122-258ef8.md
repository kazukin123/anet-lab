## 背景

PRD161（観測パイプラインと強制行動の `MakeAction` 入力化）のグリル（2026-11-20〜22）で、観測の正規化の今の作りを調べたときに分かった（[PRD161](../../memo/0161_observation_pipeline_10rfd.md) の §1.3 の c）。PRD161 は、統計つきの正規化を成り立たせることを範囲に入れず、stack 軸つきの入力で形が合わない点だけを直す（同 NG2・D28）。

範囲に入れないことは、グリルでゴールと非ゴールを確かめたときに合意した。課題にするかは、グリルの中では質問していない。工程末に起票の候補として示し、開発者が記録すると選んだ。

統計が checkpoint に保存されないことは、別の課題 [issue-20261113-b96b2c](issue-20261113-b96b2c.md) にある。

## 事象

- Actor は、行動選択のたびに、観測の正規化の統計を読んで観測に当てる（[dqn_actor.cpp](../../../src/algo/dqn/src/dqn_actor.cpp)）。この読み取りは、Agent の排他の外で行う。
- 統計の更新は、経験の受入れ（`DefaultDQNAgent::UpdateFromBatch`）の中で、Agent の排他を取って行う（[default_dqn_agent.cpp](../../../src/algo/dqn/src/default_dqn_agent.cpp) の `NormalizeAndUpdateStats` の呼び出し）。
- 背景評価と EvalPanel の Actor は、学習と並んで走る。
- 出荷の設定は、どれも素通しで、統計を読まない（[agent.txt](../../../apps/runner/config/agent.txt) の `obs_norm.pass_through`）。統計を読むのは、素通しでなく、統計つきの設定を書いた構成だけである。
- PRD161 を実装すると、統計は `Normalize` の部品が持つ。更新するのは「統計を更新しつつ Frame を作る」依頼だけで、Perception を作る依頼は読むだけになる（PRD161 の D40）。読み書きの排他は、PRD161 では変えない。

## 影響

- 統計つきの正規化の構成で、評価の Actor が、更新の途中の平均と分散を読むことがある。壊れた値か、学習の側と違う尺度の観測を、Network へ渡す。ERROR も WARN も出ない。
- 出荷の設定では起きない。

## 対応方針

未定。

着手の条件は、統計つきの正規化を使う構成（連続制御など）を足すときである（PRD161 の NG2）。checkpoint への保存（[issue-20261113-b96b2c](issue-20261113-b96b2c.md)）と、評価だけの Run で統計を止めることを、同じ仕事として決めると、統計の持ち方が 1 回で決まる。
