## 背景

2026-11-18 の定常整備の監査（観点 drift、範囲 docs/design/200_dqn_agents.jp.md）で、文書の §1〜§5 を今のコードと ADR 0038（Actor のカタログ化）に突き合わせて見つかった。3 点とも、方策を Actor が持つ形へ移ったあとの記述の取り残しで、同じ節を同時に直せる。開発者には質問していない。設計文書 200 は直近 90 日の変更回数で上位（stats の churn90 で 2,320 ファイル中 13 位）なので、ホットスポット補正で urgency を 3 から 5 へ 1 段上げた。

## 事象

- 方策の持ち主: 237 行は「DefaultDQNはTrain、Eval、target用Policyを分け」、281 行は `DefaultDQNAgent` の説明に「複数Policy」を含め、§5 の図（354-355 行）は Agent が ActionPolicy を合成で持ち、367 行で `DqnActor --> ActionPolicy` を関連にとどめる。コードで Agent がメンバに持つ方策は `target_policy_` だけ（`default_dqn_agent.hpp:849`、`rainbow_agent.hpp:137`）で、Actor 用の方策は `CreateActor` のたびにカタログ項目の `cfg.policy` から作り（`default_dqn_agent.cpp:751`）、Actor が `policy_` として持つ（`dqn_based_agent.hpp:992`）。239 行の「Trainの既定はrandom×32、Eval/targetはfixed×32」の eval 側は、コードの既定ではなく profile の `actor.@eval_base`（`apps/runner/config/agent.txt:223-225`）が与える。
- Actor Q ヒント: 257 行は「`actor_approx`の場合だけ、Train Actorは…hintを作る」と書くが、`DqnComponentAssembler::CreateActor`（`dqn_based_agent.cpp:6299-6302`）は `use_per && mode==ACTOR_APPROX` だけで決め、Actor の種類を見ない。ADR 0038 は「Actor Q ヒント送出」を RunMode への依存として外すと決めている。
- 楽観ターゲット: 192 行は「`actor.[train].policy`をtarget方策の既定へコピーし、epsilonを0にする」とだけ書く。`ReadTargetPolicy`（`default_dqn_agent.hpp:385-416`）は `uqe.epsilon` も 0 にし、`EpsilonGreedy` を `Greedy` に変え、`tau_rule` と `full_distribution_query` は train 側から引き継がず既定に戻す。

## 影響

読者は Agent に Train・Eval の固定の枠があると誤解し、任意のカタログ項目と方策の持ち主を取り違える。eval 系の Actor はヒントを作らないと思い込み、費用を見誤る。楽観ターゲットが train の τ の並べ方を引き継ぐと誤解する。

## 対応方針

未定。監査の案は、方策は「カタログ項目ごとに Actor の生成時に作り Actor が持つ。Agent が持つのは target 用だけ」と書き、図の合成を Actor 側へ移し、eval の fixed×32 は profile の既定と書き分ける。ヒントは「PER 有効かつ actor_approx のとき、Agent が作るすべての Actor が作る」とし、192 行に楽観ターゲットで変える項目と戻す項目を足す。
