## 背景

サブ機の KFM×RND（β 0.1、10M、seed s04〜s10）が RND なしの基準を上回らなかった。2026-11-11 の会話で、完走した Run の metrics_cache.db をメイン機へコピーして内的報酬の大きさを確かめ、メイン機の Montezuma の Taiga ら寄せの Run も同じ見方で確かめた。開発者の指示で暫定 PRD として起票し、質疑はしていない。

## 事象

- KFM の RND の 3M 以降、1 step の内的報酬は lane 平均 1e-4〜8e-4、報酬の絶対値に占める割合 1.4〜5.7%、Munchausen の項の約 1/100 で、正の lane は約 1 割だった。
- 誤差の平均・標準偏差は Run の最初からの累積（Welford）で、warm-up 中の誤差も入る。最初の 200k exp step の誤差が二乗偏差の総量の 97〜99%（KFM）、88〜97%（Montezuma）を占めた。
- 200k 以降の誤差だけで逆算した標準偏差に比べ、実際の標準偏差は KFM の 10M で 7〜19 倍、Montezuma で 0.5〜2M に 9〜17 倍、14〜29M に 3〜4 倍だった。

## 影響

- 内的報酬が名目の β の数分の 1〜十数分の 1 に抑えられ、β の比較が名目どおりの意味を持たない。
- 抑え方が Run の中で薄まるので、実効の β が Run の中で 3〜5 倍に上がる。設定に書いていないスケジュールが Run の結果に入る。
- 平均以下の約 9 割の状態に内的報酬が付かず、誤差が下がると内的報酬が消えていく（LunarLander・GridMaze で観測した現象と同じ形）。

## 対応方針

[PRD123](../../memo/123_rnd_intrinsic_reward_scale_10prd.md)（暫定）で、warm-up 中は誤差の統計を更新しない形、誤差の統計を指数移動平均で取るモード、平均を引かない倍率の形を決める。再グリルは別の枠で行う。

- 2026-11-11 PRD123（実装）: warm-up 中の predictor 学習と誤差統計の除外、誤差統計の累積・EMA、中心化の選択、done の内的報酬の mask の選択を実装した。累積と variance_feedback の checkpoint 書式は維持し、EMA は別の識別子にした。共通設定と日英の設計文書、PRD116 の smoke 判定を追随させた。確かめ: Debug 全体ビルド、修正後も関連60ケース・4,804断定、7環境の既存設定値の維持、RND 無効4環境とcollect_errors・variance_feedback 各100k件の全 scalar 計848,529点と定義の一致、着手前 checkpoint の読み込みが成功。独立レビューはテスト定数化の1件を修正し、2往復目で計画・実装ともOK。Atari の warm-up 200,000 行は stage20 の終了未確認のため未追加。KFM の効果確認10本は別の段取りの承認後に行う。この2件の残作業と効果未確認のため判定は残件有り、状態は対応中のままとする。[実装記録](../../memo/123_rnd_intrinsic_reward_scale_20impl.md)
