## 背景

2026-11-21 の PRD193（重みの初期化に `variance_scaling` を足す）のグリルで、初期化の設定に欄を 1 つ足すことになった。AI は、今の読み方のまま 14 か所に 1 行ずつ足す案を推奨して開発者に質問し、開発者は、初期化の設定の読み取りを 1 つの口にまとめる形を選んだ。読み取りの口の課題（親）は、初期化・GraphViz・観測の正規化の 3 つの設定の型を持つ。このうち初期化の分を、この課題に分けて PRD193 に結び付けた。GraphViz の設定、観測の正規化の設定、方策の検査の置き場は、親に残る。

## 事象

- 初期化の設定を 1 キーずつ読む行が、14 か所に 94 行ある。src/core/base/src/nn_modules.cpp に 63 行（ResBlock の `init1`・`init2`・`init_ds`、CNBlock の `init_dw`・`init_pw1`・`init_pw2`、Linear・Conv1d・Conv2d の `init`）、src/algo/dqn/src/default_dqn_agent.hpp に 18 行（`intrinsic.value.head.init`・`head.init`・`skip.head.init`）、src/core/base/src/intrinsic_rnd.cpp に 7 行、src/algo/dqn/src/rainbow_agent.hpp に 6 行である。[出典](../../memo/193_variance_scaling_weight_init_10prd.md)（§5.2）
- block の 9 か所は、読んだあとに検査を呼ばない。不正な値は、最初の forward の初期化の直前に `Invalid WeightInitConfig.trunc_std=0; expected > 0.` の形で止まり、block 名も接頭辞（`init1`・`init2` など）も文に出ない。Agent・RND の 5 か所は、読んだ直後に設定キーの全体つきで止まる。[出典](../../memo/193_variance_scaling_weight_init_10prd.md)（§5.1）
- DQN の 3 か所と Rainbow は `nonlinearity` を読まず、"linear" を使う。block の 9 か所と RND は設定から読む。
- `GetNonlinearityType`（src/core/base/src/nn_modules.cpp の 152〜159 行）は、`relu`・`linear`・`tanh`・`leaky_relu` のどれでもない名前を `relu` として扱う。

## 影響

- 初期化の設定に欄を足すと、14 か所を直すことになる。
- block で不正な値を書くと、どの block のどの設定キーかが ERROR の文から分からず、止まるのも最初の forward まで遅れる。
- `nonlinearity` の綴りを誤ると、止まらずに `relu` の gain で初期化される。

## 対応方針

PRD193 の D5〜D10・D15・D18 のとおりに直す。初期化の設定の読み取りを 1 つの口にまとめ、14 か所はその口で読む。口は、読んで検査する入口と、読むだけの入口を持つ。block は Network の構築時に、読んだ直後に検査する。どの読み手も `nonlinearity` を読み、DQN と Rainbow の Head は "linear" を既定にする。未知の `nonlinearity` は ERROR で止める。

## 対応内容

- 2026-11-21 PRD193: グリルで、読み取りの口の形（読んで検査する入口と、読むだけの入口）、block の検査の時機、`nonlinearity` を揃えること、未知の `nonlinearity` を ERROR にすることを決めた。確かめ: PRD のレビューが 2 往復目で OK。[PRD](../../memo/193_variance_scaling_weight_init_10prd.md)
