## 背景

2026-11-15 に、[実装 品質確認観点](../../quality/impl.md)の「C++ コード」へ、クラス宣言の区切りの規約（項番 78）を足した。規約は新しく書くクラスだけに当て、既存のクラスの並び・アクセス指定・空行は直さないと書いた。既存の扱いは開発者に選択を尋ね、「新しく書くものだけに当てる」と、「どっかでまとめて補正します」の回答を得た。同じ日に、関数名を動詞で始める規約の案も出した。この案も、既存の関数をこの規約だけを理由に改名しない形である。

include の順の規約（項番 63）も、既存ファイルの include をこの規約だけを理由に一括で並べ替えない、と書いている。

あとでまとめて直す分を残しておくため、開発者の指示で起票した。`.cpp` の内部リンケージと namespace のインデントの規約は PRD079 が決めており、その既存コードの直しは課題 [issue-20261103-5addea](issue-20261103-5addea.md) にある。

## 事象

- impl.md の規約のうち、既存のコードを直さないと明記しているものは 2 つある。include の順（項番 63）と、クラス宣言の区切り（項番 78）である。
- 関数名の形の規約は、2026-11-15 の時点で案の段階である。アクセサの名前（`Get` で始めるか）と、標準ライブラリ・libtorch と同じ名前の計算を例外にするかが決まっていない。
- 2026-11-15 に、core と apps の `.hpp`・`.cpp`（225 ファイル）を大まかに数えた。`private:` の前に空行が無いものは 329 か所、あるものは 133 か所である。項番 78 は、アクセス指定の前に空行を入れない。
- 同じ日に、ヘッダの引数なしの const 関数を名前の形で数えた。`Get` で始まるものが 266、`Is`・`Has` などの問いの形が 40、そのほかの PascalCase が 178（そのうち名詞の名前は約 40 種。`Capacity`・`Mean`・`Order` など）、snake_case が 35 である。
- 種類の切れ目でアクセス指定を書き直す書き方は、Runner のパネル（`Conv2dPanel.hpp`・`QValuePanel.hpp` など）の一部にだけある。
- 2026-11-15 ハーネス保守: 関数名の形の規約を impl.md に入れた（項番 79）。引数なしで状態を読む関数は `Get` で始め、標準ライブラリ・libtorch と同じ名前の計算は例外にした。既存の関数は、この規約だけを理由に改名しない。[実装 品質確認観点](../../quality/impl.md)

## 影響

- 同じファイルの中で、クラスごとに区切り方・include の並び・関数名の形が違い、読む側が規約どおりかを見分けにくい。
- impl.md の「C++ コード」は、既存コードに明確なローカル規約がある場合は周辺コードとの一貫性を優先する、と書いている。古い書き方が残るファイルに新しいコードを書くとき、どちらに合わせるかの判断が毎回要る。

## 対応方針

決めること:

- 進め方。規約ごとに分けて直すか。機械で見つけられるもの（include の並び、アクセス指定の前の空行、関数名の先頭の語）は、検出の道具で一覧にしてから直すか。
