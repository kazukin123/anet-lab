## 背景

2026-11-10〜11 のリファクタリング候補の抽出（C++ の本体を 16 単位に分けて読み、観点は docs/quality/refactor.md による）で見つかった。開発者が候補の一覧から選び、起票を指示した。2026-11-11 に今のコードで場所を確かめ直した。

どれも Runner のパネルの中の写しで、画面の確かめ方が同じなので、1 件にした。

## 事象

- GL キャンバスへ画像を貼る一式。
  - `SweepHeatMapPanel::Render`（apps/runner/src/HeatMapPanel.cpp:563 から）と `Conv2dPanel::Render`（apps/runner/src/Conv2dPanel.cpp:131 から）は 82 行ずつで、違いは画像の出どころの 1 行だけである。テクスチャの設定・転送・四角形の描画・コメント・`@todo` まで同じである。
  - `GL_CLAMP_TO_EDGE` の補い、キャンバスと context の生成（HeatMapPanel.cpp:382、Conv2dPanel.cpp:49）、`OnPaint` と `OnSize` も同じ文である。
  - 食い違いが 1 つある。`SweepHeatMapPanel` のデストラクタは `delete context_` をする（HeatMapPanel.cpp:495）が、`Conv2dPanel` のデストラクタ（Conv2dPanel.cpp:106 から）はしない。
  - Conv2dPanel.cpp の先頭のコメントは `// HeatMapPanel.cpp` のままである。core/envs/atari1 の AtariView にも同じ手順のテクスチャ描画がある。
- EvalTracePanel の行の探索。「行の ID から行の位置を引く」線形探索が 8 か所に手書きされている（apps/runner/src/EvalTracePanel.cpp:373、384、391、401、413、458、482、569）。書き方が `for` で最後の一致を残す形と `std::find_if` の形の 2 通りあり、見つからないときの扱いも箇所ごとに違う。`AddRow` の中に 4 回あり、391 は直前に `sorter_.Upsert` が返した位置へ入れた行を探し直している。
- EvalTracePanel の再生ツール。ツールの並びと記号の対応を、コンストラクタの表と `UpdateIcons` の `symbols` が同じ順で 2 回書く。配列の大きさが 6（`tool_ids_`）と 7（`icons_`）で直書きされ、再生ボタンを `tool_ids_[0]` で 4 か所から指す（551、555、556、720）。「再生できるか」の式も 2 か所で同じ文である（551、720）。
- SweepHeatMap と Conv2dPanel を名指しで確かめるテストは無い。

## 影響

- 描画の直し（テクスチャの使い回し、DPI、上下反転）を 1 つ入れると、2 つのファイル（Atari を含めると 3 か所）を同じに直すことになる。既に context の破棄の有無が食い違っている。
- 行の探索は `AddRow` の流れを追いにくくし、見つからないときの扱いの違いが意図かどうかが読めない。
- ツールを 1 つ足す・順を変えると、表・`symbols`・配列の大きさ・添字 0 の前提を同時に直すことになる。

## 対応方針

- 「wxImage を GL キャンバスいっぱいに描く小さな窓」（キャンバス・context の所有と Render・OnPaint・OnSize を持つ）を 1 つ作り、2 つのパネルは画像を渡すだけにする。Conv2dPanel の context を破棄するようにすると破棄のときの挙動が変わるので、そのことを確かめる。
- `std::optional<int> FindRowIndex(int64_t id) const` を 1 つ作って置き換える。391 は、退去でずれる分だけ `position` から導く。ID が重ならないことを `TraceRowSorter` で確かめる。
- ツールの表をファイルの定数にして `UpdateIcons` もそれを回す。再生ボタンの ID は名前のあるメンバにし、「再生できるか」を private の関数 1 つにする。
