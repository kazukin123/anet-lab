## 背景

2026-11-25 の監査（観点 defect、範囲 321_agent_core）で見つけた。分類は数値（診断値）である。開発者には質問していない。

設計 200 §9.1 と RFD0047 は、`iqn_policy_margin_mc_ratio` を「IQN+UQE 以外または `K < 2` では NaN」と書く。点の UQE（risk の問い合わせが 1 点）で本数だけを複製する場合には触れていない。

ホットスポット補正: `dqn_actor.cpp` は、`git log --since=2026-08-27 --follow` で 90 日に 9 回変わっており、コードのファイルの上位 5%（7 回以上）に当たる。urgency を 3 から 5 へ 1 段上げた。

## 事象

- `MakeUQEActionInfo` は、点の UQE の risk の問い合わせを、full query が無いときだけ `tau_rule.num_taus` 本に複製する。spatial は `point_count = full_query ? 1 : config_.tau_rule.num_taus` のあと `lower.unsqueeze(1).expand({N, point_count})`（`src/algo/dqn/src/dqn_actor.cpp:1126-1129`）、scalar は `torch::full({N, point_count}, effective_tau)`（1136〜1142 行）で、K 本はすべて同じ τ である。
- 比の成立の条件は `risk_num_taus >= 2`（1231 行）だけなので、複製でも成立扱いになる。標準偏差は同じ τ の同じ出力から作るので 0（丸めの差だけ）で、分母は `0 + 1.0e-6f`（1240 行）になり、値は「上位 2 行動の差 ÷ 1e-6」になる。
- 出荷設定で起きる。LunarLander の既定は `DefaultDQNAgent.$ = @baseline > @iqn > …`（`apps/runner/config/LunarLander.txt:21`）、`policy_type = UQE`（145 行）、`use_tail_mean = false`（147 行）、`tau_rule.num_taus = 32`（143 行）、`spatial.enabled = true`（223 行）で、`full_distribution_query.enabled ?= false`（`agent.txt:232`）のままである。tag は `M1.[33_agent_action/21_iqn_policy_margin_mc_ratio_ema]`（`LunarLander.txt:448`）が記録する。
- 実物で確かめた。`run_20261124-113451_ll`（実効設定は UQE・`use_tail_mean = false`・`num_taus = 32`）の `33_agent_action/21_iqn_policy_margin_mc_ratio_ema` は、23,791 点あり、終盤 1M exp step の平均 196,865、最小 177,116、最大 207,253 だった（`inspect_run.py metrics … --range -1M:`）。
- テスト: 点で K=1 の場合だけ NaN を確かめる（`dqn_actor_test.cpp:1015-1069`。full query 有効）。点で K=3・full query 無しの節（943〜966 行）は τ と Q だけを見て、この値を見ない。

## 影響

- ユーザーガイド 030 §4.5（187 行）は、この値で τ の本数と配置の安定度を読むと案内する。LunarLander の train では、値が τ の配置と無関係な「Q の差の 1e6 倍」なので、K の比較や条件の比較に使うと誤る。
- 学習と行動選択の値は変わらない（同じ値の平均）。

## 対応方針

- 点の問い合わせ（`use_tail_mean` が偽で、全範囲の問い合わせでもない枝）では、本数によらず比を NaN（未成立）にする。計算する条件だけの変更で、forward・乱数・行動選択に触れない。LunarLander の tag は記録されなくなる（Observer は NaN を出さない）。設計 200 §9.1 の NaN の条件も合わせて直す。
- 点で K=3・full query 無しの節に、比が NaN であることの確認を足す。
- 点の問い合わせを常に 1 本にすると行動の forward が軽くなるが、平均の丸めが変わるので同 seed の一致の確かめが要る。この課題には含めない。
