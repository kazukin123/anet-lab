## 背景

PRD116（RND の内的報酬）の 2026-11-07 の改訂で、Atari の RND の Network が意図と別の形で組まれていたことが分かった（[PRD116 §2.1](../../memo/116_rnd_lifelong_novelty_10prd.md)）。原因は、`nn.txt` の `Conv2d_S`・`Conv2d_M`（`Conv1d_S`・`Conv1d_M` も）が `out_channels`・`kernel_size`・`stride`・`padding` を block の直下に書いているのに、`Conv1d`・`Conv2d` の読み込みが `conv.out_channels` などを読むことで、直下の葉は読まれず、既定の形で組まれていた。その 4 block の葉の直しは PRD116 の実装で行う。本課題は、書かれた葉が読まれないことを仕組みとして検出できない点を扱う。

同じ系統の既存の課題は 2 件ある。[issue-20261103-66100f](issue-20261103-66100f.md)（`Conv2dPanel.conv2d.mergin_x/y` の綴りの誤りで読まれない）と [issue-20261103-b754ff](issue-20261103-b754ff.md)（`stucker.stack_keys` の存在しないキー名が検出されない）。どちらも個別の事例で、本課題は `net.block` の葉の検出の仕組みを対象にするため分けた。

開発者に質問したか: PRD116 の工程末に課題の候補として示し、開発者が起票を選んだ（2026-11-07）。PRD116 §8 の 16 に「本 PRD の範囲外」として記録してある。

WARN で報告する形を選ぶなら、正常な Run で毎回出ている WARN（[issue-20261107-a9a0e3](issue-20261107-a9a0e3.md)）に紛れないようにする。開発者は 2 件を一緒に扱う意向である（2026-11-07）。

## 事象

- `net.block.[Conv2d_S].out_channels ?= 32` のように、読み込み側が期待する階層（`conv.out_channels`）と違う位置に書かれた葉は、構築時にエラーにも WARN にもならず、`ConvConfig` の既定（128 チャンネル、3×3、stride 1、padding 0。`core/anet-core/src/nn_modules.cpp` 2969 行付近）で Network が組まれる（読み込みは同 3020 行・3059 行付近の `Conv1dModuleFactory`・`Conv2dModuleFactory`）。
- Atari の `run.@rnd` はこの block を使い、2026-11-06〜07 の RND の Run（KFM s04、Montezuma s1・s2）は 1 Network 105,006,592 パラメータ（意図は 854,240）で動いた。checkpoint の増分 1,680MB がこの値と一致する。
- PRD072 の既定葉検査（`core/anet-core/testdata/prd072/check_default_leaves.py`）は `?=` と `=` の使い分けを見る静的検査で、書かれた葉が読まれたかは見ない。`[shipped_config]` のテストも、組んだ Network の形を断定する行が無ければ気づかない。

## 影響

- 設定の階層違い・綴り違いが黙って通り、意図と違う Network や値で Run が走る。実験の条件が設定ファイルの記述と食い違ったまま結果が残る。
- 今回の例では、新しさの判別は落ちなかったが、1 step の費用（RND ありの Run が 2.4 倍遅い主因の候補）と checkpoint の大きさ（1.7GB）に害が出た。別の block なら結果そのものが変わりうる。
- 層カタログ（`nn.txt`）の見本（`@Conv2D`・`@ViT_*` など）にも同じ書き方が残っており、使った人が同じ落とし穴に当たる。

## 対応方針

未定。候補は次のとおり。

- `net.block.[<name>]` ごとに、読み込みで消費した葉と設定に書かれた葉を比べ、読まれなかった葉があれば構築時に `ANET_SYSTEM_ERROR`（Fail-Fast。AGENTS.md「設定値の扱い」の「設定に書いたことがそのまま起きる」）にする。意図して無視させる葉が要るなら、モード値で明示させる。
- 設定基盤の側で「解決されたが一度も読まれなかった葉」を Run の開始時に報告する仕組み（WARN か一覧の出力）。`net.block` 以外の節にも効くが、`intrinsic.enabled=false` のように読まないことが契約の葉と区別する基準が要る。
- どちらを選ぶかは PRD で決める。PRD116 の実装（4 block の葉を `conv.*` へ直す）はこの課題を待たない。
