## 背景

2026-11-19 の会話で、開発者が、今の RND の実装を Burda らの論文（[arXiv 1810.12894](https://arxiv.org/abs/1810.12894)）と比べるよう求めた。AI は論文の §2.3・§2.4・§3.3〜3.5 と付録 A.2〜A.5（擬似コードと表 2〜5）を読み、設定で変えられる差と Run の規模の差を除いて、実装に無いか実装の作りが違う要素に絞った。そのうちの 1 つで、開発者が起票を指示した。開発者への質問はしていない。

[PRD121](../../memo/0121_extrinsic_intrinsic_value_decomposition_10rfd.md) の §1.4 は、「n-step の和に、次のエピソードの報酬まで足すこと」を非ゴールにしている。理由は、Replay の窓がエピソードをまたぐ契約の変更になる別の関心であることで、技術の制約ではないとしている。本課題は、論文との差として、この部分を記録する。

## 事象

- 論文の §2.3 は、内的の収益を game over で切らない（非エピソード）。Algorithm 1 は rollout の中で収益と advantage を計算する（GAE の λ 0.95、表 5）ので、内的の収益は env のリセットをまたいで続く。
- anet の `terminal_mode = non_episodic` は、終端後の最初の観測から内的だけを bootstrap する（[214](../../design/214_value_decomposition.jp.md) §3.1）。n-step の和はエピソードの終わりで切れ、次のエピソードの内的報酬は和に入らない。
- Montezuma で `non_episodic` を使った Run（g99ne の群）は、実験記録 [2026-11-08_montezuma-rnd-taiga-aligned.md](../../experiments/default-dqn/atari/2026-11-08_montezuma-rnd-taiga-aligned.md) にある。
- 2026-11-21 監査で確認。replay_experience.cpp の NStepQueueController は done または truncated までで系列を区切る。DefaultExperienceBuilder はその系列から追加成分の収益を計算する。
- 2026-11-23 監査（backlog）: RFD0191（2573b18e）は本課題を範囲外とし、作る条件（non_episodic の効果が分かり、終端近くの数 step の差が効くと分かったとき）を書いた（`docs/memo/0191_rnd_raw_error_and_recent_learning_10rfd.md` の 47 行）。

## 影響

- エピソードの終わりの直前の遷移では、内的の目標値の n-step の部分が短くなり、残りを終端後の最初の観測の内的の Q に頼る。論文の非エピソードの収益とは、この部分が違う。
- anet の n-step（Atari の主な構成では 3）は GAE より短いので、差が出るのは終わりに近い数 step に限られる見込みである。測ってはいない。

## 対応方針

未定。PRD121 の非ゴールの扱いのまま、`non_episodic` の効果が分かってから要否を決める。
