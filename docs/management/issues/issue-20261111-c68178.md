## 背景

2026-11-10〜11 のリファクタリング候補の抽出（C++ の本体を 16 単位に分けて読み、観点は docs/quality/refactor.md による）で見つかった。開発者が候補の一覧から選び、起票を指示した。2026-11-11 に今のコードで場所を確かめ直した。

PRD085（DropMerge の評価スコアの軸）は、ここへ統計を足す。

## 事象

- `StepResult` は Env の 18 個のメンバを 1 つずつ写す（core/envs/dropmerge1/src/DropMergeEnv.cpp:85-109 の初期化子）。写す先のメンバも同じ名前で 18 個ある（112-130）。
- `Reset`（433 から）は同じ統計を 1 行ずつ 0 に戻す（16 行）。
- `StepResult::GetScalar`（1572 から）は 19 個の鍵を if の連鎖で比べる。終了理由の 5 つは、鍵と enum の値だけが違う同じ 4 行である。`if (!episode_ended_) return nan;` が 9 回出る（1615、1639、1643、1647、1651、1655、1661、1665、1678）。
- DropMergeEnv.hpp の「aux用 (Resetで初期化しない)」のコメントの並びにある `episode_reward_` は、Reset で 0 に戻る。

## 影響

- 統計を 1 つ足すと、Env のメンバ・Reset・StepResult の初期化子・StepResult のメンバ・GetScalar の 5 か所を直す。PRD085 で評価スコアの軸を足すときに当たる。
- Reset への足し忘れは、前のエピソードの値が残る形で現れ、コンパイルでは気づけない。

## 対応方針

エピソード統計を 1 つの struct（既定値つき）にまとめる。Env は `stats_ = {}` で戻し、StepResult は struct を 1 行で写す。終了理由の 5 つの鍵は、鍵と enum の表にする。メトリクスの鍵の名前は変えない。コメントは実際の動きに合わせる。
