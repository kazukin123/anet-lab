## 背景

[PRD116](../../memo/116_rnd_lifelong_novelty_10prd.md) の RND（一生の新しさ）は、既定（`clipped`・`whiten`）では predictor の誤差が whiten の一生平均を下回り続けると bonus が 0 になる。GridMaze では観測が (x, y) の 2 値で入力が 25 通り以下なので最初の数千 step で尽き（`run_20261107-212611`）、LunarLander でも採点 5〜10 万件で消えた（2026-11-08 の `ll_rnd_s1`〜`s3`）。

そこで開発者が 2026-11-07 に「predictor と誤差統計を一定間隔で初期化し、warm-up をやり直す（target は固定のまま）」案を出した（PRD116 §8 の 18）。初期化の直後は predictor が訪問の多い状態から先に覚えるので、訪問の少ない状態の誤差がしばらく高く残り、その間だけ訪問回数の逆順に近い bonus が出る、という狙いである。2026-11-08 に暫定実装（未コミット）で GridMaze 1 本と LunarLander 3 seed を試し、同日に開発者が「考えと現状の結果だけを課題と実験記録に残し、実装は戻す」と決めた。実装はコミットされていないので、作り直すときのために要点をここに残す。

## 事象

試した実装の要点:

- 葉は `DefaultDQNAgent.intrinsic.rnd.reset.mode ?= none`（`none`｜`predictor`）と `intrinsic.rnd.reset.interval ?= 100,000`（直近のリセットからの採点件数）。`predictor` では interval が `warmup_steps` より大きいこと、`statistics_mode=whiten` であることを構築時に検証し、`none` で interval が既定以外なら WARN 1 回。
- 採点（`Estimate`）の先頭で、直近のリセットからの採点件数が interval に達したら、predictor とその AdamW を作り直し（新しい重みは predictor の seed からリセット回数で派生）、whiten の誤差統計を初期化して warm-up をやり直す。target、観測の正規化統計、target 出力の統計は保つ。warm-up と周期はどちらもリセット時点からの採点件数で数える。
- 診断 `reset_count`（メトリクス `56_agent_in/33_reset_count`）。checkpoint は識別子を `RndNoveltyEstimator-3;reset` にし、採点件数の後ろにリセット時点の採点件数とリセット回数を置く。識別子が設定と合わなければ payload の前で拒否する。
- `run.@rnd_reset`（GridMaze.txt・LunarLander.txt。`run.@rnd` の後ろに重ね、interval 50,000）。テストは 2 本（設定の検証。リセットで warm-up と誤差統計がやり直され predictor が変わること、復元が phase を持ち越すこと）。

GridMaze（`run_20261108-003804`、seed 1、256 lane、interval 50,000、00:38〜00:45 の 1 本、44 回リセット）:

- bonus が出るのは各リセットの warm-up 直後の窓だけ。リセットからの採点 12,800〜20,000 件で `03_bonus_share` の平均 0.018、正の割合 2.6%、`02_bonus_max` 0.019。周期の残り（20,000〜50,000 件）は 3 つとも 0。`31_predictor_loss` の中央値は 5e-7。入力が 25 通り以下なので、新しい predictor が warm-up の間に全部を覚え直す。

LunarLander（`ll_rnd_rs50k_s1`〜`s3`、3 seed × 2M、各 39 回リセット。詳細は[実験記録](../../experiments/default-dqn/lunarlander/2026-11-08_rnd-harm-check-and-predictor-reset.md)）:

- bonus は 2M の間続いた（`03_bonus_share` の Run 全体平均 0.033〜0.039、正の割合 8〜12%。リセット無しの RND は 0.5M 以降 0.0003）。ただし周期の中は warm-up で 0 → 直後に 0.10〜0.11 → 周期末に 0.013〜0.020 の鋸歯で、周期ごとの平均は後半ほど大きい。状態の新しさではなく、リセットが作る周期信号になっている。
- 評価側（UQE full `21_eval/02_policy_reward`）の 1.5〜2M は 183.7／196.8／213.5 で、リセット無しの RND（181.1〜225.5）とも 11/05 の基準 9 本（188.6〜225.7）とも同じ帯。利得は無い。
- seed 2 が 0.78〜0.9M で崩れた（20k 窓の平均が −180 → −1,106、−1,000 未満の局が 8 つ。完走した 2M の LunarLander 89 本で、0.5〜1.5M にこれが 3 局以上あるのはこの Run だけ）。直前の周期は seed 2 で share が最も大きい周期（0.056、正の割合 13%）で、同じ区間に `37_agent_qtd/11_q_max_mean` が 1.35 → 3.5、`37_agent_qtd/21_grad_norm` が 0.9 → 1.45 と上がった（リセット無しの RND と基準の同じ seed は 1.05〜1.30）。因果は確かめていない。
- 全 seed で学習側が基準より荒い。1.5〜2M の `q_max_mean` 2.15／1.85／2.17（リセット無し 1.37〜1.83、基準 9 本 1.06〜1.57）、`grad_norm` 0.76〜0.81（0.38〜0.46、0.29〜0.48）、UQE full の局の長さの Run 全体 268／329／233（192〜225、188〜279）。

## 影響

実装は戻し、既定も変えていないので成果物への影響は無い。残す理由は、924 の再グリルで同じ案が出たときに同じ試行を繰り返さないことと、コミットしていない実装の要点を失わないことである。

## 対応方針

当面は実装しない。[924](../../memo/924_intrinsic_reward_novelty_10prd.md) の再グリルで、エピソード内の新しさ（NGU のエピソード記憶、E3B、NovelD のエピソード内ゲート）と比べて採否を決める。再び試すなら、新しさが尽きにくい Env（Montezuma）で、bonus の山と `q_max_mean` の膨張を一緒に見る。周期・warm-up の長さと、誤差統計の EMA（PRD116 §8 の 3）との比較も同時に置く。

## 対応内容

- 2026-11-08 PRD116: 暫定実装で GridMaze 1 本と LunarLander 3 seed × 2M を試し、上の結果を得たあと実装を戻した（`intrinsic_rnd.cpp`・`intrinsic_rnd.hpp`・`intrinsic_test.cpp`・`212_rnd_lifelong_novelty.jp.md` を HEAD へ。`agent.txt` の reset の葉、`GridMaze.txt`・`LunarLander.txt` の `run.@rnd_reset`、12 bat の `ll_rnd_rs50k` の段を削除）。[実験記録](../../experiments/default-dqn/lunarlander/2026-11-08_rnd-harm-check-and-predictor-reset.md)
