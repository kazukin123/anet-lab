## 背景

2026-11-23 の監査（観点 defect、範囲 324_dqn）で見つけた。分類は境界である。開発者には質問していない。DQN 系の同じ種類の欠け（勾配の clip の上限ほか）は [issue-20261123-eb0a0c](issue-20261123-eb0a0c.md) に分けた。Agent も設定の型も別で、別々に直せるためである。

AGENTS.md の「Fail-Fast 原則」は、Run の構築の終わりまでに判定できる設定の違反を実行時へ先送りしないとしている。ImageCls の勾配の clip は有効・無効の切り替えを持たず、常に当てる。

## 事象

- `ImageClsAgentConfig::Validate`（`src/algo/imagecls/src/image_cls_agent.hpp:107`〜117 行）が検証するのは、mixup の 4 つと `learn_log_interval` だけである。`grad_clip_max_norm`・`label_smoothing`・`weight_decay`・`learning_rate` は読む（62〜66 行）が検証しない。`learning_rate` の `ProfiledValueConfig<double>` は下限（`min_value`）を持たない（`learning_rate.value = 1e-3` だけを置く。61 行）。DQN の `learning_rate` は `.min_value = 0.0f` を持つ（`src/algo/dqn/src/dqn_config.hpp:274`）。
- 勾配の clip: `ImageClsLearner::UpdateFromBatch` は毎回 `torch::nn::utils::clip_grad_norm_(network_->parameters(), config_.grad_clip_max_norm)` を呼ぶ（`src/algo/imagecls/src/image_cls_agent.cpp:408`）。libtorch のこの関数は勾配に `max_norm / (total_norm + 1e-6)` を 1 で頭打ちにした値を掛けるので、0 なら勾配は 0、負なら向きが逆になる。
- label_smoothing: 損失は `CrossEntropyFuncOptions().label_smoothing(config_.label_smoothing)` で作る（395 行）。libtorch の cross_entropy は 0〜1 の外の値を、最初の学習の step で例外にする。例外の文に設定キーは入らない。
- learning_rate: 学習の step ごとに `learning_rate_->Update(step.exp_step)` の値を optimizer の全 group に入れる（412〜414 行。`SetAdamWLearningRate` は 314 行）。optimizer の構築時の値は torch の AdamW が負を拒むが、途中の値は確かめない。phased の予定の終わりを負に書くと、その区間は負の学習率で更新する。
- `weight_decay` の負の値は、optimizer の構築時に torch の AdamW が拒む（Fused も `torch::optim::AdamW` を継承する。`src/core/base/include/anet/nn_util.hpp:151`）。例外の文に設定キーは入らない。
- 出荷設定は `ImageClsAgent.label_smoothing = 0.1`・`grad_clip_max_norm = 1.0`（`apps/runner/config/ImageCls.txt:123`・124）で、学習率は warmup と cosine の phased（108〜117 行）である。範囲外の値を書くテストは、mixup と `learn_log_interval` のもの（`image_cls_agent_test.cpp` の 693 行のテスト）だけである。

## 影響

- `grad_clip_max_norm = 0`（0 で clip を切れると思った指定や、打ち間違い）では、Network が一度も変わらないまま Run が最後まで回り、負の値では勾配の上りで学習する。エラーも WARN も出ず、違う条件の Run の結果が残る。
- 範囲外の `label_smoothing` は、Run の構築を終えて最初の学習の step で止まり、どの設定キーが原因かがエラー文から分からない。
- 学習率の予定の書き間違いで、Run の途中から負の学習率になっても気づけない。

## 対応方針

- `ImageClsAgentConfig::Validate` に、`grad_clip_max_norm`（有限で 0 より大きい）、`label_smoothing`（0〜1）、`weight_decay`（0 以上）の値域の検証を足す。エラー文は完全キーで書く。
- `learning_rate` は、DQN と同じく `ProfiledValueConfig` の下限 0 を置き、予定の全区間を構築時に検証させる。
- 正しい値の構成では挙動を変えない。ImageCls のテストが期待値を変えずに通ることを確かめ、範囲外の値ごとに構築で止まるテストを足す。
