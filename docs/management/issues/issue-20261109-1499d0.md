## 背景

[issue-20261103-e29c92](issue-20261103-e29c92.md)（4 つの Repository の重複と、重複登録の扱いの食い違い）を、2026-11-09 の課題のメンテで分けた子である。分けることは、AI が挙げた統合・分割の候補から開発者が選んだ。重複登録の扱いをそろえる部分は小さな直しで済み、Repository をテンプレートにまとめる整理（[issue-20261109-adc5c4](issue-20261109-adc5c4.md)）とは別々に直せるため、分けた。

## 事象

同じ名前（class_id・type 名）の登録が 2 回あったとき、Env の Repository だけがエラーで止め、ほかの 3 つは後から登録したほうで黙って上書きする。2026-11-09 にコードで確かめた。

- core/anet-core/src/env.cpp:1135 `EnvRepository::Regist` は、登録済みの class_id なら `ANET_SYSTEM_ERROR` で止める（1145 の BatchEnv 版も同じ）
- core/anet-core/src/agent.cpp:49 `AgentRepository::Register` は `factories_[class_id] = factory` で上書きする
- core/anet-core/src/gui.cpp:416 `ViewRepository::Register` も `creators_[class_id] = creator` で上書きする
- core/anet-core/src/nn_impl.cpp:2607 `NetworkModuleRepository::Register` も `registry_[type_name] = std::move(factory)` で上書きする

## 影響

同じ class_id の AgentFactory（または View・NN モジュールの factory）を 2 つの .cpp が登録すると、静的初期化の順で後になったほうが黙って使われる。ビルドの構成やリンクの順が変わるだけで、別の Agent・別の NN モジュールで Run が走りうるが、エラーもログも出ない。AGENTS.md の Fail-Fast の方針と、Env の扱いとも食い違う。

## 対応方針

Agent・View・NN モジュールの `Register` でも、登録済みの名前なら `ANET_SYSTEM_ERROR` で止め、Env とそろえる。それぞれに重複登録のテストを足す。Repository をテンプレートにまとめる整理は [issue-20261109-adc5c4](issue-20261109-adc5c4.md) で行う。
