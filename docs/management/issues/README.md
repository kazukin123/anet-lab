# 課題記録

開発対象システムの課題を **1 課題 1 ファイル**で記録する。工程をまたぐ課題、および「今は解決できない」と判断した事項をここへ積む。

**AI は課題を勝手に書かない。** 工程末と、工程を途中で止めるときに起票の候補を挙げ、開発者が選んだものだけを `anet-create-issue` SKILL が書く（`docs/process/protocol.10-finish.md` 10.1 節）。開発者が直接ファイルを置いてもよい。

**1 枚の表へ追記しないのは、ブランチを分けて作業したときにコンフリクトするため。** ファイルを分ければ、別々のブランチで起票しても衝突しない。

## 書き方

**ID の形は `docs/process/numbering.md`、ファイル名の規則・frontmatter の項目・本文の構成・状態の定義は `anet-create-issue` SKILL が正本である。本書では書き写さない。**

開発者が直接ファイルを置く場合も、同じ形に揃える。既存のファイルを 1 つ開けば形は分かる。

## 一覧を見る

`anet-list-issues` SKILL を使う。状態や工程で絞り込める。

```
/anet-list-issues            全件
/anet-list-issues 本版       次版と解決を除く
/anet-list-issues 要件定義   その工程だけ
/anet-list-issues 棚卸し     監理の項目の値と、統合・分割の候補を提案する
/anet-list-issues <課題 ID>  その課題を親に持つ課題（子）だけ
```

依存（`depends`）と WSJF（`wsjf`。効果・時間・リスクを手間で割った値）を目安に並ぶ。前提の課題を待っているもの、外部要因待ち、決着済みは下に並ぶ。WSJF も優先度も並びも目安であり、どれから手を付けるかは開発者がそのときの事情で決める。

## 監理の項目を変える

`anet-update-issue` SKILL を使う。優先度・WSJF の元になる値（効果・時間・リスク・手間）・依存・親・種別を変えるときと、棚卸しの提案を採るときである。値の目安は `anet-create-issue` SKILL の「監理の項目」にある。
