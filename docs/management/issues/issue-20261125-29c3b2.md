## 背景

2026-11-25 の監査（観点 drift、範囲 `docs/design/140_observability.jp.md`）で見つけた。分類は未文書で、どちらを直すかは対応のときに決める。開発者には質問していない。

140 §6（293 行）は「不明なevent、step軸、target、属性は構築時の`ANET_SYSTEM_ERROR`で停止」と書き、309 行は「scalar・trace・graphは`metrics.<channel>.[tag] = 宣言`の1値を読むカタログ」と書く。graph の宣言の文法（キー、target、`interval`・`step_interval`・`episode_interval`）は、140 のどこにも無い。AGENTS.md の「設定値の扱い」は、動作不能な設定を暗黙に既定値へ置き換えないとしている。

ホットスポット補正: 直す場所の `observers.cpp` は 90 日の変更回数が配置の移動の前後で 15 回＋2 回（`reports/stats/stats.json` の `flow.churn90`）で、コードのファイルの上位 5% に入る。urgency を 2 から 3 へ 1 段上げた。

## 事象

- graph の節（`src/core/base/src/observers.cpp:1635-1697`）は、語を空白で分け、`$action`・`$action_info`、`key:`・`target:`・`interval:`・`step_interval:`・`episode_interval:`・`eps_interval:` を読む。それ以外の語のうち `@` か `$` で始まるものは、何も知らせずに捨てる（1674〜1678 行）。未知の属性名（`:` を含む語）と target の値は `ANET_SYSTEM_ERROR` で止まる。
- そのため、`metrics.graph.[x] = $agent @learn mcts_tree interval:100` のように、使えない event と target を書いても構築は通る。target が `$action_info`（`$action`）でなければ `GraphVizObserver::FindProvider`（1170〜1183 行）が nullptr を返し、`OnTrain` は何も知らせずに戻る（1223・1224 行）ので、Run の最後まで図が 1 枚も出ない。`@learn` を書いても `@train` と同じに扱う。知らないキーも `CreateGraph` の結果が空のときに黙って戻る（1225・1226 行）。出荷設定のコメントの例（`GridMaze_muzero.txt:144` の `@train`）は、捨てられる語を書いている。
- `interval`（`step_interval`）と `episode_interval` の既定はどちらも -1 で、両方が 0 以下なら `step_interval = 1000` にする（1686〜1689 行）。コメントは「万が一どちらも指定されていなければ、安全のためstep_interval=1000にしておくなど適宜調整」と書く。`interval:0` や `interval:-1` を明示しても、黙って 1000 step ごとになる。scalar の `interval` は 1 以上を検証して止まる（801 行）。
- 数値は `std::stoi` で読む（1666・1668 行）。読み残しを捨てる点は [issue-20261123-446e6f](issue-20261123-446e6f.md) が扱う。
- 出荷設定で使うのは `GridMaze_muzero.txt:145`（`$action mcts_tree episode_interval:50`）の 1 件だけである。graph の宣言の誤りを試すテストは無い。

## 影響

- graph の宣言の書き間違い（使えない event・target・scope、キーの綴り、0 の間隔）が、エラーにも WARN にもならず、図が出ないか、書いたものと違う条件で出る。
- 文法がどこにも書かれていないので、宣言を書く人はコードを読むしかない。

## 対応方針

- graph の宣言も、未知の `@`・`$` の語と scope を `ANET_SYSTEM_ERROR` で止め、`interval`・`episode_interval` は書いたときに 1 以上を検証する。どちらも書かないときの扱い（止めるか、既定の間隔を文書に書くか）を決める。字句の解析を scalar・trace と同じ `ParseMetricTokens` に寄せるかは、[issue-20261111-645ecc](issue-20261111-645ecc.md) と合わせて決める。
- 140 §6 に graph の宣言の文法を書く。`GridMaze_muzero.txt` のコメントの例も合わせる。
- 出荷設定の 1 件の動きは変わらない。MuZero の試作だけが使うので、起こすときの優先度は低い。
