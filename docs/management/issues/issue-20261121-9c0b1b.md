## 背景

[PRD194](../../memo/194_config_key_full_names_in_messages_10prd.md) のグリル（2026-11-21）で、題材の課題 6 件のうち 2 件（eeb2c3・4124b6）が、「共通の部品が、持ち主が別にいる設定キーを文面でどう名指すか」という同じ問いに帰着した。開発者は、その答えを題材の 6 か所に限らず、基盤全体のエラー・WARN・INFO へ広げることを選んだ（同書 D2・D3）。この課題は、題材の 6 件で覆えない仕事（完全キーを運ぶ仕組みの残り、上書きの接頭辞が空の読み口の直し、一覧の移行）を表す、PRD194 の課題である。開発者への質問は、PRD194 のグリルの中で行った。

## 事象

2026-11-21 に、`src` のテスト以外のエラー・WARN・INFO の文を集計して 1 文ずつ読んだ（PRD194 の §1.3・§8）。

- 相対キー（`learner.per_eps`、`cn.channels` など）や、1 語だけの名前（`quantile_mode=`）で設定を名指す文が 178 文、相対キーを文字の引数で渡して文面に出す呼び出しが 16 行、集計に現れないが同じ形の文が 8 つある。
- 設定の値は、読み口（`anet::Config` の派生）が完全キーを組んで読み、型の欄に詰めて部品へ渡す。渡ったあとの欄は名前を持たない。NN の block の設定は、共有の置き場と Agent の下の置き場を合成し、相対キーだけで block に渡る。
- 上書きの接頭辞が空の読み口は、root 直下の相対キーを読む。root 直下に `learner.per_eps` と書くと、DefaultDQNAgent と RainbowAgent の両方に効き、読まれない設定キーの一覧にも出ない。出荷設定は、root 直下の相対キーを使っていない。
- 具象の Env と NN には、上書きの置き場や Agent の下に書いた値でも、既定の置き場や共有の置き場の名前を固定で書く文がある（具象の Env の `.cpp` に少なくとも 27 行、NN に 5 行）。

## 影響

誤った設定で止まったとき、文面のキーを設定に貼っても効かないことがある（block の設定）。読み口の設定では、root 直下に貼ると効いてしまい、2 つの Agent に同時に効く。共通の部品は、利用側が読んでいない設定や、別の利用側の root を持つキーを指すことがある。

## 対応方針

PRD194 による。`ConfigData` が項目ごとの完全キーと置き場を覚え、読み口が読んだ欄ごとに完全キーを記録して、設定の型と一緒に部品へ運ぶ（同書 D4・§6.2）。上書きの接頭辞が空の読み口は、上書きの読み取りをしない（D18）。一覧（§8）の文を、完全キーで書く形へ直す。実装は同書 §6.1 のステージ 2 の一部とステージ 3 である。
