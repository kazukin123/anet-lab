## 背景

[RFD0200](../../memo/0200_forwarder_public_interface_rework_10rfd.md)（forwarder.hpp の公開の口の作り直し）のグリル（2026-11-23〜24）で、開発者が、RL に依らない層の公開ヘッダに `episode_start` という RL の概念が入っていることを挙げた。RFD0200 は、forwarder.hpp の口からこれを外し、行の開始の印を入力の `TensorDict` の鍵で渡す形にするが、nn.hpp は範囲に入れなかった（同 §8、前提 P28、D1 の理由）。RFD0200 の起草のあとの別モデルの検討が、Forwarder の口と Network の口で、行の開始の渡し方がそろわなくなることを挙げた。グリルの中では開発者に質問していない。工程の終わりに起票の候補として示し（AI の推奨は見送り）、開発者が記録を選んだ。

## 事象

- `src/core/base/include/anet/nn.hpp` の `NetworkForwardCallInfo`（148〜164 行）は、呼び出しごとの情報として `episode_start`（行ごとの開始のマスク）を持ち、`GetEpisodeStart()` で答える。nn.hpp は `anet::nn` 名前空間で、RL の層（`anet::rl`）ではない。
- 用語集（`CONTEXT.md`）の「NN 呼び出し情報」は、この値を episode_start と呼ぶ。NN 実行設定の「保持方式」は、ノイズを引き直す時機の区分に `episode`（lane の episode 開始ごと）を持つ。
- RFD0200 の実装のあとは、Forwarder の側は行の開始の印を入力の鍵で受け、Network の側は呼び出しごとの型つきの値で受ける。

## 影響

- RL に依らない層の NN の口に、RL の語が残る。
- 行の開始を渡す形が、Forwarder と Network で 2 通りになる。使う側（Actor）は、同じ印を 2 つの形で渡す。

## 対応方針

未定。

- 2026-11-24 RFD0200: 案の材料。名前だけを RL に依らない語（行の開始、列の開始など）にする案と、渡し方を Forwarder の側とそろえる案がある。どちらも、ノイズの保持方式の `episode` という設定の値と、用語集の「NN 呼び出し情報」「保持方式」の書き方に及ぶ。[RFD0200](../../memo/0200_forwarder_public_interface_rework_10rfd.md) §8
