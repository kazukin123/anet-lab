## 背景

PRD117（WARN の意味の線引きと読まれない設定の検出）は、WARN を「利用者が確かめて直すべき状態」に限り、読まれない設定キーを Run の構築の終わりに WARN で一覧する（止めない）と決めた（[PRD117](../../memo/117_warn_policy_and_unread_config_10prd.md) の D1・D3）。WARN が出たことは、Logs pane の未確認の警告の印で知らせる。

再グリルで、無人で走る Run では印を見る人がいないという弱点が挙がった。Run を閉じるときにも一覧を出す形は「対象ごとに 1 回」の例外になるので採らず、運用の側の手当てとして範囲外にした（PRD117 の §8、§9 の 21）。

開発者に質問したか: 質問した。手当てを足すかを聞き、開発者が「課題の候補にする」を選んだ（2026-11-10）。工程末に候補として示し、開発者が起票を選んだ（2026-11-11）。

## 事象

番号付きの bat で流す Run は無人で走る。WARN が出ても、次のとおり気づく手段が弱い。

- 印が出るのは Logs pane だけで、無人の Run では見る人がいない。
- 構築の直後に出た WARN（読まれない設定キーの一覧など）は、ログの先頭近くに埋もれる。
- bat は、各 Run が WARN を出したかどうかを、終わりにまとめて示さない。

## 影響

bat の引数の綴りを誤ったまま夜間に流すと、誤った設定の Run が走りきり、ログを探さないと気づけない。PRD117 を実装したあとは、普通の Run の WARN が 0 件になるので、WARN が 1 件でもあれば確かめる値打ちがある。それを見落とす経路が残る。読まれない設定キーに限らず、どの WARN にも当たる。

## 対応方針

未定。候補は、bat の終わりに各 Run の WARN の件数をまとめて出す、Run の要約を出す道具に WARN の件数を載せる、など。PRD117 の実装（普通の Run で WARN 0 件）のあとに入れると、件数がそのまま確かめる合図になる。
