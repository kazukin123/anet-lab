## 背景

開発者が MetricsViewer を使っていて、サンプルが 1 件しかないときにグラフが描かれないことに気づき、起票とその場での修正を指示した。

点が 1 つになる場面は、記録が 1 回だけの tag に限らない。走り始めの Run、複数 Run の比較で片方だけ 1 点の tag、点がまばらな tag を拡大して表示区間に 1 点だけが入ったときも当たる。

## 事象

サンプルが 1 件の tag を選ぶと、グラフに何も描かれない（開発者の報告）。

コードから読めたことは次のとおり。

- `PlotlyController._makeLineTrace` は、すべての trace を `mode: "lines"` で作る。線は 2 点ないと引けないので、1 点の trace には何も描かれない。Raw・MinMax・Mean・Band のどの表示も、この関数を通る。
- `HoverOverlay.coversX` は、カーソルの step が系列の先頭と末尾の間にある点だけを残す。1 点の系列では先頭と末尾が同じ step なので、カーソルがその step に正確に重ならない限り点が落ちる。点を描くだけでは Hover が出ない。
- API は 1 点でも `availability=ok` の raw 射影を返す（`MetricsApiIntegrationTest` の `run-error`/`loss`）。取り込みは非有限値を弾くので、NaN に挟まれて孤立する点は無い。

## 影響

記録があるのに、軸だけのグラフになる。データが無いのか描けていないのかを画面から区別できず、記録が欠けていると誤解する。

## 対応方針

点が 1 つの trace は線の代わりにマーカーで描く。判定は trace ごとに行い、複数 Run のグラフでも他の Run の線は変えない。1 点の系列は `coversX` の判定を通し、Plotly が近いと判断して返した点をそのまま Hover に使う。

表示区間に点が 1 つも無い tag は別の問題であり、[issue-20261103-73a449](issue-20261103-73a449.md) で扱う。

## 対応内容

- 2026-11-07 この場で直す: `_makeLineTrace` が頂点 1 つの trace をマーカーで描くようにし、`HoverOverlay.coversX` が 1 点の系列を通すようにした。設計文書 210 §9 に 1 文追記し、Playwright テストを 4 件足した。確かめ: 新しい 4 件は修正前にすべて失敗し、描画だけ直した段階では Hover の 1 件が失敗した。修正後は `mvn -B test -Dtest=*PlaywrightTest` の 116 件がすべて成功した。実サーバーで 1 点の Run と 200 点の Run を取り込み、1 点だけの表示、比較（1 点側は LOD で 1 頂点）、Band、Hover を確認した。残る振る舞い: 複数 Run のグラフでは、カーソルが 1 点の近く（Plotly の既定で約 20px 以内）にあると、Hover の見出しは他の Run の step のまま、1 点の Run の値が並ぶ（例: 見出しが step 14,000 で、run_one は step 12,345 の値）。
