## 背景

2026-11-25 の監査（観点 refactor、範囲 321_agent_core）で見つけた。観点の分類は「特例で支える汎用機構」で、「既存の重複」「暗黙の前提」が付随する。開発者には質問していない。

RFD0130 の受入 14 は「`RndNoveltyEstimator` の中で、統計方式によって分かれる箇所が、構築時に型を選ぶ 1 か所だけである」とし、構築の行にも「実行時の方式分岐は置かず、状態を所有する型をここで一度だけ選ぶ」と書く（`intrinsic_rnd.cpp:688`）。RFD0191（2573b18e、2026-11-22）のあと、外側の分岐が戻っている。

ホットスポット補正: `intrinsic_rnd.cpp` は 90 日の変更回数が配置の移動の前後で 10 回＋3 回（`reports/stats/stats.json` の `flow.churn90`）で、コードのファイルの上位 5%（7 回以上）に入る。urgency を 2 から 3 へ 1 段上げた。

## 事象

- `RndNoveltyEstimator` の中で方式を見る箇所が、構築のほかに 4 つある。`Estimate` の待ちの通知（790〜793 行）、`EstimateWithoutUpdate` の倍率の条件（825・826 行の `UsesRawError()`）、`GetMultiplierClipping`（841〜853 行、3 分岐）、`SuppressesBonus`（857 行）。checkpoint の書式の照合は数えていない。
- 倍率を 1 にする条件が 2 つの側に別々に書かれている。更新する側は `WhitenStatistics::UpdateStatistics`（302〜311 行）と `VarianceFeedbackStatistics::Estimate`（347〜350 行の mask）。読むだけの側は、外側の 825〜827 行と、`StandardizeWithoutUpdate`（235〜242 行、489〜502 行）に分かれる。
- predictor の待ちの件数を、`WhitenStatistics::predictor_warmup_steps_`（216 行）、`VarianceFeedbackStatistics` の基底の `warmup_steps_`（401 行）、外側の `config_.predictor.warmup_steps`（825・878 行）の 3 か所が持つ。
- 基底 `RndStatistics` の `warmup_steps_` と `IsWarmingUp` は、whiten では誤差の段階の待ち（213・214 行）を、variance_feedback では predictor の待ち（401 行）を指す。同じ名前が別の待ちを表す。

## 影響

- 誤差の式か統計の方式を 1 つ足すとき（RFD0173 の NGU、[issue-20261108-227b05](issue-20261108-227b05.md)、[issue-20261115-d3e094](issue-20261115-d3e094.md) の SND の試し）、型を足すほかに外側の 4 か所と、読むだけの側の条件を直す。
- 読むだけの側を直し漏らすと、Evaluation Trace の `rnd_bonus`・`rnd_norm` の列だけが学習の倍率と食い違い、ERROR は出ない。

## 対応方針

- `RndStatistics` に、今の件数で倍率が有効か、誤差から倍率を作る（更新しない。件数を引数に取る）、clip の設定、ボーナスを 0 にするか、通知する待ちの並び（キーと件数）を答える関数を置き、外側は方式を見ずに呼ぶ。`UpdateStatistics` も倍率の関数を使い、条件を 1 か所にする。`warmup_steps_` は誤差の待ちと predictor の待ちを別の名前で持つ。INFO の文言と出る順は変えない。
- 性能の区分は「中立」（採点は intake ごと。倍率の計算は今のまま CPU の float で、仮想呼び出しが数回増えるだけ）。
- トピック別まとめの「変えるときの条件」では、RFD0127（読むだけの採点を挟んでも `Estimate`・`Learn`・`Diagnostics` が変わらず、3 構成で倍率が一致する）、RFD0123 §4 D8・D11（variance_feedback の中身と checkpoint の書式を変えない）、RFD0130 と RFD0191（5 構成の全 scalar の点の一致）が当たる。
- テスト: `src/core/base/src/intrinsic_test.cpp` の 240・471・529・948・1325・1353・1404・1465・1509 行が通す。`RndStatistics` の派生は private の入れ子の型で、名指しで構築するテストは無い。
- 不採用の形との突き合わせ: ADR 0088（設定キーの置き場）と、RFD0191 §8.4 が決めた公開の口（`SuppressesBonus` は 0 にするかを返す）は変えない。RFD0130 の前の分岐を扱った課題 0ddffa は解決済みで、この候補は RFD0191 のあとの戻りである。
