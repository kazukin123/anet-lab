## 背景

2026-11-25 の監査（観点 refactor、範囲 321_agent_core）で見つけた。観点の分類は「暗黙の前提（順序）」で、「既存の重複」が付随する。開発者には質問していない。

RFD0128（2026-11-14）の D12・D19 は、診断の指標を作る側も読む側も名前で指し、並びの食い違いをビルドで止める形にした。道具は `MakeDiagnosticMetricKeys`・`MakeDiagnosticValues`・`StackDiagnosticValues`・`ReadDiagnosticScalar`（`src/algo/dqn/src/dqn_math.hpp:34-111`）である。同 RFD の §6.7 は、RFD0121 の学習のメトリクスを「共通の読み出しへ、群の指標の並びと値を 1 組足す（D12）」としていた。

ホットスポット補正: `dqn_learner.cpp`（RFD0182 の改名の前の `dqn_based_agent.cpp` は churn90 が 41）は、コードのファイルの上位 1% に入る（`reports/stats/stats.json` の `flow.churn90`）。urgency を 3 から 5 へ 1 段上げた。

## 事象

- 学習の群: キーは手書きの `std::array<const char*, 9> kValueDecompositionMetricKeys`（`dqn_math.hpp:273-275`）。値は `torch::stack({extrinsic_loss, intrinsic_loss, head_values[0], head_values[1], …, head_values[2]})`（`dqn_learner.cpp:2860-2863`）で、9 個の並びと `head_values` の添字 0〜2 を手で合わせている。読み出しは `Learner::GetScalar` の専用のループ（278〜283 行）である。
- 行動選択の群: キーの配列が 3 本（`dqn_actor.cpp:37-44`。lane・平均・session）、値は `torch::stack({disagreement, regret, external_gap, internal_gap}, 1)`（355 行）、読み出しは 2 か所の専用のループ（360〜376 行と 1729〜1734 行）である。
- step 診断は、schedule の指標を数で指す。`scalar(3)`（`dqn_assembler.cpp:117`）・`scalar(4)`・`scalar(5)`（134 行）が `kLearnerScheduleMetricKeys[index]` を引く。名前付きの添字 `LearnerScheduleMetric::Gamma` ほかは `dqn_math.hpp:113-115` にある。RFD0128 §7 の検索語（`kLearnerScheduleMetricKeys\[[0-9]+\]` など）は、ラムダの引数で渡すこの形に当たらない。
- 検索語と件数: `kValueDecompositionMetricKeys` は定義 1・利用 3、`kValueSelection` の配列は定義 3・利用 5、`scalar\([0-9]\)` は `dqn_assembler.cpp` に 3。

## 影響

- 学習の指標を 1 つ足すとき（暫定 RFD0201 は外的の Head の下限の損失のメトリクスを足すと書く）、`kValueDecompositionMetricKeys` と 2860 行の stack の並びを手で合わせる。
- `LearnerScheduleMetric` の先頭か途中に指標を足すと（RFD0148 は target の更新の時間軸を扱う）、`scalar(3)` が別の値を γ として読む。
- どちらもビルドは通り、別の値が別の名前で出る。

## 対応方針

- 2 群に名前付きの enum を置き、`MakeDiagnosticMetricKeys` と `StackDiagnosticValues`（行動選択の群は lane × 指標なので、列ごとの版を 1 つ足すか `MakeDiagnosticValues` で列を並べる）で作り、読み出しを `ReadDiagnosticScalar` に寄せる。`scalar` の引数を `LearnerScheduleMetric` の名前にする。キーの名前、NaN になる条件、`$agent`・`$action_info`・`$actor` のどこから読めるかは変えない。
- 性能の区分は「中立」（学習は更新ごと、行動は step ごとに、今と同じ stack を 1 回作る）。perf-neutral の確かめと、同 seed・決定的モードの短い Run で全 scalar の点の一致を確かめる。
- トピック別まとめの「変えるときの条件」では、RFD0128 §6.4（メトリクスの名前と WARN の文言・回数を変えず、全 scalar の点を一致させる）と RFD0128 §5 D12・D16・D18 が当たる。
- テスト: 値は `dqn_learner_test.cpp:1516`、`dqn_intrinsic_test.cpp:74`、`dqn_actor_test.cpp:2702`、step 診断は `dqn_assembler_test.cpp` が通す。並びの入れ替えでビルドが止まることを確かめるテストは無い。
- 不採用の形との突き合わせ: RFD0128 §5.1 の「指標に名前を付けるだけで、並びとの食い違いをビルドで止めない形 — 不採用」に今の 2 群が当たっている、という候補である。
- [issue-20261111-e80c7b](issue-20261111-e80c7b.md)（`DQNActionInfo::GetScalar` の分割）とは、行動選択の群の読み出しが重なるので、同時に直せる。
