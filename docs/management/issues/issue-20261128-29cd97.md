## 背景

[RFD0200](../../memo/0200_forwarder_public_interface_rework_10rfd.md) の起票とレビューのあと（2026-11-24）の会話で、開発者が次の案を述べた。「Stackingもprev_actionも、共通して、直近の系列情報(状態・行動・報酬・終端情報）を貯めて置く必要があると思うけど、入力じゃなくてそのバッファを横からいつでも部品が見れるようにしたらいいんじゃないかなあ」。

開発者は、RFD0200 を今の形のまま先に実装すると述べ、案は決定にしなかった。案は、RFD0200 §10.4 の「AI の整理 2」と、[RFD0142](../../memo/0142_agent_prev_action_obs_10rfd.md) の末尾の「再グリルの材料（2026-11-24）」に、次のグリルの材料として残った。課題の側では、[issue-20261103-9bd71e](issue-20261103-9bd71e.md)（RFD0142）と [issue-20261124-6b50cb](issue-20261124-6b50cb.md)（RFD0200）の対応方針に 1 行ずつあるだけで、6b50cb は解決した。

2026-11-24 の会話では、部品がバッファを読む道として 2 つを挙げ、AI は一方を推したが、開発者の答えは得ていない（対応方針の材料）。2026-11-28、開発者は、この案だけを扱う課題として起票することを選んだ。

関係する課題: [issue-20261103-9bd71e](issue-20261103-9bd71e.md)（直前の行動の観測。この課題の結論で、`prev_action` を Frame のキーに足すかが変わる）、[issue-20261122-4c0af5](issue-20261122-4c0af5.md)（観測をためる置き場の共通化。置き場の実装をまとめる課題で、部品が系列を見る口は扱わない）。

## 事象

- フレーム積層の履歴（`DictFrameStacker`）は、並びの `FrameStack` の部品が作る `SequenceStackForwarder`（[forwarder.cpp](../../../src/core/base/src/forwarder.cpp) 572 行）が持ち（620 行）、重ねるキーの観測だけを貯める。Sample の側は、ReplayBuffer が保存した slot から重ね直す。
- ReplayBuffer の保存（`ReplayExperienceStorage`）は、lane × 時間の行動の列（[replay_buffer_impl.cpp](../../../src/core/base/src/replay_buffer_impl.cpp) 511 行の `actions_`）と報酬（501 行の `step_rewards_`）を既に持つ。
- 直前の行動を観測に足す部品は無い（9bd71e の 2026-11-25 監査）。RFD0142 の再グリルの材料は、この案を採ると `prev_action` を Frame のキーとして保存しない形になりうると書く。
- RFD0200 の実装（3545c16a・b3e29497）は、開始の印を入力のキーにし、`FrameStack` を並びの部品のままにし、Forward の種類に `PerceptionFromSequence` を持つ（[forwarder.hpp](../../../src/core/base/include/anet/forwarder.hpp) 120・125 行）。
- [RFD0173](../../memo/0173_intrinsic_reward_novelty_10rfd.md) は、NN の入力に直前の行動・外的報酬・内的報酬を使う案を持ち、§8 の 12「履歴の所有と終了処理」は未決である。学習用と短期記録用の Replay の統合は、同 RFD の範囲に入れていない。

## 影響

- フレーム積層と直前の行動（と RFD0173 の入力）が、同じ直近の系列を、別の場所・別の形で持つことになる。行動選択と Sample で同じ値になることを、使い手ごとに作って確かめることになる。
- 案が材料のまま RFD の中にだけあると、RFD0142 の再グリルのほかの経路（RFD0173 の履歴の持ち主、4c0af5 の置き場の整理）から見つからない。RFD0142 を今の前提（`prev_action` を Frame のキーに足す）で決めたあとに採ると、作り直しになる。

## 対応方針

未定。材料は RFD0200 §10.4 の「AI の整理 2」にある（机上の整理で、試作はしていない）。

- 形の案: 行動選択では、Actor が lane ごとの直近の系列（観測・行動・報酬・開始の印）を持つ。Sample では、ReplayBuffer が標本ごとに同じ形の束を返す。部品は、どちらでも同じ束を受ける、状態を持たない変換になる。
- 部品がバッファを読む道: 部品がバッファを横から読む形と、バッファの持ち主が束を切り出して入力の Dict として渡す形がある。AI は後者を推した（Sample の側は標本ごとに見る場所が違い、部品が読むものは依頼に渡す spec に現れている必要があるため）。開発者の答えは得ていない。
- 得るもの: 直前の行動や報酬を Frame に保存しなくて済む。行動選択と Sample が同じ依頼になり、両者の一致が作りで決まる。RFD0173 の入力と、同 RFD の未決の「履歴の持ち主」に合う。
- 払うもの: ReplayBuffer の Sample の契約が変わる（行動と報酬の列を、obs・n-step 先の next_obs・skip の学習の窓の終点に返す。RFD0200 の NG4 の線を越える）。エピソードの先頭の埋め方を、Actor の側と ReplayBuffer の側でそろえる。性能（Sample で足す列の取り出し）と、ReplayBuffer の変更の大きさは確かめていない。
- 変わる見込みの RFD0200 の決定: D1 のうち開始の印を入力の鍵にすること、D11・D12、D13（§5.6 で退けた「重ねるのを、並びの外へ出す」を、行動と報酬まで広げた形に当たる）、D21 の比較、§6.4 の Forward の種類（`PerceptionFromSequence` が要らなくなる見込み）。
- 決めること: 案を採るか。採るなら、RFD0142 と RFD0200 のどちらを先に再グリルするか（RFD0142 の再グリルの材料）。4c0af5 の置き場の整理と、RFD0173 §8 の 12 と、合わせて決めるか。
