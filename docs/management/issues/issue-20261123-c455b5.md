## 背景

[RFD0195](../../memo/0195_document_term_rfd_and_4digit_numbers_10rfd.md)（文書の呼び名を RFD に改め、番号を 4 桁にする）の実装の検証で、AGENTS.md の検証の既定のスイートを回したときに見つかった。作業ツリーの 11 番の bat には、開発者の作業中の変更（既定のキューを `mz_lrpl` にした）があった。工程末に起票の候補として示し、開発者が起票を選んだ。

## 事象

- 2026-11-23 に作業ツリーで [batchrun_fatal_error_handling_test.ps1](../../../apps/tools/batchrun_fatal_error_handling_test.ps1) を回すと、終了コード 1 で「11_batch_run.bat did not print the aggregate failure count」と止まった。11 番の bat の出力の末尾は `=== ALL DONE: 1 SUCCEEDED, 5 FAILED ===` で、テストが待つのは失敗 1 件（2 件目の Run だけを失敗させる仮の Runner の分）である。
- ほかの 4 件は、前の Run の重みを読んで評価だけをする段（ev only）で、`[ERROR] agent_close.anet not found: ...\runs\run_*_mz_tg_g99ne_rr4_s2 newest=` などを出した。テストの仮の環境には前の Run のフォルダが無い。
- テストは、apps の 11・12 番の bat を写し、Runner を仮のものに替えて、bat の既定のキューを回す。11 番の bat の `:find_ckpt_missing` は、重みが見つからない段で `FAILED_RUNS` を 1 増やす（HEAD にもある）。
- HEAD の 11 番の bat（既定のキュー `mz_b512`）に RFD0195 のコメントの置き換えだけを当てた形と、今の 12 番の bat では、このテストは通った。

## 影響

- 11 番の bat の今の変更をコミットすると、既定のスイートのこのテストが落ち続け、ほかの退行を見分けにくくなる。
- 前の Run の重みを読む段を既定のキューに置くたびに、同じことが起きる。

## 対応方針

未定。

- 2026-11-23 RFD0195: 案として、(1) テストの仮の環境で、重みを探す段を仮の重みで通すか、見つからない段を数えから外すようにテストを直す。(2) bat の側で、重みが無くて飛ばした段を失敗と別に数える。(3) テストが回すキューを、bat の既定のキューではなく、テスト用の固定のキューにする。どれにするかは、実際の Run で重みが無いときに失敗として数えたいかで決める。[実装記録](../../memo/0195_document_term_rfd_and_4digit_numbers_20impl.md)
