## 背景

2026-11-15 に、PRD130（RND の採点の統計の区間を軽くする暫定 PRD）のステージ 0 の測定で、Montezuma の Run の実時間を測った。1 intake ごとの時計の記録に、どの Run にも同じ位置で、約 2 秒の停止が 1 回入っていた。RND の有無に依らない。PRD130 の題材（RND の採点の統計）の外なので、起票の候補として示し、開発者が起票を選んだ。測定の構成と結果は [PRD130](../../memo/0130_rnd_estimate_statistics_perf_10rfd.md) の §2.8 にある。

## 事象

- 測った構成は、11 bat の 27 番と同じチェーン（128 lane、replay ratio 8、batch 256）で、可塑性メトリクスの設定は `DefaultDQNAgent.learner.plasticity.probe.batch_size = 4096`、`34_agent_plasticity` の群の tag が `interval:500`（learn step）である。実運用の Run `run_20261115-055326_mz_tg_r121_vd_s1` の設定も同じ値である。
- RND なし 6 本と RND あり 6 本の全部で、36,224 経験の位置（learn step 500 の直後）の 1 intake が 2.23〜2.56 秒かかった。ほかの 1 intake の中央値は、RND なしが 92〜96 ms、RND ありが 117〜122 ms である。
- Tracy をつないだ Run では、その 1 intake（`PipelineTrainRunner::DoStep`）が 2,252.5 ms だった。その中で、`nn::ComputePlasticityMetrics` がメインスレッドの通知（`Notifier::Notify`）の中で 2 回走り、特異値の計算（`svd` の区間）が 34.6 ms と 1,693.0 ms だった。学習用のスレッドでは、probe の取得（`Learner::CapturePlasticityProbe.plasticity_probe`）が 130.3 ms、重みノルム（`plasticity_weight_norm`）が 26.0 ms だった。
- `ComputePlasticityMetrics` は、特徴を CPU へ移し（[nn_impl.cpp:451](../../../src/core/base/src/nn_impl.cpp)）、CPU で `torch::linalg_svdvals` を呼ぶ（同 474〜475 行）。呼び出しは [dqn_based_agent.cpp:3063](../../../src/core/base/src/dqn_based_agent.cpp) と同 6118 行にある。
- 通知は、メインスレッドが前回の学習の完了を待ったあと、次の行動を決めて学習を投入する前に行う（[trainer.cpp:702-742](../../../src/core/base/src/trainer.cpp)）。通知の間は、学習用のスレッドに仕事が無い。
- Nsight Systems の 10 秒の記録では、GPU が 1.78 秒動かない区間が 1 つあった。同じ記録の `nn::ComputePlasticityMetrics` は、CPU 側が 2 回で 1.783 秒、GPU 側が 1.2 ms だった。
- 前回の測定条件（64 lane、replay ratio 1、Atari.txt の既定のチェーン）では、learn step 500 の付近の 2 intake が、合わせて約 0.57 秒だった。
- 測定の出力は `.scratch/prd130/stage0-20261115-r1/`（git の管理外）にある。
- 2026-11-22 Atari の枠（Montezuma の実験の段取り）: 2026-11-16 から（c265dac8）、11 bat と 12 bat の Montezuma の Run は、probe の 5 つの指標（`34_agent_plasticity/41`〜`45`）の間隔を bat で上書きしている。RR8 は 5,000 learn step（`PL1`〜`PL5`）、RR4 は 2,500 learn step（`PL1R4`〜`PL5R4`）で、どちらも 160,000 経験ごとである。g99ne_split 以降の Run がこの上書きで走る。既定（`metrics_scalar.txt` 70 行の `interval:500`）と probe の件数（`agent.txt` 305 行の 4,096）は変えていない。約 2 秒止まること自体は残り、上書きした Run では止まる回数が既定の 10 分の 1 になる。[11 bat](../../../apps/11_batch_run.bat)・[12 bat](../../../apps/12_batch_run.bat)・[実験記録](../../experiments/default-dqn/atari/2026-11-08_montezuma-rnd-taiga-aligned.md)
- 2026-11-23 監査（backlog）: RFD0182（f25ff82b）で `dqn_based_agent.cpp` は無くなった。呼び出しは今 `src/algo/dqn/src/dqn_learner.cpp` の 223 行（probe の指標）と 3271 行（学習の batch の指標）。

## 影響

- 見積もり: 測った構成では、500 learn step は 125 intake（16,000 経験）である。RND ありの 1 intake を 118 ms とすると、14.75 秒ごとに約 2.3 秒が足され、実時間の約 13% に当たる。30M 経験の Run では 1,875 回で、約 1.2 時間になる。
- 実時間を測る区間にこの計算が入るかどうかで、時間が約 2.3 秒変わる。区間の位置を群の間でそろえないと、比がぶれる。

## 対応方針

未定。

- 2026-11-15 起票時の案（AI。検討していない）: 計算の間隔か probe の件数を設定で減らす。通知の経路から外して、学習を止めずに計算する。特異値の計算を軽い方法に替える。指標の値と刻みが変わる案は、可塑性の比較に使っている Run との比べ方を決めてから選ぶ。
