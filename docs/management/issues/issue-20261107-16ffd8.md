## 背景

PRD117（WARN の意味の線引きと読まれない設定の検出）の起票で、WARN を出す箇所を棚卸ししたときに、ERROR のログを出したあとも処理を止めずに続ける箇所が見つかった。PRD117 は設定の読み込みと metrics の定義の失敗だけを止める範囲にし（[PRD117](../../memo/117_warn_policy_and_unread_config_10prd.md) §3.2・D7）、ここに挙げる箇所は範囲外として §9 の 16 に置いた。

開発者に質問したか: PRD117 は暫定の起票で質疑を省いたので、この件の直し方は質問していない。工程末に課題の候補として示し、開発者が起票を選んだ（2026-11-07）。

## 事象

- [trainer.cpp](../../../core/anet-core/src/trainer.cpp) 1019〜1022 行: Train の BatchEnv を作れないと `LOG::error()` で「Failed to create env.」を出して return する。1041〜1044 行: Agent を作れないと「Failed to create agent.」を出して return する。どちらも例外にしない。
- [RunnerApp.cpp](../../../apps/runner/src/RunnerApp.cpp) 455〜457 行: 構築を受け取ったあと、RunManager の状態が RUNNING でなければ `LOG::error()` で「Failed to initialize RunManager.」を出すだけで、止めない。
- [DropMergeEnv.cpp](../../../core/envs/dropmerge1/src/DropMergeEnv.cpp) 897〜902 行（`checkGameOver`）: 物理の壁抜けで果物が箱の外へ出ると、`log.error()` で「Fruit out of bounds.」を出し、ゲームオーバーとして扱って続ける。止める行（`ANET_SYSTEM_ERROR`）はコメントアウトされている。
- [AGENTS.md](../../../AGENTS.md) の Fail-Fast 原則は、明示要求の不履行（Env・Agent の作成）と契約違反の内部状態を `ANET_SYSTEM_ERROR` で止めるとしている（184〜196 行）。

## 影響

- Env や Agent を作れない Run が、例外で止まらずに ERROR のログだけを残す。batchrun の終了コードや Runner の表示で失敗に気づけるかは、この課題の起票時点では確かめていない。
- DropMerge の壁抜けは、ゲームの結果（ゲームオーバー）として数えられ、成績に混ざる。どれだけ起きているかは確かめていない。

## 対応方針

未定。候補は次のとおり。

- Env・Agent の作成失敗は `ANET_SYSTEM_ERROR` で止め、RunnerApp の構築失敗の経路（`run_construction_failed_` と例外の再送出）に乗せる。
- DropMerge の壁抜けは、物理の異常として止めるか、ゲームの決まりとしてゲームオーバーにする（そのときは ERROR ではなく、回数をメトリクスで数える）かを決める。PRD117 の D1 の線引き（レベルの決め方）が確定してから決める。
