## 背景

PRD127 で、Evaluation Trace に RND の 3 列（ボーナス `intrinsic.bonus`、誤差 `intrinsic.error`、標準化した値 `intrinsic.normalized_error`）を出せるようにした。ボーナスの β は、学習の入口（`DefaultDQNAgent::UpdateFromBatch`）が直近に評価した値を Agent が覚えたもので、学習が有効なときだけ設定される（`core/anet-core/src/default_dqn_agent.cpp` の 851〜858 行）。step 診断は、β が無ければボーナスを NaN にする（同 808〜815 行）。

PRD127 の D7 は、学習の入口をまだ通っていない Run（起動直後、評価専用、checkpoint から再開した直後）ではボーナスを NaN にし、β を checkpoint に保存しないと決めた。理由として比べたのは、再開した Run で最初の学習の入口までの間だけ列が空く不利益と、checkpoint の書式の識別子を上げる不利益である。評価専用の Run では学習の入口が呼ばれない（PRD127 §2.6）ので、列が最後まで埋まらないことは、この比べ方に入っていない。PRD127 の G3 は、評価専用の Run でも値が出ることを目標にし、出ない値は §5.2 の表（行 5「β が無い」）に委ねている。

2026-11-13 の会話で、開発者が EvalPanel で観察したことを受けて AI が起票の候補に挙げ、開発者が起票を選んだ。

## 事象

2026-11-13、Montezuma の RND の継続 Run（`run_20261113-113201_mz_tg_r123_s1_c50m`、β 0.01、倍率 `clipped`、上限 5）の 50M の `agent_close.anet` を、`learner.enabled=false`（`run.@evalonly`）の Runner で読み込んだ。exe は PRD127 を含む build。EvalPanel の Evaluation Trace では、`rnd_err` と `rnd_norm` には値が入り、`rnd_bonus` は全行が空欄だった。

## 影響

- 評価専用の Run では、内的報酬を学習の報酬と同じ単位で読めない。checkpoint を読んで EvalPanel で止まった局面を調べる使い方（Montezuma の Greedy の止まりの調査）では、PRD127 の 3 列のうちボーナスが使えない。
- 回避として、`rnd_bonus = β × clamp(rnd_norm, 0, L − 1)`（`clipped` のとき。β と上限 L は設定から読む）を手で計算できる。β に予定（step で変わる値）を持たせた構成では、読み込んだ重みの exp step も手で当てる必要がある。

## 対応方針

未定。案は次の 2 つで、どちらも PRD127 の D7 を変える。

- (a) 学習を止めた Run では、設定の β の予定を、読み込んだ重みの exp step で評価して覚える。
- (b) β を checkpoint に保存する。D7 は、書式の識別子を上げて今ある checkpoint を読めなくする不利益を挙げている。

## 対応内容

- 2026-11-14 PRD129: Agent の構築時に exp step 0 の β を用意し、学習停止中も学習の入口の exp step で β を更新するようにした。checkpoint の書式と学習報酬は変更せず、テスト・日英の現行文書・検証資材の参照名を合わせた。確かめ: Debug 全体ビルド成功、PRD129 の 5 テスト・134 assertions と RND / Trace 関連の 60 テスト・4,954 assertions が成功。Montezuma の 50M checkpoint を自動開始あり・なしで読み、どちらも最初の行からボーナスが入り、3 行ずつ表示の式と一致した。[PRD](../../memo/129_eval_trace_bonus_beta_before_learning_10prd.md)・[実装記録](../../memo/129_eval_trace_bonus_beta_before_learning_20impl.md)
