## 事象

- τ の問い合わせ: `UQEActionPolicy::MakeUQEActionInfo`（`dqn_actor.cpp:1105-1142`。診断・全範囲・spatial・scalar の tail・点の 5 分岐）と `MakeValueQueryTaus`（1321〜1340 行。基底と UQE）が、「全範囲か、lane ごとの下限か、scalar の下限か」「tail の平均か点か」を別に書く。
- score: `MakeUQEActionInfo`（1181〜1190 行）と `MakeActionScores`（1358〜1373 行）が、「IQN なら q そのもの、lane ごとの τ なら vectorized、そうでなければ scalar」を別に書く。`MakeActionScores` は lane ごとの τ を `GetSpatialTauTensor` から取り直し、`MakeUQEActionInfo` が `selection_taus` に残した同じ tensor は Thompson のときだけ使う。
- 探索（「spatial なら tensor の ε、そうでなければ今の ε」）: 960〜964、1204〜1208、1353〜1355、1384〜1386 行の 4 か所。
- `MakeUQEActionInfo` は 191 行・11 引数で、AMP の設定、τ、forward、出力の切り分け、score、探索、診断の組み立て（1225〜1266 行）が 1 つの関数に並ぶ。`SelectAction` は 8 引数を 4 クラスの宣言と定義で写す。
- 検索語と件数: `MakeUQEActionInfo` の呼び出し 5、`MakeValueQueryTaus` の呼び出し 1、`MakeActionScores` の呼び出し 3、`SelectFromValues\(` の呼び出し 2。

## 影響

- UQE の score か τ の扱いを変えると（tail の作り方、risk の範囲、RFD0107 の lane ごとのノイズとの組み合わせ）、行動の選択と、価値の分解の外的の行動・Actor Q ヒント・TempoRL の長さの選択の両方を直す。片方だけだと、分解の Head ごとの hint や skip の選択が、実際の行動の選び方と黙って違う規則になる。

## 対応方針

- ActionPolicy に「τ の問い合わせを作る」「score を作る」「探索を当てる」の 3 つの部品を置き、`MakeUQEActionInfo` はそれを順に呼ぶ形に分ける。`MakeActionScores` は `selection_taus` があればそれを使い、spatial の τ を取り直さない。`iqn_risk_query` は、どの呼び出しも IQN のとき真なので消す（[issue-20261111-54c7e1](issue-20261111-54c7e1.md) の 2026-11-25 の行）。診断の組み立ては関数に出す。
- 性能の区分は「中立」（行動の step ごと。乱数の消費の順と回数、forward の数を変えない）。
- トピック別まとめの「変えるときの条件」では、RFD0161（方策の処理を全 lane で行い、強制していない lane の結果と乱数を変えない）、RFD0101（ε・τ の値と評価の時機）、RFD0104 §5.7・RFD0106 §5.3（既定の full・shared で行動と乱数の列を変えない）、RFD0061 §7.4・§8 が当たる。同 seed・決定的モードの metrics の一致を確かめる。
- テスト: `dqn_actor_test.cpp` の 133・346・875・1016・1071・1395・1462・1813・2258 行が通す。
- 不採用の形との突き合わせ: ADR 0019（IQN＋UQE の Q は同じ forward の risk の score）と、RFD0101 の「Thompson の τ の区間を設定する形 — 不採用」に触れない。
- [issue-20261111-d1d12b](issue-20261111-d1d12b.md) の群 6（基底が派生の種別を bool とメンバの組で持つ）は同じクラスなので、同時に直すかを決める。
