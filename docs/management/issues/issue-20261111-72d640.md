## 背景

2026-11-10〜11 のリファクタリング候補の抽出（C++ の本体を 16 単位に分けて読み、観点は docs/quality/refactor.md による）で見つかった。開発者が候補の一覧から選び、起票を指示した。2026-11-11 に今のコードで場所を確かめ直した。

DefaultDQNAgent の組み立てと、それを写した RainbowAgent は、Head の選択と Learner の構築を共有すれば一緒に片づくので、1 件にした。PRD121 は Head を外的と内的の 2 つにする。[issue-20261103-4a2b5e](issue-20261103-4a2b5e.md)（PRD937、Head の射影の分離）で Head が畳まれると、Head の選択が簡単になる。

## 事象

- `DefaultDQNAgent::DefaultDQNAgent`（core/anet-core/src/default_dqn_agent.cpp:50 から、242 行）の 1 つの関数に、gamma のログ、seed、内的報酬、スケーラ、Head の Factory の選択、forward 設定、stack 軸の spec、tau の spec、skip の定義、モデル、構造図、target の方策、Learner、読み込みが並ぶ。
  - Learner の構築 3 つ（IQN・QR・TD、256 と 266 からの分岐）は、型を除いて引数 14 個が同じである。
  - Head の選択（141 から）は、quantile_mode の 3 値と use_dueling の 2 値の組を入れ子の if の 6 分岐で書く。
  - gamma の初期値を同じ式で 2 回評価している。
- `RainbowAgent`（core/anet-core/include/anet/rainbow_agent.hpp、core/anet-core/src/rainbow_agent.cpp）が DefaultDQNAgent の一部を写している。
  - Head の選択の 4 分岐は、DefaultDQN の 4 分岐と同じ Factory・同じログ文で、違いは DefaultDQN が `config_.head.projection` を渡す点だけである。
  - Actor の生成（仕様の照合、カタログの検索、device の検証、source の選択、clone、`emit_hint` の 2 行）が同じである。
  - `GetScalar`・`GetTensor`・`GetTensorVector` の振り分けが同じ分岐で、Rainbow は接頭辞を `"replaybuffer."` と直書きし、DefaultDQN は `ReplayBuffer::kKeyPrefix` を使う。
  - `UpdateFromBatch` は、DefaultDQN のものから報酬のスケール・内的報酬・観測の統計を除いた形である。設定も head.init の 6 キー、learner の 25 キー、Actor のカタログが部分集合として写っている。
  - 既に 5 点が食い違っている。(a) Rainbow は `ValidateActionPolicy`・`ValidateTauRule` を呼ばない。(b) Rainbow は policy_type を見ずに常に ε-greedy の方策を作る。(c) 設定の記録の仕方が違う。(d) `net.body` と構造図の記録が Rainbow に無い。(e) `UpdateFromBatch` が Rainbow では public、DefaultDQN では private である。
  - RainbowAgent を構築するのは、Factory の登録（init.cpp）とテストだけである。

## 影響

- Learner の引数を 1 つ足すと 3 か所を直す。分布の表し方を 1 つ足すと、Head の分岐・Learner の分岐・設定の検証・テンソルの契約の検証を直す。PRD121 で Head を 2 つにすると、ここに当たる。
- Head の種類・Actor の hint の条件・ReplayBuffer の値のキーを変えると、2 つの Agent を同じように直すことになる。食い違い (a)〜(e) が意図した差か直し漏れかが、コードから読めない。

## 対応方針

先に、RainbowAgent を残すか（DefaultDQN の設定で表せるか）を決める。残すなら、Head の Factory の選択、Actor の生成の共通部分（source の選択・clone・emit_hint）、learner への値の振り分けを、dqn の内部の自由関数（または 2 つの Agent が共有する部品）へ出し、両方から呼ぶ。DefaultDQNAgent のコンストラクタは「Head の Factory を選ぶ」「network の入力 spec を作る」「Learner を作る」「構造図を記録する」を private の関数に分け、Learner は型だけを変える小さな template の関数にして引数の列を 1 回だけ書く。ログの文言と順番、seed の作り方、設定キー、メトリクスの名前は変えない。
