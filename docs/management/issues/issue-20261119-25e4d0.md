## 背景

2026-11-19、[PRD182](../../memo/0182_source_layout_10rfd.md)（ソース配置の見直し）の再グリルの会話を `anet-improve` で振り返り、手戻りの 1 つとして拾った。開発者は、対策の一覧から「推しのまま全部採る」を選んだ。この問題で推した対策は、新しいスクリプトを足すもので PRD が要るので、その場では書かず、この課題に積んだ。

## 事象

- 2026-11-19、PRD182 のレビューの 1 往復目の差し戻し（6 点）を直している途中で、会話が要約で詰められた。要約のあと、[anet-create-prd](../../../.agents/skills/anet-create-rfd/SKILL.md) の段 6 の手順（出し直す前に、直した箇所の帰結を検索し、変えた規則を実物に当てる）を読み直さずに、2 往復目の依頼を出した。
- 2 往復目と 3 往復目の差し戻しは、どちらも 1 点で、同じ種類だった。直すもの・残すものの線引きに入らないファイルが残っていた（2 往復目は検証資材の文書、3 往復目は Run の設定の写し）。3 往復目の直しで、線引きを検索に当たるファイルの全部に当ててから出し直し、4 往復目で OK になった。
- 要約には、skill の手順の細部が残らない。要約のあとの手元にあるのは、進んでいる段と、決めたことの要旨である。
- [プロセス契約](../../process/protocol.md) の 1 節は、会話が圧縮されたあとも同じ実行の続きであり、作業記録と、次にすることに要るものだけを読み直すと定める。この文も要約のあとには手元に残らず、踏むきっかけが無い。
- `AGENTS.md`、[レジストリ](../../process/registry.md)、`anet-create-prd` と `anet-impl-prd` の skill には、要約のあとの扱いを書く文が無い（「圧縮され」「要約され」で検索して 0 件）。
- 今ある hook は 2 本である（`.agents/hooks/`、`.claude/settings.json`、`.codex/hooks.json`）。ユーザーの発言のたびにコミットの知らせを差し込むもの（`commit_cue.py`）と、検索のコマンドを見張るもの（`search_guard.py`）で、要約のあとに動くものは無い。

## 影響

- 要約のあとに、続ける段の手順が飛ぶ。今回は、同じ種類の差し戻しでレビューの往復が 2 回増えた。
- 飛んだ手順が、レビューで拾えない種類（質疑の出し方、起票の候補の出し方、完了の報告の形など）なら、気づかれないまま進む。
- 見立て: 長い工程ほど要約が入り、手順の多い終盤（自己点検、差し戻し対応、完了の報告）に当たりやすい。

## 対応方針

- 2026-11-19 anet-improve: 選んだ対策は、会話が要約された直後に、読み直しを促す文を自動で差し込む仕掛け（hook のスクリプトと設定）を足すことである。差し込む文は、プロセス契約 1 節の決まり（作業記録と、次にすることに要るものを読み直す）を踏ませるもので、続けている工程の skill の、今いる段の手順を読み直すことを名指す。新しい決まりは足さない。
- PRD で決めること: 要約の直後に動かす手段（Claude Code と Codex のそれぞれで、何をきっかけに動かせるか）、差し込む文、動いたことの確かめ方。
- 採らなかった対策: `AGENTS.md` に「要約のあとは、続ける段の手順を読み直す」を書く案。すべての作業で読む量が増え、要約のあとに `AGENTS.md` が読み直されなければ効かない。
