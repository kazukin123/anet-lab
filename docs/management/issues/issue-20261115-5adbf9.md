## 背景

[PRD114](../../memo/114_findings_intake_and_fix_prd_10prd.md) の D13（2026-11-02）で、PRD の採番を次のように決めた。

- 新しい PRD は、起票した時点で 900 未満の最大の番号の次を取る。
- それまでの `999` の PRD 47 本は、置き場を変えずに、使われたことの無い 9xx の番号へ振り直す。対象の番号は 901〜909・914〜919・922〜929・934〜939・942〜959 である。
- 910〜941 の 10 本は、今の番号のまま残す。
- この形は、900 からの連番にする案を、レビューの指摘を受けて改めたものである。D13 の理由は、使われた番号を再び使うと、コミットの件名・ADR・実験記録などが番号で指す PRD が入れ替わることである。

[memo README](../../memo/README.md) の「採番」は、9xx を過去の PRD の ID とし、新しい番号にも作業順の表現にも使わないと書く。

開発者が、9xx の番号のまま残る過去の PRD を、連番へ振り直したいと指示した。この起票では質問をしていない。

## 事象

- 9xx の PRD の数（2026-11-15）:
  - `docs/memo/` 直下: 49 本（901〜959 の間の番号）
  - 保管場所: 8 本（`done/` 1 本、`dropped/` 2 本、`frozen/` 5 本）
  - 900 未満の最大の番号は 129 である。
- 9xx の PRD を指す記録:
  - `prd` 欄で 9xx の PRD を指す課題: 51 件
  - `docs/memo/` の外で 9xx の PRD のファイル名を書く追跡中のファイル: 約 130 個
  - `PRD9xx` の表記を含む追跡中のファイル: 103 個
- コミットの件名で、scope か末尾の参照に 9xx の番号を持つもの: PRD918 が 2 件、PRD934・PRD938・PRD925・PRD931 などが 1〜2 件。
- `reports/tools/wiki_support.py` の `prd_rows` は、ファイルに触れたコミットの件名から PRD 番号を読み、`docs/memo/**/<番号>_*_10prd.md` で PRD を引く。1 本に決まらない番号は「PRD を一意に決められない」の行にして、点検へ返す。

## 影響

- 9xx の番号が連番から離れていて、一覧や INDEX で並べたときに番号の並びと起票の順が合わず、読みにくい。
- 9xx の PRD のグリルや実装を進めるたびに、`PRD9xx` を含むコミットの件名が増える。件名は書き換えられないので、振り直すのが遅いほど、旧い番号のまま残る記録が増える。
  - たとえば PRD938 は、グリル済みで実装を待っている。

## 対応方針

9xx の PRD を、900 未満の連番（今の最大の番号の次から）へ振り直す。9xx の番号は、振り直したあとも再び使わない。決めることは次のとおり。

- **範囲**: 直下の 49 本だけか、保管場所の 8 本も含めるか。PRD114 の D14 は、保管場所の PRD を動かさないとしている。
- **振り直す順**: 起票した日の順か、今の 9xx の番号の順か。
- **参照の直し方**: PRD114 の §5.9 と同じ扱いにするか。§5.9 の扱いは次のとおり。
  - 現行の文書・道具・課題のリンクと名指しを直す。
  - 過去の記録は、番号だけの表記を当時のまま残す。
  - 直下の PRD の冒頭に、振り直しの 1 行を足す。
- **コミットの件名の旧い番号**: 件名に残る旧い番号を、トピック別まとめの「PRD の一覧」でどう引くか。旧→新の対応表を道具に持たせるか、「PRD を一意に決められない」の行のままにするか。
- **規約の改め**: memo README の「採番」と PRD114 の D13 をどう改めるか。ADR を起こすかも決める。
- **時期**: ほかの作業の枠が PRD を起票したりグリルしたりしている間は番号が動くので、時期を合わせる。
