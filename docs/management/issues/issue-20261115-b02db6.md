## 背景

RND の target と predictor は、どちらも Body のあとに同じ形の Linear の Head を持つ。Head の出力の幅は `intrinsic.rnd.output_dim` で決め、入力の幅は構築時の dummy forward で Body の出力から決まる（[nn_impl.cpp:2538-2542](../../../src/core/base/src/nn_impl.cpp)、[nn_heads.cpp:125](../../../src/core/base/src/nn_head.cpp)）。2 つの Network の Head は 1 つの工場から作る（[intrinsic_rnd.cpp:439](../../../src/core/base/src/intrinsic_rnd.cpp)）。

[PRD116](../../memo/0116_rnd_lifelong_novelty_10rfd.md) の未決 15 は、`output_dim` を `rnd` の直下、初期値を `rnd.head.init.*` に置いたまま、Head の設定の置き場が決まってからそろえるとした。

2026-11-15、開発者が `output_dim` を Network の設定と合わせる必要があるかを尋ね、Head の出力の幅だと分かったところで、`head.output_dim` に置けないかを挙げた。AI は 3 つの置き場（`intrinsic.rnd.head.output_dim`、`intrinsic.rnd.net.head.output_dim`、`intrinsic.rnd.common.net.head.output_dim`）を比べ、今の決まりに合う 1 つ目を勧めた。開発者は、Head は Network の一部なので実態に合わせたい気もするとし、以前は名前で Network の一部であることを表していたが今はその手掛かりも無いと述べた。そのうえで、全体の決まりを変える話に波及するので、起票だけして後回しにすると決めた。

## 事象

- `intrinsic.rnd.output_dim` は `rnd` の直下にあり、Head の初期値だけが `intrinsic.rnd.head.init.*` にある（[intrinsic_rnd.hpp:24](../../../src/core/base/src/intrinsic_rnd.hpp)、同 41-43 行）。
- DQN の Head の設定は Agent の直下の `head.*` にある（`DefaultDQNAgent.head.*`、`skip.head.*`、`intrinsic.value.head.*`）。[PRD098](../../memo/0098_temporl_skip_policy_10rfd.md) の実装で、それまでの `head_init.*` を `head.init.*` に改めてこの形にそろえ、`net.head.*` は取らなかった（[PRD155](../../memo/0155_config_root_ownership_alignment_10rfd.md) §3.8）。
- 設計文書 [130](../../design/130_neural_networks.jp.md) では、Network は Body と Head をまとめた単位である。一方で Head の設定は、Agent（RND では推定器の設定）が読み、Head の工場を `BuildNetwork` に別の引数で渡す。
- `NetworkConfig` は、`<prefix>.net` の下の block・branch・profile・`body.output` のキーだけを名前の形で拾い、ほかのキーは読まない（[nn_impl.cpp:1028-1043](../../../src/core/base/src/nn_impl.cpp)）。
- Head の設定を `<Agent>.net.head.*` へ移す案は、PRD155 の §3.8・Q8 にある（暫定。[issue-20261103-b4e5c9](issue-20261103-b4e5c9.md)）。

## 影響

- RND の Head の設定が 2 か所に分かれ、Head の出力の幅を RND 全体の設定と読み違えやすい。今回も、Network の設定と合わせる必要があるかを確かめる手間がかかった。
- 設定キーの名前から、Head が Network の一部であることが読めない（DQN 側も同じ）。

## 対応方針

未定。Head の設定の置き場の全体の決まり（PRD155 の Q8）が決まってから、RND の置き場をそろえる。

- 2026-11-15 の比較（案）: 今の決まりのままなら、`intrinsic.rnd.head.output_dim` が `head.init.*` と並び、2 つの Network に共通の Head と読める。`net.head.*` に寄せる場合、RND は 1 つの Head の設定を target と predictor の 2 つの Network で共有している点が DQN と違う。`intrinsic.rnd.target.net.head.*` と `intrinsic.rnd.predictor.net.head.*` に分けると、同じ値を 2 か所に書いてずれうる（構築時の検査が要る）。`intrinsic.rnd.net.head.*` は、無い 3 つ目の Network があるように読める。共通の置き場（`intrinsic.rnd.common.net.head.*` のような形）は、2 つの Network が引き継ぐ仕組みを新しく作ることになる。PRD155 の Q8 を決めるときの材料にする。
- 名前を変えるときは、exe と `Atari.txt`（`run.@rnd` の `output_dim = 512`）を同時に切り替える。新旧が食い違うと、起動時に「Unread config keys」の WARN を出したまま、既定の 128 で走る（[config.cpp:374](../../../src/core/base/src/config.cpp)）。

## 対応内容

- 2026-11-15 暫定の改名: `intrinsic.rnd.output_dim` を `intrinsic.rnd.head.output_dim` へ移し、DTO・読み取り・検証・利用側・テスト・日英の設計文書をそろえた。追加指示により `Atari.txt` も同時に更新し、既定128・Atariの512を維持した。凍結設定と履歴は保持し、Headの置き場の全体の判断（PRD155 Q8）はこの課題に残す。確かめ: Debug/Release全体ビルド成功、Debugの関連85ケース・8,844 assertionとReleaseのcore既定1,256ケース・194,539 assertionは失敗/ERROR 0。既定のskip 1件はCUDA利用可能時に対象外となるPRD070のテスト。LF・BOM・避ける語・旧キーの現用範囲からの除去・保護対象の保持も確認した。
