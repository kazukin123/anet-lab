## 背景

AGENTS.md は、もとからある死にコードを消さずに報告すると定めるので、消すには課題が要る。消すかどうかの判断は 1 つ（呼ばれないものを消す）で、確かめ方も同じ（ビルドとテストが通ること）なので、1 件にまとめた。probe の呼ばれないコードは [issue-20261111-0ef722](issue-20261111-0ef722.md) に分けた。

## 影響

- 読む人が「どこかで使われている」と考えて探すことになる。公開ヘッダにあるものは「使える口」に見える。
- 名前と違う動きに見えるものがある（`GetEnvClassId` は常に空、`ANET_REGISTER_VIEW_CREATOR` は使うとコンパイルできない、`total_reward` は表示する機能があるように見えて動かない、`GetConfigFilePath` の既定の経路は動かない）。
- 保存の中身を変えるたびに、誰も呼ばないログ出力を直すことになる。Conv2d の Observer は、呼ばれない `GetImageData` のために録画中の毎 step でロックと画像の写しを行っている。

## 対応方針

上の一覧を消す。消すときに 1 件ずつ、検索で呼び出しが無いことを確かめ直し、リポジトリの外（文書・スクリプト・設定ファイル）から名前で指していないかも見る。テストだけが呼ぶもの（`IsDistributional`・`UpdatePerPriorities`・Tensor 版の `MakePerRawPriority`・`GetDefaultConfigPrefix`・`ForwardedKeyEvent::GetWindow`・`GetFlattenSize` の override など）は、テストを書き換えるか残すかを決める。次の 2 つは、ほかの判断のあとにする。

- observers の呼ばれない `GetImageData` と `captured_step_`・`last_image_` は、[issue-20261103-f40ae8](issue-20261103-f40ae8.md)（PRD056）が `GetImageData` の経路の扱いを決めてから消す。`TimeHistogramObserverConfig` の項目も同じ。
- 設定の語として受け付けているもの（`HeatMapObserverConfig` の `override_*` を読むキーがあるか、flag の語など）は、消すと受け付ける設定が変わるので、残すか消すかを決める。

外から見える振る舞い、設定キー、メトリクスの名前、ログの文言は変えない。Conv2d のロックと画像の写しが無くなる分だけ、録画中の速さが変わりうる。消す量が多いので、ファイルの塊ごとに分けて受け入れてもよい。
