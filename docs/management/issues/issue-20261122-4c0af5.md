## 背景

[PRD191](../../memo/0191_rnd_raw_error_and_recent_learning_10rfd.md) の再グリル（2026-11-21）で、predictor の補助学習に、rollout ぶんの観測をためてから学ぶ形を足すと決めた。開発者は、ためる仕組みを、できるだけ汎用にして共通化したいと述べた。理想は、Replay の中のキューや、フレーム積層のキューとも共有できることである（PRD191 §12 の発言 4）。

開発者は、PRD191 では汎用の部品を新しく作るところまでにし、既存の置き場の載せ替えは入れない案を選んだ。あわせて、「ためる仕組み」を統合整理する課題を残すよう指示した。この課題は、その指示で起こした。

## 事象

- 観測の tensor をためる置き場が、今は 2 つある。フレーム積層の履歴（`DictFrameStacker`。[stacker.cpp](../../../src/core/base/src/stacker.cpp) 21 行）と、Replay の観測の置き場（`ReplayExperienceStorage`。[replay_buffer_impl.cpp](../../../src/core/base/src/replay_buffer_impl.cpp) 525 行）である。PRD191 の実装で、lane × 時間の tensor の置き場の部品（`LaneTimeTensorStore`）が 3 つめとして加わる。
- 3 つは、「キーごとに lane × 時間の tensor を、最初の書き込みで確保し、時間の軸に書き、番号で読む」ところが同じである。書き込み位置の持ち方（全 lane 共通か、lane ごとか）と、読み方は違う（PRD191 §5.6）。
- Replay の n-step の待ち行列（`ExperienceQueue`）は、tensor ではなく小さな記録の列で、同じ部品にはならない。
- 載せ替えるときに部品へ足す操作と、部品の外に残るものは、PRD191 §8.5 の対応表にある。

## 影響

- 同じ形の置き場の実装が 3 つ並ぶ。確保、device、番号で読む処理を、置き場ごとに保守する。
- 新しい置き場の部品は、使い手が 1 つの間、形を実物で確かめられない。

## 対応方針

未定。材料は PRD191 §5.6 と §8.5 の対応表である。決めることは次のとおり。

- フレーム積層の履歴を載せ替えるか。全 Run の Actor の毎 step に触るので、同 seed の metrics の一致と、性能の比較が要る。
- Replay の観測の置き場を載せ替えるか。全 Run の Push と抽出に触る。フレーム履歴の整合（PRD077・PRD078）と、抽出の性能を合わせて作り込んだ箇所である。
- 置き場の設計文書を起こすか。PRD191 は、部品の説明を設計文書 212 に置き、150 の部品の表から案内する（PRD191 の D52）。

PRD191 の実装で置き場の部品ができてから着手する。
