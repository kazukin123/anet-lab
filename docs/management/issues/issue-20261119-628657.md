## 背景

PRD121 で、DQN 系の Q を外的と内的の 2 つの Head に分ける `intrinsic.value_mode = decomposed` を入れた。損失と最適化の分け方は `learner.intrinsic.feature_gradient` で選び、`merge`（既定）と `split` の 2 つがある。Montezuma の Run では、内的の割引率を 0.99 に分けて内的をゲームオーバーで切らない形（G99NE）を merge と split の両方で流している。

2026-11-19、Atari の枠の会話で、開発者が「split でも merge でもない第 3 の形が候補に挙がっていなかったか」と尋ねた。11/16 に PRD121 の作業で MEME を読んだときのメモにあった形（下の事象）を AI が説明した。開発者の感触は「今の形（merge）のままのほうが良さそう」で、そのうえで起票を指示した。

## 事象

- `merge` は 2 つの損失を足して 1 回 backward し、全体を clip して 1 つの Adam の状態で更新する。`split` は外的と重み付きの内的の勾配を別々に取り、損失ごとに clip して別々の Adam の状態で更新する。どちらも、Head ごとに自分の目標値との誤差を取る（[214 §3.3](../../design/214_value_decomposition.jp.md)、80 行）。
- MEME（Kapturowski ら、ICLR 2023）は胴体を共有して外的・内的で別の Head を持ち、損失は合わせた値に掛ける。Head を 1 つにしても成績は同程度だったと書く（[内的報酬の手法の全体像 §4.2](../../../reports/intrinsic_reward_landscape_survey_2026-11-18.md)、[エピソード内のボーナスの論点 §2](../../../reports/episodic_bonus_value_based_survey_2026-11-18.md)。原典は MEME の §4・付録 H.4）。
- 11/16 の作業メモは、MEME の理由として「関数近似では Head ごとの損失の和と和の損失が違い、交差項が抜けて勾配がずれる」「行動は合わせた Q で選ぶ」の 2 つを挙げる。原典の本文では確かめ直していない。
- MEME で外的と内的の割引率が別かは、上の 2 つの調査レポートに書いていない。
- vd（merge・割引率は共有・内的もゲームオーバーで切る、RR8）では、学習の行動の 1 位が外的の Q の 1 位と違う割合が 4M 窓で 0.62〜0.86、内的の損失は外的の損失の 1.2 倍（0〜4M）から 12 倍（28〜30M）へ開いた（[Montezuma の実験記録](../../experiments/default-dqn/atari/2026-11-08_montezuma-rnd-taiga-aligned.md)、現時点のまとめ 23）。
- RR8 の Greedy の 20〜30M の平均は、vd が 500 点以下、g99ne（merge）が 3,160・2,791、g99ne_split が 2,394・2,265 だった（同、現時点のまとめ 22・29）。

## 影響

- Head ごとの損失が、行動を選ぶ合わせた Q を直接は鍛えていないなら、行動の順位の学習が損失の重みの偏り（内的の損失が外的の 12 倍）に引っぱられている可能性がある。今は確かめる手段が merge と split の 2 つしかなく、合わせた Q に損失を掛けた場合との差は分からない。
- 急ぎではない。merge と split の差も seed のぶれと見分けきれておらず（各 2 本）、今のベースラインは merge のまま進められる。

## 対応方針

未定。開発者の感触は今の merge のままがよい、で、着手は Montezuma の探索で RR4 などの安い構成が使えると分かってからにする。

- 案 1（純粋な MEME 型）: 合わせた Q（同じ τ どうしを β で足した値。PRD121 の D14 と同じ合わせ方）に対して、外的と内的の目標値を同じ合わせ方で足した値との誤差を 1 本だけ取る。最適化は merge と同じく 1 つの Adam。懸念: 損失が合わせた値にしか掛からないと、報酬のどの分を外的と内的の Head のどちらが持つかが決まらない。たとえば外的の Head が全部を持ち内的の Head が 0 でも誤差は消え、そのとき内的の分も外的の割引率 0.997 とゲームオーバーの切れ目で学ばれる。Montezuma で効果がはっきりした G99NE（上の事象の vd 対 g99ne）の効き目が消えうる。
- 案 2（混ぜた形）: 案 1 の損失を主にし、Head ごとの損失（今の merge）を小さな重みで足して、それぞれの Head を自分の割引率と終端に留める。AI の案で、事例は確かめていない。
- 確かめ方: Montezuma の段 34・35（g99ne merge、RR4）と同じ条件で、案 1 と案 2 を merge と並べる。比べるのは Greedy の平均、学習側で 3500 点の道へ移るか、外的と内的の Q の値の水準（案 1 で内的の Head が 0 へ寄るか）。
- 着手の前に、MEME の原典で、損失の式（§4・式 3〜5）、外的と内的の割引率の扱い、Head 1 つとの比較（付録 H.4）を確かめる。
