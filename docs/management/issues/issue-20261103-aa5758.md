## 背景

DefaultDQN が「env の出した Observation を Network の入力にする」処理は、次の 4 経路と 1 つの spec 生成に分かれて書かれている。

## 事象

対応するPRD: [161_observation_pipeline_10prd.md](../../memo/0161_observation_pipeline_10rfd.md)
- 2026-11-23 監査（drift）: `CONTEXT.md` の Frame・Perception・Forwarder・Forwarder の並び・Forward の依頼・stack 軸・値の尺度（626〜652 行。977e0c38 で入った）は今の形で書かれているが、名前（`ForwarderChain`・`ForwardRequest`・`ValueScale`・`Scaled`・`Unscaled`・`Forwarder`・`Perception`・`has_stack_axis`）は `src/` と出荷の設定に 0 件である。決めたのは RFD0161 の D17・D19・D26 と ADR 0084〜0086 で、実装計画の段階 2・3 で入る。

## 対応方針

対応するPRDと保存済み実装計画に従う。

- 2026-11-11 リファクタリング候補の抽出: PRD161 の題材の観測の正規化（scaler_impl.cpp）に、次の作りがある。(1) 正規化と clip 率の計測が `normalizeInternal` の 1 つに束ねられ、`Normalize`（287、439、590）は clip 率を捨て、`NormalizeAndUpdateStats`（293、445、608）は正規化したテンソルを返すが、呼び出し 5 件はどれも戻り値を使わない。`Normalize` は Actor の毎 step と学習 1 回につき 2 回呼ばれ、使われない clip 率のために比較・平均・`item` を毎回行う（CUDA では同期が入る）。intrinsic_rnd.cpp には「統計更新専用 API の追加を判断する」@todo がある。(2) `ObservationNormalizerFactory::CreateObservationNormalizer`（696 から）は `ObservationNormalizerConfig` を 9 個の位置引数にばらして渡し、`RunningStdSingleTensorNormalizer` は 8 個の const メンバへ写し直す。同じ型が隣り合う位置引数は、順番を取り違えてもコンパイルが通る。検証の関数 `ValidateObservationNormalizerConfig` を呼ぶのは intrinsic_rnd.cpp の 1 件だけで、Factory は呼ばない。(3) `RunningStdSingleTensorNormalizer::NormalizeAndUpdateStats`（445 から、115 行）は、入れ子が 7 段で、統計の更新・外れ値の判定・診断ログの組み立て（39 行）が同居し、実装を決めるまでの検討の経緯のコメントが約 20 行残る。統計を更新する経路が 4 つあり、全部が正常の経路だけ `last_outlier_ratio_` を書かない。PRD161 は再グリル中なので、その場でこの追記を拾うかを決める。確かめ: 関数の位置と呼び出しを今のコードで確かめた。速さへの効きは測っていない。
- 2026-11-12 PRD170 の再グリル: `MakeAction` の入力の形を 170 が先に決めた。PRD161 の Q7 は、170 の D2・D3・D4・D6 に合わせる。入力は構造体 `MakeActionOptions`（3 つ目の引数、既定値つき）で、Runner の `DoStep`・`DoUpdateFrame` も同じ構造体を受けて `MakeAction` へそのまま渡す。強制行動は `MakeActionOptions` の欄として足し、`EvalRunner::DoStep` の手動の行動の引数をそれにまとめられる。どちらの PRD を先に実装してもよい。[PRD](../../memo/0170_nn_trace_capture_unification_10rfd.md)（§9）・[ADR 0072](../../adr/0072-make-action-inputs-are-passed-per-call-through-runner-step-not-registered.md)

## 対応内容

- 2026-11-22 PRD161 のグリル: 再グリルを終え、確定事項 D1〜D45 と、受入 1〜34 を決めた。観測の加工は、設定で並べる Forwarder の並びにし、強制行動は `MakeActionOptions` の欄にする。対応方針の 2026-11-11 の追記（正規化の部品の内部）は、範囲に入れず（NG4）、[issue-20261111-5f695d](issue-20261111-5f695d.md) へ写した。先送りしたものは、[issue-20261122-258ef8](issue-20261122-258ef8.md)・[issue-20261122-ba42c9](issue-20261122-ba42c9.md)・[issue-20261122-4b9e2d](issue-20261122-4b9e2d.md) と、[issue-20261113-b96b2c](issue-20261113-b96b2c.md) への追記に記録した。確かめ: PRD のレビューは 4 回目で OK。実装はしていない。[PRD](../../memo/0161_observation_pipeline_10rfd.md)

- 2026-11-23 RFD0161 の実装: 強制行動を `MakeActionOptions` で渡し、Actor が該当 lane の行動を確定するようにした。DefaultDQN の観測加工は行動選択・経験受入れ・Sample・可視化を同じ Perception の定義につなぎ、Env の単フレーム spec から Network の入力 spec を導くようにした。強制行動の回帰テストと ReplayBuffer の 1 枚／4 枚の往復を確認した。段階 A・C と段階 B の初回学習比較の結果は [実装記録](../../memo/0161_observation_pipeline_20impl.md#経過) に記録した。
