## 対応内容

- 2026-11-11 リファクタリング候補の抽出: PRD944 の題材の観測の正規化（scaler_impl.cpp）に、次の作りがある。(1) 正規化と clip 率の計測が `normalizeInternal` の 1 つに束ねられ、`Normalize`（287、439、590）は clip 率を捨て、`NormalizeAndUpdateStats`（293、445、608）は正規化したテンソルを返すが、呼び出し 5 件はどれも戻り値を使わない。`Normalize` は Actor の毎 step と学習 1 回につき 2 回呼ばれ、使われない clip 率のために比較・平均・`item` を毎回行う（CUDA では同期が入る）。intrinsic_rnd.cpp には「統計更新専用 API の追加を判断する」@todo がある。(2) `ObservationNormalizerFactory::CreateObservationNormalizer`（696 から）は `ObservationNormalizerConfig` を 9 個の位置引数にばらして渡し、`RunningStdSingleTensorNormalizer` は 8 個の const メンバへ写し直す。同じ型が隣り合う位置引数は、順番を取り違えてもコンパイルが通る。検証の関数 `ValidateObservationNormalizerConfig` を呼ぶのは intrinsic_rnd.cpp の 1 件だけで、Factory は呼ばない。(3) `RunningStdSingleTensorNormalizer::NormalizeAndUpdateStats`（445 から、115 行）は、入れ子が 7 段で、統計の更新・外れ値の判定・診断ログの組み立て（39 行）が同居し、実装を決めるまでの検討の経緯のコメントが約 20 行残る。統計を更新する経路が 4 つあり、全部が正常の経路だけ `last_outlier_ratio_` を書かない。PRD944 は再グリル中なので、その場でこの追記を拾うかを決める。確かめ: 関数の位置と呼び出しを今のコードで確かめた。速さへの効きは測っていない。
