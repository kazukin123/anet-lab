## 背景

2026-11-25 の監査（観点 defect、範囲 321_agent_core）で見つけた。分類は数値（診断値）である。開発者には質問していない。

設計 200 §2.4（`docs/design/200_dqn_agents.jp.md:253`）は、方策の指標について「方策に使わない既知の指標はNaNとなる」と書く。RFD0101 D11 は UQE の方策と Thompson の値だけを決め、ε-greedy の `uqe_tau` を 0 にする決定は無い。

ホットスポット補正: `dqn_actor.cpp` は、`git log --since=2026-08-27 --follow` で 90 日に 9 回変わっており、コードのファイルの上位 5%（7 回以上）に当たる。urgency を 2 から 3 へ 1 段上げた。

## 事象

- `ActionPolicy::GetScalar` の `uqe_tau` の行（`src/algo/dqn/src/dqn_actor.cpp:882`）は `return thompson_ ? kNaN : current_uqe_tau_;` で、`uses_uqe_` を見ない。`uqe_epsilon`（883 行）と `uqe_tau_lane_min`・`uqe_tau_lane_max`（888・889 行）は `uses_uqe_` を見て NaN にする。
- `current_uqe_tau_` の初期値は 0（`dqn_actor.hpp:157`）で、spatial のときだけコンストラクタが NaN にする（`dqn_actor.cpp:668-669`）。EpsilonGreedy と、spatial 無しの EpsilonGreedy として作られる Greedy は τ を更新しないので、0 を返す。spatial の EpsilonGreedy だけ NaN になる。
- 出荷設定で起きる。DropMerge の既定は `A2.use_optimistic_target = false`（`DropMerge.txt:196`）で、`ReadTargetPolicy` が target の方策を Greedy にする（`default_dqn_agent.hpp:425`・447）。`M1.[32_agent_base/04_uqe_tau_target] = $agent target_policy.uqe_tau @learn $exp_step`（`DropMerge.txt:1371`）が、学習のたびに 0 を記録する。GridMaze も同じ tag を持つ（`GridMaze.txt:228`）。
- 実物で確かめた。`run_20261102-212957_dm_iqn-k32-n32-m32`（実効設定は `use_optimistic_target = false`、`target_policy.policy_type = Greedy`）の `32_agent_base/04_uqe_tau_target` は、3,011 点のすべてが 0 だった。
- テスト: UQE の spatial の平均だけを見る（`dqn_actor_test.cpp:1804-1810`）。UQE でない方策の `uqe_tau` を見るテストは無い（検索語 `"uqe_tau"`）。

## 影響

- UQE の target（τ=0.85 など）と並べて見ると、Greedy の target の Run が「τ=0 の UQE」に見える。spatial の有無だけで、同じ方策が NaN と 0 に分かれる。
- 学習の値は変わらない。

## 対応方針

- `uqe_tau` の条件に `uses_uqe_` を足し、UQE を使わない方策では NaN を返す。hot path と乱数に触れない。該当の構成では、この tag が記録されなくなる。
- UQE でない方策（Greedy、spatial の有無それぞれの EpsilonGreedy）で NaN になることのテストを足す。

## 対応内容

- 2026-11-28 UQE を使わない方策の `uqe_tau` を NaN にした。Greedy と spatial 有無の EpsilonGreedy を確認した。 [RFD0207 実装メモ](../../memo/0207_dqn_small_fixes_and_refactors_20impl.md)
