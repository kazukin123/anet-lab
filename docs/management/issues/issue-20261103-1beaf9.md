## 背景

台帳 F-0009 から移した（2026-11-03）。
観点: defect。分類: 整合性。確度: med。

- 2026-10-22 open: 2026-07-04の監査の指摘を今のコードで確かめて登録

## 事象

step Nの終わりにprev_exp_は遷移Nになるが、step Nで投入した学習は遷移N-1で行う。step N+1の待ち合わせで、遷移Nと、遷移N-1を入れたあとの学習結果を同じLearnEvent・TrainEventに入れる。Serialでは遷移と学習結果が同じstepのものなので、ランナーによってイベントの組の意味が変わる。

- core/anet-core/src/trainer.cpp:692 学習の投入は、この時点のprev_exp_（1つ前のstepの遷移）とprev_counts_で行う
- core/anet-core/src/trainer.cpp:712 そのあとprev_exp_をこのstepの遷移で上書きする
- core/anet-core/src/trainer.cpp:665 次のstepのLearnEventは、上書き後のprev_exp_と、上書き前の遷移で投入した学習の結果を組にする
- core/anet-core/src/trainer.cpp:673 TrainEventも同じ組で通知する
- core/anet-core/src/trainer.cpp:569 SerialTrainRunnerは同じexpで学習した結果を、そのexpと組にする
- 2026-11-23 監査（defect）: 同じ遅れで、Run の最初の遷移と Shutdown の前の最後の遷移の TrainEvent が出ない（`src/core/base/src/trainer.cpp` 702〜765 行。待ち合わせが成り立つ 3 step 目から、1 つ前の遷移を出す）。最初の遷移は lane 0 の episode_start が真なので、`IsEpisodeStart()` で記録を始める Conv2dVisualizationObserver・GraphVizObserver（`observers.cpp` 716・1195 行）は最初の開始を見落とし、記録するエピソードが Serial と 1 つずれる見込みである。1 step 目の `@train` の点も Pipeline だけ欠ける。

## 影響

train.runner_type=pipelineで、LearnEventのexperienceとupdate_result_listを同じstepのものとして突き合わせる処理を使う → 遷移Nの経験に、遷移N-1を入れたあとの学習結果が付き、Serialで取った値と1 stepずれる。countsも学習に使ったものではなく、1つあとのprev_counts_になる。

## 対応方針

学習を投入したときのexp・countsを結果と一緒に保持し、イベントにはその組を渡す。

- 2026-11-11 リファクタリング候補の抽出: ずれと同じ場所の作りを足す。「1 つ前の step」を `has_prev_data_`・`prev_exp_`・`prev_result_`・`prev_action_info_`・`prev_counts_` の 5 つで持ち（trainer.hpp:228-232）、5 つは必ず一緒に書かれる（trainer.cpp:756-765）。`prev_action_info_` は `prev_exp_` の action と同じものを指し、`has_prev_data_` は `prev_result_` から導ける。学習に出したデータと次に通知するデータが同じ `prev_*` の名前で、どの時点でどちらを指すかを追わないと分からない。1 step ぶんの記録（経験・結果・カウンタ）を struct にし、学習に出した組と通知する組を分けて持つと、ずれの直しと一緒に片づく。確かめ: 宣言と書き込みの行を今のコードで読んだ。
