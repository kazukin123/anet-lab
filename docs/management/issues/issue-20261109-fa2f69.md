## 背景

PRD119 の実装の検証で、設定を変えたあとに回す出荷設定の検査（`anet-core-test.exe "[shipped_config]"`。[実装 品質確認観点](../../quality/impl.md) の「設定ファイル」の規約）を、直す前と後の Debug ビルドで回したときに見つかった。PRD119 の変更とは関係なく、直す前から起きる。工程末の候補として示し、2026-11-09 に開発者が起票を選んだ。工程の途中では開発者に質問していない。

## 事象

- `core\anet-core\bin\Debug\anet-core-test.exe "[shipped_config]"` を回すと、[intrinsic_test.cpp](../../../core/anet-core/src/intrinsic_test.cpp) の 157 行の `RND shipped Atari networks and Taiga settings match their contracts` で、Debug 版 libtorch の oneDNN の assert（`Assertion failed: nthr_ == nthr`、`dnnl_thread.hpp` の 294 行）が出て、終了コード 3 で止まる。2 回回して再現した。このテストを名前で単独に回しても同じだった。
- このテストを除いた `[shipped_config]` は終了コード 0 で通る。
- 既定のテストの集合（引数なし）では、このテストも通る（終了コード 0、失敗 0）。
- [PRD028 の実装記録](../../memo/done/028_cnblock_convnext_20impl.md) の 15〜17 行は、同じ assert を Debug 版 libtorch に固有のものとし、CPU のテストでは `EnsureNNInitialized` で MKLDNN を 1 回切る方式にしたと書いている。既定の集合では先に回るテストがこの切り替えを済ませ、単独や `[shipped_config]` だけのときはこのテストが切り替えを通らずに NN を構築していると見ている（未確かめ）。
- 記録: [PRD119 の実装記録](../../memo/119_small_doc_comment_config_fixes_20impl.md) の「経過」（直す前と後の A9）。

## 影響

設定を変えたあとに `[shipped_config]` を回すと毎回このテストで止まり、それより後に回る `[shipped_config]` のテストが走らない。止まった原因を毎回切り分けることになり、後ろのテストの失敗を見落としうる。

## 対応方針

未定。このテストが NN を構築する前に、ほかの NN のテストと同じく MKLDNN の切り替えを通すようにするのが候補である。

## 対応内容

- 2026-11-11 PRD124: anet-core-test の main で Catch2 を回す前に MKLDNN を 1 回切り、nn_test.cpp と dqn_based_agent_test.cpp の中の切り替えを消した。テストの開始時に切れていることを確かめる見張りのテストを test_util_test.cpp に足し、PRD116 の検証資材の README から `OMP_NUM_THREADS=1` の手順を消した。確かめ: Debug で、このテストの単独・`[shipped_config]`（12 本）・止まった順の組がどれも終了コード 0。既定の集合は 900 本で失敗 0。main の 1 行を外すと見張りのテストが落ちる。[PRD](../../memo/124_test_process_mkldnn_off_10prd.md)・[実装記録](../../memo/124_test_process_mkldnn_off_20impl.md)
