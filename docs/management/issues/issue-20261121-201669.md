## 背景

2026-11-21 の会話で、MetricsViewer に足りない機能と問題点を洗い出した。開発者はその中から、設定の比較、Run・tag の検索、グラフごとの統計、オフラインでの動作の 4 つを選んだ。はじめは 4 件の課題に分けて起票したが、課題と PRD の数を増やさないよう、開発者の指示でこの 1 件にまとめた。

設定の比較は、開発者が認識していた「JSON や TXT などグラフ以外の情報を見られない」から出た。AI が、ただ表示するより、選んだ Run どうしの設定の差分を出すほうが役に立つと挙げた。

Run のグラフを重ねて比べる作業には、手順が決まっている。

- 比べる前に、各 Run の設定（`config/config_data.txt`、`config/*.txt`、seed、Network 構成、batch size、replay の条件など）を確かめる（[030 §4.1](../../design/030_user_guide_analysis.jp.md)）。
- 両方にデータがある共通の `exp_step` の範囲を決める。その範囲で、水準（平均・中央値）、安定性（振れ幅、seed 間の範囲・標準偏差）、傾向（前半と後半の差、傾き）を読む（[030 §4.3](../../design/030_user_guide_analysis.jp.md)）。

## 事象

### 1. 設定の比較

- Viewer には、Run の設定を出す画面も、Run どうしの設定の差分を出す画面も無い。Run の情報パネル（`RunInfoPanel`）に出るのは次のものである（[210 §3.2](../../design/210_metrics_viewer.jp.md)）。
  - 取り込みの状態
  - 最大 step
  - tag 数と隔離の数
  - 点数の合計
  - 取り込みと tag の問題
- 設定は Run フォルダに `config/*.txt` と `json/*.json` として残る。例の Run（`AtariRnd-01/runs/run_20261119-202718_mz_tg_g99ne_rr4_s2`）では、`config/` に 11 ファイル、`json/` に 19 ファイルある。
- 同じ内容は Metrics のマスタにも json 行として入り、キャッシュの `json_lines` テーブルに取り込まれている。例の Run のキャッシュには json 行が 19 件ある。`config_data`（約 105 KB）、`config_resolution`、`DefaultDQNAgent`、`net.body`、`env/env_spec`、`run.eval.[greedy].env` などである。
- Viewer の HTTP API は `json_lines` を読まない（[210 §8.2](../../design/210_metrics_viewer.jp.md)）。
- 設定の差分を出せるのは、今は CLI の `apps/tools/inspect_run.py config <run_a> <run_b> --diff` だけである（[030 §6](../../design/030_user_guide_analysis.jp.md)、[inspect_run.py](../../../apps/tools/inspect_run.py) の `build_config_diff`）。

### 2. Run・tag の検索

- Run 一覧は、workspace の Run を名前の降順で全部並べる（[metrics-viewer.js](../../../src/apps/metrics-viewer/src/main/resources/static/metrics-viewer.js) の `renderRunList`）。絞り込みは、選んだ Run だけを出す `Selected Only` だけである。
- tag 一覧は、選んだ Run の tag を合わせて名前順に並べる（同じファイルの `renderTagList`・`_visibleTagKeys`）。絞り込みは `Selected Only` だけである。選び方の保存と呼び出しはタグセットでできる（[issue-20261103-4c0f04](issue-20261103-4c0f04.md)）。
- 画面で文字を入れる欄は、タグセットの名前の入力だけである。Run 名や tag 名で絞り込む欄は無い。
- 件数の例: LunarLander-01 は 165 Run、AtariRnd-01 は 55 Run ある。1 Run の tag は 189〜237 本ある。

### 3. グラフごとの統計

- 各グラフの上部に `Min / Max / Avg / Std` を 1 行で出している。値は、選んだ Run 全部の `TagStats` を `combinedStats` が 1 つに合わせたものである（[metrics-viewer.js](../../../src/apps/metrics-viewer/src/main/resources/static/metrics-viewer.js)）。
- `TagStats` は、Run と tag の組ごとの統計である。取り込んだ全点（L0）から作り、範囲によらない。件数、平均、分散、最小、最大、step の範囲、最新値を持つ（[210 §8.2](../../design/210_metrics_viewer.jp.md)）。
- そのためグラフ上部の値は、Run ごとの値でも、表示中の範囲の値でもない。Run ごとの最新値（`last_value`）は持っているが、画面には出していない。
- 表示中の範囲で Run ごとに計算しているのは、Y 軸の表示範囲を絞る percentile だけである。これは画面の点（LOD）から出していて、グラフ上部の統計は変えない（[030 §3](../../design/030_user_guide_analysis.jp.md)）。
- 統計は LOD から作らない決まりがある。LOD から作ると、表示の Step 幅や空の区間で結果が変わるためである（[210 §8.2](../../design/210_metrics_viewer.jp.md)）。
- 範囲を決めた統計は、今は CLI の `inspect_run.py metrics <run...> --range <範囲>` で出している。`--range-mode common` を付けると共通の範囲になる（[030 §6](../../design/030_user_guide_analysis.jp.md)）。

### 4. オフラインでの動作

- [index.html](../../../src/apps/metrics-viewer/src/main/resources/static/index.html) は、Plotly を `https://cdn.plot.ly/plotly-2.27.0.min.js` から読む。repo にも jar にも Plotly の写しは無い。画面が外から読むものはこれだけである。
- 設計文書は、完全にオフラインの環境で使うには Plotly の取り方を別に用意する必要があると、既知の制約として書いている（[210 §11.5](../../design/210_metrics_viewer.jp.md)、[160 §6](../../design/160_applications_and_tools.jp.md)）。
- この `<script>` には `integrity` 属性（SRI）が無い。
- Viewer の UI テスト（Playwright）にも、Plotly を手元のファイルに差し替える仕組みは見当たらない。テストも同じ URL から読んでいる。
- リリースの zip（[release.yml](../../../.github/workflows/release.yml)）は Viewer の jar を同梱する。第三者ライセンスの一覧は、Maven の依存から作る `THIRD-PARTY.txt` を `licenses/` に入れている。

## 影響

### 1. 設定の比較

- グラフを重ねたまま条件を確かめられない。別のターミナルで CLI を回すか、AI に頼むことになる。
- 確かめを省くと、seed 以外の設定も違う Run を、同じ条件だと思って比べてしまう。Run の名前が似ていても、設定が同じとは限らない（[030 §4.1](../../design/030_user_guide_analysis.jp.md)）。

### 2. Run・tag の検索

- 欲しい Run や tag を、スクロールして目で探している。Run が増えるほど手間が増える。
  - Run の例: 同じ条件で seed だけ違う `_s1`・`_s2` など
  - tag の例: `77_agent_value/` の群など
- タグセットに無い組を作るときは、群の tag を 1 本ずつクリックして選ぶことになる。

### 3. グラフごとの統計

- 2 本以上を比べるときに知りたいのは、Run ごとの、比べる範囲での平均・最終値・ばらつきである。グラフ上部からはこれが読めず、CLI か目分量で読んでいる。
- 合わせた値を、ある Run の値だと読み違えるおそれがある。

### 4. オフラインでの動作

- インターネットにつながらない環境や、CDN に届かないときは、グラフを描けない。どこまで動くかは試していない。
- リリースの zip を受け取った人が、つながらない環境で Viewer を開いても同じになる。
- CDN から配られる中身が変わっても、ブラウザはそのまま実行する（SRI が無いため）。
- UI テストが外のネットワークに頼っている。

## 対応方針

未定。4 つは別々に直せるが、開発者の指示で 1 件として扱う。

### 1. 設定の比較

- **読み口。** 2 つの案がある。
  - キャッシュの `json_lines` を API から返す。マスタから作り直せる範囲に収まる（[ADR 0015](../../adr/0015-metrics-cache-disposable-derivative.md)）が、取り込みが済むまで出せない。
  - Run フォルダの `config/` と `json/` を直接読む。取り込みを待たないが、Run フォルダの形に Viewer が新たに依存する。
- **差分の単位と規則。** `inspect_run.py` は、解決済みの設定キーごとに差分を出している。Viewer は Java なので、同じ規則を移すか、どちらを正本にするかを決める。
- **見せ方。** 選んだ Run を全部並べるか、2 本ずつにするか。違うキーだけを出すか、全部を出して違う行を目立たせるか。
- **範囲。** 設定以外の json（tag の定義など）、ログ（`*.log`・`stderr.log`）、`dot/` の表示は含めない。

### 2. Run・tag の検索

- 一致のさせ方（部分一致、空白で区切った複数語をすべて含む、正規表現など）
- 絞り込んでいる間の `Select All`・`Clear All` の対象を、見えている行に限るか
- `Selected Only` と組み合わせたときの動き
- 絞り込みの文字を、Reload やページの開き直しのあとも残すか
- 近い案（入れるかは対応のときに決める）: tag を先頭の群（`42_env/` など）でまとめて折りたたむ

### 3. グラフごとの統計

- **出す統計。** 平均、中央値、最終値、最小、最大、標準偏差、点数、前半と後半の差、傾きのどれを出すか。
- **範囲。** 全期間か、表示中の範囲か、両方か。表示中の範囲の値は LOD から作れない。server が全点（L0）から計算して返す口が要る。
- **置き場。** グラフ上部の行を Run ごとに増やすか、グラフの横にパネルを出すか、表にするか。
- **横軸の種類との関係。** 表示中の範囲は、その tag の横軸での範囲になる。横軸の種類は tag ごとに違う（[issue-20261103-52bda0](issue-20261103-52bda0.md)）。これを範囲の表示にどう出すか。
- 同じ条件の Run（seed 違い）をまとめて、平均と範囲の帯で描く機能は含めない。

### 4. オフラインでの動作

- **案 1: `static/` に置く。** Plotly の min.js（数 MB）を repo に入れ、jar に含める。ライセンスの一覧には手で足す。
- **案 2: Maven の依存として取り込む。** WebJars などの形で依存に足し、jar を作るときに含める。repo に大きなファイルが入らず、`THIRD-PARTY.txt` にも自動で載る。使える版と配信の形は、対応のときに確かめる。
- どちらの案でも、[210 §11.5](../../design/210_metrics_viewer.jp.md) と [160 §6](../../design/160_applications_and_tools.jp.md) の記述を直す。
