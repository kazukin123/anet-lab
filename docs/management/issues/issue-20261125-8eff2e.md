## 背景

2026-11-25 の監査（観点 refactor、範囲 321_agent_core）で見つけた。観点の分類は「既存の重複」で、「局所の繰り返し」が付随する。開発者には質問していない。

RFD0121 と ADR 0074 は、Network は合わせた Q を出さず、DQN 側の 1 つの関数（`DecomposedValueCombiner::Combine`）が外的・内的の Head から合わせると決めた。関数は 1 つだが、呼ぶ条件と引数が写しになっている。

ホットスポット補正: `dqn_learner.cpp`（改名の前の `dqn_based_agent.cpp` は churn90 が 41）は、コードのファイルの上位 1% に入る。urgency を 3 から 5 へ 1 段上げた。

## 事象

- `if (config_.intrinsic.decomposed) DecomposedValueCombiner::Combine(<出力>, intrinsic_beta_, config_.use_tbo, config_.tbo_epsilon);` が `dqn_learner.cpp` の 590 行（replay fit）、665・670 行（Noisy の probe）、788 行（policy churn）、2193 行（QR・IQN の current）、2880 行（TD の current）の 6 か所にある。同じ形が Agent の可視化用の forward（`default_dqn_agent.cpp:861-862`）に 1 か所ある。
- もう 1 つの道は `DqnForwardExecutor`（`dqn_math.hpp:247-259`）で、構築のときに受けた β があれば forward のあとに合わせる。Actor（`dqn_actor.cpp:1526`）と Learner の hard target（`dqn_learner.cpp:2717`）が使う。
- `DqnForwardExecutor` の構築子は 1 引数でも呼べて explicit でないので、`NetworkForwardExecutor` をそのまま渡すと β なしの実行器に変わる。`dqn_learner.cpp:2239`・2604 行の `SelectAction` の呼び出しがこの変換を使う。
- 検索語と件数（テストを除く）: `DecomposedValueCombiner::Combine` は定義 1、実行器の中 1、条件つきの呼び出し 7。`DqnForwardExecutor` の構築は 2。

## 影響

- 合わせた Q を読む forward を足すたびに（診断の群、RFD0201 の記憶からの標本など）、この 1 行を忘れずに書く。忘れると、分解の Network は `q` を出さないので、`At("q")` の例外で分解の Run だけが途中で止まる。

## 対応方針

- Learner に「出力に合わせた Q を足す（分解でなければ何もしない）」private の関数を 1 つ置いて 6 か所が呼ぶ形か、Learner の forward の口（current・probe・診断）を `DqnForwardExecutor` に通して、条件を構築時の β の有無で表す形のどちらかを選ぶ。`DqnForwardExecutor` の構築子は explicit にし、β なしの箇所を明示にする。
- 性能の区分は「中立」（2193・2880 行は更新ごと、ほかは診断の間隔ごと。計算は変わらない）。
- トピック別まとめの「変えるときの条件」では、RFD0125 §4 D5・D13（forward の順と AMP の範囲の端）と D16（更新 1 回あたりの実時間）が当たる。同 seed・決定的モードの metrics の一致を確かめる。
- テスト: 数値は `dqn_learner_test.cpp:1426`、分解の更新は同 1516・1666 が通す。6 か所を並べて確かめるテストは無い。
- 不採用の形との突き合わせ: RFD0121 §5 の「`q` を外的の Head の出力のままにし、読み手ごとに合わせる形 — 不採用」と ADR 0074 の決定は守る。
- 選んだ行動の値を取り出す式の写し（[issue-20261125-9e8834](issue-20261125-9e8834.md)）と同じ関数に当たるので、同じ変更でまとめて直せる。
