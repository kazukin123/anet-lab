## 背景

[PRD191](../../memo/0191_rnd_raw_error_and_recent_learning_10rfd.md) の再グリル（2026-11-21〜22）で、開発者は、使わない設定が既定と違うときの WARN も INFO も要らないと述べ、設定を、段階ごとのスコープとモード別の名前空間で持つ形を示した（PRD191 の P46・P48、§12 の発言 5〜10）。PRD191 は、RND と補助学習の設定だけをこの形にし、`rnd` の下の通知だけを無くす（D7・D12）。RND の外は範囲外とした（非ゴールの表、未決表の U2）。

決まりそのものの見直しは、[issue-20261122-2fc208](issue-20261122-2fc208.md) に分けた。この課題は、その決まりが決まったあとに、沿わない今ある設定キーと通知を見直す仕事である。工程の終わりに起票の候補として示し、開発者が、RND の外の特定の設定に限らず、決まりに沿わない設定の全体を対象にするよう指示した。

## 事象

- PRD191 は、RND の外の設定キーと通知を変えない。
- 使われない設定を知らせる通知のうち、文が `Ignored` で始まるものを出す文は、テストを除く `src/` に 9 か所ある（2026-11-22 に検索）。補助の関数を含むので、対象の設定キーはこれより多い。うち [intrinsic_rnd.cpp](../../../src/core/base/src/intrinsic_rnd.cpp) の 3 か所は、PRD191 が無くす。残りは 6 か所である。[default_dqn_agent.hpp](../../../src/algo/dqn/src/default_dqn_agent.hpp) の 152・174・287・316 行、[scaler.hpp](../../../src/core/base/include/anet/scaler.hpp) の 181 行、[nn_modules.cpp](../../../src/core/base/src/nn_modules.cpp) の 235 行。ほかの文面の通知は数えていない。
- 分かっている例の 1 つは、`intrinsic.observation` と `intrinsic.use_done_mask` である。`observation = state` のとき `use_done_mask` を使わず、既定と違えば WARN を出す（default_dqn_agent.hpp 172〜176 行）。
- もう 1 つの例は `reward_scaler.*` である。真偽のキー（`use_dynamic_scaling`）とモードのキー（`dynamic_mode`）と、どちらかの場合にだけ使う値のキー（`constant_scale` など）が、同じ階層に並ぶ。外的報酬用と内的報酬用が同じ設定の型を共用する。`apps`・`src`・設計文書（jp）で、書いている箇所は 662 行ある（PRD191 の P60）。
- 出荷の設定（`apps/runner/config` の txt 13 ファイル）で、名前が `mode` で終わる設定キーを書いた行は 260 行、末尾の名前は 29 種類ある（2026-11-22 に検索。コメント行を除く）。このうちどれが決まりに沿わないかは、決まりが決まっていないので、分けていない。
- 2026-11-22 issue-20261122-2fc208 の対応: 通知の決まりが決まった。選んだモードや意図した休止（有効フラグの偽・間隔 0・schedule の無い評価タグ）のために、書いた値が結果を何も変えない設定キーは、知らせずに値域だけを検証する（AGENTS.md の Fail-Fast 原則の表と「設定値の扱い」）。当たる通知は、文が `Ignored` で始まるものに加え、`use_optimistic_target = true` で楽観の無い方策をそのまま写すときの WARN（[default_dqn_agent.hpp](../../../src/algo/dqn/src/default_dqn_agent.hpp) 409 行）がある。組み合わせで結果が歪むか弱まる構成の WARN（`use_tbo` と動的な報酬スケーラなど）は、当たらない。[issue-20261122-2fc208](issue-20261122-2fc208.md)
- 2026-11-22 issue-20261122-2fc208 の対応: 設定キーの形の決まりが決まった（impl.md の「名前の付け方」の 10・11）。モードによって使う設定キーが変わるときは、スコープの `mode` とモードの名前の名前空間で持ち、どのモードでも使うがモードによって意味・単位・適した値が変わる設定キーも、モードごとに持つ。値を選ぶだけで、そのモードでだけ使う設定キーも、モードで意味が変わる設定キーも持たないモード（`AtariEnv.resize_mode` など）は、平らな `<何の>_mode` のままでよい。上の 260 行・29 種類のうち、直す対象は、そのモードでだけ使う設定キーか、モードによって意味・単位・適した値が変わる設定キーを持つものである。沿わないまとまりにキーを足す・変える PRD は、そのまとまりを同じ変更で移すので、この課題より先に移るまとまりがある。[issue-20261122-2fc208](issue-20261122-2fc208.md)

## 影響

- モードを切り替えて比べる Run で、関係のない設定を書き直すか、WARN を受ける。
- RND と補助学習だけが新しい形になり、設定の読み方が部品ごとに違う。

## 対応方針

未定。[issue-20261122-2fc208](issue-20261122-2fc208.md) で決まりが決まってから、次を決める。

- 沿わない設定キーと通知を調べて一覧にし、直す範囲と順を決める。
- `reward_scaler.*` のように書いている箇所が多いものを、別の課題に分けるか。
- 旧いキーの別名は作らない決まりなので、直す範囲ごとに、設定・bat・テスト・設計文書の書き直しが要る。その規模を、直す前に数える。
