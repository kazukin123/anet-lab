## 背景

2026-11-25 の監査（観点 drift、範囲 `docs/design/140_observability.jp.md`）で見つけた。分類は文書 stale と ADR ずれ（決定と実装の不一致）である。開発者には質問していない。

ホットスポット補正: 140 は 90 日の変更回数が 38 回で、設計文書（jp）の中で 200・160 に次いで多い（`reports/stats/stats.json` の `flow.churn90`）。urgency を 2 から 3 へ 1 段上げた。

## 事象

- 140 の trace チャネルの節（`docs/design/140_observability.jp.md:325`）は、trace の行について「`timestamp`を持ち、top-level `value` は持たず」と書く。同じ節の行の例（322 行）には `timestamp` が無い。
- 実装は持たない。`MetricsLogger::LogTrace`（`src/core/base/include/anet/metrics_logger.hpp:201-206`）は `type`・`tag`・`step`・`lane`・`data` の 5 つだけを書き、`JsonlBackend::WriteJsonl` は何も足さない。時刻を付けるのは `type:"json"` と動画の記録（`metrics_logger.cpp:673`・741・818）だけである。
- 実際の行でも確かめた。`run_20261123-132453_tmp_st51` の `metrics.jsonl` の trace の 1 行のキーは `data`・`lane`・`step`・`tag`・`type` だった。
- 経緯: PRD069 の実装（8f8104fa）では、140 は「`timestamp` と top-level `value` は持たず」と書いていた。PRD097 の実装（4d191af3、2026-10-20）で、この文が「`timestamp`を持ち」に変わった。PRD097 は時刻を扱っていない。
- ADR 0047 は「trace 行は固定属性として `timestamp` を持つ」と決め、RFD0081（[issue-20261103-955e50](issue-20261103-955e50.md)、調査中）が実装の指示書だが、まだ実装されていない。ADR 0047 の本文に、未実装であることの記述は無い。
- `apps/tools/inspect_run.py` と Runner のテストには、trace の `timestamp` を読む・確かめる箇所が無い（検索語 `timestamp`）。

## 影響

- 解析の道具や Viewer を作る人が、140 を信じて trace の行の時刻を読むコードを書くと、値が無い。録画の時刻から該当のゲームを引く手順（RFD0081 の目的）が、今すぐ使えると読み違える。

## 対応方針

- 140 の 325 行を、今の契約（固定属性は `tag`・`step`・`lane`、時刻は持たない）に戻し、RFD0081 の実装で時刻を足すときに書き換える。英訳も同じに直す。
- ADR 0047 に「行の時刻は RFD0081 の実装待ち」の注記を足すかを決める（`docs/adr/` の書き方の決まりに従う）。
