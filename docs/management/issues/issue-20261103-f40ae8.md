## 対応内容

- 2026-11-11 リファクタリング候補の抽出: PRD056 の前提のうち「EvalPanel の `GetImageData` 経路は互換維持」を、今のコードと照合した。確かめ: `GetImageData` を呼ぶのは HeatMapPanel.cpp:536・543 の 2 か所だけで、相手は `SweepedHeatMapObserver` である。`TimeHistogramObserver` の `GetImageData` と `captured_step_` を使う箇所は無い。グリルで前提を見直す材料になる。
- 2026-11-11 リファクタリング候補の抽出: PRD056 が触る heat_map の型に、読まれない設定と使われないメンバがある。`HeatMapFlags` の 10 個のうち `HM_AutoNormX`・`HM_AutoNormY`・`HM_SumMode`・`HM_AutoScaleAxis` の 4 個は、立てる側（image.cpp・HeatMapPanel.cpp・QValuePanel.cpp と既定値 heat_map.hpp:35・156）はあるが、`flags_ &` で読む箇所が無い。heat_map.hpp の TimeHistogram のコメントは「固定/自動(EMA)の二択」と書くが、`HM_AutoScaleAxis` を読まないので、レンジは常に広がる方向へ追従する。TimeHeatMap は、ctor の引数 `max_points` を使わず、`smoothed_scale_x_`（heat_map.hpp:119）は初期化も読み出しも無く、`EraseCol_`（heat_map.cpp:408、本体はコメントアウト）と `GetCurrentFrame`・`GetTotalFrames`（heat_map.hpp:107-108）は呼ばれない。TimeHistogram の `buffer_` は確保するだけで、`MinVal`・`MaxVal` は呼ばれない。`SweepedHeatMap::SetValues`（heat_map.cpp:860）も呼ばれない。PRD056 で TimeHistogram を作り直すときに、これらを消すか、flag を「効果なし」と書くかを一緒に決める。flag の設定の語ごと消すと、設定で受け付ける値が変わる。確かめ: 定義と読み出しの位置を今のコードで確かめた。4 つの語が設定ファイルで使われているかは確かめていない。
