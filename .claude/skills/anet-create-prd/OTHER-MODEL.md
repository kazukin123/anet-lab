# 別モデルの検討: 依頼文の雛形

`anet-create-prd` の「別モデルの検討」で、呼び出し元が次の雛形を埋め、セッションとは違うモデルを指定して `anet-other-model` へ渡す。役割と返す形は本書が持ち、汎用エージェントの定義には置かない。

## 渡すもの

- PRD 草案のパス。
- 草案に書いたゴールアンカー（節の所在と内容）。
- 確定事項の節の所在と内容。
- 改訂なら、基準コミットと、そこからの差分を保存したファイルのパス。

会話の発言・経緯・要約は渡さない。前提が草案に足りなければ先に草案へ書く。改訂差分は呼び出し元が用意し、読み取り専用のエージェントに生成させない。

改訂差分は [anet-review の「差分を書き出す」](../anet-review/SKILL.md#差分を書き出す) と同じ手順・置き場（`.scratch/prdNNN/diff-<YYYYMMDD-HHMM>/`）・ファイル名の決め方で、呼び出し元が書き出す。対象は PRD と、あわせて変えた `CONTEXT.md` と ADR。本用途では PRD も差分を書き出す対象にする。基準コミットは同スキルの「1. 対象を決める」に従う。

新規の PRD では差分を作らず、雛形の「改訂の差分」に「新規」と書く。

## 雛形

```text
次のPRD草案を読み、別のモデルの立場から論点を返してください。成果物は編集しないでください。

草案のパス: {実在するパス}
ゴールアンカー: {草案の節と内容}
確定事項: {草案の節と内容}
改訂の差分: {基準コミットと差分ファイルのパス。新規なら「新規」}

頼むこと:
- 自分なら問う論点と、その推奨案。
- 反対する決定と、その理由。
- 抜けと矛盾。コードや文書との食い違いは、その場所を添える。
- 設計の妥当性を検討してよい。品質確認観点の充足を判定するレビューとは役割が違う。

項目ごとに次を返してください:
- 論点と根拠。コードや文書は開けるリンクと場所を添える。
- 推奨案、または反対する決定と理由。
- 結論への反対なのか、理由・前提の確認なのか。
- 次の仕分けのどれに当たるかの見立て:
  ①コードや文書で分かる事実
  ②規約・ADR・CONTEXT.md・現行コードから一意に導ける事項
  ③ゴール・優先度・許容する不利益の選択
  ④実験・試作でしか分からない事項
  ⑤PRDの契約に効かない実装の詳細（クラス構成・名前を除く）
  ⑥範囲外
論点が無ければ「なし」と返してください。
```

## 返ったあと

呼び出し元が [SKILL.md](SKILL.md) の6区分に照らして扱う。本文の理由・前提の不足だけなら補って①として示す。結論への反対なら、会話で済ませた事項でも両意見を示して③として聞く。依頼先の仕分けを無条件に採用しない。
